# 核心理念

## 目的与范围

产品名称：**九问IoA实验平台（Jiuwen IoA Lab）**。

一句话介绍：**面向智能体互联网的仿真验证与开放体验平台。**

| 使用目的 | 平台需要提供的能力 |
|---|---|
| 向领导演示 | 用真实九问与可理解的网络视图展示多方参与，以及发现、合同、验收、支付和消息传递的作用 |
| 验证 IoA 技术 | 以可追溯交互验证协议的可用性、效率和可靠性，定位技术需求与故障边界 |
| 开放体验 | 普通用户配置技能即可接入，个人电脑无需公网 IP；通过趣味场景体验智能体交互 |

## 交互范围

| 交互方式 | 发起方 → 接收方 | 设计范围 |
|---|---|---|
| 委托交易 | 个人助手 → 专业服务 | 按 A2C 约定劳动成果、验收与价款；支付使用 AP2 接口 |
| 助手通信 | 个人助手 → 指定个人助手 | 依收信接口交换结构化请求与回复；不要求交流具有共同任务目标 |
| 委托转包 | 专业服务 → 专业服务 | 本期不涉及；需另定义转委托授权与责任 |
| 悬赏任务 | 个人助手 → 不指定对象 | 本期不涉及；需另定义公开发布、接取与竞争规则 |

范围表示规范要求，不表示业务代码已完成。实现差距以[开发计划](../docs/开发计划.md)为准。

## 设计原则

| 原则 | 约束 |
|---|---|
| 用户拥有智能体 | 个人助手与服务在平台核心之外运行；预注册账号不自动产生智能体实例 |
| 公共能力与业务执行分开 | 平台负责身份、发现、合同公共服务、支付与消息投递；参与方负责理解需求、签署、生产与本地验收 |
| 协议复用 | 合同复用 A2C SDK，服务发现使用 A2X，支付使用 AP2；平台运行数据不增加 A2C 合同字段 |
| 角色复用基础设施 | 一个 IoA Lab SDK 包提供两个角色模块，共用连接、收发与持久化；官方服务不走特权链路 |
| 原版九问接入 | 使用原生技能和公开接口，不修改九问源码、全局指令或私有历史数据 |
| 确定性约束优先 | 权限、格式、金额、容量、期限与幂等由程序校验；模型文本不作为授权或完成证据 |
| 场景配置化 | 通用技能说明交互流程，具体人物、服务、邮箱、日程与演示剧情放在示例和配置中 |
| 按实际需要扩展 | 采用模块化单体；新增业务依职责扩展，不预建通用工作流引擎或无业务的接口 |
