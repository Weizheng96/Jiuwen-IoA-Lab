# 智能体消息中心

界面与演示统称“个人助手间交互”，不预设交互目的都是协作或共同完成任务。个人接口区域使用“我定义的交互接口”；不以收费与否作界面卖点，协议仍禁止个人接口收费和市场挂牌。指定账号查询时仅向允许的调用者返回接口，不提供全站公开检索。示例可用王经理、赵专员等账号显示名，权限判断仍使用真实账号id与接口版本；双方消息中的显示名只向有权查看该消息的账号返回。

会议示例聚焦接口发现、输入格式、消息中心投递、冲突回执与改约：符合规则才发出邀请，交所有者接受；冲突时拒绝该时间，由发起方依据回执重新提出。邀请受理、等待审批和用户接受入历分别展示，不将预设规则描述为模型自由协商或私人Outlook读取。

## 边界与接口

免费、按账号定向的结构化异步消息，与A2C委托并列。无合同、收费、市场挂牌或交易信誉；不进入A2X搜索。平台只持久保存和投递，本地SDK与九问处理业务。

个人助手通过SDK登记接口：`name`、`description`、`inputSchema`、可选`outputSchema`、`allowedSenders`、`enabled`；服务端分配递增revision并保存不可变版本。未设置allowedSenders表示所有已登录账号，空数组表示无人；白名单解析成不可变账号id。按已知账号只返回调用者有权访问的接口，不提供全站目录。

Schema采用JSON Schema基础子集：object/array/string/number/integer/boolean/null、properties/required/additionalProperties/items/enum、长度、数量、范围与date-time。禁止外部引用、任意代码及无界递归；schema≤16KiB、消息≤32KiB、深度≤8。类型和格式由服务器与SDK核验，业务时效和规则由接收方再次核验。发送者只由登录态确定，不相信正文中的from/owner。

| 操作 | `/api/v1/messaging`下的接口 |
|---|---|
| 登记/停用接口 | `PUT /interfaces/{name}`，所属账号；查询自身`GET /interfaces` |
| 定向查询 | `GET /accounts/{username}/interfaces`，精确账号、按白名单裁剪 |
| 投递 | `POST /messages`：to、interface、revision、payload、idempotencyKey、expiresAt?、parentId? |
| 同步/查询 | `GET /inbox?after=&limit=&wait=`、`GET /messages`、`GET /messages/{id}`；仅双方可读 |
| 确认/处理 | `POST /messages/{id}/ack`、`/claim`、`/complete`；仅收件方，处理租约与结果校验 |

接口被更新后旧消息保留原schema，但处理前按当前白名单/停用状态复核；撤权不能被排队消息绕过。回复通过原消息的result或带parentId的新消息关联，限制链长度，避免自动互答循环。

## 持久化、投递与清理

复用平台SQLite，按收件人和单调seq增量查询，不引入消息中间件。幂等键按发送账号唯一，同键异正文冲突。查询不删除消息；SDK先将消息及游标可靠写入本地SQLite再ack。浏览器查询不推进SDK游标。

状态queued→synced→processing→completed/rejected；queued/synced/processing可过期为expired。claim使用短租约，过期租约允许恢复；完成结果只能由当前租约提交。投递至少一次，客户端按消息id去重，外部副作用结果不明时标unknown并停止自动重试，不承诺跨系统恰好一次。

正文默认保存30天，普通请求有效期默认7天且不超过正文期限；业务请求另有更早截止时间。已同步到本地的消息执行前仍复核expiresAt。到期只失去执行资格；正文到保留期才清理，结果与正文同样按30天清理，消息状态等元数据保留90天。容量默认每账号1000条未完成消息；满额明确拒绝，不覆盖旧消息。每发送账号每分钟60条，另有限定单对收发速率。离线不自动代办、不无限保存；发送方可查已过期/被拒绝/待处理。

平台活动只记录消息id、双方、接口、状态等元数据；正文不广播到全局事件流。管理员消息审计需显式权限入口，普通用户只能看双方消息。SDK应把外部正文作为数据，不能当用户的新授权或后台管理命令。

## 用户侧与管理员助手

`MailboxClient`只依赖平台公开接口与本地消息存储，不长期占用A2C身份目录锁。收件器在线才处理，无消息不调模型。九问Skill增加接口登记、定向查询、投递、同步、结果查询；接口定义只声明数据，处理器在用户本机配置，不从消息安装或执行代码。

`personal-assistant/`是随部署附带的独立管理员个人助手客户端，账号ISC_001，独立进程、九问venv与数据目录；核心仍无助手运行时。默认提供message.forward与meeting.request两个免费接口，允许所有已登录用户。普通用户可自行登记同名或其他接口、收紧范围。账号的浏览器管理员角色不等于外部消息的自动执行权限；自动处理器只具备消息与预配置通知能力。

九问版本锁定安装包版本、源码提交与摘要，不自动升级。候选采用已研究的workswarm 0.2.5b1/b465f45；通过真实安装与协议检查后记入部署锁文件。使用九问官方ApplicationPluginExtension提供经独立口令鉴权的`ioa.notification.deliver`，经宿主已建立的AgentServerClient持久化通知会话。WebChannel未直接公开history.append_record，扩展只接受消息id、已验证发送者和正文，目标用户与写入方法固定，不暴露任意RPC。外部正文仅作为通知记录，不进入模型或工具输入；不改九问源码、不直接改九问历史数据库。扩展持久化幂等回执；发送状态不明则unknown并停止自动重写。向网页转发必须进入绑定用户的真实Web会话历史；已存IoA信箱、已投九问会话与用户已读分别显示。九问不在线则保留待转发；测试适配器必须显著标注，不能冒充九问页面或真实投递。

## 会议邀请

输入包括title、start、end、timeZone；接收方本地配置recipientEmail、工作日/时段、时长上下限、提前量、可预约天数。默认管理员收件邮箱zhengw.cc@outlook.com。按事先授权规则自动处理，无需逐次确认。预约依据可显式选择本地时间安排或已授权的Graph日历，并合并本地待接受预约；当前演示使用本地安排。不能读取或验证选定依据时明确失败，不能假定空闲。

### 本地可编辑时间安排

`IOALAB_CALENDAR_BACKEND=local`明确采用助手自己的本地安排，不读取私人Outlook日历。`IOALAB_SCHEDULE_FILE`默认指向该账号IOALAB_HOME下的schedule.json；文件包含timeZone、rules和events。rules只维护可预约规则；events为主人维护的已有安排，带唯一id、title、带时区的start/end及busy/cancelled状态。文件不上传平台，不进入Git；用户可以直接用编辑器修改，九问通过本地SDK的schedule命令读取和更新。文件丢失、格式错误、非法时区或重复id一律阻止自动预约，不自动重建为空日历。

`schedule init/show/replace`不依赖平台在线。首次init显式创建工作日9–18点的空安排，展示其适用范围；不覆盖已有文件。show返回内容和摘要revision；replace必须带上读取时的revision，校验整个文档、加本地文件锁、保存上一份备份并原子替换；旧revision冲突，不静默覆盖。收件器逐次读取规则与事件，不必重启。在线编辑优先用SDK；手工编辑时暂停收件器，保存后恢复，避免外部编辑器绕过文件锁。

自动邀请的幂等和待接受预约仍在现有客户端SQLite维护，不把外部通知状态交给手工文件修改。schedule show同时列出本账号本地预约的简要状态，手改events不能释放已发出或结果不明的预约。预约时锁定本地安排，检查其内容未变化后才提交邮件；没有接受回执保持待接受，不因写了本地记录就宣称Outlook已入历。外部消息无权任意修改主人日程或可预约规则，修改须来自本机用户指令。

所有用例均由部署方配置的通知邮箱发送标准iCalendar邀请邮件，用户接受后才更新其Outlook日历；不直接调用创建管理员日历事件接口。选用graph后端时，个人Microsoft账号使用委托授权读取calendarView（含重复事件实例），不使用其不支持的getSchedule。首次OAuth登录需用户操作；令牌仅在客户端独立目录，不上传核心。Outlook通知邮箱使用SMTP XOAUTH2（smtp-mail.outlook.com:587、STARTTLS），仅请求SMTP.Send与offline_access；日历读取使用独立的Graph委托授权，两个资源分开登录、分别缓存，不能混用访问令牌。可复用同一个支持个人Microsoft账号的公共客户端应用；不使用客户端密钥，不要求填写通知邮箱密码。其他通知服务保留显式SMTP密码模式；Outlook端点不回退密码登录。授权校验成功后才持久化新令牌，错误账号不能覆盖有效授权。

通知邮箱支持AgentMail：通过官方API创建专用邮箱并由部署者验证所有权，通过官方Calendar API的send_invites发送iMIP会议请求，避免通用SMTP转发丢失日历MIME参数；邮箱与API key复用已有客户端SMTP配置，不再重复配置密钥。API只创建通知邮箱作为组织者的事件，不能写入收件人的Outlook日历。固定本地请求id作为client_id，服务端生成的实际UID/Event ID与请求id一起保存；同请求同正文保持幂等。通用SMTP仍用于其他邮件服务和独立连通诊断。注册、验证与本地配置由独立部署工具完成，不进入平台核心，也不把密钥交给模型。通知邮箱的收信能力不自动授予消息处理器任意读信或执行邮件指令的能力；启用更广的九问邮件工具需另行限定用途。AgentMail的验证、配额与投递状态按实际服务结果记录，不绕过未验证账号的发信限制。收件方仍可使用Outlook；选用graph后端时，换发件服务不替代其读取授权；选用local后端时以本地安排为依据。

同一邮箱预约串行处理，发送前重新检查日历并建立本地预约记录；固定邀请UID/请求id用于追踪。发送失败可按明确结果重试；发送结果不明时保留unknown，禁止自动重发。邮件服务受理不代表送达、接受或已写日历。AgentMail邀请为异步发送：API创建成功只表示已提交，须另核对发件记录与收件人界面；不能因组织者事件已创建而显示对方已接受。Calendar API不可用时明确失败，不静默退回已验证不兼容的SMTP附件方式。没有可靠接受回执时显示invite_submitted/awaiting_acceptance，不伪造accepted。明确拒绝/取消/失效后释放本地待接受预约。

## 本地验收与录屏

两个主要use case：①真实九问网页发起A2C委托＋个人助手进展页，再切到实际服务账号查询完成记录；②B向限定范围的A留言并预约，A按本地可预约规则和已有安排处理、九问网页收到留言，通知邮箱发出邀请，用户在Outlook接受后可见日历。字幕明确本地安排为预约依据，不暗示读取私人日历。全景并发流量为独立实验客户端，标experiment。

本地自动验收运行核心、官方Provider、独立收件器、SMTP收件测试服务与浏览器，验证实际数据库和协议调用；另测真实九问与选定的预约依据；Graph读取需单独授权验收。SMTP测试收件、日历fixture、九问适配测试与真实端到端分别出具证据，不能互相替代。录屏脚本只录实际页面与调用，保存运行证据、字幕和旁白；缺真实依赖时明确阻断正式录屏。
