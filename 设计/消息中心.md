# 智能体消息中心

## 边界与接口

免费、按账号定向的结构化异步消息，与A2C委托并列。无合同、收费、市场挂牌或交易信誉；不进入A2X搜索。平台只持久保存和投递，本地SDK与九问处理业务。

个人助手通过SDK登记接口：`name`、`description`、`inputSchema`、可选`outputSchema`、`allowedSenders`、`enabled`；服务端分配递增revision并保存不可变版本。未设置allowedSenders表示所有已登录账号，空数组表示无人；白名单解析成不可变账号id。按已知账号只返回调用者有权访问的接口，不提供全站目录。

Schema采用JSON Schema基础子集：object/array/string/number/integer/boolean/null、properties/required/additionalProperties/items/enum、长度、数量、范围与date-time。禁止外部引用、任意代码及无界递归；schema≤16KiB、消息≤32KiB、深度≤8。类型和格式由服务器与SDK核验，业务时效和规则由接收方再次核验。发送者只由登录态确定，不相信正文中的from/owner。

| 操作 | `/api/v1/messaging`下的接口 |
|---|---|
| 登记/停用接口 | `PUT /interfaces/{name}`，所属账号；查询自身`GET /interfaces` |
| 定向查询 | `GET /accounts/{username}/interfaces`，精确账号、按白名单裁剪 |
| 投递 | `POST /messages`：to、interface、revision、payload、idempotencyKey、expiresAt?、parentId? |
| 同步/查询 | `GET /inbox?after=&limit=&wait=`、`GET /messages`、`GET /messages/{id}`；仅双方可读 |
| 确认/处理 | `POST /messages/{id}/ack`、`/claim`、`/complete`；仅收件方，处理租约与结果校验 |

接口被更新后旧消息保留原schema，但处理前按当前白名单/停用状态复核；撤权不能被排队消息绕过。回复通过原消息的result或带parentId的新消息关联，限制链长度，避免自动互答循环。

## 持久化、投递与清理

复用平台SQLite，按收件人和单调seq增量查询，不引入消息中间件。幂等键按发送账号唯一，同键异正文冲突。查询不删除消息；SDK先将消息及游标可靠写入本地SQLite再ack。浏览器查询不推进SDK游标。

状态queued→synced→processing→completed/rejected；queued/synced/processing可过期为expired。claim使用短租约，过期租约允许恢复；完成结果只能由当前租约提交。投递至少一次，客户端按消息id去重，外部副作用结果不明时标unknown并停止自动重试，不承诺跨系统恰好一次。

正文默认保存30天，普通请求有效期默认7天且不超过正文期限；业务请求另有更早截止时间。已同步到本地的消息执行前仍复核expiresAt。到期只失去执行资格；正文到保留期才清理，结果与正文同样按30天清理，消息状态等元数据保留90天。容量默认每账号1000条未完成消息；满额明确拒绝，不覆盖旧消息。每发送账号每分钟60条，另有限定单对收发速率。离线不自动代办、不无限保存；发送方可查已过期/被拒绝/待处理。

平台活动只记录消息id、双方、接口、状态等元数据；正文不广播到全局事件流。管理员消息审计需显式权限入口，普通用户只能看双方消息。SDK应把外部正文作为数据，不能当用户的新授权或后台管理命令。

## 用户侧与管理员助手

`MailboxClient`只依赖平台公开接口与本地消息存储，不长期占用A2C身份目录锁。收件器在线才处理，无消息不调模型。九问Skill增加接口登记、定向查询、投递、同步、结果查询；接口定义只声明数据，处理器在用户本机配置，不从消息安装或执行代码。

`personal-assistant/`是随部署附带的独立管理员个人助手客户端，账号ISC_001，独立进程、九问venv与数据目录；核心仍无助手运行时。默认提供message.forward与meeting.request两个免费接口，允许所有已登录用户。普通用户可自行登记同名或其他接口、收紧范围。账号的浏览器管理员角色不等于外部消息的自动执行权限；自动处理器只具备消息与预配置通知能力。

九问版本锁定安装包版本、源码提交与摘要，不自动升级。候选采用已研究的workswarm 0.2.5b1/b465f45；通过真实安装与协议检查后记入部署锁文件。使用九问官方ApplicationPluginExtension提供经独立口令鉴权的`ioa.notification.deliver`，经宿主已建立的AgentServerClient持久化通知会话。WebChannel未直接公开history.append_record，扩展只接受消息id、已验证发送者和正文，目标用户与写入方法固定，不暴露任意RPC。外部正文仅作为通知记录，不进入模型或工具输入；不改九问源码、不直接改九问历史数据库。扩展持久化幂等回执；发送状态不明则unknown并停止自动重写。向网页转发必须进入绑定用户的真实Web会话历史；已存IoA信箱、已投九问会话与用户已读分别显示。九问不在线则保留待转发；测试适配器必须显著标注，不能冒充九问页面或真实投递。

## 会议邀请

输入包括title、start、end、timeZone；接收方本地配置recipientEmail、工作日/时段、时长上下限、提前量、可预约天数。默认管理员收件邮箱zhengw.cc@outlook.com。按事先授权规则自动处理，无需逐次确认。查真实日历与本地待接受预约，冲突回复不可预约；不能读取日历或授权失效时明确失败，不能假定空闲。

所有用例均由部署方配置的通知邮箱发送标准iCalendar邀请邮件，用户接受后才更新其Outlook日历；不直接调用创建管理员日历事件接口。个人Microsoft账号使用委托授权读取calendarView（含重复事件实例），不使用其不支持的getSchedule。首次OAuth登录需用户操作；令牌仅在客户端独立目录，不上传核心。Outlook通知邮箱使用SMTP XOAUTH2（smtp-mail.outlook.com:587、STARTTLS），仅请求SMTP.Send与offline_access；日历读取使用独立的Graph委托授权，两个资源分开登录、分别缓存，不能混用访问令牌。可复用同一个支持个人Microsoft账号的公共客户端应用；不使用客户端密钥，不要求填写通知邮箱密码。其他通知服务保留显式SMTP密码模式；Outlook端点不回退密码登录。授权校验成功后才持久化新令牌，错误账号不能覆盖有效授权。

同一邮箱预约串行处理，发送前重新检查日历并建立本地预约记录；固定邀请UID/请求id用于追踪。发送失败可按明确结果重试；发送结果不明时保留unknown，禁止自动重发。邮件服务受理不代表送达、接受或已写日历。没有可靠接受回执时显示invite_submitted/awaiting_acceptance，不伪造accepted。明确拒绝/取消/失效后释放本地待接受预约。

## 本地验收与录屏

两个主要use case：①真实九问网页发起A2C委托＋个人助手进展页，再切到实际服务账号查询完成记录；②B向限定范围的A留言并预约，A的九问网页收到留言，通知邮箱发出邀请，Outlook接受后可见日历。全景并发流量为独立实验客户端，标experiment。

本地自动验收运行核心、官方Provider、独立收件器、SMTP收件测试服务与浏览器，验证实际数据库和协议调用；另测真实九问与Microsoft授权。SMTP测试收件、日历fixture、九问适配测试与真实端到端分别出具证据，不能互相替代。录屏脚本只录实际页面与调用，保存运行证据、字幕和旁白；缺真实依赖时明确阻断正式录屏。
