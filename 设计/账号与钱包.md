# 账号与钱包

## 身份与数据归属

| 项 | 规则 |
|---|---|
| 账号 | 用户名密码，无手机号要求；支持邮箱形式用户名但不宣称已验证邮箱归属；`isp`、`isc` 仅用途标签，任意账号可关联个人助手与服务 |
| 预注册 | 部署幂等创建 ISP_001…（每领域一个，口令 001…）与 M 个 ISC_001…；账号保持空闲，不创建密钥或助手运行实例 |
| 本地身份 | SDK 在用户的独立目录生成委托方、用户、付款身份，只上传公钥；账号和本地身份绑定后，平台显示助手登记记录 |
| 绑定 | 登录态取得一次性限时 challenge；本地委托方签署包含 challenge、账号、平台地址、三把公钥的对象；平台验签并原子消费 challenge。相同身份重复登记幂等；不同账号不得占用同一身份或付款公钥，不静默覆盖已绑定公钥 |
| 服务 | 登录登记所属账号与服务公钥/收款公钥；官方服务身份由官方进程生成，不由核心生成；认证与模板公示见交易中心 |
| 权限 | kind仅用途标签；用户角色独立存储，ISC_001默认admin；登录后按权限切换管理员/个人助手/服务方视角，服务方按所属服务id查询。保留原管理口令作为兼容恢复入口。trial部署首次生成ISC_001强口令并自动配置管理员客户端，不能沿用001作为管理口令 |
| 会话 | 保留 Bearer 与浏览器 cookie 认证、Origin 校验、注册限制和管理员独立认证 |
| 一账号多设备 | 首期支持一个逻辑助手身份；跨设备复用须显式迁移本地身份与合同状态。不自动换钥，不用登录密码重新生成另一套身份覆盖旧合同 |

本地保存合同原件、材料、交付件、用户授权与未发送的观察事件；官方进程保存服务合同、交付件与任务；平台只保存账号、公钥、市场存证、支付凭证、合同观察副本和事件。核心重启不把远端合同改成失败。

## 模拟支付

虚拟币只是记账单位，协议币种暂用 SDK 已支持的 CNY，页面显示虚拟币。每账号每日首次登录赠币；内部账号不因空闲而自动补币。实验客户端需要额度时通过正常管理员操作准备。

模拟支付方按本地绑定的付款公钥识别付款账号，按服务登记识别收款账号。保留读卡核金额、签名与用途、余量核对、重复付款拦截及事务性过账；不因普通遥测事件改变账本。付款由本地 Client 经 AP2 发起；市场只提供付款依据。裁定文书不触发付款。

既有数据升级：不销毁历史私钥或合同；升级前备份，旧的核心助手数据保留用于查询，停止执行。新用户侧身份使用新的数据目录；正在进行的旧合同须先完成或显式结束，不能在新身份下直接接管。
