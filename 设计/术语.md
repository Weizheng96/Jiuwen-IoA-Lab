# 术语

## 目的与范围

统一文档、界面与接入契约中的名称。本文解释用途；状态规则和字段约束由所链接的职责页定义。代码标识与显示名称分别管理，不以全文替换破坏协议兼容。

## 参与方与产品

| 正式名称 | 英文/标识 | 含义与边界 |
|---|---|---|
| 九问IoA实验平台 | Jiuwen IoA Lab | 产品名，见[核心理念](核心理念.md) |
| 平台核心 | ioalab / platform core | 部署方提供的公共中心及网页，不运行参与方的业务智能体 |
| 个人助手 | personal assistant | 代表用户发起委托或与其他个人助手通信的智能体 |
| 专业服务 / 服务方 | service / provider | 服务是可承接委托的能力，服务方是提供该能力的一方；账号可拥有多个服务 |
| 官方预置服务 | official service | 随部署提供的普通服务配置，经公开 SDK 接入，无特殊协议权限 |
| 内部服务提供者/使用者 | ISP / ISC | 预注册账号的用途标签，不是互斥角色或权限等级 |
| IoA Lab SDK | ioalab-sdk / ioalab_sdk | 一个软件包，包含两个角色模块及共用接入能力，复用 A2C SDK |
| 个人助手端 SDK | assistant | 个人助手使用的委托发起、助手通信与收信配置能力 |
| 服务方端 SDK | provider | 服务发布、接单和履约能力；“服务方端”不是平台后端 |
| 本地接入组件 | local runtime | SDK 的常驻进程，负责连接、可靠收发、调度与持久化；“本地”相对于参与方，可在个人电脑或服务器运行 |
| 原版九问 Swarm | Jiuwen Swarm | 用户交互与业务执行宿主；原版依赖保存于 vendor，通过原生技能和公开接口接入 |
| 九问适配器 | ioalab-jiuwen / ioalab_jiuwen | 本仓可选适配包，连接共用运行时与原版九问；不包含九问本体或业务规则 |
| 宿主接口 | AgentHost | 本地运行时依赖的窄接口；由九问适配器实现会话执行、通知、能力探测及真实用户答复关联 |
| 官方参与方资源包 | official resources | 官方服务、管理员助手预设、业务技能与工具；使用通用 SDK，不包含另一套执行引擎 |

## 技能名称

| 正式名称 | 用途及内容位置 |
|---|---|
| IoA Lab 接入技能 | 两种产品接入技能的统称；产品源文件位于 `src/access/skills/` |
| IoA Lab 个人助手技能 | 指导配置个人助手、选择委托交易/助手通信、调用个人助手端 SDK；内容规范见[个人助手技能](接入/个人助手技能.md) |
| IoA Lab 服务方技能 | 指导服务配置、发布和接单，并提供受限履约说明；内容规范见[服务方技能](接入/服务方技能.md) |
| 业务技能 | 用户为九问配置的领域能力，例如开发或咨询；不等于 IoA 接入技能 |
| Skill / 技能格式 | 宿主加载的 `SKILL.md` 及相关资源组织形式；不能单独作为某个产品的正式名称 |
| Codex 开发技能 | `.agents/skills/` 内供维护本仓使用的指导，不交付给参与方九问 |

技能指导模型选择步骤，SDK 执行程序约束，本地接入组件维持连接；三者不可互代。技能安装标识可与正式显示名不同，映射由各技能设计页维护。

## 交互与业务对象

| 正式名称 | 英文/字段 | 含义及规则入口 |
|---|---|---|
| 交互方式 | delegation / messaging | 接入技能选择的业务流程；本期为委托交易与助手通信 |
| 委托交易 | delegation | 按 A2C 约定成果、验收和价款；[流程](流程/委托交易.md) |
| 助手通信 | messaging | 向指定个人助手请求、留言及回复，不预设所有交流都是协作；[流程](流程/助手通信.md) |
| 交互 | interaction | 同一参与关系下的一笔委托或一组相关通信请求，不能等同单条消息 |
| 收信规则 | inbox rule | 本地完整配置：接收什么、允许谁发送、如何处理与回复；由九问辅助起草，SDK校验 |
| 收信接口 | inbox interface | 收信规则对获准发信人公开的名称、说明、接收和回复格式；不在 A2X 挂牌，不公开本地处理步骤 |
| 接收格式 / 回复格式 | inputSchema / outputSchema | 正常业务输入与输出的数据约束；标准错误和处理状态另按统一封套表达 |
| 接口修订 | revision | 已发布声明的不可变版本；与本地处理规则版本配对，见[消息中心](组件/消息中心.md) |
| 用户授权范围 | scope | 已确认的用途、对象/类别、预算、期限及行为限制；不是模型生成的同意文字 |
| 接单预留 | admission | 委托中心记录的容量占用及其承诺关联，不是 A2C 合同字段 |
| 接单容量 | max_active_delegations | 同时有效的预留、可成约承诺和未结束合同的数量上限 |
| 模型执行并发 | max_model_runs | 同时运行模型任务的数量限制；等待用户不一定占模型名额，但仍可能占接单容量 |

## 标识与状态

| 名称 | 字段 | 含义 |
|---|---|---|
| 智能体标识 | agentId | 平台登记的稳定身份，不随连接、设备 IP 或九问会话变化 |
| 协议主体地址 | protocolId | A2C 原对象中的签名主体；个人助手可为其原 URN，服务为平台派生的稳定协议 URL，由身份绑定关联至 agentId |
| 消息标识 | messageId | 发起端生成、平台强制全局唯一的 UUID；同一发送重传不变 |
| 交互 ID | interactionId | 首请求接收端生成并回传的 UUID；双方 SDK 保存并用于后续内容关联 |
| 起始消息标识 | originMessageId | UUID 建立前的关联和恢复依据 |
| 回复关联 | inReplyTo | 指向被回复请求，不能凭此调用第三方或扩大权限 |
| 本地操作标识 | operationId | SDK 一次逻辑操作的幂等与恢复标识；一个操作可以产生多条传输消息 |
| 本地交互句柄 | interactionRef | SDK 提供的本地引用，自动携带已登记 UUID 和修订，避免模型抄写标识 |
| 阶段确认引用 | confirmationRef | 指向真实用户答复与对象绑定记录，不能由模型布尔值替代 |
| 九问会话 | session_id | 某端的九问上下文；不同于交互 ID，不作为付款幂等键，也不向对端公开 |
| A2A任务 / 合同摘要 | taskId / card digest | A2A/A2C 原有协议标识，交互 ID 不替代它们 |
| 执行代次 | generation | 某智能体活动执行租约的代次，用于阻止旧连接继续提交新动作 |
| 已受理 / 已送达 / 已完成 | accepted / delivered / completed | 平台持久化、本地持久化、业务完成三个不同层次的事实 |
| 结果未知 | unknown | 无法确认实际业务效果，需查原操作；不能当作失败自动重复 |
| 消息有效期 | TTL / expiresAt | 消息可投递及首次开始执行的窗口，不延长合同期限 |
| 交流截止 | deadline | 助手通信允许新增或开始业务请求的期限，不替代 A2C 终态 |
| 已核验 / 参与方上报 | verified / reported | 已验证证据与过程陈述，见[界面通用规范](界面/通用规范.md) |
| 余量 / 过账 | balance / posting | 虚拟记账数量及按依据变动，不代表真实货币业务 |
| 本地预留 / 邀请已提交 / 已接受 | reserved / invite_submitted / accepted | 会议场景的不同事实，接受入历需真实证据；[会议预约](示例/会议预约.md) |
