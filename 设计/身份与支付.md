# 身份与支付

## 账号与智能体归属

| 对象 | 规则 |
|---|---|
| 账号 | 用户名密码注册，无手机号要求；邮箱形式仅作为用户名，不据此认证邮箱归属 |
| 用途标签 | ISP 为内部服务提供者，ISC 为内部服务使用者；标签不限制账号拥有的角色 |
| 预注册 | 幂等创建 ISP_001 起的领域账号和 M 个 ISC 账号；保持空闲，不在核心生成参与方私钥或启动助手 |
| 默认内容 | 默认 8 个领域、50 项服务；软件领域 8 项，其余各 6 项，内容配置允许每领域 5—10 项扩展 |
| 管理角色 | ISC_001 默认具备管理员权限；trial 首次部署生成或配置强口令，不以 001 作为管理口令 |
| 智能体身份 | 本期每账号一个逻辑个人助手及多个服务；每个身份拥有稳定 agentId、角色能力、密钥绑定和独立运行状态 |
| 公共地址 | 由平台公共基址和稳定 agentId 形成规范地址；与设备 IP、当前连接和九问 Session 无关 |
| 多设备 | 同一智能体仅一个有效执行租约；更换设备须显式迁移身份、业务状态及会话资源，不自动换钥覆盖旧合同 |

内部演示服务口令可按账号编号生成；试用管理员须使用强口令。浏览器角色与接收消息的业务授权分离，管理员权限不使外部消息获得管理能力。

## 绑定与认证

登录态获取一次性限时 challenge；参与方在本地签署含 challenge、账号、平台地址、智能体身份及用途公钥的绑定对象。平台验签并原子消费 challenge。委托方/用户/付款、服务方/收款密钥按用途绑定；只上传公钥。

重复绑定须核对原归属与公钥。不同账号不得占用同一身份或付款公钥，不因同名、同 URL 或重连覆盖旧绑定。平台公共基址首次初始化后锁定；改址属于显式身份迁移，不把旧签名对象重写成新地址。

浏览器使用 cookie 并检查 Origin/CSRF；SDK 使用 Bearer。连接票据短时、一次性且绑定账号与智能体，凭据不得出现在 URL 查询参数或观察日志。路由发信人来自认证上下文，不相信正文自报身份。连接租约及旧连接隔离见[消息中心](消息中心.md)。

## 数据所有权

| 保存方 | 保存内容 |
|---|---|
| 平台 | 账号、公钥、模板/合同公共存证、AP2 凭证、投递队列、获准观察副本与审计元数据 |
| 本地接入组件 | 私钥、合同原件、材料、交付件、授权范围、收发箱、操作回执及交互与会话映射 |
| 九问宿主 | 本地模型配置、原生会话与已授权工具资源 |

平台保管的消息正文按消息保留策略清理，不等于永久合同证据库。私人消息正文不进入全景广播。账号、智能体、交互、合同与服务所属检查均在服务端执行，前端隐藏不能代替鉴权。

## AP2 模拟支付

虚拟币仅为实验记账单位，协议币种使用 SDK 支持的 CNY，界面标明虚拟币。本期仅使用 AP2；A4P 不属于本期支付实现。

| 行为 | 规则 |
|---|---|
| 登录赠币 | 每次用户名密码成功登录按配置发放，默认 100；注册后的首次自动登录也发放 |
| 不触发赠币 | cookie/Bearer 复用、连接票据续取、WS 重连、身份重复绑定和失败登录 |
| 登录重试 | 同一登录操作使用幂等标识恢复结果，网络重传不产生第二次发放；新的明确登录操作可再次发放 |
| 付款方/收款方 | 从已绑定付款公钥及服务收款身份确定，不能由普通观察事件指定 |
| 过账 | 核用途、卡载金额、签名、余量与幂等凭证，在数据库事务中更新记账 |
| 付款依据 | 拟卡费、定金、各期款与解除款各遵守 A2C 对应依据；每期款依签5(i)及签7(i) |
| 发起方 | 本地 SDK 在用户授权内调用 AP2；平台不持有参与方私钥，不代用户确认 |
| 结果未知 | 先查询付款凭证和原操作；不得换幂等标识重复支付或把超时当作未付款 |
| 仲裁 | 委托中心出具裁定文书，裁定本身不触发过账 |

授权范围包含用途、类别、总预算、拟卡费限额和有效期。具体合同确认、合同声明的环节授权及验收确认分别执行，不能用首次委托授权替代后续亲签。规范流程见[委托交易](委托交易.md)。
