# Agent 交易中心

交易中心 = 注册中心（A2X 发现 · 分类树）+ 市场（`a2c.market.Market`：签模板 · 签3 · 签5(i) · 结清）+ 平台自建的认证 · 信誉 · 仲裁文书。协议内的部分原样用 SDK；本文记平台怎么用它。

## 注册中心（A2X，作库进程内调用）

| 项 | 规则 |
|---|---|
| 数据集 | `RegistryService(database_dir=data/a2x)` → 数据集 `ioalab`；不挂任何 A2X 路由 |
| 索引卡 | A2X 副本的 Agent Card 只放索引字段：`name · description · url（服务方 URL）· skills（每个标签一条）· a2c: {templates: [{digest, formation, price, proposalFee}], paymentProvider} · status: online｜listed｜busy`；权威模板由助手经 `template.get` 从服务方取 |
| 注册 | 种子 `register_batch` 一次写盘；运行期 `register_one`；只改索引字段用 `update_card`（不动 name / description，不触发树失效） |
| 分类树 | **按领域确定性生成**，零 LLM：`seed/domains/<nn>-<slug>.json` 给出领域 `category {id: cat_<slug>, name, description, decision_rule}` 与其服务；生成 `taxonomy.json`（root → 各领域叶类 → 服务）与 `class.json`（名称 · 描述 · 判别规则）；`service_hash` 在注册之后按 A2X 同法回写（name + 注册表描述），树即 `available`。树深 1，每类 ≤ 10 个服务 |
| 运行期归类 | 用户 / 外部服务方注册时**必填 `domain`**：确定性加入该叶类并重写哈希；兜底叶类 `cat_misc`。不用 A2X 的 LLM 增量建树 |
| 检索 | 默认 A2X 分类树导航（`get_all` 取叶类整组 → 向量重排 → 并上向量前 3）；树不可用、未配 key 或 60 s 超时 → 向量退路（嵌入模型 + numpy 余弦；无嵌入时字符二元组）。检索一律 `to_thread`，与智能体模型共用一个并发闸；事件 `discovery.search` 记 sender（哪个助手问的）、模式与命中 id |

## 市场（协议内，原样用 SDK）

`Market(models={})`：模板签认（`template.endorse`）· 签3（快照验收器包）· 签5(i)（交付留痕时间戳）· 结清（`card.close`）。skill 模板自然拒签（首版只认 script 验收器）。
验收器包只认 `ioalab://pkg/<digest>`（平台打包存 `data/packages/`，`manifest.kind` 只许 `script`，单包 ≤ 256 KB）。

## 认证 · 信誉 · 仲裁（协议外）

| 职责 | 做法 |
|---|---|
| 服务认证 | 注册服务时记一条认证记录（市场签名），服务方公钥加入 `Directory`；认可名单首版为空。外部服务方按 [接入.md](接入.md) §服务方登记 JWKS 与收款公钥 |
| 信誉条目 | 由 `ledger` + `rulings` 按服务方汇总：已完成总数 + 成功比例（完成 = 成功；委托方解除不计；仲裁按裁定 `liable`）；未结清且未裁定的卡不计。条目用市场签名签发，助手逐条验签。**不造随机信誉**：试用前用内部流量预热 |
| 仲裁 | 收卡 + 期号 + 本期交付件 + 验收报告 → 先按清单逐文件核摘要，不符驳回 → 两类同一格式裁定文书（JWS：`cardHash · period · kind: recompute｜deadline · liable: provider｜client · evidence`）：复算类调 `Market.recompute`（快照里的验收器包，wasm 沙箱）；时限类按卡上签名时刻判 → `record_ruling`。到此为止，不划转 |
| 接单上限 | 待批准 / 提案型服务 `capacity`（默认 1）· 窗口 300 s：窗口内接满即拒绝复签 / 退回提案卡，理由「已接满」；助手换下一家 |
