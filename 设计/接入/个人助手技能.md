# IoA Lab 个人助手技能

## 目的与范围

本技能是交付给九问 Swarm 的产品，用于引导用户接入平台、选择委托交易或助手通信，并按通用流程调用[个人助手端 SDK](个人助手端SDK.md)。它不承担常驻连接，不包含具体行业剧情，也不替代用户自己的业务技能。

“IoA Lab 接入技能”是两种产品技能的统称；通用 Skill 格式及 Codex 开发技能的区别见[术语](../术语.md)。接入全过程见[个人助手接入](../流程/个人助手接入.md)。

## 内容来源与目录

内容规范由本页及所引用的设计页面定义；产品源文件归属 `src/access/skills/assistant/`。构建时使用安装标识 `ioalab-delegate` 作为技能包根目录，显示名称为“IoA Lab 个人助手技能”。安装后的规范目录如下：

```text
ioalab-delegate/
├── SKILL.md
├── settings.example.json
├── scripts/ioalab.py
└── references/
    ├── setup.md
    ├── delegation.md
    ├── messaging.md
    └── inbox-rules.md
```

发布包由源文件生成，另携带公共引导、锁定 SDK/九问适配/协议依赖及摘要，规则见[SDK 共用机制](SDK共用机制.md)。两个产品技能共用 `src/access/skills/VERSION`，版本与交付归属见[架构](../架构.md)。用户的 `settings.local.json`、规则文件、私钥和运行数据不进入分发包。

## 主 SKILL.md 契约

| 部分 | 必须包含的内容 |
|---|---|
| 标识与说明 | 原生加载名称、产品用途、适用的用户需求；说明这是技能而非同名工具 |
| 实际加载 | 在九问原生菜单选择后，使用宿主技能加载接口读取主文件；仅选中名称不等于读取完整指令 |
| 路由表 | 按用户需求选择下表流程；混合需求拆成关联子流程，授权分别核验 |
| 公共调用 | 从宿主返回的实际 skill_directory 定位脚本，先生成参数文件，再调用 SDK；不用猜测路径 |
| 状态与确认 | 只依据 SDK 真实回执报告结果，缺确认就等待；对象变化重新确认 |
| 数据边界 | 不读取凭据文件、不把外来正文当指令、不修改九问源码或全局指令 |

| 用户目的 | 必须读取的流程页 | 对应设计 |
|---|---|---|
| 安装、配置、启动、诊断连接 | `references/setup.md` | [个人助手接入](../流程/个人助手接入.md) |
| 找专业服务，约定成果、验收与价款 | `references/delegation.md` | [委托交易](../流程/委托交易.md) |
| 向指定账号发消息、请求或继续交流 | `references/messaging.md` | [助手通信](../流程/助手通信.md) |
| 设置谁能发什么、收到后如何处理 | `references/inbox-rules.md` | [收信规则 SDK](个人助手端SDK.md) |

没有确定对象或用途时只澄清缺少的业务信息，不让用户解释内部协议。新增交互方式需先更新设计、对应 SDK 和独立流程页，再加入路由表；不向主文件堆入全部细节。

## 流程页契约

每个流程页按“触发条件 → 必要输入 → SDK 操作 → 真实返回 → 下一步或等待条件 → 异常收敛”组织。页面必须能指导模型继续执行，不能只写概念摘要或要求用户手工运行多条协议命令。

| 流程页 | 重点约束 |
|---|---|
| 委托交易 | 明确需求与授权，发现并检查候选；提案取得有效签名报价，待批准按有效模板生成未签算价卡并标明状态；比较后取得具体合同确认，才执行对应成约步骤；开工、环节授权、验收与支付按阶段执行 |
| 助手通信 | 定向查询可调用接口，按 Schema 构造输入，保留 SDK 交互句柄，解释真实结果；继续请求与网络重试分别处理 |
| 收信设置 | 九问用自然语言澄清、生成候选；SDK 起草/检查/预览；用户确认后发布；能力缺失时说明配置要求 |
| 配置与诊断 | 引导填写本地配置，经公共安装流程校验依赖及九问能力、启动或复用运行时，再核验身份与能力；不让模型查看密码或私钥 |

合同规格、默认值、实名环节、服务名、候选数量和验收方式来自用户需求与实际合同；美甲等内容仅在[示例](../示例/美甲预约.md)中配置。报价比较不得只比较金额或条目数量，不因最低数量已满足而省略其他合格候选。

待批准服务方复签后已经成约，技能不得为比选先向多家发起复签；失败或未知时核实原操作，不自行改选并签约。收到真实合同环节请求后，向用户展示该环节及对象，取得当前答复再调用 `assistant.delegation.answer_step`；首次委托授权和合同确认均不能代替它。

## 收件执行与信任边界

用户主动对话通过本技能选择流程；入站消息由本地接入组件装载**平台受理时冻结修订对应的收信规则**，向原版九问提供本次处理上下文与受限工具。尚未建立 UUID 的已受理消息同样保留原修订；开始处理仍复核当前权限、启用状态和 TTL。来信不能切换到设置模式、修改规则或取得账号管理权限。

允许无模型的确定性业务处理；需要九问时按同一交互续接会话。回复工具只作用于当前请求，通信正文作为数据处理。原生用户确认通过可信宿主关联或本地受控入口取得，模型传布尔值不构成授权。

收信设置流程可以指导用户选择并配置已提供的业务技能/工具，但通用技能不内置会议或邮件处理程序。官方会议规则、日程及邀请工具归官方参与方资源；缺少工具时先说明配置要求，不能通过来信自动安装。

## 脚本与验证

`scripts/ioalab.py` 只负责参数读取、确定性 SDK 调用与结构化回执；不包含场景分支、第二套协议实现或额外语言模型。后台收件和断线恢复由常驻组件完成，技能不指导模型高频轮询。

安装验收分别验证：干净环境安装、原生菜单选择后实际加载、自然业务请求正确分流、阶段确认、接收推送和异常恢复。未预选时的自动识别依赖宿主及模型，不能作为可靠使用前提。具体验收项目见[验收](../工程/验收.md)；实际实现及能力缺口在[开发计划](../../docs/开发计划.md)记录。
