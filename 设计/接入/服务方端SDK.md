# IoA Lab 服务方端 SDK

## 目的与范围

服务方端 SDK 为用户自己的九问提供登记、上线、接单与履约能力。它与个人助手端共用一个 IoA Lab SDK 包和[公共运行机制](SDK共用机制.md)，主动连接平台，不要求公网 IP。普通服务和官方服务使用相同入口。

本文定义服务配置与 SDK 能力；角色实现归 `src/access/sdk/ioalab_sdk/provider/`，共用连接、持久化和调度归运行时。接入过程见[服务方接入](../流程/服务方接入.md)，容量及承诺状态以[委托中心](../组件/委托中心.md)为准，目录与依赖边界见[架构](../架构.md)。

## 服务配置

| 配置 | 内容与校验 |
|---|---|
| 身份 | 所属账号、稳定 service/agentId 引用、本地签名及收款公钥绑定 |
| 公开说明 | 名称、说明、可选 A2X 分类、能力和材料要求；省略分类时由注册中心匹配并返回实际路径，不把模板当服务生产程序 |
| 合同模板 | A2C 原格式、验收器包及必要模型引用；按摘要核验并签认 |
| 成约模式 | 默认待批准或提案；不得用预批准绕过平台接单保障 |
| 接单上限 | `max_active_delegations`：有效预留与未结束承诺的上限 |
| 执行资源 | 业务技能、已授权工具和九问定义引用；`max_model_runs` 属于共用运行时 |

一个本地实例可运行同账号的多个服务；每个服务有独立身份、声明、容量和业务状态。配置降低上限时不取消已有合同；已有占用超过新上限期间停止新增预留，控制消息继续处理。

官方服务定义、模板、验收器及业务技能归 `src/official/services/`，通过显式配置和资源引用交给同一 SDK；通用服务方模块不导入官方目录，也不另建官方执行器。固定候选、报价与台词归 Demo 场景配置，不能成为服务方 SDK 的默认决策。

| 官方资源构造 | 契约 |
|---|---|
| 入口 | `ioalab_services.prepare` |
| 输入 | 原目录服务ID、本地profile、实际已发布的验收器引用、平台支付声明 |
| 输出 | `service`：未签公示及模板；`execution`：该profile的业务配置 |
| 依赖 | 复用SDK的 `template_from_definition`，不复制算价、签署或调度逻辑 |
| 模型资源 | 报价策略、验收引用、输出格式及业务说明；不包含sample交付样件 |
| 验收源码 | 只用于打包，不在宿主导入或执行 |


常驻配置的 provider.services 以本地 profile 为键；每项声明 instructions、skills、max_active_delegations 和 accepting，可选 resources 保存本服务已发布的验收器引用等业务数据。仅装配已配置身份与宿主；未配置专业处理规则时只提供公示，不接取业务。skills 为本机已安装的业务技能引用，不从来信加载；resources 不授予额外工具权限。验收器可以预先配置复用，也可在本单quote阶段按业务判据生成，再经provider.task.verifier.publish打包取得真实引用；不要求用户手工搬运每单资源。模型通过本单 quote 或 decision 工具输出结构化业务决定，SDK 保存决定后复用原 A2C 拟卡/复签；价格、验收条目、服务选择不由通用模块填充。

可选 native_tools 保存本机所有者预配的原生生产工具及精确权限，例如 {"write_file":"allow"}；省略表示不启用。SDK 核对原版公开能力及明确拒绝策略；未核实工具单独报告，不把权限表缺项当作不存在或已验证。实际缺工具、配置或调用失败不得伪报完成。工具、权限、业务技能及说明一起冻结于原交互；当前服务配置改变不扩大既有合同能力。固定 Agent 自拟卡首轮包含这些工具名，拟卡/复签时全部 deny，只有原合同生产轮次按冻结权限启用，同一 Session 的定义不变。

原生工具只用于本机已授权的业务生产，不能借其绕过 SDK 签约、付款、合同环节授权或外部效果恢复。日程、邀请邮件、实名注册等效果须使用已配置且核原授权/幂等记录的业务工具；不能因准许写文件就获得任意外部业务许可。工具白名单不保证工具参数或路径安全，仍遵守原宿主及业务工具的实际约束；传入业务文本不能选择新工具或权限。

装配入口可按服务profile注入本地业务工具；它们与固定生产工具一起纳入本单定义和策略摘要。拟卡/复签阶段不能调用；生产时输入Schema、原上下文、真实环节答复及原调用幂等均由SDK核对。外部工具执行不持共享协议写锁，业务结果未知时停止本轮新效果。工具包及凭据不来自委托消息，见[SDK共用机制](SDK共用机制.md)。

本机provider.tools.list输入profile，返回该身份已装配工具策略；不暴露其他身份的工具或凭据。

## 管理操作

| 操作 | 输入 | 输出及边界 |
|---|---|---|
| `provider.template.draft` | profile、terms（原A2C模板的业务字段） | 完整未签模板；SDK补协议版本、kind、当前时间起30天的有效期及实际平台支付声明，复用原A2C校验，不报价、不签署或发布 |
| `provider.configure` | 本地服务配置 | 配置草稿与缺项，不自动发布或修改已有合同 |
| `provider.validate` | 配置草稿引用 | 业务工具、宿主、模板/包、模式、身份和容量检查结果 |
| `provider.verifier.publish` | profile、verifierId、source，可选 reads、kind | 通过平台的确定性打包通道上传验收器源码，返回真实包引用；不在宿主执行源码，同操作恢复原内容 |
| `provider.preview` | service：profile、名称、说明、标签、未签模板及可选categoryId | 实际分类、完整service、contentDigest、expectedRevision；可发布时nextAction指向provider.publish申请确认，不创建批准记录 |
| `provider.publish` | 原预览返回的service、contentDigest、expectedRevision；可选原confirmationRef | 首次创建待确认记录并返回waiting；仅真实批准后恢复原操作才签名、市场签认及A2X登记 |
| `provider.reputation.submit` | 所属已完成合同引用、稳定操作标识 | 核验收与付款凭证，复用 A2C Provider.close 提交结清卡，查询平台签发信誉；重复调用恢复原结果，未结清不能伪造成功日志 |
| `provider.status` | 所属服务引用 | 公示、连接、可执行、容量、未完成任务、异常分别列示 |
| `provider.tasks.get` | profile，可选原taskRef | 返回该服务最近至多100个本地业务任务，或指定原任务；含阶段、状态、原交互/Session及canResume、resumeReason，不返回凭据或其他身份任务 |
| `provider.task.resume` | profile、原taskRef；共用operationId | 仅对已核实安全的验收器准备中断恢复原拟约作业；快速返回accepted及resumeReceipt、currentTask，后续查询原任务。accepted不代表拟约成功，不新建请求、签名或收费 |
| `provider.pause` | profile，原operationId | 允许公示前暂停；经当前WS设置实际接单策略，返回policyReceipt及currentPolicy；只关闭新预留，原有效预留及合同继续 |
| `provider.resume` | profile，原operationId | 核本机业务/工具/宿主、有效公示和当前连接后开启；返回原policyReceipt与实时currentPolicy，不把旧成功回执当作当前仍开启 |

### 接单策略的归属与恢复

平台admission策略是实际状态；本地accepting和max_active_delegations是用户配置输入。SDK保存上次已处理的配置快照；首次应用两个字段，后续只应用相对上次配置明确改变的字段，未改变字段保留平台现值。pause/resume明确改变开关，公示前暂停同样保存已见配置，发布、重连或同配置重启不能重新启用。容量降低不取消已有占用。

策略写入前保存原操作、配置快照及expectedRevision；未知时恢复同一WS请求，取得终局前不越过它执行另一次策略写入。原回执、已处理配置快照和清除待处理记录同事务保存。重复原操作返回原policyReceipt，并另外读取currentPolicy；不重放旧开关。并发策略修改用平台修订检查拒绝覆盖，不能读新修订后悄悄重做失败操作。

provider.status额外返回当前WS核实的admissionPolicy；executionReady只表示执行能力，不等同接单开关。原意向重传由平台恢复已有预留，SDK不能因当前暂停而把已取得预留的同单误判成新单。失败返回实际原因，未取得真实回执不能宣称已暂停或恢复。

运行时启动/停止使用公共 `runtime.start/stop`。服务发布的各阶段有独立回执，部分失败恢复原操作；不能因 A2X 已显示就宣称模板签认或模型执行已就绪。模板更新和官方续期规则见[注册中心](../组件/注册中心.md)。

模板起草的terms直接使用原A2C字段：formation、deliverables、deadlines、pricing及可选inputs、acceptance、authorizableSteps、samples、extensions；不新建一套合同字段。a2cVersion、kind、validUntil、provider、templateDigest、signatures和pricing.paymentProviders由SDK持有，不由模型猜测。支持原协议多交付件及两种普通接入模式；价格、规格、判据、期限、环节与金额权重由业务决定，SDK不代填。普通起草不上传sample，不执行验收器。相同操作和参数恢复原模板与有效期，异参数返回冲突；要重新起草使用新操作。官方定义转换与本入口共用协议元信息构造，不复制算价或验收逻辑。

公示调用分为 `provider.preview` 和 `provider.publish`：预览输入本地profile、名称、说明、标签、可选categoryId和未签模板草稿。SDK取得注册中心分类预览后，保存并返回完整解析后的service、category、内容摘要及当前预期修订；省略分类时，preview通过持久的非模型本地作业请求平台，RPC先返回accepted和job引用，不占用所属用户的模型名额，也不持共享锁等分类模型。原操作重传在作业完成后返回已保存结果；不能确定分类时只返回待选择和实际选项，不产生可发布摘要。可发布的preview返回nextAction={operation:provider.publish,purpose:request_confirmation}；不能确定分类时没有此动作。publish使用预览返回的完整service、contentDigest和expectedRevision，首次调用创建绑定原操作的待确认记录，返回waiting、confirmationRef及nextAction={operation:runtime.open_ui,purpose:collect_user_decision}；此时尚未签名或公示。按[共用确认流程](SDK共用机制.md#用户确认)取得本机用户真实决定后重发原操作，才生成provider模板签名和声明证明，保存完整请求后上传。拒绝或过期不执行新效果。用户确认页包含实际分类路径。签署前只按已确定categoryId复核当前叶类及路径，不重新调用匹配模型；类别已删除时拒绝发布；待确认记录绑定的路径发生变化时拒绝沿用原确认，重新预览并确认。模型的confirmed字段不是授权。回执丢失时恢复已保存请求及原平台操作，不能重新生成签名时间、模板期限或更换分类。返回分别列出 publicationReceipt 和 currentPublication，避免把旧成功回执当成当前修订。

## 入站接单与任务工具

入站消息由运行时确定性分派。服务方 SDK 先检查身份、结构、协议时效和接单策略，通过 `admission.reserve` 取得平台预留并可靠返回原请求；平台提交容量后才允许形成有效承诺。满额拒绝新委托，既有合同继续处理。接单结果、交互关联和合同成立分别记录。

| 任务能力 | 输入 | 输出及限制 |
|---|---|---|
| `provider.task.inspect` | 运行时授予的本单 taskRef | 本单模式、原合同/提案、材料、阶段与可用能力；不返回其他任务或凭据 |
| `provider.task.verifier.publish` | 本单verifierId、UTF-8源码source，可选reads与kind（script/skill）；源码至多64 KiB | 仅提案quote阶段可用；与管理上传共用打包、包摘要核验及原操作恢复，返回真实id/uri/digest；不执行源码、不签约、不修改公示或配置 |
| `provider.task.quote` | 符合本单模板的确定报价、验收条目与验收时长，或单独拒绝原因 | 返回业务决定已记录；SDK 后续复用原 A2C 拟卡/签认，实际结果从原任务读取；不能绕过期限或容量提交 |
| `provider.task.decision` | 本单待批准 taskRef、批准或拒绝及原因 | 仅处理真实 card.countersign 请求；批准前复核委托方签1、卡摘要、期限及接单资格，原子提交预留后复用 A2C 复签形成签2；拒绝返回原协议原因，不签约 |
| `provider.task.request_step` | 已开工合同、模板声明的环节名 | 复用 A2C Provider.request_step，产生签名 stepRequest 并经原任务推送；保存等待状态，收到对应有效授权前不执行受保护动作 |
| `provider.task.selftest` | 本单候选成果 | 用合同验收器进行自测，返回真实报告；不修改判据、不替委托方验收 |
| `provider.task.deliver` | 本单通过检查的成果引用 | A2C 原协议交付与存证结果；只有真实回执才报告已交付 |

上述操作是 A2C Provider 原语的本单适配，不定义第二套合同状态机。业务技能负责实际生产；SDK 负责协议与权限。九问任务由运行时固定当前交互、Session、技能及工具能力，来信不得选择平台管理模式或另一任务。

宿主任务工具的本单上下文由 SDK 固定；模型不传入或更换 taskRef、UUID、签名身份及 Session。quote 的 acceptance、acceptWithin、lineItems 均以实际模板交付件名为键，拒绝报价时只提交 reason，不把说明文本混入成功报价的拒绝分支。

SDK 每轮明确给出当前协议阶段、所需动作和输入 Schema；业务技能说明不改变当前阶段。调用其他阶段工具时返回准确的本单拒绝原因和允许动作，由同一轮次纠正；不能把审查已确认合同变成重新报价，也不把错误提示的改进当作新增授权。

本单验收器回调由SDK绑定当前身份、作业和交互，模型不传profile、UUID或会话；同一本单同内容复用原上传记录，不因宿主调用ID改变而重复准备；每个quote作业至多准备32份包。SDK上传前复用原A2C清单校验，明确返回reads等格式错误；reads声明合同规格/材料字段路径，不是交付文件名。平台对最终包完成原A2C核验后才保存并返回引用，不生成已知无效的公示资源。原输入、待核上传和已取得引用由SDK保存，显式恢复先核原上传，再把已准备引用带回原Session。收到真实引用后才能填入quote；上传未知时保留原输入并结束本轮，核对后恢复，不能编造引用继续。报价决定已记录、待批准审查或生产阶段均不得再创建本单验收器；已签验收标准不能被此入口改变。

### 原拟约任务的恢复

| 检查 | 规则 |
|---|---|
| 查询 | 本机服务管理入口按所属profile查询原taskRef；SDK保存并返回关联，用户不手抄UUID。任务状态与恢复入队回执分别展示 |
| 可续接证明 | 仅quote阶段、验收器上传结果未知、原宿主轮次明确返回completed或failed终局且Session已保存、尚无报价决定；SDK保存已结束轮次的事实。进程重启或上传pending本身不构成证明，普通模型异常和其他未知效果保持unknown |
| 显式恢复 | 本机用户明确要求后调用provider.task.resume；核原任务、服务身份、交互、Session、定义摘要、原期限及可执行能力。暂停新接单不阻止已承接任务的恢复 |
| 持久入队 | 调度器同事务保存恢复操作回执与原作业续接；相同operationId重传返回原resumeReceipt，并另列currentTask，不因后续再次unknown而重新入队；同操作指向另一任务报冲突 |
| 再执行 | 原作业先核同内容上传，再把preparedVerifiers带回原Session。调用A2C Provider.resume_request及原finish，复用原A2C任务、请求、材料核验、拟卡费凭证与respondWithin，不重新request.submit |
| 新轮次 | 真正调用宿主前清除上次可续接证明；若新轮次结果不明，不能沿用旧证明。SDK仍使用原会话串行、模型并发及容量约束，不提供任意任务重跑入口 |

quote 工具明确区分三类验收器引用，不要求每项交付同时包含三类。保存业务决定前复用 A2C 校验卡结构、包摘要与清单种类；错误返回本单准确校验原因，由原模型轮次修正，不自动删改业务条款，不因此重收费或另起委托。

待批准模式的签2即成约，不能用 decision 给多个未获用户具体确认的候选预先复签。批准或签署结果未知时恢复原操作，不生成另一份承诺；拒绝和过期均返回实际原因。

待批准的 held 只允许接收原签1卡及审查，不允许直接签2。原 Provider 审查回调完成业务检查后提交容量，提交成功才返回批准；失败返回真实拒绝，不由模型自行绕过。这样服务方能先取得提交所需签名原件，也保留签2前的原子容量保障。

环节授权经原交互和任务回到委托方，个人助手端 `assistant.delegation.answer_step` 消费当前请求绑定的真实用户答复，并调用 A2C 原语返回同意或拒绝。服务方 SDK 核对 stepRequest 摘要、签名、当前阶段和期限后恢复；拒绝不能当作同意继续执行该动作。授权等待及期限计算仍遵守 A2C，服务方不能替委托方回答。业务工具可按服务配置扩展，不强制所有服务只使用官方样例工具；任何新增外部效果都须受本地授权约束。

生产工具的上下文继续绑定原交互、原 Session 和固定 Agent 定义；完整调用与等待规则见 [A2C 适配](A2C适配.md)。request_step 输入 step，SDK 派生原卡和期次，返回原请求及等待状态；selftest/deliver 的 files 以交付文件名为键，每项含 mediaType，以及 text、bytesBase64、artifactPath 三选一。artifactPath 仅指本次工作区 artifacts 下的相对文件，不接受任意本机路径。自测只返回实际报告；deliver 只有取得原签5才返回已交付。

发出环节请求或交付后，本轮停止产生新的业务效果，等待真实答复或本期验收及应付款凭证；后续阶段由同一 Session 续接。业务工具读取原授权状态，不以模型称“已同意”为凭据。原任务的控制收件保持可用；宿主缺失、离线或原定义不兼容时，明确停止新生产，不另开一个无历史的 Session。

## 部署发布授权与续期

普通账号仍逐次通过真实用户确认公示。服务方SDK从平台所属状态读取部署发布授权；仅目标身份、全部公开条款及寿命满足[注册中心](../组件/注册中心.md#部署发布授权)规则时，才以该授权修订替代本次公示确认，并在IoA公示外层附authorizationRevision。模型不能提交授权、confirmed字段或选择绕过确认；授权不匹配时普通操作仍需用户确认，官方自动启动器则停止并报告需部署方配置。

同一发布operationId在首次选择授权来源后固定使用该来源。已存在用户确认的操作继续遵守其原决定；后增部署授权不得绕过待确认、拒绝或过期。使用部署授权的原操作在首次签署前复核相同授权修订，失配时停止；未知网络结果仍先恢复原已签请求。

条款摘要计算为`provider.publication_terms(protocolId,service)`的纯函数，不发网络请求、不签名；只按注册中心的明确排除字段处理模板。返回的术语和实际字段见[平台接口](平台接口.md)。授权、公示、接单和模型执行是不同状态，不能因已获公示授权恢复已暂停接单。

SDK保存签名请求及当时的授权修订后再上传；未知结果先查询原操作。原公示已成功但索引未就绪时，重发同一已保存请求以恢复当前投影，不重新签署、轮换模板或覆盖后续修订。续期由启动器给出新的有限有效期，原合同及其模板引用保持不变。


## 暂停、恢复与失败

| 情况 | 处理 |
|---|---|
| 新委托超限 | 返回明确满额结果，不付款后才发现无法接单 |
| 等待合同确认、授权或验收 | 继续占接单名额；业务等待可释放模型执行名额 |
| 零拟卡费 | 仍在有效签署前原子提交预留，不能跳过 admission |
| 已付拟卡费但拟卡失败 | 核对原付款及有效承诺后关闭；不自动重复收费或无依据释放 |
| 服务重启或未知签署 | 先核对平台台账、A2C 原件及工具回执，再接新单 |
| 模型称完成但缺交付回执 | 保持未交付状态，有界补齐；不伪造合同完成 |

释放容量、有效承诺窗口和未知付款的详细条件只在[委托中心](../组件/委托中心.md)定义。各工具必须维护原操作幂等，网络重传不创造第二份承诺。
