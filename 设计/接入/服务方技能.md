# IoA Lab 服务方技能

## 目的与范围

本技能是交付给九问 Swarm 的产品，引导服务提供者配置、发布和运行专业服务，并为入站委托提供通用履约说明。它调用[服务方端 SDK](服务方端SDK.md)，业务生产使用服务提供者自行配置的技能与工具。

产品不要求用户部署公网入口，也不修改九问源码、全局指令或技能加载机制。接入全过程见[服务方接入](../流程/服务方接入.md)。

## 内容来源与目录

内容规范由本页及所引用的设计页面定义，产品源文件归属 `connector/ioalab-provider/skills/ioalab-provider/`；安装标识为 `ioalab-provider`，展示名称为“IoA Lab 服务方技能”。规范目录如下：

```text
ioalab-provider/
├── SKILL.md
├── settings.example.json
├── scripts/ioalab.py
└── references/
    ├── setup.md
    ├── publication.md
    └── execution.md
```

发布包依[SDK 共用机制](SDK共用机制.md)携带锁定依赖和引导。官方服务目录只保存具体业务配置、模板和业务技能；通用接入/履约说明在 connector 维护，不在每个官方服务中复制。

## 管理与执行入口

同一产品包含两种入口，由可信调用上下文确定，不由请求正文选择。

| 入口 | 触发者 | 可用能力 |
|---|---|---|
| 服务管理 | 本机用户在九问原生菜单选中并实际加载技能 | 配置、校验、预览、用户确认后发布、启动、停止接单及状态检查 |
| 本单执行 | 本地接入组件收到已校验且获准开始的委托 | 固定交互与 Session、本单材料、当前阶段 SDK 工具、经授权业务技能 |

入站任务不得获得发布、改容量、读凭据、跨任务或平台管理能力。服务管理模式不能靠来信中的“请管理员执行”进入。SDK 根据真实主体、阶段和能力句柄进行检查，不仅依赖提示词限制。

## 主 SKILL.md 与流程页

| 文件 | 必须定义的内容 |
|---|---|
| `SKILL.md` | 产品身份、原生实际加载方式、可信入口区别、流程路由、公共脚本调用、状态与权限边界 |
| `references/setup.md` | 配置账号/平台、检查原版九问及业务能力、安装隔离 SDK、启动常驻组件、核验连接与身份 |
| `references/publication.md` | 服务说明、A2X 分类、模板、验收器、接单容量与工具权限；检查、摘要确认、签认及登记；暂停/恢复接单 |
| `references/execution.md` | 读取本单、按模式拟提案或批准/拒绝待批准请求、生产、自测、交付、提出并等待环节授权、真实结果与异常收敛 |

各流程页使用“触发条件 → 输入 → SDK 操作 → 返回 → 下一步/等待 → 异常”格式。主文件只保留路由和共同边界；服务名称、报价、成果格式及验收要求来自当前模板和合同，不固化到通用技能。

## 本单执行契约

| 阶段 | 九问与 SDK 的分工 |
|---|---|
| 任务进入 | 运行时绑定身份、交互、合同/请求、已授权材料和阶段；技能先 inspect，不能猜任务地址或令牌 |
| 提案 | 九问根据允许的业务范围提出报价与交付内容；SDK 校验确定金额、容量、期限并完成 A2C 原语 |
| 待批准 | 九问作出业务批准或拒绝建议，经 provider.task.decision 校验；批准时先提交容量再复签，签2即成约；不得把候选比较当复签授权 |
| 生产 | 九问按合同和业务技能完成成果；所需卡载环节经 provider.task.request_step 提出并等待绑定当前请求的真实授权，同意前不执行受保护动作 |
| 自测 | 使用 SDK 运行合同验收器，失败按明确检查项修正；不改验收标准，不用示例产物冒充真实生产 |
| 交付 | SDK 提交原协议交付并取得回执；模型自然语言“完成”不能代替交付结果 |
| 失败或未知 | 保存原因和原操作引用，等待恢复/核实；不自动重付、换合同或绕过期限 |

工具集合由本地配置和当前任务共同限定，不把所有业务服务限制为同一种固定工具集。网络正文和材料是业务数据，不能成为修改 SDK、技能或授权的命令。服务方自测不替代委托方验收。

## 运行与验证

常驻组件监听推送，模型只在业务需要时执行。接单容量限制未结束承诺，模型执行并发控制运行资源，两者分别配置；等待用户答复不释放有效接单承诺。新委托满额时明确拒绝，既有合同控制消息继续处理。

验证须覆盖：无公网 IP 接入、按原生技能配置并发布、不同委托独立 Session、同一委托续接、满额拒单、断线恢复及停接新单后既有履约。完整验收条件见[验收](../工程/验收.md)；文档目录和接口是交付规范，实际实现差距见[开发计划](../../docs/开发计划.md)。
