# 平台接口

## 目的与范围

定义平台与 IoA Lab SDK 之间的网络契约：HTTP 入口、WebSocket 帧、消息封套和恢复查询。消息投递及收信权限规则由[消息中心](../组件/消息中心.md)定义，合同与签名规则直接复用 A2C。本文是接口设计，不表示所有入口均已实现；实现差距见[开发计划](../../docs/开发计划.md)。

## 网页观察接口

这些接口服务于获准浏览器，读取已保存事实，不执行参与方业务。字段中的合同摘要与交互ID沿用原定义；没有的证据不填成成功。

| 入口 | 返回与权限 |
|---|---|
| GET /api/workbench | 本账号身份、委托意向、所属合同/服务、实际付款、统一助手消息、本人收信接口及裁剪事件；其他用户私有数据不进入响应 |
| GET /api/catalog | 当前公开服务名称、分类、说明、模板可用及连接/接单状态；不返回其他用户执行配置 |
| GET /api/admin/delegation-intents | 尚无合同卡的委托意向元数据，含originMessageId及已有interactionId/接单记录，不返回私人需求正文 |
| GET /api/admin/orders、/api/admin/messages | 全景元数据；不返回私人输入、消息正文或完整合同 |
| GET /api/admin/messages/{messageId} | 当前auditor读取统一消息原正文/结果并产生审计记录；一般管理员或受限SDK拒绝 |
| PUT /api/admin/users/{userId}/roles | admin提交roles、expectedRoles，集合仅含admin/auditor且auditor须同时具有admin；原子比较，返回目标账号当前roles；重复目标结果不重复修改，竞争返回冲突 |
| GET /api/admin/events、/api/admin/replay/{run}、/ws/admin | 同一允许字段投影；历史补齐不领取智能体消息、不改变业务游标 |

观察事件的迟报标记为布尔值stale：管理员事件位于detail.stale，工作台裁剪事件位于顶层stale，未标记等同false。该字段仅描述快照相对当前投影的先后关系；显示与回放规则见[通用规范](../界面/通用规范.md)。历史和回放读取数据库已提交原件，JSONL仅为导出。

助手消息视图显式包含deliveryState、requestState、readState=unknown及原interactionId；处理结果与投递回执独立。合同视图区分原卡验签所得effective、签名进度、原市场结局和实际payments。集合、历史和正文详情均先在服务端核账号/角色后查询；不能把全部数据发给浏览器再隐藏。

## 部署发布授权接口

| 入口 | 契约 |
|---|---|
| POST /api/admin/publication-authorizations | 当前Web管理员提交operationId及changes数组，1—64项且身份不重复；每项恰为agentId、expectedRevision、termsDigest、maxTemplateSeconds、enabled。目标限内部ISP已绑定服务，首次预期修订0；maxTemplateSeconds为60—31622400的整数，enabled为布尔值。整批事务比较并保存，返回原authorizationReceipt及currentAuthorizations |
| GET /api/admin/publication-authorizations | 当前管理员读取授权状态；包含已撤销记录，不用删除实现撤销 |
| GET /api/v1/services/{agentId}/status | 所属SDK查询额外publicationAuthorization；不存在时为null，否则包含agentId、revision、termsDigest、maxTemplateSeconds、enabled；不返回管理员凭据 |
| POST /api/v1/services/{agentId}/publications | 普通请求仍为operationId、declaration、proof、templates；使用部署发布授权时由SDK内部附正整数authorizationRevision，不能增加A2C模板字段或省略原签名 |

GET返回currentAuthorizations数组；POST的authorizationReceipt包含operationId、authorizations和acceptedAt，authorizations是该次提交原结果，外层currentAuthorizations是当前记录。两者不得混同。

termsDigest为完整公开条款的规范摘要，计算规则只在[注册中心](../组件/注册中心.md#部署发布授权)维护。请求的原操作标识与原参数不可改变；重复操作恢复历史回执，currentAuthorizations反映查询时的当前状态，不能把旧成功当作当前仍启用。授权设置在写入事务复核管理员权限，受限SDK Bearer不能设置授权。授权修订冲突、身份不符、条款或寿命超范围均不提交新的公示。


所属GET /api/v1/services/{agentId}/status另含publishedTermsDigest及templateExpiresAt，分别对应当前完整条款摘要和全部当前原模板中最早到期时间；未公示时为null。过期不删除当前原件，观察值仍可用于续期判断。

## 通道与认证

| 通道 | 用途 | 身份要求 |
|---|---|---|
| HTTPS | 登录、目录和历史查询、配置发布、文件传输 | 浏览器 cookie 或 SDK Bearer；按入口检查归属 |
| `/ws/agents` | 智能体业务消息、任务进展、回执和控制操作 | 一次性短时票据首帧认证；连接绑定账号及获准的 agentId 集合 |
| `/ws/admin` | 浏览器观察订阅 | 浏览器授权上下文；不领取业务消息、不更新收件游标 |

票据不放 URL。连接中的每次操作显式选择本端 `agentId`，平台核对票据范围及该身份的执行代次；封套 `sender` 由平台确定。一个运行时可管理多个身份，每个身份分别维护租约、游标和状态。连接建立/刷新不等于用户名密码登录。

| `POST /api/v1/identity/challenge`；`POST /api/v1/identity` | 一次性挑战 → 本地签名绑定对象 → 稳定 agentId 与绑定结果 |
| `POST /api/v1/connections/ticket` | SDK Bearer 及 agentIds 数组 → ticket、expiresAt；仅限所属的 1—64 个已登记身份，不接受浏览器 cookie 代替 Bearer |
| `POST /api/v1/search`；`GET /api/v1/providers/reputation` | 分类/需求 → A2X 候选、现有服务状态快照及真实信誉；完整模板另按返回引用取得并验签 |
| `POST /api/v1/services/{agentId}/publications`；`GET /api/v1/services/{agentId}/status` | SDK Bearer；签名服务声明、模板原件和 operationId → 原发布回执；查询当前公示及索引状态 |
| `GET /api/v1/services/categories` | SDK Bearer；返回实际A2X叶类及路径、说明和分类规则 |
| `POST /api/v1/services/category-preview` | SDK Bearer；name、description、tags和可选categoryId → matched或choose_category、实际路径/依据、目录摘要；不登记、签署或发布 |
| `POST /api/v1/messaging/interfaces`；`GET /api/v1/messaging/interfaces` | 公开声明、权限、内容摘要、预期修订及操作标识 → 新修订；查询自己的声明 |
| `POST /api/v1/scopes`；`GET /api/v1/scopes/{scopeDigest}`；`POST /api/v1/scopes/{scopeDigest}/close` | SDK Bearer、actor及稳定操作；登记 context/grant/proof、查询预算或关闭新许可；仅所属账号可操作 |
| `GET /api/v1/messaging/accounts/{username}/interfaces` | URL 编码的精确账号 → 获准使用的接口、当前修订及目标 agentId；不返回私有处理步骤或完整白名单 |
| `GET /api/v1/interactions` | 本端 agentId + originMessageId → 建立状态、已登记 UUID 或建立前终态；也可按有权读取的 interactionId 查询 |
| `GET /api/v1/messages/{messageId}` | 本端 agentId → 原消息的投递/处理状态及权限允许的已存结果；不存在与无权读取均不披露内容 |
| `GET /api/v1/operations/{operationId}` | 本端 agentId + 操作类型 → 原平台控制/发布/付款操作结果；付款返回原 AP2 凭证，不重新执行 |
| `GET /api/v1/payments/{paymentId}`；`GET /api/v1/payments` | 按 paymentId，或 ref + purpose + period 查询；仅原付款/收款账号可读原摘要、voucher 与 Payment Receipt；无此权限或不存在统一返回不可读，不触发付款或重新签署 |
| `GET /downloads/ioalab-skill.zip`；`GET /downloads/ioalab-client.zip` | 下载配置目录中的通用接入包；缺失返回未就绪，不从源码相邻路径查找或在请求中触发构建，不包含用户配置 |
| `POST /api/v1/provider/packages`；`GET /api/v1/packages/{digest}` | 验收器包 → 内容摘要；按摘要获取原包，SDK 必须核摘要 |
| `POST /api/v1/files/{agentId}` | SDK Bearer、原上传 operationId、name、digest 查询参数及原始字节 → 私有文件引用；单文件最多16MiB，同操作异内容冲突 |
| `GET /api/v1/files/{fileId}?agentId=…` | SDK Bearer 及所属读取身份 → 已获准文件原字节；不存在或无权统一不可读，下载方复核摘要和字节数 |
| `POST /api/v1/observations`；`GET /api/v1/orders/{digest}` | 所属过程上报；有权查看的合同观察投影 |
| `POST /api/v1/arbitrations` | 当事方合同、交付与验收证据 → 争议受理/裁定引用 |
| `/a2a/market`；`/a2a/pay` | A2C 公共服务与 AP2 原协议接口，保留原请求、签名和响应 |
| `/a2a/agents/{agentId}` | 稳定协议地址：提供已签名公开元数据，并将获准协议请求转入统一投递适配 |

注册、发布及登录重传使用稳定操作标识；查询无权代签、验收或付款。材料与交付件使用有归属检查的文件通道，消息只携带引用与摘要。公开协议地址不要求服务方暴露公网端口；平台不抓取用户任意 URL，也不生成参与方私钥。

### 搜索中的服务状态快照

搜索保持A2X返回的候选、顺序及原始card，在每个hit的顶层增加availability，不改写card或其签名资料。availability来自与公开目录相同的现有状态投影，不新增心跳、探测或后台任务，不因离线或满额隐藏命中。

| availability字段 | 含义 |
|---|---|
| observedAt | 本次读取快照的UTC时间，不是服务方承诺时间 |
| status | 现有公开状态：listed、offline、paused、busy、online、unavailable或disabled；不将已登记、连接在线或模板有效单独视为可接单 |
| activeDelegations | 当前仍占接单容量的委托数 |
| maxActiveDelegations | 当前接单策略的容量上限 |

没有对应公开投影时availability为null，表示未取得状态，不伪装为online。快照用于识别当时的离线、暂停或满额情况，不保证宿主可执行，也不预留容量；正式征集仍读取并核验完整模板、材料、规格、验收依据、期限及信誉，由实际接单门禁决定是否接纳。状态不包含所属账号、连接标识、私有执行配置或业务正文；历史搜索中的快照不能冒充当前状态。

注册和登录 body 含 operationId、username、password，注册另含 display_name 与 invite；操作绑定调用通道，不能用 SDK 操作取得浏览器管理员凭据。响应含原操作标识与 credited；登录重传恢复原令牌有效期。续用入口只读 Authorization Bearer，不接受 cookie 代替，不产生新的登录记录。

角色绑定的 challenge body 为 operationId、role（assistant/service）、agentId；服务 ID 使用 `svc-` 加本地 UUID，个人助手保留本地稳定 URN。响应包含 challenge、expiresAt、protocolId 和当前 phase。提交绑定 body 含同一 operationId、challenge、owner、platform、role、agentId、name、source、keys、proof；source 为 client/provider/experiment，keys 的 assistant 用途为 agent/user/payer，service 用途为 agent/payee。agent/user 为 Ed25519 公钥，payer/payee 为 P-256 公钥，禁止私钥字段。proof 是以相应 agent 密钥签署完整绑定对象摘要的 A2C 签名，slot 使用 client 或 provider；绑定时按提交的内联公钥验签，proof 不携带 kid，公钥可保留后续 JWKS 发布用的 kid。protocolId 由平台导出，不由调用者提供任意 URL。

绑定返回 agentId、protocolId、role 与公钥映射。已绑定表示身份就绪，登记模板、分类、连接和可执行状态分别报告。服务稳定地址至少提供已绑定公开 JWKS；未完成业务发布或执行门禁时明确未就绪，不宣称已上线接单。

分类预览的结果字段为status、categoryId、categoryPath、reason、taxonomyDigest和categories；无法确定时categoryId为null、路径为空，并返回可选择的实际叶类。指定categoryId必须非空且属于实际叶类；无效分类返回category_required。自动匹配故障不泄露模型凭据或原始异常。分类预览不是发布凭据，最终上传仍核签名声明和当前目录。

发布 body 为 `operationId + declaration + proof + templates`。declaration 固定字段为 schema（ioalab.service/1）、agentId、protocolId、revision、name、description、tags、categoryId、templateDigests；proof 使用绑定服务 Ed25519 密钥签署 `digest(declaration)`，slot 为 `ioa-service`。templates 与摘要列表一一对应，提交 provider 已签署的 A2C 原模板，平台返回回执中的原签认模板。`GET /api/v1/operations/{operationId}?agentId=…&operation=service.publish` 恢复原回执，不刷新期限。

稳定地址提供 `/.well-known/agent-card.json`、`/.well-known/jwks.json`、`/publication` 和 A2A `template.get`；publication 返回声明、proof 与声明摘要。Agent Card 由锁定 A2C 公开构造器生成，不接受上传任意远端接口。未发布身份只提供 JWKS；模板读取不表示允许开始委托。

发布回执包含 agentId、acceptedRevision、declarationDigest、templateDigests、原签认 templates 和 acceptedAt。status 返回当前 revision、published、declarationDigest、categoryId、indexedRevision、indexedCategoryId、indexReady、templateReady、activeTemplateDigests 和 executionStatus；索引就绪与有效模板不代表执行就绪。

## WebSocket 帧

帧是 IoA 平台的接入协议，不宣称为 A2A 标准 WebSocket 绑定。认证后控制帧结构为 `type + operationId + agentId + generation + payload`；认证前只有携带票据和恢复游标的 `connection.auth` 合法。`operationId` 在首次发送前持久化，恢复同一操作必须沿用；只读查询可使用一次性请求标识。

| 帧/控制操作 | 输入 | 输出与持久边界 |
|---|---|---|
| `connection.auth` | ticket、持久 runtimeId、各身份已连续保存的 cursors | connection.ready：connectionId、各身份 generations、服务端已确认游标、heartbeatSeconds、leaseSeconds；历史缺口显式返回 |
| `connection.ping/pong` | 连接标识 | 心跳与租约有效信息，不产生登录赠币 |
| `message.send` | 本端身份、消息封套 | 校验并持久化后返回 `accepted` 与原 messageId |
| `message.deliver` | 平台推送消息及 recipientSeq | 接收端落库后发送 `message.ack` |
| `message.ack` | messageId、连续保存的游标 | 平台确认已送达；不表示已开始或已完成 |
| `request.start` | 原请求 messageId、interactionId、当前代次 | 按原请求核验并保存 startedAt，返回原许可；已成约A2C请求另含contractCard及有实际记录时的depositVoucher，供宿主绑定原有效签1/2/3和实付凭证，不表示开工或新增授权 |
| `interaction.close` | interactionId；未建立时使用 originMessageId；关闭原因 | 原子关闭入口，可靠产生 `interaction.closed`；委托先通过委托中心核验 |
| `admission.reserve/commit/release/status` | 交互、服务、绑定摘要、预留及相关证据 | 委托中心原子预留/提交/核实释放；返回原台账记录 |
| `scope.register/status/close` | context/grant/proof；或 scopeDigest | 用户签名授权、原记录恢复、预算查询及拒绝新许可；关闭不解除合同 |
| `scope.select` | scopeDigest、完整原卡和用户选择证明 | 验证后预留完整价款；只绑定一份 cardDigest，不执行 A2C 签1或付款 |
| `contract.bind` | admissionId、完整原有效 card | 原个人助手连接登记同单生效签1/2/3；核原承诺、范围选择和双方，返回原成约事实，不开工或付款 |
| `a2c.market` | admissionId、op、原 body；card.endorse 另带原 signed request | 当前服务连接申请 card.endorse、delivery.anchor 或 card.close；按阶段核承诺/成约、实际原件与付款证据，返回原 A2C Reply |
| `operation.get` | 原操作标识与类型 | 查询同一操作的已存结果；与 HTTP 恢复查询读同一记录 |

普通业务结果由持久消息返回；控制操作超时先查询原操作，不重新生成标识尝试同一副作用。平台拒绝旧代次发起新的执行，但允许当前执行者恢复已有操作结果。平台自己产生的关闭/到期通知使用平台系统身份，参与方不得伪造。

控制响应统一为 `operation.result`，包含 agentId、operationId、operation、ok，以及 result 或 error；多身份连接按完整三元组关联原操作。推送 `message.deliver` 包含 message、recipientSeq 和独立的 deliveryState；投递状态不修改原封套摘要。认证失败关闭连接；被新代次替代的连接使用关闭码 4409，旧运行时停止自动重连并报告已失去执行权。

`runtimeId` 由本地实例首次建立时生成并持久保存，不是账号或会话标识。另一个 runtimeId 在原租约仍有效时不能自动接管；同一实例网络重连递增代次。ACK 的 through 为该身份连续持久保存的 recipientSeq，不能超过已接受序列；过期消息的元数据占据原序列位置，恢复时仍显式返回，不能跳过缺口。

`POST /api/v1/messaging/interfaces` 的输入为 operationId、name、expectedRevision 与 definition；definition 仅包含公开说明、object 根输入/输出 Schema、allowedSenders、enabled、完整本地规则的 contentDigest。原文处理步骤不上传。发布返回不可变修订和目标 agentId；读取及发送均复核当前权限，操作重试不重复建立修订。

## 持久消息封套

| 字段 | 必填条件与来源 |
|---|---|
| `messageId` | 必填；发送端 UUID，平台全局唯一；相同发送者及内容重传返回原记录，冲突不覆盖 |
| `kind` | 必填；下表中的明确类型，不从自然语言猜测 |
| `recipient` | 必填；目标稳定 agentId |
| `interactionId` | 已建立交互必填；首次业务请求省略；由原接收端生成后登记 |
| `originMessageId` | 建立/关闭及建立前错误必填；指向原始请求，用于恢复关联 |
| `inReplyTo` | 业务结果必填；指向实际请求，限制返回对象与结果格式 |
| `expiresAt` | 必填；UTC RFC 3339 时间，受平台及业务期限约束 |
| `body` | 必填；由 kind 指定结构；不改 A2C 原字段、摘要或签名 |
| `sender`、`acceptedAt`、`recipientSeq` | 平台赋值；客户端不能声明其他主体或入队顺序 |

封套不携带九问 Session ID、私钥或模型凭据。UUID、admission、路由及连接代次属于平台运行数据，不进入 A2C 合同。

| kind | body 的必要内容 | 关联约束 |
|---|---|---|
| `delegation.intent` | formation、templateDigest、scopeDigest、bindingDigest，及未签 request（提案）或 card（待批准） | 首次请求不带 interactionId；原协议摘要不含后续签名，只表达意向，不形成合同；材料仍走有权文件通道 |
| `delegation.result` | outcome；成功时 admissionId、绑定摘要、holdUntil；拒绝时 error | 原意向的 inReplyTo；建立后沿用已登记 UUID |
| `a2c.request` | 原协议方法/请求、任务引用及 admissionId 等外层元数据 | 必须已有委托交互；原协议请求 ID 与签名保持原义 |
| `a2c.result` | 原协议响应/任务进展与原任务标识 | 绑定原请求；进展不冒充终态，不反派为新请求 |
| `message.request` | interfaceName、revision、input | 首次受理时校验当前启用修订并冻结；后续沿用原交互句柄及固定接口 |
| `message.result` | outcome；完成时 output；失败/拒绝/未知时 error | inReplyTo 指定原请求；output 按原修订 outputSchema 校验 |
| `interaction.opened` | interactionType；通信另含 interfaceName、revision、deadline、maxRequests；原始关联在封套中 | 仅原接收端可提交；平台先登记不可变双方及类型，再可靠转发 |
| `contract.ruling` | caseRef、admissionId、subject、原裁定；原交互关联在封套中 | 仅平台系统产生，核原双方；终止合同新履约，不冒充执行已结束 |
| `interaction.closed` | reason、closedAt；原始关联在封套中 | 平台在关闭事务后产生；拒绝新请求但不抹掉迟到结果 |

`delegation.result.outcome` 使用 `reserved / rejected / failed / unknown`；reserved 只表示预留成功。`message.result.outcome` 使用 `completed / rejected / failed / unknown`。`completed` 表示取得结构化业务答复；例如 `output.status=conflict` 是有效结果，不能冒充预约成功。标准错误不要求伪造符合业务 Schema 的成功数据。

同一请求只保存一个不可变业务终局；`unknown` 是可核实推进的非终局报告。结果消息以 inReplyTo 关联，平台不允许迟到的 unknown 降级已确认终局；同终局重传返回原结果，矛盾终局报冲突。A2C 任务进展按原协议分辨进展与终态。

首次请求在建立前被拒绝时，结果可不含 interactionId，但必须引用原消息；发起方据此退出等待。登记失败或原消息已关闭时不能执行业务；同源不同 UUID、同 UUID 不同参与方均报冲突。助手通信的后续请求保持原请求方向和接口；反向调用对方的另一接口必须另开交互。

首请求已受理但尚未建立 UUID 时也属于在途请求；`interaction.opened` 核对原消息冻结的修订，不再次要求等于最新内容修订。仅更新接口内容不能使其失效，当前停用/撤权、消息到期或关闭仍会阻止取得开始许可。

a2c.request 的常规方向为个人助手到服务方；唯一逆向请求为原服务方在同一委托交互发送的 ap2.checkout，body只含purpose=termination及原cardDigest。平台核已接受的原协商解除及实际负余额，固定参与方和admission；个人助手只用Client.refund_checkout产生本单收款单，a2c.result沿原请求返回。此通道不依赖个人助手通信接口，不提供任意反向业务或跨合同收款。

## 幂等与错误

平台控制操作的幂等范围为“认证主体 + 操作类型 + operationId”，另绑定参数摘要；同键异参数返回冲突。消息另以全局 messageId 去重；控制操作 ID、消息 ID、交互 ID 和 A2C 任务 ID 不相互替代。

HTTP业务错误统一返回 `{"error":{"code","message","recovery"}}`，保留对应HTTP状态；参数、原A2C校验、认证及请求结构错误均使用同一封套，不混用字符串error或detail。已确定的输入错误明确拒绝并指导修改后新建操作，不因解析失败变成unknown；服务端故障或响应缺失仍按原操作核实，不据此推断业务未执行。原A2A/A2C协议响应保持原协议格式。

错误统一包含 `code`、可公开的 `message` 和 `recovery`：原操作恢复、修改输入后新建、等待用户、核实外部结果或不可重试。至少区分 `not_ready`、`forbidden`、`invalid_input`、`revision_conflict`、`id_conflict`、`capacity_full`、`service_paused`、`expired`、`closed`、`stale_generation`、`history_gap`、`quota_exceeded`、`protocol_error`、`unknown_result`；不得把网络超时等同业务未执行。

AP2 拟卡费通过平台应用服务协调 admission 与付款的同一事务，参数仍遵循 AP2，预留关联放在外层控制上下文。零拟卡费也必须在有效签署前提交预留；平台接口不新增绕过容量、付款幂等或参与方亲签的快捷路径。

ap2.pay提交期的PSP明确拒绝使用payment_rejected，保留可公开实际原因；所属应用事务必须回滚后才能发送对应ok=false的operation.result。SDK可依据认证WS收到并持久保存的准确原回执核实该次拒绝，同时核账号、操作类型、原ID、冻结payload、实际付款及其他同付款键尝试。HTTP原操作查询仍只返回已有成功结果；仅404、错误文本或缺少凭证不能证明没有未决付款，unknown不产生新提交权限。

文件引用固定为 fileId、name、digest、size，不接受远端 URL 或服务端磁盘路径。上传仅授予原上传身份读取权限；通过合法 A2C 封套提交文件引用时，平台在接受原消息的同一事务授予原接收身份读取权。不能把他人传入引用再授权给第三方；跨任务材料须由参与方明确准备。文件名是协议元数据，不用于拼接存储路径；同操作恢复原引用，不重新生成上传身份。

每账号文件引用与在途上传合计上限512MiB。先原子预留元数据和配额，再写入字节并标为就绪；中断保留原操作，未就绪引用不可读取或投递，恢复不能另占配额。原文件和合同证据按业务生命周期保留。

`a2c.request` 的 body 为 op、原 body、files 引用映射和 admissionId，可选原 taskId；`a2c.result` 为原 reply、files 引用映射及原任务状态，保留 inReplyTo。适配封套不改签名字段或原协议 task ID。非只读执行必须有当前开始许可；接收端先持久记录执行检查点，完成后推送原结果。模型退出、超时或未知执行不能自动重做签署、开工、交付或通知。

每个原方法调用单独使用 messageId；后续期次、环节及验收通知可以在同一交互再次调用相同方法。它们须关联各自已保存的业务操作和原 taskId，不能用新标识替换未知调用。方法/任务映射和读取边界统一见 [A2C 适配](A2C适配.md)。

reply 保留原 A2C SDK 的 body、taskId 与 state；无任务的原响应可省略 state 或保留 null，投递台账将其视为本次调用完成。任务状态保留 working、auth-required、completed、failed、rejected、canceled，不将 auth-required 改名为界面用语。同一原请求的进展保持 taskId，终态结果不可替换；重传返回原回执。

reply 可附原 task 快照（id、op、state、artifacts、status），其身份与状态须和当前原响应一致，op 保留创建该任务的原方法。后续请求若复用原任务，不得用本次请求方法覆盖 task.op。外层 files 仅保存原 Reply.files，另以 taskFiles 保存原 Task.files；两者不能合并，同名文件也可能是不同原件。taskFiles 有值时必须附任务快照；两份映射均在接受结果的同一事务中校验并授予原请求方读取权。旧封套未携带 taskFiles 时按空映射处理，不推断为 Reply.files。

宿主调用或外部效果未知时，a2c.result 外层可附 executionError（code=unknown_result、recovery），同时保留原非终态 Reply/Task。它只报告 SDK 执行状况，不写成 A2C failed、不撤销合同或释放容量；发送端适配器结束本地等待并返回 unknown。之后取得真实原结果仍可沿原任务推进，未知报告不能覆盖已确认终态。

card.countersign 允许在原 held 预留仍有效时投递签1卡、取得审查开始许可；服务方审查通过后，以收到的原卡提交 admission，再让原 SDK 签2。带签2的结果必须已有 committed 并通过原卡与签名校验。request.submit 仍要求先提交容量；ap2.checkout 只取得原拟卡费支付数据，不等于已付款或已承诺接单。

委托交互的 opened body 为 interactionType=delegation、bindingDigest、deadline；登记回执和恢复查询均返回同一绑定。admission.configure 使用 expectedRevision、maxActiveDelegations、accepting；reserve 使用 interactionId、originMessageId、bindingDigest；commit 使用 admissionId 和绑定的原签署证据；status 使用 admissionId 或所属服务。`ap2.pay` 控制 payload 为 `{admissionId,ap2}`，ap2 保持原协议 body；平台操作结果及原 AP2 付款凭据分别可查询。

授权 context/grant/proof 的字段与时间规则以[支付中心](../组件/支付中心.md)为准。HTTP 登记 body 为 `{operationId,context,grant,proof}`；查询/关闭 body或查询串显式选择 actor。scope.select 的 proof 对 `{scopeDigest,cardDigest}` 使用用户密钥签署，slot=`ioa-contract-selection`，签署新鲜度最长15分钟且须在当前 grant 内。API 返回 scopeDigest、acceptedRevision、授权截止、已付费用、已选合同及额度摘要，不返回私钥。原成功操作重传先恢复原结果，新动作才检查当前授权；平台操作记录和领域预算在同一短事务。

稳定 `/a2a/agents/{agentId}` 地址的协议投递也必须携带有效 IoA 交互与接单上下文；缺少时明确拒绝。兼容协议地址不能形成绕过统一接入的第二条接单路径。

提案签认 payload 为 `{admissionId,op:"card.endorse",body:{card},request}`。request 必须与消息中心已接受并取得开始许可的原签名请求完全一致；card 尚只有服务方签2，复用 A2C 核验请求不变量及响应期限。市场核包和准备在事务外，提交前重新核当前代次、绑定和期限；原签认、协议快照、业务卡绑定及操作回执在同一短事务保存。相同候选恢复原签3，不能重新签认延长时间；同一接单记录不能关联另一份仍有效承诺。

## 仲裁接口

| 入口 | 输入 | 输出与边界 |
|---|---|---|
| POST /api/v1/arbitrations/preview | agentId、admissionId、ground；理由需要时含period | SDK Bearer认证；只读核本案原双方，返回subject、ground、period、assessedAt、deadline、eligible、route、basisDigest、evidence及requiredEvidence；不创建案件、不执行复算 |
| WS arbitration.request | admissionId、ground、必要period、basisDigest、materials分组；沿共用operationId | 返回平台caseRef及原受理回执，材料归属和内容摘要由平台复核，不能传替代原卡 |
| GET /api/v1/arbitrations/{caseRef} | agentId | 仅原双方查原案件/裁定、评估尝试及执行结束状态；未完成不返回虚构裁定 |
| GET /api/v1/arbitrations | agentId、admissionId | 以本机已保存的原接单引用恢复caseRef/案件；不存在明确返回无案件，不把其他账号的案件传给客户端 |
| GET /api/admin/arbitrations | 可选state、limit（1—100，默认50）、cursor | 网页管理员案件列表；过滤本账号作为当事方的案件，返回有界元数据及nextCursor，不返回私人正文 |
| GET /api/admin/arbitrations/{caseRef} | 原caseRef | 当前非本案当事网页管理员读取本案冻结申请、材料、实际评估及review当前复核依据；不扩大为私人消息审计 |
| GET /api/v1/arbitrations/{caseRef}/materials/{fileId} | agentId | 仅本案原双方读取本案冻结引用，核当前归属和实际摘要；不是任意文件下载入口 |
| GET /api/admin/arbitrations/{caseRef}/materials/{fileId} | 原caseRef、原fileId | 当前非本案当事网页管理员读取本案冻结引用；无本案引用、角色失效或自己案件均拒绝 |
| POST /api/admin/arbitrations/{caseRef}/review | operationId、expectedEvidenceDigest、liable（client/provider/none）、明确reason；必要时含compensation（amount、currency） | 当前非本案当事网页管理员复核；提交时重新核权限、依据和已知程序结果，SDK/模型不能调用 |
| POST /api/admin/arbitrations/{caseRef}/reevaluate | operationId、expectedEvidenceDigest、明确reason | 仅无已知结果且原writer结束的unknown案件，重用原材料/模型，记录实际尝试；不是普通SDK重跑 |
| WS arbitration.finish | caseRef及原执行关联 | 原服务方在实际收敛后确认结束；核对原任务事实，再释放并关闭，不调用被裁定禁止的card.close |
| 系统contract.ruling | 原caseRef、admissionId、subject和原裁定 | 只由平台可靠投递给原双方；参与方不能冒充系统发送；不是interaction.closed |

preview的period仅接受正整数；start-overdue及proposal-overdue不含period，其余理由必须指定真实期次。route为deterministic、recompute或review；eligible只说明当前理由的前提是否成立，requiredEvidence仍须在申请时补齐。basisDigest绑定原依据而不绑定流逝的时钟；受理与裁定再次核当前事实及期限。取证保留不足、原凭证矛盾或签名损坏时明确拒绝，不当作“没有证据”。

materials仅接受deliveryFiles、fetchEvidence、inputMaterials三个可选分组，每组为“协议文件名 → 完整FileRef”映射；FileRef沿用fileId、name、digest、size，所有分组合计最多32项。未使用分组省略；所需分组取自preview.requiredEvidence，空材料不能代替所需证据。SDK不让用户手工编辑引用：从已有授权字节准备所属上传，确认绑定实际依据及材料清单。相同操作不能替换任一引用；已存在案件恢复原受理结果，不创建第二份案件。

### 案件视图与摘要

| 字段 | 定义 |
|---|---|
| assessment / basisDigest | 冻结申请的原证据视图及内部原快照摘要；不随查询时钟或后续事实覆盖 |
| evaluation | 已知原程序结果及其原输入关联；尚无完整结果为null，不用异常伪造pass/fail |
| review | 仅独立网页管理员详情含此对象：evidence为最新原事实的公开视图，evidenceDigest为该视图摘要，expectedEvidenceDigest为实际复核确认依据，availableActions为当前可提交操作 |
| expectedEvidenceDigest | 规范JSON对象的摘要，对象含basisDigest、decisionEvidenceDigest（当前公开事实摘要）、materialsDigest、evaluationDigest、modelBindingDigest、currentModelBindingDigest、state。evaluationDigest对实际evaluation值（包括null）计算；不包含查询时刻，不授权动作 |
| decisionEvidence | 仅终局存在，为决定时冻结原事实的公开视图；尚未裁定为null。包含本单subject、原template/card/request、完整原环节、实际付款及marketOutcome（原市场结局；未结束为null），并用不含原请求凭据的protocolCalls摘要表示原协议进展 |
| decisionEvidenceDigest | 对decisionEvidence直接使用共用规范JSON摘要算法计算；裁定文书签名绑定该摘要。SDK必须重新计算，不能用原basisDigest或接收的摘要字符串代替 |
| execution | pending或finished；已有合法市场结清的中立案件沿原终态标finished，不重新释放或改写原市场结局 |

review/reevaluate的operationId沿原有1—128字符操作标识规则；reason为去除首尾空白后1—2000字符。原操作者/操作标识的同内容恢复原回执，异内容冲突；恢复仍须当前独立管理员权限。review只接受needs_review/unknown且本案实际评估writer已结束，reevaluate还要求无已知结果及原依据/材料/固定模型未变；双方SDK不能提交这些操作。

compensation仅在ground为termination-compensation且liable为client时使用；amount为明确非负十进制定数字符串，currency等于原卡币种，并核原未验收期金额上限。其他理由或中立裁定不得用该字段新增付款义务；不生成付款用途或自动过账。

案件及其文书为IoA外层对象；裁定含caseRef、admissionId、subject、ground、必要period、basisDigest、materialsDigest、decisionEvidenceDigest、rulingKind、liable、issuedAt及市场signature。实际合同另含cardDigest供原record_ruling使用；无卡请求不得伪造cardDigest或合同ledger。人工裁定rulingKind为review，附实际operator、reason及必要compensation；原程序结果保持原件。文书使用市场独立对象签名，不冒充A2C卡或带a2cVersion的协议对象。

案件内容、理由成立条件、人工复核与终局规则只在[委托中心](../组件/委托中心.md#争议案件与原证据)定义。申请/查询/结束均使用原caseRef，不让用户手抄UUID，也不新增轮询维持连接的职责。
