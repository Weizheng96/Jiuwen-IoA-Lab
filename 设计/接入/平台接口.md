# 平台接口

## 目的与范围

定义平台与 IoA Lab SDK 之间的网络契约：HTTP 入口、WebSocket 帧、消息封套和恢复查询。消息投递及收信权限规则由[消息中心](../组件/消息中心.md)定义，合同与签名规则直接复用 A2C。本文是接口设计，不表示所有入口均已实现；实现差距见[开发计划](../../docs/开发计划.md)。

## 通道与认证

| 通道 | 用途 | 身份要求 |
|---|---|---|
| HTTPS | 登录、目录和历史查询、配置发布、文件传输 | 浏览器 cookie 或 SDK Bearer；按入口检查归属 |
| `/ws/agents` | 智能体业务消息、任务进展、回执和控制操作 | 一次性短时票据首帧认证；连接绑定账号及获准的 agentId 集合 |
| `/ws/admin` | 浏览器观察订阅 | 浏览器授权上下文；不领取业务消息、不更新收件游标 |

票据不放 URL。连接中的每次操作显式选择本端 `agentId`，平台核对票据范围及该身份的执行代次；封套 `sender` 由平台确定。一个运行时可管理多个身份，每个身份分别维护租约、游标和状态。连接建立/刷新不等于用户名密码登录。

## HTTP 入口

| 方法与路径 | 输入与结果 |
|---|---|
| `POST /api/auth/register` | 用户名、密码及注册操作标识；创建账号并返回注册/登录结果，不创建助手进程 |
| `POST /api/v1/token`；`POST /api/v1/token/refresh`；`GET /api/v1/me` | 登录操作标识与凭据 → 受限SDK登录态；有效 Bearer 续用不发币；查询本账号、权限与可操作身份 |
| `POST /api/v1/identity/challenge`；`POST /api/v1/identity` | 一次性挑战 → 本地签名绑定对象 → 稳定 agentId 与绑定结果 |
| `POST /api/v1/connections/ticket` | SDK Bearer 及 agentIds 数组 → ticket、expiresAt；仅限所属的 1—64 个已登记身份，不接受浏览器 cookie 代替 Bearer |
| `GET /api/v1/search`；`GET /api/v1/providers/reputation` | 分类/需求 → A2X 候选及真实信誉；完整模板另按返回引用取得并验签 |
| `POST /api/v1/services/{agentId}/publications`；`GET /api/v1/services/{agentId}/status` | SDK Bearer；签名服务声明、模板原件和 operationId → 原发布回执；查询当前公示及索引状态 |
| `GET /api/v1/services/categories` | SDK Bearer；返回可选择的 A2X 叶类；不能自动确定分类时由用户选择 |
| `POST /api/v1/messaging/interfaces`；`GET /api/v1/messaging/interfaces` | 公开声明、权限、内容摘要、预期修订及操作标识 → 新修订；查询自己的声明 |
| `POST /api/v1/scopes`；`GET /api/v1/scopes/{scopeDigest}`；`POST /api/v1/scopes/{scopeDigest}/close` | SDK Bearer、actor及稳定操作；登记 context/grant/proof、查询预算或关闭新许可；仅所属账号可操作 |
| `GET /api/v1/messaging/accounts/{username}/interfaces` | URL 编码的精确账号 → 获准使用的接口、当前修订及目标 agentId；不返回私有处理步骤或完整白名单 |
| `GET /api/v1/interactions` | 本端 agentId + originMessageId → 建立状态、已登记 UUID 或建立前终态；也可按有权读取的 interactionId 查询 |
| `GET /api/v1/messages/{messageId}` | 本端 agentId → 原消息的投递/处理状态及权限允许的已存结果；不存在与无权读取均不披露内容 |
| `GET /api/v1/operations/{operationId}` | 本端 agentId + 操作类型 → 原平台控制/发布/付款操作结果；付款返回原 AP2 凭证，不重新执行 |
| `GET /api/v1/payments/{paymentId}`；`GET /api/v1/payments` | 按 paymentId，或 ref + purpose + period 查询；仅原付款/收款账号可读原摘要、voucher 与 Payment Receipt；无此权限或不存在统一返回不可读，不触发付款或重新签署 |
| `GET /downloads/ioalab-skill.zip`；`GET /downloads/ioalab-client.zip` | 下载配置目录中的通用接入包；缺失返回未就绪，不从源码相邻路径查找或在请求中触发构建，不包含用户配置 |
| `POST /api/v1/provider/packages`；`GET /api/v1/packages/{digest}` | 验收器包 → 内容摘要；按摘要获取原包，SDK 必须核摘要 |
| `POST /api/v1/observations`；`GET /api/v1/orders/{digest}` | 所属过程上报；有权查看的合同观察投影 |
| `POST /api/v1/arbitrations` | 当事方合同、交付与验收证据 → 争议受理/裁定引用 |
| `/a2a/market`；`/a2a/pay` | A2C 公共服务与 AP2 原协议接口，保留原请求、签名和响应 |
| `/a2a/agents/{agentId}` | 稳定协议地址：提供已签名公开元数据，并将获准协议请求转入统一投递适配 |

注册、发布及登录重传使用稳定操作标识；查询无权代签、验收或付款。材料与交付件使用有归属检查的文件通道，消息只携带引用与摘要。公开协议地址不要求服务方暴露公网端口；平台不抓取用户任意 URL，也不生成参与方私钥。

注册和登录 body 含 operationId、username、password，注册另含 display_name 与 invite；操作绑定调用通道，不能用 SDK 操作取得浏览器管理员凭据。响应含原操作标识与 credited；登录重传恢复原令牌有效期。续用入口只读 Authorization Bearer，不接受 cookie 代替，不产生新的登录记录。

角色绑定的 challenge body 为 operationId、role（assistant/service）、agentId；服务 ID 使用 `svc-` 加本地 UUID，个人助手保留本地稳定 URN。响应包含 challenge、expiresAt、protocolId 和当前 phase。提交绑定 body 含同一 operationId、challenge、owner、platform、role、agentId、name、source、keys、proof；source 为 client/provider/experiment，keys 的 assistant 用途为 agent/user/payer，service 用途为 agent/payee。agent/user 为 Ed25519 公钥，payer/payee 为 P-256 公钥，禁止私钥字段。proof 是以相应 agent 密钥签署完整绑定对象摘要的 A2C 签名，slot 使用 client 或 provider；绑定时按提交的内联公钥验签，proof 不携带 kid，公钥可保留后续 JWKS 发布用的 kid。protocolId 由平台导出，不由调用者提供任意 URL。

绑定返回 agentId、protocolId、role 与公钥映射。已绑定表示身份就绪，登记模板、分类、连接和可执行状态分别报告。服务稳定地址至少提供已绑定公开 JWKS；未完成业务发布或执行门禁时明确未就绪，不宣称已上线接单。

发布 body 为 `operationId + declaration + proof + templates`。declaration 固定字段为 schema（ioalab.service/1）、agentId、protocolId、revision、name、description、tags、categoryId、templateDigests；proof 使用绑定服务 Ed25519 密钥签署 `digest(declaration)`，slot 为 `ioa-service`。templates 与摘要列表一一对应，提交 provider 已签署的 A2C 原模板，平台返回回执中的原签认模板。`GET /api/v1/operations/{operationId}?agentId=…&operation=service.publish` 恢复原回执，不刷新期限。

稳定地址提供 `/.well-known/agent-card.json`、`/.well-known/jwks.json`、`/publication` 和 A2A `template.get`；publication 返回声明、proof 与声明摘要。Agent Card 由锁定 A2C 公开构造器生成，不接受上传任意远端接口。未发布身份只提供 JWKS；模板读取不表示允许开始委托。

发布回执包含 agentId、acceptedRevision、declarationDigest、templateDigests、原签认 templates 和 acceptedAt。status 返回当前 revision、published、declarationDigest、categoryId、indexedRevision、indexedCategoryId、indexReady、templateReady、activeTemplateDigests 和 executionStatus；索引就绪与有效模板不代表执行就绪。

## WebSocket 帧

帧是 IoA 平台的接入协议，不宣称为 A2A 标准 WebSocket 绑定。认证后控制帧结构为 `type + operationId + agentId + generation + payload`；认证前只有携带票据和恢复游标的 `connection.auth` 合法。`operationId` 在首次发送前持久化，恢复同一操作必须沿用；只读查询可使用一次性请求标识。

| 帧/控制操作 | 输入 | 输出与持久边界 |
|---|---|---|
| `connection.auth` | ticket、持久 runtimeId、各身份已连续保存的 cursors | connection.ready：connectionId、各身份 generations、服务端已确认游标、heartbeatSeconds、leaseSeconds；历史缺口显式返回 |
| `connection.ping/pong` | 连接标识 | 心跳与租约有效信息，不产生登录赠币 |
| `message.send` | 本端身份、消息封套 | 校验并持久化后返回 `accepted` 与原 messageId |
| `message.deliver` | 平台推送消息及 recipientSeq | 接收端落库后发送 `message.ack` |
| `message.ack` | messageId、连续保存的游标 | 平台确认已送达；不表示已开始或已完成 |
| `request.start` | 原请求 messageId、interactionId、当前代次 | 按已受理的冻结修订及当前 ACL/enabled/TTL 原子校验并保存 startedAt；返回原许可或明确拒绝 |
| `interaction.close` | interactionId；未建立时使用 originMessageId；关闭原因 | 原子关闭入口，可靠产生 `interaction.closed`；委托先通过委托中心核验 |
| `admission.reserve/commit/release/status` | 交互、服务、绑定摘要、预留及相关证据 | 委托中心原子预留/提交/核实释放；返回原台账记录 |
| `scope.register/status/close` | context/grant/proof；或 scopeDigest | 用户签名授权、原记录恢复、预算查询及拒绝新许可；关闭不解除合同 |
| `scope.select` | scopeDigest、完整原卡和用户选择证明 | 验证后预留完整价款；只绑定一份 cardDigest，不执行 A2C 签1或付款 |
| `operation.get` | 原操作标识与类型 | 查询同一操作的已存结果；与 HTTP 恢复查询读同一记录 |

普通业务结果由持久消息返回；控制操作超时先查询原操作，不重新生成标识尝试同一副作用。平台拒绝旧代次发起新的执行，但允许当前执行者恢复已有操作结果。平台自己产生的关闭/到期通知使用平台系统身份，参与方不得伪造。

控制响应统一为 `operation.result`，包含 agentId、operationId、operation、ok，以及 result 或 error；多身份连接按完整三元组关联原操作。推送 `message.deliver` 包含 message、recipientSeq 和独立的 deliveryState；投递状态不修改原封套摘要。认证失败关闭连接；被新代次替代的连接使用关闭码 4409，旧运行时停止自动重连并报告已失去执行权。

`runtimeId` 由本地实例首次建立时生成并持久保存，不是账号或会话标识。另一个 runtimeId 在原租约仍有效时不能自动接管；同一实例网络重连递增代次。ACK 的 through 为该身份连续持久保存的 recipientSeq，不能超过已接受序列；过期消息的元数据占据原序列位置，恢复时仍显式返回，不能跳过缺口。

`POST /api/v1/messaging/interfaces` 的输入为 operationId、name、expectedRevision 与 definition；definition 仅包含公开说明、object 根输入/输出 Schema、allowedSenders、enabled、完整本地规则的 contentDigest。原文处理步骤不上传。发布返回不可变修订和目标 agentId；读取及发送均复核当前权限，操作重试不重复建立修订。

## 持久消息封套

| 字段 | 必填条件与来源 |
|---|---|
| `messageId` | 必填；发送端 UUID，平台全局唯一；相同发送者及内容重传返回原记录，冲突不覆盖 |
| `kind` | 必填；下表中的明确类型，不从自然语言猜测 |
| `recipient` | 必填；目标稳定 agentId |
| `interactionId` | 已建立交互必填；首次业务请求省略；由原接收端生成后登记 |
| `originMessageId` | 建立/关闭及建立前错误必填；指向原始请求，用于恢复关联 |
| `inReplyTo` | 业务结果必填；指向实际请求，限制返回对象与结果格式 |
| `expiresAt` | 必填；UTC RFC 3339 时间，受平台及业务期限约束 |
| `body` | 必填；由 kind 指定结构；不改 A2C 原字段、摘要或签名 |
| `sender`、`acceptedAt`、`recipientSeq` | 平台赋值；客户端不能声明其他主体或入队顺序 |

封套不携带九问 Session ID、私钥或模型凭据。UUID、admission、路由及连接代次属于平台运行数据，不进入 A2C 合同。

| kind | body 的必要内容 | 关联约束 |
|---|---|---|
| `delegation.intent` | 请求模式、模板摘要、requestDigest 或 cardDigest、材料引用 | 首次请求不带 interactionId；只表达意向，不形成合同 |
| `delegation.result` | outcome；成功时 admissionId、绑定摘要、holdUntil；拒绝时 error | 原意向的 inReplyTo；建立后沿用已登记 UUID |
| `a2c.request` | 原协议方法/请求、任务引用及 admissionId 等外层元数据 | 必须已有委托交互；原协议请求 ID 与签名保持原义 |
| `a2c.result` | 原协议响应/任务进展与原任务标识 | 绑定原请求；进展不冒充终态，不反派为新请求 |
| `message.request` | interfaceName、revision、input | 首次受理时校验当前启用修订并冻结；后续沿用原交互句柄及固定接口 |
| `message.result` | outcome；完成时 output；失败/拒绝/未知时 error | inReplyTo 指定原请求；output 按原修订 outputSchema 校验 |
| `interaction.opened` | interactionType；通信另含 interfaceName、revision、deadline、maxRequests；原始关联在封套中 | 仅原接收端可提交；平台先登记不可变双方及类型，再可靠转发 |
| `interaction.closed` | reason、closedAt；原始关联在封套中 | 平台在关闭事务后产生；拒绝新请求但不抹掉迟到结果 |

`delegation.result.outcome` 使用 `reserved / rejected / failed / unknown`；reserved 只表示预留成功。`message.result.outcome` 使用 `completed / rejected / failed / unknown`。`completed` 表示取得结构化业务答复；例如 `output.status=conflict` 是有效结果，不能冒充预约成功。标准错误不要求伪造符合业务 Schema 的成功数据。

同一请求只保存一个不可变业务终局；`unknown` 是可核实推进的非终局报告。结果消息以 inReplyTo 关联，平台不允许迟到的 unknown 降级已确认终局；同终局重传返回原结果，矛盾终局报冲突。A2C 任务进展按原协议分辨进展与终态。

首次请求在建立前被拒绝时，结果可不含 interactionId，但必须引用原消息；发起方据此退出等待。登记失败或原消息已关闭时不能执行业务；同源不同 UUID、同 UUID 不同参与方均报冲突。助手通信的后续请求保持原请求方向和接口；反向调用对方的另一接口必须另开交互。

首请求已受理但尚未建立 UUID 时也属于在途请求；`interaction.opened` 核对原消息冻结的修订，不再次要求等于最新内容修订。仅更新接口内容不能使其失效，当前停用/撤权、消息到期或关闭仍会阻止取得开始许可。

## 幂等与错误

平台控制操作的幂等范围为“认证主体 + 操作类型 + operationId”，另绑定参数摘要；同键异参数返回冲突。消息另以全局 messageId 去重；控制操作 ID、消息 ID、交互 ID 和 A2C 任务 ID 不相互替代。

错误统一包含 `code`、可公开的 `message` 和 `recovery`：原操作恢复、修改输入后新建、等待用户、核实外部结果或不可重试。至少区分 `not_ready`、`forbidden`、`invalid_input`、`revision_conflict`、`id_conflict`、`capacity_full`、`expired`、`closed`、`stale_generation`、`history_gap`、`quota_exceeded`、`protocol_error`、`unknown_result`；不得把网络超时等同业务未执行。

AP2 拟卡费通过平台应用服务协调 admission 与付款的同一事务，参数仍遵循 AP2，预留关联放在外层控制上下文。零拟卡费也必须在有效签署前提交预留；平台接口不新增绕过容量、付款幂等或参与方亲签的快捷路径。

授权 context/grant/proof 的字段与时间规则以[支付中心](../组件/支付中心.md)为准。HTTP 登记 body 为 `{operationId,context,grant,proof}`；查询/关闭 body或查询串显式选择 actor。scope.select 的 proof 对 `{scopeDigest,cardDigest}` 使用用户密钥签署，slot=`ioa-contract-selection`，签署新鲜度最长15分钟且须在当前 grant 内。API 返回 scopeDigest、acceptedRevision、授权截止、已付费用、已选合同及额度摘要，不返回私钥。原成功操作重传先恢复原结果，新动作才检查当前授权；平台操作记录和领域预算在同一短事务。

稳定 `/a2a/agents/{agentId}` 地址的协议投递也必须携带有效 IoA 交互与接单上下文；缺少时明确拒绝。兼容协议地址不能形成绕过统一接入的第二条接单路径。
