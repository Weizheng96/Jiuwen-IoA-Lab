# 九问网页通知

## 目的与范围

职责：把已经获准的本地通知送入所属用户的真实九问网页会话，定义宿主配置、工具及扩展协议。通知组件归九问适配包，不属于平台消息中心，也不运行另一套助手或履约流程；业务结果与通知结果分别保存。

## 配置与工具

在本机host.business_tools中选择已安装的jiuwen-web工厂并指定profile；配置采用[SDK共用机制](SDK共用机制.md)。工厂构造不写库、不连接或发送；本地运行时取得实例所有权后才启动资源，作业停止后才关闭。普通用户沿用既有九问；扩展须通过该版本原生支持的入口由用户显式配置，不自动注入安装目录、修改全局配置或更换版本，边界见[部署](../工程/部署.md)。

| options | 类型与规则 |
|---|---|
| url | 原版WebChannel地址，含/ws路径；回环可ws，远端须wss；不得含用户名/密码；不得自动换目的地 |
| user_id | 主人明确选择的九问用户；URL中的user_id须与之相同，扩展能力回执再次核对固定目标用户 |
| secret_env / credentials_file | 通知密钥的环境变量名、可选本机凭据文件；值不交给模型、平台或Git |
| ttl_seconds | 本地通知有效期，默认7天，范围60秒至30天；不延长原消息或合同的许可 |
| max_pending | 默认256，范围1至4096；满额明确拒绝新增，不清理未知结果来腾位置 |
| retry_seconds | 明确未发送时的重试间隔，默认5秒，范围1至300；不用模型维持 |

| 工具/入口 | 输入与结果 |
|---|---|
| owner.notify | text，及可选title；来源身份、消息、交互、对方身份取SDK固定上下文；同一来源消息只产生一份不可变通知，改内容拒绝 |
| owner.notification_status | notificationRef；只读原通知，限原身份、交互和对方；不重发 |
| 宿主notify | 输入为input（通知参数）和context（SDK固定来源上下文）；装配入口按实际所属agentId选定profile工具。同样使用固定的本地来源及上下文，不接受来信增加权限；返回实际通知回执；业务状态提示须引用已保存事实 |
| 本机状态 | 已配置工厂、按profile划分的排队/接收/未知数量及缺项；不展示密钥；安装或进程运行不等于会话已收到 |

SDK工具回执和原message.result均保持当时快照；queued不能改写为已读。后续查询使用独立状态入口。工具描述及用户收信规则必须明确排队与会话接收的差别，不能只返回笼统成功布尔值。

## 原生配置准备

网页通知为显式启用项。用户在已有接入配置中选择jiuwen-web工厂及主人user_id后，运行ioalab-jiuwen web-extension --config <原配置> --profile <身份配置键>。命令复用配置中的既有九问数据目录和本机密钥，仅准备本扩展；不安装九问，不启动或停止用户原进程，不编辑全局配置。

| 阶段 | 行为与结果 |
|---|---|
| 检查 | 校验本机配置、所属profile、固定WebChannel目标及现有九问工作区；缺少配置明确失败，不初始化一套空九问冒充原实例 |
| 准备 | 本机尚无密钥时，仅可在已明确配置且尚不存在的credentials_file内生成；新文件须位于IoA配置目录内并限制权限，不追加或覆盖既有凭据文件。使用原生application_plugins目录约定，在现有数据目录的application_plugins/ioa-notifications下准备随包扩展和私有settings.local.json；只写本扩展命名空间，不安装依赖到九问环境 |
| 已存在 | 文件及固定目标相同则复用；内容或目标不同拒绝覆盖，给出显式核对/迁移提示；不清理回执和旧通知 |
| 生效 | 若宿主需要重启，由用户经九问原生入口处理；命令只报告prepared，不能把文件已准备当作loaded或ready；运行时继续用真实capabilities核验 |

settings.local.json只含固定user_id和通知secret，权限限制为本机用户；扩展只读取本目录的该文件，不读取IoA账号、模型设置或其他私人配置。本扩展仅使用这份私有设置，不保留旧全局环境配置或旧回执格式的兼容路径；不支持的格式明确失败，不能重建空库掩盖旧状态。发布包不含本机设置。宿主不支持该扩展机制时通知保持未就绪，不能强制换版或修改源码来补齐。

## 投递与恢复

通知库位于所属profile的business/web-notifications私有目录，保存固定目的地及来源绑定；构造阶段不创建。重启恢复原记录和标识；更换目标用户或地址需显式迁移，不能把旧内容发给新目标。数据库锁只用于短事务，外部RPC不持共享写锁。

| 状态 | 含义与推进 |
|---|---|
| queued | 本地已保存，尚无九问接收证据；连接建立前失败可保留原标识重试 |
| sending | 发送前持久保存；响应不明时先查扩展原回执，不另造标识 |
| session_received | 原版公开历史接口已确认持久化；保留真实sessionId，read仍为unknown |
| unknown | 原写入可能已发生，保留原件；只查询，不自动重写或借新工具调用重做 |
| expired / rejected | 未发送的记录到期，或明确拒绝；发送未知不凭TTL推断为未发生 |

扩展端在写历史前保存sending及完整输入摘要；同ID同内容恢复原回执、异内容冲突。崩溃遗留sending不能当作未执行。客户端因响应丢失而查询原回执；仅在同一回执库确认不存在且仍在原通知有效期内时，才可按原ID继续，扩展去重仍是最终写入屏障。已尝试发送而到期的记录保留unknown，不能据absent推断从未执行。持久化和发送失败不触发任何合同、验收、付款或用户批准。

扩展回执库持久保存随机receiptStoreId，客户端首次核对后绑定；后续查询及发送均携带并核验原标识。回执库重建、标识缺失或改变时，保留原队列并要求显式核对，不能因新库返回absent而重写旧通知。扩展至少在支持的最长通知有效期及传输容差内保留去重记录；sending和unknown在核对完成前不清理。

## IoA 通知扩展协议

扩展源码及清单归src/hosts/jiuwen，随适配包资源分发；使用原版ApplicationPluginExtension和E2A公开历史接口。部署通过原版支持的扩展入口加载，固定目标用户，独立密钥鉴权；不得修改九问源码、全局指令或私有历史数据库。

| WebChannel方法 | 受控语义 |
|---|---|
| ioa.notification.capabilities | 鉴权后返回协议ioa.web-notifications/1、固定userId和持久receiptStoreId；不返回密钥 |
| ioa.notification.deliver | 接收固定通知ID、已验证发送者、标题/正文及来源分组；校验摘要后只写通知，不执行正文 |
| ioa.notification.get | 鉴权后按原ID和摘要查询absent、session_received或unknown；不创建会话或重发 |

扩展不暴露任意RPC、角色、写入方法或目标用户参数。扩展经原生session.create建立固定用户、web渠道及来源分组所属的持久会话，保存原版分配的Session ID；不自造原生会话ID。创建前先保存稳定create_token及creating状态，取得结果后先保存分组映射，再写通知；创建结果不明保留unknown，不另建会话。通知会话与业务Process Session分别关联，不伪造模型执行过程。原版插件未加载、协议不符、密钥错误或用户不匹配时明确未就绪，保留已排队通知。

## 验证与边界

核对无配置/缺包、鉴权/固定目标、离线恢复、重复/异内容、重启、未知与TTL、资源关闭及真实原版网页可见性。普通测试适配和session_received不能替代实际页面证据；用户已读需要另有可靠信号。

业务阶段的自动通知须从已保存事实产生，可合并观察性提示，不替代平台完整活动历史；尚未接通的阶段在开发计划中标明，不能以本通道安装或单条留言成功推断全部前台业务完成。
