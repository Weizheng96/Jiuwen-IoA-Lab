# IoA Lab SDK 共用机制

## 目的与范围

IoA Lab SDK 是一个软件包，分为[个人助手端 SDK](个人助手端SDK.md)和[服务方端 SDK](服务方端SDK.md)，共用连接、存储、身份及宿主调用契约。服务方端运行在服务提供者的电脑或服务器，不是平台后端；两端均主动连接平台。

本文定义公共调用、配置、返回和安装契约。常驻执行的内部职责、状态权威及恢复规则只在[本地接入组件](../组件/本地接入组件.md)定义；网络格式只在[平台接口](平台接口.md)定义。

## 包结构与调用边界

| 对象 | 规范职责 |
|---|---|
| `ioalab-sdk` / `ioalab_sdk` | 源码归 `src/access/sdk/`，提供 assistant、provider 两个角色入口及共用 runtime |
| 本地接入组件 | SDK 的常驻运行方式；唯一持有该实例私钥、SDK 业务数据库及连接 |
| 接入技能脚本 / CLI | 读取非模型配置、发送结构化本地请求、显示真实回执；不再实现签名和业务状态机 |
| A2C 适配 | 复用 A2C Client/Provider、验签、算价及 WASM 验收；IoA transport 接入推送及本地任务视图 |
| `ioalab-jiuwen` / `ioalab_jiuwen` | 源码归 `src/hosts/jiuwen/`，实现可选 AgentHost 适配及接入启动装配，通过原版公开接口连接九问 |

项目目录、发行包及 VERSION 归属统一见[架构](../架构.md)。核心 SDK 不导入平台、九问或官方业务工具；九问适配包依赖 SDK，并在启动入口构造宿主对象、注入运行时及角色处理器。宿主能力契约见[本地接入组件](../组件/本地接入组件.md)，不建立另一套角色执行器。

九问调用可能附带 call_goal 等已知展示元数据。适配层只在宿主声明中接纳其对应字段，分离后将原业务参数交给 SDK 严格校验；不扩大业务 Schema、不把元数据当作权限或执行指令，也不修改九问源码。业务 Schema 已显式定义的同名字段按业务字段保留，适配不得静默删除。

本文各页的点分名称是 SDK 能力及脚本操作契约。脚本形式统一为 `python "<skill_directory>/scripts/ioalab.py" <operation> --config "<外置配置文件>" --args-file <UTF-8参数文件>`；具体 Python 类封装不另定义业务含义。参数文件须先实际创建，结果必须来自脚本真实输出。

业务调用经过本机认证的 IPC 或回环 API；CLI 不打开运行时身份库。启动引导可创建运行时，但失败必须返回未就绪，不能退回脚本自行持有私钥执行。长连接由运行时维持，不靠模型循环调用平台收件接口。

## 本机调用与启动

| 项 | 契约 |
|---|---|
| 常驻入口 | SDK 提供运行入口；九问适配包在自己的入口装配宿主及角色处理器，不修改 SDK 的分发器 |
| 配置入口 | start、serve、validate和call均使用--config；SDK统一读取UTF-8 JSON（包括Windows UTF-8 BOM）并解析相对数据目录，不另提供call --home别名 |
| 读取归属 | 产品引导只安装、检查固定产品元信息并转交配置/参数文件路径；不自行解析账号配置。SDK负责共用配置、参数文件和原操作标识；宿主经同一SDK读取配置后校验自己的命名区域 |
| 调用前检查 | 诊断与安全停止仅从配置定位data_dir，不要求密码、角色或宿主业务配置仍完整；普通业务完整校验当前配置、账号、配置摘要和安装，并固定同一bootId再提交 |
| 参数文件 | 独立于账号配置和SDK数据目录；同一实际文件（含硬链接/路径别名）或SDK运行数据不得作可回写参数，拒绝发生在添加operationId或任何业务请求之前 |
| 本机端点 | 只监听 127.0.0.1 的随机端口，POST `/v1/call`；拒绝任意 Origin、非本机 Host、无访问凭据及超限请求；不提供跨域访问 |
| 请求 | operation、operationId、arguments 三字段；显式登记操作，禁止任意反射/执行；默认最大128 KiB |
| 返回 | 使用本文统一操作结果；业务未就绪明确返回，不能因为本机 HTTP 成功而报告委托成功 |
| 端点发现 | CLI 只读 data_dir 中 runtime.json，验证回环地址及实例；不打开 SDK SQLite 或私钥文件，不把本机访问凭据打印给模型 |
| 生命周期 | runtime.start 验证受限配置并启动；runtime.status 查询当前实例；runtime.stop 拒绝新业务、等待当前轮次收敛并关闭连接，保留所有数据及原业务状态 |
| 原操作 | 变更请求的 operationId 在发送前保存；超时返回 unknown，恢复沿用原标识；已持久入 outbox 表示本地接受，不表示平台送达或业务完成 |
| 未知能力 | 没有对应处理器或宿主能力时返回 not_ready；不能落回旧脚本直接执行或接受 confirmed=true 自证授权 |

共用配置用 JSON 保存 platform_url、username、password（或 password_env）、data_dir；相对路径以配置文件目录为基准。data_dir 是 SDK 专用目录，配置及调用参数文件保存在其外；检测到混放的无关数据时拒绝启动，不修改它们的权限。运行目录及凭据文件使用所属用户权限，Windows 使用用户 SID 的 ACL，不能把只读写标志视为 ACL。identities 为本机激活的 profile 列表，每项含 key、role（assistant/service）、name；key 对应本地持久身份，不是账号名或用户手填 UUID。最多一个助手及总计64个身份，默认模型并发2、待处理上限128，分别由 max_model_runs、max_pending_requests 配置。角色业务与宿主配置使用独立命名区域，由相应装配模块校验，SDK 不加载配置中指定的任意 Python 类或脚本。

本机查询声明waitSeconds时，取值为0至30秒；客户端传输预算须覆盖该显式等待及5秒传输余量，不得在服务端允许的等待尚未结束时提前将查询报为unknown。无等待的调用继续使用原传输预算，超时不会授权重做业务效果。

原生技能模型未必能看到宿主返回的目录元数据。产品共用定位页按公开JIUWENSWARM_DATA_DIR，或JIUWENSWARM_HOME下的默认.jiuwenswarm目录，确定当前技能唯一脚本；若目录布局不符则明确未找到并请求实际导入位置，不递归扫描项目或读取私有配置。

本机状态分别列出进程/IPC、认证、身份绑定、平台连接、宿主和角色执行能力。状态查询从当前调用环境复核实际安装；不匹配时保留观测数据并返回明确安装错误，不能以旧实例在线、同名版本号或身份已绑定报告新包就绪。诊断仍可取得实际状态，安全停止不受匹配失败阻断。只收到 WS 消息不能报告业务处理完成；离线、缺宿主或缺规则时可靠保存消息并保持未执行。

脚本、SDK CLI、宿主装配CLI及随附业务CLI的标准输出统一使用UTF-8；结构化结果为JSON，诊断标准错误也使用UTF-8。产品技能脚本将真实结构化结果重新序列化为ASCII转义JSON，使宿主按不同代码页解码时仍保留相同中文值；不更改SDK原记录或根据回显重写业务输入。原SDK结果缺失或结构不可识别时保持unknown，不能伪造明确拒绝或自动重做。参数读取区分文件不可读、非UTF-8、JSON语法及非对象；语法错误只报告行列，不暴露输入内容，也不建议改编码。

## 不读取凭据的配置辅助

本机用户先在技能包外私下填写平台、账号、密码或环境变量引用及专用SDK数据目录。随后由九问按用户意图调用下列启动前命令；它们不走常驻RPC、不登录、不建身份、不运行模型或业务工具。产品引导只转交路径，SDK是配置唯一解析与更新者。

| 操作 | 输入 | 输出及边界 |
|---|---|---|
| `runtime.configuration` | 本地配置引用 | configurationDigest、dataDir、身份列表、已配置服务键、宿主字段名和可修改字段；不返回账号、凭据、业务资源、宿主参数值或工具选项 |
| `runtime.configure` | 独立参数文件中的expectedDigest、changes | SDK校验后的新摘要、changed；不返回配置正文，不启动或发布 |

changes仅允许：identities按稳定key新增或更新显示名；provider.services按服务key局部更新instructions、skills、native_tools、max_active_delegations、accepting；host的command、data_dir、model及按名称补充skill_directories；max_model_runs、max_pending_requests、user_browser。未指定字段保留，不删除身份、不改变已有role、不替换整个服务列表。profile键在大小写折叠后唯一，避免Windows目录冲突。业务资源和host.business_tools由用户或明确的工具配置入口单独管理，不通过这个通用入口读取或修改；参数文件不得含凭据。

变更沿用实际data_dir的client.lock，与运行实例、登录及其他配置变更互斥；有持锁者则拒绝，不能自动停止实例或另建目录。取得锁后复核原文件，按字段合并并由原公共及角色校验器检查，再用所属用户权限原子替换。账号、平台、凭据和data_dir始终原样保留。配置摘要已变则拒绝；若所请求字段已全部相同，只报告当前事实changed=false，不冒充原操作回执。配置操作不需要另一套业务日志或操作状态机。

配置读取与写入之间发现人工修改时拒绝覆盖；手工编辑与SDK修改须串行，不承诺对未配合的编辑器提供文件系统级比较交换。启动入口保存所读配置快照，取得实例锁后、认证或建库前复核；期间文件变化则拒绝启动，避免并发启动使用旧配置。单纯查询和validate不得创建数据目录、锁或数据库。validate检查公共配置和角色命名区域，输出仍不含正文；通过只表示本地结构有效，连接、宿主探测、技能和工具可用性在实际启动后分别核验。

## 安装与实例核对

运行状态的installation在启动时冻结，包含format、environment（实际Python安装前缀）、releaseId、versions和assembly。产品安装器在依赖/版本/完整性检查后写入环境根的ioalab-release.json及.ready；前者保存格式ioalab.access-installation/1、清单摘要releaseId和发行包versions，后者保存相同摘要。运行时只读取本机安装元数据，不导入清单中的业务模块。两文件不一致、已安装版本不符或缺必需项时拒绝就绪，不修补正在使用的环境。

runtime.start同时核账号、非凭据配置摘要及installation；旧进程缺该信息、宿主装配不同、安装前缀或发布摘要改变，均返回installation_changed，要求显式安全停止后用原配置/数据目录启动。不能启动第二个写入者或删除状态来消除不兼容。

产品技能/CLI的普通角色或业务调用先核当前受认证运行状态的installation，再将请求固定到同一bootId；核对后实例发生切换时返回instance_changed，不向新实例发送业务。runtime.status、identity.status、confirmations.get、operations.get、runtime.open_ui和runtime.stop保留为旧实例诊断及安全停止入口，不由此开放新的业务效果。停止仍绑定实际bootId。独立serve主线程接收SIGINT/SIGTERM时只设置停止意图，随后通过同一调度器排空；拒绝新业务和新调度，原已运行作业可完成原授权工具。信号处理保持到连接、数据库及执行锁实际关闭，重复信号不强杀；嵌入其他线程的运行时由宿主管理信号。runtime.stop的completed只表示调度器当前无活动作业，不证明IPC、连接和目录写入者已全部释放；升级方仍需核对对应目录的OS锁，不得以答复或描述符消失替代。排空期间，仅由调度器认证为当前运行中、未等待用户的原作业上下文可继续执行工具；上下文须属于本实例且仍在活动集合中，异步工具回调保留该上下文。队列、已结束、等待用户或其他实例的上下文不能取得许可；平台连接、原授权、工具范围和期限照常核验，不通过普通RPC提供排空豁免。

未经过产品安装器的自管环境报告实际安装前缀、SDK及装配包版本，releaseId为空；不得冒充已核验发布。自管环境执行显式停止后升级，不支持对活跃进程原地热替换源码或依赖。安装信息只用于兼容核对，不代替身份认证、用户授权或工具权限。

## 按摘要读取验收器包

两角色共用账号会话读取ioalab://pkg/sha256引用，只请求同一平台的原不可变资源，每次核验完整字节摘要。读取断开或响应截断时，可在同一次调用中最多读取3次，间隔150、300毫秒；只重复GET，不重新调用模型、上传、签名、付款或其他业务写入。凭据在读取前取得一次，不因重试重复续用。超时、HTTP状态错误和摘要不符直接报告，不当作可重试断开；次数耗尽仍保留原错误与业务状态，不以重新生产掩盖未知结果。

## 公共操作

账号会话由 SDK 共用模块维护：两角色复用同一账号目录中的凭据缓存和待恢复登录操作；首次调用前先持久化 operationId，响应未知时沿用。有效凭据复用及续用不调用密码登录；明确重新登录才建立新操作，已有未核实登录须先恢复，不能覆盖。失效凭据不妨碍通过受控 account.login 入口显式重新认证。凭据与本地私钥不进入模型参数、状态摘要或日志。服务身份绑定不创建个人助手，身份就绪、连接就绪和可以接单分别报告。

| 操作 | 输入 | 输出 |
|---|---|---|
| `account.login` | 本地账号配置引用、显式登录意图 | 原登录结果或待恢复操作；不向模型返回原密码/令牌 |
| `account.refresh` | 当前有效的本地凭据 | 受限 SDK 凭据更新；不赠币，失效时要求重新登录 |
| `runtime.start` | 本地配置引用、要启用的角色 | 实例、各身份及连接/宿主能力状态；失败原因明确 |
| `runtime.status` | 本地实例引用 | 各角色就绪、连接、队列、等待确认与未核实操作摘要；不暴露凭据 |
| `runtime.stop` | 停止方式及等待条件 | 进程停止或等待已有动作收敛；不删除状态、不声明业务取消 |
| `identity.status` | 本端身份引用 | 当前账号、agentId、角色、公钥绑定及权限摘要 |
| `operations.get` | 原data.reference完整对象：job为kind/id；delivery为kind/agentId/operation/operationId；不以job.reference字符串替代 | 外层status表示查询结果；data内的原作业status才表示业务进展，completed后从data.data读取原产物 |
| `operations.resume` | 同一原reference | 核同一投递/作业；不提供通用模型重跑，未知效果由所属角色恢复 |
| `runtime.open_ui` | 空参数 | 打开本机受控用户页，不返回批准凭据、不表示已批准 |
| `confirmations.get` | 原确认引用 | 等待、同意、拒绝或过期，以及可信答复关联 |

`provider.pause` 只停止接新单；`runtime.stop` 停止进程。两者不得混用。停止或重启不自动取消合同、释放有效承诺或延长协议期限。

## 显式登录恢复

account.login由SDK的短期账号控制入口执行，不是另一个常驻运行时。产品技能将命令交给已安装的SDK；SDK统一读取配置，持同一data_dir的client.lock，只打开账号会话，不加载角色、私钥、业务库、九问或模型。常驻实例仍持锁时明确要求先runtime.stop并核实际释放；不停止别人的实例或并发读写账号库。普通启动不因认证失效自动重新密码登录。

| 当前账号会话 | 显式account.login行为 |
|---|---|
| 有效缓存、无未核实登录 | 在线核账号后复用；不生成新登录操作、不赠币 |
| 缓存失效、无未核实登录 | 明确认证失败后新建一次登录，成功后保存同一账号的新凭据；网络错误或5xx不能触发新登录 |
| 无缓存 | 沿同一会话模块创建一次初始登录 |
| 未核实登录 | 先校验原输入并恢复同一operationId；不换标识，不因重试增加赠币 |
| 已明确拒绝的登录 | 普通启动保持拒绝；再次显式account.login保存原拒绝记录后复用有效缓存或建立一次新登录，允许用户修正账号配置 |
| 输入已改变或原记录无法验证 | 保留原记录并要求检查；不能拿新密码/新账号改写未核实请求 |

登录发送前保存operationId、待恢复阶段及本机HMAC输入摘要；HMAC密钥仅在同一受限账号库中，输入摘要、密钥、密码及令牌均不回传模型。请求仍只含原有username、password、operationId，不新增网络字段。结构化400/invalid_input或401的明确认证拒绝保存为rejected；超时、断开、5xx、限流、冲突和不可识别响应保留pending，不能据此推定未提交。已提交结果恢复但凭据已经失效时先保留该原结果，再由下一次显式登录开始新操作。

账号绑定是平台、账号名及已知不可变账号ID的共同约束。不可变ID独立保存于账号绑定元数据，不能因单条令牌缓存缺失而丢失原归属。核当前账号、恢复登录或续用时不得把同名但不同ID当作原所有者；拒绝发生在替换缓存或本地身份之前。成功回执仅报告认证、账号、原登录标识和是否新登录，不暴露凭据；重试相同回执不等于又赠币。

SDK CLI采用`ioalab-access login --config <文件>`；两种产品技能均以`account.login --config <文件>`调用，不要求用户填写令牌或账号库路径。account.refresh继续由当前常驻实例经认证IPC处理，使用既有会话续用；失败不回退密码登录，也不赠币。受管实例启动前可由明确部署配置调用同一login入口，不给长期进程添加管理员凭据或额外登录引擎。

## 配置契约

| 范围 | 必需/可选内容 | 读取方 |
|---|---|---|
| 公共配置 | platform_url、username、password、data_dir；可选user_browser | 本地接入组件；凭据由受限配置文件或明确环境变量提供 |
| 执行配置 | 原版九问命令/工作目录、max_model_runs、业务工具授权 | 本地运行时及宿主适配器 |
| 个人助手配置 | 收信规则目录、委托比选策略、允许的本地工具 | 个人助手端模块 |
| 服务方配置 | 多个服务声明、模板引用、业务技能与接单上限 | 服务方端模块 |

配置模板和部署归属见[部署](../工程/部署.md)。模型通过状态接口获知缺项和能力，不读取密码、私钥、模型密钥或包含它们的整个配置文件。平台不下发可执行指令来改写本地配置。

业务技能是处理说明，不自动授予宿主工具。服务方配置的 native_tools 将精确工具名映射为 allow、ask 或 deny，不接受通配符、别名歧义或与 SDK 回调同名；其归属与使用规则见[服务方端 SDK](服务方端SDK.md)。AgentHost 定义携带冻结工具清单，角色为每轮明确是否启用；九问适配映射为原版工具白名单和本轮 permissions，不修改宿主全局策略，保留原有拒绝与参数安全规则。工作目录不是额外的安全沙箱。

SDK 提供的本单回调在宿主本轮可标记 allow；原生 ask_user 不由此放宽，回调内部仍执行全部阶段、签名和用户确认检查。真实用户许可来自 SDK 确认记录，不来自宿主工具被允许、配置中写 allow 或模型提供的参数。

业务技能 names 与本机源目录分别配置：角色的 skills 列出本单可用名称；九问宿主的 skill_directories 将名称映射为本机用户明确选择的绝对目录，可来自原生技能加载结果中的 skill_directory。它是普通业务文档输入，不依赖九问内部数据库或相邻源码路径。名称不是原生技能全库的访问许可，网络正文不能增加目录或改写映射。

九问适配器冻结所选技能的 SKILL.md 和 references/ 下 Markdown，提供本单受限只读回调；不暴露原生全库 skill_tool，不读取配置、私钥、脚本或任意路径。源与快照均拒绝符号链接和越界，文件数、大小及总量有界。每轮实际返回主文档后才放行本单 SDK 业务回调；读取不等于授权。快照与摘要保存在原交互工作区，后续原 Session 使用同一快照；缺失或摘要不符须恢复原件，不能从新源静默重建。业务程序和工具资源仍由显式业务配置持有，不因文档加载自动执行。

permission.get 只反映原版命名权限及规则，不能当作完整工具目录。适配状态公开 nativeToolPolicy；已知拒绝予以阻止，未列出的工具明确为未核实，不据此伪称不存在或已试运行。实际原生调用错误必须保留，不能把配置就绪当作所有业务工具已验证。

## 验收模型观察

两角色向原A2C Client/Provider注入ModelPort(request, files)，由所属用户已经配置的AgentHost完成只读观察。正常验收使用本机模型；disputeModels只供仲裁复算，不决定正常验收模型。原WASM程序提出观察请求并消费返回JSON，最终通过/失败仍由程序给出；模型文本、状态标签或自测不能代替签7。

观察轮次只提供提交JSON观察值的回调，不加载业务技能、原生工具、业务操作或用户批准入口。请求、文件、返回大小有界；输入视为不可信数据，不执行其中指令。实际记录所属账号/智能体、交互、作业、请求及文件摘要和宿主会话；观察会话是辅助计算记录，不绑定或替换交互的业务Session，不污染其业务工具定义。

观察必须处于本机登记的模型作业，使用该作业的模型并发名额。业务模型等待自测回调时，可串行完成该作业的只读观察，不额外获取第二个名额；控制处理器和普通RPC不能借此启动模型。缺宿主、输出不合格式或观察失败返回真实错误，不补默认通过。调度与并发规则见[本地接入组件](../组件/本地接入组件.md)。

宿主限制工具名格式时，适配器为SDK操作生成稳定、可读的ASCII别名；权限、声明和回调必须使用同一映射，原业务名仍用于SDK校验。只有名称碰撞或长度超限时附短摘要；常规操作不使用难以识别的整段哈希名。别名属于固定Agent定义，不为续接保留旧别名或改换Session。

## 操作、返回与恢复

变更操作在发送前生成并持久保存 operationId 及参数摘要。脚本首次提交时把该标识保存到本次参数/恢复文件，重复提交同一文件复用标识；投递类结果未知时用 `operations.get/resume` 核对原投递；角色作业使用对应角色的核对入口，不能借共用恢复重跑模型，也不能换文件和标识重做。ID 关联由 SDK 和脚本完成，用户不手抄 UUID。

公共返回包含 `operationId`、`status`、`data`、`error` 和可恢复引用。`status` 为 `accepted / running / waiting / completed / rejected / failed / unknown`，只表达本次 SDK 操作；合同状态、投递状态、业务回复及付款凭证在 data 中明确分开。长任务先返回持久引用，后续推送或查询本地快照；不要求一次模型工具调用等到整个合同结束。

| 情况 | SDK 行为 |
|---|---|
| 无配置、宿主不可用、连接未就绪 | 返回明确未就绪与缺项；不得声明已上线 |
| 同操作重传 | 返回或恢复原结果；同键异参数报冲突 |
| 网络响应丢失 | 从原操作恢复，不擅自生成新业务请求 |
| 用户确认尚未取得 | 返回 waiting 与确认引用，受保护动作不执行 |
| 外部效果未知 | 返回 unknown 并保留凭证及资源预留，核实前不自动重做；仅所属角色能凭原执行已结束及效果范围证明显式续接，恢复回执与原作业同事务保存 |
| 协议错误或权限失效 | 原样保留可公开的原因，停止对应阶段，不绕过 SDK |

业务请求重试、改变业务输入和继续同一交互是三件事：重试沿用原消息；新输入创建新消息并保持已有交互句柄；不同目的或接口创建新交互。完整关联规则见[消息中心](../组件/消息中心.md)。

原 Store、逐次调用关联、任务快照、履约组合和恢复规则统一见 [A2C 适配](A2C适配.md)。角色经共用适配使用原协议，不另建签名、算价或合同状态机。

## 本地业务工具

业务工具以SDK的ToolBinding描述名称、输入Schema、副作用类别、实现修订、可选requires_steps与output_schema；BusinessTools返回一组绑定，以及可选start、status、close资源回调；构造无副作用，取得本地实例所有权后启动，status只读且有界，作业停止后关闭。普通SDK仅接收注入的绑定，不导入具体业务包。装配入口按本机host.business_tools配置加载已安装包在ioalab.business_tools组登记的工厂：每项含factory、profile、options；工厂名是注册名，不是Python路径，profile必须属于本实例。没有配置时不加载；重名、未知包或能力缺失明确拒绝。工厂只校验和构造本地工具，不认证身份、初始化空日程或执行业务。

output_schema为可选的自包含JSON Schema对象，最大16 KiB，构造绑定时校验结构，拒绝布尔值及外部引用；声明的format必须具有已安装校验器，缺失或不支持时明确拒绝，date-time按RFC3339核验，不能将未执行校验当作通过。None明确表示工具未提供正式输出格式，不推断其成功字段。已声明时，工具目录、发布预览、入站模型上下文均提供原输出格式及字段含义；输出契约纳入工具策略及会话定义摘要。已有冻结规则不能静默取得改变后的工具契约，须按原规则更新与确认流程发布新修订。

助手、服务方及直接通知等执行入口使用同一输出校验。业务工具返回后先保存可序列化的原回执，再校验声明的格式；有效结果原样返回，不转换状态或补默认成功。格式不符报告invalid_tool_output并保留原回执及未知效果检查点，阻止后续写入与自动重跑；不能以输出错误断定副作用没有发生。未声明输出格式的工具仍保留原JSON与效果检查，不强制替换既有业务工具。

工具限定在所配置profile；助手工具须在已确认收信规则中列出，服务方工具只在本单生产阶段开放。SDK提供固定operationId、agentId、messageId、interactionId、sessionId；服务方另含contractRef和period。输入不得替换上下文。工具前保存调用原件，重复原调用恢复结果，异输入冲突；未知效果阻止新的写入，不自动重调。规则/会话保存工具策略摘要，后续缺失或变更须恢复原定义或重新确认，不扩展在途权限。requires_steps仅用于服务方工具，调用前须有本卡本期对应环节的原有效同意，不接受模型自称已获准。

operationId关联一次工具调用，不代表唯一业务请求；模型可能用不同调用ID再次处理同一条消息。工具按其业务语义选择SDK提供的稳定来源或合同依据进行去重，不以模型生成的调用ID解除原结果约束；改变业务输入须走所属流程的新请求，不能在原消息内改写已决定的效果。SDK不为各业务另建状态机。

日程、通知等工具各自保存业务记录，SDK只保存调用关联和回执。关闭时先等SDK作业结束，再关闭工具资源。业务凭据由工具读取本机显式变量/文件引用，不进入工具Schema、模型、平台或Git。独立SDK用户按需安装业务包，产品接入环境预装官方工具但按本机配置加载；分发/原生网页接入须另行验收，不能将已安装等同业务就绪。

## 用户确认

确认记录绑定账号、业务对象及摘要、阶段、动作和有效期。宿主从真实用户答复建立可信关联；模型提供的 `confirmed=true`、自己的“用户已同意”文本或外来消息均无效。SDK 在执行前复核确认对象未变化、权限未扩大、未过期。

九问原生答复关联经过适配验证后使用；宿主无法提供可信关联时，操作保持 waiting，由本地受控确认入口取得真实答复。该入口只在本机授权上下文中工作，远端服务和模型不能替用户写入批准记录。一次委托授权不能替代合同确认、合同声明的环节授权或验收确认。

本机确认记录绑定账号/智能体、原操作、对象摘要、阶段、动作、实际可读预览及期限；同操作重传恢复原记录。受保护模块根据真实对象生成预览并核验完整绑定，不接受模型提供一段替代摘要。批准只供原操作使用，未知外部结果保持原关联；已完成的原结果可恢复，新效果仍核验当前期限。

预览完成不等于已创建待确认记录。需要确认的角色操作先调用一次以申请确认；返回waiting及原确认引用后再调用runtime.open_ui。页面打开只表示入口已打开，不表示有待确认内容或用户已批准；真实决定后重发原参数文件和operationId。不得要求用户先在聊天中回复同意，再创建实际待确认操作。

确认页使用本机配置的可选user_browser：省略或null表示系统默认浏览器，指定时必须为已安装浏览器可执行文件的绝对路径，不含命令参数。SDK在启动时读取并纳入非凭据配置摘要；改动后按原实例安全停止/重启生效，不修改系统默认浏览器或九问。runtime.open_ui不接受浏览器路径、URL或额外参数，启动失败明确返回未就绪，不回退其他浏览器。脚本只返回是否已发起打开，不返回入口凭据；浏览器扩展连接及权限仍由用户配置。

受控页面与脚本 RPC 使用分开的认证能力。runtime.open_ui 只在用户本机打开页面，不向脚本返回页面访问凭据；一次性入口换取仅浏览器持有的会话，批准还须同源及 CSRF 校验。confirmations.get 只读取原确认，不提供 approve/answer 的普通 RPC。页面展示完整预览、所代表账号、允许/拒绝及真实状态；拒绝、过期或对象变化均不执行受保护动作。

九问原生 ASK 的问题保留真实 request/session/interaction 关联，通过同进程回调等待用户答复；该答复只回答对应宿主问题，不自动批准另一个 SDK 动作。确实需要等待回调的进程保持运行，截止或取消按真实结果处理；不伪造回答、不杀进程后将其记成可恢复 waiting。

部署管理员可为自有内部服务配置[部署发布授权](../组件/注册中心.md#部署发布授权)，仅替代匹配条款的逐次公示确认；普通角色RPC不能创建或扩大此授权，不能据此替用户签署合同或验收。

收信规则可表达用户事先批准的自动处理范围；只在该范围内执行，新增工具、副作用或扩大范围仍需用户确认。天然的业务拒绝不属于系统失败，也不能用不断重试绕过拒绝。

SDK本机启动辅助函数允许装配入口显式提供子进程环境；这不是RPC参数或新权限。部署协调器按[部署](../工程/部署.md)隔离管理员凭据；普通启动仍使用所属用户的环境。

## 安装与发布

原生流程页通过宿主技能加载接口的相对文件参数读取，不从参与方data_dir拼接技能路径。终端脚本使用原生返回的实际目录；若模型可见结果省略目录，限定在九问工作区定位所选技能，不增加安装搜索服务或修改宿主。

两个产品技能的源文件归 `src/access/skills/`，最小接入样例归 `src/access/examples/`。发布包包含配置模板、通用流程页、确定性脚本，以及清单锁定的 `ioalab-sdk`、`ioalab-jiuwen`、A2C 和九问 Process SDK 的本地 wheels；摘要与安装资源由构建工具生成，不回拷成为第二份源码。九问本体仍按[部署规范](../工程/部署.md)保存在 vendor，使用独立宿主环境。

原生通知准备也由引导转交配置路径、独立参数文件和产品角色给九问适配入口；适配使用SDK统一读取，核对profile实际归属与角色，不另写配置解析器。

配置完成后，经随包scripts/ioalab.py执行runtime.start。依赖已安装时校验配置并启动装配；缺依赖时只发起独立安装任务并快速返回waiting，随后按nextAction查询runtime.install.status。安装完成后再调用runtime.start，查询runtime.status与identity.status核身份、连接及宿主。runtime.install用于显式预装/重试已知失败；runtime.install.status仅查询，不触发安装。runtime.validate仅做配置检查；其他业务或诊断操作不得隐式安装，依赖未就绪时返回明确前置条件。runtime.*、assistant.*、provider.*是脚本操作参数，不是九问原生工具或商店动作。

普通依赖使用配置的国内包镜像，不现场拉取GitHub。检查用户已有九问的公开接口，缺少支持能力时返回具体未就绪项，不自动替换用户九问。读取脚本、清单或模型自述不能证明执行成功；须保留真实调用回执及实际状态，不根据源码推演或补写成功报告。

两种技能使用同一接入发布清单固定兼容组合，同账号、同本地实例复用安装环境和常驻组件。导入另一角色技能只增加相应配置；版本不兼容时先报告，不能再启动竞争的身份库写入者。SDK、适配包、技能和示例的设计依据分别按[架构](../架构.md)记录，不把设计版本当成已实现版本。

产品本机配置使用本地运行时格式，两个技能默认读取~/.ioalab/settings.local.json；用户由settings.example.json创建该外置文件，不放在会被原生导入覆盖的技能目录中。脚本可通过--config指定其他配置，第二个技能继续复用同一文件及data_dir。配置与SDK持久数据目录也分开；分发和升级不携带或重建用户本机文件。不再回退读取技能目录中的旧位置。两个技能的公共脚本维护一份源，构建时生成各包的 scripts/ioalab.py；共用源及说明归 src/access/skills/_shared，已生成分发内容不另行手改。公共启动说明维护在_shared/references/shared-runtime.md，构建到两个产品的references/shared-runtime.md；角色setup页只保留自己的配置与业务差异。安装生命周期由共用scripts/installer.py负责，ioalab.py仅路由操作和转交用户文件路径；两脚本各只有一份共用源，随包生成。安装按依赖清单摘要releaseId共用一次尝试，以attemptId区分已知失败后的显式重试；不建立IoA交互或读取账号配置。前台短期启动锁防止重复创建，后台安装锁证明当前所有权；元数据读取与临时文件替换另共用短期元数据锁，不持此锁执行安装。PID/任务文件不能独立证明存活，元数据损坏仍返回unknown，不据锁或重启猜测修复。等待阶段返回stage=installation、原releaseId/attemptId、日志路径和下一步，明确requestSubmitted=false，原业务参数文件不回写。查询不创建任务；前台退出或工具观察超时不终止后台任务，不通过修改九问全局时限解决。后台仅继承必要系统环境和明确的包镜像配置，不继承平台/模型/通知凭据。

完成须核清单、wheels、依赖版本和pip check，再发布安装标记；标记与实际包不符拒绝原地覆盖。安装锁已释放且记录为明确failed时，修正原因后可显式runtime.install重试；记录仍为进行中但无实际所有者时返回unknown，保留环境和日志，不因PID缺失自动重新安装、删缓存或运行SDK。完成和失败的元数据只表达依赖安装，不代表SDK启动或业务就绪。

共用依赖约束在开发环境验证后随源发布，构建不通过读取服务器上已安装的参与方包来推导版本；平台构建技能包无需先把 Process SDK 装进核心环境。更改依赖时更新锁文件并补做隔离安装，两个包仍使用同一份清单。

本机 CLI validate --config 只读取并校验，返回配置摘要、数据目录和身份概要，不登录、签名或打开运行数据库。摘要覆盖账号标识、平台、数据目录、身份、并发及角色/宿主执行配置，排除密码实际值。runtime.status 返回本实例启动时的同一摘要；引导检查预期与实际摘要，存在差异时返回明确配置未生效和安全停止/重启提示，不能以旧实例存在报告新配置就绪。摘要不是登录证明或授权凭证，密码变更不作为此摘要的用途。

不得修改九问源码、全局指令、加载机制或全局 Python 环境。导入技能、成功安装、启动进程和业务就绪分别报告。失败不写就绪标记，升级先保留身份与业务状态，不能靠删库解决迁移。官方会议等业务工具按用户配置选装，不成为通用 SDK 或接入技能的必需依赖。

## 案件恢复与新轮次

双方共用案件读取、文书验签和原引用恢复适配。验签固定原市场、caseRef、对象及依据/材料摘要，并核签名时点与issuedAt一致；已经签发的历史裁定不能按新请求的新鲜度窗口作废。除新宿主轮次外，委托方新的验收、环节授权、解除等受保护动作也先核当前案件；迟到的用户批准不能复活已裁定卡，已签历史恢复不重签，付款仍只允许冻结原卡的既有依据。恢复使用本机已存admission查询所属案件，不依赖首次通知仍在TTL内，也不要求用户手抄caseRef。启动恢复和每个新的宿主业务轮次开始前取得当前案件事实；旧的幂等request.start回执不证明当前仍可开始新业务。读取未知时不启动新轮次，原已开始轮次按实际writer收敛处理。

contract.ruling可靠推送继续用于及时停止新动作；它是原裁定的通知，不是运行结果，也不是唯一恢复渠道。已裁定卡的原控制/付款与新业务区分，直至委托中心确认安全结束；完整规则见[委托中心](../组件/委托中心.md#裁定执行与容量收尾)。
