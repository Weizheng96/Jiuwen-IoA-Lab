# IoA Lab SDK 共用机制

## 目的与范围

IoA Lab SDK 是一个软件包，分为[个人助手端 SDK](个人助手端SDK.md)和[服务方端 SDK](服务方端SDK.md)，共用连接、存储、身份及宿主调用契约。服务方端运行在服务提供者的电脑或服务器，不是平台后端；两端均主动连接平台。

本文定义公共调用、配置、返回和安装契约。常驻执行的内部职责、状态权威及恢复规则只在[本地接入组件](../组件/本地接入组件.md)定义；网络格式只在[平台接口](平台接口.md)定义。

## 包结构与调用边界

| 对象 | 规范职责 |
|---|---|
| `ioalab-sdk` / `ioalab_sdk` | 源码归 `src/access/sdk/`，提供 assistant、provider 两个角色入口及共用 runtime |
| 本地接入组件 | SDK 的常驻运行方式；唯一持有该实例私钥、SDK 业务数据库及连接 |
| 接入技能脚本 / CLI | 读取非模型配置、发送结构化本地请求、显示真实回执；不再实现签名和业务状态机 |
| A2C 适配 | 复用 A2C Client/Provider、验签、算价及 WASM 验收；IoA transport 接入推送及本地任务视图 |
| `ioalab-jiuwen` / `ioalab_jiuwen` | 源码归 `src/hosts/jiuwen/`，实现可选 AgentHost 适配及接入启动装配，通过原版公开接口连接九问 |

项目目录、发行包及 VERSION 归属统一见[架构](../架构.md)。核心 SDK 不导入平台、九问或官方业务工具；九问适配包依赖 SDK，并在启动入口构造宿主对象、注入运行时及角色处理器。宿主能力契约见[本地接入组件](../组件/本地接入组件.md)，不建立另一套角色执行器。

九问调用可能附带 call_goal 等已知展示元数据。适配层只在宿主声明中接纳其对应字段，分离后将原业务参数交给 SDK 严格校验；不扩大业务 Schema、不把元数据当作权限或执行指令，也不修改九问源码。业务 Schema 已显式定义的同名字段按业务字段保留，适配不得静默删除。

本文各页的点分名称是 SDK 能力及脚本操作契约。脚本形式统一为 `python "<skill_directory>/scripts/ioalab.py" <operation> --args-file <UTF-8参数文件>`；具体 Python 类封装不另定义业务含义。参数文件须先实际创建，结果必须来自脚本真实输出。

业务调用经过本机认证的 IPC 或回环 API；CLI 不打开运行时身份库。启动引导可创建运行时，但失败必须返回未就绪，不能退回脚本自行持有私钥执行。长连接由运行时维持，不靠模型循环调用平台收件接口。

## 本机调用与启动

| 项 | 契约 |
|---|---|
| 常驻入口 | SDK 提供运行入口；九问适配包在自己的入口装配宿主及角色处理器，不修改 SDK 的分发器 |
| 本机端点 | 只监听 127.0.0.1 的随机端口，POST `/v1/call`；拒绝任意 Origin、非本机 Host、无访问凭据及超限请求；不提供跨域访问 |
| 请求 | operation、operationId、arguments 三字段；显式登记操作，禁止任意反射/执行；默认最大128 KiB |
| 返回 | 使用本文统一操作结果；业务未就绪明确返回，不能因为本机 HTTP 成功而报告委托成功 |
| 端点发现 | CLI 只读 data_dir 中 runtime.json，验证回环地址及实例；不打开 SDK SQLite 或私钥文件，不把本机访问凭据打印给模型 |
| 生命周期 | runtime.start 验证受限配置并启动；runtime.status 查询当前实例；runtime.stop 拒绝新业务、等待当前轮次收敛并关闭连接，保留所有数据及原业务状态 |
| 原操作 | 变更请求的 operationId 在发送前保存；超时返回 unknown，恢复沿用原标识；已持久入 outbox 表示本地接受，不表示平台送达或业务完成 |
| 未知能力 | 没有对应处理器或宿主能力时返回 not_ready；不能落回旧脚本直接执行或接受 confirmed=true 自证授权 |

共用配置用 JSON 保存 platform_url、username、password（或 password_env）、data_dir；相对路径以配置文件目录为基准。data_dir 是 SDK 专用目录，配置及调用参数文件保存在其外；检测到混放的无关数据时拒绝启动，不修改它们的权限。运行目录及凭据文件使用所属用户权限，Windows 使用用户 SID 的 ACL，不能把只读写标志视为 ACL。identities 为本机激活的 profile 列表，每项含 key、role（assistant/service）、name；key 对应本地持久身份，不是账号名或用户手填 UUID。最多一个助手及总计64个身份，默认模型并发2、待处理上限128，分别由 max_model_runs、max_pending_requests 配置。角色业务与宿主配置使用独立命名区域，由相应装配模块校验，SDK 不加载配置中指定的任意 Python 类或脚本。

本机状态分别列出进程/IPC、认证、身份绑定、平台连接、宿主和角色执行能力。只收到 WS 消息不能报告业务处理完成；离线、缺宿主或缺规则时可靠保存消息并保持未执行。

## 公共操作

账号会话由 SDK 共用模块维护：两角色复用同一账号目录中的凭据缓存和待恢复登录操作；首次调用前先持久化 operationId，响应未知时沿用。有效凭据复用及续用不调用密码登录；明确重新登录才建立新操作，已有未核实登录须先恢复，不能覆盖。失效凭据不妨碍通过受控 account.login 入口显式重新认证。凭据与本地私钥不进入模型参数、状态摘要或日志。服务身份绑定不创建个人助手，身份就绪、连接就绪和可以接单分别报告。

| 操作 | 输入 | 输出 |
|---|---|---|
| `account.login` | 本地账号配置引用、显式登录意图 | 原登录结果或待恢复操作；不向模型返回原密码/令牌 |
| `account.refresh` | 当前有效的本地凭据 | 受限 SDK 凭据更新；不赠币，失效时要求重新登录 |
| `runtime.start` | 本地配置引用、要启用的角色 | 实例、各身份及连接/宿主能力状态；失败原因明确 |
| `runtime.status` | 本地实例引用 | 各角色就绪、连接、队列、等待确认与未核实操作摘要；不暴露凭据 |
| `runtime.stop` | 停止方式及等待条件 | 进程停止或等待已有动作收敛；不删除状态、不声明业务取消 |
| `identity.status` | 本端身份引用 | 当前账号、agentId、角色、公钥绑定及权限摘要 |
| `operations.get` | 原 operationId | 本地操作、远端凭证及当前真实状态 |
| `operations.resume` | 原 operationId | 恢复同一操作；先核对已有结果，不能创建第二笔付款或承诺 |
| `confirmations.request` | 所属业务对象、阶段、动作、摘要与期限 | 待确认记录及用户可读摘要；不表示已同意 |
| `confirmations.get` | 原确认引用 | 等待、同意、拒绝或过期，以及可信答复关联 |

`provider.pause` 只停止接新单；`runtime.stop` 停止进程。两者不得混用。停止或重启不自动取消合同、释放有效承诺或延长协议期限。

## 配置契约

| 范围 | 必需/可选内容 | 读取方 |
|---|---|---|
| 公共配置 | platform_url、username、password、data_dir | 本地接入组件；凭据由受限配置文件或明确环境变量提供 |
| 执行配置 | 原版九问命令/工作目录、max_model_runs、业务工具授权 | 本地运行时及宿主适配器 |
| 个人助手配置 | 收信规则目录、委托比选策略、允许的本地工具 | 个人助手端模块 |
| 服务方配置 | 多个服务声明、模板引用、业务技能与接单上限 | 服务方端模块 |

配置模板和部署归属见[部署](../工程/部署.md)。模型通过状态接口获知缺项和能力，不读取密码、私钥、模型密钥或包含它们的整个配置文件。平台不下发可执行指令来改写本地配置。

业务技能是处理说明，不自动授予宿主工具。服务方配置的 native_tools 将精确工具名映射为 allow、ask 或 deny，不接受通配符、别名歧义或与 SDK 回调同名；其归属与使用规则见[服务方端 SDK](服务方端SDK.md)。AgentHost 定义携带冻结工具清单，角色为每轮明确是否启用；九问适配映射为原版工具白名单和本轮 permissions，不修改宿主全局策略，保留原有拒绝与参数安全规则。工作目录不是额外的安全沙箱。

SDK 提供的本单回调在宿主本轮可标记 allow；原生 ask_user 不由此放宽，回调内部仍执行全部阶段、签名和用户确认检查。真实用户许可来自 SDK 确认记录，不来自宿主工具被允许、配置中写 allow 或模型提供的参数。

## 操作、返回与恢复

变更操作在发送前生成并持久保存 operationId 及参数摘要。脚本首次提交时把该标识保存到本次参数/恢复文件，重复提交同一文件复用标识；若原动作结果未知，使用 `operations.get/resume`，不能换文件和标识重做。ID 关联由 SDK 和脚本完成，用户不手抄 UUID。

公共返回包含 `operationId`、`status`、`data`、`error` 和可恢复引用。`status` 为 `accepted / running / waiting / completed / rejected / failed / unknown`，只表达本次 SDK 操作；合同状态、投递状态、业务回复及付款凭证在 data 中明确分开。长任务先返回持久引用，后续推送或查询本地快照；不要求一次模型工具调用等到整个合同结束。

| 情况 | SDK 行为 |
|---|---|
| 无配置、宿主不可用、连接未就绪 | 返回明确未就绪与缺项；不得声明已上线 |
| 同操作重传 | 返回或恢复原结果；同键异参数报冲突 |
| 网络响应丢失 | 从原操作恢复，不擅自生成新业务请求 |
| 用户确认尚未取得 | 返回 waiting 与确认引用，受保护动作不执行 |
| 外部效果未知 | 返回 unknown 并保留凭证及资源预留，核实前不自动重做 |
| 协议错误或权限失效 | 原样保留可公开的原因，停止对应阶段，不绕过 SDK |

业务请求重试、改变业务输入和继续同一交互是三件事：重试沿用原消息；新输入创建新消息并保持已有交互句柄；不同目的或接口创建新交互。完整关联规则见[消息中心](../组件/消息中心.md)。

## 原协议适配与任务

原 Store、逐次调用关联、任务快照、履约组合和恢复规则统一见 [A2C 适配](A2C适配.md)。角色经共用适配使用原协议，不另建签名、算价或合同状态机。

## 用户确认

确认记录绑定账号、业务对象及摘要、阶段、动作和有效期。宿主从真实用户答复建立可信关联；模型提供的 `confirmed=true`、自己的“用户已同意”文本或外来消息均无效。SDK 在执行前复核确认对象未变化、权限未扩大、未过期。

九问原生答复关联经过适配验证后使用；宿主无法提供可信关联时，操作保持 waiting，由本地受控确认入口取得真实答复。该入口只在本机授权上下文中工作，远端服务和模型不能替用户写入批准记录。一次委托授权不能替代合同确认、合同声明的环节授权或验收确认。

本机确认记录绑定账号/智能体、原操作、对象摘要、阶段、动作、实际可读预览及期限；同操作重传恢复原记录。受保护模块根据真实对象生成预览并核验完整绑定，不接受模型提供一段替代摘要。批准只供原操作使用，未知外部结果保持原关联；已完成的原结果可恢复，新效果仍核验当前期限。

受控页面与脚本 RPC 使用分开的认证能力。runtime.open_ui 只在用户本机打开页面，不向脚本返回页面访问凭据；一次性入口换取仅浏览器持有的会话，批准还须同源及 CSRF 校验。confirmations.get 只读取原确认，不提供 approve/answer 的普通 RPC。页面展示完整预览、所代表账号、允许/拒绝及真实状态；拒绝、过期或对象变化均不执行受保护动作。

九问原生 ASK 的问题保留真实 request/session/interaction 关联，通过同进程回调等待用户答复；该答复只回答对应宿主问题，不自动批准另一个 SDK 动作。确实需要等待回调的进程保持运行，截止或取消按真实结果处理；不伪造回答、不杀进程后将其记成可恢复 waiting。

收信规则可表达用户事先批准的自动处理范围；只在该范围内执行，新增工具、副作用或扩大范围仍需用户确认。天然的业务拒绝不属于系统失败，也不能用不断重试绕过拒绝。

## 安装与发布

两个产品技能的源文件归 `src/access/skills/`，最小接入样例归 `src/access/examples/`。发布包包含配置模板、通用流程页、确定性脚本，以及清单锁定的 `ioalab-sdk`、`ioalab-jiuwen`、A2C 和九问 Process SDK 的本地 wheels；摘要与安装资源由构建工具生成，不回拷成为第二份源码。九问本体仍按[部署规范](../工程/部署.md)保存在 vendor，使用独立宿主环境。

引导脚本校验清单及摘要，在用户目录准备隔离接入环境，普通依赖使用配置的国内包镜像，不现场拉取 GitHub。随后检查用户已有九问的公开接口，启动适配包的装配入口；缺少支持能力时返回具体未就绪项，不自动替换用户九问。

两种技能使用同一接入发布清单固定兼容组合，同账号、同本地实例复用安装环境和常驻组件。导入另一角色技能只增加相应配置；版本不兼容时先报告，不能再启动竞争的身份库写入者。SDK、适配包、技能和示例的设计依据分别按[架构](../架构.md)记录，不把设计版本当成已实现版本。

不得修改九问源码、全局指令、加载机制或全局 Python 环境。导入技能、成功安装、启动进程和业务就绪分别报告。失败不写就绪标记，升级先保留身份与业务状态，不能靠删库解决迁移。官方会议等业务工具按用户配置选装，不成为通用 SDK 或接入技能的必需依赖。
