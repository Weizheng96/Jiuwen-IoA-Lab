# SDK共用机制 · 配置

本页是[SDK共用机制](../SDK共用机制.md)的子页；目的、范围与其他子页见父页。

## 不读取凭据的配置辅助

本机用户先在技能包外私下填写平台、账号、密码或环境变量引用及专用SDK数据目录。随后由九问按用户意图调用下列启动前命令；它们不走常驻RPC、不登录、不建身份、不运行模型或业务工具。产品引导只转交路径，SDK是配置唯一解析与更新者。

| 操作 | 输入 | 输出及边界 |
|---|---|---|
| `runtime.configuration` | 本地配置引用 | configurationDigest、dataDir、身份列表、已配置服务键、宿主字段名和可修改字段；不返回账号、凭据、业务资源、宿主参数值或工具选项 |
| `runtime.configure` | 独立参数文件中的expectedDigest、changes | SDK校验后的新摘要、changed；不返回配置正文，不启动或发布 |

changes仅允许：identities按稳定key新增或更新显示名；provider.services按服务key局部更新instructions、skills、native_tools、max_active_delegations、accepting；host的command、data_dir、model及按名称补充skill_directories；max_model_runs、max_pending_requests、user_browser。未指定字段保留，不删除身份、不改变已有role、不替换整个服务列表。profile键在大小写折叠后唯一，避免Windows目录冲突。业务资源和host.business_tools由用户或明确的工具配置入口单独管理，不通过这个通用入口读取或修改；参数文件不得含凭据。

变更沿用实际data_dir的client.lock，与运行实例、登录及其他配置变更互斥；有持锁者则拒绝，不能自动停止实例或另建目录。取得锁后复核原文件，按字段合并并由原公共及角色校验器检查，再用所属用户权限原子替换。账号、平台、凭据和data_dir始终原样保留。配置摘要已变则拒绝；若所请求字段已全部相同，只报告当前事实changed=false，不冒充原操作回执。配置操作不需要另一套业务日志或操作状态机。

配置读取与写入之间发现人工修改时拒绝覆盖；手工编辑与SDK修改须串行，不承诺对未配合的编辑器提供文件系统级比较交换。启动入口保存所读配置快照，取得实例锁后、认证或建库前复核；期间文件变化则拒绝启动，避免并发启动使用旧配置。单纯查询和validate不得创建数据目录、锁或数据库。validate检查公共配置和角色命名区域，输出仍不含正文；通过只表示本地结构有效，连接、宿主探测、技能和工具可用性在实际启动后分别核验。

## 配置契约

| 范围 | 必需/可选内容 | 读取方 |
|---|---|---|
| 公共配置 | platform_url、username、password、data_dir；可选user_browser | 本地接入组件；凭据由受限配置文件或明确环境变量提供 |
| 执行配置 | 原版九问命令/工作目录、max_model_runs、业务工具授权 | 本地运行时及宿主适配器 |
| 个人助手配置 | 收信规则目录、委托比选策略、允许的本地工具 | 个人助手端模块 |
| 服务方配置 | 多个服务声明、模板引用、业务技能与接单上限 | 服务方端模块 |

配置模板和部署归属见[安装与升级](../../工程/安装与升级.md)。模型通过状态接口获知缺项和能力，不读取密码、私钥、模型密钥或包含它们的整个配置文件。平台不下发可执行指令来改写本地配置。

业务技能是处理说明，不自动授予宿主工具。服务方配置的 native_tools 将精确工具名映射为 allow、ask 或 deny，不接受通配符、别名歧义或与 SDK 回调同名；其归属与使用规则见[服务方端 SDK](../服务方端SDK.md)。AgentHost 定义携带冻结工具清单，角色为每轮明确是否启用；九问适配映射为原版工具白名单和本轮 permissions，不修改宿主全局策略，保留原有拒绝与参数安全规则。工作目录不是额外的安全沙箱。

SDK 提供的本单回调在宿主本轮可标记 allow；原生 ask_user 不由此放宽，回调内部仍执行全部阶段、签名和用户确认检查。真实用户许可来自 SDK 确认记录，不来自宿主工具被允许、配置中写 allow 或模型提供的参数。

业务技能 names 与本机源目录分别配置：角色的 skills 列出本单可用名称；九问宿主的 skill_directories 将名称映射为本机用户明确选择的绝对目录，可来自原生技能加载结果中的 skill_directory。它是普通业务文档输入，不依赖九问内部数据库或相邻源码路径。名称不是原生技能全库的访问许可，网络正文不能增加目录或改写映射。

九问适配器冻结所选技能的 SKILL.md 和 references/ 下 Markdown，提供本单受限只读回调；不暴露原生全库 skill_tool，不读取配置、私钥、脚本或任意路径。源与快照均拒绝符号链接和越界，文件数、大小及总量有界。每轮实际返回主文档后才放行本单 SDK 业务回调；读取不等于授权。快照与摘要保存在原交互工作区，后续原 Session 使用同一快照；缺失或摘要不符须恢复原件，不能从新源静默重建。业务程序和工具资源仍由显式业务配置持有，不因文档加载自动执行。

permission.get 只反映原版命名权限及规则，不能当作完整工具目录。适配状态公开 nativeToolPolicy；已知拒绝予以阻止，未列出的工具明确为未核实，不据此伪称不存在或已试运行。实际原生调用错误必须保留，不能把配置就绪当作所有业务工具已验证。
