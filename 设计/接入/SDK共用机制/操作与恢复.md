## 操作、返回与恢复

确认页从原绑定preview确定性展示中文动作、授权范围、合同双方、总额/本次金额及费用、材料发送、交付物、验收要求与未覆盖项、期限；原件可展开，缺项标明未知，不由模型补写。展示与签署共用同一原件及bindingDigest，文本转义，模型提供的confirmed或A2UI答复不能产生批准。

可由受信启动装配注入封闭的用户确认通道，仅提供列举、读取原引用和提交原引用/摘要/用户决定，最终仍由既有decide/claim核验；它不属于模型IPC，不接受任意RPC、路径或代签参数，不将authority送出进程。本机UserUi的Host、Origin、一次入口和CSRF保持不变。远程试用通道额外绑定owner、seat、epoch和期限，撤权后拒绝读取、决定和恢复；通道密钥不得进入模型、页面或日志。

返回可携确定性nextActions，列出当前允许操作、真实原引用和缺失参数；拒绝、待确认或unknown不得给出跳过门禁的新效果指引。合并流程持久保存父操作、子操作与当前阶段，恢复不重建业务引用或重复费用，不把整个合同变成无用户节点的自动执行器。

变更操作在发送前生成并持久保存 operationId 及参数摘要。脚本首次提交时把该标识保存到本次参数/恢复文件，重复提交同一文件复用标识；投递类结果未知时用 `operations.get/resume` 核对原投递；角色作业使用对应角色的核对入口，不能借共用恢复重跑模型，也不能换文件和标识重做。ID 关联由 SDK 和脚本完成，用户不手抄 UUID。

CLI参数文件顶层的operationId保留给本次请求封套的外层幂等标识，转交arguments时将它分离；角色业务参数不得另以顶层operationId表示查询目标。业务引用使用所属入口明确命名的字段，例如合同履约查询的fulfillmentOperationId。operations.get的完整reference中嵌套的operationId仍属于原投递引用，不提升为参数文件的顶层字段。

公共返回包含 `operationId`、`status`、`data`、`error` 和可恢复引用。`status` 为 `accepted / running / waiting / completed / rejected / failed / unknown`，只表达本次 SDK 操作；合同状态、投递状态、业务回复及付款凭证在 data 中明确分开。长任务先返回持久引用，后续推送或查询本地快照；不要求一次模型工具调用等到整个合同结束。

| 情况 | SDK 行为 |
|---|---|
| 无配置、宿主不可用、连接未就绪 | 返回明确未就绪与缺项；不得声明已上线 |
| 同操作重传 | 返回或恢复原结果；同键异参数报冲突 |
| 网络响应丢失 | 从原操作恢复，不擅自生成新业务请求 |
| 用户确认尚未取得 | 返回 waiting 与确认引用，受保护动作不执行 |
| 外部效果未知 | 返回 unknown 并保留凭证及资源预留，核实前不自动重做；仅所属角色能凭原执行已结束及效果范围证明显式续接，恢复回执与原作业同事务保存 |
| 协议错误或权限失效 | 原样保留可公开的原因，停止对应阶段，不绕过 SDK |

业务请求重试、改变业务输入和继续同一交互是三件事：重试沿用原消息；新输入创建新消息并保持已有交互句柄；不同目的或接口创建新交互。完整关联规则见[消息中心](../../组件/消息中心.md)。

## 按摘要读取验收器包

两角色共用账号会话读取ioalab://pkg/sha256引用，只请求同一平台的原不可变资源，每次核验完整字节摘要。读取断开或响应截断时，可在同一次调用中最多读取3次，间隔150、300毫秒；只重复GET，不重新调用模型、上传、签名、付款或其他业务写入。凭据在读取前取得一次，不因重试重复续用。超时、HTTP状态错误和摘要不符直接报告，不当作可重试断开；次数耗尽仍保留原错误与业务状态，不以重新生产掩盖未知结果。

## 验收模型观察

两角色向原A2C Client/Provider注入ModelPort(request, files)，由所属用户已经配置的AgentHost完成只读观察。正常验收使用本机模型；disputeModels只供仲裁复算，不决定正常验收模型。原WASM程序提出观察请求并消费返回JSON，最终通过/失败仍由程序给出；模型文本、状态标签或自测不能代替签7。

观察轮次只提供提交JSON观察值的回调，不加载业务技能、原生工具、业务操作或用户批准入口。请求、文件、返回大小有界；输入视为不可信数据，不执行其中指令。实际记录所属账号/智能体、交互、作业、请求及文件摘要和宿主会话；观察会话是辅助计算记录，不绑定或替换交互的业务Session，不污染其业务工具定义。

观察必须处于本机登记的模型作业，使用该作业的模型并发名额。业务模型等待自测回调时，可串行完成该作业的只读观察，不额外获取第二个名额；控制处理器和普通RPC不能借此启动模型。缺宿主、输出不合格式或观察失败返回真实错误，不补默认通过。调度与并发规则见[本地接入组件](../../组件/本地接入组件.md)。

宿主限制工具名格式时，适配器为SDK操作生成稳定、可读的ASCII别名；权限、声明和回调必须使用同一映射，原业务名仍用于SDK校验。只有名称碰撞或长度超限时附短摘要；常规操作不使用难以识别的整段哈希名。别名属于固定Agent定义，不为续接保留旧别名或改换Session。

## 案件恢复与新轮次

双方共用案件读取、文书验签和原引用恢复适配。验签固定原市场、caseRef、对象及依据/材料摘要，并核签名时点与issuedAt一致；已经签发的历史裁定不能按新请求的新鲜度窗口作废。除新宿主轮次外，委托方新的验收、环节授权、解除等受保护动作也先核当前案件；迟到的用户批准不能复活已裁定卡，已签历史恢复不重签，付款仍只允许冻结原卡的既有依据。恢复使用本机已存admission查询所属案件，不依赖首次通知仍在TTL内，也不要求用户手抄caseRef。启动恢复和每个新的宿主业务轮次开始前取得当前案件事实；旧的幂等request.start回执不证明当前仍可开始新业务。读取未知时不启动新轮次，原已开始轮次按实际writer收敛处理。

contract.ruling可靠推送继续用于及时停止新动作；它是原裁定的通知，不是运行结果，也不是唯一恢复渠道。已裁定卡的原控制/付款与新业务区分，直至委托中心确认安全结束；完整规则见[委托中心](../../组件/委托中心.md#裁定执行与容量收尾)。
