# 平台接口 · 仲裁接口

本页是[平台接口](../平台接口.md)的子页；目的、范围与其他子页见父页。

## 仲裁接口

| 入口 | 输入 | 输出与边界 |
|---|---|---|
| POST /api/v1/arbitrations/preview | agentId、admissionId、ground；理由需要时含period | SDK Bearer认证；只读核本案原双方，返回subject、ground、period、assessedAt、deadline、eligible、route、basisDigest、evidence及requiredEvidence；不创建案件、不执行复算 |
| WS arbitration.request | admissionId、ground、必要period、basisDigest、materials分组；沿共用operationId | 返回平台caseRef及原受理回执，材料归属和内容摘要由平台复核，不能传替代原卡 |
| GET /api/v1/arbitrations/{caseRef} | agentId | 仅原双方查原案件/裁定、评估尝试及执行结束状态；未完成不返回虚构裁定 |
| GET /api/v1/arbitrations | agentId、admissionId | 以本机已保存的原接单引用恢复caseRef/案件；不存在明确返回无案件，不把其他账号的案件传给客户端 |
| GET /api/admin/arbitrations | 可选state、limit（1—100，默认50）、cursor | 网页管理员案件列表；过滤本账号作为当事方的案件，返回有界元数据及nextCursor，不返回私人正文 |
| GET /api/admin/arbitrations/{caseRef} | 原caseRef | 当前非本案当事网页管理员读取本案冻结申请、材料、实际评估及review当前复核依据；不扩大为私人消息审计 |
| GET /api/v1/arbitrations/{caseRef}/materials/{fileId} | agentId | 仅本案原双方读取本案冻结引用，核当前归属和实际摘要；不是任意文件下载入口 |
| GET /api/admin/arbitrations/{caseRef}/materials/{fileId} | 原caseRef、原fileId | 当前非本案当事网页管理员读取本案冻结引用；无本案引用、角色失效或自己案件均拒绝 |
| POST /api/admin/arbitrations/{caseRef}/review | operationId、expectedEvidenceDigest、liable（client/provider/none）、明确reason；必要时含compensation（amount、currency） | 当前非本案当事网页管理员复核；提交时重新核权限、依据和已知程序结果，SDK/模型不能调用 |
| POST /api/admin/arbitrations/{caseRef}/reevaluate | operationId、expectedEvidenceDigest、明确reason | 仅无已知结果且原writer结束的unknown案件，重用原材料/模型，记录实际尝试；不是普通SDK重跑 |
| WS arbitration.finish | caseRef及原执行关联 | 原服务方在实际收敛后确认结束；核对原任务事实，再释放并关闭，不调用被裁定禁止的card.close |
| 系统contract.ruling | 原caseRef、admissionId、subject和原裁定 | 只由平台可靠投递给原双方；参与方不能冒充系统发送；不是interaction.closed |

preview的period仅接受正整数；start-overdue及proposal-overdue不含period，其余理由必须指定真实期次。route为deterministic、recompute或review；eligible只说明当前理由的前提是否成立，requiredEvidence仍须在申请时补齐。basisDigest绑定原依据而不绑定流逝的时钟；受理与裁定再次核当前事实及期限。取证保留不足、原凭证矛盾或签名损坏时明确拒绝，不当作“没有证据”。

materials仅接受deliveryFiles、fetchEvidence、inputMaterials三个可选分组，每组为“协议文件名 → 完整FileRef”映射；FileRef沿用fileId、name、digest、size，所有分组合计最多32项。未使用分组省略；所需分组取自preview.requiredEvidence，空材料不能代替所需证据。SDK不让用户手工编辑引用：从已有授权字节准备所属上传，确认绑定实际依据及材料清单。相同操作不能替换任一引用；已存在案件恢复原受理结果，不创建第二份案件。

### 案件视图与摘要

| 字段 | 定义 |
|---|---|
| assessment / basisDigest | 冻结申请的原证据视图及内部原快照摘要；不随查询时钟或后续事实覆盖 |
| evaluation | 已知原程序结果及其原输入关联；尚无完整结果为null，不用异常伪造pass/fail |
| review | 仅独立网页管理员详情含此对象：evidence为最新原事实的公开视图，evidenceDigest为该视图摘要，expectedEvidenceDigest为实际复核确认依据，availableActions为当前可提交操作 |
| expectedEvidenceDigest | 规范JSON对象的摘要，对象含basisDigest、decisionEvidenceDigest（当前公开事实摘要）、materialsDigest、evaluationDigest、modelBindingDigest、currentModelBindingDigest、state。evaluationDigest对实际evaluation值（包括null）计算；不包含查询时刻，不授权动作 |
| decisionEvidence | 仅终局存在，为决定时冻结原事实的公开视图；尚未裁定为null。包含本单subject、原template/card/request、完整原环节、实际付款及marketOutcome（原市场结局；未结束为null），并用不含原请求凭据的protocolCalls摘要表示原协议进展 |
| decisionEvidenceDigest | 对decisionEvidence直接使用共用规范JSON摘要算法计算；裁定文书签名绑定该摘要。SDK必须重新计算，不能用原basisDigest或接收的摘要字符串代替 |
| execution | pending或finished；已有合法市场结清的中立案件沿原终态标finished，不重新释放或改写原市场结局 |

review/reevaluate的operationId沿原有1—128字符操作标识规则；reason为去除首尾空白后1—2000字符。原操作者/操作标识的同内容恢复原回执，异内容冲突；恢复仍须当前独立管理员权限。review只接受needs_review/unknown且本案实际评估writer已结束，reevaluate还要求无已知结果及原依据/材料/固定模型未变；双方SDK不能提交这些操作。

compensation仅在ground为termination-compensation且liable为client时使用；amount为明确非负十进制定数字符串，currency等于原卡币种，并核原未验收期金额上限。其他理由或中立裁定不得用该字段新增付款义务；不生成付款用途或自动过账。

案件及其文书为IoA外层对象；裁定含caseRef、admissionId、subject、ground、必要period、basisDigest、materialsDigest、decisionEvidenceDigest、rulingKind、liable、issuedAt及市场signature。实际合同另含cardDigest供原record_ruling使用；无卡请求不得伪造cardDigest或合同ledger。人工裁定rulingKind为review，附实际operator、reason及必要compensation；原程序结果保持原件。文书使用市场独立对象签名，不冒充A2C卡或带a2cVersion的协议对象。

案件内容、理由成立条件、人工复核与终局规则只在[委托中心](../../组件/委托中心.md#争议案件与原证据)定义。申请/查询/结束均使用原caseRef，不让用户手抄UUID，也不新增轮询维持连接的职责。
