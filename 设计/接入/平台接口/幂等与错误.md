# 平台接口 · 幂等与错误

本页是[平台接口](../平台接口.md)的子页；目的、范围与其他子页见父页。

## 幂等与错误

平台控制操作的幂等范围为“认证主体 + 操作类型 + operationId”，另绑定参数摘要；同键异参数返回冲突。消息另以全局 messageId 去重；控制操作 ID、消息 ID、交互 ID 和 A2C 任务 ID 不相互替代。

HTTP业务错误统一返回 `{"error":{"code","message","recovery"}}`，保留对应HTTP状态；参数、原A2C校验、认证及请求结构错误均使用同一封套，不混用字符串error或detail。已确定的输入错误明确拒绝并指导修改后新建操作，不因解析失败变成unknown；服务端故障或响应缺失仍按原操作核实，不据此推断业务未执行。原A2A/A2C协议响应保持原协议格式。

错误统一包含 `code`、可公开的 `message` 和 `recovery`：原操作恢复、修改输入后新建、等待用户、核实外部结果或不可重试。至少区分 `not_ready`、`forbidden`、`invalid_input`、`revision_conflict`、`id_conflict`、`capacity_full`、`service_paused`、`expired`、`closed`、`stale_generation`、`history_gap`、`quota_exceeded`、`protocol_error`、`unknown_result`；不得把网络超时等同业务未执行。

AP2 拟卡费通过平台应用服务协调 admission 与付款的同一事务，参数仍遵循 AP2，预留关联放在外层控制上下文。零拟卡费也必须在有效签署前提交预留；平台接口不新增绕过容量、付款幂等或参与方亲签的快捷路径。

ap2.pay提交期的PSP明确拒绝使用payment_rejected，保留可公开实际原因；所属应用事务必须回滚后才能发送对应ok=false的operation.result。SDK可依据认证WS收到并持久保存的准确原回执核实该次拒绝，同时核账号、操作类型、原ID、冻结payload、实际付款及其他同付款键尝试。HTTP原操作查询仍只返回已有成功结果；仅404、错误文本或缺少凭证不能证明没有未决付款，unknown不产生新提交权限。

文件引用固定为 fileId、name、digest、size，不接受远端 URL 或服务端磁盘路径。上传仅授予原上传身份读取权限；通过合法 A2C 封套提交文件引用时，平台在接受原消息的同一事务授予原接收身份读取权。不能把他人传入引用再授权给第三方；跨任务材料须由参与方明确准备。文件名是协议元数据，不用于拼接存储路径；同操作恢复原引用，不重新生成上传身份。

每账号文件引用与在途上传合计上限512MiB。先原子预留元数据和配额，再写入字节并标为就绪；中断保留原操作，未就绪引用不可读取或投递，恢复不能另占配额。原文件和合同证据按业务生命周期保留。

`a2c.request` 的 body 为 op、原 body、files 引用映射和 admissionId，可选原 taskId；`a2c.result` 为原 reply、files 引用映射及原任务状态，保留 inReplyTo。适配封套不改签名字段或原协议 task ID。非只读执行必须有当前开始许可；接收端先持久记录执行检查点，完成后推送原结果。模型退出、超时或未知执行不能自动重做签署、开工、交付或通知。

每个原方法调用单独使用 messageId；后续期次、环节及验收通知可以在同一交互再次调用相同方法。它们须关联各自已保存的业务操作和原 taskId，不能用新标识替换未知调用。方法/任务映射和读取边界统一见 [A2C 适配](../A2C适配.md)。

reply 保留原 A2C SDK 的 body、taskId 与 state；无任务的原响应可省略 state 或保留 null，投递台账将其视为本次调用完成。任务状态保留 working、auth-required、completed、failed、rejected、canceled，不将 auth-required 改名为界面用语。同一原请求的进展保持 taskId，终态结果不可替换；重传返回原回执。

reply 可附原 task 快照（id、op、state、artifacts、status），其身份与状态须和当前原响应一致，op 保留创建该任务的原方法。后续请求若复用原任务，不得用本次请求方法覆盖 task.op。外层 files 仅保存原 Reply.files，另以 taskFiles 保存原 Task.files；两者不能合并，同名文件也可能是不同原件。taskFiles 有值时必须附任务快照；两份映射均在接受结果的同一事务中校验并授予原请求方读取权。旧封套未携带 taskFiles 时按空映射处理，不推断为 Reply.files。

宿主调用或外部效果未知时，a2c.result 外层可附 executionError（code=unknown_result、recovery），同时保留原非终态 Reply/Task。它只报告 SDK 执行状况，不写成 A2C failed、不撤销合同或释放容量；发送端适配器结束本地等待并返回 unknown。之后取得真实原结果仍可沿原任务推进，未知报告不能覆盖已确认终态。

card.countersign 允许在原 held 预留仍有效时投递签1卡、取得审查开始许可；服务方审查通过后，以收到的原卡提交 admission，再让原 SDK 签2。带签2的结果必须已有 committed 并通过原卡与签名校验。request.submit 仍要求先提交容量；ap2.checkout 只取得原拟卡费支付数据，不等于已付款或已承诺接单。

委托交互的 opened body 为 interactionType=delegation、bindingDigest、deadline；登记回执和恢复查询均返回同一绑定。admission.configure 使用 expectedRevision、maxActiveDelegations、accepting；reserve 使用 interactionId、originMessageId、bindingDigest；commit 使用 admissionId 和绑定的原签署证据；status 使用 admissionId 或所属服务。`ap2.pay` 控制 payload 为 `{admissionId,ap2}`，ap2 保持原协议 body；平台操作结果及原 AP2 付款凭据分别可查询。

授权 context/grant/proof 的字段与时间规则以[支付中心](../../组件/平台/支付中心/接口.md)为准。HTTP 登记 body 为 `{operationId,context,grant,proof}`；查询/关闭 body或查询串显式选择 actor。scope.select 的 proof 对 `{scopeDigest,cardDigest}` 使用用户密钥签署，slot=`ioa-contract-selection`，签署新鲜度最长15分钟且须在当前 grant 内。API 返回 scopeDigest、acceptedRevision、授权截止、已付费用、已选合同及额度摘要，不返回私钥。原成功操作重传先恢复原结果，新动作才检查当前授权；平台操作记录和领域预算在同一短事务。

稳定 `/a2a/agents/{agentId}` 地址的协议投递也必须携带有效 IoA 交互与接单上下文；缺少时明确拒绝。兼容协议地址不能形成绕过统一接入的第二条接单路径。

提案签认 payload 为 `{admissionId,op:"card.endorse",body:{card},request}`。request 必须与消息中心已接受并取得开始许可的原签名请求完全一致；card 尚只有服务方签2，复用 A2C 核验请求不变量及响应期限。市场核包和准备在事务外，提交前重新核当前代次、绑定和期限；原签认、协议快照、业务卡绑定及操作回执在同一短事务保存。相同候选恢复原签3，不能重新签认延长时间；同一接单记录不能关联另一份仍有效承诺。

认证入口明确区分401/authenticate凭据拒绝、429/rate_limited预算满额和400/invalid_input字段错误，不能将限流投影成密码错误。限流及未知响应保留原operationId，客户端不自动新建登录；认证及限流规则见[身份中心](../../组件/平台/身份中心/接口.md#认证失败与流量限制)。
