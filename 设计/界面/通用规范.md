# 界面通用规范

## 目的与范围

定义三类工作台的共同布局、可见性、证据表达与动画。业务名称以[术语](../术语.md)为准；界面消费事实，不定义合同、支付或消息状态。

## 视图与权限

| 视图 | 数据范围 |
|---|---|
| 管理员工作台 | 获管理权限的全景元数据、组件状态与历史；消息正文需独立审计授权 |
| 个人助手工作台 | 本账号助手、所属合同、获准双方交互及公开服务目录 |
| 服务方工作台 | 本账号服务、对应委托与支付凭证 |

登录后按权限切换视图。服务端先裁剪数据；不得把其他用户的消息、合同或全局私有事件发送给普通浏览器后仅用样式隐藏。账号管理权限不改变收信接口的业务授权。

## 网络布局与组件标注

| 区域 | 规则 |
|---|---|
| 左侧 | 个人助手；区分登记、在线、忙碌、断联 |
| 中间 | 平台组件等宽对齐，整列高度与相邻参与方列一致；委托中心内能力紧凑展示 |
| 右侧 | 按领域排列专业服务，缩减宽度以突出平台 |
| 详情 | 点击账号高亮名下助手和服务；点击组件展示职责及相关记录；再次点击或 Esc 恢复 |

| 节点 | 展示标注 |
|---|---|
| 身份中心 | 智能体身份码 |
| 注册中心 | A2X 服务发现 |
| 委托中心 | 智能体委托合同协议（A2C） |
| 支付中心 | 智能体支付授权协议（AP2） |
| 消息中心 | 个人助手交互协议 |
| 悬赏中心（灰色建设中） | 不指定对象的委托 |
| 意图中心（灰色建设中） | 用户权限白名单管理 |

布局须为标题及状态保留最小内容高度；较矮窗口允许页面滚动，不压缩组件到文字重叠。

这些是展示标签，协议边界以[架构](../架构.md)及对应组件为准。建设中组件没有活动或可调用入口；事件观察、进程与事件总线放运维详情，不画作业务节点。

## 事件与证据

| 来源 | 展示依据 |
|---|---|
| 平台公共服务 | 核验后的签认、存证、过账、结清与裁定事实 |
| 所属参与方合同副本 | 验签后标 verified；旧副本不得覆盖更完整签名链 |
| SDK 过程上报 | 检索、比较、生产、等待确认等标 reported，不能充当付款或裁定依据 |
| 连接与投递记录 | 使用实际连接、入队和送达回执；业务结果另行表达 |

实时协议事件在原事务内固定本次已接受事实，提交成功后发布；不得事后读取更新卡并附到更早的请求事件。入队只表示待投递，不能推断复签、开工或交付完成。事件按稳定 ID 去重，合同摘要与交互 ID 分别关联其业务。重传和历史恢复只补状态，不制造新活动；乱序不能使已结束合同重新开工。观察断开显示“观察中断／状态未知”，不推断合同失败。

完整协议报文可按权限展开；内部模型仅展示获准输入与输出，不上传密钥、凭据或隐藏推理。金额区分合同价、已付款及服务收入，币种明确标为虚拟币。

## 授权观察视图

| 展示对象 | 唯一依据与边界 |
|---|---|
| 委托意向 | 原意向消息及接单记录；离线暂存、预留、拟约及未知结果分别显示。尚无卡时不填合同摘要或零报价，已付拟卡费仍按真实凭证显示；已有卡后不重复列作未成约意向 |
| 合同快照 | 本次委托接单关系内已接受的原A2C卡，核模板、双方身份、原请求及签名；仅保存原件，不由模型文字或事件标签拼卡。更新必须扩展原签名链，旧副本不能回退、等长异链不能覆盖 |
| 快照写入 | 原协议请求/结果、市场签认/存证/结清及实际付款提交时，由观察模块保存已核验副本。重复原件不产生第二次活动；展示失败不构造新的协议动作 |
| 形成与结束 | 成约以原A2C验证结果为准，不把仅签1或预留容量当成成约；结清/裁定读取真实市场记录，不能以消息送达、全部已签或金额相等推断整单结束 |
| 阶段与金额 | 签名、开工回执、环节请求、协议未知及付款分别显示；拟卡费、委托价款及实际已付分开。收入只计绑定本次接单及正确付款/收款方的真实AP2凭证，不计同摘要的手工转账；累计金额和完成数独立于列表分页及展示副本计算 |
| 助手消息 | 从统一可靠投递记录读取本账号参与的message.request及原结果；保留messageId、interactionId、接口修订、投递和处理状态。送达、处理完成和用户已读分开，后者没有凭据时保持未知 |
| 公开服务 | 使用当前已公示的真实名称、分类和有效模板；登记、公示、索引、连接与接单状态分别展示，不把历史online标记当作当前执行租约 |
| 记录保留 | 合同展示副本独立于短期投递正文保存，含原签名及来源关联；启动可从仍保存的原协议事实重建。历史证据缺失明确标明，不按最终状态反推缺失签名；消息正文按原TTL及保留规则失效，不从本地参与方文件补读 |

工作台只读查询和网络观察不调用旧轮询收件接口，不混合两套消息记录补齐界面。原实现尚未整组替换的差距记开发计划；新网页不建立旧格式回退。浏览器断线补历史只恢复状态，不能重放为当前活动。

管理事件仅输出允许的标识、参与方、时间、动作、结果、期次、金额和核验标记；不传递原detail任意字段、正文、完整合同、业务材料或凭据。管理员概览、实时WS、历史及回放采用同一裁剪规则；属于本账号的具体合同与消息内容仍按所属检查返回。

## 动画与异常

| 触发 | 表现 |
|---|---|
| 实际传输 | 快速、短时连接；结束后移除路径、光点及文字，无残影 |
| 离线入队 | 先画发件方到消息中心；真实送达后才画接收半程 |
| 履约等待 | 保留状态与详情，不用常亮连线表达等待 |
| 并发 | 按实际时间允许多个发起方和多种交互同时发生 |
| 选择高亮 | 用户选择保持到取消，与短时事件动画分开管理 |
| 历史补齐 | 恢复数据，不重放发送动画 |

管理员网络只使用实际事件。个人助手工作台可使用不含他人私有数据的匿名环境示意，具体范围见[个人助手工作台](个人助手工作台.md)。讲解动画与真实监控的制作边界见[演示制作](../示例/演示制作.md)。
