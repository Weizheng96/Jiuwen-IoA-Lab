# 美甲预约场景约束

## 目的与范围

本例用于验证[委托交易](../流程/委托交易.md)通用流程。服务名称、默认规格、比选结果预期和录屏台词只属于本场景，不进入主接入技能或 SDK 核心。固定候选、模板与判据差异、账号策略及预约演示工具归 `demo/delegation/src/`；通过通用服务运行入口加载，不在官方运行器内硬编码场景名。默认官方服务仍使用的业务资产留在 `src/official/services/`。视频规则见[演示制作](演示制作.md)。

|---|---|
| 用户 | 小美美甲店店主 |
| 平台演示账号 | `xiaomei@outlook.com` |
| 演示密码 | `123456`；仅用于用户明确允许公开的隔离演示账号 |

| 技能入口 | 注册平台账号 → 保存本地接入技能配置 → 启动本地接入组件 → 在九问原生菜单选择 IoA Lab 个人助手技能 → 输入业务需求 |

账号仅用于 IoA 平台；不注册或认证同名外部邮箱。注册必须真实发生在录制画面中，不预建账号后重演注册成功。配置镜头只显示已允许公开的演示凭据，不显示模型、通知邮箱或私钥配置。

用户只提供业务需求；不得在需求中夹入 SDK 命令、固定推荐、文件路径或技术救援提示。原生菜单选中不等于完整技能已加载，须保留实际读取主接入技能 与委托流程页的工具证据。

## 候选与比选

场景通过公开注册中心提供七家服务，使用 A2X 搜索“美甲预约 微信小程序”，查询数量上限为 8。独立场景可替换软件领域的演示候选，不改变平台默认领域种子；不使用核心专用后门。

| 候选 | 场景定义 | 比较依据 |
|---|---|---|
| 微页通 | 不包含顾客自助取消 | 与需求不符 |
| 极速APP工坊 | 只交付 APP | 与微信小程序目标不符 |
| 云构工作室 | 要求用户提供架构图 | 依真实材料要求判断；本演示不提供架构图，不能伪造材料 |
| 尊享定制 | 报价 1280 虚拟币 | 超出授权预算 |
| 灵犀小程序 | 提案报价 239；skill 验收、单仲裁模型 | 阅读实际判据、检查方式及未覆盖项 |
| 快搭建站 | 提案报价 259；5 项基础行为判据 | 与实际验收报告逐项对应 |
| 码上飞 | 提案报价 299；10 项行为判据 | 覆盖竞争请求容量、重复提交、请求重试与时段隔离等 |

表内数字是场景定义，画面与付款以当次验签模板和正式提案卡为准。信誉只读取实际记录；没有历史就显示暂无记录，不移植参考视频中的订单数或失败率。

先判断候选资格，再向合格服务征集正式合同，最后比较交付、价款、判据、期限和未覆盖项。预期由真实模板筛出三家，不加载“最低三份”账号策略来替代通用多选流程。

场景预期依据可核验覆盖推荐码上飞，其比快搭贵 40 虚拟币；推荐须来自实际合同比较，不能写死在 接入技能、SDK 或录制救援指令中。若实际事实不支持该结论，应保留结果并定位服务定义或流程问题，不伪造推荐。

本例每份拟卡费 1，三份合计 3；选择码上飞时合同 299、总支出 302，均计入 500 上限。拟卡费不是交付报价；费用不明先核实，超出授权须重新征求用户同意。

`account-policy.json` 仅供独立比选策略试验；正式通用流程录制不加载。单家／多家由真实候选和授权费用决定，不向用户提出基础版／高级版选择题。

## 规格与材料

| 字段 | 场景值或约束 |
|---|---|
| `shop` | 用户提供的店名 |
| `capacity` | 每时段最多 2 人 |
| `open`、`close` | 无其他设置时，可提议 10、20 作为待确认默认值 |
| `service1Name`、`service1Minutes` | 可提议纯色美甲、60 分钟 |
| `service2Name`、`service2Minutes` | 可提议延长甲、90 分钟 |
| 项目时长 | 15—240 的整数 |

实际字段取自模板的 `specSchema`。本例使用两个预约项目的四个标量字段，满足 A2C 值域子集；不能把嵌套 JSON 藏入字符串后延迟校验。

默认值不是用户记忆。委托授权可允许不影响核心需求的合理默认值，助手仍须在合同确认时逐项列明。必需材料缺失应请求补充，不得自行编造或静默放宽需求。

交付配置按合同顺序将四个项目字段组装为 `services` 数组，验收器逐项核对；生产时不得擅自翻译或更改合同字段。

## 用户参与节点

| 节点 | 必须呈现的实际行为 |
|---|---|
| 发起 | 用户在九问输入业务需求 |
| 委托授权 | 九问说明目的、总预算、拟卡费上限及有效期，等待本阶段明确答复 |
| 合同确认 | 展示真实提案比较与推荐，用户确认具体规格、判据、价款及期限 |
| 实名注册授权 | 服务开工后发出模板声明的 `authorizableSteps` 请求，再独立征求用户授权 |
| 验收确认 | 展示真实本地报告与本期金额，用户确认后签验收结论并读卡付款 |

确认合同、补充材料或接受默认值均不能代替后续实名注册授权。实名注册仅演练合同环节授权，不提交身份证件、不申请微信账号、不声称微信审核、发布或公网部署完成。

业务澄清可以额外发生；剧本须记录实际问题及自然业务答复。不能把真实澄清剪成无条件自动完成，也不能用技术提示推动模型跳过通用流程。

## 生产与验收

服务通过自己的九问 Swarm 和受限任务工具生产，输入来自本单合同；不使用样例成果替换真实输出。生成的 Python 只在 A2C WASM 沙箱运行，不在宿主导入或执行。

行为测试覆盖预约、满额拒绝、取消、竞争请求和重复请求等；不能以配置中的 `true` 代替实际测试。文字判据与验收器检查由同一份场景定义生成，名称和报告逐项核对。

竞争与重试检查属于顺序调用的行为模拟，不声称等同真实多线程压力或网络故障注入。验收覆盖更多也不能泛化为对任意软件的完整质量保证。

收到实际存证期号后取件，在本地执行验收；未到可验时间则等待，失败或错误不得签验收通过和付款。展示报告后才询问用户验收确认。

完成合同后，切换对应服务方账号，核对同一合同摘要、完成记录及实际收入；再演示交付配置启动的本地预约工具。宿主使用仓内固定运行器，不执行交付的 Python 源码。

## 录制与恢复

每轮正式录制使用独立参与方数据目录，开始前检查无旧合同。未采纳提案可能仍占容量，不得删除旧合同、重置任务或反复支付拟卡费来重拍。

画面中断时可接续同一账号、技能和九问会话；核对原视频、已取得提案及合同摘要，保留新的录制时间原点，不重放已成功的注册、授权或付费操作。

接续前按真实签名时刻与模板 `respondWithin` 检查响应窗口并预留录制余量。过期则停止，不能修改签名时间、延长期限、改写目的重建授权或把旧确认当成新授权。

未知写入或付款结果先核实；失败录像与事实回执保留。比较后通过合同详情选中本轮中选合同，流程、金额、组件讲解和最终收入始终对应同一摘要。
