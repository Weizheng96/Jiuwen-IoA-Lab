# 演示制作约束

## 目的与范围

本文规定四个 Demo 的剧本、画面、声音及证据边界。业务规范分别见[委托交易](../流程/委托交易.md)、[助手通信](../流程/助手通信.md)；界面规则见[管理员控制台](../界面/通用规范.md)。具体镜头和台词只在各场景源中维护。

## 场景与制作资源

四个场景分别在 `demo/global/`、`demo/delegation-provider/`、`demo/delegation-assistant/`、`demo/messaging/`，共用 `demo/tools/` 的配音、录制、剪辑、发布与证据检查。目录整体分工见[架构](../架构.md)；每个场景按下表维护自身内容。

| 内容 | 场景内位置 | 规则 |
|---|---|---|
| 复现说明 | `README.md` | 列实际入口、依赖、运行顺序与发布范围 |
| 剧情与执行源 | `src/` | 旁白/镜头源、演示客户端、场景账号及业务配置；不复制通用 SDK 或官方运行器 |
| 可读剧本 | `剧本.md` | 由场景源、实测时间轴与脱敏证据生成，不手改 |
| 正式素材 | `assets/` | 正式配音与观看/重制所需的公开素材，受版本管理 |
| 成片 | `video/` | 正式视频及播放器，受版本管理 |
| 证据 | `evidence/` | 脱敏业务回执、画面/音轨检查、源/工具/素材摘要及成片关联 |
| 设计依据 | `VERSION` | 各场景分别记录实际体现的规范；未重制的成片不随设计升级 |

固定美甲候选、价格和剧情配置归委托场景；默认官方服务真正使用的模板与验收器仍归官方资源。会议场景配置复用本地日程/通知工具，不在 Demo 重写业务状态机。正式背景流量工具归 `experiments/`，通过公开 SDK 调用；一次性试验归不入库的 `temp/`。

平台网络渲染器由真实界面与 Demo 共用，剧情控制器只在 Demo；平台不得反向依赖 Demo。公共制作工具不放场景账号、台词或推荐结果；来自 A2C 主仓的工具及必要素材随仓保留来源，复现不得隐含依赖相邻仓库或临时文件。

## 制作顺序与剧本

| 顺序 | 产物与检查 |
|---|---|
| 1 | 先更新场景剧本源，确定角色、业务前提、镜头、字幕和完整旁白 |
| 2 | 验证场景所需的真实平台、九问、模型及通知依赖；测试替身明确标识 |
| 3 | 真实执行并连续录制，保存业务回执、工具调用与实测时间点 |
| 4 | 按实际配音时长裁切，叠加短字幕和组件讲解；等待压缩须明确标记 |
| 5 | 逐镜核对证据、同步与最终编码，再生成发布材料 |

每个 Demo 的 `剧本.md` 包括角色、操作、字幕、完整旁白、实测时间和证据边界。根 `demo/README.md` 只维护四个场景的入口和共用制作命令，不复制完整剧本。

已完成业务链路但未通过画面、声音和编码检查的材料不能作为正式成片。缺失真实依赖或必需证据时阻断对应范围的发布，不以测试替身、旧录像或旧邮件确认代替本轮证据。

## 统一视觉与声音

| 项 | 要求 |
|---|---|
| 名称 | 九问IoA实验平台（Jiuwen IoA Lab） |
| 一句话介绍 | 面向智能体互联网的仿真验证与开放体验平台。 |
| 开场 | 完整封面，先介绍平台再进入网络 |
| 字幕 | 高对比底条、大字、短句；优先一行，每镜头一件事；1080p 不小于 44px，保留安全区 |
| 旁白 | 约正常语速的 1.12 倍，按实测音频核对字速，不以参数值代替听感检查 |
| 发音 | A2C 读作“A to C”；英文术语单独检查 |
| 同步 | 旁白、字幕、点击组件和实际进展共用时间轴；先发生业务，再展示结果 |
| 辅助动画 | 可叠加组件描边、箭头和流动光点；注明讲解性质，不改业务数据或统计 |
| 证据 | 模型文字不代表签约、交付或付款；验收画在个人助手本地 |

四片使用同一套网络组件目录、命名及动效。讲解与真实监控共用布局基础；支付中心使用 AP2，注册中心与委托中心分别呈现。

## 全局视角的主线

叙述参考 A2C 主仓 `demo/智能体互联网` 的剧本，突出平台定位、参与方式和价值。详细的合同字段、比选、授权与验收操作放在两个委托片；全局片不逐项讲解 ANN、签名编号、拟卡费或仲裁步骤。

| 段落 | 旁白主题 | 同步画面 |
|---|---|---|
| 0 | 九问 IoA 实验平台及一句话定位 | 完整封面 |
| 1 | 接入自己的个人助手或专业服务 | 用户与助手对应、服务随机错峰上线；简述虚拟体验额度 |
| 2 | 委托交易：发现服务、约定成果、交付验收和支付 | 依旁白突出注册、委托、支付中心；用一次完整链路说明各自用途 |
| 3 | 助手间交流：按接口发送、离线保存、上线处理 | 突出消息中心，预约、报平安、维修和聚餐等错峰短连接 |
| 4 | 验证协议、发现需求与开放体验 | 渐变进入唯一全屏真实监控，委托和助手通信同时活跃 |

0—3 每段只展示当前旁白相关活动。采用可复现的有限随机计划：多参与方、错峰、部分并发、快速单次传输；不用固定逐个点亮、周期循环或长期高亮填满镜头。片尾转入持续的真实多方网络。

悬赏中心、意图中心只作灰色建设中节点，不加入旁白和业务活动。事件观察不作网络节点；行为日志仅在真实管理员画面显示。机制介绍不伪造实际未发生的裁定或付款。

## 讲解到真实监控的过渡

讲解图保留用户角色，左侧按编号与个人助手配对。真实监控不包含用户节点；过渡时用户先虚化淡出，助手、组件和服务平滑移至真实首帧位置，再交叉淡化。

过渡统一为 2.8 秒，预加载并固定真实首帧；过渡结束才从该帧继续播放，避免后台先推进产生跳变。日志随实录渐显；检查多个过渡时点和几何对齐，不只比较首尾两帧。

片尾只保留一个全屏真实监控，不并排概念图与真实图。播放页可循环合格的真实录屏；回放不作为平台的新业务事件。

## 真实全景活动密度

实验客户端在平台核心之外运行，经同一 SDK 产生 `experiment` 活动；不发送真实通知邮件。使用多个账号和多个领域服务，支持多个发起方同时活动，避免少量节点长时间常亮。

委托与消息独立持续调度；委托等待、模型发现或生产不得阻塞消息。首次请求和后续请求均随机错峰，不先演完委托再演消息；接单仍遵守容量，不删除合同以制造可用名额。

按可见传输活动调整两类交互到接近比例；委托包含发现、定约、交付、验收、付款多次往返，不能直接拿订单数与消息数比较。保存订单数、消息数、可见传输数、不同发起方数及瞬时连接数。

录制前等待两类真实传输出现，剪去初始化空场。每个完整十秒窗口须同时出现委托与个人助手间消息传输，保存窗口计数、重叠与总体比例；不达标的素材不发布。播放页循环源与影片实录段使用同一份合格素材。

## 两个委托交易视角

两片业务均遵守[美甲预约](美甲预约.md)，分别保存实际场景、合同与执行证据；不因共享剧本而假定两片属于同一笔交易。

| 视频 | 左侧真实九问 | 右侧平台与必要操作 |
|---|---|---|
| 服务方视角 | 注册服务方账号；配置专业业务技能/工具；导入 IoA Lab 服务方技能；让九问配置 SDK 并发布“码上飞”；接单、生产、交付和结清 | 同账号服务方工作台；展示编程分类、模板签认、接单状态、实际收入、结清与信誉记录 |
| 个人助手视角 | 注册小美账号；导入和配置 IoA Lab 个人助手技能；启动常驻接入并在原生菜单选择技能；一句需求发起真实流程 | 本人工作台；展示发现、真实比选、合同、进展、本地验收、付款和完成历史 |

个人助手片保留真实的委托授权、合同确认、实名注册环节授权和验收确认，出现必要业务澄清时如实记录。服务方片不代小美回答授权或验收；其业务生产须来自本轮合同，不能用固定样件替换。

逐阶段点击相关平台组件，网络始终可见。收入、信誉与状态以真实证据为准；完成后可展示交付工具。录制及剪辑不修改业务数据，未知付款、过期合同或已占用容量按真实状态处理，不为剧情重发收费请求。

## 个人助手交互片

以王经理的个人助手、赵专员的个人助手命名，使用[会议预约](会议预约.md)的本地规则、账号范围和结构化接口。本片假定两人已注册并接入，不重复注册或技能安装。

固定四宫格：左上王经理平台个人助手界面、左下王经理真实九问、右上赵专员平台个人助手界面、右下赵专员真实九问。保持相关网络与会话可见，裁剪关键区域并放大文字，不能把完整网页缩小到无法阅读。

王经理用自然语言让九问起草预约接口，检查并确认发布；赵专员读取接口后第一次预约冲突，依推荐时间在原交互中再次请求，成功预留并提交邀请。界面、消息标识和回执须证明两次请求属于同一交互；不直接预置已发布接口替代起草过程。

旁白表达：王经理定义预约接口，允许指定范围按格式预约；时间合适则发邀请交王经理接受，冲突则返回建议；赵专员的助手读取接口、构造结构化消息，并依据回复再次预约。不预设所有交流都是协作，不讲解本地日历实现细节。

留言必须实际进入九问用户界面；邀请提交和接受入历分开表达。两种成片范围须显式选择：

| 范围 | 录制与证据要求 |
|---|---|
| 平台链路实录＋旁白收尾 | 实录权限、接口、留言、冲突、改约及邀请提交；以条件式旁白和标明性质的流程图说明本人接受后入历，原回执保留待接受 |
| 完整邮箱实录 | 在上述链路之外，录制本轮真实 Outlook 接受及日历可见画面；缺镜头或证据不得宣称完成 |

不制作伪造邮箱页面，不以通知服务受理代替收件证据；不在旁白加入邮箱字符串归属认证的解释。没有显式声明旁白范围时，缺少邮箱实录证据不得按完整实录发布。

## 发布检查

剪辑、剧本生成、成片检查与发布共用同一证据判定；核对生成一致性、公开素材摘要、音轨、字幕安全区、术语读音及关键业务时间点。

原始录像、私有运行数据与公开脱敏证据分开保存。画面故障、失败轮次和中断记录不得改写为成功；发布说明准确标明演示范围，实测证据归各场景的 `evidence/`。共用工具由 Git 及证据中的摘要追踪，不以工具更新自动改变影片 VERSION。

目录迁移须同步播放器、复现命令、证据路径与素材关联；只调整路径时保留原实测时间、摘要和结论，不宣称重新执行或录制。源、配音、剧本与视频不一致时先标明实际产物状态，不覆盖旧证据造成“已复验”的假象。
