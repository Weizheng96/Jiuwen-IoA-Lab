# 演示制作约束

## 目的与范围

本文规定三个 Demo 的剧本、画面、声音及证据边界。业务规范分别见[委托交易](../流程/委托交易.md)、[助手通信](../流程/助手通信.md)；界面规则见[管理员控制台](../界面/通用规范.md)。具体镜头和台词只在各场景源中维护。

## 制作顺序与剧本

| 顺序 | 产物与检查 |
|---|---|
| 1 | 先更新场景剧本源，确定角色、业务前提、镜头、字幕和完整旁白 |
| 2 | 验证场景所需的真实平台、九问、模型及通知依赖；测试替身明确标识 |
| 3 | 真实执行并连续录制，保存业务回执、工具调用与实测时间点 |
| 4 | 按实际配音时长裁切，叠加短字幕和组件讲解；等待压缩须明确标记 |
| 5 | 逐镜核对证据、同步与最终编码，再生成发布材料 |

每个 Demo 的场景目录提供 `剧本.md`，包括角色、操作、字幕、完整旁白、实测时间和证据边界。由场景源、配音时间轴及脱敏证据生成，不手改生成文件；根 `demo/README.md` 只维护入口和复现命令。

已完成业务链路但未通过画面、声音和编码检查的材料不能作为正式成片。缺失真实依赖或必需证据时阻断对应范围的发布，不以测试替身、旧录像或旧邮件确认代替本轮证据。

## 统一视觉与声音

| 项 | 要求 |
|---|---|
| 名称 | 九问IoA实验平台（Jiuwen IoA Lab） |
| 一句话介绍 | 面向智能体互联网的仿真验证与开放体验平台。 |
| 开场 | 完整封面，先介绍平台再进入网络 |
| 字幕 | 高对比底条、大字、短句；优先一行，每镜头一件事；1080p 不小于 44px，保留安全区 |
| 旁白 | 约正常语速的 1.12 倍，按实测音频核对字速，不以参数值代替听感检查 |
| 发音 | A2C 读作“A to C”；英文术语单独检查 |
| 同步 | 旁白、字幕、点击组件和实际进展共用时间轴；先发生业务，再展示结果 |
| 辅助动画 | 可叠加组件描边、箭头和流动光点；注明讲解性质，不改业务数据或统计 |
| 证据 | 模型文字不代表签约、交付或付款；验收画在个人助手本地 |

三片使用同一套网络组件目录、命名及动效。讲解与真实监控共用布局基础；支付中心使用 AP2，注册中心与委托中心分别呈现。

## 全局视角的固定主线

叙述参考 A2C 主仓 `demo/智能体互联网` 的剧本；角色、能力和结果服从本平台设计，不借用其历史战绩或实际未发生的裁定。

| 段落 | 旁白主题 | 同步画面 |
|---|---|---|
| 0 | 构建九问 IoA 实验平台 | 封面及一句话定位 |
| 1 | 用户接入自己的九问个人助手 | 多组用户／助手成对排列，助手错峰或部分同步由灰转彩 |
| 2 | 每次成功登录赠送 100 虚拟币 | 支付中心高亮，向个人助手发放的短连接 |
| 3 | 专业 Agent 注册服务、公开接取委托 | 注册中心与多个服务登记，服务由灰转彩 |
| 4 | 用户需求、预算和授权 | 翻译、文案、起名、简历、正则、旅行等需求；对应用户和助手交互 |
| 5 | 发现潜在服务 | 多个助手访问注册中心；点击展示 A2X 分类树与 ANN 两种方案 |
| 6 | 比较、协商、定约、交付、本地验收及争议 | 对应委托中心内部组件和参与方，按当前讲解步骤聚焦 |
| 7 | 验收后读卡付款、记录信誉 | 支付和信誉相关活动，结束即撤除连接 |
| 8 | 个人助手间助手通信 | 消息中心传递预约、报平安、维修、聚餐等不同消息 |
| 9 | 探索开放网络中的智能体经济 | 渐变进入唯一全屏真实管理员监控，多类型活动同时发生 |
| 10 | 对内验证协议、发现需求；对外体验、数据和影响力 | 继续活跃真实网络，助手可随实际连接上线或离线 |

0—8 每段只展示当前旁白涉及的交互，不播放无关背景路径。采用可复现的有限随机计划：多参与方、错峰、部分并发、快速单次传输；不用固定逐个点亮、周期循环或长期高亮填满镜头。

5 同时介绍两种发现方式，真实执行只使用 A2X 时须有相应事件依据；ANN 标明方案介绍。支付授权或仲裁若只说明机制，以简短画面标识区分，不伪造授权报文或裁定；旁白不追加“本轮没有发生裁定”等说明。

悬赏中心、意图中心只作灰色建设中节点，不加入旁白和业务活动。事件观察不作网络节点；行为日志仅在真实管理员画面显示。

## 讲解到真实监控的过渡

讲解图保留用户角色，左侧按编号与个人助手配对。真实监控不包含用户节点；过渡时用户先虚化淡出，助手、组件和服务平滑移至真实首帧位置，再交叉淡化。

过渡统一为 2.8 秒，预加载并固定真实首帧；过渡结束才从该帧继续播放，避免后台先推进产生跳变。日志随实录渐显；检查多个过渡时点和几何对齐，不只比较首尾两帧。

片尾只保留一个全屏真实监控，不并排概念图与真实图。播放页可循环合格的真实录屏；回放不作为平台的新业务事件。

## 真实全景活动密度

实验客户端在平台核心之外运行，经同一 SDK 产生 `experiment` 活动；不发送真实通知邮件。使用多个账号和多个领域服务，支持多个发起方同时活动，避免少量节点长时间常亮。

委托与消息独立持续调度；委托等待、模型发现或生产不得阻塞消息。首次请求和后续请求均随机错峰，不先演完委托再演消息；接单仍遵守容量，不删除合同以制造可用名额。

按可见传输活动调整两类交互到接近比例；委托包含发现、定约、交付、验收、付款多次往返，不能直接拿订单数与消息数比较。保存订单数、消息数、可见传输数、不同发起方数及瞬时连接数。

录制前等待两类真实传输出现，剪去初始化空场。每个完整十秒窗口须同时出现委托与个人助手间消息传输，保存窗口计数、重叠与总体比例；不达标的素材不发布。播放页循环源与影片实录段使用同一份合格素材。

## 委托交易片

业务场景以[美甲预约](美甲预约.md)为准：从真实注册、修改 接入技能配置、启动接入组件、原生选择技能开始，随后以一句业务需求触发通用流程。

主要布局为左侧真实九问网页、右侧本人工作台。用户参与委托授权、具体合同确认、实名注册环节授权、验收确认；出现真实业务澄清时如实保留，不用技术提示替代。

比较真实模板与正式提案，展示验收覆盖差异及费用；逐阶段点击对应组件。完成后切换实际服务方账号，核对同一合同摘要和实际收入，再展示交付工具；这两段可切为整屏。

录制及剪辑不修改业务数据。未知付款、已过期合同或已占用容量按实际状态处理，不为了剧情重发收费请求；恢复条件见场景约束。

## 个人助手交互片

以王经理的个人助手、赵专员的个人助手命名，使用[会议预约](会议预约.md)的本地规则、账号范围和结构化接口。画面突出平台的接口发现、消息投递、冲突回复和同一交互改约。

旁白表达：王经理定义预约接口，允许指定范围按格式预约；时间合适则发邀请交王经理接受，冲突则返回建议；赵专员的助手读取接口、构造结构化消息，并依据回复再次预约。不预设所有交流都是协作，不讲解本地日历实现细节。

留言必须实际进入九问用户界面；邀请提交和接受入历分开表达。两种成片范围须显式选择：

| 范围 | 录制与证据要求 |
|---|---|
| 平台链路实录＋旁白收尾 | 实录权限、接口、留言、冲突、改约及邀请提交；以条件式旁白和标明性质的流程图说明本人接受后入历，原回执保留待接受 |
| 完整邮箱实录 | 在上述链路之外，录制本轮真实 Outlook 接受及日历可见画面；缺镜头或证据不得宣称完成 |

不制作伪造邮箱页面，不以通知服务受理代替收件证据；不在旁白加入邮箱字符串归属认证的解释。没有显式声明旁白范围时，缺少邮箱实录证据不得按完整实录发布。

## 发布检查

剪辑、剧本生成、成片检查与发布共用同一证据判定；核对生成一致性、公开素材摘要、音轨、字幕安全区、术语读音及关键业务时间点。

原始录像、私有运行数据与公开脱敏证据分开保存。画面故障、失败轮次和中断记录不得改写为成功；发布说明准确标明演示范围，实际验收记录保存在 `demo/verification/`。
