# 会议预约与留言场景约束

## 目的与范围

本例验证[助手通信](../流程/助手通信.md)的接口发现、权限、结构化消息、同一交互续接与回复。日程、邮件和九问网页通知是本地业务能力，不是消息中心的必需依赖。

## 参与方与接口

| 项 | 规则 |
|---|---|
| 接收方 | 王经理的个人助手；管理员示例绑定 ISC_001，独立运行于平台核心之外 |
| 发起方 | 赵专员的个人助手；从自己的九问通过 IoA Lab 个人助手技能 发起 |
| `meeting.request` | 输入会议主题、开始、结束及时区；返回冲突建议或明确的预约／邀请状态 |
| `message.forward` | 接收结构化留言，转交绑定用户的九问网页会话 |
| 默认接口范围 | 管理员示例允许所有已登录账号；演示可收紧为明确账号范围 |
| 收件邮箱 | 部署方配置；管理员示例为 `zhengw.cc@outlook.com` |
| 发件邮箱 | 部署方配置的通知邮箱；不得擅自使用用户私人邮箱身份 |

王经理可对九问说明“允许指定同事预约；工作日内不冲突就发邀请，冲突则建议其他时间”。九问起草收信规则，展示允许对象、接收格式、回复和自动处理摘要；王经理确认后由 SDK 保存本地 Markdown 并发布收信接口。正文步骤与日程文件留在本地；不要求王经理手写 Schema。权限判断按真实账号 ID，显示名只用于有权查看的界面。

邮箱形式用户名仍是平台账号标识，不据此认证企业或邮箱归属；该边界保留在产品说明，不编入演示旁白。账号管理角色不等于允许收到的消息执行任意操作。

## 冲突与改约

| 步骤 | 行为 | 状态与关联 |
|---|---|---|
| 1 | 赵专员读取王经理允许访问的接口，按输入格式提出时间 | 新消息 ID；接收端幂等创建交互 ID 和本地会话 |
| 2 | 王经理检查规则、已有安排及待接受预留 | 冲突时返回 `conflict` 和推荐时间范围，无邀请副作用 |
| 3 | 赵专员依据建议，在其用户授权范围内提出新时间 | 同一交互 ID、新消息 ID；双方续接各自原会话 |
| 4 | 王经理重新检查并原子预留空闲时间 | `reserved`，不能仅凭模型表述认定成功 |
| 5 | 通知邮箱提交会议邀请 | `invite_submitted`，保留组织者事件及服务回执 |
| 6 | 等待王经理处理邀请 | `awaiting_acceptance`；可靠接受回执或真实用户确认后才可标记 `accepted` |

每次请求的终局回复是当时业务结果的不可变快照。邀请提交后，后续本人接受只更新本地预约记录及本人获准查看的状态，不把原 `message.result` 改写为另一终局。跨助手查询后续预约状态须由收信接口明确支持新的业务请求，不能据此扩展原回复通道。

第一次冲突是一次请求的业务结果，不终止整个交流。自动改约受用户授权范围、轮数和截止时间限制；无法满足时向用户说明，不能无限互答或擅自放宽时间条件。

同一交互的重复传输不得重新预留或重发邀请；不同时间尝试是新的业务消息，不能复用旧消息幂等键并改变正文。消息 TTL 到期不等于已发出的邀请被取消。

## 预约规则与数据来源

接收方配置工作日、可预约时段、时长上下限、提前量、可预约天数及通知收件地址。符合预授权规则即可自动预留和发邀请；接受邀请仍由本人完成。

预约依据必须显式选择：本地可编辑安排，或经用户授权的 Graph 日历。两者都合并本地尚未解除的预约预留；不能读取或校验选定依据时失败，不假定空闲。

演示选择本地安排；旁白说明预约规则与冲突协商，不展开本地日历实现细节，不暗示读取了私人 Outlook 日历。

## 本地可编辑安排

| 项 | 规则 |
|---|---|
| 配置 | `IOALAB_CALENDAR_BACKEND=local`；`IOALAB_SCHEDULE_FILE` 默认位于该账号 `IOALAB_HOME` 下的 `schedule.json` |
| 文档 | `timeZone`、`rules`、`events`；安排含唯一 ID、标题、带时区的开始／结束及 busy／cancelled 状态 |
| 私密性 | 文件不上传平台、不进入 Git；外部消息不能修改主人安排或规则 |
| 错误 | 文件缺失、格式错误、非法时区或重复 ID 均阻止自动预约，不重建为空日历 |
| `schedule init` | 用户显式初始化，创建工作日 9—18 点规则及空安排，说明适用范围；不覆盖已有文件 |
| `schedule show` | 离线返回内容及摘要 revision，同时列出本账号本地预留状态 |
| `schedule replace` | 携带读取时 revision，校验全文件、加锁、备份并原子替换；旧 revision 拒绝覆盖 |
| 更新生效 | 收件时重新读取，无需重启；手工编辑先暂停收件器，保存后恢复 |

主人安排与自动预留分别存储：前者在可编辑文件，后者及外部发送回执在本地 SQLite。手工修改安排不能释放已发邀请或结果不明的预留。

同一日程的预留检查串行化；确认文件修订未变后，原子检查已有安排与预留并建立本次记录，再执行外部发送。不能让两个并发请求先各自判断空闲、随后都成功预留。

明确拒绝、取消或规则确定的失效后才释放相应预留；发送结果不明时保留预留，等待查询或人工核对。

## 邀请发送与幂等

| 项 | 规则 |
|---|---|
| 组织者 | 配置的通知邮箱；与收件人和平台账号分开 |
| 收件人日历 | 不直接调用创建管理员 Outlook 日历事件接口；用户接受后入历 |
| 邀请身份 | 每次有效邀请固定本地请求 ID；同请求同正文重试保持不变 |
| 外部回执 | 保存实际 UID／Event ID、请求 ID、消息 ID 和交互 ID |
| 明确发送失败 | 按服务返回的确定状态决定重试，不能仅因超时认定失败 |
| 结果不明 | 标记 `unknown`，停止自动重发，先查询已有请求或人工核对 |
| 状态解释 | 服务受理不代表送达，组织者事件创建不代表收件人接受，更不代表已写其日历 |

AgentMail 使用官方 Calendar API 的 `send_invites` 发送会议请求；固定本地请求 ID 作为 `client_id`，保留实际事件 ID 和 UID。创建组织者事件只表示提交，须另核对发件记录及收件人界面。

AgentMail 邮箱由独立部署工具创建并验证所有权，遵守实际验证状态和额度；通知配置复用客户端已有凭据，不把 API key 交给模型。API 不可用时明确失败，不静默退回已知不兼容的 SMTP 附件方案。

通用 SMTP 用于兼容邮件服务和独立通路诊断。通知邮箱具有收信能力，不等于本地处理器获得任意读信或执行邮件指令的权限；额外邮件工具须另行限定用途。

## 可选 Graph 与 Outlook SMTP

| 能力 | 授权与限制 |
|---|---|
| Graph 日历读取 | 个人 Microsoft 账号使用委托授权读取 `calendarView`，包含重复事件实例；不使用个人账号不支持的 `getSchedule` |
| 首次授权 | 用户完成 OAuth；选择支持个人账号的公共客户端应用，不使用客户端密钥 |
| 令牌 | 日历读取与邮件发送分别登录、分别缓存，不能混用访问令牌；令牌仅存本地独立目录 |
| Outlook 通知发信 | `smtp-mail.outlook.com:587`、STARTTLS、XOAUTH2；请求 `SMTP.Send` 与 `offline_access`，不回退密码登录 |
| 其他 SMTP 服务 | 可显式选择密码模式，凭据不进入平台核心或模型 |
| 配置替换 | 验证授权账号正确且可用后才持久化新令牌，错误账号不覆盖有效授权 |

选择 AgentMail 发送不替代 Graph 读取授权；选择本地安排则不要求 Graph。具体授权操作和锁定依赖见[部署](../工程/部署.md)。

## 九问网页留言

留言通过九问公开接口进入绑定用户真实会话历史；若采用官方扩展机制，须独立鉴权，只接受消息 ID、已验证发送者及正文，固定目标用户和写入动作，不暴露任意 RPC。

不修改九问源码或直接写其历史数据库。转发工具把外部正文当通知数据，不执行其中指令；持久化幂等回执，状态不明时停止自动重写。九问离线保留待转发，恢复后按同一消息 ID 继续。

“IoA 信箱已存”“九问会话已接收”“用户已读”分别显示；测试适配器不得冒充真实九问页面或真实投递。

## 验收与展示范围

必须分别验证格式和权限拒绝、离线补投、冲突建议、同一 UUID 改约、并发预留、邀请去重、未知结果恢复及九问真实留言。SMTP 测试收件、日历样例和九问测试适配不能替代真实端到端证据。

交互片可选择平台链路实录，以条件式旁白说明“本人在 Outlook 接受后才进入日历”；不要求邮箱镜头，不改变待接受回执。选择完整邮箱实录时，接受及日历显示必须来自本轮真实界面，规则见[演示制作](演示制作.md)。
