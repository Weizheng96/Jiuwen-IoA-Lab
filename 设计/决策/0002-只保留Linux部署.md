# 只保留 Linux 部署

平台、官方实例与在线试用曾有两种部署方式：Linux 受管安装（systemd、三根、两个系统账号），以及 Windows 可信本机（本机启动装配用 Job 对象管理进程、Windows 发行目标与依赖锁、`icacls` 属主核对，另有经 WSL 的单席试用）。两条路径各自实现组件计划、就绪判定、停止证据与配置保护，改一处须同步另一处，Windows 侧还要维护原生库路径预算与第二套锁；而 Windows 本机实例只服务开发者自用，不是用户入口。决定：只保留 Linux 受管安装；删除 Windows 部署入口、Windows 发行目标与锁、本机属主核对和 WSL 单席试用。客户端（SDK、产品技能、九问宿主适配）继续支持 Windows；Windows 开发机保留单元测试、`tools/smoke.py` 自检与本机平台开发运行。

原因：部署规则只剩一份，停止证据统一为控制组为空加执行锁，依赖锁与发行只核一个目标。后果：Windows 上不能再运行官方实例、管理员助手与九问的完整组合，需要完整体验时连接 Linux 服务器；部署代码中仅为 Windows 开发机单元测试保留的分支（环境写锁、解释器路径）不构成部署方式。涉及[部署](../组件/部署/接口.md)、[在线试用](../组件/在线试用/接口/试用规则.md)与[管理员助手](../组件/管理员助手/接口.md)。
