# 委托中心

## 发现与服务登记

委托中心 = A2X 发现 + A2C Market + 认证、信誉和仲裁。保留按领域确定性分类树：默认8个领域、50项服务；软件开发领域8项，其余领域各6项，保持每领域5—10项的扩展范围。官方服务定义是树与账号种子的内容来源。只有官方进程登记、公示成功后，服务才可接单，不能因数据库中存在一条种子记录就显示可用。

所有服务走同一流程：账号登录 → 服务端点与 JWKS 可达 → 登记并认证公钥与收款公钥 → 服务方调用 `Provider.publish` 请求市场签模板 → 刷新发现索引。登记幂等时必须核对所属账号与原公钥；不能因 URL 相同而跨账号覆盖。官方服务不使用核心内存对象或专用后门。

## 模板与验收器

| 项 | 规则 |
|---|---|
| 模板公示 | 服务方与市场签署的完整模板可在市场缓存，浏览与取模板不唤醒 Swarm；服务方 `template.get` 从自身持久化原件返回，Client 沿用标准验签路径 |
| 缓存 | 保存原摘要、签名、有效期和 provider 身份；修改即新摘要，旧合同仍指向旧模板 |
| 提案型 | 缓存提案模板；逐单拟卡与标准由服务方按协议生成，不由注册中心预先代填 |
| 包 | 平台存内容寻址的 script 验收器包；SDK 将 `ioalab://pkg/<digest>` 解析为公开取包接口并核摘要，执行只在各自的 A2C WASM 沙箱 |
| 市场 | 直接复用 Market 的模板签认、签3、签5、结清与快照；支持script与skill包，仍使用A2C既有字段；skill的disputeModels须全部来自部署方明确配置的仲裁模型注册表，否则市场拒签。正常L2验收使用客户端自己的模型，仲裁才逐个复算；均在WASM内由程序判定，不让模型直接裁决 |

## 信誉与仲裁

信誉只从市场已结清合同与裁定汇总，不用实验事件伪造战绩。实验交易通过同一套真实 SDK 与虚拟币通路，并在展示中标明来源。

申请人通过账号认证提交合同、期号、交付件与报告；平台核对申请人是合同登记的当事方，市场验证签名链与交付摘要后复算或按期限判定。拒绝不在合同中的账号。裁定独立签署、引用合同摘要，不上卡、不触发过账。正常履约验收在用户侧；市场复算只属于争议处理。

## 美甲原剧本场景

独立服务进程可选nail-booking场景，替换软件领域的演示候选，不改变默认8领域内容。七项为微页通、极速APP工坊、云构工作室、尊享定制、灵犀小程序、快搭建站、码上飞。均走公开注册与完整模板验签；前三项按实际能力/材料要求筛选，尊享定制1280超预算，后三项真实报价239/259/299。原剧本的41单失败9单等历史数据不能移植为当前信誉，暂无记录就显示暂无记录。码上飞比快搭贵40虚拟币，九问按可核验判据自行推荐，不向用户提出版本选择题。

实名注册作为authorizableSteps预先上模板；服务收到开工后发出标准环节请求，未授权不交付。演示不提交身份证件或申请微信账号。交付件包含声明式预约配置与微信小程序页面源码；本地运行器从交付配置启动，WASM脚本对预约、满额拒绝、取消、并发抢约及重复请求等行为执行测试，不把配置中一个true当作行为测试通过。
