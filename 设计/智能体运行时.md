# 智能体运行时

## 用户侧

九问 Swarm 按个人助手技能调用本地 SDK：发现 → 信誉 → 取模板验签 → 比较 → 拟卡/提案 → 用户确认 → 签字 → 开工 → 等事件 → 取件 → 本地验收 → 按授权签7并付款。计算、签名、付款凭证和验收规则直接使用 A2C Client；模型不能把聊天结论当成验收结果。

SDK `verify` 只运行验收器、不签名；`accept` 按 A2C 重跑验收，pending 不签，fail 出失败报告，pass 才签7并付款。亲签事项由九问交互确认；技能不能替用户虚构确认。预算和类别由本地连接授权约束，平台不替用户持有权限。

轻量本地 `poll`/`watch` 维护等待，不靠持续模型对话或平台轮询用户卡。客户端退出期间停止处理，重启读取本地合同状态并恢复；期限不中断。SDK 明确区分已验收未付、待验收与已结清，网络重试不能再次签同一期或重复付款。观察失败写本地 outbox，可重发，不撤销已经完成的协议动作。

## 官方服务侧

| 触发 | 处理与是否唤醒 Swarm |
|---|---|
| Agent Card / JWKS / template.get / 取交付件 | 常驻 Provider 端点直接处理，不唤醒 |
| 待批准复签 | SDK 核签、材料与期限；简单容量规则直接判断，只有业务审核才运行技能 |
| 提案拟卡 | 任务式应答后运行拟卡技能，返回定数报价与有效判据；SDK 组卡、签2、请市场签3 |
| work.start | SDK 核合同、材料与凭证，保存回执；业务回调只投递持久化任务，立即返回 |
| 生产 | 有界工作池按合同建立独立九问会话；服务技能通过 SDK 读取本单材料、请求环节授权、自测、交付 |
| 验收与付款通知 | Provider SDK 更新状态；末期凭证齐备后服务进程结清，不唤醒模型 |

持久化队列以合同摘要/期号/任务类型唯一标识；重复请求不重复生产。任务状态 queued → running → done/failed；进程启动时检查 SDK 已有签4，已交付不再次交；中断任务恢复至队列，先检查合同是否已结束、授权与期限再继续。收到解除或裁定后不追加交付。冷启动、排队计入既有合同期限，不重置时钟。

九问适配器只依赖其公开入口，锁定经过验证的版本。生产模式缺少九问或配置时明确失败，不能静默改用样件、直接调用聊天模型或伪称已由 Swarm 完成。桩模式显式选择，用样件和固定报价验证协议，不代表真实 Swarm 已验收。

## 实验客户端

`experiments/` 是独立进程，经同一本地 SDK 和公开接口使用 ISC 账号。可按服务/领域/数量生成背景委托，明确标记 `source=experiment`。核心只展示结果，不投放需求、不执行助手、不自动补币。运行记录包含实验 id、版本、服务、成约方式、耗时、结局；真实模型调用由服务进程记录。比较只使用相同场景与可追溯输入。
