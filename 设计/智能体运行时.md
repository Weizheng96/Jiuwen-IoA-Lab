# 智能体运行时

## 用户侧

九问 Swarm 按个人助手技能调用本地 SDK：发现 → 信誉 → 取模板验签 → 比较 → 拟卡/提案 → 用户确认 → 签字 → 开工 → 等事件 → 取件 → 本地验收 → 按授权签7并付款。计算、签名、付款凭证和验收规则直接使用 A2C Client；模型不能把聊天结论当成验收结果。

SDK `verify` 只运行验收器、不签名；`accept` 按 A2C 重跑验收，pending 不签，fail 出失败报告，pass 才签7并付款。亲签事项由九问交互确认；技能不能替用户虚构确认。预算和类别由本地连接授权约束，平台不替用户持有权限。

轻量本地 `poll`/`watch` 维护等待，不靠持续模型对话或平台轮询用户卡。客户端退出期间停止处理，重启读取本地合同状态并恢复；期限不中断。SDK 明确区分已验收未付、待验收与已结清，网络重试不能再次签同一期或重复付款。观察失败写本地 outbox，可重发，不撤销已经完成的协议动作。

## 官方服务侧

| 触发 | 处理与是否唤醒 Swarm |
|---|---|
| Agent Card / JWKS / template.get / 取交付件 | 常驻 Provider 端点直接处理，不唤醒 |
| 待批准复签 | SDK 核签、材料与期限；简单容量规则直接判断，只有业务审核才运行技能 |
| 提案拟卡 | 任务式应答后运行拟卡技能，返回定数报价与有效判据；SDK 组卡、签2、请市场签3 |
| work.start | SDK 核合同、材料与凭证，保存回执；业务回调只投递持久化任务，立即返回 |
| 生产 | 有界工作池按合同建立独立九问会话；服务技能通过 SDK 读取本单材料、请求环节授权、自测、交付 |
| 验收与付款通知 | Provider SDK 更新状态；末期凭证齐备后服务进程结清，不唤醒模型 |

持久化队列以合同摘要/期号/任务类型唯一标识；重复请求不重复生产。任务状态 queued → running → done/failed；进程启动时检查 SDK 已有签4，已交付不再次交；中断任务恢复至队列，先检查合同是否已结束、授权与期限再继续。收到解除或裁定后不追加交付。冷启动、排队计入既有合同期限，不重置时钟。

九问适配器只依赖其公开入口，锁定经过验证的版本。官方进程使用同源码提交构建的纯PythonProcess SDK，经`--run-jsonl`声明四个本单host工具：inspect、quote、selftest、deliver；工具回调进入本地IoA SDK的任务能力接口，令牌仅在宿主，不传给模型。不向服务模型开放Shell、文件系统、任意URL或其他账号操作。技能描述业务与SDK操作顺序；数据通过结构化参数传递。长源码可在selftest的text_fields中以路径段与文本行数组表达，由宿主确定性组装字符串；不开放文件系统、不执行源码。自测成功保留本轮候选，deliver可提交该候选，避免模型重复抄写。失败自测清除候选，不能提交之前的旧成果；交付仍经Provider/A2C SDK自测和签名。交互要求不能自动回答，实际SDK交付与模型终止结果分别记录。生产模式缺少九问或配置时明确失败，不能静默改用样件、直接调用聊天模型或伪称已由 Swarm 完成。桩模式显式选择，用样件和固定报价验证协议，不代表真实 Swarm 已验收。

## 美甲预约配置服务

默认软件领域保留两项配置服务；原版美甲演示选择独立nail-booking场景，七个公开服务、筛选与三份提案以[委托中心](委托中心.md)为准，不向用户提出基础/高级选择题。该场景交付预约配置、BookingEngine源码和微信小程序页面源码；生成的Python只在WASM中执行行为测试，宿主仍使用仓内固定预约运行器。不声称完成微信注册、发布、审核或对任意软件的完整质量保证。

本示例限定两个预约项目，以service1Name、service1Minutes、service2Name、service2Minutes四个标量字段表达，时长为15至240的整数，符合A2C值域子集。模板specSchema在申请提案前校验，不能把嵌套JSON藏在字符串里延迟到签约后才发现不兼容。交付配置将这四个合同字段依序组为services数组，WASM逐项核对；不得在生产时擅自翻译合同字段。服务宿主保存本单结构化工具事件与模型终止结果供诊断，失败记录保留，不改写为成功。

发现、模板核验和候选比较由个人助手完成；SDK可上报真实比较结果，标reported。报价和签名以返回的合同卡为准，不根据讲解台词改价。演示虚拟币授权限定预算，确认签约和确认验收分开；实际生产使用独立九问Swarm，不用样例替代。

## 实验客户端

`experiments/` 是独立进程，经同一本地 SDK 和公开接口使用 ISC 账号。可按服务/领域/数量生成背景委托，明确标记 `source=experiment`。核心只展示结果，不投放需求、不执行助手、不自动补币。运行记录包含实验 id、版本、服务、成约方式、耗时、结局；真实模型调用由服务进程记录。比较只使用相同场景与可追溯输入。

服务任务仅暴露与kind匹配的本单工具：quote为inspect/quote，deliver为inspect/selftest/deliver。模型正常结束但SDK未提交时，在同一会话提示缺少实际操作并继续，最多3轮且合计300秒；保留逐轮结果和真实用量。网络错误、用户交互需求、写入结果未知均不自动续执行或重发。SDK已经成功提交时，以真实提交为准。
