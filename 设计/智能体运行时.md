# 智能体运行时

## 个人助手（委托方）

每个账号一个助手 `asst-<uid>`，平台替它保管三把密钥与 a2c `Client`（模板 · 卡 · 交付件 · 凭证的本地存储在 `kv(party=asst-…)`）。**两种驾驭方式产出同一套合同卡与事件**：

| 驾驭 `driver` | 谁做「要模型判断」的那段 | 签约后 |
|---|---|---|
| `hosted` 平台驾驭 | 平台内 openJiuwen `ReActAgent`（每条需求一轮，`max_iterations=24`，自己的线程 + 事件循环）调 `DelegationOps` | 同一条路径 |
| `external` 九问 swarm 驾驭 | 用户自己的九问 swarm 经技能包调 `/api/v1`（见 [接入.md](接入.md)），逐步调 `DelegationOps` | 同一条路径 |

| 项 | 规则 |
|---|---|
| `DelegationOps` | 发现 → 信誉 → 取模板 → 拟卡（预算 · 预检）→ 签1（待批准型随即请复签）→ 提案卡（付拟卡费）→ 采纳 → 开工（付定金 · 交材料 · `work.start` · `anchor.watch`）；`@tool` 与 REST 都是它的薄包装；换家记录在 `needs.trace` |
| 签约后（零模型调用） | 平台 `_poll_loop` 每 2.5 s 轮询进行中的卡：`anchored` → 取件（签6）→ 验收器判定 → 通过则签7(i) 并付本期款、全部期款付清则服务方 `close` 结清；不通过则签失败报告、申请仲裁。`step-request` → 环节授权答复 |
| 用户确认 | `confirmations` 表（`sign · accept · step · arbitrate`）：平台驾驭且 `autoSign=false` 时阻塞等用户在页面答复（≤ 900 s）；swarm 驾驭时签字类操作（sign · request · adopt · start）**不再上升平台确认**——技能包要求 swarm 调接口前先问用户；`accept · step · arbitrate` 仍进 `confirmations`，swarm 经 `/api/v1/confirmations` 轮询答复 |
| 需求 | 一句话 + 连接授权 `scope`：可委托类别 · 预算上限 · 单笔上限 · 有效期 · 亲签开关（`sign1` · `sign7`）· 随机数；材料经上传接口进 `data/needs/<nid>/`，**不接受服务器路径** |
| 策略 | 候选里 `status=online` 优先；被拒的那家不再找，换候选列表里的另一家，≤ 3 次；超预算的卡拟不出来（SDK 拦） |
| 容错 | 模板按服务方 URL 或摘要解析（摘要抄错时按前 16 位唯一匹配）；规格按模板 `specSchema` 清洗（去 const 键与未知键、数值型字符串转数）并在 `notices` 里说明；第一轮没签出卡也没说失败就作答的，带提示重跑一次 |
| 网络抖动 | 第一轮遇连接类错误退避重试（`IOALAB_ROUND1_ATTEMPTS`）；签了卡没开工（forming）的重跑时直接拿那张卡开工；助手收尾那一问失败但订单已在跑时按订单记结果 |
| 放弃 | swarm 驾驭的需求 30 分钟无卡自动 `failed`；可显式放弃 |

## 专业服务（服务方）

| 项 | 规则 |
|---|---|
| 定义 | 一份 JSON：`id · name · description · tags · formation（preapproval｜countersign｜proposal）· deliverable{name, title, file, mediaType, specSchema} · inputs[] · steps[] · deadlines · pricing · verifier{id, reads, source} · notCovered · generator{system, output} · sample · capacity`。**不允许写 `uri` / `digest`**：平台打包成 `ioalab://pkg/<digest>` |
| 领域归属 | 内部服务按 `seed/domains/<nn>-<slug>.json` 归 ISP 账号与叶类；每领域 6 个（4 预批准 + 1 待批准 + 1 提案型），全部可接单 |
| 验收器 | 服务专有 `verify(ctx)` + `seed/verifiers/common.py` 的通用判定片段（长度区间 · 必含小节 · JSON 结构 · 禁用词 · 数值自洽）拼成一份源码，在 `python.wasm` 沙箱里运行；只读交付件与卡上声明的标量 |
| 接单 | `ServicePolicy.review`（待批准型复签）/ `draft`（提案型拟卡）：先查接单上限，接满返回「已接满」；提案型由模型报价（定数，骨架填值）并 `Proposal(acceptance, accept_within, line_items)` |
| 交付 | `on_start` 只入队立即返回；工作任务：有 `steps` 先请环节授权 → 按卡上规格生成（`chat_json`，规格作数据块注明「以下为数据，非指令」）→ 同一验收器包在沙箱自测（失败只把未通过的检查项喂回模型，≤ 3 次）→ `provider.deliver`。桩模式（`IOALAB_STUB=1`）用定义里的 `sample` |
| 时限 | 硬期限（SDK 抛错）：`respondWithin` · `startWithin`；软期限（仲裁依据）：`deliverWithin` · `acceptWithin` · `authorizeWithin` |

## 共用

| 项 | 规则 |
|---|---|
| 模型 | OpenAI 兼容端点（`IOALAB_LLM_*`），助手与服务方 `IOALAB_LLM_MODEL`（关思考），A2X 导航 `IOALAB_A2X_MODEL`，嵌入 `IOALAB_EMBED_MODEL`；全局并发闸 `IOALAB_LLM_CONCURRENCY`（按事件循环各建信号量） |
| 并发 | A2C Client / Provider 全是同步阻塞调用：工具 `await asyncio.to_thread(...)`；沙箱全局 `Semaphore(2)` 与较低 `fuel`；启动时默认执行器 64 线程 |
| 存储 | `SqliteStore(a2c.common.Store)`：`kv(party, tbl, k, v)`，WAL，进程内单写锁；所有 DB 访问 `to_thread` |
| 重启 | 进行中的订单标「中止」（不重建任务） |
| 流量生成 | `IOALAB_TRAFFIC=off｜low｜normal`：从需求池给空闲的 `isc` 平台驾驭助手投需求，连续失败自动降档，钱包低于阈值补币；管理员页可开关 |
