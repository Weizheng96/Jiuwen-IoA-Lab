# 智能体运行时

本文定义用户设备与服务进程中的执行、调度和恢复。消息投递见[消息中心](消息中心.md)，委托接单见[委托交易](委托交易.md)，个人助手业务接口见[助手通信](助手通信.md)。

## 一套运行时、两种使用入口

| 对象 | 职责 |
|---|---|
| IoA 个人助手 Skill | 引导配置与启动；选择委托交易或助手通信；读取该类型的通用流程，逐项调用 SDK |
| IoA 服务方 Skill | 引导配置账号、服务说明、模板、业务技能和并发限制；启动并检查服务接入 |
| 本地接入组件 | 常驻运行 SDK；维护连接、持久化收发、业务调度、授权等待与会话映射 |
| 九问适配器 | 通过原生公开接口启动或续接九问会话，提供本单工具并接收结构化结果 |
| 业务技能与工具 | 完成具体服务生产或助手通信处理，不实现协议签名、支付或传输重试 |

两种 Skill 共享同一 SDK 和运行时实现；每个用户运行自己的实例。账号角色是能力组合，不是两套网络栈。同一本地实例可承载属于该账号的个人助手与多个服务，各自保留身份、配置和业务状态。

导入 Skill 不等于启动进程。安装引导与启动命令由[接入](接入.md)定义；组件启动后无需模型轮询，九问会话只在业务需要时运行。平台核心不创建个人助手，不执行服务生产。

## 模块与依赖

| 模块 | 唯一职责 | 依赖方向 |
|---|---|---|
| 传输 | WebSocket、认证恢复、收发回执与推送订阅 | 依赖公共协议数据，不依赖业务技能 |
| 本地存储 | inbox、outbox、交互映射、业务检查点和工具回执 | 为运行时及业务模块提供事务能力 |
| 调度 | 每交互串行、跨交互并发、模型名额及等待恢复 | 调用业务处理器，不解释合同字段 |
| 委托交易 | 委托方与服务方流程、接单预留、A2C/AP2 调用 | 依赖 A2C SDK 与公共运行时 |
| 助手通信 | 本地接口发布、请求与回复、处理流程装载 | 依赖公共运行时，不依赖委托交易 |
| 九问适配器 | 原版九问进程协议、工具与会话续接 | 依赖九问公开 SDK；为上述业务模块提供模型执行能力 |

SDK 核心不依赖平台核心、A2X 实现、官方服务目录或美甲场景。九问作为可选适配依赖，不被基础 SDK 强制导入；平台也不导入九问。仅保留明确的小型宿主接口，不增加通用工作流引擎。

## 本地状态所有权

本地接入组件是身份目录、私钥和业务数据库的唯一写入所有者。Skill 脚本及 CLI 通过经本地认证的 IPC 或回环接口调用它，不各自打开相同身份库，不争抢全局长期锁。

| 保存内容 | 规则 |
|---|---|
| 身份与授权 | 私钥、付款身份、授权范围及原生用户确认保存在本地；不上传平台、不交给模型 |
| 协议原件 | 模板、合同、材料、交付件、签名链和付款回执由 A2C SDK 管理 |
| 收发记录 | inbox、outbox、去重键、ACK 游标及外部工具回执持久化 |
| 会话映射 | 交互 ID、原始请求、参与方、会话 ID、技能/工具定义摘要、业务状态及检查点 |
| 锁 | 数据库事务和交互锁只覆盖短操作；不在数据库锁中等待网络、模型或用户 |

观察事件投递失败只进入 outbox，不回滚已经成功的协议动作。平台观察副本不替代本地合同原件。

## 交互 ID 与会话

| 标识 | 作用与生命周期 |
|---|---|
| 消息 ID | 一次发送及其重传的身份；重复送达不产生新业务 |
| 起始消息 ID | 首个有效业务请求的消息 ID，用于幂等创建交互 |
| 交互 ID | 接收端首次接纳有效业务请求时创建并回传；整笔委托或整段助手通信共用 |
| 九问 Session ID | 本地九问会话；双方分别保存自己的映射，不要求两端会话 ID 相同 |
| A2C 标识 | 请求 ID、任务 ID、模板/合同摘要继续使用协议原义，不被交互 ID 替代 |

接收端以“接收智能体、发送智能体、起始消息 ID”建立唯一记录，并在同一事务写入映射及 `interaction.opened` 待发回执。回执包含 `originMessageId`、`interactionId`、交互方式与接口修订；助手通信还包含截止及最大请求轮数。先完成平台关联登记并取得请求开始许可，才执行业务工具；初始请求重传返回原记录。

平台依据原始消息验证回执确实来自原接收端，持久登记双方、类型和 UUID 的路由关系，再可靠投递给发起端。平台只保存可校验的关联关系，不保存九问 Session。发起端按 `originMessageId` 原子补齐本地映射；缺少 UUID 时进入 `awaiting_open`，不能凭正文相似或账号猜测关联。

回执丢失时重投原始消息或按起始消息查询已登记关系，均不得另建交互；起始消息已过期且尚未建立关系时返回过期。SDK 后续发送接口接受原本地交互句柄并自动带上 UUID，未建立或已关闭时明确返回状态，不让模型手抄 UUID。

接收端的每个交互拥有独立执行会话；发起端的用户会话可以协调多个对外子交互，但其入站回复先更新各自任务状态，不自动作为新请求创建收件会话。对同一个实际九问 Session 的执行还须串行，不能仅按 UUID 加锁。查询模板与能力不创建模型会话，也不占用接单名额。

后续请求与回复须证明属于原参与方、交互方式及接口，不能仅凭 UUID 加入会话。委托报价、授权、生产与交付在同一业务映射下续接；不同候选服务分别保留交互。助手通信的冲突、建议和改约可以属于同一交互，单次请求结束不等于整个交互关闭。建立前拒绝、建立后失败和关闭后迟到结果的统一处理见[消息中心](消息中心.md)。

同一交互同一时刻最多执行一个模型轮次；接续固定原 Agent 定义、技能版本与工具集合。接口更新不静默改变在途会话的行为，变更处理见[助手通信](助手通信.md)。

## 调度与等待

| 资源 | 限制对象 | 释放条件 |
|---|---|---|
| 服务接单容量 | 已预留及尚未完成的委托 | 依[委托交易](委托交易.md)规定释放，等待授权/验收仍占用 |
| 模型执行并发 | 正在运行的九问轮次 | 本轮结束或中断；等待业务输入时释放 |
| 本地待处理队列 | 已送达但尚未执行的业务消息 | 开始处理、过期或明确拒绝；大小有界 |
| 控制处理通道 | 授权答复、解除、查询、回执等 | 独立处理，不被满额新委托或模型队列阻塞 |

业务处理器到达用户确认或外部事件检查点后，持久化 `waiting` 并结束本轮；收到有效答复后续接会话。不得让长时间阻塞的模型轮次占住全部工作线程。九问原生交互回调需要同一运行进程答复时，只能由真实用户或已明确授权的宿主处理；不能伪造同意，也不能把杀进程当作可透明恢复的暂停。

业务状态采用 `queued / running / waiting / completed / rejected / failed / unknown`；合同状态仍由 A2C 管理，业务状态不得替代签名证据。排队和冷启动计入合同期限，不能因重启或等待自动延长。

## 按需调用九问

| 触发 | 执行方式 |
|---|---|
| 身份、已发布模板、历史结果查询、消息 ACK | 确定性处理，不调用模型 |
| A2C 校验、金额计算、签名、确定性验收 | 由 A2C SDK 执行；模型不能直接给出签名或代替验收报告 |
| 提案业务判断与服务生产 | 容量/权限检查后，按本单技能与工具启动或续接九问 |
| 助手通信 | 装载用户批准的本地处理流程；按需调用九问和受限业务工具 |
| 用户确认 | 向用户呈现真实对象与状态；未确认不推进受保护操作 |

九问适配器使用锁定的原版公开接口，不改源码、全局提示词或私有历史数据库。Process SDK 每次运行可启动新进程，但以同一 Session ID 续接；它的运行请求 ID 不等于业务幂等键。网页会话展示、通知和审批通过九问公开能力独立适配，后台执行成功不能直接记为网页已展示或用户已读。

宿主工具能力限定在当前账号、交互与阶段；凭据留在宿主。用户配置的业务工具可以按授权启用，不把官方样例的固定工具集强加给所有服务。模型输出必须经过结构校验和 SDK 状态检查；“已完成”的自然语言不构成交付或付款凭证。

## 恢复与外部副作用

启动时先恢复连接代次与本地记录，再核对已完成协议步骤及工具回执。已交付、已验收或已付款的步骤不重复执行；接单预留从委托中心权威台账核对恢复，本地只保存镜像，不另建权威计数。授权和期限失效时停止相应动作并返回明确状态。

连接失效或执行租约过期时停止发起新的外部动作；工具调用前复核本实例执行资格。失联前已经发出的操作依真实回执恢复，连接代次不能消除外部系统中已经产生的效果。

外部调用发起前保存稳定操作键，返回后保存实际结果。网络中断导致结果未知时标 `unknown`，查询真实结果或交由用户处理；不能自动重新发送邮件、重复付款或重新生产。模型进程正常退出但缺少必需 SDK 操作时，只能在有界轮次内提示补齐；未知副作用、原生交互需求或协议错误不自动重放。

## 官方服务与实验客户端

官方服务、外部服务及管理员助手使用相同公开 SDK 和运行时。`official-services/` 只维护领域、服务配置、模板、验收器和业务技能；管理员助手是独立账号配置，预约规则见[会议预约](示例/会议预约.md)。核心不为官方账号提供执行后门。

实验客户端在核心外通过同一 SDK 产生委托与助手通信，标记 `source=experiment`；运行记录保留输入、参与方、真实协议回执、模型调用及结局。样件或桩运行必须显式选择和标注，不能冒充真实九问生产。
