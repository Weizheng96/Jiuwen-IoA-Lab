# 委托交易

职责：定义个人助手向专业服务发起委托的流程，以及注册中心、委托中心和本地 SDK 的分工。合同字段、成约方式、签名与期限计算直接遵守 A2C，不复制协议实现。

## 服务登记与发现

| 步骤 | 规则 |
|---|---|
| 登记 | 所属账号绑定服务身份、收款公钥和稳定平台地址，提交签名 Agent Card/JWKS；不要求用户提供公网 IP 或公网监听端口 |
| 配置 | 服务方设置说明、类别、合同模板、接单容量、业务技能和工具；SDK 校验宿主可用后上线 |
| 发布 | 服务方本地签模板，调用 A2C Market 签认，注册中心索引完整模板的摘要和公开元数据 |
| 可用性 | 登记、公示、在线、容量、模型配置分别记录；存在服务种子不代表已经可接单 |
| 发现 | 本期实际使用 A2X 分类搜索；候选依据公开说明、模板、材料、规格、验收与期限筛选 |
| 缓存 | 平台可缓存完整签名模板与 Agent Card/JWKS；SDK 仍走标准验签，缓存不改摘要、身份或有效期 |

普通服务默认待批准或提案模式。预批准仍是 A2C 合法模式，但本期普通服务接入不启用；未建立原子接单保证前，不允许用预批准绕过容量检查。

## 委托方通用流程

| 阶段 | 行为及确认边界 |
|---|---|
| 需求与授权 | 明确用途、预算、可委托类别、拟卡费总限额及授权有效期；取得真实用户答复后建立本地 scope |
| 发现与筛选 | search → 信誉 → 完整模板验签；逐项记录合格或不适合的依据，材料不足先澄清，不虚构材料 |
| 多方征集 | 对实际合格候选准备 spec/materials，分别预留容量，再申请正式提案或待批准卡；允许并按预算进行多选 |
| 合同比较 | 读取签名报价、交付件、验收覆盖与未覆盖项、金额、拟卡费、期限、亲签条款；不能只按价格或验收条目数量排序 |
| 合同确认 | 展示具体合同及采用的默认值，获取本阶段用户确认；按 A2C 成约方式签署，不把模型建议当作用户确认 |
| 开工与履约 | 成约后独立调用 work.start；推送进展，收到合同声明的环节请求才取得对应授权 |
| 取件与验收 | 本地 SDK 取件并运行卡上验收器；verify 不签字；验收失败或无法判断时上升用户，不伪造通过 |
| 接受与付款 | 用户确认后 accept 按协议复验，合格才签7并在授权内调用 AP2；验收与实际付款分别显示 |
| 结束与争议 | 保存证据及付款凭证；对解除、超时、争议按协议处理，不靠改本地状态冒充结清 |

费用不明时先核实；拟卡费不是交付总价。多家合格且额度允许时征集多家正式报价，不能把最低数量已满足误读为其他候选不需处理。单方指定、仅一家适合或预算不足时如实解释。

本地可配置最低报价数 1—8，默认 1，固化到 scope；同服务多张卡只计一家。满足最低值只允许进入比较，不替用户推荐或确认。美甲服务名、数量和推荐剧情只属于[示例](示例/美甲预约.md)。

## 接单容量与预留

### 一次委托的完整控制链

| 顺序 | 发起端 → 平台 → 接收端 | 持久事实与下一步条件 |
|---|---|---|
| 1 | 发起端发送 `delegation.intent`，附待请求摘要和材料元数据 | 原消息 ID 负责重传；离线只暂存意向，不付款 |
| 2 | 接收端核验意向，建立交互 ID 并返回 `interaction.opened` | 平台登记不可变双方关系，发起端关联本地记录 |
| 3 | 服务方 SDK 检查接单策略，向委托中心申请 admission | 平台原子检查容量；成功返回 held，失败给出满额等明确原因 |
| 4 | 接收端可靠返回 `delegation.result` | 携带同一交互 ID、admissionId、绑定摘要和 holdUntil；拒绝则关闭未成约交互 |
| 5 | 发起端确认预留有效且用途/预算仍获授权 | 此前不能付拟卡费；支付入口原子检查绑定和有效期、提交预留并执行 AP2 |
| 6 | 通过同一交互提交正式 A2C 请求 | 服务方核签名、期限、材料与凭证，拟卡/复签结果通过原任务与消息回传 |
| 7 | 按合同确认、开工、生产、验收和付款 | 双方均以 A2C 原件为准；新阶段的用户授权单独取得 |
| 8 | 形成终局 | 已成约按 A2C 终态结束；未成约按明确拒绝/失败及对账结果关闭，保留所有事实回执 |

发起方通过 SDK 关联原意向、预留与正式请求，不手抄标识。`interaction.opened` 只说明建立关联，不表示容量获准；`delegation.result` 的预留成功也不表示合同成立。每个交互的多个网络请求共用上述链路，不另建平行的接单握手。

### 台账与并发

容量单位是**仍可能独立成约的承诺或尚未结束的合同**，不是模型线程或交互 ID。一个交互若产生多份同时有效的承诺须分别计数；本期同一交互只允许一个未结束承诺，不在有效承诺未关闭时另发替代版本。

权威 admission 台账放在平台委托中心，属于运行数据；服务方 SDK 决定接单策略并申请原子预留、提交及释放。本地仅保存镜像和恢复依据。平台不因此持有服务私钥、代签合同或运行服务。

| 台账字段 | 含义 |
|---|---|
| admissionId | 稳定预留标识，留在 IoA 封套和运行数据库 |
| provider / initiator | 服务与发起身份，禁止跨主体复用 |
| requestDigest / cardDigest | 绑定本次提案请求或待批准卡；不得偷换报价对象 |
| state | held（短期预留）、committed（付款或有效承诺已开始）、released（已核实释放） |
| holdUntil | 仅适用于尚未进入付款或有效签署的预留 |
| paymentOperation / task / contract | 恢复与对账关联，不增加 A2C 字段 |

`held + committed` 未释放记录计入服务容量。平台在事务中检查容量并创建记录；同请求重传返回原记录。SDK 本地模型执行并发另行控制，见[智能体运行时](智能体运行时.md)。

| 时点 | 规则 |
|---|---|
| 离线意向 | 可排队等待，但不算接单、不付拟卡费、不声明已成约 |
| 待批准 | 先预留，再提交签署请求；业务审查后重新检查期限，原子提交预留，再发有效签名 |
| 提案 | 准备请求摘要并预留；支付入口先提交预留，再按 AP2 付拟卡费；取回凭证、签请求并提交拟卡 |
| 提案输出 | 重新核验响应期限和预留，持久化承诺，再签署并请求市场认证；排队、模型和断线时间均计入期限 |
| 容量已满 | 拒绝新的预留，给出明确状态；已有合同的授权、交付、验收、付款、解除和恢复照常处理 |
| 等待授权/验收 | 委托仍占接单容量，模型执行名额可释放 |

AP2 拟卡费入口在平台应用事务内协调预留状态、付款操作唯一性及有效期检查，再过账。支付组件不自行判断是否接单。旧的付款入口关闭或结果核实前，预留不得自动释放；不能只假定底层 JWT 解码已核验截止时间。

## 承诺窗口与故障恢复

| 情况 | 释放条件 |
|---|---|
| 未付款、未签署的 held | holdUntil 到期后原子释放，原付款入口随之失效 |
| 待批准已签2、未开工 | 至少保留至签2时刻 + startWithin，再按协议核实未开工与终态 |
| 提案已签3、未开工 | 至少保留至签3时刻 + respondWithin + startWithin；不能只等响应窗口结束就释放 |
| 已开工 | 依据协议终态及必要凭证释放，不因连接断开或模型结束释放 |
| 付款/签署结果未知 | 保留 committed，先查原支付操作、签名和任务；不得重付、重签成另一份承诺或按短租约释放 |
| 已付拟卡费但未形成承诺 | 拟卡明确拒绝/失败或期限结束后，先关闭原付款/签署入口并核实无在途有效承诺，再结束预留；已付凭证保留，不自动退款或重新收费 |
| 未中选 | UI 选择不构成协议撤销；有效签名提案继续保留到合法窗口关闭 |

平台为本地 SDK 提供幂等付款结果查询，返回原凭证或明确未生效状态。无自动判定依据的异常进入待核实状态并可审计，不能清库释放容量。重启先对账再开放新接单。

A2C 即发即收签名的新鲜度、模板有效期与合同期限独立于消息 TTL。长期离线仅排队业务意向；接收端可用并预留成功后再准备有效协议请求。过期请求返回协议错误，平台不改时间或代签。重新准备前核对原操作是否已生效；可延迟取回的结果按协议本身的核验规则处理。

## 模板、验收与仲裁

验收器包按摘要寻址，SDK 解析 `ioalab://pkg/<digest>` 并核摘要；只在 A2C WASM 沙箱运行。正常 L2 验收使用委托方自己的模型；disputeModels 仅用于仲裁复算，均须来自部署者明确登记的模型集合，缺配置拒签相应模板。结论由验收器程序判定。

申请争议须核当事人归属、合同签名链、交付摘要和报告；裁定独立签署并引用合同摘要，不上卡、不自动触发付款。信誉只来自已核实结清与裁定，实验交易如实标记，不填充虚构历史。

## 内部服务模板自动续期

官方新模板发布时起有效 30 天；剩余不足 7 天重新签认并刷新 A2X，启动时及运行中每 60 秒检查。续期失败保留原件并报告，不伪称成功；到期模板不再用于新签约。

模板轮换产生新摘要，旧模板保留供原合同验收和争议复核。用户委托授权默认 7 天，过期须重新取得同意；合同期限依原签名锚定，服务重启不延长。官方服务以公开 SDK 执行续期，在配置、连接和容量满足时启动即可试用。
