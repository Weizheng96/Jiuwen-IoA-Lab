# 设计 · 唯一事实来源

本目录定义九问IoA实验平台（Jiuwen IoA Lab）的现行规范：**面向智能体互联网的仿真验证与开放体验平台。** 代码、SDK、Skill、部署、界面、测试和演示均以此为依据。根 README 是概要，AGENTS.md 是维护约束，均不另行定义产品行为。

现行规范可以领先实现。实现范围与待迁移项只记在[开发计划](../docs/开发计划.md)，实际结果只记在[验证记录](../demo/verification/README.md)及对应证据中；设计成立不等于功能已实现或验收通过。

版本入口：[VERSION](VERSION)。历史索引和变更原因统一保存在[变更/](变更/README.md)，不在正文保留旧方案、迭代过程或完成记录。

依据的 A2C 设计版本：v0.0.19（协议以 [A2C 主仓](https://github.com/Weizheng96/AgentContractProtocol/tree/main/设计)为准；依赖来源见 [SOURCE.json](../vendor/wheels/SOURCE.json)）。平台与协议独立维护版本。

## 阅读与裁决

1. 首次阅读：术语 → 边界与组件 → 所需交互方式 → 接入与运行时。
2. 平台边界由边界与组件裁决；具体规则由上表对应的唯一职责文档裁决，其他位置只链接。
3. A2C 合同字段、签名、期限、验收和付款依据遵守上游协议；平台封套和运行元数据不得改写协议语义。
4. 场景只能配置通用能力，不得反向规定通用 Skill、SDK 或平台必须采用该场景值。
5. 发现正文矛盾先修正职责归属和规范，再修改产物；不能用代码现状覆盖设计，也不能用历史文件覆盖正文。

## 维护格式

| 项 | 约定 |
|---|---|
| 结构 | 每页先写职责，再列对象、规则、流程与异常；优先表格及必要的 Mermaid |
| 用词 | 术语首次出现链接术语表；界面名称、中文术语和代码字段分别标明 |
| 约束 | “必须/不得”表示不变量；“默认”表示可配置初值；范围外能力不提供占位业务 API |
| 去重 | 一条规则只写全一次；示例、部署和验收引用该规则，补充各自特有条件 |
| 历史 | 变更原因、替代方案、迁移经过和逐轮结果仅进入变更/；不在正文追加“此前/本次修复”段落 |
| 版本 | 修改规范时仅递增 VERSION 最后一位，在变更索引加条目和详情；较高位由用户决定 |
| 产物 | 仅实现并验证相应规范后更新产物 VERSION；部分迁移如实记录差距 |

维护后执行 `python 设计/check.py` 与 `python tools/check_docs.py`，并完成 AGENTS.md 要求的回归。历史索引与现行正文均须可从本页到达。
