# 设计 · 唯一事实来源

本目录是九问IoA实验平台的统一文档入口：模块文件夹与流程页定义现行规范，工程下的实施资料及[部署教程](工程/部署.md)单独保存非规范操作事实。代码、SDK、接入技能、部署、界面和演示以模块接口页为准。目标见[核心理念](核心理念.md)，版本只见[VERSION](VERSION)。规范可以领先实现；实际差距见[进展](工程/进展.md)，实测结果见[验证记录](工程/实施资料/部署发行.md#历史验证资料归档)。

依据的 A2C 设计版本：v0.0.23。合同协议以 [A2C 主仓](https://github.com/Weizheng96/AgentContractProtocol/tree/main/设计)为准，锁定依赖来源见 [SOURCE.json](../vendor/wheels/SOURCE.json)；平台不重新定义 A2C 字段、签名、期限、验收或付款依据。

## 阅读顺序

1. 理解平台：[核心理念](核心理念.md) → [术语](术语.md) → [架构](架构.md)。
2. 理解一次使用：选择下表中的接入或业务流程，再按链接阅读涉及模块的接口页。
3. 实现与核验：对照接口页的测试列与验收条件、流程页的端到端验收，差距见[进展](工程/进展.md)。
4. 改代码或修文档：按开发技能的[路由表](../.agents/skills/develop/references/routing.md)进入模块文件夹，只读本模块、所依赖模块的接口页及所列测试，不通读本目录。

## 唯一归属与一致性

| 内容 | 完整定义的位置 | 其他位置如何使用 |
|---|---|---|
| 概念含义 | 术语 | 使用正式名称并链接归属模块的接口页 |
| 运行边界与跨模块规则 | 架构 | 模块与流程遵守边界；实际路径在各模块实现页，差距在模块票据 |
| 领域状态与不变量 | 对应模块接口页 | 流程引用规则，只补参与方的先后关系 |
| 字段、方法与格式 | 对应模块接口页 | 其他模块说明校验语义，场景页填入业务值 |
| 用户可见内容 | 网页UI 接口页 | 按模块事实表达，不自行推进状态 |
| 场景专属值 | 场景页 | 通用技能、SDK 和平台不反向依赖场景 |

例如：`interactionId` 的含义在术语，双方绑定规则在消息中心，本地会话映射在共用运行时，封套字段在 web服务 接口，多轮使用顺序在助手通信流程。各页补充不同职责，不重复定义同一规则。

发现冲突时先修正唯一归属页及引用方，再开发；不能以代码现状、历史文件或某个示例覆盖现行规范。根 README 只提供概述和实际入口，AGENTS.md 只提供维护约束。

## 统一格式与维护

模块文件夹的文件与模板见[模块文件夹格式](../.agents/skills/design/references/module-format.md)。其余规范页先写“目的与范围”，末尾列“相关文档”；部署教程按两平台操作顺序编排，不套规范页格式；主体优先表格，必要时使用 Mermaid。按类型采用以下顺序，不保留无内容的空章节。

| 类型 | 主体顺序 |
|---|---|
| 流程 | 参与方与前置条件 → 时序 → 步骤及结果 → 异常分支 |
| 工程/场景 | 范围 → 配置或条件 → 执行要求 → 验证与边界 |

“必须/不得”表示不变量，“默认”表示可配置初值；不把计划能力写成已实现。只有不变量变化才递增 VERSION 第三位并登记变更表；事实性修正随代码修正、定期收口，判据与步骤见 [design 技能](../.agents/skills/design/SKILL.md)与[交付](../.agents/skills/develop/references/delivery.md#提交标题与版本)。产物只在发布时更新自己的 VERSION。不变量改变先形成初始方案，在模块票据标开发中并更新唯一归属的接口页与版本，再实施；完成后将最新完整方案收回接口页与实现页，删除已完成票据。实现偏离正确设计时，在模块票据写修复方案并标“开发中，与当前设计有偏离”，不为实现缺陷修改正确规范。

迁移文档需同时更新当前引用；目标代码目录以架构模块表为准，尚未落地的路径用代码标识，不建立无效文件链接。实际使用入口随代码迁移更新，不能先将可运行命令改为未存在的路径。历史文件保留当时路径和语境，依 Git 历史追溯。维护后按 AGENTS.md 执行版本、链接、回归与交付检查。
