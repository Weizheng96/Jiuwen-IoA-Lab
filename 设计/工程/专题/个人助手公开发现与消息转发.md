# 个人助手公开发现与消息转发

> 实施资料：用户已确认的初始方案与任务票据；客户端21已开始本机公开原语验证，业务功能尚未实现、发布或实机验收。实施前先将各项契约收回所属模块接口页并递增设计版本，本页不替代现行规范。

## 已确认范围

| 项目 | 决定 |
|---|---|
| 公开选择 | 个人助手接入后自愿公开能力；既有账号也能主动发布，默认不公开 |
| namespace | 保留现有服务方数据集 `ioalab`，新增个人助手数据集 `ioalab-assistants`；同一稳定助手身份一份档案 |
| 分类 | 初期不分类，所有档案直接属于个人助手 namespace 的根目录；不生成领域叶类、不调用分类模型、不转入服务方兜底类目 |
| 描述 | 能力描述非空且不超过100字；首版不另加长说明、标签或能力列表绕过限制 |
| 公开接口 | 所有公开能力的个人助手同时提供固定的“消息转发”接口，拟用机器名 `message.forward` |
| 发信范围 | 所有现有及未来注册的平台账号均可投递；必须登录，以平台认证账号和助手身份标明来源，不做真实姓名或证件核验 |
| 会话 | 按接收助手与发送方稳定账号分组，每个发送方一个独立收信会话；新的交互不另建同一发送方的会话 |
| 接收行为 | 只做确定性校验、保存、转发和回执；用户不操作就不调用模型处理来信，不自动总结、回复或执行工具 |
| 首版人工操作 | 人工查看，用户自行向助手提出处理要求；不增加专用“让模型处理来信”入口 |
| 宿主与交付 | 九问、Codex、Claude Code三种宿主均通过完整收信验收后统一交付；任一宿主未通过不能将本功能记为完成 |

## 初始方案

### 公开档案与根目录发现

身份中心继续持有账号、助手身份与停用事实；注册中心新增个人助手公开档案、修订、操作回执与索引投影。档案只保存稳定身份关联、平台公开显示名、100字能力描述、发布状态、修订与时间。客户端本地会话、宿主地址、通知凭据及私人处理规则不进入目录。

字数按去除首尾空白后的Unicode码点计数，汉字、英文字母、数字、标点及内部空白均计数；中英文使用同一标准。组合表情可占多个码点，前后端采用一致计数并显示余量。只接受纯文本，不静默截断、不由模型自动压缩后发布；超长时交还用户修改、重新预览确认。

SDK起草并展示具体公开摘要，用户经可信确认后发布。首次公开同时确认面向全部认证账号开放的固定转发入口和实际收信宿主；不能用模型文本或 `confirmed=true` 替代批准。平台通过已认证所属关系生成档案身份，不接受自报发送者或另一个账号的身份。

将现有Discovery的数据集、缓存和搜索器作用域显式化；两个namespace的目录、查询、投影及缓存相互隔离。个人助手先对根目录中的公开摘要作向量或确定性文本检索，不走服务分类、分类预览及树导航。搜索可无结果，不把任意top-k包装成有对应能力；匹配门槛由实现票使用有正负样例的验证集校准并记录。

拟增加个人助手档案发布/状态/撤回与发现的HTTP入口，SDK与原生Skill提供公开、修改、撤回、找人及选择目标发信流程；入口及字段在实施前由web服务、注册中心与个人助手端接口页定稿。保留现有服务搜索契约；找人不要求先建立委托任务，不混入服务报价、模板或A2C交易。

### 固定消息转发与零模型处理

消息中心继续拥有收信接口、当前权限、请求受理与投递关系；注册中心只索引公开能力。跨中心的首次发布、更新和撤回由web服务用例协调，不由两个中心互读私有表。公开状态与固定转发入口的一致性在数据库事务内维护，A2X是可恢复投影；搜索返回前复核最新公开状态，不能因旧索引继续暴露已撤回档案。

固定接口输入仅含自然语言 `text`，首版上限2000个Unicode码点；不接收任意URL、目标会话、脚本、工具、处理指令或自报发送者。来源取平台认证封套。正文按外部纯文本展示，特殊标记、链接及看似命令的内容均作为文字；不自动执行命令、抓取链接或生成摘要。复用现有消息长度总限额、账号限流和未完成队列配额，另校验文本上限。

SDK为该接口登记固定、可核版本的确定性处理器，复用现有投递、租约、调度与原消息恢复机制，直接调用经本机明确配置的会话投递资源。不能先调用普通收信的 `host.run` 再要求模型转发，也不能靠Markdown处理正文、模型选择工具或模型承诺不执行来保证零模型。普通已授权收信规则仍沿原流程执行；固定转发接口不能被改造成模型处理规则。

接收者在本机确定目的宿主和本人账号，发送方不能指定目标或扩大权限。会话分组使用接收助手ID和平台认证发送方稳定账号ID，不使用可变显示名、单次interactionId或来信自带的group值。来源标注与正文分开展示，不把外部来信伪装成接收用户本人指令、系统指令或助手自行作出的结论。

收到、恢复、重投和打开查看来信都不启动模型轮次；来信不进入其他业务会话或正在运行的模型轮次。专用收信会话的后续用户主动处理仍须将原文标为外部数据，不授予工具或业务批准。对会话原语隐式合并上下文的宿主，先验证实际行为并制定隔离办法；若无法满足，不放宽规则来宣称适配完成。

### 状态、撤回与恢复

公开前必须确认本机固定处理器、目标绑定及相应宿主投递能力已经通过核验；仅安装CLI或有后台模型能力不等于可公开。暂时离线不删除公开档案，分别展示档案已公开、连接在线与会话投递就绪；明确说明允许离线暂存，不保证即时处理。

发信方只取得绑定原消息的排队、投递或失败回执；会话已持久接收不等于用户已读或处理，不向发送者泄露本地Session ID、路径或凭据。后续投递状态由独立查询读取，不改写原请求已经返回的不可变结果。创建会话、写入及确认丢失时保留原操作和原摘要，先查原回执；无法核清的结果为unknown，不能另建会话或用新消息ID重写。

修改公开描述须重新预览确认并比较修订；操作丢响应恢复原操作，旧请求不能覆盖新描述。撤回公开同步关闭本次公开所绑定的固定转发入口，停止新搜索命中和新请求受理，不影响用户另行授权的普通私信接口。已受理未开始的请求按当前启停状态复核并明确拒绝；已开始的确定性投递按真实效果对账，不声称撤回能够删除对方或本人已经收到的内容。本人历史记录与幂等证据按原保留规则保存。

## 宿主调研与证据边界

2026-11-13已开始专用会话的本机公开接口实测，见[专项记录](../实施资料/零模型收信宿主验证.md)。被动探针不执行模型推理；用户随后明确授权一次Codex模型对比轮次。不向其他业务会话注入消息，不直接读取或编辑宿主私人历史。

| 宿主 | 已确认基础 | 尚待验证 |
|---|---|---|
| 九问 | 本仓通知扩展经公开 `session.create` 与 `history.append_record` 写会话；现有工具按交互分组 | 固定零模型入口、按发送方分组、来信来源展示及整条链路；既有通知代码不是本功能完成证据 |
| Codex | [官方App Server](https://learn.chatgpt.com/docs/app-server#inject-items-into-a-thread)说明 `thread/inject_items` 不启动用户轮次，但内容持久化并进入后续模型请求；本机 `codex-cli 0.167.0-alpha.3.2` 生成的公开Schema包含该方法 | 本机桌面/目标前台可见性，纯展示与模型上下文的隔离，创建/恢复/追加回执、重复写入及接收时已有活动轮次的行为 |
| Claude Code | [官方TypeScript Agent SDK](https://code.claude.com/docs/en/agent-sdk/typescript#sdkusermessage)提供 `shouldQuery:false`，追加transcript而不启动助手轮次，但会合入下一条触发轮次的用户消息；本机CLI为2.1.322 | 版本和公开Python输入契约、原生终端/目标前台可见性、持久查询/去重/恢复及下一轮上下文隔离 |

Claude [Channels](https://code.claude.com/docs/en/channels-reference#notification-format)会将事件送入模型上下文，不能当作已满足零模型收信的证明。Codex的 `turn/start`、`turn/steer` 及Claude普通query也不用于被动转发。Python SDK虽支持流式字典输入，其[官方参考](https://code.claude.com/docs/en/agent-sdk/python#claudesdkclient)未单列 `shouldQuery`，不能仅凭TypeScript字段就宣称现有Python适配已支持。

上表保留原官方调研范围，后续实测以专项记录为准：Codex创建/追加/原线程恢复可做，但公开消息与时间线无来信；用户获准运行模型后才有公开可读取的对话轮次，前台显示待用户确认。Claude已取得CLI被动持久、公开查询、同UUID恢复及零用量证据，原生前台/隔离及Python主适配仍待验。

Codex原始Schema在本机 `temp/assistant-discovery-research/codex-schema/`，不入库。尚无本功能完整验收结论。三宿主验证是统一交付的硬门槛；不通过时在票据登记真实缺项并回到方案讨论，不改写私人历史文件、不自动换宿主版本或启用模型兜底。平台独立收信会话仅为待讨论建议，原方案未修改。
