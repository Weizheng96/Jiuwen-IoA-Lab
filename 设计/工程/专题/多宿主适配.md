# 多宿主适配

> 实施资料：初始方案与票据顺序。现行契约归各模块接口页。

## 方案

九问、Codex与Claude Code为客户端同级适配子模块，均实现共用运行时的三方法AgentHost；个人助手、服务方、可靠连接、业务数据库及授权规则保持同一权威。新增适配器不修改宿主源码、全局设置、历史数据库或用户已有聊天。宿主登录与模型访问归用户已有宿主，不把开发模型源写入适配器。

Codex采用本机App Server的stdio JSON-RPC，生成实际版本Schema核对实验动态工具；先实现仅SDK工具的受限轮次，原生生产工具未验证时明确拒绝。Claude Code采用官方Python Agent SDK，使用进程内MCP工具、明确Session ID与中断；不以命令输出解析代替结构化宿主协议。两者保留未知结果、不自动重发，可信业务批准继续复用SDK本机确认入口。

业务技能冻结文档由共用运行时提供，九问和Codex复用同一实现；宿主原生问题转为既有SDK问题封套，原问题ID与Session必须保留。首轮固定定义摘要，后续续接不得换定义、技能或权限。通知通过owner.notify业务工具另行提供，创建后台会话不等于向用户当前聊天投递。

## 验证接缝

以公开AgentHost三方法为适配验收面；stdio子进程为可替身外部边界，验证真实消息分派、Session先绑定、恢复、拒绝及未知结果；技能快照沿已有公开行为回归。本机真实Codex只执行无外部副作用的工具探针和取消，不触发签约、付款或邮件。

官方依据：[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[Claude Python SDK](https://code.claude.com/docs/en/agent-sdk/python)、[权限与提问](https://code.claude.com/docs/en/agent-sdk/user-input)。实际字段以所选安装版本的公开Schema及运行回执为准。
