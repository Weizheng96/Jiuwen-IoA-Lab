# 一句话接入与三宿主全流程

> 实施资料：2026-11-16形成并按源码调研调整客户端26—37票据，待领票；已拆开既有能力、新增差距与目标待验，本次未修改产品代码或完成新实机验收。新不变量先落到唯一归属模块接口页并升版再实现；本页不是现行规范。另一个Codex会话实现，独立Claude会话验收。

## 目的与范围

目标：任何人在自己的Claude Code CLI、Codex桌面版或九问Swarm中说一句“参考https://gitcode.com/WeiZheng96/jiuwen-IoA-lab/blob/main/README_AGENT.md，帮我接入ioa lab”，智能体即自行下载、配置、启动客户端；用户配置相应Skill后，可完成四个流程：委托交易-发起委托、委托交易-发布服务、私人交互-发布接口、私人交互-发起交互。Skill优先自动接入，不行再给手动指导；不以用户预先修改宿主作为接入前提。允许的原生扩展配置见决策D21。Codex桌面版是本期验收对象，不用Codex CLI后台探针替代桌面验收。

架构前提：智能体调用客户端统一走两份角色Skill；客户端反向调用智能体按宿主分别适配（`src/client/hosts/{jiuwen,codex,claude_code}`）。

两条调用方向不混用：智能体→相同的角色Skill→同一套客户端接口；客户端→宿主适配层→目标智能体。三宿主读取每角色相同的Skill正文与引用，不要求模型选择、拼装或阅读宿主专属协议。会话归属、生命周期与业务流程由客户端统一实现；宿主定位、原生Skill安装／加载、会话投递和工具协议差异由适配层封装。共用入口只调度统一契约；手动指导由适配层按实际宿主和失败步骤生成。首次接入宿主为默认执行宿主，已有业务保持原宿主／会话绑定。

本期三宿主均在Windows用户本机连接远程IoA服务器；Linux先不测试，标未实测。九问不限定为本机Linux。

不在本专题：好友特性（客户端21—25暂缓，不阻塞本专题）；服务器上基于九问的在线试用（先关闭）；macOS；按消息接口／服务逐项配置工具权限（后续需求，本期默认全部可用工具）。

本轮已定：会话按业务上下文统一绑定，由宿主分别适配；首次接入保存配置并优先自动安装Skill，后续调用检查并复用或启动原客户端；只检测默认宿主反向可调用性，持续不可调用默认10分钟后安全退出，旧12小时方案废弃。消息复用平台缓存，服务用现有暂停／恢复接口，仅客户端新增联动；模型复用已有额度控制。完整方案与各票实施步骤见子页。
