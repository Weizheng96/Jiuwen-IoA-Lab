| D21 | 接入时允许自动安装／配置必要的宿主原生扩展（插件、MCP、hooks等）；必须重载／重开时明确指导，不修改宿主程序源码；每种机制的实际能力仍须验证 |
| D22 | 首次一句话接入的宿主保存为默认执行宿主。主动发起业务绑定发起宿主与原会话；外部新业务由默认执行宿主新建会话；更换默认宿主只影响新业务，已有业务沿用原绑定；新增调用宿主不自动改默认 |
| D23 | 两条方向严格分工：智能体→客户端统一通过产品Skill及同一套客户端接口；客户端→智能体统一通过宿主适配层。三宿主读取每角色相同的Skill正文和引用，使用相同操作、参数与回执，不出现多套宿主调用教程；两角色的业务分工保留。宿主定位、配置、原生Skill安装／加载、会话与工具协议等差异收敛到src/client/hosts；共用入口仅调度统一契约，不嵌宿主专属业务分支 |
| D24 | 一句话接入明确覆盖Claude Code CLI、Codex桌面版、九问Swarm三种用户入口；下载／配置／启动自动完成，Skill优先自动接入，否则给手动指导。不以预先修改宿主为前提，允许接入时配置D21中的原生扩展。Codex CLI后台工具轮次不替代桌面验收 |
| D25 | 为简化生命周期，仅检测默认宿主，不轮询其他宿主在线状态；默认宿主持续不可调用达D26时长后准备退出。仍在执行的任务在结束或安全检查点后退出；仅等待用户／对方／后续消息的业务保存状态后允许退出。不自动切换默认宿主 |
| D26 | 持续不可调用退出时长为配置项，默认10分钟（600秒）；不再采用空闲12小时方案 |
| D27 | 私人消息复用消息中心离线缓存；服务下线采用已有暂停接单而非撤销公示。只改客户端检测／暂停／恢复联动，不改平台离线排队与接单语义。重启核宿主和服务就绪后，仅恢复本客户端因宿主故障自动暂停且未被用户后续修改的服务 |
| D28 | 官方服务respondWithin统一PT24H，接受机器报价／复签允许响应窗口一起放宽；真人验收／环节授权同为PT24H，startWithin/deliverWithin仍PT30M；原计时与已签合同不变 |
| D29 | 当前版本不开放在线试用，仅网页入口置灰不可点击，API不关；已完成前端候选随官方时限票一并本地提交 |

## 已解决的讨论项与实施前技术核实

产品要求已足以拟定票据；600秒及平台复用方案均已确认。旧12小时、接单常开即永不退出、九问仅Linux、原生工具默认关闭等候选方案均不实施。

| 项 | 落点 |
|---|---|
| 三宿主公开通道与适用认证 | 客户端26实测；握手不证明推理可执行，独立进程回投桌面／原会话单独核验。无可行公开通道时带证据问用户，禁止默认为降级 |
| 宿主契约及工具共用 | 27、33落实；框架差异进hosts，公共业务不复制 |
| 文档与事件路由 | 28、34落实；相同角色Skill／回执，需求澄清与SDK真实确认分工不变 |
| 安装来源与网络 | 29保留官方依赖和完整性验证、uv兜底与显式镜像；失败如实指导，不另换非官方SDK |
| main与GitCode | 依项目规则仅用户明确要求才合入发布；本次票据和后续日常提交只到develop |
| 在线试用关闭 | 保留既有在线试用04及本轮已定暂停范围，实际后端是否关闭另核，不夹带他人WIP或服务器操作 |
| 健康／生命周期竞争 | 26、35实现方案；busy／暂时异常不按单次失败判不可调用，600秒与自动暂停恢复按原回执核验 |

本页为实施决策记录；新不变量由实施会话先落到唯一归属接口页并升版，再开发。本次仅拟定专题与票据，不把方案记成已实现。
