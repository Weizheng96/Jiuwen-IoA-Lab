# 技术方案

目的：明确后续实现的职责、输入、状态与恢复方式。此为实施方案，不覆盖现行模块规范；每票先修订唯一归属接口与版本再开发，正确规范下的bug按修复处理。Windows为本期唯一实测环境。

## 调用方向与归属

```text
Claude Code CLI／Codex桌面／九问Swarm
       ↓ 同一角色Skill、相同操作／参数／回执
统一绑定调用器 → 客户端接口 → 共用运行时与角色流程
       ↓ 业务到宿主／原生会话的持久绑定
宿主适配层 → 对应智能体公开接口
```

| 唯一owner | 职责 |
|---|---|
| 共用运行时 | 配置、单写入实例、宿主登记与默认引用、业务上下文到会话映射、串行、健康状态及停止计时 |
| 两角色端 | 委托／服务／私人交互业务规则、原Agent流程、合同、真实确认与接单管理 |
| 产品Skill | 两角色各一份通用正文和引用，不按宿主复制；统一操作、参数、回执和恢复引用 |
| src/client/hosts | 宿主定位、模型／认证状态探测、原生Skill安装加载、来源会话采集、新建续接与投递、工具映射、必要原生扩展 |
| 接入入口 | 编排通用步骤并调度适配契约，不内嵌三套模型解析、目录、菜单、消息协议 |
| 平台 | 复用现有离线队列、连接租约、暂停恢复接单，不新增宿主健康协议 |

原生包装与绑定路径可不同，但不产生三套业务Skill。手动步骤由适配层在实际失败时仅返回当前宿主指导，不把宿主专属教程搬到多个引用页让模型全读。

## 宿主与上下文

首次一句话接入宿主为默认执行宿主，配置持久保存；后装其他宿主补齐可选依赖与原生安装，复用同一账号和实例，不改默认。单host配置演进为登记列表与默认引用，显式一次迁移后只保留新权威。

26按宿主分别核能力和阻塞项；已验证宿主的独立切片可继续，三宿主整体仍由36把关。27按实测定义统一能力、接入准备、来源定位、健康、会话新建／恢复／投递与取消契约；不为预设方法名伪造支持。复用现有交互映射、检查点与调度，三宿主分别实现适配，不复制角色业务。

| 来源 | 路由 |
|---|---|
| 用户已有会话主动发起 | 绑定实际发起宿主和原会话；原会话可协调多个业务上下文 |
| 外部首次私人交互／委托 | 按当前默认宿主，每次交互／每笔委托独立新建会话 |
| 同一业务后续多轮／各阶段 | 复用原持久绑定，不按发送方账号合并，不改当前默认 |
| 默认宿主变更／重启 | 新默认只影响新业务；已绑定业务和原操作恢复不变 |

在既有交互／流程检查点中记录中性上下文、宿主引用、真实Session、工作目录和原回执。来源由原生适配机制采集，不让模型手抄三种环境变量；同会话串行，未知效果查原操作不重发。

原用户会话投递与客户端自建固定执行会话在适配内分工，不能把自建workspace、指令或工具定义覆盖到用户原聊天。实际执行、同ID续接、活动会话回投、原生历史可见四项分别证明。Claude须在claude --resume中找到，Codex须桌面可见，九问须有原生用户／渠道归属。无公开可行通道时26报告用户并阻塞对应实施，不默认降级成后台日志、新会话或下次调用带回。

## 一句话接入

| 阶段 | 方案 |
|---|---|
| 下载 | 先GitHub develop验证，正式GitCode发布标签；同来源解析固定commit，保留完整性与依赖校验 |
| 环境 | 无合适Python时uv兜底取得依赖支持的Python≥3.11；最小引导不依赖尚未安装的完整适配包，避免循环。镜像显式配置，不关闭TLS |
| 配置启动 | 宿主专属定位由适配完成，缺项才问；账号在SDK本机页创建／复用，保存原私有配置，准备双角色但不隐式发布服务 |
| Skill | 优先自动安装相同两Skill和必要原生插件／MCP／hooks；需重载、重开或手动导入时给当前宿主的准确步骤 |
| 后续使用 | 每次业务前统一ensure-running核IPC、配置及安装身份；运行中复用，未运行按原配置启动；并发用原OS锁，不凭遗留PID |
| 完成 | 返回固定脱敏摘要，安装、发现Skill、认证、连接、角色绑定与业务就绪分别报告 |

28负责日常调用ensure-running并复用现有start、IPC及OS锁；29负责首次环境准备、宿主登记和后装依赖，启动调用同一接缝。

根目录、程序、账号配置与业务数据沿用持久布局；不重复注册或询问有效配置，不增加开机自启或额外唤醒守护进程。宿主已有认证由宿主持有，不复制秘密。README和Skill只留通用流程；一次安装不冒充新会话原生发现。

## 默认宿主健康与退出

持续不可调用时长为持久配置项，默认600秒。废弃12小时空闲方案；只检测默认宿主，不轮询其他宿主。用户关窗口后若仍能后台反向调用，则继续常驻。

| 状态 | 处理 |
|---|---|
| 预检可用 | 保持运行；不声称下一次模型推理必成功 |
| busy | 正在执行或并发满，排队，不当离线 |
| 暂时异常／不确定 | 单次超时、网络／限流或证据不足，有界重查，不凭单次失败关闭 |
| 明确持续不可调用 | 结合通道／配置及正常业务反馈确证，累计连续时间；旧目录缓存不能覆盖真实认证失败 |
| 恢复 | 重新核可调用性及具体服务就绪，清除连续不可调用计时，恢复符合条件的自动暂停服务 |

日常检查不调用模型；初始化预检可启动短命进程，只代表能建立执行通道。检测间隔有界退避，由实现测负载确定；不暗中定时付费推理。

确认不可调用后停止开始新模型业务，暂停本实例原接单服务，私人接口保留供消息中心缓存。持续600秒后排空运行中任务，结束或安全检查点保存后退出；只等待用户／对方的业务可保存退出，不取消合同，不切默认。无法安全收敛的任务保留unknown和所有权并报告，不能强杀后宣称安全。退出后等下一次Skill调用启动，不再检测已退出实例。

## 服务暂停与自动恢复

复用AdmissionPolicy和admission.configure，服务下线采用暂停接单，不撤销公示或模板。平台继续允许合规私人消息／委托意向排队，队列不是接单、成约、收费，原TTL／合同期限不变；本专题不改平台语义。

1. 先保存服务、原接单状态、系统暂停原因、原修订及稳定操作ID，再提交暂停并保存真实回执。
2. 仅把因宿主故障由本客户端暂停的服务登记为待恢复；用户原已暂停的服务不登记。
3. 回执未知先查原操作／政策，不另起操作覆盖。网络故障时依现有租约离线，不伪报暂停成功。
4. 重启恢复未决操作，核默认宿主与服务模板／Skill／工具就绪；只有平台修订仍符合原自动暂停预期才resume。
5. 用户后续改动、下架、禁用或新修订不覆盖，保留当前政策并报告。
6. 保留既有合同、消息、身份和业务检查点；恢复不重复收费、签约或生产。

既有initialize会保留平台暂停状态，不能假定已实现自动resume；35负责新增联动。平台缓存与租约只做定向回归。

## 工具、用户确认与额度

私人消息处理和服务生产默认全部可用工具，宿主映射在适配层，缺凭据／资源按真实错误报告；本期不实现37的逐接口／服务权限配置。原生工具、统一Skill与SDK回调推进同一原操作，不能构成递归或双执行链。签约、验收、付款等仍走SDK真实确认。

模型并发／队列复用现有控制，scope预算是交易预算，不声称已有统一LLM累计费用封顶。共用SDK本机浏览器待办承接用户决定，九问owner.notify只作提醒；需求澄清可普通对话，不以模型文字代替批准。

## 验收与发布边界

官方服务涉及用户操作的等待窗口默认24小时，由官方服务03接手原候选，核字段、计时起点、模板与执行资源一致性；服务方机器执行时限不统一延长。新模板生效，已签合同与过期授权不改；作为客户端36前置验收。

三宿主×四流程分别通过，另有至少一组跨宿主委托和私人交互；拒绝、过期、unknown、离线重连及暂停恢复有独立证据。Windows以外本期不测，好友票暂缓。

在线试用先关闭归既有在线试用票；置灰不表示后端已关。本专题不擅自部署、停止服务器或合并其他会话的UI／官方服务改动。实施小步提交仅develop；main合入和GitCode发布需用户另行明确要求，36的正式来源验收在发布后完成。
