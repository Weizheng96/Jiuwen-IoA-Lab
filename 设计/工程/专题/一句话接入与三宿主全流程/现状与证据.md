### Codex公开队列：已证实的最小接缝

用户授权后从独立进程执行一次：`codex queue --thread <原threadId> --message <测试消息>`，未加`--resume`，标记`IOA-T26-QUEUE-ACTIVE-20261116`。退出0，queueId为`01a1e363-3580-71f2-bd67-e801e679c463`；另起stdio进程经公开`thread/queue/list`按同threadId查回原条目，未续接、抢占原写者或发第二次消息。主会话在忙时未收到该标记作为新userMessage；用户随后明确观察到原桌面聊天有排队消息。主智能体结束当前turn后，同一原聊天自动收到标记全文作为user消息，主智能体实际回复确认。真实链路为独立CLI→桌面原会话队列可见→当前轮结束后下一轮消费；没有将中途steer当作前提，也未用内部桌面工具投递。**入队、队列可见、消费成userMessage、模型处理是四种证据。**

[官方CLI文档](https://learn.chatgpt.com/docs/developer-commands#codex-queue)说明queue接受UUID或精确名称；`--resume`尝试恢复未加载会话，恢复失败也可能命令成功。自动化必须保存真实queueId并查询原条目，不把CLI退出0当作已处理，不在效果未知时重发。公开同版本Schema有`thread/queue/add`、`thread/queue/list`、`thread/queue/start`等；本轮只调用add/list，未调用start强推当前聊天。

[App Server公开协议](https://learn.chatgpt.com/docs/app-server)提供stdio、Unix socket与实验性WebSocket。当前桌面进程无`--listen`，依默认stdio；ROG真实环境`app-server daemon version`及`app-server proxy`均退出1，默认控制socket不存在，错误10050。此为当前实例无可连接默认控制通道，不能推出Windows永远不支持或独立CLI queue不可用。沙箱用户和ROG用户探针分开；采用ROG结果作为本机事实。自有持久会话queue退出0，原stdio观察到`thread/queue/changed`。首次尚无rollout的空会话queue被拒(-32603)；不可仅thread/start成功就宣称可排队。

[桌面Connections](https://learn.chatgpt.com/docs/remote-connections)公开的是受信设备／SSH主机连接；CLI `--remote`连接TUI。尚未取得本机桌面任意连接自定义App Server URL的公开配置依据；不为补能力修改内部socket或桌面实现。

### Claude后续30的可行切片

[Channels](https://code.claude.com/docs/en/channels)仍为研究预览，当前支持claude.ai和Console API key，不支持第三方云提供商；Console受组织managed settings约束，Team／Enterprise需管理员启用。MCP配置不等于渠道已启用。[Channels reference](https://code.claude.com/docs/en/channels-reference)要求声明`capabilities.experimental['claude/channel']={}`，用`notifications/claude/channel`发送`content`及可选字符串字典`meta`；busy时留待后续turn，通知写出不等于已处理，需应用回执。

自建Channel须在原生交互CLI启动时使用`--dangerously-load-development-channels server:<name>`并完成原生确认；`-p`和Agent SDK忽略该开发开关。最小可行实现是客户端鉴权入口→自有stdio MCP Channel→原生交互会话，保存会话绑定与回执；不能由SDK悄悄启用，也不使用未公开messaging socket。[会话文档](https://code.claude.com/docs/en/sessions)明确SDK/-p会话在默认resume列表隐藏；向运行中background会话resume发prompt要求真实terminal，重定向／pipe／JSON受限，不是通用独立stdio回投接缝。

## 宿主适配

### 本轮子智能体可调用性调研摘要

三宿主均可封装轻量预检，但没有查到无需模型推理就能保证下一次反向业务成功的公开接口。九问支持`protocol.capabilities`、`model.list`／`model.resolve`、`permission.get`；Codex支持`initialize`、`model/list`、`account/read`及仅适用部分认证方式的限额查询；Claude支持`claude auth status`、SDK握手与`get_server_info`、MCP状态查询。`get_server_info`读取初始化缓存；自定义Codex provider不能因`account=null`直接判不可调用。

现有三种probe均可自行启动后台进程，检测的是启动／连接能力，不是用户窗口是否打开；关闭窗口后仍可后台执行，按用户定义应继续算可调用。实际新会话执行、原ID续接、活动会话投递、原生历史可见须独立验证。只核文档、仓内代码与已安装SDK，未跑新的模型轮次或进程探针。

### 平台离线处理代码核实

`src/platform/ioalab/messaging/connections.py`通过连接租约判在线，正常断连接口立即到期，异常失联等租约到期；消息中心规范默认心跳15秒、租约45秒。`observation/services.py`按有效租约、接单政策与容量投影offline／paused／busy／online，不读取参与方模型健康。

`messaging/sending.py`会将合规请求持久化为queued；`tests/test_agent_delivery.py`已有离线请求后重连投递的用例，`tests/test_delegation_admission.py::test_offline_intent_queues_without_charging_then_delivers_after_connection`明确覆盖离线委托意向入队、未收费及重连投递。委托`admission.py::_held`在承诺／付款前核服务连接在线。由此，离线不是禁止发消息或提交意向：可以排队，不表示已处理或已接单；到期按原期限处理。

缺口是宿主不可调用而客户端WS仍续租时，平台不会据此自动判离线。本期需把宿主不可调用与停止承接／公开可执行状态联动，并继续保留已有合同和可靠投递恢复。上述结论为代码与既有用例阅读；本轮没有重新运行这些测试，也未核当前服务器部署行为。
