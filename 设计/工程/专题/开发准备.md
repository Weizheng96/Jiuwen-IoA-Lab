# 开发准备

## 方案

目标是后续开发需求时，新会话只读架构模块表、本模块文件夹与所依赖模块的接口页即可动手。[设计文档按模块重组](设计文档按模块重组.md)解决文档侧；本专题补代码与工具侧的缺口：模块入口、平台与 SDK 的通信契约、测试映射、智能体操作目录、大文件与死代码、九问实例启动，最后用阅读预算门槛防止回退。v0.0.138.16 已完成两项：根目录 `.ignore` 让默认搜索排除历史备份、vendor 与旧变更详情；`tools/reading_budget.py` 度量改一个模块的必读字数，基准存于 `temp/reading-budget/2026-11-09-重组中途.json`。

各票只做行为不变的收拢，不实现后续需求（MCP、悬赏中心、在线升级、资源池等）；需要改不变量时先交 design。票据跨多个模块，所以集中在本页；执行中发现只属某一模块的后续工作，登记到该模块 `进展/`。全部票据在重组收口票 10 完成后才开始；两个 AI 默认串行，领票先把状态改为 claimed 并注明执行者，完成后在本表标“完成 vX.Y.Z.N”。

引用写法：“重组10”指重组专题的票；“平台07”“客户端01”指 `组件/平台/进展/`、`组件/客户端/进展/` 的票，以票名为准（括号内为登记时的名称，编号可能在重组收口时调整）。

- [ ] 运行 `tools/reading_budget.py --json .agents/data/reading-budget/<日期>-重组收口.json`；客户端各子模块已有依赖页，依赖接口计入

## 03a：定入口规则

**目标行为：** 模块文件夹格式对“入口文件”有可检查的单一规则，读入口即知全部公开名。
**范围：** [模块文件夹格式](../../../.agents/skills/design/references/module-format.md)、`tools/check_modules.py`；按 design-it-twice 比较方案。现状：平台各中心实现页登记 3—9 个入口文件，大多数 `__init__.py` 只有 1—6 行。

- [ ] 包形态模块（各中心、SDK 子包、宿主适配等）只以 `__init__.py` 为入口，公开名在其中导出
- [ ] 散文件模块（平台基础、web服务 的 `app.py`、`operations.py` 等）二选一并写入格式页：迁入包目录，或保留按文件入口并限定入口数；给出迁移成本（导入点、测试、构建清单）后再定
- [ ] `check_modules.py` 增加入口数上限或单入口核对，先对已收敛模块生效，未收敛模块列为待办而不判失败

## 03b、03c、03d：按模块收敛入口

**目标行为：** 每个模块外部只经 03a 规定的入口导入；实现页入口表与代码一致；行为不变。
**范围：** 03b 平台九个子模块；03c 共用运行时、个人助手端、服务方端、宿主适配；03d 官方服务、管理员助手、在线试用、部署。每票内部按模块逐个提交亦可。
**定向测试：** 各模块接口页测试列；收尾跑 `check.py --layer fast`。

- [ ] 入口导出公开名，外部导入改为经入口；入口内不放业务逻辑
- [ ] 实现页“入口”表收缩，“内部分区”表随之更新
- [ ] `check_modules.py` 对本组模块开启 03a 的严格核对且通过

## 04：通信契约单一来源

**目标行为：** 参与方控制报文种类（如 `admission.*`、`delivery.*`、`payment.notify`）、系统消息种类与错误码只在接口页的表中定义一次；平台的分派表与 SDK 的发送方各有一个测试解析该表并核对，两端不互相导入。现状：两端各写字符串字面量，平台04（接单释放控制操作与接口文档一致）就是这样产生的不一致。
**范围：** web服务 接口子页“WebSocket与消息封套”、共用运行时接口子页“A2C适配”；平台分派表（平台07 完成后在 web服务 应用层）；SDK `adapters/`。

- [ ] 契约表列种类、方向、发送方、处理方模块、错误码；表格可被测试解析
- [ ] 平台测试：分派表的键集合等于表中“平台处理”的种类
- [ ] SDK 测试：发送方使用的种类集合是表的子集，SDK 处理的错误码在表中
- [ ] 新增或删除种类只需改表与实现，测试即提示另一端

## 05：测试映射单一来源

**目标行为：** “改某模块跑哪些测试”只由该模块接口页的测试列决定。现状写在三处：路由表的定向测试列、`tools/check_scope.py` 的 FILE_RULES 与 RULES、接口页测试列。
**范围：** `tools/check_scope.py`、`.agents/skills/develop/scripts/check.py`、路由表、testing 技能。

- [ ] `check_scope.py` 对模块代码目录从 `check_modules.MODULES` 与接口页测试列推导测试；FILE_RULES 只留不属于模块的文件（tools、tests 支撑件等）

## 06：智能体操作目录

**目标行为：** 智能体可调用的全部操作在共用运行时的一张声明表中，每条含名称、输入结构、效果类别、是否需要用户确认、可能的结果状态与处理器；常驻运行时的固定操作和两角色的处理表都从这张表注册；对外行为与命令不变。现状：约 45 个操作分散在 `runtime/resident.py` 的 `call` 分支、`assistant/role.py` 与服务方角色的处理表中，参数与下一步只写在产品技能文字里。
**范围：** 共用运行时、个人助手端、服务方端；产品技能只核对不改写。

- [ ] 声明表与注册方式；处理器签名不变
- [ ] 测试：产品技能 references 中出现的每个操作名都在目录中，目录中每个对智能体开放的操作都在技能中出现
- [ ] 不新增公开操作（如列出目录的接口）；那属于后续需求
