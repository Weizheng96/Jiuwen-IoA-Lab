# 设备会话开发说明

本次依据设计 v0.0.152。唯一规范见[账号与登录](../../组件/客户端/共用运行时/接口/账号与登录.md)和[身份中心设备会话](../../组件/平台/身份中心/接口.md#设备会话)。代码未提交，既有 8750 服务未更新。

## 使用路径

1. 用户通过原本机受控账号页登录或注册。程序保存稳定设备安装 ID；密码用于这次认证，不作为长期配置。
2. 平台返回 15 分钟访问令牌和 30 天绝对期限的设备续期凭据。SDK 自动轮换，丢响应恢复同一 operationId，不重新登录或赠币。
3. 本地 stdio MCP 仍由宿主启动，复用 ClientOperations → IPC → SDK；平台 HTTP 和业务 WebSocket 绑定同一设备会话。浏览器本机 Cookie/CSRF 和 IPC 密钥各自独立，MCP 配置不含平台凭据。
4. 受控账号页可查看设备、撤销其他设备或退出当前设备。先安全停止原客户端；网络结果未知则“恢复上次未核实的撤销”。会话失效需输入密码重新登录；身份、私钥、合同、业务库和原请求保持原位置。
5. 自动生成的注册密码可一次取回并自行保存，也可明确清除；尚未领取的值作为加密临时记录保留，不用于自动重登。新版本手输密码不会提供长期查看；旧已完成注册记录无生成标志，迁移后也提供一次取回，避免升级后无法自行保存原密码。

## 存储和部署前提

keyring 安全后端只保存加密主密钥；credentials.enc 保存绑定原绝对目录、平台与账号的加密会话，原子替换并以 credentials.lock 串行轮换。account.sqlite 仅存公开摘要、设备 ID、不可变归属和操作绑定。密钥丢失/系统凭据库未解锁/密文损坏时原地报错，不能删除密文后“重试”。移动整个账号目录需明确迁移，不能复制 credential_ref 当成新设备。

桌面端需要运行用户可用的 macOS Keychain、Windows Credential Locker 或 Linux Secret Service/KWallet。无人值守 Linux 可由服务管理者显式配置受管凭据目录：CREDENTIALS_DIRECTORY/ioalab-vault-key 是 Fernet 的 URL-safe Base64 编码 32 字节随机主密钥，必须由运行用户独占读取、普通文件，位于客户端数据目录外；应通过 systemd LoadCredential 等现有管理机制提供。它属于管理员提供的凭据，不写入普通客户端 JSON 或 MCP 参数，也不由 SDK 自动创建普通密钥文件。官方协调器只转发该目录引用及系统凭据库会话环境，不回显密钥。本次不替用户配置系统服务；升级无人值守实例前必须先准备此依赖，启动前置登录会在缺失时明确失败。

私有加密记录与独立主密钥都需按原运维归属备份；部署备份仅有客户端数据不能恢复设备授权。旧 password/password_env 配置在显式登录或启动时迁移：取得原 client.lock，验证系统存储和真实账号，保存加密会话，然后原子写 credential_ref、清理原账号库凭据。失败保留原配置与未决操作；用户自己的备份不自动删除。旧平台 SDK Token 和旧连接票据不能继续取得新授权，升级需同时安装新版平台和 SDK。旧版未决登录以原 operationId、密码和输入绑定一次性转成设备会话，保留原赠币结果；已经加载旧配置的 SDK 调用方须从原文件重新加载迁移后的配置，再重启实例。

## 实现位置

| 位置 | 责任 |
|---|---|
| platform/identity/devices.py、sessions.py | 设备授权、会话状态、密码摘要绑定、轮换与撤销幂等 |
| platform/web/api_v1.py、agents.py | HTTP 认证与设备管理、票据绑定、连接撤销通知和至多 1 秒轮询 |
| sdk/runtime/credentials.py、session.py | 本机加密记录、系统主密钥、认证恢复、串行续期与退出回执恢复 |
| sdk/runtime/authentication.py、config.py | 旧配置验证和迁移、credential_ref 绑定检查 |
| sdk/runtime/onboarding.py、web/identity/setup.html | 用户专用账号与设备管理、程序生成密码一次取回 |

维护接入包约束时使用原 `tools/build_access_skills.py --update-lock`；开发聚合 requirements.txt 同时安装 keyring 三个平台后端的元数据依赖，锁生成会覆盖这些条件依赖。Linux 部署锁由原 `python -m tools.lock_deployment` 从新 wheel 元数据生成。新增凭据依赖使参与方版本表为70项，SDK及部署安装标识上限同步为128，仍核全部版本及32KiB文件上限。
