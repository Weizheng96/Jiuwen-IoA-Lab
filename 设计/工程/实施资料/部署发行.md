# Windows 本机与 Linux 远程部署

## 目的与范围

> 实施资料（非规范）：以下为实际操作入口；规则见[部署](../部署.md)和[安装与升级](../安装与升级.md)，验证范围见[开发计划](开发计划.md)。

两条路径使用同一套平台、SDK 和接入技能，区别在安装与进程管理。Windows 路径启动本机核心和网页，完整托管编排使用 WSL／Linux；Linux 服务器路径由默认安装器托管核心、官方服务和管理员助手。

在线试用另行准备，单席／三席只指试用容量，不限制正式平台账号或 SDK 连接数量；核心启动也不代表试用已开放。

## 1. Windows 本机部署

前提：Windows x86_64、CPython **3.11**、完整本仓（含 `vendor/`），可访问普通 Python 包镜像。以下在 **PowerShell、仓库根目录**运行。`D:\ioa-env` 和 `D:\ioa-data` 为示例专属目录；首次选择新目录，运行环境路径保持简短。

### 构建发行并安装核心

```powershell
py -3.11 -m venv temp\deployment-build
$BuildPython = (Resolve-Path temp\deployment-build\Scripts\python.exe).Path
& $BuildPython -m pip install --index-url https://pypi.tuna.tsinghua.edu.cn/simple -r deploy\locks\build.lock
& $BuildPython -m tools.build_deployment --target windows-x86_64 --out dist\windows | Tee-Object temp\deployment-build.log
if ($LASTEXITCODE -ne 0) { throw '发行构建失败，请检查上方输出' }
$Release = (Get-Content temp\deployment-build.log -Tail 1).Trim()
& $BuildPython -m deploy.environment --release $Release --unit core --root D:\ioa-env | Tee-Object temp\core-install.log
if ($LASTEXITCODE -ne 0) { throw '安装失败，请保留原目录和日志' }
$CorePython = (Get-Content temp\core-install.log -Tail 1 | ConvertFrom-Json).python
```

构建器核对来源、依赖锁和摘要，生成包含 wheel、种子和两份接入技能 ZIP 的发行目录；安装器最后一行 JSON 返回核验后的解释器路径，前面的进度保留在日志中。普通包走镜像，本地 wheel 按摘要安装，无需安装根开发依赖或现场访问 GitHub。

### 配置并启动

```powershell
$env:IOALAB_MODE = 'trial'
$env:IOALAB_BIND = '127.0.0.1'
$env:IOALAB_PORT = '8750'
$env:IOALAB_PUBLIC_URL = 'http://127.0.0.1:8750'
$env:IOALAB_DATA = 'D:\ioa-data\core'
$env:IOALAB_SEED_FILE = Join-Path $Release 'seed.json'
$env:IOALAB_BUNDLES_DIR = Join-Path $Release 'skills'
$env:IOALAB_ADMIN_PASSWORD = [Net.NetworkCredential]::new('', (Read-Host '设置至少12位管理员口令' -AsSecureString)).Password
& $CorePython -m ioalab check-config
if ($LASTEXITCODE -ne 0) { throw '请先修正配置' }
& $CorePython -m ioalab init
if ($LASTEXITCODE -ne 0) { throw '初始化未完成，请保留现场' }
& $CorePython -m ioalab serve
```

保持窗口运行，浏览器打开 `http://127.0.0.1:8750/`，管理员页为 `/admin`。公共地址首次初始化后保持不变；需其他机器接入时，先确定可达地址再初始化。

默认未配置模型密钥，核心使用确定性检索。需要模型发现时，在启动前安全输入密钥，并按[核心配置模板](../../../deploy/ioalab.env.example)填写端点和模型名：

```powershell
$env:IOALAB_LLM_API_KEY = [Net.NetworkCredential]::new('', (Read-Host '模型API key' -AsSecureString)).Password
```

环境变量仅对当前窗口生效；重开窗口需设置同一组配置。密钥和口令不写入命令历史、仓库或发行包。官方服务生产模型由参与方九问独立配置，核心不会代其生产。

### 查看、停止和重启

另开 PowerShell 查看网页是否响应和最近日志：

```powershell
Invoke-RestMethod http://127.0.0.1:8750/api/config
Get-Content D:\ioa-data\core\logs\ioalab.log -Tail 30
```

在运行 `serve` 的窗口按 **Ctrl+C**，等待正常退出；再次运行 `& $CorePython -m ioalab serve` 即可重启。更新时重新构建、安装并采用安装器返回的新解释器，保持原公共地址、数据和配置。不要用 `reset`、删库或换空目录代替升级。

此路径提供 Windows 原生核心网页；官方服务、管理员助手的完整托管编排目前使用下面的 Linux/systemd 入口。个人助手和服务方按[接入技能说明](../../../src/access/skills/README.md)接入。

## 2. Linux 服务器远程部署

前提：Linux **x86_64**、CPython **3.11**、systemd、统一 cgroup v2、sudo 权限和可用包镜像。准备一个可从服务器及参与方访问的 HTTPS 公共入口，反代至 `127.0.0.1:8750` 并支持 WebSocket；参考 [nginx.conf](../../../deploy/nginx.conf)。

### 本地：打包、上传、登录

在本机仓库根目录的 PowerShell 执行，把 SSH 目标换成自己的服务器：

```powershell
$Server = 'deployuser@server.example.com'
$Revision = (git rev-parse --short HEAD).Trim()
$Archive = "ioalab-$Revision.tgz"
New-Item -ItemType Directory -Force temp | Out-Null
git archive --format=tar.gz --output="temp/$Archive" HEAD
scp "temp/$Archive" "${Server}:~/"
ssh $Server
```

上传 **HEAD 已提交快照**，不夹带未跟踪的本机配置、数据和密钥；先提交并验证需要部署的内容。SSH 使用已有认证方式，不上传私钥或模型配置目录。

### 服务器：解包并填写首次配置

以下在 **SSH 登录后的 Bash** 执行，把 `<commit>` 换成上一步的 `$Revision`：

```bash
set -e
REV='<commit>'
mkdir -p "$HOME/ioalab-$REV"
tar -xzf "$HOME/ioalab-$REV.tgz" -C "$HOME/ioalab-$REV"
cd "$HOME/ioalab-$REV"
python3.11 --version
sudo install -d -m 700 /etc/ioalab-bootstrap
sudo test -e /etc/ioalab-bootstrap/deployment.json || sudo install -m 600 deploy/deployment.json.example /etc/ioalab-bootstrap/deployment.json
sudoedit /etc/ioalab-bootstrap/deployment.json
```

填写 `public_url`、`model.name`、`model.base_url`、`model.api_key`；管理员口令可留空由安装器生成并私存。JSON 只留服务器，权限 `600`；升级继续使用原文件，不覆盖人工配置。源码、运行根、状态根和配置根必须互不嵌套。

### 服务器：安装并查看

```bash
sudo bash deploy/install.sh --config /etc/ioalab-bootstrap/deployment.json
sudo python3.11 -m deploy status --state /var/lib/ioalab
```

安装由独立 systemd 任务执行，不随 SSH 断开而终止。重复运行 `status`，等其中的 `task` 完成并核对各服务的实际就绪结果，再检查网页：

```bash
sudo journalctl -u ioalab-core.service -n 30 --no-pager
curl --fail http://127.0.0.1:8750/api/config
```

默认运行根 `/opt/ioalab-runtime`、状态根 `/var/lib/ioalab`、配置根 `/etc/ioalab`。重新登录后回原源码目录观察原任务，不重复发起安装。浏览器访问 `public_url`，管理员页为 `/admin`。

管理员九问网页默认只监听回环。在本地另开终端建立隧道，打开 `http://127.0.0.1:18753/?user_id=ioa-admin`：

```powershell
ssh -N -L 18753:127.0.0.1:18753 $Server
```

隧道采用默认网页端口；改过 `swarm_ports` 时使用实际值。通知邮箱未配置时会议接口保持禁用。

### 服务器：正常停启与升级

```bash
units=(ioalab-core ioalab-swarm-agent ioalab-swarm-gateway ioalab-swarm-web ioalab-official ioalab-admin-assistant)
sudo systemctl stop "${units[@]}"
```

以上停止默认完整部署，等待所有服务正常退出；需要启动时在同一 Bash 会话执行：

```bash
sudo systemctl start "${units[@]}"
```

systemd 按依赖处理顺序。尚未排空或任务状态未知时，不强杀、不切换环境。

升级时上传新的已提交快照，解包到新的提交目录，进入该目录执行：

```bash
sudo bash deploy/upgrade.sh --config /etc/ioalab-bootstrap/deployment.json
sudo python3.11 -m deploy status --state /var/lib/ioalab
```

升级入口处理候选、排空、备份和切换；保留账号、身份、合同、付款、工作区与原配置。不在运行目录执行 `git pull`，不删除旧数据来消除失败。

## 可选在线试用与验证范围

在线试用是核心外的独立应用。先按[试用部署](../../../deploy/trial/README.md)准备镜像、Linux 控制器环境、受限配置和两个独立 HTTPS 入口，再选择启动方式。

Windows 在仓库根目录的 PowerShell 执行，`IoA-Trial` 替换为实际 WSL 2 发行版名；`--python` 和 `--config` 都是该发行版内的绝对路径，JSON 填 `deployment_profile: windows-wsl`：

```powershell
py -3.11 deploy/trial/start_windows.py --distribution IoA-Trial --python /opt/ioalab-trial-controller/bin/python --config /etc/ioalab-trial/config.json
```

Linux 服务器在 Bash 执行，JSON 填 `deployment_profile: linux-server`：

```bash
/opt/ioalab-trial-controller/bin/ioalab-trial --config /etc/ioalab-trial/config.json
```

Windows 当前固定一席、Linux 服务器固定三席，使用相同协调器与生命周期；具体边界以[在线试用](../在线试用.md)为准。配置 profile 必须与实际环境相符，WSL 不能冒充 Linux 服务器档位。原版网页、可信确认和整轮清理未完成专项验收时，试用仍不开放。

Linux 默认 systemd 整体验收仍须独立记录，不能由 Windows 或构建检查通过推出。已有证据见[生产发行核验](../../../deploy/verification/production-release.json)和[Linux 独立安装](../../../deploy/verification/linux-installed-release.json)。
