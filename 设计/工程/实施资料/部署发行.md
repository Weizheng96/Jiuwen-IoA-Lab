# Windows 本机与 Linux 远程部署

## 目的与范围

> 实施资料（非规范）：命令对应当前源码；配置规则见[平台配置](../平台配置.md)，验收状态见[开发计划](开发计划.md)。

两种部署使用同一平台、SDK与原版九问。Windows是持久保存数据的可信本机部署，不依赖Docker/WSL；Linux使用独立系统账号和systemd。Linux三席在线试用是另一个核心外应用，不等于普通平台注册人数限制。

平台参数只编辑一个私有platform.json，安装JSON只引用路径并选择组件。新部署管理员为admin/admin1234；初始虚拟币500，登录100，同账号北京时间每天默认只领取一次。“管理者全景→平台配置”可热改限流及赠币；账号、模型、地址等需停机修改后重启。密钥、密码和运行数据不进Git或发行包。

## 1. Windows 本机部署

前提：Windows x86_64、CPython 3.11、包含vendor的完整仓库。以下在仓库根目录PowerShell执行。D:\ioa-local为专用本机实例，D:\ioa-env保存运行环境；已有实例保留原目录，不用清空数据代替恢复或升级。

### 构建发行

```powershell
py -3.11 -m venv temp\deployment-build
$BuildPython = (Resolve-Path temp\deployment-build\Scripts\python.exe).Path
& $BuildPython -m pip install --index-url https://pypi.tuna.tsinghua.edu.cn/simple -r deploy\locks\build.lock
& $BuildPython -m tools.build_deployment --target windows-x86_64 --out dist\windows | Tee-Object temp\deployment-build.log
if ($LASTEXITCODE -ne 0) { throw '发行构建失败' }
$Release = (Get-Content temp\deployment-build.log -Tail 1).Trim()
$Assets = Join-Path 'D:\ioa-local\runtime\envs\releases' (Split-Path $Release -Leaf)
```

构建器核来源与摘要，打包核心、参与方、原版九问、种子和产品Skill；普通Python包可走国内镜像。

### 配置并安装

```powershell
& $BuildPython -m deploy.configure --root D:\ioa-local\runtime --state D:\ioa-local\data --config-dir D:\ioa-local\config --assets $Assets
if ($LASTEXITCODE -ne 0) { throw '配置创建失败，请保留原目录' }
notepad D:\ioa-local\config\core\platform.json
```

填写llm.api_key、base_url及model，其他平台模型按需要填写。本机runtime.public_url保持http://127.0.0.1:8750，监听保持回环。配置父目录和文件受限，不另设逐字段环境变量。

```powershell
$Install = @{ platform_config='D:\ioa-local\config\core\platform.json'; pypi_index='https://pypi.tuna.tsinghua.edu.cn/simple'; max_model_runs=2 }
$Install | ConvertTo-Json -Depth 8 | Set-Content -Encoding utf8 D:\ioa-installation.json
& $BuildPython -m deploy.windows_local install --home D:\ioa-local --release $Release --environments D:\ioa-env --config D:\ioa-installation.json
& $BuildPython -m deploy.windows_local start --home D:\ioa-local
& $BuildPython -m deploy.windows_local status --home D:\ioa-local
```

安装三套独立venv，通过普通公开入口准备官方服务与管理员助手。浏览器访问http://127.0.0.1:8750/，原版九问默认http://127.0.0.1:18753/?user_id=ioa-admin。网页或SDK ready只证明对应探针；产品Skill、原生聊天、可信确认和完整停启分别验收。

### 正常停启

```powershell
& $BuildPython -m deploy.windows_local stop --home D:\ioa-local
& $BuildPython -m deploy.windows_local status --home D:\ioa-local
& $BuildPython -m deploy.windows_local start --home D:\ioa-local
```

先排空SDK再退出所属进程，保留账号、合同、付款和工作区。状态未知或旧Job不可确认时保留原记录，不按进程名批量强杀。本机入口不自动执行发行升级；换版本前核原实例恢复及明确迁移方案。

## 2. Linux 服务器远程部署

前提：Linux x86_64、CPython 3.11、systemd、cgroup v2、sudo和可用包镜像。公共入口可以是公网IP；HTTPS须先准备实际可用证书。公共URL首次初始化后保持不变。

### 直连服务器，从GitCode取已发布代码

```powershell
ssh -o ProxyCommand=none -o ProxyJump=none root@SERVER_IP
```

服务器Bash中执行，COMMIT换成已验证且已同步GitCode的完整提交：

```bash
set -e
COMMIT='<validated-commit>'
git -c http.proxy= -c https.proxy= clone https://gitcode.com/WeiZheng96/jiuwen-IoA-lab.git ioalab-source
cd ioalab-source
git checkout --detach "$COMMIT"
python3.11 --version
sudo python3.11 -m deploy.configure
sudoedit /etc/ioalab/core/platform.json
```

填写runtime.public_url为实际入口，例如https://SERVER_IP；模型填写同Windows。使用[反代模板](../../../deploy/nginx.conf)时，authentication.trusted_proxy_addresses设为["127.0.0.2"]；Nginx必须proxy_bind该独立源地址并覆盖X-IOALAB-Client-IP。核心关闭Uvicorn自动代理头处理，不能用可伪造XFF判断本机；反代与伪头须实测。

```bash
sudo install -d -m 700 /etc/ioalab-bootstrap
sudo install -m 600 deploy/deployment.json.example /etc/ioalab-bootstrap/deployment.json
sudoedit /etc/ioalab-bootstrap/deployment.json
sudo bash deploy/install.sh --config /etc/ioalab-bootstrap/deployment.json
sudo python3.11 -m deploy status --state /var/lib/ioalab
```

安装JSON只引用/etc/ioalab/core/platform.json，其他选项见[安装说明](../安装与升级.md)。独立systemd安装任务不随SSH断开退出。重复status观察原任务，核各服务实际就绪；失败保留原任务、日志和目录。GitHub更新先在开发端用[gitcode-sync技能](../../../.agents/skills/gitcode-sync/SKILL.md)同步，再从GitCode取固定提交。

### 访问与日志

```bash
curl --fail http://127.0.0.1:8750/api/config
sudo journalctl -u ioalab-core.service -n 30 --no-pager
```

浏览器访问配置的公网IP入口，管理员页为/admin。管理员九问只监听回环，本地另开终端转发：

```powershell
ssh -o ProxyCommand=none -o ProxyJump=none -N -L 18753:127.0.0.1:18753 root@SERVER_IP
```

打开http://127.0.0.1:18753/?user_id=ioa-admin。未配置通知邮箱时会议接口保持禁用。

### 升级与旧配置导入

在新的已验证源码目录执行，继续引用原platform.json及三根，不覆盖人工配置：

```bash
sudo bash deploy/upgrade.sh --config /etc/ioalab-bootstrap/deployment.json
sudo python3.11 -m deploy status --state /var/lib/ioalab
```

旧core.env部署先完成原安装，再显式一次性导入：

```bash
sudo python3.11 -m deploy.migrate_configuration --state /var/lib/ioalab
```

按回执将安装JSON改为platform_config引用后执行upgrade。导入保留原core.env与initial.before-platform-config.json，新启动不回退读取；原密码、模型、密钥及业务记录保持。升级处理排空、备份与切换，不用删库、改公共URL或强改source/input绑定绕过恢复门槛。
