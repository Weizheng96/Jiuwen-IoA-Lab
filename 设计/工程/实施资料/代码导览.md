## 当前接入链路

| 活动 | 阅读路径 |
|---|---|
| 产品技能启动 | `src/access/skills/assistant/` 或 `provider/` → `_shared/ioalab.py` → 已安装 SDK/九问适配 CLI；安装归 `_shared/installer.py`，两角色共用本机实例 |
| 常驻执行 | `ioalab_sdk/runtime/resident.py` 装配账号、身份、调度与角色；`ipc.py` 提供本机认证调用，`connection.py` 维持 WS 和可靠收发；SDK不直接导入宿主和业务工具实现 |
| 委托发起 | 产品技能流程 → `assistant/delegation.py`、`trading.py`、`contracts.py`、`fulfillment.py` → 锁定 A2C/AP2；委托、合同、环节、验收与付款分别核真实授权 |
| 服务发布与履约 | `provider/publication.py` 中 ProviderRole 与同目录执行模块；真实确认后公示，统一运行时处理接单、生产和恢复 |
| 收信设置与交流 | `assistant/rules.py`、`role.py` → 共用运行时 → 平台 `messaging/`；入站上下文绑定已确认规则、实际请求和明确允许的工具 |
| 九问宿主 | `src/hosts/jiuwen/ioalab_jiuwen/process.py` 的 ProcessHost 调用原版公开接口；`skills.py` 读取业务技能，`tools.py` 装配明确选中的工具工厂；网页通知归宿主 `web_setup.py`、`web_notifications.py` |
| 日程与邀请 | `src/official/tools/ioalab_tools/` 的可选工具工厂；业务安排和外部回执留在本地，SDK持有操作键及检查点，未知效果先查原回执 |
| 安全停止与账号恢复 | `runtime/authentication.py`、`session.py` 和 ResidentRuntime 的排空流程；身份、合同和原操作不因重启重建 |

## 平台请求、事实与观察

| 活动 | 阅读路径 |
|---|---|
| 装配 | `src/platform/ioalab/__main__.py` → `app.py` → 各组件；`storage.py` 提供连接/短事务，核心只装配公共服务，不执行私人助手或服务生产 |
| 应用用例 | `operations.py` 的 AccountOperations、LedgerOperations、DiscoveryOperations、ServiceOperations，以及付款/市场协调；Web与种子初始化调用其明确入口，不再调用旧Platform业务别名 |
| 服务发现 | `registry/discovery.py`、`taxonomy.py`、`models.py`；只读检索与公共可用性组合由 DiscoveryOperations 协调，不预留接单容量 |
| A2C 公共服务 | `delegation/service.py` 的 MarketService 包装原协议，`market.py` 适配接单要求；验收包归 `delegation/packages.py`，仲裁观察模型归 `delegation/models.py` |
| 案件与独立复核 | `delegation/arbitration_evidence.py` 只取原事实，`arbitration_cases.py` 持有申请、文书和回执，`arbitration_review.py` 决定独立复核政策；`web/arbitrations.py` 提供管理员入口；SDK共用历史核验在 `adapters/arbitration.py`，完整角色体验另列开发计划 |
| 可靠投递与活动事件 | `Platform.delivery` 装配 `messaging/delivery.py`，在原操作事务内记录真实投递与 `EventBus.record_in`，提交后仅 publish；重放查询原回执，不二次生成事件或业务 |
| 公开接口目录 | `messaging/interfaces.py` 持有当前声明/版本/ACL，`schema.py` 共用冻结校验；`InterfaceDirectory` 仅授权读取本人或对方公开声明。HTTP保留目录GET，实际发布与可靠投递走当前SDK入口，旧轮询队列不参与 |
| 管理统计 | `observation/overview.py` 的 OverviewQueries 显式接收当前组件；`/api/admin/stats` 与组件查询读取它，Platform不保留统计转发方法 |
| 工作台与合同展示 | `observation/` 构建可重建、经过验签和权限裁剪的投影；`web/workbench.py` 与 `/api/orders` 读取该投影。旧客户端 `POST /observations` 和旧v1订单接口不再参与当前显示 |
| 页面与网络 | `web/static/index.js`、`network.js` 展示本人网络；`panorama.js` 展示管理员事实；共用 `network-map.js/css`。`tools/check_panorama.py`、`check_workbench.py` 是离线界面验证入口 |

## 部署与官方参与方

发行构建从 `tools/build_deployment.py` 进入 `deploy/release.py`、`environment.py`。默认安装/升级使用 `deploy/install.sh`、`upgrade.sh` → `deploy.__main__` → 独立安装任务 `jobs.py` → `installation.py`，其配置、单位、备份和激活各调用所属模块。实际命令和环境边界见[部署发行](部署发行.md)，Linux/systemd实机验收仍属第七阶段。

官方领域与验收资源只有 `ioalab_services.catalog` 一个来源；`profiles.py` 构造配置，`preparation.py`、`authorization.py`、`coordinator.py` 处理准备、受限授权、运行和续期。管理员助手预设由 `src/official/admin-assistant/ioalab_admin_assistant/` 准备，运行仍使用同一 SDK/九问适配，不另建收件器。原版九问与固定第三方输入的来源、摘要和许可见 [vendor](../../../vendor/README.md)。

核心CLI保留显式全量 `reset`、`--keep-keys` 和 `backup`，均先取得 DataOwner 排他锁；旧 `--keep-accounts` 部分删除协议证据的路径已退出。整理和检查不执行真实数据重置。

## Demo 与退出入口

当前三段视频及媒体工具见 [Demo 入口](../../../demo/README.md)。七家固定候选的定义在 `demo/delegation-provider/src/scenario/definitions.py`；预约运行器在 `demo/delegation-assistant/src/booking_app.py`。业务素材不反向进入通用 SDK 或官方领域；已经发布的视频、剧本和证据保持原事实。

旧HTTP执行器、轮询收件器、旧技能编排及配套旧录制/自动业务驱动按调用链整组退出，源码仅在[历史备份](../../../历史备份/README.md)追溯。当前代码、构建和测试不得从历史目录导入它们。必要的协议、签名、授权、付款、事务及生命周期断言迁到现行公开链路；媒体完整性和原证据校验继续保留。
