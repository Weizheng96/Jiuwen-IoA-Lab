# 安装与升级

## 目的与范围

职责：定义Linux受管部署和Windows可信本机体验的私有输入、目录所有权、启动停止、升级与失败恢复。发行和依赖边界见[部署](部署.md)，业务实例见[官方实例](官方实例.md)。普通用户已有九问不由本安装器接管。

## Windows可信本机体验

复用windows-x86_64受审内容发行和现有独立环境安装器，核core、participant、swarm实际身份、依赖锁及原版依赖摘要；开发venv或同名版本不能代替此核验。最少前提及业务边界见[部署](部署.md)，实际命令只在[部署发行](实施资料/部署发行.md)维护。

本机装配归deploy.windows_local，只调用现有发行、环境、SDK及原版公开入口，不承载业务状态或轮次销毁。

启动装配读取明确的本机私有输入，核原部署标识、持久目录及端口归属后，依序启动核心、原版公开Web/Process入口及所属SDK。程序只接管自己创建并能核PID、创建时间、运行身份和安装来源的进程；不按通用进程名杀进程，不占用或停止未知现有服务。组件使用各自持久工作目录及明确回环地址；端口冲突或依赖缺失明确失败，不自动漂移、不改原版源码或宿主全局配置。已有工作区、模型配置、身份及业务状态复用原所属配置，不反复初始化、登录赠币或重放授权。

停止先经原SDK的runtime.stop及bootId核对请求排空，保留原操作、合同、付款与未知结果，再通过经核实的原版公开关闭入口及本启动器确证所属的Windows进程控制处理网页、Front与Worker。分别核全部所属写入者和真实OS锁释放，才能报告已停止；仅父PID退出不代表Worker结束。Popen.terminate/TerminateProcess或强制终止不作为正常停机证据；公开关闭未支持、归属不明或仍有执行时报告未完成并保留数据，不补调用私有关闭函数伪装支持。

本机关闭、重启及升级均不执行trial reset、轮次销毁或清空历史。身份私钥、确认、会话、合同原件、账本、取件、操作恢复记录、人工配置与日志保留在原持久目录；再次启动沿原引用恢复，不创建试用身份来替代用户账号。升级候选沿同一发行校验，先排空和备份再切换，未核释放或新实例可能已有业务时不原地覆盖或自动回退数据。Windows正常关闭及真实业务需分别实测，静态适配声明不代表通过。

## Linux受管入口与前置条件

以下各节定义Linux受管安装；Windows启动装配遵守上节，并复用其中的发行校验及组件公开契约，不引入systemd依赖。

| 入口 | 行为 |
|---|---|
| deploy/install.sh --config <JSON> | 从显式本地源码准备发行、三个运行环境及官方实例，启动后核验实际就绪 |
| deploy/upgrade.sh --config <同一初始JSON> | 从已同步的本地源码生成候选，排空、备份、切换及核验；不执行Git更新 |
| python -m deploy status --state <目录> | 读取本部署及服务的真实状态，不安装、启动或修改业务 |

以下受管安装默认运行根为/opt/ioalab-runtime，状态根为/var/lib/ioalab，配置根为/etc/ioalab；可用--root、--state、--config-dir显式选择。三根与源码目录互不嵌套。入口使用CPython3.11、systemd及统一cgroup v2，Linux首批目标为x86_64；Windows本机入口按上节独立装配进程，不能冒充systemd部署成功。

部署者预先同步完整本仓，可通过GitCode或目录复制；安装器不拉取Git、不使用子模块，也不复制整棵开发工作区。普通包走配置的HTTPS镜像，构建只用固定的独立build环境，运行不使用根requirements或editable包。源码、构建、发行、运行环境与持久状态分别定位。

## 安装任务与模块边界

安装/升级由本部署记录的独立systemd临时service执行；前台命令只提交或观察原任务，SSH断开或观察结束不终止安装，也不启动第二写入者。原操作保存输入/源码摘要、单位及实际控制组；同一操作仍在执行时只查询。进程状态未知、原控制组仍有活进程或部署OS锁不可取得时禁止重启安装；实际终止且组已空后才允许继续原阶段。失败保留原环境、操作和日志，不通过清理状态制造新任务。

| 模块 | 唯一职责 |
|---|---|
| deploy.__main__ | 命令解析、发起/观察原任务及脱敏状态 |
| deploy.installation | 固定安装/升级阶段及原操作记录；复用发行、环境、工作区与激活模块 |
| deploy.jobs | 本部署安装临时service的发起、原任务观察及原阶段续接 |
| deploy.linux | 系统账号、角色目录/配置权限、systemd状态及内核控制组的窄操作 |
| deploy.units | 从已安装包入口确定性生成业务单位，不运行协议或访问业务库 |
| deploy.configs | 首次配置及生成凭据；已完成后保留人工运行设置 |
| deploy.backup | 原写入者释放后的一致性备份及校验，不自动回退业务数据 |

状态只保存部署事实，不复制SDK调度、确认或A2C合同状态机。任务完成状态与实际进程组已空分别检查；日志、PID和状态JSON不能替代执行所有权证明。

## 安装输入与平台配置

安装输入保留运行根、状态根、配置根、包镜像与所选官方组件等部署意图；以platform_config字段引用唯一的[平台配置文件](平台配置.md)。平台地址、监听、模型、管理员和发币/认证参数不在安装输入或core.env再次定义。先验证同一文件及所有权，再使用组件公开接口装配；安装记录保存引用与原部署身份，不因一次合法动态修订便重放初始化或拒绝同一部署。

新部署采用[平台配置](平台配置.md)的默认管理凭据；已配置密码、模型和其他人工设置保留。已有环境变量/core.env部署须显式一次性导入受审新文件并切换启动引用，再移除旧执行入口；不自动猜测或运行两套参数源。迁移保存原文件与业务数据，不改账号、密钥、合同、付款及未知操作，不补造初始赠币。正式切换前验证同一配置与原公共URL，禁止改址伪装重装。

官方资源及管理员助手的持久工作区、通知、收信、原授权和模型设置仍属其组件，不因平台动态改限流/发币而重建；部署更新须显式处理其自有配置，不能把主平台文件变成跨参与方配置后门。

## 目录与权限

| 位置 | 所有者与内容 |
|---|---|
| 运行根 | root管理的builder、内容发行、不可变envs及环境集合；服务只读安装包，不读取源码 |
| 状态根/.deployment | root私有的部署标识、初始输入、凭据、原操作、服务/路径归属及备份索引 |
| 状态根/core、cache/core | ioalab-core拥有的核心数据库、机构密钥、日志与独立缓存 |
| 状态根/agents、cache/agents | ioalab-agents拥有的官方SDK、九问工作区、用户接口、预约/通知回执及独立缓存 |
| 配置根/core | 核心账号独占的配置叶目录及唯一平台JSON，文件与临时文件受限且支持原子热写；上级配置根仍root管理，不授予agents或其他用户读取，不保留core.env执行链 |
| 配置根/agents | 各角色自己的环境与配置；服务协调器不接收管理员或助手通知凭据 |
| 状态根/backups | root私有一致性备份；不包含运行环境、发行物及可重建缓存 |

Linux受管部署的核心与参与方必须使用不同系统账号。不可变运行前缀及其非敏感安装元数据由root拥有，允许服务账号读取/执行且不可写；不能依赖调用者umask。部署私有记录、构建日志及含凭据配置不因此公开。公共父目录只允许必要的遍历，敏感叶目录及文件按所属方限制访问；不能通过把整个状态树交给agents来解决权限。初次工作区准备后只移交所属状态叶目录；后续公开九问查询以所属服务账号执行，不能在agents工作区生成root所有的数据库或配置。系统账号、三根和单位文件的归属在首次建立时记录；未知旧目录、冲突的账号用途、越界链接或非本部署单位拒绝接管。不提供旧布局兼容、空数据规避或自动删除。

## 初始化与启动

1. 先以排他创建的归属标识认领明确的新目录，再持有本部署实际OS锁；部分认领只继续同一标识，竞争不得覆盖对方。原所有者和完成证据存在时复用，不因PID/状态文件存在便认定完成。
2. 准备固定build环境、内容发行及core/participant/swarm环境，核各单元完整身份与真实导入；放行非敏感安装资源后，以core/agents的真实服务身份再次执行导入与安装身份检查，确认父路径可遍历，不改运行根之外的目录权限。失败保留原日志；未知安装不自动重建。
3. 生成首次核心、官方服务和管理员助手配置；通过原版公开接口初始化两个独立的官方/管理员九问工作区。已有完整配置与工作区只核归属，不重放模板。受管SDK启动前以自身账号调用同一显式登录入口，先复用有效缓存或恢复原登录，再处理确实失效的凭据；不删除账号库、身份或未知操作，也不以反复启动赠币规避错误。
4. 生成已安装包入口的systemd单位；启核心并核实际公共入口；内部账号和分类由显式种子输入初始化，SDK自己创建参与方密钥。
5. 按官方实例的prepare/authorize流程设置受审服务资产声明的必要账号与服务；只有短期初始授权进程取得管理员凭据，正常serve不继承，不在安装器另维护业务数量。
6. 在管理员网页进程启动前，准备ISC_001业务助手的原生通知扩展和固定预设，再移交所属状态目录。升级复用原准备回执及人工设置，不重装扩展或重新授权。
7. 启管理员原版AgentServer、Gateway和预构建网页，再以同一九问适配/SDK入口运行助手；使用原版模块及明确回环端口，不使用自动漂移端口或强杀子进程的外层启动器，不现场npm构建；通过原版JIUWENSWARM_CLI_PORTS=1保留注入端口，不被工作区.env中的旧端口覆盖。分别报告SDK连接、宿主、公示/索引、接口及通知能力；缺邮件时明确禁用会议预约，不能伪称邀请可用。

正常服务只调用安装包。原版网页与官方生产使用不同工作区；网页访问地址携带本部署固定的原生user_id，通知与网页归属一致。管理员网页只开放回环访问，部署者可通过受控本机或SSH通道使用；公开运维入口在相应后续设计中定义。

## 激活与升级

环境集合在envs/sets/<集合摘要>中引用三个已核验真实环境；集合摘要覆盖发行摘要和各实际安装身份/路径，不能只以发行摘要假定不同Python补丁环境相同。环境目标留在环境根内；集合另含release链接，固定原发行及其种子/接入包，目标仅能是本部署运行根releases中的原目录。服务通过current/release读取发行资源，不复制可漂移资源或为升级改写人工配置。current只指向一个完整集合，以一次符号链接替换激活，不能逐个切换造成混合环境。稳定命令与工作区路径不因包更新变化；SDK仍按真实安装前缀及完整身份核对。原版Python可以链接到系统解释器，环境前缀按bin/Scripts的父目录定位；不能沿二进制链接误读系统目录。

| 阶段 | 前提、结果与失败规则 |
|---|---|
| 候选 | 服务运行期间先核本地输入、构建并安装候选；完整后才进入停服，不原地修补旧环境 |
| 排空 | 停官方协调器和管理员SDK，使用原实例的停止入口/实际执行锁核释放；再停原版网页服务及核心。SDK独立serve将SIGTERM映射为同一排空意图；参与方SDK及核心使用mixed模式，管理员原版九问使用control-group模式向其Front/Worker发送SIGTERM（原版Front停止只断开Worker，不终结Worker）；全部禁用最终SIGKILL且不设置强制停止期限；原控制组cgroup.events的populated必须为0，且SDK实际执行锁可取得；残留执行或观察超时阻止备份/切换 |
| 备份 | 在写入者已释放后备份核心、参与方、九问工作区、配置及原操作；保存校验摘要及旧集合引用，含未知付款/通知等证据 |
| 切换 | 核对候选、旧集合及原升级记录，单次替换current，更新本部署单位；不改身份、合同、会话、接单开关或规则 |
| 重启 | 分别保存实际运行状态与开机启用设置；只恢复升级前实际运行的本部署单元，保持原开机设置，手动停止的单元不被重新启动；已有官方准备/授权和管理员预设复用，不重新赠币、公示授权或启用已撤销内容 |
| 中断与失败 | 原操作先保存再执行；重复命令查询实际阶段并继续原候选，不并发启动第二写入者。保留失败现场、旧环境及备份；不在新实例可能已有业务后自动回退数据或重放未知效果 |

升级不代表合同结清。无法安全接管的配置/业务变化先由所属方处理原合同；不新增通用兼容执行器。回退须先停止当前执行并核对新发生业务、原件和备份，不能只换旧代码便声称数据已恢复。

## 部署方九问工作区

工作区初始化是部署准备步骤，不是普通用户接入步骤。配置先校验全部字段；首次模型配置仅支持核心和官方实例共同使用的OpenAI兼容端点。name为API模型名，Process模型选择键从公开model.list取得，不能拼接资源ID或默认使用模板占位模型。

| 阶段 | 所有权与恢复规则 |
|---|---|
| 认领 | 只在空的新目录写入部署标识、绝对工作区路径及所有者记录；无记录的既有目录、链接路径或不同部署标识拒绝接管。整段准备持有实际OS锁 |
| 初始化 | 只调用原版prepare_workspace(overwrite=False)，在独立后续解释器调用公开配置接口；不改安装包模板、全局指令、工具权限或其他工作区。固定官方版本的新工作区关闭自身自动更新 |
| 配置模型 | 使用已保存的固定model_id，经公开upsert_model_resource配置；写前保存原请求阶段。中断后先查询该资源，内容相同复用，缺失才继续原创建，内容不同停止，不覆盖人工设置或增加重复资源 |
| 缺少模型 | 保存awaiting_model并明确报告未配置；可补齐同一次准备的模型输入，不把模板占位模型当作就绪，不调用生产模型或邮件 |
| 完成与重装 | 保存原模型资源引用；每次读取当前资源及公开目录以解析有效选择键，保留人工修改的模型、权限和技能。不同首次配置输入拒绝静默重配；资源缺失或目录歧义保持未就绪 |

工作区配置记录和日志属于本机私有部署数据。模型密钥只经子进程标准输入交给原版公开配置接口，不进入命令行、返回JSON或共享日志。子进程不继承其他项目凭据或Python导入路径；Windows保留架构等OS必需变量。完成初始化及目录查询只证明配置可读，不证明真实模型生产、接单、公示或systemd部署完成。
