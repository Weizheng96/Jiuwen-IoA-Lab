# 官方实例

## 目的与范围

职责：定义核心外的官方服务及默认管理员业务助手，复用同一SDK、九问适配和原版宿主。目录与权限由[安装与升级](安装与升级.md)规定，不另建收件器、履约循环或合同状态机；运维助手在影片完成后另行设计。

## 预置服务账号归属

官方资源按服务类型/领域声明唯一提供者账号，同一类型的全部候选服务均归该账号；账号和服务身份分开，每个候选保留独立agentId、能力、模板、公钥及履约状态。目录加载与准备过程须核同类唯一账号及服务到账号的映射，不能把服务品牌名称当成不同登录账号。规则归官方资产，不进入核心或通用SDK的行业分支。

既有同类同账号的配置直接保留。变更预置目录不重写已绑定身份、历史合同/签名/付款归属或强制换钥；新部署按新声明准备，已有不一致实例须显式处理活动业务与原身份后再切换，不能静默把旧合同移到新账号。

## 官方服务启动器

`ioalab-official`在核心外协调官方配置，复用同一SDK运行时、服务方模块和九问适配，不另建消息收件器、履约循环或合同状态机。每个ISP账号一个运行时，账号下多项服务分别绑定身份；模型只随实际任务创建Session，启动和续期不请求模型生产。

| 阶段 | 行为与持久结果 |
|---|---|
| 准备 | 按所选官方资源发行声明生成必要账号配置及服务profile；通过SDK上传并核验真实验收包引用。准备阶段不公示、不运行模型、不接受业务；需要控制运行时时使用未配置宿主的同一SDK，不用桩冒充生产 |
| 生成配置 | 准备运行时安全停止后写入完整业务资源和宿主配置；保存实际身份、原操作及包引用。已有完整配置和身份直接复用，不因重启重建密钥、登录赠币或覆盖人工设置 |
| 初始授权 | 安装器用部署管理员会话明确授权本次固定清单；一批原操作与条款摘要持久化。重复安装不重发新授权、不重新启用已撤销记录；已有公示与清单不符时报告需明确配置，不能覆盖 |
| 正常运行 | 复用九问适配探测真实宿主，SDK建立长连接后按授权公示。长期进程只持各服务账号凭据，不保留管理员口令或会话；不能给自身授权 |
| 周期检查 | 依下表的30天有效、7天余量、60秒检查策略，保存一次续期的原参数/operationId后调用SDK；回执丢失恢复原签名和发布操作，不生成新身份、重置接单开关或冒充新成功 |
| 状态 | 分别报告各服务的授权、公示、索引、宿主、连接及接单状态；部分失败不伪称全部就绪。公示成功但索引未就绪时恢复原发布以重建当前投影，不重签模板 |

控制入口分为prepare、authorize、serve、status和stop，部署安装器编排首次使用；普通重启只执行serve。authorize是部署管理员的明确配置入口，serve不得读取管理员凭据或调用授权设置。资源、运行目录及宿主路径都显式配置，不依赖相邻源码目录。安装清单固定实际SDK/适配/官方包的内容摘要；相同数字版本不能使安装器跳过已改变的wheel。

初次公示发生在真实宿主就绪之后。准备阶段不启用公示；正常SDK启动继续以当前接单台账为准，不把资源中的初始accepting值重放为恢复。配置需要改变时先通过正常SDK确认可安全停止；在途合同、未知作业、原密钥和Session不得被覆盖。模板有效期轮换只更新公示请求，不修改业务配置或已有合同原件。


### 模板有效期与轮换

| 时点 | 官方预置服务规则 |
|---|---|
| 新模板发布 | 从签认起有效 30 天 |
| 启动与运行 | 启动时检查；运行中每 60 秒检查 |
| 即将到期 | 剩余不足 7 天时由服务方端 SDK 重新签署、请求签认并刷新 A2X |
| 轮换完成 | 新模板具有新摘要，新委托使用有效版本；原合同继续使用原模板 |
| 轮换失败 | 保留原件并报告，不能伪称续期成功；到期模板不得用于新签约 |

以上是官方服务的配置策略，不修改 A2C 模板字段及有效期语义。续期不能延长已签合同的履约期限，也不能恢复过期的用户授权。配置、连接、容量满足且模板有效后，服务启动即可试用。

### 启动器配置与入口

命令为ioalab-official {prepare|authorize|serve|status|stop} --config <文件>；配置和本地状态只属于部署协调，不写入A2C字段。authorize必须以--admin-username显式提供部署管理员用户名，并以--admin-password-env指定该次受限子进程的管理员口令环境变量名；部署器从同一平台配置读取并传入，官方资源不反向读取平台秘密配置文件。经同时校验用户名和密码的管理员登录接口取得本次Web会话，不保留password-only旧入口；口令和令牌只在该进程内使用，不写入配置、状态、日志或serve环境。首次安装编排prepare/authorize，普通重启只serve。

| 配置 | 类型、初值与生效 |
|---|---|
| platform_url | 必填平台HTTP(S)地址，不含凭据、查询或片段 |
| data_dir | 必填专用部署数据目录，相对配置文件解析；拒绝与其他数据混用 |
| host | 必填原版九问ProcessHost配置，含command/data_dir，可选model/skill_directories；路径解析为绝对值；准备阶段只校验格式，不探测或运行模型 |
| accounts | 可选ISP账号到password或password_env的映射，每项二选一；缺省使用部署种子约定密码；敏感值仅留本机，不回传模型 |
| max_model_runs | 每个ISP运行时的模型并发，默认2，1—64；服务承接上限继续采用各服务配置 |
| native_tools | 原版宿主每任务的工具权限映射，默认read_file/write_file为allow；受原全局deny约束，不修改九问全局权限 |

部署状态保存配置及安装资源摘要绑定、各账号准备阶段、原验收包操作与真实引用、公开身份及完整业务配置。准备仅新建或继续未完成账号；已完整配置直接复用，不覆写人工编辑。验收包原操作在效果前保存；关闭控制运行时后才写完整生产配置。准备中断恢复同一身份/原操作，不先清理目录。

授权请求在发送前保存。一批目标均未配置授权时才自动建立初始请求；已有记录全部符合则仅报告当前状态，部分存在、撤销或失配则停止并由管理员显式调整现有授权，不生成新操作来重新启用。原请求丢响应继续恢复它，区分原回执和当前授权。

serve的子进程环境仅保留OS运行、证书/代理、SDK的A2C_CACHE_DIR及各账号显式password_env，固定使用UTF-8，不继承其他环境；宿主模型使用其既有数据目录中的配置。SDK启动函数可由装配入口显式传入环境映射，不接受模型RPC覆盖。

serve经九问现有SDK装配启动/接管每个ISP运行时，要求配置/安装身份匹配、原宿主探测及连接就绪。生成配置固定require_publication_authorization=true。启动器只经本机认证IPC读取身份、服务状态和发布，不读取参与方私钥或业务数据库。状态入口只查询，不启动、修改或补配置。

续期使用准备时保存的完整模板，只替换validUntil，不重新构造场景或合同。每项发布原参数和operationId先保存；未知先恢复同一SDK操作，已明确拒绝且观察依据未变时保持失败；授权或公示修订变化后重新核条件。当前公示条款与准备清单不符时停止，不覆盖人工变更。既有有效模板无需发布；少于7天时生成新的30天模板。各项分别报告授权、公示、索引、连接、宿主、接单状态。正常检查间隔60秒；停止启动器通过对应bootId请求SDK排空退出，不按进程名称终止。

### 停止与接管

协调器收到SIGINT/SIGTERM后，在当前SDK调用保存原回执后停止启动其他账号和发布操作；持有部署锁直到原SDK执行写入者实际释放。停止使用初始化清单确定的账号及专用resident目录，不随人工编辑后的配置重定向。

| 阶段 | 判断与结果 |
|---|---|
| 固定对象 | 经认证IPC核对账号、平台与准备记录中的完整身份集合，冻结本次实际bootId；不以PID文件、旧描述符或包版本替代认证。停止诊断允许原实例与当前配置/发行包不同 |
| 请求排空 | 对原bootId调用runtime.stop；waiting和completed都只表示排空进度。保留所有密钥、合同、队列、未知结果和原Session。排空前已运行的任务仍可执行自己已授权的工具；新任务和排队任务不再开始，不强制清理 |
| 证明释放 | 以该resident目录的OS锁可取得证明执行写入者已释放；IPC消失但锁仍被持有时继续等待，不能报告已停止；不声称OS锁释放证明整个操作系统进程组已经退出 |
| 实例变化 | 冻结后出现另一bootId或账号/身份不符时拒绝继续，不向替换实例重发停止、不改目录；其他已核验账号可以完成自己的排空 |
| 独立恢复 | stop仅在协调器/准备/授权均未持有部署锁时操作原SDK；占锁则明确要求先停止协调器。可选--wait-seconds为0至30秒，默认0；到时仍未释放返回waiting，不强杀、不启动运行时或模型 |
| 服务管理 | 协调器由服务管理器发送停止信号；采用mixed停止模式、禁用最终SIGKILL并保留排空时间，先停止参与方后停止核心。剩余子进程使重启保持未完成，不能据此原地覆盖环境。systemd行为与Windows进程调用分别验证 |

SDK暂时不可访问时仅报告当前原因及继续核对入口。协调器持续等待已有运行时结束收尾，重复停止使用同一bootId；严重身份冲突明确失败并保留现场。停止不等于合同业务结清；重启以原身份、合同与会话继续符合协议的待办。

## 默认管理员业务助手

预设源位于src/official/admin-assistant/，属于ioalab-official。ioalab-admin-assistant prepare --config <文件>只准备本部署ISC_001的固定预设，status只查询；正常收信使用ioalab-jiuwen serve。该入口不注册为模型工具，不提供任意动作批准能力。

| 项 | 规则 |
|---|---|
| 账号/身份 | 预置ISC_001，唯一assistant profile=admin；不替其他账号配置，不取得核心机构私钥 |
| 运行 | 与核心隔离的同一ResidentRuntime，使用原版ProcessHost；入站上下文、工具、UUID/Session及可靠收发沿用SDK |
| message.forward | 面向全部已登录账号；接受明确的title/text，调用owner.notify提交到同一原生user_id的网页会话；区分排队、网页已收到与用户已读 |
| meeting.request | 面向全部已登录账号；有完整日程/通知配置才启用，否则保留明确停用预设；输入/输出与冲突、邀请语义遵守会议示例 |
| 日程 | 首次显式初始化本地安排；以后不覆盖手工安排或规则；预约/发信回执与SDK状态分别保存 |
| 通知 | 使用九问原生应用扩展和jiuwen-web工厂；不写九问源码、全局指令或历史库；凭据只在自己的配置中 |
| 缺项 | 缺模型或公开能力不就绪；缺邮件时会议停用但留言可用，不用桩、假邀请或默认空日历冒充能力 |

### 初始预设的操作授权

部署者运行安装器并启用admin_assistant时，授权安装器作为本部署ISC_001的配置方设置固定内置预设。受限root准备进程仅在新建、未运行模型的受管实例中，校验账号/目录归属、包资源摘要及两个指定接口，展示/保存实际处理与工具摘要，再通过同一SDK可信本地用户通道确认原rules.publish操作。来源记录为deployment-preset及本部署/预设摘要。

该特权只配置内置接口，不批准委托授权、合同、实名环节、验收或付款；不接受模型提供的任意确认引用/规则/账号，不暴露批量批准RPC。普通用户规则仍通过真实用户确认。准备完成后进程退出、执行锁释放，参与方目录交给其独立账号，长期运行时不持该准备权或管理员口令。

每个预设的原draft、内容摘要、operationId、确认及发布结果持久化；中断先恢复原发布，不新建操作规避结果未知。已准备实例重装不重发确认或发布；人工停用、修改、预约及原消息均保留。缺少原记录、资源失配或未登记旧实例停止并报告，不能用空状态恢复默认。

### 准备记录与命令输入

准备入口只接受安装器生成的`<状态根>/.deployment/admin-assistant/config.json`；不提供账号、接口名、规则或确认引用的命令行参数。其`deployment_id`必须匹配三根的原归属记录；`password`仅为固定ISC_001的本机凭据，使用首次部署生成的原密码，不硬编码试用口令；`platform_url`、原版`host`、回环`web_url`、`recipient`、可选`notification`及`max_model_runs`定义固定实例配置。通知使用工具工厂的凭据文件/变量引用，不把密钥写入模型上下文。

| 项 | 规则 |
|---|---|
| 准备权限 | 仅部署root进程；配置、原归属和准备记录不可被参与方改写。拒绝符号链接、归属冲突或未登记的旧实例，不接管用户已有九问 |
| 固定位置 | SDK配置和本地安排在`<状态根>/agents/admin-assistant/`，原版九问工作区为`<状态根>/agents/swarm-admin/`；原操作与确认摘要在root私有准备记录中 |
| 准备执行 | 创建不装配宿主、不启动连接/调度的同一SDK控制实例，校验并发布两个固定接口；业务工具只用于校验声明，不调用生产、通知或模型；关闭并释放SDK锁后才写完整宿主配置 |
| 已完成 | 只核对原配置/身份仍在，保留人工编辑；不重放初始发布，不把原回执当作当前启用状态。缺少原文件要求恢复，不重建空日程或身份 |
| 中断 | 保存原草稿、操作、确认摘要及原发布结果，继续原操作；确认已过期或被拒绝时停止并报告，不制造新确认绕过决定；已提交但丢回执由SDK查询原操作恢复 |
| 状态 | `status`不创建目录、登录或运行模型；报告准备状态、原发布回执及实际可查询的运行状态，明确区分未查询、未运行与就绪 |
