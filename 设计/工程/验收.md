# 验收

## 目的与范围

本文定义判定条件，不记录某轮是否通过。运行结果写入对应验证记录，设计差距写入[开发计划](../../docs/开发计划.md)；测试桩、真实九问、真实邮件和正式视频分别提供证据。

## 架构与文档

| 编号 | 场景 | 必须满足 |
|---|---|---|
| A01 | 新成员阅读 | 从设计入口找到唯一规则归属；术语一致，现行正文不混入历史或完成记录 |
| A02 | 模块依赖 | 平台不导入参与方执行器；SDK 基础包不依赖平台、九问实现或官方场景；两角色 SDK 与两个接入技能共用运行时，九问适配经 AgentHost 注入 |
| A03 | 产品配置 | 官方/普通服务走相同 SDK；个人助手在核心外；新接口不需要改平台分发器源码 |
| A04 | 版本 | 历史索引首项匹配设计 VERSION；发行包使用自己的实际产物依据；技能、示例和四个 Demo 的 VERSION 归属明确，未完成迁移的产物保留真实旧版本；正文链接有效 |
| A05 | 数据与跨中心用例 | 每类状态有唯一写入方；组件不直接修改其他组件的表；接单与拟卡费由明确应用入口在同一短事务协调，观察投影不能推进业务 |
| A06 | 本地写入所有权 | 技能/CLI 只经本机认证的 IPC 调运行时；同一实例的两个角色复用身份和连接，不另开数据库或持有竞争的长期锁 |
| A07 | 源码与资源独立性 | 可安装包离开仓库源码布局仍可加载必需资源；不靠手工 sys.path、调用者工作目录、temp 或相邻 A2C 仓库运行；预置旧构建缓存时，wheel 仍仅包含现行源码模块 |
| A08 | 业务工具隔离 | 日程与邀请规则归官方业务工具，SDK 只保存操作关联及执行检查点；同一稳定操作键恢复原回执，未知外部效果不自动重做 |
| A09 | 配置与参数所有权 | 引导不解析账号配置；两技能、SDK及宿主一致读取Windows UTF-8配置/参数。账号配置或其文件别名、SDK数据不得被参数元信息覆盖；配置/安装改变时业务拒绝且无效果，缺凭据或业务配置错误时仍可定位原实例诊断与安全停止；不提供旧CLI别名 |
| A10 | 确认流程可执行 | 预览不创建批准；按下一步角色调用生成真实waiting后才打开页面。打开页面不改变pending；重复申请同一操作复用原确认，聊天confirmed无效；真实批准后原操作只签名/发布一次 |

## 账号与角色接入

| 编号 | 场景 | 必须满足 |
|---|---|---|
| I01 | 注册/登录并发重传和丢响应 | 同操作返回同账号、原令牌及原赠币结果，不重复发放；账号或赠币写失败整体回滚 |
| I02 | 凭据续用与重建 SDK | 两角色复用同一缓存；续用不新增登录或赠币，失效不循环密码认证 |
| I03 | 独立服务身份 | 无个人助手、无公网端口即可证明并绑定服务公钥，取得票据与连接；未发布时不宣称可接单 |
| I04 | 绑定回执丢失及挑战到期 | 先落本地证明，再提交；已成功证明恢复原结果，不另建身份或覆盖公钥 |
| I05 | 归属与范围 | 同键异参数、他人身份/公钥、跨角色挑战及私钥字段均拒绝；新设备不覆盖既有逻辑助手 |
| I06 | 本机实例与 IPC | 同目录只能一个进程持有运行数据；描述文件遗留不证明存活，旧实例不能删除新端点；Origin/Host/访问凭据/大小检查有效，CLI 不打开身份库 |
| I07 | 离线与停止 | 仅已绑定且凭据有效的实例能离线启动，状态明确离线；重连不再登录赠币；停止保留合同及操作，已有轮次未收敛时不提前释放所有权 |
| I08 | 调度与恢复 | 同交互及同实际Session串行，跨交互受模型上限约束；等待释放轮次、控制不阻塞；重启不重跑未知外部效果，原作业重传及异参数校验正确 |
| I09 | 用户确认入口 | 脚本不能取得浏览器批准凭据或写入同意；确认绑定真实对象、预览和原操作，跨对象/阶段/过期/重复伪造拒绝，原发布未知可查询恢复 |
| I10 | 原版宿主轮次 | 固定 Agent/技能/工具与原Session续接；真实 Session 在工具前保存，原生问题在同进程获得真实答复，不伪造批准或把后台结果当网页已显示 |
| I11 | 原生生产工具 | 加载技能不自动授予工具；本机精确清单及权限冻结，报价/复签 deny、生产按原许可启用；明确宿主拒绝阻止新生产，未核实不伪称已验证，实际错误保留；工具配置变化不扩大原会话权限；SDK回调允许不代替真实用户确认 |
| I13 | 本单业务文档 | 原生选中不是授权；只读回调仅访问所选技能的冻结主文档/Markdown引用，拒绝其他技能、私有文件、链接与越界；源变化不替换旧交互，快照损坏不得重建掩盖；实际读主文档后才可提交本单动作 |
| I14 | 模型观察与验收预览 | 原L2包提出观察、WASM判定，错误观察/缺宿主不得通过；观察无业务工具和批准入口，不覆盖业务Session；受当前模型作业预算约束，并发上限1时嵌套自测不死锁；异步预览不签7，真实批准后原SDK复验；用户拒绝或确认过期后，无需再次模型调用即可结束本地等待，不签7、不付款 |
| I12 | 双技能与配置生效 | 两包共享兼容清单和隔离环境，同账号复用配置/数据目录；不泄露密码；修改身份/角色/执行配置后旧实例摘要不匹配，明确安全停止/重启，不并行启动或伪报已生效；独立配置校验不产生业务效果；原生加载技能后实际执行随包runtime.start并核身份、连接及宿主状态，读文件或模型报告不能代替调用回执；接入前后既有九问安装及全局配置不变，不自动换版或放宽权限，额外扩展经原生入口显式配置 |
| I15 | 本地业务工具 | 仅本机选择已安装工厂，按profile隔离；SDK不导入具体包，外来消息不能加载工具；工具目录无凭据，规则/会话绑定策略修订；服务方只在生产及本期真实环节同意后执行，未知不重调；作业结束后才关闭工具资源 |
| I16 | 安装与运行版本 | 两包共享含可选工具的清单和环境，未配置不启用；检查完成才发布安装标记，损坏不原地覆盖；旧实例缺身份或发布/环境不同拒绝启动和业务，仍可诊断/安全停止；预检后bootId切换不得发送业务；重启保留稳定身份、原交互/会话、合同、授权及回执，不重新登录赠币 |
| I16a | 安装任务 | 前台快速返回，父调用结束后后台继续；双技能并发只产生一个实际安装任务。纯查询/业务不隐式安装、不读凭据、不回写原业务参数。实际锁与完成包决定状态；明确失败才显式重试，进行中失去所有者保持unknown且不重建；损坏就绪标记不覆盖 |
| I17 | 九问网页通知 | 原生命名空间准备可重复执行，异内容/目标拒绝覆盖，不改安装和全局配置、不自动重启；prepared不等于loaded或ready；显式配置 IoA 通知扩展和固定用户，缺密钥/错用户不发送；离线保留、同源同内容去重、异内容冲突；发送未知先查询原回执，不换ID重写；TTL不抹除未知，回执库标识改变不得将absent当作未执行；工具资源按实例生命周期启动/关闭；真实网页可见与会话持久化分别验收 |
| I18 | 本单验收器准备 | 无预置验收引用时可在原quote作业内打包并取得真实引用后拟卡；身份及UUID由SDK绑定，变换宿主调用ID复用原内容；错误源码/包摘要/种类及越界字段拒绝，上传未知先保留原记录；待批准、生产或决定后拒绝；不改公示、配置或已签判据，完整履约仍经原WASM验收和AP2付款 |
| I19 | 原拟约恢复 | 无原模型结束证明、已返回决定、其他阶段/身份、过期或原Session变更时不可重跑；已核验验收器准备中断可经公开任务查询及显式恢复，同事务保持恢复回执与原作业，丢回复/重传/并发/重启不重复入队；原UUID/Session/A2C任务/费用及期限保持，最终真实验收付款结清 |
| I20 | 确认页浏览器 | 默认浏览器或本机配置的绝对可执行路径；含空格路径按独立参数启动，不使用shell，远端/模型不能临时传路径或URL；无效配置/打开失败明确报错且不回退或泄露入口。配置摘要变化须安全重启；打开前后原确认仍待决定，仅真实浏览器通道可批准 |

## 连接与投递

| 编号 | 场景 | 必须满足 |
|---|---|---|
| T01 | 无公网 IP 的两端 | 均只主动连接平台，完成请求、回复和任务进展推送 |
| T02 | 任一 ACK 丢失/重连 | 平台与本地落库后确认；原消息补发，不重复执行业务或副作用 |
| T03 | 长期离线 | TTL 内恢复送达；到期返回过期，未开始的业务不执行，不宣称离线助手在运行 |
| T04 | 协议期限短于 TTL | 拒绝过期 A2C 签名/请求，不修改签名时间或合同期限 |
| T05 | 同身份两设备 | 只有一个有效执行租约；旧连接不能提交新动作，接管先核未完成操作 |
| T06 | 队列满/恶意大包 | 明确拒绝新业务，不能覆盖旧消息；已有合同控制与恢复消息仍可处理 |
| T07 | 账号边界 | 不能冒用发信人、读取第三方正文或用别人的交互 ID 回复 |
| T07a | 不同发信人故意使用同消息ID | 平台拒绝全局标识冲突，不披露原正文；本地与平台去重范围一致 |
| T08 | 重连与登录 | 自动重连和票据刷新不赠币；同一登录操作重传不重复赠币 |
| T09 | 本地写入与断点 | inbox 与连续游标同事务；建立 UUID 与 opened outbox 同事务；落库失败整体回滚，不能先 ACK |
| T10 | 多身份结果关联 | 控制响应携带 agentId、操作类型与操作 ID；不得把另一身份的同名操作结果应用到本地任务 |
| T11 | 保留与幂等边界 | unknown 及未收敛执行的关联不能清理；终结后重新计保留期，已清理 ID 不重新执行；超出恢复历史明确报缺口 |

## 委托与容量

| 编号 | 场景 | 必须满足 |
|---|---|---|
| D01 | 多候选委托 | 真实模板筛选、正式报价与验收比较；用户按阶段确认，无场景常量控制推荐 |
| D02 | 并发争抢最后名额 | 仅一个成功预留，其他明确满额；被拒绝者不付拟卡费 |
| D03 | 预留到期、付款竞争及进程中断 | 原子协调名额、支付操作和账本，不能出现已释放名额却仍收取本次拟卡费，或付款记录与实际记账分裂 |
| D04 | 已签提案未选中 | 不提前释放仍可成约/开工的名额；等待窗口按 A2C 计算 |
| D05 | 等待用户 | 占接单名额、释放可释放的模型名额；原生确认不会由模型自动答复 |
| D05a | 暂停与恢复 | 公示前可暂停；真实策略回执/当前状态分列，同配置重启及重公示不恢复。新预留拒绝，原有效held可提交、既有合同继续；容量单字段改变不改暂停，未知写入恢复原请求，旧resume回执不重新开启 |
| D06 | 断线/重启/写入未知 | 查原凭证、任务和承诺，恢复原单，不重复收费或生成第二份合同 |
| D07 | 满额后的后续消息 | 原单授权、交付、验收、付款、解除继续可用 |
| D08 | 本地验收 | 包摘要有效、WASM 执行；失败/pending 不签7，不据模型文字付款 |
| D09 | 官方模板续期 | 新模板可试用，旧合同仍使用原件；重启不延长旧合同 |
| D10 | 多候选同时付拟卡费 | 本地授权额度原子预留；并行请求总额不超授权，未知结果占用额度直到核实 |
| D10a | 签名授权与续期 | 非所属/错误用户密钥、过期、篡改及旧修订拒绝新动作；同范围显式续期不换卡载摘要、不重置已花费用，关闭后旧登记重传不能重开 |
| D10b | 合同完整价款 | 具体确认后的用户选择证明先原子预留完整价款；并发拟卡费不能使剩余额度不足，不能签1后补额度；分期付款不重复扣预算，也不能超过所选完整价款 |
| D11 | 零拟卡费 | 仍先提交接单预留，再签署有效承诺，不能绕过容量检查 |
| D12 | 待批准与提案混合比选 | 待批准候选在用户选定前仅有未签报价卡；选中并确认后才签1、请求签2；不得先形成多份待批准合同再选择 |
| D13 | 待批准审查与提交 | 签1卡可在有效 held 下投递并开始审查；审查通过后提交容量，再产生签2；到期或提交失败不签2，未提交或替换原卡的结果不能进入平台 |
| D14 | 材料与私有文件 | 归属、摘要、原用户材料授权及审查范围有效后，读取权与消息原子提交；失败不泄露读取权，待完成上传不可读，原操作恢复不重复占配额 |
| D15 | 原协议任务进展 | 保留上游 taskId、任务状态及无任务响应；不能替换原任务或回退终态；投递台账的调用完成不替代合同完成 |
| D16 | 常驻原协议闭环 | 两端原 Client/Provider 经 WS 收发；每交互 Store、原任务和 Session 独立，模型并发受控；重启恢复已有原件，未知执行不自动重跑 |
| D17 | 提案签认竞争 | 只签认原已开始请求对应的服务方签2卡；容量/用户/期限/当前连接提交前复核；快照、原签3、卡绑定及操作回执原子保存，丢响应不重签 |
| D18 | 具体合同确认 | 无真实合同确认不得签1；完整价款预留成功在先；提案沿原 UUID，待批准在选中后才预留并复签；并发选择不得签出第二张卡，未知结果不重签或重跑审查 |
| D19 | 完整履约 | 两模式实际开工、环节用户答复、交付及签4/5/6/7、WASM 报告、AP2 及结清；各事实与原件对应，不能仅验证演示入口 |
| D20 | 同方法多次调用 | 多期 checkout、取件及验收通知各有原操作；当前格式下重启保留原消息、签名、任务与结果，不覆盖早期调用；不要求旧表自动迁移 |
| D21 | 等待与控制 | 生产等待环节/验收时，同交互的原控制可处理并续接原 Session；模型忙或缺失不阻断已有控制，不重复执行 unknown |
| D22 | 既有合同与窗口 | 原模板退出公示、意向或新委托许可到期后仍可接收合法原合同证据；新的付款另核许可，开工和履约仍遵守原 A2C 窗口 |
| D23 | 结清与释放 | 缺实际付款、未知开工/签署不得释放；真实结清、容量与通知原子提交；重复结清不新增信誉次数 |
| D24 | 首次履约与任务归属 | 定金 checkout 可先于开工登记有效成约；篡改原承诺、其他卡/用户/Task 均拒绝；Task.op 保留创建方法，环节答复须绑定真实用户与原请求 |
| D25 | 分类预览与发布 | 根据公开能力在实际A2X叶类匹配；路径来自实际目录；无模型/含糊/错误结果请求用户选择，不静默选其他；SDK异步预览不阻塞本机查询，同操作恢复原预览、异输入冲突，发布不重跑匹配；用户确认实际分类后才签署，类别删除或发布修订变化时拒绝，丢发布回执仍恢复原分类和签名 |
| D26 | 服务方起草与错误输入 | 原A2C业务字段、多交付件与真实平台支付声明；有效起草同操作重传/重启保留原有效期，异内容冲突；不签署或公示，不改业务定价；错误输入、鉴权、限流及跨站拒绝使用统一对象，已知拒绝不成为未知结果 |
| D27 | 多期完整履约 | 至少两期经同UUID/Task/Session完成真实HTTP/WS、逐期WASM/确认/原AP2；上期付款前不排产下期，中间期不释放容量；下期授权不复用上期答复。重启、丢付款回复及同名文件保持各期原件；取件前HTTP中断无签6/缓存时给出已知读取失败，可显式重新读取，不把已有签收当失败重签；最终只结清/计信誉一次 |

## 付款原子性与回执

| 编号 | 场景 | 必须满足 |
|---|---|---|
| P01 | 扣增/回执写入中断 | 账本、paid 和原回执整体提交或回滚；失败后重试不遇到虚假的已付标记 |
| P02 | 并发/重启/丢响应 | 同一原请求只过账一次，返回相同 voucher、Payment Receipt 和 paymentId |
| P03 | 旧 JWT、错对象或改参数 | 新付款核时效与原摘要绑定；同付款键异原请求拒绝，不能复用别人的凭证 |
| P04 | 投影失败 | 真实付款仍有可查询原凭证，不产生第二笔过账 |
| P05 | 旧记录缺原件 | 明确待核实，不重新签凭证或删除已付记录后重付 |

## 助手通信与会话

| 编号 | 场景 | 必须满足 |
|---|---|---|
| M01 | 自然语言配置收信规则 | 九问起草、本地无副作用预检、摘要确认、SDK发布；用户无需写Schema，处理步骤不上传为平台代码 |
| M01a | 规则更新/发布回执丢失 | 修订冲突拒绝、同操作恢复原发布；不误扩大范围，不用缺失的本地版本处理消息 |
| M02 | 更新/撤权 | 队列消息按原格式版本校验，按当前权限复核；不能用旧消息绕撤权 |
| M03 | 首请求重传 | 一个交互 ID、一个接收端会话映射；不会因重连创建多个任务 |
| M03a | 建立回执丢失/双方重启 | 本地映射与待发回执同事务；平台查原始双方；发起端按 originMessageId 补齐，后续自动带 UUID，不靠模型猜测 |
| M03b | 建立前拒绝/同源不同UUID | 原请求明确结束，不无限等UUID；第二个UUID不能覆盖已有关系 |
| M03c | 关闭与建立/开始竞争 | 平台事务决定先后，迟到opened不重开；未获开始许可的请求不执行 |
| M04 | 多轮交流 | 同一交互续接原会话，同交互串行、不同交互可并发；回复保持原参与关系 |
| M05 | 冲突后改约 | 首次结构化冲突结果、推荐时间、同交互新消息改约、原子预留与邀请提交；同消息换工具调用ID恢复原结果，改变输入拒绝，不能自行采用建议时间；并发及重启不重复预约或邀请 |
| M06 | 业务副作用未知 | 标 unknown 并对账，不自动重发邀请；本地记录不冒充 Outlook 已接受 |
| M07 | 本地规则与权限 | 远程正文不能改日程规则、工具权限或用户授权；无效日程阻止预约 |
| M08 | 原版九问 | 适配器检查公开能力、按原定义恢复 session；真实用户答复绑定对象与阶段，关联不可用时保持待确认；未获用户答复不回答原生 ASK，网页呈现单独核验 |
| M09 | 交互结束与回复晚到 | 停止新请求、继续返回已发生结果；消息 TTL、交流截止与 A2C 合同终态不混用 |
| M10 | 最后一轮请求 | 达到轮数上限拒绝新增请求，但已接受的限额内请求仍可取得开始许可；显式关闭或截止另判 |
| M11 | 请求方向与返回权限 | 同交互只调用固定接收方接口；结果仅返回原请求方，反向新调用需独立交互与授权 |
| M12 | 结果乱序与重复 | unknown 不覆盖已确认终局；同请求相同终局恢复原结果，冲突终局明确拒绝；后续预约状态不改写旧请求终局 |
| M13 | 首请求排队时更新规则 | 受理时冻结修订；已入队未建立UUID也按冻结版处理，同时开始前检查当前权限/启停/TTL |

## 部署、观察与演示

| 编号 | 场景 | 必须满足 |
|---|---|---|
| E01 | 无 GitHub 的干净部署 | 第三方源码、许可、摘要及预构建资产完整；普通依赖走配置的国内镜像，不使用 VCS 安装或现场网页构建 |
| E02 | 安装单元隔离 | 平台、统一 SDK、九问适配的依赖闭合；九问本体在独立宿主环境；平台环境不安装参与方 Process SDK；技能清单锁定兼容组合；并发读写安装元数据取得完整快照，不把文件替换竞争误作损坏；真实损坏仍停止。验收失败保留目录及原安装任务，不清理仍在工作的环境 |
| E03 | 默认初始化 | 部署清单显式输入内部账号与分类；重复初始化不覆盖已有凭据/状态；参与方自己生成密钥，经同一 SDK 绑定身份和发布服务 |
| E04 | 升级与接管 | 保留原合同、密钥、授权和操作回执；新旧执行器不同时活动；不能接管的在途业务先完成或按协议结束 |
| E05 | 目录与数据 | temp 及私人运行数据不入库；正式 experiments 可复现且不依赖临时文件；Windows 本地与 Linux systemd 分别记录结果 |
| E06 | 场景产物 | 每个 Demo 的源、剧本、素材、视频和证据可关联；共享工具只有一份，跨仓依赖随仓保留来源；迁移路径不篡改旧实测事实或虚升视频依据 |
| E07 | 四片真实用例 | 全局简述平台；服务方真实注册/配置专业能力/技能发布/编程分类/交付/信誉；个人助手真实注册/接入/四处确认/验收支付；四宫格自然语言发布接口、冲突后同交互改约成功；第2—4片完整实录用户接入配置、启动及业务操作，使用户可按对应视频复现；各自剧本与新代码证据完整 |

私钥、模型密钥、通知凭据不得出现在日志或提交中。普通接入、官方配置和演示场景应分别验证，不能以演示专用路径代替通用产品验收。

观察用真实证据核对阶段、收入与消息状态；普通账号只能获得获准数据；平台网页不读取本地收信处理正文，配置详情通过九问本地入口查看。管理员全景同时出现多发起方委托和助手通信；匿名示意不计真实事件。四段 Demo 的剧本、镜头、旁白和证据要求见[演示制作](../示例/演示制作.md)。
