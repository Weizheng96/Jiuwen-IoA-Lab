# 验收

## 目的与范围

本文定义判定条件，不记录某轮是否通过。运行结果写入对应验证记录，设计差距写入[开发计划](../../docs/开发计划.md)；测试桩、真实九问、真实邮件和正式视频分别提供证据。

## 架构与文档

| 编号 | 场景 | 必须满足 |
|---|---|---|
| A01 | 新成员阅读 | 从设计入口找到唯一规则归属；术语一致，现行正文不混入历史或完成记录 |
| A02 | 模块依赖 | 平台不导入参与方执行器；SDK 基础包不依赖平台、九问实现或官方场景；两角色 SDK 与两个接入技能共用运行时，九问适配经 AgentHost 注入 |
| A03 | 产品配置 | 官方/普通服务走相同 SDK；个人助手在核心外；新接口不需要改平台分发器源码 |
| A04 | 版本 | 历史索引首项匹配设计 VERSION；发行包使用自己的实际产物依据；技能、示例和三个 Demo 的 VERSION 归属明确，未完成迁移的产物保留真实旧版本；正文链接有效 |
| A05 | 数据与跨中心用例 | 每类状态有唯一写入方；组件不直接修改其他组件的表；接单与拟卡费由明确应用入口在同一短事务协调，观察投影不能推进业务 |
| A06 | 本地写入所有权 | 技能/CLI 只经本机认证的 IPC 调运行时；同一实例的两个角色复用身份和连接，不另开数据库或持有竞争的长期锁 |
| A07 | 源码与资源独立性 | 可安装包离开仓库源码布局仍可加载必需资源；不靠手工 sys.path、调用者工作目录、temp 或相邻 A2C 仓库运行 |
| A08 | 业务工具隔离 | 日程与邀请规则归官方业务工具，SDK 只保存操作关联及执行检查点；同一稳定操作键恢复原回执，未知外部效果不自动重做 |

## 连接与投递

| 编号 | 场景 | 必须满足 |
|---|---|---|
| T01 | 无公网 IP 的两端 | 均只主动连接平台，完成请求、回复和任务进展推送 |
| T02 | 任一 ACK 丢失/重连 | 平台与本地落库后确认；原消息补发，不重复执行业务或副作用 |
| T03 | 长期离线 | TTL 内恢复送达；到期返回过期，未开始的业务不执行，不宣称离线助手在运行 |
| T04 | 协议期限短于 TTL | 拒绝过期 A2C 签名/请求，不修改签名时间或合同期限 |
| T05 | 同身份两设备 | 只有一个有效执行租约；旧连接不能提交新动作，接管先核未完成操作 |
| T06 | 队列满/恶意大包 | 明确拒绝新业务，不能覆盖旧消息；已有合同控制与恢复消息仍可处理 |
| T07 | 账号边界 | 不能冒用发信人、读取第三方正文或用别人的交互 ID 回复 |
| T07a | 不同发信人故意使用同消息ID | 平台拒绝全局标识冲突，不披露原正文；本地与平台去重范围一致 |
| T08 | 重连与登录 | 自动重连和票据刷新不赠币；同一登录操作重传不重复赠币 |
| T09 | 本地写入与断点 | inbox 与连续游标同事务；建立 UUID 与 opened outbox 同事务；落库失败整体回滚，不能先 ACK |
| T10 | 多身份结果关联 | 控制响应携带 agentId、操作类型与操作 ID；不得把另一身份的同名操作结果应用到本地任务 |
| T11 | 保留与幂等边界 | unknown 及未收敛执行的关联不能清理；终结后重新计保留期，已清理 ID 不重新执行；超出恢复历史明确报缺口 |

## 委托与容量

| 编号 | 场景 | 必须满足 |
|---|---|---|
| D01 | 多候选委托 | 真实模板筛选、正式报价与验收比较；用户按阶段确认，无场景常量控制推荐 |
| D02 | 并发争抢最后名额 | 仅一个成功预留，其他明确满额；被拒绝者不付拟卡费 |
| D03 | 预留到期、付款竞争及进程中断 | 原子协调名额、支付操作和账本，不能出现已释放名额却仍收取本次拟卡费，或付款记录与实际记账分裂 |
| D04 | 已签提案未选中 | 不提前释放仍可成约/开工的名额；等待窗口按 A2C 计算 |
| D05 | 等待用户 | 占接单名额、释放可释放的模型名额；原生确认不会由模型自动答复 |
| D06 | 断线/重启/写入未知 | 查原凭证、任务和承诺，恢复原单，不重复收费或生成第二份合同 |
| D07 | 满额后的后续消息 | 原单授权、交付、验收、付款、解除继续可用 |
| D08 | 本地验收 | 包摘要有效、WASM 执行；失败/pending 不签7，不据模型文字付款 |
| D09 | 官方模板续期 | 新模板可试用，旧合同仍使用原件；重启不延长旧合同 |
| D10 | 多候选同时付拟卡费 | 本地授权额度原子预留；并行请求总额不超授权，未知结果占用额度直到核实 |
| D11 | 零拟卡费 | 仍先提交接单预留，再签署有效承诺，不能绕过容量检查 |
| D12 | 待批准与提案混合比选 | 待批准候选在用户选定前仅有未签报价卡；选中并确认后才签1、请求签2；不得先形成多份待批准合同再选择 |

## 助手通信与会话

| 编号 | 场景 | 必须满足 |
|---|---|---|
| M01 | 自然语言配置收信规则 | 九问起草、本地无副作用预检、摘要确认、SDK发布；用户无需写Schema，处理步骤不上传为平台代码 |
| M01a | 规则更新/发布回执丢失 | 修订冲突拒绝、同操作恢复原发布；不误扩大范围，不用缺失的本地版本处理消息 |
| M02 | 更新/撤权 | 队列消息按原格式版本校验，按当前权限复核；不能用旧消息绕撤权 |
| M03 | 首请求重传 | 一个交互 ID、一个接收端会话映射；不会因重连创建多个任务 |
| M03a | 建立回执丢失/双方重启 | 本地映射与待发回执同事务；平台查原始双方；发起端按 originMessageId 补齐，后续自动带 UUID，不靠模型猜测 |
| M03b | 建立前拒绝/同源不同UUID | 原请求明确结束，不无限等UUID；第二个UUID不能覆盖已有关系 |
| M03c | 关闭与建立/开始竞争 | 平台事务决定先后，迟到opened不重开；未获开始许可的请求不执行 |
| M04 | 多轮交流 | 同一交互续接原会话，同交互串行、不同交互可并发；回复保持原参与关系 |
| M05 | 冲突后改约 | 首次结构化冲突结果、推荐时间、同交互第二次请求、原子预留与邀请提交 |
| M06 | 业务副作用未知 | 标 unknown 并对账，不自动重发邀请；本地记录不冒充 Outlook 已接受 |
| M07 | 本地规则与权限 | 远程正文不能改日程规则、工具权限或用户授权；无效日程阻止预约 |
| M08 | 原版九问 | 适配器检查公开能力、按原定义恢复 session；真实用户答复绑定对象与阶段，关联不可用时保持待确认；未获用户答复不回答原生 ASK，网页呈现单独核验 |
| M09 | 交互结束与回复晚到 | 停止新请求、继续返回已发生结果；消息 TTL、交流截止与 A2C 合同终态不混用 |
| M10 | 最后一轮请求 | 达到轮数上限拒绝新增请求，但已接受的限额内请求仍可取得开始许可；显式关闭或截止另判 |
| M11 | 请求方向与返回权限 | 同交互只调用固定接收方接口；结果仅返回原请求方，反向新调用需独立交互与授权 |
| M12 | 结果乱序与重复 | unknown 不覆盖已确认终局；同请求相同终局恢复原结果，冲突终局明确拒绝；后续预约状态不改写旧请求终局 |
| M13 | 首请求排队时更新规则 | 受理时冻结修订；已入队未建立UUID也按冻结版处理，同时开始前检查当前权限/启停/TTL |

## 部署、观察与演示

| 编号 | 场景 | 必须满足 |
|---|---|---|
| E01 | 无 GitHub 的干净部署 | 第三方源码、许可、摘要及预构建资产完整；普通依赖走配置的国内镜像，不使用 VCS 安装或现场网页构建 |
| E02 | 安装单元隔离 | 平台、统一 SDK、九问适配的依赖闭合；九问本体在独立宿主环境；平台环境不安装参与方 Process SDK；技能清单锁定兼容组合 |
| E03 | 默认初始化 | 部署清单显式输入内部账号与分类；重复初始化不覆盖已有凭据/状态；参与方自己生成密钥，经同一 SDK 绑定身份和发布服务 |
| E04 | 升级与接管 | 保留原合同、密钥、授权和操作回执；新旧执行器不同时活动；不能接管的在途业务先完成或按协议结束 |
| E05 | 目录与数据 | temp 及私人运行数据不入库；正式 experiments 可复现且不依赖临时文件；Windows 本地与 Linux systemd 分别记录结果 |
| E06 | 场景产物 | 每个 Demo 的源、剧本、素材、视频和证据可关联；共享工具只有一份，跨仓依赖随仓保留来源；迁移路径不篡改旧实测事实或虚升视频依据 |
| E07 | 四片真实用例 | 全局简述平台；服务方真实注册/配置专业能力/技能发布/编程分类/交付/信誉；个人助手真实注册/接入/四处确认/验收支付；四宫格自然语言发布接口、冲突后同交互改约成功；各自剧本与新代码证据完整 |

私钥、模型密钥、通知凭据不得出现在日志或提交中。普通接入、官方配置和演示场景应分别验证，不能以演示专用路径代替通用产品验收。

观察用真实证据核对阶段、收入与消息状态；普通账号只能获得获准数据；平台网页不读取本地收信处理正文，配置详情通过九问本地入口查看。管理员全景同时出现多发起方委托和助手通信；匿名示意不计真实事件。四段 Demo 的剧本、镜头、旁白和证据要求见[演示制作](../示例/演示制作.md)。

基础检查：`python 设计/check.py`、`python tools/check_docs.py`、`python -m pytest -q tests`、`python tools/selfcheck.py`。接入安装和完整端到端另按对应产物入口执行；基础检查通过不等于新增架构已经完成。
