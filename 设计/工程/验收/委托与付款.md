# 验收 · 委托与付款

本页是[验收](../验收.md)的子页；目的、范围与其他子页见父页。

## 委托与容量

| 编号 | 场景 | 必须满足 |
|---|---|---|
| D01 | 多候选委托 | 真实模板筛选、正式报价与验收比较；用户按阶段确认，无场景常量控制推荐 |
| D02 | 并发争抢最后名额 | 仅一个成功预留，其他明确满额；被拒绝者不付拟卡费 |
| D03 | 预留到期、付款竞争及进程中断 | 原子协调名额、支付操作和账本，不能出现已释放名额却仍收取本次拟卡费，或付款记录与实际记账分裂 |
| D04 | 已签提案未选中 | 不提前释放仍可成约/开工的名额；全窗口后核原请求、签名和终局回执，再原子释放、关闭并通知；保留拟卡费和提案，不增加信誉。已选择、合同/开工/付款存在、调用未知或证据缺失均不自动释放；重复维护及事务失败不重复通知或部分释放 |
| D05 | 等待用户 | 占接单名额、释放可释放的模型名额；原生确认不会由模型自动答复 |
| D05a | 暂停与恢复 | 公示前可暂停；真实策略回执/当前状态分列，同配置重启及重公示不恢复。新预留拒绝，原有效held可提交、既有合同继续；容量单字段改变不改暂停，未知写入恢复原请求，旧resume回执不重新开启 |
| D06 | 断线/重启/写入未知 | 查原凭证、任务和承诺，恢复原单，不重复收费或生成第二份合同 |
| D07 | 满额后的后续消息 | 原单授权、交付、验收、付款、解除继续可用 |
| D08 | 本地验收 | 包摘要有效、WASM 执行；失败/pending 不签7，不据模型文字付款 |
| D09 | 官方模板续期 | 新模板可试用，旧合同仍使用原件；重启不延长旧合同 |
| D10 | 多候选同时付拟卡费 | 本地授权额度原子预留；并行请求总额不超授权，未知结果占用额度直到核实 |
| D10a | 签名授权与续期 | 非所属/错误用户密钥、过期、篡改及旧修订拒绝新动作；同范围显式续期不换卡载摘要、不重置已花费用，关闭后旧登记重传不能重开 |
| D10b | 合同完整价款 | 具体确认后的用户选择证明先原子预留完整价款；并发拟卡费不能使剩余额度不足，不能签1后补额度；分期付款不重复扣预算，也不能超过所选完整价款 |
| D11 | 零拟卡费 | 仍先提交接单预留，再签署有效承诺，不能绕过容量检查 |
| D12 | 待批准与提案混合比选 | 待批准候选在用户选定前仅有未签报价卡；选中并确认后才签1、请求签2；不得先形成多份待批准合同再选择 |
| D13 | 待批准审查与提交 | 签1卡可在有效 held 下投递并开始审查；审查通过后提交容量，再产生签2；到期或提交失败不签2，未提交或替换原卡的结果不能进入平台 |
| D14 | 材料与私有文件 | 归属、摘要、原用户材料授权及审查范围有效后，读取权与消息原子提交；失败不泄露读取权，待完成上传不可读，原操作恢复不重复占配额 |
| D15 | 原协议任务进展 | 保留上游 taskId、任务状态及无任务响应；不能替换原任务或回退终态；投递台账的调用完成不替代合同完成 |
| D16 | 常驻原协议闭环 | 两端原 Client/Provider 经 WS 收发；每交互 Store、原任务和 Session 独立，模型并发受控；重启恢复已有原件，未知执行不自动重跑 |
| D17 | 提案签认竞争 | 只签认原已开始请求对应的服务方签2卡；容量/用户/期限/当前连接提交前复核；快照、原签3、卡绑定及操作回执原子保存，丢响应不重签 |
| D18 | 具体合同确认 | 无真实合同确认不得签1；完整价款预留成功在先；提案沿原 UUID，待批准在选中后才预留并复签；并发选择不得签出第二张卡，未知结果不重签或重跑审查；窗口内准备、窗口后提交拒绝新选择，不能与过期释放竞争后再生成承诺，原成功操作仍恢复原回执 |
| D19 | 完整履约 | 两模式实际开工、环节用户答复、交付及签4/5/6/7、WASM 报告、AP2 及结清；各事实与原件对应，不能仅验证演示入口 |
| D20 | 同方法多次调用 | 多期 checkout、取件及验收通知各有原操作；当前格式下重启保留原消息、签名、任务与结果，不覆盖早期调用；不要求旧表自动迁移 |
| D21 | 等待与控制 | 生产等待环节/验收时，同交互的原控制可处理并续接原 Session；模型忙或缺失不阻断已有控制，不重复执行 unknown |
| D21a | 显式生产续接 | 按[原生产恢复](../../组件/客户端/服务方端/接口/接单与任务恢复.md#原生产任务的恢复)分别验证真实Host终局来源与所有者审阅来源；工作区伪造日志、空闲/重启、无真实确认均不得伪造证明。未决业务或原生效果、已交付/验收/解除、错误身份/合同/期次/Session/定义、未批准环节及活动执行者拒绝；正确原件和已核效果仅续接原作业。预览变化、拒绝/过期、重复操作、并发恢复、入队/开始前崩溃和新轮未知均不复用旧批准或重复执行；原失败、自测、签名、费用及历史结果保留 |
| D22 | 既有合同与窗口 | 原模板退出公示、意向或新委托许可到期后仍可接收合法原合同证据；新的付款另核许可，开工和履约仍遵守原 A2C 窗口 |
| D23 | 结清与释放 | 缺实际付款、未知开工/签署不得释放；真实结清、容量与通知原子提交；重复结清不新增信誉次数 |
| D24 | 首次履约与任务归属 | 定金 checkout 可先于开工登记有效成约；篡改原承诺、其他卡/用户/Task 均拒绝；Task.op 保留创建方法，环节答复须绑定真实用户与原请求 |
| D25 | 分类预览与发布 | 根据公开能力在实际A2X叶类匹配；路径来自实际目录；无模型/含糊/错误结果请求用户选择，不静默选其他；SDK异步预览不阻塞本机查询，同操作恢复原预览、异输入冲突，发布不重跑匹配；用户确认实际分类后才签署，类别删除或发布修订变化时拒绝，丢发布回执仍恢复原分类和签名 |
| D26 | 服务方起草与错误输入 | 原A2C业务字段、多交付件与真实平台支付声明；有效起草同操作重传/重启保留原有效期，异内容冲突；不签署或公示，不改业务定价；错误输入、鉴权、限流及跨站拒绝使用统一对象，已知拒绝不成为未知结果 |
| D27 | 多期完整履约 | 至少两期经同UUID/Task/Session完成真实HTTP/WS、逐期WASM/确认/原AP2；上期付款前不排产下期，中间期不释放容量；下期授权不复用上期答复。重启、丢付款回复及同名文件保持各期原件；取件前HTTP中断无签6/缓存时给出已知读取失败，可显式重新读取，不把已有签收当失败重签；最终只结清/计信誉一次 |
| D28 | 未开工解除 | 两成约模式先登记原有效卡；无work.start/存证也能按原协议解除，定金仅认实际支付；同卡重传不重签，篡改或跨账号拒绝 |
| D29 | 解除与执行竞争 | 合法解除阻止新业务和签名，已开始工具真实收尾；未知结果不重做或释放。正/零/负余额均经同一UUID/Session结清，缺退款不得释放，重复结清不增信誉 |

## 付款原子性与回执

| 编号 | 场景 | 必须满足 |
|---|---|---|
| P01 | 扣增/回执写入中断 | 账本、paid 和原回执整体提交或回滚；失败后重试不遇到虚假的已付标记 |
| P02 | 并发/重启/丢响应 | 同一原请求只过账一次，返回相同 voucher、Payment Receipt 和 paymentId |
| P03 | 旧 JWT、错对象或改参数 | 新付款核时效与原摘要绑定；同付款键异原请求拒绝，不能复用别人的凭证 |
| P04 | 投影失败 | 真实付款仍有可查询原凭证，不产生第二笔过账 |
| P05 | 旧记录缺原件 | 明确待核实，不重新签凭证或删除已付记录后重付 |
| P06 | 协商退款 | 原服务方真实AP2付款、原个人助手签Checkout；错方向/身份/定金/跨合同拒绝，零余额无假凭证；重启与丢响应恢复同一原件；退款不扩大原预算或允许改选 |

## 争议证据与裁定

| 编号 | 范围 | 必须证明 |
|---|---|---|
| R01 | 原证据预览 | 原双方身份、原提案/合同摘要、签名、实际回执及全部环节历史；无交付时也能核开工期限。查询不建案、不写原业务、不调用模型或付款，缓存不足不伪装无证据 |
| R02 | 理由成立 | 未到期、已收回执/已付款/零额、失败报告、环节停表及原答复均排除错误申请；拟卡费已付但原请求未提交不判服务方超时；未知理由与跨方/跨期拒绝 |
| R03 | 独立复算 | 核实际文件摘要和原市场快照；保留上游pending/程序错误折为fail语义。未完成复算的基础设施异常不签裁定，模型不直接给裁决 |
| R04 | 原申请与终局 | 双方并发、换操作、丢回执和重启均恢复同一案件/最终文书；异内容冲突，评估未知不自动重调；最终提交与真实付款/签7/解除竞争时核最新依据 |
| R05 | 执行与容量 | 原裁定可靠通知；有活动writer或未知工具效果时保留容量，实际收敛后原结束回执只释放一次；已裁定卡不能新增履约/验收/定金或普通card.close，不伪造解除 |
| R06 | 付款与复核 | 全过程不按裁定划转；原已验收款及实际凭证保留。人工复核权限及本案证据范围明确，当事账号不能审自己案件，SDK/模型不能代人提交终局 |
| R07 | 孤儿与重评 | 真正单写所有权之后恢复evaluating为unknown；未知不自动重调模型，已知结果提交丢回执只恢复原结果。独立管理员明确重评同依据且无存活writer；不能改变模型或挑选结果 |
| R08 | 原引用与新轮次 | 错过TTL通知后按admission恢复同caseRef；启动和新宿主轮次取得当前事实，旧幂等开始回执不能复权。普通SDK不能读他人案件或调用管理员复核 |
| R09 | 中立与既有付款 | 人工中立裁定不伪称程序结果、不惩罚服务方成功率；无卡请求裁定只记一次真实信誉。未齐原已验收价款/协商余额时不释放，齐全及实际收敛后仅释放一次；不要求新定金或按裁定过账 |
| R10 | 单一终止型案件 | 同admission改理由、期次、操作或发起方只恢复同caseRef，不重复复算；原操作异内容拒绝；已有终局不覆盖 |
| R11 | 人工发现与证据 | 独立网页管理员能从列表打开并读取本案材料，再提交复核；当事账号、撤权管理员及SDK均不能复核，不能读其他私人文件或消息 |
| R12 | 冻结材料 | 所有权/就绪/大小/实际摘要及交付清单均核验；收到的他人引用不被直接转授；所有分组合计32项，引用不可在恢复时替换，缺所需证据不受理 |
| R13 | 固定模型映射 | 原模型集合和非凭据登记摘要固定；重启或显式重评前映射变化时不调模型、不造裁定，凭据不进入材料或公开结果 |
| R14 | 当前复核事实 | 受理后新增签7、实际付款或解除可完整查看；不因原理由现在不成立丢失最新事实。旧页面提交冲突，不能用冻结申请摘要掩盖状态变化；决定时原卡及原已知结果分别保留 |
| R15 | 决定证据核验 | SDK重算公开决定证据摘要并验签，与本案及原合同绑定；改卡、删付款、换案件、替换摘要、签名时间不符均拒绝。历史有效文书可恢复，不泄露原AP2请求凭据 |
| R16 | 人工操作与补偿 | 活跃评估、当事账号、撤权及SDK均不能人工终局；同操作异内容冲突、已知结果不重算挑选。中立与原程序结果区分，单方解除补偿超期次金额、币种错误或不适用理由均拒绝，不自动付款 |
| R17 | 既有终态与程序边界 | 案件等待期间已合法结清时仅可中立，不覆盖原ledger/信誉或重复释放；其他裁定不覆盖。已知程序归责不翻转，尚未完成复算不人工补判pass/fail，确定性理由已消解仅可中立 |
