## 部署、观察与演示

| 编号 | 场景 | 必须满足 |
|---|---|---|
| E01 | 无 GitHub 的干净部署 | 第三方源码、许可、摘要及预构建资产完整；普通依赖走配置的国内镜像，不使用 VCS 安装或现场网页构建 |
| E02 | 安装单元隔离 | 平台、统一 SDK、九问适配的依赖闭合；九问本体在独立宿主环境；平台环境不安装参与方 Process SDK；技能清单锁定兼容组合；并发读写安装元数据取得完整快照，不把文件替换竞争误作损坏；真实损坏仍停止。验收失败保留目录及原安装任务，不清理仍在工作的环境 |
| E03 | 默认初始化 | 部署清单显式输入内部账号与分类；重复初始化不覆盖已有凭据/状态；参与方自己生成密钥，经同一 SDK 绑定身份和发布服务 |
| E04 | 升级与接管 | 保留原合同、密钥、授权和操作回执；新旧执行器不同时活动；不能接管的在途业务先完成或按协议结束 |
| E05 | 目录与数据 | temp 及私人运行数据不入库；正式 experiments 可复现且不依赖临时文件；Windows 本地与 Linux systemd 分别记录结果 |
| E06 | 场景产物 | 每个 Demo 的源、剧本、素材、视频和证据可关联；共享工具只有一份，跨仓依赖随仓保留来源；迁移路径不篡改旧实测事实或虚升视频依据 |
| E07 | 四片真实用例 | 全局简述平台；服务方真实注册/配置专业能力/技能发布/编程分类/交付/信誉；个人助手真实注册/接入/四处确认/验收支付；四宫格自然语言发布接口、冲突后同交互改约成功；第2—4片完整实录用户接入配置、启动及业务操作，使用户可按对应视频复现；各自剧本与新代码证据完整 |
| E08 | 默认部署闭环 | 核心/参与方/九问分离并核版本、依赖及禁止组件；目标平台锁与输入匹配；本地Git依赖只用随仓wheel；清单变更生成新环境，失败保留现场；首次准备/管理员授权/serve与重启分离，长期进程无管理员凭据  Windows短路径、原生库长度及真实依赖加载通过；目录短摘要须与完整身份核对 |
| E09 | 安装与升级保护 | 未登记目录/越界链接/摘要失配拒绝；原凭据、模型、身份和业务不被重装覆盖；真实释放后备份、切换，未知不强制重做；Windows依赖验证与Linux/systemd实机分别记录 |
| E10 | 部署方九问准备 | 新空工作区有部署归属及真实OS锁；原版公开初始化后由新解释器配置，安装模板和已有用户实例不变；缺模型不就绪；中断恢复原资源不重复创建，冲突不覆盖；重装保留模型/权限/技能修改并从公开目录解析选择键，不泄露密钥 |
| E11 | 默认部署入口 | 单一受管布局与本地源码输入；独立build和三运行环境；两个系统账号的真实目录/凭据隔离；实际8账号50服务及ISC_001同SDK接入；启动不请求模型生产；不走旧轮询入口 |
| E12 | 管理员预设 | root固定预设准备仅限本部署ISC_001的两个接口；原确认及发布可恢复，模型/普通用户不得取得此权；缺邮件明确停用会议；重装保留人工修改/停用及原通知回执 |
| E13 | 升级闭环 | 候选先核验；实际SDK锁和原控制组已释放后备份；三个环境与发行资源随一个集合原子切换；保存原身份/合同/会话/未知效果，恢复此前实际运行及原开机设置；中断继续原升级操作，不强杀、不自动恢复旧数据、不重新授权或赠币 |
| E14 | 安装任务与服务账号 | 前台退出后原安装临时service继续，重复命令观察同一任务；主进程结束但组仍有进程时禁止二次执行。真实低权限账号可读取/执行已安装环境及SDK安装身份，不能写环境或读取核心/部署私有凭据；后续工作区查询不生成root所有文件 |
| E14 | 显式登录恢复 | 同一OS锁且不碰身份/业务；有效缓存不赠币，失效时仅显式新登录，丢响应恢复原操作；输入改变或账号ID变更拒绝；明确拒绝、限流、5xx及未知结果分开；双Skill和真实安装包入口均验证 |

私钥、模型密钥、通知凭据不得出现在日志或提交中。普通接入、官方配置和演示场景应分别验证，不能以演示专用路径代替通用产品验收。

观察用真实证据核对阶段、收入与消息状态；普通账号只能获得获准数据；平台网页不读取本地收信处理正文，配置详情通过九问本地入口查看。管理员全景同时出现多发起方委托和助手通信；匿名示意不计真实事件。四段 Demo 的剧本、镜头、旁白和证据要求见[演示制作](../../示例/演示制作.md)。

基础检查：`python 设计/check.py`、`python tools/check_docs.py`、`python -m pytest -q tests`、`python tools/selfcheck.py`。接入安装和完整端到端另按对应产物入口执行；基础检查通过不等于新增架构已经完成。

## 官方服务部署与续期

| 编号 | 范围 | 可核验条件 |
|---|---|---|
| S01 | 默认配置 | 安装包生成8个ISP运行时及50个服务profile；通过实际SDK绑定、上传验收包、授权、公示和A2X索引；不新增核心执行器或50项启动模型任务 |
| S02 | 授权隔离 | 普通外部账号和受限SDK不能设置部署授权；越身份、条款、寿命及授权修订均拒绝；原正常用户确认仍必需且无confirmed快捷参数；同一操作固定授权来源，后增授权不绕过原待确认、拒绝或过期 |
| S03 | 批量与竞争 | 授权设置原子比较，失败不部分提交；重传、丢响应及写事务前被撤权正确；提交公示时再次核当前授权 |
| S04 | 轮换 | 启动及周期按30天/7天/60秒策略检查；实际原模板仍有效可复用，到期不用于新委托；续期生成新摘要，原合同及原Session仍可完成 |
| S05 | 重启和未知 | 保留原身份/引用/签名请求/操作；重复启动不重新赠币、不覆盖暂停或撤销，不重签未知发布；索引失败恢复当前投影而不覆盖新修订 |
| S06 | 人工变更 | 所属方修改公开条款后旧自动授权停用；旧启动器不能回滚新条款；再次配置须明确授权新范围 |
| S07 | 真实执行 | 至少一项由原版九问经同一部署入口完成实际生产、WASM验收、AP2付款及信誉；记录模型/Session/原卡，不拿批量桩代替真实业务 |
| S08 | 发行与部署 | 模块、资源、路径及精确依赖摘要随包；离开源码目录可安装运行，无部署期GitHub访问；Windows与Linux分别证明，旧入口仅在整体切换后归档 |
| S09 | 启动器恢复 | 准备无公示/模型，真实引用与操作先保存；中断恢复同一身份；已完整配置及人工编辑不覆盖；严格授权缺失不生成确认；启动/状态不读取私钥或业务库，状态无副作用；到期观察含已过期原件，原合同不改 |
| S10 | 安全停止 | 活动作业期间等待且原已授权工具可收尾；跨异步线程保留原作业许可，排队/已结束/等待用户/异实例不得借用，离线仍拒绝；排空答复与OS锁释放分开；丢回复、IPC暂失、启动中及原安装/配置变化均保留原对象；换bootId或身份不符拒绝；占部署锁不并发停止；超时返回waiting，原合同/密钥/未知结果与会话保留 |
