# 部署教程

新装创建独立目录；再次部署先停止并核清本部署的旧进程，再保留原数据、账号、工作区和模型配置重新部署。不要删除数据库、配置或锁文件来重试。以下路径可整体替换为自己的专用路径。

> 整理中：新装命令已按公开入口核对；保数据换发行重部署、Linux HTTPS与三席试用仍待部署负责人实机交接。本稿不承诺这些环节已经可用。

## Windows本地部署

需要 Windows x64、Git、CPython 3.11 和浏览器，不需要 Docker、WSL、Node/npm 或外接数据库。以下在 PowerShell 执行。

**1. 获取源码。** 下载含固定依赖的完整仓库，再进入目录。

```powershell
git -c http.proxy= -c https.proxy= clone https://gitcode.com/WeiZheng96/jiuwen-IoA-lab.git D:\ioa-source
Set-Location D:\ioa-source
```

**2. 先停止旧部署。** 新装跳过；已有 `D:\ioa-local` 实例时，在原源码目录运行以下命令，请求停止该部署，并查询结果。若返回 `waiting`，继续查询直到 `phase=stopped` 且 `allOwnedJobsEmpty=true`；失败时保留现场并停止后续操作。

```powershell
py -3.11 -m deploy.windows_local stop --home D:\ioa-local
py -3.11 -m deploy.windows_local status --home D:\ioa-local
```

**3. 构建发行。** 第一条创建构建环境；第二条保存解释器路径；第三条从国内镜像安装固定构建依赖。

```powershell
py -3.11 -m venv temp\deployment-build
$BuildPython = (Resolve-Path temp\deployment-build\Scripts\python.exe).Path
& $BuildPython -m pip install --index-url https://pypi.tuna.tsinghua.edu.cn/simple -r deploy\locks\build.lock
```

以下构建 Windows 发行并保存输出，失败即停止；最后两条取得发行目录与资源安装位置，供后续命令使用。

```powershell
& $BuildPython -m tools.build_deployment --target windows-x86_64 --out dist\windows | Tee-Object temp\deployment-build.log
if ($LASTEXITCODE -ne 0) { throw '发行构建失败' }
$Release = (Get-Content temp\deployment-build.log -Tail 1).Trim()
$Assets = Join-Path 'D:\ioa-local\runtime\envs\releases' (Split-Path $Release -Leaf)
```

**4. 填写模型与管理员配置。** 仅新装执行第一条，生成受限私有配置及随机内部密钥；第二条用记事本打开配置。已有实例只编辑原文件，不重跑初始化。

```powershell
& $BuildPython -m deploy.configure --root D:\ioa-local\runtime --state D:\ioa-local\data --config-dir D:\ioa-local\config --assets $Assets
notepad D:\ioa-local\config\core\platform.json
```

在编辑器中填写下表字段，保存并关闭。API key 只写文件，不贴入命令或聊天。

| 字段 | 填写内容 |
|---|---|
| `llm.api_key` | 自己的模型服务 API key |
| `llm.base_url` | 该 key 对应的 OpenAI 兼容 API 地址，例如阿里云百炼 `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| `llm.model` | 服务商允许调用的主模型名称 |
| `llm.discovery_model` | 可调用的检索模型名称，可与主模型相同 |
| `llm.embedding_model` | 可调用的嵌入模型名称；阿里云示例为 `text-embedding-v4` |
| `admin.password` | 自己设置的管理员密码，账号默认 `admin` |

保留 `runtime.public_url=http://127.0.0.1:8750` 和回环监听。首次安装使用选定主模型准备独立的官方服务及管理员九问工作区；已有工作区保留原模型设置，不因编辑平台文件自动覆盖。

**5. 安装并启动。** 第一条创建只含配置路径与安装选项的对象；第二条保存为 JSON，不含 API key。

```powershell
$Install = @{ platform_config='D:\ioa-local\config\core\platform.json'; pypi_index='https://pypi.tuna.tsinghua.edu.cn/simple'; max_model_runs=2 }
$Install | ConvertTo-Json -Depth 8 | Set-Content -Encoding utf8 D:\ioa-installation.json
```

以下依序安装三个运行环境、启动所属进程、查询状态。启动返回 `waiting` 时继续查询，直到 `running`；失败时保留原目录。

```powershell
& $BuildPython -m deploy.windows_local install --home D:\ioa-local --release $Release --environments D:\ioa-env --config D:\ioa-installation.json
& $BuildPython -m deploy.windows_local start --home D:\ioa-local
& $BuildPython -m deploy.windows_local status --home D:\ioa-local
```

> 当前公开 `install` 只支持同一发行复用，换发行会拒绝。保数据换发行的普通重部署步骤待公开入口发布后收口，不能删除安装记录绕过。

**6. 使用与停止。** 浏览器打开 `http://127.0.0.1:8750/`，用 `admin` 及第4步保存的密码登录。原版九问网页为 `http://127.0.0.1:18753/?user_id=ioa-admin`。结束使用时重复第2步，数据和配置保留。

分别检查平台实际模型检索、官方宿主无业务问答和本人九问无业务问答。配置标志、服务目录或 HTTP 200 不能代替模型回答；不使用签约、付款或邮件验证部署。

## Linux服务器远程部署

需要 Linux x86_64、CPython 3.11、systemd、cgroup v2、sudo、Git、Nginx 与可访问的国内包镜像。先确定公共 HTTPS 地址和可用证书，平台首次初始化后不改公共地址。采用运行根 `/opt/ioalab-runtime`、状态根 `/var/lib/ioalab`、配置根 `/etc/ioalab`。

**1. 连接服务器。** 在本机终端运行以下命令，将 `SERVER_IP` 换成真实地址。首次连接核对服务器指纹；此命令不经过 SSH 代理跳板。

```powershell
ssh -o ProxyCommand=none -o ProxyJump=none root@SERVER_IP
```

**2. 获取源码。** 在服务器 Bash 执行以下命令，从 GitCode 下载完整源码，再进入目录。服务器不需要访问 GitHub 或从 VCS 下载依赖。

```bash
git -c http.proxy= -c https.proxy= clone https://gitcode.com/WeiZheng96/jiuwen-IoA-lab.git /root/ioalab-source
cd /root/ioalab-source
```

**3. 先停止旧部署。** 新装跳过；已初始化部署在其原源码目录执行公开停止并查询状态。`waiting`继续查询；只有`allOwnedGroupsEmpty=true`且`executionLocksReleased=true`才继续。尚未完成的旧部署按部署技能的异常入口核归属清退并归档原数据，不删除锁或数据库重试。

```bash
sudo python3.11 -m deploy stop --state /var/lib/ioalab --wait-seconds 30
sudo python3.11 -m deploy status --state /var/lib/ioalab
```

**4. 填写模型与地址。** 新装执行第一条，认领独立目录并生成唯一私有配置；第二条打开文件。已有配置保留，停止后仅编辑原文件。

```bash
sudo python3.11 -m deploy.configure --root /opt/ioalab-runtime --state /var/lib/ioalab --config-dir /etc/ioalab
sudoedit /etc/ioalab/core/platform.json
```

填写 Windows 第4步表中的模型及管理员字段，无需开发者 profile。另设 `runtime.public_url` 为已确定的 `https://域名或公网IP`，保持 `runtime.bind=127.0.0.1`、`runtime.port=8750`；`authentication.trusted_proxy_addresses` 填 `["127.0.0.2"]`，与反代的独立来源一致。保存并退出，密钥不进入命令、Git或普通日志。

**5. 准备 HTTPS。** Nginx 根路径和 `/ws/` 均代理到 `127.0.0.1:8750`，使用 `proxy_bind 127.0.0.2`，覆盖 `X-IOALAB-Client-IP` 为真实 `$remote_addr`，并开启 WebSocket 升级。证书安装、可信链及续期命令待服务器负责人实机交接；现有 Nginx 模板只有域名示例，不能直接当作公网 IP 证书方案。

**6. 安装。** 第一条创建受限输入目录；第二条复制不含密钥的安装选项模板；第三条打开它，核 `platform_config=/etc/ioalab/core/platform.json`、国内 `pypi_index` 与 `max_model_runs=2` 后保存。

```bash
sudo install -d -m 700 /etc/ioalab-bootstrap
sudo install -m 600 deploy/deployment.json.example /etc/ioalab-bootstrap/deployment.json
sudoedit /etc/ioalab-bootstrap/deployment.json
```

第一条提交独立 systemd 安装任务，SSH 断开后仍继续；第二条查询同一任务，重复查询直到 task.status=completed、lastReadiness.runtimeReady=true，且所属单元及官方服务实际就绪；外层 status=completed 只表示查询成功。失败保留任务、日志和原数据。

```bash
sudo bash deploy/install.sh --config /etc/ioalab-bootstrap/deployment.json
sudo python3.11 -m deploy status --state /var/lib/ioalab
```

**7. 检查并访问。** 第一条检查核心回环接口；第二条读取核心最近日志。然后用浏览器访问第4步配置的公共 HTTPS 地址，以自己的管理员密码登录。

```bash
curl --noproxy '*' --fail http://127.0.0.1:8750/api/config
sudo journalctl -u ioalab-core.service -n 30 --no-pager
```

管理员九问只监听回环。在本机另开终端，以下命令把服务器网页转发到本机；保持终端运行，再打开 `http://127.0.0.1:18753/?user_id=ioa-admin`。

```powershell
ssh -o ProxyCommand=none -o ProxyJump=none -N -L 18753:127.0.0.1:18753 root@SERVER_IP
```

分别检查平台实际模型检索、官方宿主无业务问答和个人助手无业务问答，不以配置存在代替三类模型已可调用。未配置邮件时会议通知保持禁用。

三席在线试用是独立应用，不能靠填平台 key 自动开通。供应商 key 只归模型 sidecar，席位仅持本轮 token 和内网代理地址。当前尚缺完整实机就绪与常规开通交接，本教程不将其写成已经开放；纳入常规交付时须在本节补齐已验证的创建、模型、HTTPS及检查命令，不要求读者另找必需步骤。
