# 部署

## 目的与范围

职责：规定交付、安装、进程、配置和运行数据管理。项目目录与依赖方向以[架构](../架构.md)为准；实际可运行命令及迁移状态见[开发计划](../../docs/开发计划.md)与部署产物。本页不把设计要求当作已验证结果。

## 交付与安装单元

| 单元 | 源位置 | 安装与资源边界 |
|---|---|---|
| 平台 `ioalab` | `src/platform/` | 包含五个中心、观察和 Web；不安装参与方执行器、九问 Process SDK 或九问本体 |
| 统一 SDK `ioalab-sdk` | `src/access/sdk/` | 包含两个角色模块与共用常驻组件；不导入平台源码、九问实现或官方场景 |
| 九问适配 `ioalab-jiuwen` | `src/hosts/jiuwen/` | 启动装配、公开接口适配和扩展资源；依赖统一 SDK 及固定的九问 Process SDK，通过 AgentHost 边界注入 |
| 产品接入技能 | `src/access/skills/assistant/`、`src/access/skills/provider/` | 包含技能、流程、配置引导、确定性调用脚本和依赖安装清单；复用兼容的 SDK/适配环境 |
| 可选官方资源/工具 `ioalab-official` | `src/official/` | 服务定义、模板、验收器、管理员预设与业务工具；安装包在本目录构建，由通用运行时加载，不建立专属执行引擎；核心 SDK 不反向依赖 |
| 原版九问及第三方依赖 | `vendor/` | 固定源码与发行物；九问本体安装在独立宿主环境，源码不归入自研适配包 |

三个 Python 发行包使用各自实际产物 VERSION，不从设计 VERSION 推断实现完成。接入发布清单记录 SDK、适配、技能、Process SDK 的兼容组合及摘要；官方资源包另列资源和工具依赖。产物依据的归属见架构，迁移目录不自动升级依据。

仓库根 `requirements.txt` 只作为开发环境入口；生产环境按安装单元使用明确依赖清单。可安装包通过包资源或显式配置定位文件，不读取相邻源码目录；运行入口不手工修改 `sys.path`，资源定位不隐含依赖调用者工作目录或相邻 A2C 仓库。

Python 发行包从隔离源码快照构建，排除 build、dist、egg-info、字节码和开发环境；构建后按源码清单核对模块，已有构建缓存不得使已删除的旧模块重新进入安装包。

## 进程与网络

采用 Linux、Python 3.11、隔离 venv、systemd 和可选 Nginx，不要求 Docker。开发环境兼容 Windows。只有平台公共 HTTPS/WSS 入口必须可达；个人助手和服务方主动连接，不要求公网 IP、端口映射或用户服务反代。

| 实例 | 内容 | 数据与模型 |
|---|---|---|
| 平台核心 | 身份、注册、委托、支付、消息、观察与 Web | 平台数据库/机构密钥；发现和仲裁模型独立配置 |
| 官方服务 | 用 SDK 共用运行时加载官方服务配置，经九问适配按需执行 | 独立服务密钥、合同、工具和会话；独立模型设置 |
| 管理员助手 | 同一运行时的个人助手角色及原版九问，自动配置 ISC_001 | 独立账号、日程、通知凭据和会话 |
| 普通参与方 | 自己电脑/服务器上的运行时及九问 | 用户自己的本地数据、模型、技能和工具 |
| 实验客户端 | 通过公开 SDK 产生委托与助手通信 | 独立实验身份与可追溯输入，标记 experiment |

核心默认本地 8750。反代支持 `/ws/agents` 与 `/ws/admin` 升级、心跳和足够空闲超时；断线由运行时恢复，反代不能将消息缓存成另一套投递队列。正式外网使用 TLS，回环测试可显式使用明文。

安装顺序：安装核心 → 初始化账号与分类 → 配置官方服务及管理员助手 → 校验九问/模型/工具 → 绑定身份并发布 → 建立连接 → 开放接单。未配置模型或通知能力时显示具体不可用项，不能用桩替代真实运行。

部署清单显式选择 `src/official/` 的资源及初始化数据，通过受控本机初始化命令或管理员授权入口创建内部账号与分类。核心校验传入数据，不跨目录读取官方参与方源码；初始化不能覆盖已有账号凭据或重置运行状态。自有JSON来源的清单摘要按UTF-8/LF规范字节计算，Windows检出产生的CRLF不改变同一来源；业务内容变化仍使摘要失效。第三方归档与wheel继续按原始字节核验，不做换行归一。私钥由参与方本地创建，身份绑定与服务模板发布通过同一 SDK 完成，不能把初始化当作代签。

## 配置归属

| 所属方 | 字段组与默认规则 |
|---|---|
| 核心 | `IOALAB_BIND/PORT/PUBLIC_URL/DATA/SECRET`；公共地址首次初始化后锁定 |
| 账号策略 | `IOALAB_MODE`、`IOALAB_REGISTRATION`、`IOALAB_ISC_COUNT`（默认10）、`IOALAB_AUTOSEED`、`IOALAB_LOGIN_CREDIT`（默认100） |
| 初始化输入 | `IOALAB_SEED_FILE` 指向部署清单生成的 JSON；包含 domains，各项为内部提供者 account、label、A2X category 及公开服务摘要；自动初始化启用时必须可读取并通过校验，原始业务能力与验收器仍由官方参与方管理 |
| 技能分发 | `IOALAB_BUNDLES_DIR` 指向构建后的接入包目录，默认当前启动目录下 dist；部署器填写安装位置的绝对路径。平台仅从该显式目录提供固定文件名下载，包内不含本地账号或凭据 |
| 管理员初始化 | `IOALAB_ADMIN_PASSWORD/ASSISTANT_PASSWORD`；trial 使用至少12位强口令，自动生成时写受限本地文件，不打印日志 |
| 消息策略 | `IOALAB_MESSAGE_TTL_DAYS/RETENTION_DAYS/METADATA_DAYS/PENDING_LIMIT/RATE`；默认值及语义以[消息中心](../组件/消息中心.md)为准 |
| 连接策略 | `IOALAB_CONNECTION_TICKET_SECONDS` 默认60（1—300）；`IOALAB_WS_HEARTBEAT_SECONDS` 默认15，`IOALAB_WS_LEASE_SECONDS` 默认45且至少为心跳的三倍 |
| 核心模型 | `IOALAB_LLM_API_KEY/BASE_URL`、A2X/embedding 选择及 `IOALAB_ARBITRATION_MODELS`；不下发给用户 |
| 参与方 | `IOALAB_BASE_URL/USERNAME/PASSWORD/HOME`，由接入技能本地设置导入运行时；不写入主接入技能文本或核心配置 |
| 服务容量 | 本地服务配置 `max_active_delegations`，启动后经认证同步权威接单台账；降低上限不取消已有合同 |
| 执行并发 | 运行时 `max_model_runs`，默认2；变更只限制新模型任务，不中断已运行任务 |
| 九问宿主 | `IOALAB_SWARM_COMMAND` 为 JSON argv；`IOALAB_SERVICE_MODEL` 采用原生 model.list 的 selection_key；独立 `JIUWENSWARM_DATA_DIR` |
| 验收 | 本地 `A2C_CACHE_DIR`；正常 L2 使用本地 verifier 模型配置，仲裁使用平台明确登记的模型 |
| 业务工具 | `src/official/tools/` 提供可选工具，日程、AgentMail/SMTP、可预约规则按[会议示例](../示例/会议预约.md)归属助手本地配置；普通用户不因安装通用技能而获得邮箱权限 |
| 测试 | `IOALAB_STUB` 只能显式启用；生产缺依赖必须报错 |

核心只从环境变量读取其配置，不遍历用户凭据文件。接入技能配置文件仅由本地运行时读取。新增字段必须在所属配置模板中登记类型、默认、是否敏感及生效时点，文档不能作为唯一“实现”。连接票据有效期、心跳和重连退避属于传输配置，不改变合同期限。

## 依赖与发布

所有 Git 源码依赖随本仓固定，按 `vendor/SOURCES.json` 保存来源、提交、许可证、摘要及构建信息。服务器不访问 GitHub，不使用子模块、VCS 安装或现场 Node/npm 网页构建。可从部署方配置的 GitCode 远端同步或导入完整源码目录；来源 URL 仅用于追溯。

| 依赖 | 发布形式 |
|---|---|
| A2X | 普通源码快照；本平台分类数据由本仓配置生成 |
| A2C、九问 Process SDK | 锁定 wheel，并保留相应源码来源与摘要 |
| 九问及其 Git 依赖 | 原始固定源码归档、许可证、预构建 wheel；网页资产随包 |
| 普通 PyPI 依赖 | 锁定依赖及部署者可访问的国内镜像；不宣称全离线 |
| 产品接入技能 | 从源构建安装包，包含 SDK、九问适配、A2C 和固定 Process SDK 的 wheels、引导与校验清单；两个技能使用同一兼容清单，生成物不回拷为第二份源码 |

技能安装脚本先验证清单与摘要，在用户目录准备隔离接入环境；相同账号、相同实例的另一角色复用已有运行时，仅增加角色配置。依赖或状态版本不兼容时停止接管并明确报告，不同时启动两个身份库写入者。SDK 的调用脚本经本机认证的 IPC 操作常驻组件，不另开同一身份数据库。

不修改九问源码或全局指令。部署方安装器关闭自动更新和非必需外部技能市场，保留已有账号、授权、技能与模型设置；普通用户技能安装只检测已有九问，不自动替换宿主。可选联网工具由使用者另行配置。宿主适配先检查公开能力，不使用网页内部资源 ID 代替进程模型选择键；真实用户答复关联不可用时保持待确认。

## 运行与数据迁移

| 目录 | 数据性质与管理 |
|---|---|
| `data/` | 持久身份、密钥、业务数据库、日程及本地配置；不入库，按所属方备份 |
| `logs/`、`recordings/` | 运行日志、原始录屏及浏览器状态；不入库，公开证据经脱敏另行发布 |
| `dist/` | 可再生成的安装包；不入库，构建输入和摘要受版本管理 |
| `temp/` | 一次性调查、临时文档和脚本；由仓库忽略规则排除，不作为部署输入或持久数据目录 |
| `experiments/` | 正式可复现实验源码与非私密配置；入库，通过公开 SDK 运行，实测私有数据仍放运行目录 |

核心、服务、助手分别备份；数据库和业务文件使用一致性快照，恢复后核对签名、支付操作与接单台账，再开放新任务。部署、SDK、业务工具不得隐含读取临时目录才能工作。

停止新接单后，已有合同继续收发和履约。升级需保留身份、原合同、模板、授权、支付与投递回执；不能清理数据来规避期限或容量。尚未具备新运行时接管条件的合同先在原执行环境完成或按协议结束；新旧执行器不能同时持有同一智能体的活动执行权。

模型调用中断后先核操作回执再恢复。业务工具使用运行时传入的稳定操作键保存业务回执；工具自己的预约/邀请状态与运行时检查点分别管理，邮件/付款结果未知不得自动重做。离线期间合同计时继续。队列、磁盘和配额达到上限应拒绝新业务并可观察，保留已有合同的控制及恢复通道。

验收分别覆盖无 GitHub 的依赖安装、原版九问接入、协议闭环和 Linux 实机/systemd；各层证据独立保存。部署成功不自动代表真实邮件、原生网页审批或视频质量已验收。
