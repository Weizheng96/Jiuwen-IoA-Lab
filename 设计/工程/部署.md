# 部署

## 目的与范围

职责：规定安装、进程、配置和运行数据管理。实际可运行命令及迁移状态见[开发计划](../../docs/开发计划.md)与部署产物；本页不把设计要求当作已验证结果。

## 进程与网络

采用 Linux、Python 3.11、隔离 venv、systemd 和可选 Nginx，不要求 Docker。开发环境兼容 Windows。只有平台公共 HTTPS/WSS 入口必须可达；个人助手和服务方主动连接，不要求公网 IP、端口映射或用户服务反代。

| 实例 | 内容 | 数据与模型 |
|---|---|---|
| 平台核心 | 身份、注册、委托、支付、消息、观察与 Web | 平台数据库/机构密钥；发现和仲裁模型独立配置 |
| 官方服务 | 用通用运行时加载官方服务配置，按需调用九问 | 独立服务密钥、合同、工具和会话；独立模型设置 |
| 管理员助手 | 通用个人助手运行时及原版九问，自动配置 ISC_001 | 独立账号、日程、通知凭据和会话 |
| 普通参与方 | 自己电脑/服务器上的运行时及九问 | 用户自己的本地数据、模型、技能和工具 |
| 实验客户端 | 通过公开 SDK 产生委托与助手通信 | 独立实验身份与可追溯输入，标记 experiment |

核心默认本地 8750。反代支持 `/ws/agents` 与 `/ws/admin` 升级、心跳和足够空闲超时；断线由运行时恢复，反代不能将消息缓存成另一套投递队列。正式外网使用 TLS，回环测试可显式使用明文。

安装顺序：核心与种子 → 配置官方服务及管理员助手 → 校验九问/模型/工具 → 绑定身份并发布 → 建立连接 → 开放接单。未配置模型或通知能力时显示具体不可用项，不能用桩替代真实运行。

## 配置归属

| 所属方 | 字段组与默认规则 |
|---|---|
| 核心 | `IOALAB_BIND/PORT/PUBLIC_URL/DATA/SECRET`；公共地址首次初始化后锁定 |
| 账号策略 | `IOALAB_MODE`、`IOALAB_REGISTRATION`、`IOALAB_ISC_COUNT`（默认10）、`IOALAB_AUTOSEED`、`IOALAB_LOGIN_CREDIT`（默认100） |
| 管理员初始化 | `IOALAB_ADMIN_PASSWORD/ASSISTANT_PASSWORD`；trial 使用至少12位强口令，自动生成时写受限本地文件，不打印日志 |
| 消息策略 | `IOALAB_MESSAGE_TTL_DAYS/RETENTION_DAYS/METADATA_DAYS/PENDING_LIMIT/RATE`；默认值及语义以[消息中心](../组件/消息中心.md)为准 |
| 核心模型 | `IOALAB_LLM_API_KEY/BASE_URL`、A2X/embedding 选择及 `IOALAB_ARBITRATION_MODELS`；不下发给用户 |
| 参与方 | `IOALAB_BASE_URL/USERNAME/PASSWORD/HOME`，由 接入技能本地设置导入运行时；不写入主接入技能 文本或核心配置 |
| 服务容量 | 本地服务配置 `max_active_delegations`，启动后经认证同步权威接单台账；降低上限不取消已有合同 |
| 执行并发 | 运行时 `max_model_runs`，默认2；变更只限制新模型任务，不中断已运行任务 |
| 九问宿主 | `IOALAB_SWARM_COMMAND` 为 JSON argv；`IOALAB_SERVICE_MODEL` 采用原生 model.list 的 selection_key；独立 `JIUWENSWARM_DATA_DIR` |
| 验收 | 本地 `A2C_CACHE_DIR`；正常 L2 使用本地 verifier 模型配置，仲裁使用平台明确登记的模型 |
| 业务工具 | 日程、AgentMail/SMTP、可预约规则按[会议示例](../示例/会议预约.md)归属助手本地配置 |
| 测试 | `IOALAB_STUB` 只能显式启用；生产缺依赖必须报错 |

核心只从环境变量读取其配置，不遍历用户凭据文件。接入技能配置文件仅由本地运行时读取。新增字段必须在所属配置模板中登记类型、默认、是否敏感及生效时点，文档不能作为唯一“实现”。连接票据有效期、心跳和重连退避属于传输配置，不改变合同期限。

## 依赖与发布

所有 Git 源码依赖随本仓固定，按 `vendor/SOURCES.json` 保存来源、提交、许可证、摘要及构建信息。服务器不访问 GitHub，不使用子模块、VCS 安装或现场 Node/npm 网页构建。可从部署方配置的 GitCode 远端同步或导入完整源码目录；来源 URL 仅用于追溯。

| 依赖 | 发布形式 |
|---|---|
| A2X | 普通源码快照；本平台分类数据由本仓配置生成 |
| A2C、九问 Process SDK | 锁定 wheel，并保留相应源码来源与摘要 |
| 九问及其 Git 依赖 | 原始固定源码归档、许可证、预构建 wheel；网页资产随包 |
| 普通 PyPI 依赖 | 锁定依赖及部署者可访问的国内镜像；不宣称全离线 |
| 产品接入技能 | 打包所需 SDK/wheel、引导与校验清单；两种接入技能 复用同一依赖清单 |

不修改九问源码或全局指令。安装器关闭自动更新和非必需外部技能市场，保留已有账号、授权、技能与模型设置；可选联网工具由使用者另行配置。宿主适配先检查公开能力，不使用网页内部资源 ID 代替进程模型选择键。

## 运行与数据迁移

数据目录、私钥、日程、模型凭据、浏览器状态和原始私人消息不入库。核心、服务、助手分别备份；数据库和业务文件使用一致性快照，恢复后核对签名、支付操作与接单台账，再开放新任务。

停止新接单后，已有合同继续收发和履约。升级需保留身份、原合同、模板、授权、支付与投递回执；不能清理数据来规避期限或容量。尚未具备新运行时接管条件的合同先在原执行环境完成或按协议结束；新旧执行器不能同时持有同一智能体的活动执行权。

模型调用中断后先核操作回执再恢复，邮件/付款结果未知不得自动重做。离线期间合同计时继续。队列、磁盘和配额达到上限应拒绝新业务并可观察，保留已有合同的控制及恢复通道。

验收分别覆盖无 GitHub 的依赖安装、原版九问接入、协议闭环和 Linux 实机/systemd；各层证据独立保存。部署成功不自动代表真实邮件、原生网页审批或视频质量已验收。
