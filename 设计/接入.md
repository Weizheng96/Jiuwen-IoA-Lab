# 接入

## 一、委托方：九问 swarm 作个人助手

**形态**：jiuwenswarm 连接器包，`integration.type = skill-only`（无 MCP 进程）；用户在连接器里填平台地址、用户名、密码（`token-schema.json` 三个字段，
swarm 注入环境变量 `IOALAB_BASE_URL · IOALAB_USERNAME · IOALAB_PASSWORD`）；技能 `SKILL.md` 指导 swarm 用 bash 调 `scripts/ioalab.py <子命令>`，脚本只用标准库，输出 JSON。
没有连接器市场的 swarm 把 `skills/ioalab-delegate/` 复制进技能目录、在脚本旁 `config.json` 填账号即可。

```
connector/ioalab-client/
  manifest.json          package_type mcp · id ioalab-client · integration {type: skill-only} · credentials {type: token, file: token-schema.json} · skills [{dir: skills/ioalab-delegate}]
  token-schema.json      IOALAB_BASE_URL（text）· IOALAB_USERNAME（text）· IOALAB_PASSWORD（password）
  icon.png
  skills/ioalab-delegate/SKILL.md      流程表 · 必须请用户确认的操作 · 规则（照 A2C 主仓 a2c-client 技能）
  skills/ioalab-delegate/scripts/ioalab.py
```

**分工**：swarm 做发现 → 比较 → 拟卡 → 签字 → 开工，并答复确认；平台保管密钥与 Client、跑签约后的固定流程。swarm 侧每 60 s 心跳 `status` + `confirmations`，有待确认即 `ask_user`。

**必须请用户确认再调**：`sign` · `request`（付拟卡费）· `adopt` · `start`（付定金）· `answer`（验收付款 · 环节授权 · 是否仲裁）· `terminate`。

### REST（`/api/v1`，`Authorization: Bearer <token>`）

| 方法 路径 | 作用 |
|---|---|
| `POST /token` | 用户名密码 → token（首次自动注册个人助手） |
| `GET /me` | 账号 · 助手 id · 余量 · 待确认 |
| `POST /delegations` | 下需求：`{text, scope{budget, category, sign1, sign7, validity}, autoSign}`，驾驭方式记 `external` |
| `POST /delegations/{nid}/materials` | 上传材料（multipart，≤ 2 MB/件 · ≤ 10 件）→ `{name, declared}` |
| `POST /delegations/{nid}/search` | `{query, top_k}` → 候选服务方（经交易中心检索，记事件） |
| `GET /providers/reputation?provider=` · `GET /providers/templates?provider=` | 信誉条目 · 合同模板摘要 |
| `POST /delegations/{nid}/cards` | `{templateDigest, cardId, spec, materials[]}` → 拟卡（派生价 · 预算 · 输入预检 · 提示） |
| `POST /cards/{cd}/sign` | 签1；待批准型随即请复签 → `{countersigned, reason}`；需确认时回 `{pending: cid}` |
| `POST /delegations/{nid}/requests` · `POST /cards/{cd}/adopt` | 提案型：发提案卡（付拟卡费）· 采纳服务方拟的卡 |
| `POST /cards/{cd}/start` | 付定金 · 交材料 · 开工 · 订阅存证 |
| `GET /delegations/{nid}` · `GET /delegations/{nid}/events?after=` | 需求 + 订单 + 待确认 + 事件 |
| `GET /confirmations` · `POST /confirmations/{cid}` `{granted}` | 待确认清单 · 答复 |
| `POST /cards/{cd}/pay/{period}` · `POST /cards/{cd}/arbitrate` `{period, ground}` · `POST /cards/{cd}/terminate` | 补付本期款 · 申请仲裁 · 解除 |
| `POST /delegations/{nid}/abandon` | 放弃（无卡时） |
| `GET /orders/{cd}/deliveries/{period}` | 下载本期交付件 |

事件与订单与平台驾驭的助手完全同形，管理员全景按账号聚焦即可看到 swarm 驾驭的那一路。

## 二、服务方：外部专业智能体

内部服务方全在进程内。外部服务方运行在别处，由平台**出站**访问，接入步骤：

| 步 | 做法 |
|---|---|
| 1 | 用 a2c 服务方 SDK + a2a-sdk 起一个 A2A 应用（声明 A2C 扩展），样例 `examples/external_provider/` |
| 2 | 验收器包上传到平台：`POST /api/v1/provider/packages`（登录态，≤ 256 KB，只认 script）→ `ioalab://pkg/<digest>` 写进模板 |
| 3 | 模板 `paymentProvider` 填平台支付方 `<PUBLIC_URL>/a2a/pay`；向公开的 `<PUBLIC_URL>/a2a/market` 发 `template.endorse` 取市场签认 |
| 4 | `POST /api/v1/provider/register {url, name, description, tags, domain, ap2_jwk}`：平台取 `url/.well-known/agent-card.json` 与 JWKS → 市场认证（公钥进 `Directory`）→ 登记 AP2 收款公钥 → `agents` 行 `ext-<slug>`（`meta.url`）→ 按 `domain` 确定性归入分类树 |
| 5 | 收款归注册账号的钱包；结清按市场 ledger 判定；对外部服务方的调用带超时与失败记账 |

内部服务方仍只放行回环；外部服务方不能反向调用内部服务方。
