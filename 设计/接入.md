# 接入

## 一、委托方：九问 swarm 作个人助手

**形态**：jiuwenswarm 连接器包，`integration.type = skill-only`（无 MCP 进程）；用户在连接器里填平台地址、用户名、密码（`token-schema.json` 三个字段，
swarm 注入环境变量 `IOALAB_BASE_URL · IOALAB_USERNAME · IOALAB_PASSWORD`）；技能 `SKILL.md` 指导 swarm 用 bash 调 `scripts/ioalab.py <子命令>`，脚本只用标准库，输出 JSON。
没有连接器市场的 swarm 把 `skills/ioalab-delegate/` 复制进技能目录、在脚本旁 `config.json` 填账号即可。

```
connector/ioalab-client/
  manifest.json          package_type mcp · id ioalab-client · integration {type: skill-only} · credentials {type: token, file: token-schema.json} · skills [{dir: skills/ioalab-delegate}]
  token-schema.json      IOALAB_BASE_URL（text）· IOALAB_USERNAME（text）· IOALAB_PASSWORD（password）
  icon.png
  skills/ioalab-delegate/SKILL.md      流程表 · 必须请用户确认的操作 · 规则（照 A2C 主仓 a2c-client 技能）
  skills/ioalab-delegate/scripts/ioalab.py
```

**分工**：swarm 做发现 → 比较 → 拟卡 → 签字 → 开工，并答复确认；平台保管密钥与 Client、跑签约后的固定流程。swarm 侧每 60 s 心跳 `status` + `confirmations`，有待确认即 `ask_user`。

**必须请用户确认再调**：`sign` · `request`（付拟卡费）· `adopt` · `start`（付定金）· `answer`（验收付款 · 环节授权 · 是否仲裁）· `terminate`。

### REST（`/api/v1`，`Authorization: Bearer <token>`）

| 方法 路径 | 作用 |
|---|---|
| `POST /token` | 用户名密码 → token（账号没有助手则自动注册「九问 Swarm」，`agents.meta.last_driver=external`） |
| `GET /me` | 账号 · 助手 id · 余量 · 待确认 · 进行中的需求 |
| `POST /delegations` | 下需求：`{text, scope{budget, category, sign1, sign7, validity}, autoSign}`，`needs.driver=external`，状态 `open`；不接受材料路径 |
| `POST /delegations/{nid}/materials` · `GET …/materials` | 上传材料（multipart：`file` · `name`（对应模板 inputs 的 name）· `declared` JSON；≤ 2 MB/件 · ≤ 10 件）· 列材料（名字 · 声明 · 预览） |
| `POST /delegations/{nid}/search` | `{query, top_k}` → 候选服务方（经交易中心检索，记 `discovery.search` 事件） |
| `GET /providers/reputation?provider=` · `GET /providers/templates?provider=` | 信誉条目 · 合同模板摘要（去签名与样件） |
| `POST /delegations/{nid}/cards` | `{templateDigest, cardId, spec, materials[]}` → `{cardDigest, derived, notices, inputPrecheck}`；超预算回 `error` |
| `POST /delegations/{nid}/cards/{cd}/sign` | 签1；待批准型随即请复签 → `{countersigned, reason, switches, hint}` |
| `POST /delegations/{nid}/requests` · `POST /delegations/{nid}/cards/{cd}/adopt` | 提案型：发提案卡（付拟卡费）→ `{returned, reason}` 或 `{cardDigest, derived}` · 采纳服务方拟的卡 |
| `POST /delegations/{nid}/cards/{cd}/start` | 付定金 · 交材料 · 开工 · 订阅存证；需求转 `started` 并发 `need.contracted` |
| `GET /delegations/{nid}` · `GET /delegations/{nid}/events?after=` | 需求 + 订单 + 待确认 + 已换过的服务方 `tried` · 本需求的事件 |
| `GET /confirmations` · `POST /confirmations/{cid}` `{granted}` | 待确认清单（验收亲签 · 环节授权 · 是否仲裁）· 答复 |
| `GET /orders/{cd}` · `GET /orders/{cd}/deliveries/{period}` | 订单详情（卡 · 签名链 · 裁定 · 事件）· 本期交付件内容 |
| `POST /orders/{cd}/pay/{period}` · `POST /orders/{cd}/arbitrate` `{period, ground}` · `POST /orders/{cd}/terminate` `{agree}` | 补付本期款 · 申请仲裁 · 解除（协商 / 单方） |
| `POST /delegations/{nid}/abandon` | 放弃（尚未开工时）；`open` 状态 30 分钟没签出卡的需求平台自动作废 |

签字类操作（sign · request · adopt · start）在 swarm 驾驭下**不再上升平台确认**——技能包要求 swarm 调用前先问用户；
`accept · step · arbitrate` 仍进 `confirmations`，swarm 轮询答复。事件与订单与平台驾驭的助手完全同形，管理员全景按账号聚焦即可看到 swarm 驾驭的那一路。

## 二、服务方：外部专业智能体

内部服务方全在进程内。外部服务方运行在别处，由平台**出站**访问，接入步骤：

| 步 | 做法 |
|---|---|
| 1 | 用 a2c 服务方 SDK + a2a-sdk 起一个 A2A 应用（声明 A2C 与 AP2 扩展，带 AP2 收款密钥），样例 `examples/external_provider/provider.py`；平台 `GET /api/config` 给出 `market` · `pay` · `publicUrl` |
| 2 | 验收器源码上传到平台：`POST /api/v1/provider/packages {verifierId, source, reads}`（登录态，只认 script）→ `ioalab://pkg/<digest>` 写进模板；三方取包 `GET /api/v1/packages/<digest>`（内容寻址） |
| 3 | **先登记**：`POST /api/v1/provider/register {url, name, description, tags, category, ap2Jwk}`：平台取 `url/.well-known/agent-card.json` 与 JWKS → 市场认证（Ed25519 公钥进 `Directory`，市场签认模板要用）→ 登记 AP2 收款公钥 → `agents` 行 `ext-<sha1(url)[:10]>`（`meta.url`）→ 按 `category` 确定性归入分类树；此时状态 `listed` |
| 4 | **再公示**：模板 `paymentProviders` 填平台支付方 `<PUBLIC_URL>/a2a/pay`；向公开的 `<PUBLIC_URL>/a2a/market` 发 `template.endorse` 取市场签认 |
| 5 | `POST /api/v1/provider/refresh {id}`（平台也每 30 s 自动拉一次 `listed` 的外部服务方）：取 `template.get`、验市场签名、写进 A2X 索引 → 状态 `online`，事件 `service.online` |
| 6 | 接单与交付走 A2C 服务方 SDK；收款归登记账号的钱包（AP2 `ap2.checkout` 由服务方应答，`ap2.pay` 由平台支付方读卡过账到登记账号）；服务方收到末期付款凭证后自己 `card.close`，平台按市场 ledger 把订单标完成 |

`GET /api/v1/provider/mine` 列自己名下的服务（含外部标记、地址、信誉）。内部服务方仍只放行回环；外部服务方不能反向调用内部服务方。
