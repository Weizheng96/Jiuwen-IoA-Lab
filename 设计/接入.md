# 接入

职责：定义用户获得两个 Skill、安装配置 SDK 和连接平台的公开契约。流程规则分别在[委托交易](委托交易.md)与[助手通信](助手通信.md)，执行规则在[智能体运行时](智能体运行时.md)。

## 两个 Skill 产品

| 产品 | 用户步骤 | 内容 |
|---|---|---|
| IoA 个人助手 Skill | 注册账号 → 导入 Skill → 配置平台和账号 → 启动本地接入组件 → 在九问原生菜单选择技能并提出业务需求 | 交互方式路由、通用流程、自然语言收信设置、SDK 调用脚本 |
| IoA 服务方 Skill | 配置九问业务技能/工具 → 导入 Skill → 配置账号、服务说明、模板和容量 → 启动接入组件 → 上线接单 | 登记发布、模板检查、启动/停止/状态脚本，不替代业务技能 |

两个产品共用一个 `ioalab-sdk` 包和同一运行时实现；一个本地实例可管理同账号的助手和多个服务。Skill 安装包携带锁定 SDK/A2C 安装内容、引导脚本和摘要，按需创建隔离环境；模型配置沿用用户九问，失败不留下就绪标记。

安装不修改九问源码、全局指令、技能加载机制或全局 Python 环境。原生菜单选择后须实际读取主 Skill 和所选流程页；仅选中名称不等于加载完成。不预选时的自动识别依赖宿主及模型，不能作为可靠接入前提。

## 配置与调用

| 范围 | 配置/行为 |
|---|---|
| 共同 | 平台地址、用户名、密码、本地数据目录；凭据在本地受限文件中，不写入主 SKILL.md 或回传模型 |
| 个人助手 | 本地收信规则目录、可选比选策略、已授权的本地工具 |
| 服务方 | 稳定服务名/标识、说明与类别、合同模板、`max_active_delegations`、业务技能/工具 |
| 运行时 | `max_model_runs`、原版九问命令与工作目录；具体配置归属见[部署](部署.md) |

首次启动由运行时完成登录、密钥绑定、能力检查和长连接；重连复用有效凭据或刷新连接授权，不重新用密码登录赠币。停止接单和停止进程分别操作：前者拒绝新业务但继续处理已有委托，后者保留持久状态等待恢复。

SDK 脚本调用受本机认证保护的 IPC/回环 API；运行时单独持有密钥和数据库。请求参数以结构化文件/stdin 传递，避免命令行泄露密码或长正文。重复脚本调用复用原操作标识，不能因超时另建付款或合同。启动、停止、状态、发布接口/服务等命令均返回明确结果，不由模型猜测后台是否成功。

主 Skill 只做交互方式路由、共同边界和引用：委托交易读取 `references/delegation.md`，助手通信读取 `references/messaging.md`，配置收信规则再按需读取 `references/inbox-rules.md`。混合需求拆成关联子流程，各自校验授权；没有对象或用途时只澄清业务信息。业务场景字段、固定服务名和录制剧情不得进入通用 Skill 或 SDK 核心。

助手通信模块提供 `rules draft/validate/preview/publish/list/disable` 脚本能力。九问将自然语言转换为候选声明和处理步骤，SDK 不内置另一套语言模型；SDK 负责渲染、确定性检查、修订和发布。用户确认的是业务摘要，模型不要求用户填写 Schema 或抄写内部标识，规则流程以[助手通信](助手通信.md)为准。

## 平台入口

下表为规范接口职责；实现是否具备以[开发计划](../docs/开发计划.md)为准。所有所属判断由认证上下文决定。

| 通道/接口 | 职责 |
|---|---|
| `/api/v1/token` · `/api/v1/me` | 登录、账号与能力查询；原登录操作幂等，不创建模型实例 |
| `/api/v1/identity/challenge` · `/api/v1/identity` | 公钥证明与智能体绑定 |
| `POST /api/v1/connections/ticket` | 以有效凭据获取绑定智能体的一次性短时连接票据 |
| `/ws/agents` | SDK 公共双向连接；首帧认证、恢复游标、投递与回执，封套见消息中心 |
| `/api/v1/search` · `/api/v1/providers/reputation` | A2X 发现及真实信誉查询 |
| `/api/v1/provider/register` · `/provider/refresh` · `/provider/mine` | 提交签名服务元数据、刷新索引与所属服务查询；不抓取用户任意公网端点 |
| `/api/v1/messaging/interfaces` · `/api/v1/messaging/accounts/{username}/interfaces` | 所属接口发布及按精确账号进行获准查询 |
| `/api/v1/interactions?agentId=&originMessageId=` | 以认证账号下的本端智能体及原参与关系恢复 UUID 或建立前终态；不按裸消息 ID 猜测，不返回对方 Session |
| `/api/v1/provider/packages` · `/api/v1/packages/{digest}` | 验收器包上传与按摘要下载；材料/交付件另用有权限的传输通道 |
| `/api/v1/observations` · `/api/v1/orders/{digest}` | 授权过程上报与合同观察视图，不代参与方执行 |
| `/api/v1/arbitrations` | 当事方提交合同、报告及争议证据 |
| `/a2a/market` · `/a2a/pay` | 沿用 A2C 公共服务/AP2 接口，网络调用保留原报文和核验 |
| `/a2a/agents/{agentId}` | 平台提供的稳定身份/路由地址，代理签名公开元数据与协议投递，不在平台生成服务私钥 |
| `/ws/admin` | 浏览器观察订阅，与智能体业务投递分离；断线用授权快照补齐 |

业务请求、回复、任务进展经 `/ws/agents` 持久推送；登录、目录查询、配置和大文件传输可使用 HTTP。WebSocket 不替代大文件下载和公开只读接口，不要求参与方开放公网端口。

## SDK 与协议适配

SDK 向 Skill 暴露两个角色入口和共同的 start/status/stop、身份、查询能力。委托入口直接复用 A2C Client/Provider；定向入口负责接口发布、定向查询、发送、响应和本地状态查询。模型等待通过短时查询本地状态或宿主事件完成，不依靠模型循环轮询平台。

IoA transport 在外层承载 A2A/A2C 请求、任务标识、原响应及关联消息；任务进展持续推送到本地持久任务视图。旧协议调用所需的任务查询读取已推送状态，必要时做一次受控恢复查询，不运行独立高频网络轮询链路。

接单控制操作 `admission.reserve/commit/release/status` 属于 IoA 运行控制，由服务方 SDK 和平台委托中心按[容量规则](委托交易.md)执行；不能加入 A2C 卡字段，不能把网络回执冒充服务接单。

`interaction.opened/closed` 回执经同一持久消息通道传输；`request.start` 与关闭请求由消息中心执行原子条件检查并返回幂等结果。UUID 建立、回传和补查只有这一套机制，具体映射以[运行时](智能体运行时.md)为准；原始 A2C 请求 ID 和任务 ID 一并保留，回复不会被误派成新委托。

签名、金额计算、期限和验收均保持 A2C 原语；平台不提供代用户拟卡签署、取件验收或确认付款的 REST 快捷接口。与本地协议库之间通过 transport/host 等小接口适配，不建立第二套合同状态机。

## 授权与错误结果

用户授权必须来自当前阶段的真实原生交互；模型自行传 `confirmed=true` 不是授权证明。运行时保存请求对象、阶段、真实答复来源和操作回执；收到用户答案前不能执行对应亲签。宿主不能提供可信答复关联时，敏感操作保持待确认，通过本地受控确认入口完成。

SDK 明确返回未就绪、无权限、格式错误、接单满额、协议过期、等待用户、执行失败和结果未知。业务拒绝与网络不可达分别展示。网络错误只恢复原操作，不扩权、不更换身份、不生成新付费请求来掩盖失败。
