# 委托意向与原子接单

## 问题与决定

服务公示不代表可接单。将原未签 A2C 对象、双方交互 UUID、容量资格及 AP2 付款放在同一明确链路：先投递意向，接收端登记 UUID，当前服务连接申请预留；有拟卡费时当前委托方连接再原子提交预留、预算与付款。恢复原结果不得重置期限或创造第二份关系。

分类用于授权边界，在线状态用于执行资格；二者分别判断。活动承诺由委托中心保管，不由普通消息 TTL 或模型退出清理。完整签约、业务执行和结清继续复用 A2C，不另造合同状态机。

## 实施与验证

| 实现 | 范围与边界 |
|---|---|
| 委托中心 | 新增 Admissions，保存意向业务绑定、消息中心已确认的 UUID 引用、接单策略、预留及操作/付款关联；上限、开始许可、当前模板与分类逐项核验 |
| 消息中心 | 委托意向/结果及 delegation 类型 opened；原接收端登记 UUID；当前连接下 configure/reserve/commit/status；与助手消息共用可靠投递，不改 A2C 字段 |
| 应用协调 | operations.PaymentOperations 在同一事务提交 admission、真实 AP2、范围预算和原控制回执；新绑定服务不能从公网 AP2 跳过上下文 |
| SDK | 常驻助手 intent/intent_status，以及两类型共用的 UUID 原子关联/恢复；委托准备操作统一为设计中的 prepare，默认7天，新旧已存许可不自动改变 |
| 保留与拒绝 | held 可安全到期释放；committed 不随 TTL、撤权或模型状态释放；当前公示尚未完成分类投影时禁止用旧分类接新单 |
