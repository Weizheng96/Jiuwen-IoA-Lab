# 仲裁闭环

## 原因与整体取舍

旧raw-card HTTP路由假设已有交付记录；旧时限分支未核ground实际成立，且把完整环节/付款历史传空。新SDK不能直接调用该路径。由委托中心统一拥有案件和证据，接入双方共用；不增加合同字段、兼容别名或第二套协议状态机。

## 上游语义核对

逐条核对A2C合同协议第十一节、验收器第四/五节及实际recompute。上游明确将仲裁时仍pending、验收器程序错误或不可重放认证原件折为fail；此前本机草案将所有异常都视为待核实的表述不准确，已纠正。只有原复算尚未完成的快照/运行资源/平台调用异常不能签发裁定。正常验收报告是否失败也必须核原签名，不能拿模型文字替代。

## 简化与闭环

| 事项 | 选择 |
|---|---|
| 对象 | 原admission关联合同或未成约提案请求；没有卡时不造卡 |
| 只读准备 | 公共preview取得真实依据摘要，用户确认后才申请；不为预览搭建新任务状态机 |
| 期限 | 原A2C公开函数加完整原请求/答复、真实付款，禁止按字符串直接指定责任方 |
| 人工因果 | 复用网页管理员本案复核，不新增泛化审批引擎；当事账号不可自审，模型不裁决 |
| 收尾 | 裁定终止原卡，实际writer收敛后IoA结束；不再调用被上游禁止的card.close，不把释放容量说成已付款 |
| 替换 | 原始覆盖迁入新链路并切换全部调用后整组归档，不提前删除仍使用模块 |

## 归属与实施

规范见委托中心、平台接口、双方SDK、身份权限及验收职责页。先实现原证据读取及preview，再接案件/复算/终局事务、双方SDK和执行收尾；实际差距记开发计划。此文不是实现验收，产物版本不升级，未提交或推送。前轮已保存完整测试及可回退快照。

## 原证据阶段结果

已实现委托中心的只读证据快照和认证HTTP preview：admission、合同、协议转发、消息及支付分别提供其原证据接口，预览组装校验，不更新合同、建案或调用模型。完整原协议进展保留全部环节与答复，不从监控投影反推事实；原付款只返回验签凭证，不返回AP2授权请求。

首轮9项通过；加入原绑定/缺请求校验后，连同合同登记和解除控制共28项通过（264.17秒）。最终取证14项通过（130.62秒），覆盖无交付开工期限、原模板当前过期、边界时刻、费用已付但请求未提交、正式答复、多环节停表、真实失败报告、已付款/零额及签名/绑定损坏。

跨类别同名验收器实际用例曾复现409误拒绝（1失败，17.98秒）：原因是把原判据ID转成集合，丢失出现次数；现按多重集合核原报告，保留原A2C允许的两类同名判据，不放宽签名或覆盖校验。设计、文档与先前全仓自检均通过；最后修正后的四项整仓检查继续执行，不用前轮879通过的快照替代本轮。

本阶段不表示案件受理、独立复算、人工复核、终局事务、双方SDK通知/执行收尾已接通；旧仲裁路径及原覆盖须在完整替换验收后一起切换。原生九问、Linux默认部署、旧组归档和四个新影片仍未完成。产物依据不虚升；原发布审批限制未解除，未提交、打标签或推送。

冻结1008项输入的四项检查均通过，完整测试893通过、39跳过，期间输入未变。两目标发行内全部56个Core及65个SDK模块与该快照匹配。全新Windows独立Core环境和已安装SDK经真实HTTP/WS及认证IPC公示两服务、取得三份报价、形成原合同并调用已安装preview。原卡与预览对象相符，尚未到期的理由明确不成立。
