# 常驻接入与本机调用

## 问题与决定

共用账号及 WS 传输已具备，但产品脚本仍独立打开身份库。补齐常驻进程的单一所有权、受限回环入口、启动与停止、本地操作及调度规则，使两角色真正共享同一实例。业务规则和宿主配置由所属模块处理，不由 IPC 反射调用任意对象或加载网络提供的代码。

服务端投递 ACK、业务开始、执行检查点及外部效果继续分开；本机接口可用不等于宿主或业务已就绪。原生用户确认、A2C 接单和四片演示仍按开发计划逐项核验。

## 实现与边界

运行时新增专用配置、稳定 profile 身份、进程锁、后台入口、受限回环 RPC 和确定性 CLI；旧直接客户端目录须显式迁移，不自动换钥。端点按实例原子发布、重启换凭据，旧实例不能删除新描述。Windows 使用用户 SID ACL，数据目录混放其他文件时拒绝启动而不修改它们。

调度按交互及实际 Session 排他，模型上限与待处理数量分别控制；控制入口不等待模型。waiting 释放本轮资源，未核实的 running 在重启后保留 unknown，只有角色核原回执后才能解除阻塞。有效执行连接和保守心跳租期是新调度前提；网络离线不等于业务失败。

公共原子文件和收件/作业数据库各负责自己的持久边界；启动缓存并发触发的 WAL 初始化竞争通过短期 OS 初始化锁解决，不在网络调用期间占锁。Windows 对未读取请求直接关连接可能吞掉拒绝回执，IPC 用有界丢弃返回明确错误，客户端先检查报文上限。

默认装配尚无业务角色处理器和九问宿主，明确报告缺失；已验证收件落库和 ACK 不会启动业务。现有产品技能及原合同入口尚未切换，不能把本轮进程基础当作完整接入或新视频证据。

## 核验

全部237项测试、54份文档/索引/版本和完整仓库自检通过。新增24项覆盖真实子进程、两角色登录共享、增添角色、无直接 SQLite 的 CLI、参数标识持久化、本机权限/报文拒绝、离线启动、缺钥恢复、效果后进程中断、控制响应与停止，以及交互/Session并发、未知阻塞和心跳失效。Windows 实际保存的 ACL 仅含所属用户 SID；构建安装包包含真实 ioalab-access 入口。

只读原版九问能力探测确认公开协议支持宿主工具、技能及会话续接，并在原已配置数据目录查得三个模型选择项。数据目录决定实际模型配置，不能仅指定代码/工作目录推断可用模型；脱敏结果保存于部署验证目录。这不证明真实模型业务、用户确认或网页可见性。产物 VERSION 保留实际实现依据，后续真实接入与四个新版视频按开发计划推进。
