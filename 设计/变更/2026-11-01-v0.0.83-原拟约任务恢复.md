# 原拟约任务恢复

## 依据与决定

验收器引用恢复不等于拟约作业恢复。原A2C将后半段保存在进程内回调，SDK不能删除协议记录或重发请求绕过它；也不能因为重启就重跑未知模型。

| 归属 | 决定 |
|---|---|
| A2C | 使用已提交的原任务续接能力，保留请求、材料核验、费用凭证和期限；平台不复制拟卡/签认 |
| 服务方任务模块 | 提供所属任务的只读查询及显式恢复，持有原模型轮次确已结束的证明；只处理验收器准备这一已知中断，其他未知保持停止 |
| 调度器 | 同事务保存恢复回执与原作业续接，重传返回旧回执并另列当前状态；不维护第二套任务执行器 |
| 宿主 | 原Session与定义不变，新轮次前清除旧可续接证明；不能从来信获得管理恢复能力 |

真实模型首轮暴露两个边界：不易读的哈希工具别名被模型混拼，原白名单正确拒绝；宿主明确failed终局与执行结果unknown不能混同。适配器改用稳定可读别名，仍严格校验声明/权限/回调；仅验收器准备未知且轮次已返回completed或failed终局时保留可续接证明。

不增加合同字段或线上操作，不要求修改用户九问；不提供旧数据猜测修复或通用强制重跑。

真实恢复还暴露清单校验时点错误：模型把reads填成文件名，平台曾在核验前返回包引用。SDK增加原A2C清单预检与明确Schema说明，平台核验最终包后才落盘；不自动删除声明或更改业务判据。
