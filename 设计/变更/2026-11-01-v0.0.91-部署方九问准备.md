# 部署方九问准备

## 问题与决定

生产环境隔离安装已交付，默认部署入口尚未切换。直接复用旧初始化器会把“存在config.yaml”当作归属，并且is_default不保证Process选中实际模型。先补齐工作区准备边界，再迁移默认编排。

| 问题 | 决定 |
|---|---|
| 用户已有九问不能修改 | 仅准备带本部署标识的新空工作区；普通接入不调用此工具 |
| 中断后模型可能已创建 | 效果前保存固定model_id，恢复先读原资源；冲突停止，不生成另一个模型 |
| 人工修改不能被重装覆盖 | 已完成工作区只读取，当前模型由公开资源和目录映射；不同输入需显式配置 |
| 缺模型被占位项掩盖 | 明确awaiting_model，不以公开目录中存在任意模型判就绪 |
| 核心/官方模型能力不一致 | 首次共享配置只支持已实现的OpenAI兼容端点，拒绝其他provider |

## 实施与验证

本轮先交付配置校验和工作区准备，默认安装、服务管理、升级及管理员接入仍按开发计划继续。真实证据在完成检查后补充；不把准备结果当作完整部署验收。

| 已验证项目 | 证据与范围 |
|---|---|
| 定向回归 | 工作区/配置及生产发行共41项通过；既有Windows pytest临时清理权限告警1项 |
| 原版实测 | 缺模型待配置；模型创建成功后丢回执，继续原工作区仅保留一个原模型资源；修改模型名称/密钥/别名和updater后再次准备不改配置字节；原ProcessHost可用 |
| 来源未变 | 原版安装中的三份配置模板与随仓wheel摘要一致；未登记用户目录未被接管 |
| 证明边界 | 仅本机Windows和配置/公开目录；测试密钥不可外连，无真实模型生产或邮件。默认编排、Linux/systemd及影片尚待后续 |

原版CLI要求--query-json后显式传入标准输入选择符-。首次实测发现缺参，修正后继续原工作区并完成验证；未清空或重新创建原模型。公开脱敏记录见deploy/verification/owned-workspace.json。

## 整仓回归发现的读取问题

首轮整仓663通过、16跳过，1项两期履约失败；失败发生在预设文件断网注入之前。原隔离状态显示首期自测工具调用已保存但无结果，生产作业保留ReadError未知状态，没有继续签字或付款。单项复现通过，不能据此把首轮算通过。

自测仅通过账号会话GET读取原摘要验收包。统一在该读取边界有限重试ReadError/RemoteProtocolError，不重跑生产或业务写入；超时、HTTP错误、摘要错误及耗尽仍明确失败。新增确定性断开/截断/摘要错误/超时测试，并重跑完整检查。原失败现场保留在本机data验证目录及原pytest目录，不清空合同或作业。

整仓最终检查：设计/文档/自检通过；pytest 674 passed、16 skipped、1 warning，1449.56秒；总检查1496.27秒，570项冻结代码输入未变。另从实际CLI复用原环境/工作区，两份测试密钥均未出现在输出；真实Windows目录联接在初始化前被拒绝，目标未变。
