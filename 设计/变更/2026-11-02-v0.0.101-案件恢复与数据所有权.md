# 案件恢复与数据所有权

## 整体问题与取舍

原取证14项及干净安装已通过，但案件实施前联合推演发现：离线接收方可能不知道caseRef；已开始模型评估不能按旧状态盲重跑；裁定后提前释放会阻断原已验收债务，要求未付新定金又会与裁定停履约矛盾；最新事实变化需明确终局；无卡失败不能遗漏信誉。Core现有进程内RLock不构成单实例证明，且公共地址及模型文件在DB打开前已经写入。

## 简化选择

| 问题 | 选择 |
|---|---|
| 案件最终性 | 沿用ruled终态，人工可中立，不另建撤案重开/版本引擎；已知程序结果不能重试挑选 |
| 资金与容量 | 原已验收价款/协商余额齐全且执行收敛后再释放；不新增关闭后付款通道，不要求被禁止的新定金，不执行裁定补偿 |
| 引用恢复 | 按原admission查询case，通知不是唯一来源；新宿主轮次读当前事实，不把旧幂等回执当许可 |
| 单写所有权 | Platform在任何私有配置/DB修改前持真实OS锁；普通DB保持普通连接的职责，不从部署/SDK反向导入、不依赖PID |
| 评估恢复 | queued和evaluating区分；评估未知只由独立管理员明确处理，固定依据和模型、记录尝试；不提供通用SDK强制重跑 |

规则分别归委托中心、支付中心、平台接口、共用SDK、A2C适配及部署页；本记录不是实现验收。先完成Core实际所有权和退出路径，再接案件、双端SDK与原执行收尾。旧实现仍待完整替代后整体归档，远端发布限制未解除。

## 数据所有权实施阶段

存储层增加真实OS排他句柄，完整Platform角色在私有配置/DB前取得；普通DB仍可用于原凭证检查。关闭路径等待实际启动线程及A2X线程池，观察方取消不放弃原关闭任务；构造、启动和lifespan失败均清理原资源。现有init/serve不再提前写文件，停服备份与清理也复用同一所有权，锁文件不作为可删除状态。

隔离定向测试38项通过，包含真实跨进程排他、终止本测试进程后的OS锁释放、部分DB初始化失败、实际线程被阻塞时的启动/关闭取消、网页lifespan失败和各CLI入口拒绝活动数据，同时回归原付款原子性、部署与监听地址。首次测试因读取Windows锁字节被系统拒绝；改核该文件元数据，其余业务文件继续核原摘要，没有弱化真实排他测试。

此后开始冻结完整检查；定向结果不等于整仓、Linux默认部署或仲裁案件及双端闭环已完成。设计中的案件申请、评估/复核、终局、按原admission恢复、SDK新轮次门禁和原应付款联合收尾仍待开发。远端发布限制仍保留。

## 公开请求取消的补充验证

进一步隔离实验发现，普通同步网页处理器会等待原线程，但显式asyncio.to_thread入口在请求取消后可能遗留实际线程；旧关闭路径可先关闭DB并释放锁。正式公开HTTP回归重现一次失败，原线程随后访问已关闭DB。因该确定缺陷，本任务核实并停止原检查进程及测试子树，原日志保留且结果标为canceled，未把部分回归当作通过。

修复复用同一Core工作生命周期：网页和WebSocket的显式线程都由平台持有，Core A2C入口保留完整原ASGI轮次，观察方取消不取消原工作；关闭统一等待这些对象，停止后的新工作明确拒绝。未增第二套执行器、协议状态机或九问修改。A2C原线程与任务存储更新仍使用原绑定。

修复后42项定向全部通过，用例包括HTTP、WebSocket和A2C入口被取消后原线程仍能访问原DB、实际退出前锁保持，以及上述38项共享回归；另有一项历史pytest临时目录清理权限警告，未删除该目录。随后重新冻结完整检查。案件闭环、Linux默认部署、原生完整操作及四片仍未因此完成，产物依据未虚升。

## 完整数据所有权快照

冻结1012项输入，设计、文档、完整测试及全仓自检均通过，期间输入未变化；完整测试913通过、39跳过。两目标包内56个Core及65个SDK模块与该快照一致。全新Windows Core/SDK经真实HTTP/WS/IPC公示两服务、取得三份报价、形成原合同并查询原证据；另一已安装解释器核实际Core持锁及其真实进程退出后的锁释放。

宿主与用户确认是明确测试替身，不表示原生用户操作、真实模型或邮件；Linux包构建不是默认部署验证。范围、源码摘要和局限见[Core数据所有权验证](../../deploy/verification/core-ownership.json)。案件及双端收尾、Linux默认部署、旧链路归档和新影片仍待完成；未提交、打标签或推送。
