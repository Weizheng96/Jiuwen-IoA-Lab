# 通用多候选比选阶段

| 项 | 说明 |
|---|---|
| 用户检查点 | 是否因模板不适配被排除；skill是否允许多选 |
| 模板证据 | 未设下限的真实take中，九问已读取灵犀、快搭、码上飞完整模板，并明确三家均满足核心需求；随后只请求码上飞299提案即询问采纳，未将另外两家判为不合格 |
| 技能证据 | 原通用流程已有多份提案比较，但没有足够明确的候选集合/报价征集完成边界；模型把验收覆盖偏好前置为只向一家询价 |
| 处理 | 强化通用skill的阶段约束；模板不因本轮问题改业务能力，SDK不写三家名称或行业选择器 |
| 复测 | 不加载演示最低三份偏好，检验模型根据真实模板与费用许可征集多个候选；此前下限策略试验保留，不作为此项验收 |
| 边界 | 通用流程不保证任意模型必然服从；原生菜单先选择，真实工具结果与签名卡才是证据。未完成新片不更新发布完成状态 |
