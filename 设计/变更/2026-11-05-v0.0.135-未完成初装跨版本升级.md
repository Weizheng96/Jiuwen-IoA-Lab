# 未完成初装跨版本升级

首次安装失败在bootstrap时，已准备候选可能仍使用旧配置与安装逻辑；原repair-bootstrap只允许受限控制器变化并复用旧候选，不能将业务来源变化伪装为控制修复，也不能冒称已升级运行产物。

[安装与升级](../工程/安装与升级.md)新增显式bootstrap-upgrade入口，只接受已停止、失败bootstrap且尚未完成初始化/官方授权/管理员准备的原部署。不可变父子请求绑定旧新来源和输入、原候选、旧环境及既有preparing账号。先正常排空并核控制组与SDK锁，再保原权限全量备份、归档旧输入并显式导入唯一平台JSON，真实构建和激活新候选，复用原Installation.bootstrap与SDK幂等准备。

新核心就绪后仅对请求登记的原preparing账号经公开SDK登录恢复rejected，缓存和unknown由SDK处理；保存回执，不删库、不重放赠币或业务授权。未知与变化拒绝保现场，不另建安装引擎、配置权威、协议状态机或运行旧格式兼容链。规范发布不代表实现或Linux实机验收已完成；差距归开发计划，不虚升产物VERSION。
