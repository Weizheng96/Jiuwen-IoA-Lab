# 原生技能业务路由

| 项目 | 内容 |
|---|---|
| 原因 | 原生九问已选中并读取个人助手技能，但把成果需求转给同机业务技能，开始本地开发，未进入平台委托 |
| 决定 | 原生选择 IoA Lab 个人助手技能明确当前使用方式；成果类需求读取委托流程，经 SDK 进入授权和服务发现，无需用户使用协议术语 |
| 调用 | 两角色共用调用页明确参数文件、编码、原操作及确认；角色流程明确字段类型与回执来源，减少猜字段和覆盖参数文件；外层产品脚本也强制既定UTF-8输出，不依赖父终端编码 |
| 需求 | 原生试验实际得到0价空规格提案；按单模板须传递需求，助手不删去必须条件换取格式通过，固定无参数成果仍允许空规格 |
| 边界 | 不修改九问源码或全局指令；不禁用其他技能；不加入行业、报价、候选数量或中选服务规则；安装和助手通信仍独立路由 |
| 验证 | 在同时安装业务技能的原版九问中，通过原生菜单选择后提交自然业务需求，检查实际流程读取及 SDK 授权回执；不以提示词或关键字测试代替真实运行 |
| 依据 | 现行规则见[个人助手技能](../接入/个人助手技能.md)与[验收](../工程/验收.md)；实际结果另记验证记录 |
