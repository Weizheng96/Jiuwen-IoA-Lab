# 默认部署切换

## 问题与取舍

| 问题 | 统一决定 |
|---|---|
| 工程规范继续堆入部署长页 | 部署保留安装单元/依赖，默认流程归安装与升级，业务实例归官方实例；不重复字段 |
| 默认入口仍用开发环境和旧运行器 | 独立build和三个运行环境；正常服务只用安装包及同一SDK |
| 根状态目录权限混合 | core/agents分离系统账号；部署凭据及快照归root，敏感叶目录不共享 |
| 三环境逐个切换可产生混用 | 完整集合准备后，单次替换current；实际SDK安装身份仍核真实环境 |
| 官方原版外层启动器会漂移端口并最终强杀 | systemd直接管理原版AgentServer/Gateway/网页三个模块；SDK先排空，不修改九问源码 |
| SDK独立serve缺少信号排空 | SIGTERM/SIGINT沿同一调度器排空至实际释放；故意崩溃测试改用明确强杀，保留未知结果恢复覆盖 |
| 自动管理员接口如何具有真实配置意图 | 用户启用内置助手即授权root只准备新ISC_001的固定预设；同SDK对象/摘要确认，不能扩展到合同/付款或普通账号 |
| 缺通知配置不能假装可约会 | 留言可用，会议明确停用，模型和邮件均不以桩冒充 |
| 升级后可能已经出现新业务 | 保留原操作、旧环境和一致性备份，不在未知时自动回滚数据或重放效果 |
| GitHub不可达且部署路径可能为同步目录 | 部署工具仅消费本地源码；GitCode同步由部署方先完成，不增加Git获取/分支切换引擎 |

## 实施与验证

规范先更新职责页、版本与历史，再实现。当前交付目录归属、固定构建器、完整环境集合核验/原子切换、共用子进程环境白名单、SDK信号排空和绑定地址修复。工程页按部署、安装升级、官方实例分工；默认脚本尚未完成装配，管理员预设仍待实现，未归档仍有调用者的旧入口。

完整检查707 passed、31 skipped，723个冻结输入未变；跳过项包含Windows无符号链接权限及非POSIX信号，Linux CI执行对应真实路径。实际独立build构建两个目标发行，在Windows干净安装核心与参与方包，离开源码验证真实HTTP/WS、原身份/赠币缓存重启及执行锁释放；不调用生产模型或发送邮件。新增deployment CI按同一正式实验安装Linux三环境，不以开发依赖或静态模板冒充systemd部署。证据见[部署生命周期核验](../../deploy/verification/deployment-lifecycle.json)。

真实构建发现并修正两项校验问题：锁文件按原字节保存，避免CRLF造成摘要误判；按实际site-packages核独立发行，不把setuptools内置库计为额外安装。首次失败环境和日志保留，修正后仅对已确认failed的构建器显式创建新尝试。Linux原版venv解释器可链接到系统Python，工作区工具按安装前缀定位标记，不沿二进制链接跳出环境。
