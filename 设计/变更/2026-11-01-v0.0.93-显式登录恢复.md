# 显式登录恢复

## 问题与统一取舍

| 问题 | 决定 |
|---|---|
| 规范已有account.login，失效缓存却使常驻启动先失败 | 用SDK短期账号控制入口，持同一实例锁；不另建降级运行时或收件器 |
| 重启可能重复赠币 | 有效缓存复用；密码重登仅来自明确意图，未知登录先恢复原操作 |
| 修正配置与未核实原请求冲突 | 待恢复请求先保存本机HMAC输入绑定；只在明确拒绝后允许显式新操作，未知输入不能改写 |
| 同名不等于原所有者 | 已知账号ID必须一致，在更新缓存前拒绝冲突；不触碰原身份和业务 |
| 两端接入方式易分叉 | 双产品技能同一account.login引导，同一SDK实现；刷新仍由原常驻实例处理 |

## 实施与验证

规范先更新，再实现同一AccountSession、短期账号控制、IPC续用及双产品入口。完整检查729 passed、31 skipped，727个冻结输入未变。真实干净安装包完成显式登录、失效凭据恢复和三次SDK启停；同一身份保留，重登仅赠一次，随后重启不赠币。未调用模型或发送邮件；wheel实际模块与源码一致。

新增真实HTTP故障与竞争验证：原登录丢响应、5xx/限流/冲突/不可识别响应、原输入改变、输入校验密钥缺失、明确拒绝后修正、账号ID变化、当前实例/短期控制占锁、双Skill路由与原常驻续用。凭据校验回归发现身份中心原Bearer判断接受网页令牌，现统一要求SDK受限主体；外部账号所有权测试使用有效SDK令牌以继续覆盖原403边界，不放宽权限。
