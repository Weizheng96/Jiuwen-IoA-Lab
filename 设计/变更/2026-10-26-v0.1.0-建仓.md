# 2026-10-26 · v0.1.0 · 建仓

## 起因

领导要试用一个可部署在服务器上的 IoA 仿真平台。此前的实现在 A2C 主仓 `仿真平台/`（包名 `agentnet`），只在本机 dev 模式跑过：
手机号 + 固定验证码注册、凭据读 `APIkey/*.csv`、参与方 id 内嵌 `http://127.0.0.1:8750`、没有部署脚本。

## 决定

| 事项 | 取法 | 为什么 |
|---|---|---|
| 独立子仓 | 本仓 `Jiuwen-IoA-Lab`，自己的 `设计/` 与版本号（自 v0.1.0） | 平台是产品，演进节奏与协议设计不同；主仓只留协议、SDK 与 demo |
| 依赖 A2C | `vendor/wheels/a2c-*.whl`（`tools/sync_a2c.py` 从主仓 `src/` 构建，`SOURCE.json` 记来源提交与依据的 A2C 设计版本） | 服务器可离线安装；不要求构建机能访问主仓；升级就是重跑同步脚本 |
| 依赖 A2X | git 子模块 `vendor/A2X-registry`（钉 v0.3.3） | 仓很小，子模块最直接 |
| 配置 | 全部 `IOALAB_*` 环境变量；A2X 要的 `llm_apikey.json` 由平台按同一把 key 生成 | 部署方自配 API key，平台不读任何凭据文件 |
| 对外地址 | `IOALAB_PUBLIC_URL`，首次运行记入 `data/public_url`，之后不一致拒绝启动 | 市场 · 支付方 · 服务方 URL、模板、A2X 索引都内嵌它 |
| 进程内互调 | 发往自己 PUBLIC_URL 的报文改走 `http://127.0.0.1:PORT`（Host 头保留） | Nginx 后面不绕圈、不依赖域名解析 |
| 种子 | 首次启动自动注入（`IOALAB_AUTOSEED=1`）；`ioalab init` 可离线预置 | systemd 一条 `ExecStart` 即可 |
| 部署 | 裸 Linux Python 3.11：`deploy/install.sh` → `/opt/ioalab` venv · `/etc/ioalab/ioalab.env` · `/var/lib/ioalab` · systemd；Nginx 可选 | 目标服务器无 Docker |
| 改名 | 包 `ioalab`、`IOALAB_*`、cookie `ioalab_session`、`urn:ioalab:`、`ioalab://pkg/`、A2X 数据集 `ioalab`；旧名零命中 | 新部署无兼容负担 |

## 影响

`ioalab/` `deploy/` 依据 v0.1.0。后续分期（账号体系 · 内部服务与分类树 · 委托方开放接口与九问技能包 · 管理员全景 · 外部服务方接入）各自 +1。
