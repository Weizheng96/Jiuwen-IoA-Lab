# 试用固定入站与资源布局

实际Windows Docker Desktop工程探针中，仅连接internal网络的原版九问容器可在容器内提供HTTP/WS，但宿主loopback发布结果为空。独立固定转发器临时原型验证了入站路径；该结果只证明工程传输，不证明原生浏览器、SDK可信确认或合同业务通过。

现行规则集中在[在线试用](../工程/在线试用.md)。每epoch采用席位、模型代理、入站转发器三个独立容器；席位只在isolated内部网络，供应商secret仅归模型代理，入站转发器只提供两个固定本轮目标。明确IPv6禁用及实证门槛、连接和资源上限、PID1信号处理与活动连接退出；不给席位增加外网连接，不修改原版九问或复制SDK授权链。

控制库、受审镜像及资源绑定固定布局，拒绝旧布局缺失或不符的实例，不静默补记或接管。第一个停止信号前完整核三个容器、卷及内部网络归属，控制bearer发送前另核固定入站发布目标。撤权后依次停止模型代理、经仍活转发器撤销SDK确认、停止席位、停止转发器；全部退出且再次核验后才销毁整轮资源，再分配。任何未知保持隔离，共用外网桥不删除。

资源测量包含入站转发器，宿主传输、原版加载/清洁状态和真实浏览器/SDK业务分别验收。本次规范发布不代表目标环境与业务通过，不递增产物VERSION。Linux服务器本次保持原样，Windows工程探针不作为Linux部署验收。
