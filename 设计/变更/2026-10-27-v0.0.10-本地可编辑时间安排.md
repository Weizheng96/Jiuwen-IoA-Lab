# 本地可编辑时间安排

| 项 | 决定 |
|---|---|
| 用户需求 | 助手在本地保存可编辑的时间安排，减少外部日历授权依赖 |
| 预约依据 | 显式选择local，主人维护工作时段与已有安排；当前演示采用此方案 |
| 编辑 | IDE直接编辑，或九问经SDK读取与带revision替换；文件锁、校验、备份、原子写入 |
| 自动记录 | 继续使用既有SQLite保存邀请幂等与待接受预约，不引入第二套消息状态机 |
| Outlook | 通知邮箱发标准邀请；用户接受后入历，本地安排不自动同步私人Outlook日历 |
| 失败处理 | 文件缺失、非法或被并发修改时阻止发信，不假定空闲 |
| 兼容 | Graph读取仍为可选后端；旧配置不隐式切换 |

此前讨论过使用AgentMail日历作为依据；用户随后提出本地可编辑安排，本次将其作为演示选用方案。AgentMail继续承担已验收的会议邀请传输。后续录屏需展示本地安排与实际消息结果；已有邮件受理证据不能替代本轮整条交互验收。
