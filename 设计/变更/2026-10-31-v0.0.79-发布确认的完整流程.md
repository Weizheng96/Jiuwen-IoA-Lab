# 发布确认的完整流程

## 依据与决定

原版九问的服务入驻实测完成预览后直接打开本机页面，并要求用户在聊天中回复“确认发布”。预览没有创建待确认记录；打开页面也不创建记录，流程因此缺少实际可批准的对象。另一个独立问题是Windows电脑控制无法读取Edge网址，不能把工具限制当作平台确认已完成。

| 问题 | 决定 |
|---|---|
| 预览后做什么 | SDK返回下一步申请确认的操作，不增加发布状态机或新操作别名 |
| 谁创建待确认对象 | 角色受保护操作首次调用；当前预览、原操作、阶段及期限共同绑定，尚不签名或公示 |
| 何时打开页面 | 收到真实waiting后打开；opened只表示入口打开，不能等同有记录或已批准 |
| 用户如何决定 | 保留独立浏览器认证、同源和CSRF校验；聊天confirmed不替代页面决定 |
| 决定后如何继续 | 原文件与operationId恢复，先查已发生效果，沿用原签名请求和回执 |
| 经验如何复用 | 两角色共享确认流程；Codex九问技能区分申请、页面打开和实际批准三种证据 |

本轮不放宽授权、不改九问、不内置浏览器自动批准通道。验收器业务质量、完整原生公示/生产、浏览器连接及四片仍分别验收。

## 验证范围

| 范围 | 实测结果 |
|---|---|
| 确认与恢复 | 定向42项通过、1项跳过，40.68秒；预览无确认副作用、重复申请同引用、打开页面仍pending、聊天confirmed拒绝，以及真实测试用户批准后丢回执/重启恢复通过 |
| 完整检查 | 487项通过、13项跳过，781.49秒；设计、文档及仓库自检通过。保留一项既有临时目录清理警告 |
| 发布包 | 两ZIP干净安装与原合同接管通过，26.34秒；原生导入17文件与构建包逐字节一致 |
| 原生九问 | 新会话原生选中技能后，经真实安装、IPC/WS、起草、上传、自动分类和publish取得pending，再打开本机页面；没有额外流程救援提示。原九问配置摘要及稳定身份保留 |
| 未通过边界 | 原生模型仍读取完整账号配置，本轮仅公共演示凭据；验收器只检查文件存在；模型口头不接单未落实为程序暂停。实际用户批准、公示、生产及私密凭据隔离均不认定完成 |

[脱敏证据](../../deploy/verification/publication-confirmation.json)及[原生等待画面](../../docs/progress/native-publication-pending.png)只证明对应范围；画面上的模型成功描述不替代SDK回执，Windows确认页并未取得可操作状态。后续先收敛接单策略、业务验收及凭据配置，再完成原生业务与影片。
