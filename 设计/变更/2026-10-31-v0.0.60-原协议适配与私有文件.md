# 原协议适配与私有文件

## 问题与决定

统一接单之后仍需传送原 A2C 请求、任务进展和实际材料/交付件。采用独立受鉴权的文件通道保存字节，消息只带原协议与文件引用；合法消息入库和接收方读取授权同事务。原模板、签名和协议任务不改字段，参与方继续调用原 A2C SDK。

每个委托使用独立协议 Store/Session，平台只核接入资格和绑定。市场签认提案、开工未知与结清释放也必须与 admission 保持一致，不能为录制另开直通接口。

## 实施与验证

| 实现 | 实际范围 |
|---|---|
| 私有文件 | 鉴权上传/下载、原操作绑定、摘要与大小核验；写入前预留账号配额，磁盘中断保留不可读的待完成引用，恢复同一文件与配额 |
| 原协议投递 | 初始 request.submit、card.countersign、拟卡费 ap2.checkout 的绑定校验与开始许可；原 A2C reply 和任务 ID 通过同一交互返回；待批准先投递签1审查，容量提交后才允许有效签2返回 |
| 材料权限 | 原用户签署的信息授权、材料摘要及预审范围先核验；读取授权、协议关联和消息接受在同一事务，失败整体回滚 |
| 市场门禁 | 新绑定服务不能从公共 card.endorse 绕过已提交 admission；当前连接下的签3操作仍待装配 |
| 文档一致性 | 架构补充文件基础设施和数据权威归属；索引与验收中遗漏的三个 Demo 表述统一为四个；旧变更记录保留原语境 |

上游原任务使用 auth-required、rejected 等状态，无任务 Reply 的 state 可以为 null。适配保持原值，不能把界面用语 input-required 写回原协议；投递台账独立判断本次调用是否完成。真实延迟 Provider 测试验证 working 到 completed 的同任务进展、任务替换拦截和终态不回退；无任务响应另用明确测试返回验证，不代替真实支付验收。

流程复核发现待批准的先后依赖：commit 需要收到签1卡，投递签1却要求先 commit。修正为有效 held 下投递与审查、原 Provider 审查回调提交、提交后签2；不增加补发签名接口。正常接收链路及审查期间预留到期的反例均已验证，结果还检查原签1、卡摘要及绑定服务方签名。

11项新增覆盖已通过：5项私有文件、6项协议投递；与原14项 admission 共25项联合通过。原 Provider 复签使用真实 A2C 签名与校验，测试用户和业务输入为隔离配置。

最终完整检查通过：300项测试通过、2项可选模型测试跳过、2项测试警告；版本、56份当前文档、包构建/安装清单与仓库完整自检通过。最终测试耗时285.39秒。未删除或放宽原覆盖。

本轮未运行真实模型、发信或视频制作。常驻 SDK 原协议执行器、提案签3协调、完整履约与结清释放尚未完成；门禁关闭不代表这些阶段已经可用。未升级产物 VERSION，旧路径也不能代替新链路的端到端证据。
