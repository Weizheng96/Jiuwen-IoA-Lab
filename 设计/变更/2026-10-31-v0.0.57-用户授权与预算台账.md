# 用户授权与预算台账

## 问题与决定

现行设计要求核验真实用户授权、总预算及并发费用，但尚未给出签名对象和续期语义。A2C 卡载 delegationScopeDigest 必须稳定；把可变有效期直接放进卡载摘要会让已成约合同无法续期。按期扣款若重复叠加整份合同价款也会误拒合法付款。

范围 context 固定，授权 grant 独立修订；用户签名覆盖两者，scopeDigest 只锚定 context。续期不扩大预算、不重置支出或原选中合同。具体合同选择先使用用户选择证明原子预留完整价款，再签1；付款消费该额度而非再次预留。一个范围只选一份合同，未知效果保持原绑定，避免额外撤销/回收状态机。

生命周期审查补齐撤回语义：撤回授权不应使已成约合同永远无法继续支付。关闭只撤回当前许可并推进修订，拒绝旧许可和原在途续期；明确用户重新授权可以在下一修订恢复原范围，仍保留原预算、支出和合同，不通过清空或更换卡载摘要恢复。

范围许可按其用户确认的有效期判断，不能误套 AP2 单次付款的15分钟窗口；已签范围许可离线延迟登记时仍按原截止生效。具体合同选择证明和单次 AP2 凭证继续各自的新鲜度规则。

平台模块维护签名授权与预算台账，SDK消费本机可信确认后签发、保存并恢复原操作。接单与付款仍通过明确平台应用事务协调，不把范围许可当作容量许可，也不修改 A2C 或 AP2 原字段。旧产品路径尚未切换，完成新履约门禁后统一淘汰。

## 实现范围

- 支付组件 ScopeLedger 独占范围、用户许可、选择与预算记录；原签名对象、修订及操作幂等均持久保存。scopeDigest 不随续期变化，关闭后旧登记重传不重开。
- 注册/查询/关闭提供 SDK Bearer HTTP 入口，WS scope 操作共用同一存储和恢复查询；签名/卡校验在事务外，提交再次核归属、当前用户密钥和许可时点。
- 个人助手角色新增本地任务及初始授权/续期/关闭；本机用户批准后才签名。原 payload 先持久保存，响应丢失不新签名，返回原接受记录和当前状态两个明确字段。
- 新注册中心读取视图提供实际已上线服务类别；旧发布入口保存 A2X 实际分类回执，不把用户请求的未知分类当作实际归属。旧数据正式迁移仍须核对索引和目录。
- 预算消费方法可参与同一应用事务；真实 AP2 测试在预算写入失败处注入故障，验证付款/过账/预算一起回滚及原凭证恢复。接单容量和主付款入口统一切换仍待后续实现，不开放绕过路径来完成演示。
