# 配置读取与调用边界

## 依据与决定

原生服务方实测中，SDK已经读取配置并建立连接，引导脚本却再次用不同方式解析同一文件，使正常UTF-8配置被报为JSONDecodeError。配置、操作参数和运行目录的边界也需在回写operationId前统一核验；不通过逐处添加解析兼容来解决。

| 问题 | 统一决定 |
|---|---|
| 谁读配置 | SDK持有同一JSON读取与目录解析；运行时完整校验，CLI按操作所需校验。引导只转交文件路径，宿主调用SDK后校验自己的配置 |
| CLI为何要求用户手抄数据目录 | call直接使用--config，替换--home，不保留旧别名；修改本仓全部现行调用者与说明 |
| 改错业务配置或缺密码后能否停机 | 安全查询/停止只需有效JSON及data_dir；完整配置只用于普通业务。无法解析的JSON仍明确拒绝，不猜另一份配置或另建身份 |
| 账号配置被当作参数文件 | 比较实际文件身份，参数文件还须位于SDK运行数据之外；拒绝后原文件及元信息保持不变 |
| 当前配置与已启动实例不同 | 普通业务核对账号与非凭据配置摘要、安装及同一bootId，未生效不能执行；安全诊断与停止不受业务配置错误阻断 |
| 原生通知准备 | 同一配置和独立参数文件转给宿主，SDK读取；显式核profile角色，不修改九问源码或全局设置 |

SDK仅重组输入和调用边界，不新增业务引擎、协议字段、配置副本或格式回退。身份、原操作、合同及未知结果仍保留。

## 验证范围

| 范围 | 实测结果 |
|---|---|
| 配置及调用边界 | 两技能只转交路径；BOM配置和参数经过真实CLI/IPC；相同文件、硬链接及运行数据拒绝且不回写；缺凭据/业务配置错误仍能诊断并停止原实例，业务配置改变无效果 |
| 完整检查 | 487项通过、13项跳过；693.66秒。设计、文档、自检通过；保留一项既有临时目录清理警告 |
| 干净安装 | 两ZIP共享安装后的独立接管测试通过，26.32秒；身份私钥摘要、原A2C合同、授权/UUID及实际AP2拟卡费保留；宿主和用户确认为显式隔离测试驱动 |
| 原生接入 | 服务方包17个文件逐字节匹配；带BOM配置经公开引导脚本读取成功，SDK与平台WS连接、稳定身份及宿主可用；原九问配置摘要未变 |
| 下载与页面 | 公开HTTP响应200且ZIP摘要匹配；浏览器下载事件未取得。Windows页面控制因工具无法读取当前网址停止，不能作为本机确认或完整发布的证据 |

脱敏输入摘要和代码摘要见[配置边界报告](../../deploy/verification/configuration-boundary.json)。原生完整发布、生产、私有凭据边界、Linux和新影片仍待验收；不因底层检查通过升级整个产物的设计依据。
