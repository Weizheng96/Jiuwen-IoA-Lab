# 具体合同确认与原签名恢复

## 问题与决定

取得候选不等于选择或成约。合同确认必须绑定本机实际候选和独立用户答复；平台完整价款预留先于原签1。提案沿用已建立交互，待批准仅在用户选中后才申请接单与复签，不能为比选预先签多份合同。

采用独立合同记录保存具体确认、选择证明、原卡及实际结果，不覆盖候选记录。并发选择由同一 scope 的原子约束收敛；签署和答复未知时只恢复原件，不重签、不重跑模型或自动改选。

## 实施与验证

两种模式已接通常驻确认操作，绑定具体候选、独立真实用户答复和完整价款预留，再复用原 Client.sign/adopt/countersign。原签1丢失、服务方答复丢失以及确认随后过期均恢复原件；并发选择不同卡只允许一张取得选择回执并签1。拒绝、过期、超额及错误阶段确认不产生额外签名。

原版九问待批准实测曾在 decision 阶段误调用 quote；明确 requiredAction 并返回结构化阶段错误，保留同一轮次纠正机会。修正后[两种真实成约实测](../../deploy/verification/resident-contract.json)均通过，耗时84.66秒。用户通道由测试驱动，不修改九问源码、全局指令或历史库；仅对可由公开事件确认的本单 SDK 工具提供一次性测试答复，不授予通配或永久权限。

原合同、提案及投递的25项联合检查通过；最终完整回归321项通过、5项显式模型测试跳过，耗时428.30秒，另有2项既有私有临时目录清理警告。版本、56份文档与仓库自检通过。确认入口实现后的非法 confirmed 参数仍被拒绝，原测试相应由 not_ready 精确改为 invalid_input；首轮本地 SMTP 连接复位经单独及完整复测通过，未放宽验收或增加副作用重试。

[SDK 独立安装](../../deploy/verification/sdk-install.json)以全新 Windows venv、随仓 wheels 及国内镜像完成依赖安装、隔离导入、CLI 与 pip check；不借用原开发环境，不宣称平台/宿主或 Linux 全部安装完成。开工、生产和后续亲签不因合同确认完成而视为已实现。
