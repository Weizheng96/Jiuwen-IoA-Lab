# 原版业务工具与运行权限

## 问题与决定

原版九问的显式 Agent.tools 是工具白名单，加载业务技能并不自动授予本地生产工具。原适配仅列出 SDK 回调，因而不能仅凭技能已加载声称能生产文件。公开 permission.get 可查看已配置工具，run_permissions 仅作用于本次运行且保留宿主拒绝规则。

服务方本机配置显式列出 native_tools 的精确名称和权限；与业务说明、技能一起冻结于原交互。原生工具名称自首轮进入固定 Agent 定义，但只有原合同生产轮次启用，拟卡与复签轮次明确拒绝。既有运行时没有此配置时仍无原生工具权限。权限变化不能静默接管旧 Session。

SDK 所声明的本单回调可在本次宿主轮次标记允许，避免每次调用都重复询问宿主工具许可；回调仍核原账号、交互、阶段、连接与真实用户确认。这不自动批准合同、实名环节或验收，也不自动回答原生问题。原生工具仅承载已配置本地生产能力，跨账号或外部业务效果继续经有幂等和授权检查的工具入口。

## 实施与验证

先更新规范，再实现配置冻结、能力检查、阶段权限和实际工具测试。原生权限及阶段边界12项通过；原交互配置冻结、缺工具不就绪1项通过。初次清单摘要把内部 tuple 直接交给原 I-JSON 编码，被确定性测试拒绝，改为 JSON 对象后通过，未放宽原编码规则。

原版九问完整履约1项通过，96.03秒：精确准许本机 write_file，真实文件通过原 WASM 内容判据，同一 Session 在真实环节答复后续接，原 AP2 支付定金1与期款8，结清释放名额并登记一次信誉。用户动作由隔离浏览器驱动，不作为原生网页或影片证据；脱敏记录见 deploy/verification/resident-fulfillment.json。完整测试348项通过、6项真实模型测试默认跳过，553.23秒；版本、57份文档、仓库自检和构建检查通过，产物依据不提前升级。

平台另以全新 Windows venv 安装随仓 A2C/A2X/平台 wheel 及国内镜像依赖，pip check、隔离导入与实际 HTTP 生命周期、主页、配置、会话及组件快照通过；未安装参与方 SDK、九问或共享系统包。第一次临时检查误用了不存在的路由，改为实际公开路由后仅重做验证，未改平台或重装环境。证据见 deploy/verification/core-install.json；不代替 Linux、宿主安装或完整多方验收。
