## 架构澄清

- 一个 IoA Lab SDK 包提供个人助手端与服务方端两个角色模块，共用本地接入运行时；服务方端运行于服务提供者环境，不是平台后端。
- IoA Lab 接入技能是产品统称，分个人助手技能、服务方技能；与业务技能、技能格式及 Codex 开发技能分别定义。
- 技能内容规范明确入口、按需流程页、脚本、配置及真实确认边界。实际产品文件放 connector，当前代码与目标路径的差距写入开发计划。
- 流程只串联动作与结果；组件独占领域规则；接入独占字段和方法契约；界面按证据表达，不定义另一套业务状态。

## 逻辑审查与统一处理

| 问题 | 统一处理 | 验证位置 |
|---|---|---|
| 多候选并发拟卡可能各自通过预算检查 | 本地按 scope 和稳定操作原子预留额度；未知付款继续占用，真实结果后核销 | 工程/验收 D10 |
| 零费用分支可能绕过容量提交 | 有效签署前仍须提交接单预留 | 工程/验收 D11 |
| 达到消息轮数上限即关闭会拦住最后一轮 | 上限只拒绝新增；已接受请求仍可申请开始，显式关闭及截止独立判定 | 工程/验收 M10 |
| 同一 UUID 被用于反向调用其他接口 | 固定原请求方向、参与方和接口；返回通道只回原请求，反向新业务独立授权 | 工程/验收 M11 |
| 不同消息 ID 的结果覆盖同一请求终局 | 终局不可变；相同结果返回原记录，冲突拒绝，unknown不覆盖已确定结果 | 工程/验收 M12 |
| 待批准签署被错误放在多候选比选之前 | 待批准先生成未签算价卡；用户选定确认后才签1并请求签2。提案仍可先取得签2/3报价卡后比较；最低候选报价数按两种可比来源区分状态 | 工程/验收 D12 |
| 首请求排队期间发布新修订 | 受理时冻结原修订，已入队未建UUID亦为在途；开始前仍复核当前权限 | 工程/验收 M13 |
| 网页展示本地处理摘要没有合法数据来源 | 网页仅显示公开接口与发布状态，本地处理说明由九问本地入口查看 | 界面/个人助手工作台 |
| 会议后续接受状态与不可变请求终局冲突 | 终局是当时业务回复快照，接受后更新独立预约记录，不能覆盖旧回复 | 工程/验收 M12 |
| 待批准及环节授权缺明确SDK出口 | 补受限批准/拒绝与阶段授权调用，仍使用原A2C原语 | 接入/两角色SDK |

待批准成约顺序核对 A2C `src/a2c/client.py` 的 `countersign`、`provider.py` 的 `op_card_countersign` 和 `slots.py` 的 `verify_card`；依赖版本与源码提交按本仓 `vendor/wheels/SOURCE.json` 追溯。
