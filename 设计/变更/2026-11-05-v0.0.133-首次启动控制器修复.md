# 首次启动控制器修复

Linux首次bootstrap的实际systemd字段编码问题已修正，但原安装任务固定源码摘要，直接换来源继续会破坏原请求绑定；另造部署根也会丢失原账户、候选和操作关系。因此在[安装与升级](../工程/安装与升级.md)定义显式repair-bootstrap入口。

修复仅允许已停止、失败于首次bootstrap且尚未完成的部署。新子任务固定原输入、完整候选、父来源及控制器差异；首次提交和worker首次执行重复核所有权与空控制组。不得修改平台、SDK、资产、配置接线、依赖或构建来源，不重建/激活候选、不改父记录，也不重放未知业务。后续合法子任务沿原阶段恢复，终态仍需完整首次安装就绪证据。

规范发布仅说明恢复边界，不代表实现检查或实际服务器恢复成功；原失败记录及数据保留，运行证明另按实际结果记录。
