# 后台依赖安装

## 依据与决定

原生暂停测试中，任何脚本操作都会同步执行ensure_runtime，前台60秒超时后模型重复执行。安装、SDK启动和业务操作的证明边界也不够清晰，不能靠继续延长时限或增加救援提示解决。

| 问题 | 决定 |
|---|---|
| 长安装由谁执行 | 共用installer.py中的独立进程；前台只创建或查询，不持有安装工作 |
| 两技能并发首次调用 | 按releaseId共享启动锁与后台安装锁；父调用离开后安装继续，查询不创建第二个任务 |
| 业务操作遇到缺依赖 | 明确前置条件或当前安装等待；不把安装藏在pause/status等操作中，不回写业务operationId |
| 谁读取账号配置 | 仍由SDK负责；安装任务没有账号或业务权限，环境不继承业务凭据 |
| 任务记录和进程关系 | 以实际OS锁及已校验就绪包为准；PID/时间/文件不是存活证明 |
| 后台正常失败 | 明确failed并保留日志；修正原因后显式install可重试 |
| 后台异常消失 | 未取得终局且无实际所有者则unknown，不删除或重装；避免遗留子进程和新安装同时写一个环境 |
| 完成意味着什么 | 仅依赖环境可用；配置校验、SDK启动、连接及业务仍分别核验 |

不增加旧同步入口别名，不新增平台组件或合同字段。安装实现集中到一个模块，构建及维护核验使用同一公开流程。

## 验证范围

已覆盖前台退出后的真实后台安装、双技能并发共享任务、明确失败/异常消失、纯查询和业务不安装及不读写用户文件、凭据环境隔离、完成标记损坏拒绝。实际ZIP验收检出Windows架构变量被错误剥离，修正后实导入Wasmtime、pip check及原合同接管通过；完整回归507 passed, 13 skipped, 1 warning in 833.63s (0:13:53)，设计/文档/全仓自检通过。原生九问全新缓存沿同一attemptId完成，18文件与分发包一致，原配置摘要不变。证据见[后台安装](../../deploy/verification/background-installation.json)。

本轮仅验收依赖安装；不代表完整用户接入、公示生产、私人凭据隔离、Linux或四个新影片完成。按预计耗时加权，开发约68%，整个目标约44%；产物VERSION保留实际部分依据。
