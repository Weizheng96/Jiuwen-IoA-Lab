# AgentMail会议请求兼容

| 项 | 结论 |
|---|---|
| 实测问题 | 首封SMTP邀请已送达，Outlook只有附件、没有接受按钮；AgentMail保存的转发邮件把日历变成普通附件并丢失MIME method=REQUEST，不能仅凭ICS正文正确报告通过 |
| 修正 | AgentMail使用官方Calendar API及send_invites=true发iMIP请求；其他服务仍走SMTP。只新增客户端发信适配器，不新增平台组件或第三方SDK依赖 |
| 边界 | API创建的是通知邮箱的组织者事件；接收者仍收到邮件后接受，不能直接写管理员Outlook日历，也不能替代日历冲突读取授权 |
| 配置 | IOALAB_NOTIFICATION_TRANSPORT=smtp/agentmail，默认smtp；AgentMail配置工具设置agentmail，复用已配置的邮箱/API key |
| 幂等 | 本地请求UID作为client_id，保存实际provider UID、事件id和operation_id；未知结果不自动重发，客户端状态只表示提交，不能伪造接受 |
| 验收 | 首先核对服务实际产生的text/calendar及method参数，再由用户检查Outlook接受界面和日历；旧SMTP邮件作为失败兼容样本保留，不删除原始证据 |

参考：[AgentMail邀请](https://docs.agentmail.to/calendar-invitations)、[事件和client_id](https://docs.agentmail.to/calendar-events)、[微软会议请求格式](https://learn.microsoft.com/en-us/previous-versions/office/developer/exchange-server-interoperability-guidance/hh428684(v=exchg.140))。
