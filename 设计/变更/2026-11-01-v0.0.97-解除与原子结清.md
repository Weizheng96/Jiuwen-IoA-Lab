# 解除与原子结清

## 原因

审查发现常驻个人助手没有解除入口，平台也未开放原termination.quote/notify；原成约事实只在付款checkout或开工时登记，使未开工解除无法贯通。结清还强制开始许可与非空存证，并把声明定金当实际付款；原参考支付实现无法正确完成负余额退款。

先在A2C主仓按其规则完成设计与SDK，提交712cce0及设计标签已推送，155项源码测试、七场景自检及安装后16项支付测试通过。起初不能仅换wheel：适配依赖私有金额方法且缺新的付款身份核验，必须先统一金额及身份边界。

## 整体决定

| 边界 | 决定 |
|---|---|
| 协议 | 继续使用原Client/Provider/Market、签名记录及AP2；无新合同字段、退款协议或付款引擎 |
| 委托中心 | contract.bind独立登记实际成约；保存本单原报价/通知及已核进展，按真实终态与过账结清 |
| 两端SDK | 个人助手查询报价及独立确认；服务方处理通知、收敛生产、按原协议退款及结清；同UUID/Session及原操作恢复 |
| 支付中心 | 上游公开payment_terms确定实际双方及金额；原委托方身份仍核归属，退款不要求收款方续预算，不扩大预算或允许改选 |
| 生命周期 | 解除、通知送达、资金处理、执行停止和结清分别报告；未知工具不能因收到通知就释放容量 |

## 问题审查

| 问题 | 统一处理 |
|---|---|
| 未开工是否已成约 | 依原签1/2/3登记，不以支付或work.start代替 |
| 提案服务方缺最终签1 | 宿主向原Provider.bind_contract传入本单验签原件，不假开工 |
| 定金未实际支付 | 余额按0而非卡声明扣除；零结算无付款凭证 |
| 负余额谁发起/谁收款 | 原服务方以自己的AP2身份付款，原委托方提供受限Checkout；不交换合同字段 |
| 接收退款要否重授权 | 只接收原协商差额，无新支出；原预算支出与退款分别记，不重开选合同 |
| 收到通知能否释放接单 | 先收敛实际执行及工具，再核应付款/退款并原子结清 |
| 离线和过期能否重签 | 消息TTL不改A2C期限；原签名和授权保持，未能核实保持未知 |

## 解除闭环与恢复

普通个人助手RPC可取得原签名解除报价，独立本机确认绑定合同进展、实际定金、模式和报价；依据变化拒绝旧预览。已签通知恢复沿原operationId，不重新签名或批准。原服务方与个人助手复用同一AP2 Port与身份，个人助手的退款Checkout在无模型控制通道执行，不发布个人收费接口。

服务方只停止未开始的业务；收敛核全部本交互作业和真实Future，不使用界面100条列表、取消状态或通知ACK替代执行结束。已开始工具收尾且有真实结果后可结清，效果未知保留原检查点和占用。进程重启从原消息恢复协议上下文，只读扫描不修改实际执行策略；已提交结清丢回执按原结果核对。

定向验证覆盖两种成约下补款、零额、退款和单方解除，以及原解除/付款回执丢失、工具运行/未知、服务方重启及结清回执恢复。另验证观察副本从原证据重建、旧快照不覆盖解除、实际净收支/退款方向及超过100条作业的收敛。用户确认均为隔离浏览器通道测试，不代表真实前台人工批准。当前完整回归和最终安装包仍待复验；原Linux默认部署发布限制未解除。
