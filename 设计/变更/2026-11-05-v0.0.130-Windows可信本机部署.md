# Windows可信本机部署

用户明确Windows是本机部署，不需要数据隔离和销毁重建，要求直接启动并减少依赖。Windows因此改走普通平台、SDK及原版九问的可信本机装配；Linux面向陌生用户的在线三席仍保留独立trial隔离生命周期。两者复用同一业务、协议、产品技能和真实用户批准机制，不建设第二套业务链。

现行最低依赖、配置和组件归属见[部署](../工程/部署.md)，持久目录、进程所有权与正常停止门槛见[安装与升级](../工程/安装与升级.md)。最低前提是一套Windows x64 CPython3.11和浏览器，三个venv用于锁版本隔离；原版发行自带网页静态资源，默认SQLite及内置记忆，不要求Docker、WSL、Node、nginx或外部数据库。本机入口不引入准入队列、租期、epoch或reset，保留身份、确认、合同付款和操作恢复记录。

停止仍须先SDK排空，再核全部自有原版进程和写入锁释放，不能把Windows强制TerminateProcess、父PID消失或私有关闭调用当作正常停机。可信确认继续由SDK决定，A2UI选择和模型文字不能代签。Linux试用的供应商secret独占模型代理规则仍在[在线试用](../工程/在线试用.md)，不反向增加本机依赖。

已完成的Windows Docker/WSL工程记录保留各自证明范围，不转算本机直启或Linux上线通过；被替换的Windows试用入口在本机链路验证和引用切换后整组退役，不长期维护双轨。本次仅发布规范，不递增产物VERSION；原生启动、正常停止、浏览器及完整SDK业务仍须实际验证。
