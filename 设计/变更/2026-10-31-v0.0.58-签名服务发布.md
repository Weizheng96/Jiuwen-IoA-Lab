# 签名服务发布

## 问题与决定

旧外部服务登记从用户 URL 抓取 Agent Card、JWKS 和模板，与无公网 IP 的长连接接入目标冲突。身份绑定后的稳定地址尚不提供已发布资料，普通服务方无法独立完成公示。

采用认证上传签名声明与 provider 已签模板；委托中心复用 A2C 签认，注册中心原子保存原件及回执，再重建 A2X 投影。源数据修订、原操作回执与当前索引状态分开，避免响应丢失或旧重试覆盖新公示。服务方 SDK 经常驻组件预览及真实用户确认后签署，不让模型字段替代发布授权。

## 实施与验证

| 实现 | 范围 |
|---|---|
| 注册中心 | 签名声明、修订、原模板及原发布回执独立保存；A2X 失败可按原操作重建当前投影，旧重试不覆盖新修订 |
| 应用协调 | ServiceOperations 调用委托中心 A2C 签认后提交源记录；命名为 service_operations，不与平台内服务运行器混淆 |
| 稳定协议地址 | 原版 A2C Agent Card、绑定 JWKS、声明/证明与 template.get；每服务复用持久 A2A 应用，避免临时任务队列在工作线程回收时死锁 |
| 常驻 SDK | provider.categories/preview/publish/status；发布前本机用户确认，签名请求先保存，响应丢失或重启恢复原操作 |
| SDK 分层 | 原服务执行实现移入 provider/agent.py，保留公开导入；公示模块独立，不增加官方专属执行器 |

| 完整开发检查 | 275 项通过，2 项依本机模型配置跳过；版本、56份文档、包安装清单和仓库完整自检通过 |

本轮未运行新的真实九问、会议邮件或视频验收。接单容量、统一付款及业务履约仍按开发计划推进；现有旧路径只作为迁移中的回归依据，最终须统一切换。业务产物 VERSION 保留实际旧依据。
