# 管理员控制台

## 事件与可信度

| 来源 | 可显示内容 | 可信度 |
|---|---|---|
| 市场与模拟支付 | 模板签认、签3、签5、结清、过账、裁定 | 平台直接核验 |
| 客户端/服务方合同副本 | 参与方、阶段、已核验签名链 | 签名核验后标 verified；只接受属于上报账号的卡 |
| SDK 过程事件 | 检索、比较、开始生产、等待确认、耗时与模型用量 | 标 reported，不据此付款或裁定 |

以 id 幂等接收上报；拒绝签名不符、冒用主体和旧副本覆盖更多签名的副本。市场 ledger 与支付凭证优先于过程事件；重发或乱序不使已结束合同重新开工。平台观察断开时显示“观察中断/状态未知”，不据此宣布合同失败。完整协议报文按需展开，内部模型只展示输入输出，不上传私钥或模型凭据。

消息活动以id和双方关联全景；转发会话与邀请状态如实显示，正文不进入全局广播。账号角色和消息规则分别见账号与钱包、消息中心。

## 领导演示与账号网络

个人助手页固定上方可点选网络，下方独立滚动当前委托、历史委托、金额、接口及消息；查看表单和详情时网络仍可见。网络复用管理员界面的组件目录、命名与动效，自己的助手、有关服务与平台组件保持彩色。其他个人助手用匿名灰色节点表示；专业服务始终取公开目录的真实名称，关联服务彩色、其他服务弱化。浏览器本地生成的错峰短连接不进入业务计数，图例详情说明其为示意，不在节点名称中使用“匿名服务”“背景展示”；自身活动只依实际事件和状态变化播放，连接结束彻底移除。服务器只返回本账号订单、双方消息及经授权的过程事件，不向普通浏览器传送全局事件再隐藏。公开的服务分类与描述可供浏览。

## 三段正式视频

真实全景采用四列：个人助手、平台组件、专业服务、行为日志。组件列随相邻参与方列占满同一可视高度，委托中心优先分配内部空间；悬赏/意图中心仍为灰色占位。行为日志是监控辅助面板，不作为IoA业务组件，按实际事件追加时间、参与方、动作与关联摘要，不展示消息正文或凭据；仅管理员可见，保留最近200条，支持暂停自动滚动与继续，不重播历史为新活动。

活跃演示由多账号同时发起委托与消息，首次与后续请求都随机错峰；同服务受容量约束，客户端可复用已发现的服务并周期重新发现。除十秒混合窗口外，采集瞬时连线数、不同发起方数与每秒新增传输，验收多发起方并发和活动密度；不得通过延长常驻线或增加虚构事件制造热闹。

讲解到实录使用统一的2.8秒过渡：用户先淡出，助手、整列平台组件及服务区按本轮真实首帧几何平滑变换，再进行充分重叠的交叉淡化。首帧预加载并在过渡中保持一致，过渡完成后从该帧继续播放，避免实录在后台先推进导致切换跳动。行为日志随实录渐显，概念讲解不伪造日志；最终编码核对多时点过渡帧及几何误差。

全局演示以平台组件为视觉中心：中央扩大A2X、合同模板、存证与签名、信誉及仲裁、消息和模拟支付区域；个人助手在左，专业服务在右侧窄栏按领域滚动，事件流保持辅助地位。录屏可叠加明确标识的讲解动画，包括组件描边、路径箭头和流动光点，用于说明连接关系；不能写入业务状态、伪造签名或改动真实统计。验收动画回到个人助手本地，不画成平台代验。真实状态与讲解层分别取自平台和demo脚本。

全景采用统一网络布局与动效：讲解图左侧按编号成对排列独立“用户”与“个人助手”节点，用户需求及授权从用户节点出发；真实监控只显示已登记助手，不加入用户角色。右侧按领域显示专业服务，中间组件等宽对齐。身份中心标注“智能体身份码”，委托中心标注“智能体委托合同协议”，消息中心标注“个人助手交互协议”，支付中心标注“智能体支付授权协议”。事件观察保留在运维页，不在网络拓扑展示。灰色“悬赏中心（建设中）”仅说明可发布不指定对象的委托、由助手或服务主动接取；不提供业务接口、事件或旁白。另设灰色“意图中心（建设中）”，副标题“用户权限白名单管理”；当前仅展示规划，不加入旁白、交互或现有授权逻辑。

真实监控只随实际事件产生短连接，发送后彻底移除路径、光点和文字；合同关联保留为状态，不画常驻线，历史恢复不重播连接。消息入队只显示发送到中心，收取事件才显示中心到收件人。组件可点击聚焦并查看职责，重复点击或Esc恢复。助手登记不代表在线心跳；概念片灰转彩须保持概念标识。多参与方实验在核心外通过SDK运行，消息包含预约、报平安、维修、聚餐等不同结构化用途，错峰收发；不产生真实通知或邮件。

全局视频按0—10固定剧本组织：封面；个人助手接入；登录赠币；服务登记；需求与授权；服务发现；比较/定约/交付/本地验收/争议；付款与信誉；P2P消息；平台定位；对内外价值。0—8只播放当前旁白对应路径，使用可复现的有限随机事件计划：错峰、部分并发、快速单次传输，结束即撤除；不用逐个点亮、周期循环或持续连线填满镜头。9—10通过短渐变切入唯一的全屏真实管理员监控：用户角色先虚化淡出，个人助手从配对排列平滑过渡到真实监控位置，真实画面渐显；片尾继续展示活跃网络；不同时并排概念图与真实图。概念片与真实监控复用网络布局和路径动效。A2X分类树与ANN并列解释，本轮执行必须有a2x-tree事件，ANN标为方案介绍，不伪称本轮启用。支付授权、分歧仲裁若仅展示机制须有简短画面标识，不补造本轮授权报文或裁定；不在仲裁旁白追加本轮是否发生裁定的说明。

片头为完整封面，名称与一句话介绍一致；字幕使用高对比底条、大字、短句，单条不挤成小段落。英文术语单独控制读法，A2C配音为“A to C”；旁白沿用参考视频的快语速参数并核对实际字速，镜头时长服从实测音频。

| 视频 | 观看顺序 | 验收边界 |
|---|---|---|
| 全局视角 | 平台定位 → 个人助手与专业服务接入 → 多方并行 → 发现/定约/交付/本地验收/模拟支付 → 助手消息 → 账号聚焦 → 对内验证与对外体验价值 | 叙述参考A2C主仓demo/智能体互联网剧本；使用当前独立客户端实录，旧片人数、拒单与仲裁结局不沿用；标记experiment，不在核心运行助手 |
| 美甲委托 | 九问输入 → A2X发现/筛选 → 比较报价及验收 → 用户确认 → 服务生产 → 本地验收 → 模拟支付 → 服务方记录 | 左真实九问网页、右本人工作台；用户只说需求，九问在授权、签约、实名注册与验收四处等待确认；交付预约工具和微信小程序源码，注册环节只演练授权，不声称微信已审核上线 |
| 助手交互 | A设置精确账号范围 → B查询结构化接口 → 留言/预约 → A处理 → 邀请 → 用户在Outlook接受 | 账号字符串不等于邮箱域名认证；预约依据必须真实可用，邀请受理不等于已入历 |

字幕每镜头只讲一件事，优先一行、短句，成片1080p字号不小于44px并留安全区。旁白语速约正常的1.12倍；先按实际音频时长安排镜头，真实调用等待可标明后压缩，不能提前显示尚未发生的结果。组件点选与所讲步骤同步，音频、字幕与业务证据同一时间轴。剧本与录制入口在demo，正式成片与原始运行证据分开保存；测试替身持续标识，不冒充正式用例。

委托片比较实际服务模板与报价，显示判据覆盖差异，合同完成后切换服务方账号核对同一摘要和实际收入，再演示交付配置启动的本地预约工具。消息片以王经理的个人助手和赵专员的个人助手为例，展示王经理设置的交互接口、账号范围、输入格式，以及赵专员查询接口、发送结构化消息、收到冲突回执后改约的真实过程。讲解聚焦消息中心，不展开本地日历实现；接收方依预授权规则处理，不宣称模型自由谈判或读取私人Outlook。合适的预约发出邀请，交王经理接受。邀请由配置的AgentMail通知邮箱发送，当前交互片以平台消息链路为实录范围，Outlook接受及入历用条件式旁白与明确标注的流程说明图收尾；不显示伪造邮箱页面，不宣称本轮已收件或已接受。若另制作完整邮箱实录版，接受及日历显示必须来自本轮真实界面。

两段正式片采用同一制作顺序：真实端到端执行并保存时间点 → 按实测旁白裁切连续录像 → 叠加短字幕和组件说明 → 核对业务证据与最终编码。左九问、右工作台为主，服务方和交付工具可切为整屏；录制本身不更改业务数据。长等待剪辑明确标记，不能先展示完成结果再补录执行过程。委托先取得目的、总预算和拟卡费限额授权，渐进筛选七家原剧本服务，比较三份真实提案并推荐码上飞；确认合同后开工，遇到合同声明的实名注册环节再请求用户授权；本地验收结果出现后再确认接受付款。交互发起方仍通过九问的本地IoA技能，接收方以既定规则处理；展示接口规则和邀请待接受状态。收件人邮箱与发起账号分开，邮箱形式账号不宣称已经认证企业归属。

实际接入须区分网页模型资源ID与Process模型选择键；官方服务启动前以只读查询验证模型选择，不在收取拟卡费后才暴露无效配置。技能只在已明确授权的对象、用途与限额内传递confirmed；命令漏参不使既有授权失效，也不允许借此扩大授权。模型建议、模板价格与真实提案卡分别记录。

每轮正式委托录制使用新的独立参与方数据目录，开始前检查没有旧合同。未采纳的提案仍可能占用服务容量，不能为了重拍删除旧合同、重置任务或反复支付拟卡费。比较完成后，通过工作台现有合同详情按钮选中本轮中选合同，流程条、金额和组件讲解始终对应同一摘要；成片逐镜头核对。已跑通但未完成镜头质量检查的片段标为初剪，交互片显式选择接受环节的呈现方式：recorded要求本轮真实Outlook接受入历证据；narrated为用户允许的平台链路演示，后续接受入历仅旁白说明，原回执保留待接受。未显式选择旁白范围时仍拒绝缺失邮箱实录证据的正式发布。

每个Demo在自己的场景目录提供一份剧本.md，包含角色、镜头、画面操作、字幕、完整旁白、实测时间与证据边界。剧本由场景源、已发布配音时间轴和脱敏证据生成；按本片演示范围生成分镜；旁白收尾版不编排Outlook操作镜头，明确其后续流程说明。完整实录版缺失的镜头仍标待补录，不编造起点。根演示说明只维护入口与复现命令，不再另写一份镜头方案。生成一致性、公开素材哈希和缺证拒绝纳入自检；剪辑、成片检查和发布共用同一套真实用例证据判定。

真实录制的实验流量由独立的委托与消息工作线程持续产生，委托等待或模型搜索不阻塞收发消息；不按业务类型分段，也不以固定笔数结束委托后单独保留消息。初次发送与后续活动均随机错峰，维持两类交互同时进行。按可见传输活动调整到接近的比例，一笔委托的发现、定约、交付、验收与付款包含多次往返，不用订单数直接对比消息数。实际订单、消息及可见活动计数分别记录。按服务串行控制实验容量，不删除合同或伪造业务活动。

录制开始前等待两类真实传输均已出现，剪去初始化空场；通过管理员绘制计数的定时采样检查录制窗口，每个完整十秒窗口都必须同时包含委托与P2P传输，保存各窗口数量、重叠比例及总体比例。未达到混合要求的实录不发布；播放页循环源与影片真实监控段使用同一份合格素材。

服务方工作台采用运营台布局：页首服务数、履约数、完成数、实际收入；左侧A2X分类和服务导航，右侧固定展示所选服务的身份、可用状态、履约队列与历史合同。服务选择跨轮询保持；收入仅来源于该服务的deposit/installment凭证，拟卡费另列，不计为交付收入。没有注册服务时给出接入入口，不补造服务、客户或收入。
