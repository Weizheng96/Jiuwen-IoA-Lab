# 管理员控制台

本文规定三种工作台的可见范围、证据表达与网络视图。视频制作规则见[演示制作](示例/演示制作.md)。

## 视图与数据权限

| 视图 | 内容 | 数据范围 |
|---|---|---|
| 管理者 | 全景网络、组件详情、行为日志、当前活动与历史记录 | 具有管理权限的账号；消息正文须另经消息审计入口读取 |
| 个人助手 | 上方网络；下方当前委托、历史委托、金额、接口及双方消息 | 本账号所属助手、所属合同及有权读取的交互 |
| 服务方 | A2X 分类树、所属服务、履约队列、历史合同、实际收入 | 本账号所属服务及其合同 |

登录后按账号权限切换视图。ISC_001 默认具有管理权限；账号角色不授予外部消息执行权限。未关联助手的内部账号保持空闲，不生成平台内助手。

服务端先裁剪数据，再交给浏览器。不得把其他用户的合同、消息或全局过程事件发送给普通用户后仅用样式隐藏。

## 全景网络

| 区域 | 布局与行为 |
|---|---|
| 左列 | 已登记个人助手；区分登记、在线、忙碌、断联，不把登记视为在线心跳 |
| 中列 | 平台业务组件；组件等宽对齐，整列高度与相邻参与方列一致，委托中心获得充足内部空间 |
| 右列 | 专业服务按领域组织，使用公开名称；缩减所占宽度，突出平台组件 |
| 最右列 | 管理员行为日志；展示实际事件时间、参与方、动作、关联摘要 |

| 业务节点 | 协议或用途标注 |
|---|---|
| 身份中心 | 智能体身份码 |
| 注册中心 | A2X 服务发现 |
| 委托中心 | 智能体委托合同协议（A2C） |
| 支付中心 | 智能体支付授权协议（AP2） |
| 消息中心 | 个人助手交互协议 |
| 悬赏中心（建设中） | 不指定对象的委托；助手或服务可主动接取 |
| 意图中心（建设中） | 用户权限白名单管理 |

悬赏、意图中心使用灰色占位，无可执行业务接口、活动事件或自动授权能力。事件观察、事件总线和运行进程状态放在运维详情中，不作为智能体互联网业务节点。

身份与服务节点可点击聚焦；按账号聚焦时，高亮其名下全部助手和服务，其他参与方弱化。组件可点击高亮并展开职责及相关记录；重复点击或 Esc 恢复，刷新保持有效选择。

## 事件与证据

| 来源 | 可显示内容 | 证据标识 |
|---|---|---|
| 委托中心与支付中心 | 模板签认、签名存证、结清、过账、裁定 | 平台直接核验 |
| 参与方合同副本 | 参与方、期号、签名链与合同状态 | 验签后为 verified；仅接受所属账号有权上报的副本 |
| SDK 过程事件 | 检索、比较、生产、等待确认、耗时、用量 | reported；不能作为付款或裁定依据 |
| 连接及投递记录 | 在线状态、暂存、送达、处理结果 | 按相应层的实际回执显示 |

事件按稳定 ID 幂等接收。拒绝冒用主体、签名不符及旧副本覆盖更完整签名链；重发和乱序不能使已结束合同重新开工。合同摘要贯穿相关视图，交互 ID 关联助手通信，二者不混用。

观察断开显示“观察中断／状态未知”，不能据此认定合同失败。完整协议报文按需展开；内部模型只展示输入和输出，不上传密钥、凭据或隐藏推理。

行为日志保留最近 200 条，支持暂停自动滚动和继续。日志不含消息正文、凭据，不把历史恢复重播为新活动；消息审计权限与一般全景权限分别检查。

## 动画与状态

| 情况 | 展示规则 |
|---|---|
| 实际传输 | 按事件产生快速、短时连接，完成后彻底移除路径、光点和文字，无残影 |
| 合同仍在履约 | 保留状态与详情，不以常驻连线表示 |
| 消息已入队 | 展示发件方到消息中心；接收端送达回执出现后才展示后半段 |
| 历史恢复 | 恢复状态，不重放发送动画 |
| 同时发生 | 允许多个发起方、不同交互方式并发，按真实时间顺序表现 |
| 预约 | 分开显示本地预留、邀请提交和接受状态，不把服务受理画成已入历 |

管理员真实网络只使用实际事件，不在空闲时补造交易。讲解动画可独立使用可复现的有限事件计划，必须与真实状态区分；其制作要求见[演示制作](示例/演示制作.md)。

## 个人助手工作台

上方网络始终可见，下方记录、表单和详情独立滚动。组件目录、命名及短连接动效与管理员界面一致；自身助手、相关服务和相关组件突出显示。

其他个人助手使用匿名灰色节点；专业服务使用公开目录的真实名称，关联服务彩色、其他服务弱化。节点不使用“匿名服务”“背景展示”等名称。

为了表达网络环境，浏览器可生成其他匿名助手之间的错峰短连接示意；示意不来自其他用户私有数据、不计入活动统计，图例说明其性质。自己的活动严格来自实际事件，不用示意补齐缺失步骤。

流程条依次表达发起、发现、筛选、协商、定约、交付、本地验收和付款；没有观察到相应事件就保持未知，不补造完成节点。点击对应组件可查看作用、真实回执和证据。

设置区域标题为“我的收信规则”，支持查看允许发信人、接收格式及处理摘要；提供在九问中辅助配置的入口。对外说明使用“收信接口”；活动统一使用“个人助手间交互”，不把所有交流都称作协作，也不强调收费与否。双方消息的显示名仅向有权读取的账号展示。

## 服务方工作台

页首先展示服务数、履约数、完成数和实际收入；左侧为 A2X 分类与服务导航，右侧固定展示选中服务的身份、可用状态、履约队列和历史合同。

服务选择在数据刷新后保持；按稳定服务身份关联记录，不按显示名称猜测归属。无服务时提供接入入口，不补造服务、客户或收入。

收入仅计实际过账凭证；定金与分期款按服务汇总，拟卡费单列。合同总额、报价及已验收金额不能直接作为收入。

管理员双屏入口保留 `/admin?view=panorama`，另一屏展示真实九问。浏览器观察流与智能体业务长连接各司其职，断线后按快照补齐状态，不伪造模型轨迹。
