# 支付中心

## 目的与范围

通过 AP2 接口执行虚拟币记账、授权核验和按证据付款。虚拟币仅为实验记账单位，协议币种使用 SDK 支持的 CNY，界面明确标注虚拟币。本期不实现 A4P。

支付中心不决定服务是否接单，不替用户确认合同或验收，不根据普通观察事件或模型声明付款。A2C 负责合同与付款依据；本组件按其证据过账。

## 职责与数据

| 对象 | 权威记录与约束 |
|---|---|
| 虚拟币余量 | 按已核实过账记录计算；更新受数据库事务保护 |
| 授权凭证 | 绑定付款身份、用途、类别、预算/费用限制和有效期；核验签名与适用范围 |
| 付款操作 | 稳定操作标识、付款/收款方、用途、协议摘要、金额及最终结果 |
| 付款凭证 | 成功操作的原始凭证；相同操作重传返回原凭证 |
| 登录发放记录 | 与身份中心确认的登录操作绑定，防止同一登录重传重复发放 |

付款公钥与收款身份以[身份中心](身份中心.md)绑定为准。运行时私钥和用户确认保留在本地，支付中心只接收相应签名与必要凭证。

## 登录赠币

| 情况 | 规则 |
|---|---|
| 用户名密码成功登录 | 每次新的明确登录按配置发放，默认 100 虚拟币 |
| 注册后的首次自动登录 | 按该登录操作发放 |
| 同一次登录网络重传 | 恢复原登录操作，只发放一次 |
| cookie/Bearer 复用、票据续取、WS 重连、重复身份绑定 | 不构成新的登录，不发放 |
| 登录失败 | 不发放 |

身份中心发布的登录成功记录与发放记录按稳定操作关联；跨组件处理失败时恢复原操作，不能要求客户端重新密码登录来补发。

## 授权与过账

| 检查 | 必须满足 |
|---|---|
| 主体 | 付款方、服务收款方及用途公钥与已绑定身份一致 |
| 用户授权 | 真实授权在有效期内，覆盖用途、类别、总预算和拟卡费限额；不能只解码 JWT 而不验证签名及截止 |
| 协议依据 | 拟卡费、定金、各期款和解除款分别使用 A2C 规定的依据；每期款依签5(i)及签7(i) |
| 金额 | 从可验证卡/请求及协议计算取得确定数值，不能接受模型任意填写的费用 |
| 幂等 | 同操作同内容返回原结果；同操作异内容冲突，不另行过账 |
| 可用余量与额度 | 在同一过账事务中核实并更新；同一付款授权并发使用不能绕过总额度 |
| 成功证据 | 持久化过账和凭证后才返回成功；观察事件只是其投影 |

首次委托授权、具体合同确认、合同声明的环节授权及验收确认分别执行，不能相互替代。具体取得确认的过程见[委托交易](../流程/委托交易.md)；本地保护规则见[本地接入组件](本地接入组件.md)。

## 与接单预留的事务边界

当前 AP2 模拟支付与委托中心使用平台内明确的应用事务协调，无需引入分布式交易框架：

1. 委托中心核实预留归属、绑定摘要、有效期和未关闭状态。
2. 支付中心核实授权、付款操作与费用依据。
3. 同一事务将预留提交为 `committed`，执行虚拟过账并保存原凭证；任一检查失败不产生本次过账。

支付中心不自行创建接单承诺。拟卡费为零时无需虚构付款，但仍由委托中心在服务方有效签署前提交预留。已经开始付款或签署的未知结果必须先对账，不能按短预留到期直接释放，详见[委托中心](委托中心.md)。

## 异常与恢复

| 情况 | 处理 |
|---|---|
| 付款响应丢失 | 按原操作查询并返回原凭证或明确未生效状态，禁止更换标识重复付款 |
| 付款结果未知 | 保留原凭据与关联预留，进入待核实；不能把超时解释成未付款 |
| 授权过期或超限 | 拒绝新过账并说明原因；不自动扩大授权或移动费用用途 |
| 拟卡失败但已付费 | 保留实际费用凭证；不自动退款、重新收费或抹掉记录 |
| 仲裁裁定 | 文书供当事人使用；裁定本身不自动触发过账 |
| 客户端进程退出 | 从原付款操作、合同与授权检查点恢复；不按模型会话是否结束判断付款结果 |
