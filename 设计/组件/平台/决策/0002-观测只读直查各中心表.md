# 观测只读直查各中心的表

工作台、管理员全景与公开统计要把账号、服务发布、接单、合同、付款与投递汇成一屏。备选是每个中心各自提供查询接口再由观测拼装，或建一套物化的读模型。决定：观测用只读 SQL 直接连接各中心的表生成视图；它自己只写随原业务事务保存的已验签合同展示副本；事件历史 `events` 由平台基础的事件总线定义并写入；任何查询都不写业务表、不领取消息、不推进游标。

原因：单库下跨表只读连接最简单，分页与权限裁剪在一条查询内完成；各中心不必为页面维护查询接口。代价是各中心的表结构对观测可见，改表须同时改观测的查询。约束：其他业务模块不得援引本决定直接读写他人的表；观测不得把视图结果回写为任何模块的权限依据。规则见[观测接口](../观测/接口.md#不变量)。
