# 支付中心

## 目的与范围

通过 AP2 接口执行虚拟币记账、用户授权核验和按 A2C 证据付款，并持有账号初始发放与登录赠币的资格台账。虚拟币仅为实验记账单位，协议币种使用 CNY，界面明确标注虚拟币；本期不实现 A4P。本模块不决定服务是否接单，不替用户确认合同或验收，不按观察事件或模型声明付款；A2C 负责合同与付款依据，本模块按其证据过账。调用方是 web服务 的应用用例与路由；参与方经 HTTP 入口到达，不直接导入。

## 独占数据与配置

| 数据或配置 | 说明 | 存储 |
|---|---|---|
| 钱包与账本 | 每账号一个钱包，余量按已核实过账记录计算；发放、扣减、转账三种改法全部留痕，更新受事务保护 | `wallets`、`wallet_log`、`transfers` |
| 发放资格 | 账号初始发放只在新建账号的同一事务发放一次；登录赠币按账号与业务日记录，绑定原登录 operation | `wallet_log(kind=initial/login)`、`login_reward_days` |
| 付款记录与原凭证 | 付款键、付款与收款账号、金额、币种、付款方公钥指纹、已签 voucher 与 Payment Receipt | `payment_records`、`paid` |
| 委托范围与许可 | 不可变 context、按修订的 grant 与 proof、已付拟卡费、已选合同与预留价款、逐笔付款关联、范围操作幂等记录 | `delegation_scopes`、`delegation_grants`、`delegation_scope_payments`、`delegation_scope_operations` |
| 付款操作记录 | 应用层一次 AP2 付款加容量与预算的幂等记录；表由本模块定义，当前写入者见[票据](../进展/01-付款操作记录归属.md) | `delegation_payment_operations` |
| 配置 | 初始发放额默认 500、登录赠币额默认 100、同日重复领取开关默认关闭；唯一取自平台配置，只影响随后新操作，不追溯账本 | [平台配置](../../../工程/平台配置.md) |

付款公钥与收款身份以身份中心绑定为准；运行时私钥和用户确认留在参与方本地，本模块只接收签名与必要凭证。

## 接口

事务内接口以 `_in(conn, …)` 命名，只接受所属平台连接并要求已在事务中；准备类接口在事务外完成签名、合同与金额核验，不产生过账。错误对象与状态码见[平台基础](../../../工程/平台配置.md)所属的 `LabError`，协议错误复用 A2C 的 `BAD_SIGNATURE`、`CARD_INVALID`、`OUT_OF_ORDER`。

### 账号发放与登录赠币

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `Wallets.initial_credit_in(conn,user_id,amount)` | 新账号初始发放 | 在账号创建的同一事务调用；返回实际发放金额，已发放返回 `0.00` | 非有限或负金额拒绝；预置账号同规则；不给历史账号补造 | account_rewards |
| `Wallets.login_credit_in(conn,user_id,operation,policy)` | 成功的明确登录或注册自动登录赠币 | 返回 `{login,day,reason}`，reason 为 granted、restored、already_claimed、disabled、history_unverified | 同 operation 重传返回原结果，不按新配置补发；cookie/Bearer 复用、票据续取、WS 重连、重复绑定不构成登录；登录失败、内部错误或零额不占当日资格；缺可核日期的旧发放记录不再授予第二次 | account_rewards、authentication_recovery |
| `Wallets.reward_day(timestamp)` | 业务日 | Asia/Shanghai 日期字符串 | 与宿主时区无关 | account_rewards |

### 账本

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `money(x)` | 两位小数十进制定值 | `Decimal`，四舍五入到 0.01 | 调用方须拒绝 NaN、无穷、负数与超两位输入 | wallet、rule_boundaries |
| `Wallets.ensure(user_id,payer_thumbprint=None)`、`bind_payer_in(conn,owner,thumbprint)`、`by_thumbprint(tp)` | 钱包存在性与付款公钥指纹绑定 | 指纹唯一，反查账号 | 绑定只在所属应用事务内改写 | wallet、payment_atomicity |
| `Wallets.balance(user_id)`、`log(user_id,limit=50)` | 余量与流水 | `GET /api/wallet` 的数据源 | 未建钱包返回 0.00 | wallet |
| `Wallets.adjust(user_id,delta,*,by,note,kind)`、`adjust_in(conn,…)` | 管理员发放或扣减 | 追加记录并返回新余量；`POST /api/admin/wallet` | 扣减后余量为负拒绝“余量不足” | wallet、admin_api |
| `Wallets.transfer_in(conn,payer,payee,amount,*,purpose,ref,payment_id)` | 过账转账 | 双方流水与 `transfers` 一行 | 金额须正；余量不足则两边都不变 | wallet、payment_atomicity |

### 委托授权台账

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `ScopeLedger.prepare(owner,actor,kind,payload)` | 事务外校验 `scope.register`、`scope.status`、`scope.select`、`scope.close` 的字段、签名与时间 | 返回 `PreparedScope`；register 核 context 归属、grant 最长 7 天、proof 签署时间等于 issuedAt；select 核原模板、卡链、币种、归属、提案响应窗口与选择证明 | invalid_input；他人 actor 或平台 forbidden 403；提案窗口已过 expired 409 | delegation_scopes、rule_boundaries |
| `ScopeLedger.apply_in(conn,owner,operationId,prepared)` | 同一短事务登记、查询、选择或关闭 | 公开摘要：scopeDigest、acceptedRevision、授权截止、已付费用、已选合同与额度；`POST /api/v1/scopes`、`GET /api/v1/scopes/{scopeDigest}`、`POST …/close` | 同 operation 异内容 id_conflict 409；原成功操作重传恢复原结果；关闭原子推进修订并拒绝新动作，保留证据与支出 | delegation_scopes |
| `ScopeLedger.operation(owner,actor,kind,operationId)` | 查询原范围操作结果 | 原结果 | 不存在或他人 not_ready 404，recovery=retry_original | delegation_scopes |
| `ScopeLedger.record_payment_in(conn,owner,actor,scope,payment)` | 在 AP2 与容量提交的同一事务记入拟卡费或合同付款 | 更新已付费用与合同已付；同 payment_id 重入返回原摘要 | 拟卡费：已选合同 closed 409、分类越界 forbidden 403、超拟卡费上限或总预算 quota_exceeded 409；合同付款：非被选合同 forbidden 403、超预留价款 quota_exceeded 409 | delegation_scopes、payment_atomicity |
| `ScopeLedger.eligibility_in(conn,owner,actor,scope,subject,provider,currency,*,selected)` | 接单准入前的授权视图，不预留不签名 | 公开摘要 | 客户端、用户、币种或分类不符 forbidden 403；已选合同不再征集 closed 409 | delegation_admission |
| `ScopeLedger.authority_in(conn,owner,actor,scope)` | 原 A2C 材料授权所用的用户公钥 | context.user | 过期或关闭拒绝 | delegation_scopes |
| `ScopeLedger.contract_in(conn,owner,actor,scope,card)`、`selected_card_in(…)` | 已选合同权威与历史选择 | 已选合同在新许可过期或关闭后仍有效 | 非原被选完整价款合同 forbidden 403 | delegation_scopes、resident_contracts |

### AP2 付款

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `SimPaymentProvider.prepare(body,files=None)` | 事务外用上游参考实现核验 PM、CM、Checkout 签名、双方绑定、定金与金额，不动账 | 返回 `PreparedPayment`；同 fingerprint 已过账直接返回原件视图 | 无付款方公钥、身份不绑定、付款方非原协议身份、定金与原合同不符 BAD_SIGNATURE/CARD_INVALID；带文件拒绝；窗口外拒绝 | payment_rules、payment_rejection |
| `SimPaymentProvider.commit(conn,prepared)` | 调用方事务内重核身份绑定、定金事实与期限，统一写扣增、`paid`、`payment_records` 及按提交时点签署的 voucher 与 Payment Receipt | 返回 `(Reply, created)`；同键同请求返回原件且 created 为假 | 同键异请求 OUT_OF_ORDER；历史付款缺原件 OUT_OF_ORDER 待核实；绑定变化 BAD_SIGNATURE；提交前过期 BAD_SIGNATURE | payment_atomicity、payment_rejection |
| `SimPaymentProvider.project(prepared)` | 提交后发布过账观察 | 调用 on_transfer | 失败只记日志，不撤销付款 | payment_atomicity |
| `SimPaymentProvider.op_ap2_pay(body,files,task_id)` | `/a2a/pay` 原协议入口 | 未登记服务直接准备并在自有短事务提交 | 已登记服务要求当前 IoA 执行连接与准入上下文 OUT_OF_ORDER | payment_rules |
| `SimPaymentProvider.lookup(owner,payment_id=None,*,ref,purpose,period)` | 原付款或收款账号查询原凭证 | `GET /api/v1/payments/{paymentId}`、`GET /api/v1/payments?ref&purpose&period` | 非当事人 404 | payment_transport_recovery |

## 不变量

| 规则 | 说明 |
|---|---|
| 授权核验 | 真实授权在有效期内覆盖用途、分类、总预算与拟卡费上限；必须验签与截止，不能只解码 JWT。分类以注册中心实际归属核验，不采用来信自报 |
| 主体 | 由上游 `payment_terms` 确定付款与收款双方；正向付款由委托方拥有的身份发起，解除退款由原服务方拥有的身份发起；双方 AP2 公钥与账号绑定在准备与提交均复核 |
| 金额 | 从可验证卡或请求与协议计算取得，不接受模型填写；拟卡费、定金、各期款与解除款分别使用 A2C 规定依据，每期款依签 5(i) 与签 7(i) |
| AP2 窗口 | PM、CM 与 Checkout 均核 iat 与 exp；最长 15 分钟，iat 最多超前 60 秒；过期不发起新付款，但完全匹配的已成功请求可恢复原件 |
| 付款键与幂等 | 协议摘要、用途、期次构成付款键，另绑定认证付款方与完整原请求摘要；同键同请求恢复原件，同键异请求冲突不再过账；过账 paymentId 与回执 payment_id 一致 |
| 成功证据 | 持久化过账与原凭证后才返回成功；观察事件只是投影，投影失败不撤销付款也不造成第二笔 |
| 范围与许可 | context 不可变，scopeDigest 只对 context 计算；grant 最长 7 天，签署最多超前 60 秒；续期只换期限，不改 context、不重置支出或已选合同；撤回推进修订，旧许可与撤回前在途续期不能恢复权限。取舍见[决策](../决策/0001-委托范围上下文与许可分离.md) |
| 预算 | 拟卡费只在实际过账事务计入，累计不超过拟卡费上限与总预算；选择具体合同在签 1 前原子预留完整价款，一个范围只有一个被选 cardDigest；合同付款只消费预留价款，不重复计入总预算；提交时再核原模板与提案响应截止 |
| 协商解除 | 按原签名解除记录计算费用减实际已付定金；正数补付、负数退绝对值、零不生成付款；退款不增加委托方支出、不重置预算、不开放改选；服务方余量不足不强制划转 |
| 事务边界 | 接单预留、范围预算与 AP2 过账由 web服务 的应用用例在同一短事务协调；本模块是账本唯一写入者，不自行创建接单承诺；见[跨模块决策](../../../决策/0001-应用短事务协调接单与付款.md) |
| 发放 | 同账号同业务日登录赠币最多一次，开关开启后每个新 operation 可再领但同一 operation 仍只发一次；初始发放不消耗当日资格；展示与事件使用实际发放金额 |
| 结果未知 | 响应丢失按原操作查询原凭证或明确未生效，禁止换标识重付；未知结果保留原凭据与关联预留进入待核实，不解释为未付款；客户端进程退出从原操作检查点恢复 |
| 明确拒绝 | 同一应用事务回滚后保留原拒绝与可公开原因，余量不足、期限变化不统一掩盖为过期；拒绝只证明该准确请求未过账 |
| 历史与裁定 | 旧 `paid` 缺原件保持待核实，不重签也不删后重付；已裁定原卡只允许已签 5、签 7 的原价款与协商解除余额，裁定本身不触发过账；拟卡失败但已付费保留凭证，不自动退款或重收 |
| 数据保留 | 已产生付款事实不以“保留账号并清空交易”方式重置；实验使用新身份或独立数据目录 |
