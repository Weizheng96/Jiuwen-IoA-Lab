# 03：服务目录事实归入所属模块

**目标行为：** 服务的公开名称、分类、协议地址与 listed 状态只由一个模块的表持有并经其接口读写。现状是注册中心的 `indexed_in` 直接 UPDATE 身份中心的 `agents` 表（name、definition、status），`RegistryView.category_in` 直接 SELECT 该表的 definition，身份中心的 `list_owned`、`services_owned` 又读这些字段。

**阻塞于：** 无

**状态：** ready

**范围：** 注册中心与身份中心。两个可选方案：注册中心自建 `registry_services` 表持有目录事实，身份中心只保留身份与绑定；或身份中心暴露 `IdentityDirectory.list_service_in` 一类事务内接口供注册中心写入。需读[注册中心接口](../注册中心/接口.md#签名发布)、[身份中心接口](../身份中心/接口.md#归属查询)与两者的实现页。

**定向测试：** service_publication、search_availability、account_views、delegation_admission、domain_migrations

- [ ] 目录事实只有一个写入者
- [ ] 跨模块读写经接口页所列接口
- [ ] 两个模块的接口、依赖与实现页同步
