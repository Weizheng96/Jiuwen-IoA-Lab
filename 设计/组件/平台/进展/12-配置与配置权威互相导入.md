# 12：配置与配置权威不互相导入

**目标行为：** 平台基础内 `config.py` 只定义类型化配置，不导入 `configuration.py`；从私有平台配置文件得到 `Settings` 只经配置权威 `PlatformConfiguration` 一个入口；`ioalab --config`、配置修订更新与脱敏视图的行为不变。现状：`configuration.py` 顶层 `from .config import Settings, DEFAULT_LLM_BASE`，而 `config.Settings.load` 在函数内延迟 `from .configuration import PlatformConfiguration` 再调用其 `settings()`，`Settings.policy` 又依赖鸭子类型的 `_configuration` 字段回调配置权威；两文件互为依赖，靠延迟导入避开循环。`tools/check_modules.py` 只核跨模块导入，不报模块内循环。`Settings.check` 的种子清单校验已改由命令行注入，本票不必再处理。

**阻塞于：** 无

**状态：** ready

**范围：** 平台基础 `config.py`、`configuration.py`；调用方 web服务 `cli.py`（`Settings.load`）。方案：把 `Settings.load` 收为配置权威的模块函数或类方法，`Settings` 不再持有回调配置权威的字段，`policy` 由调用方从配置权威取得或在构造时传入值。需读[平台基础接口](../平台基础/接口.md#配置)与[平台基础实现](../平台基础/实现.md)。

**定向测试：** platform_configuration、configuration_web

- [ ] `config.py` 不导入 `configuration`，两文件之间只剩单向导入
- [ ] `cli.py` 与测试经配置权威入口取得 `Settings`；缺文件、无效内容与权限错误的报错不变
- [ ] 平台基础实现页的入口表与内部分区随之更新
