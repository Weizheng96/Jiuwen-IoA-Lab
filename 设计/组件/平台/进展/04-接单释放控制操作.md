# 04：接单释放控制操作与接口文档一致

**目标行为：** 接口文档列出的接单控制操作与代码一致。现状：[WebSocket 控制报文表](../web服务/接口/WebSocket与消息封套.md)写 `admission.reserve/commit/release/status`，代码的 `Admissions.apply_in` 只实现 configure、reserve、commit、status；释放只发生在预留到期、真实结清、交互关闭与未中选提案维护。文档还缺 `admission.configure`。

**阻塞于：** 无

**状态：** ready

**范围：** 委托中心与 web服务 的接口文档。先由用户裁定取向：一是删除文档中的 release 并补上 configure，说明释放只由平台按证据完成；二是实现受限的显式释放，仅用于已付拟卡费而服务方明确拒绝拟卡等可证明无承诺的情形。前者是事实性修正，后者是不变量变化须先改接口页并升版。需读[接单与容量](../委托中心/接口/接单与容量.md#到期与释放)。

**定向测试：** provider_admission、delegation_admission、proposal_expiry

- [ ] 接口文档与 `apply_in` 支持的种类一致
- [ ] 若实现显式释放，覆盖有承诺时拒绝、无承诺时原子释放与重传恢复
