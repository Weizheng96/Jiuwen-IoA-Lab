# 14：浏览器与参与方路由经装配层取种子与文件限额

**目标行为：** `web/` 下的 HTTP 路由只调用 `Platform` 已装配的对象与应用用例，不直接导入种子、存储与文件模块；`/api/services/definitions`、`/api/admin/seed` 与 `/api/v1/files/{agentId}` 的请求、结果与拒绝不变。现状：`web/app.py` 的 `definitions` 路由在函数内 `from ..seed import load_definitions` 并按请求读取种子文件；`/api/admin/seed` 路由 `from ..seed import seed_all` 后把整个 `platform` 交给它，而 `Platform.ensure_seeded` 已是同一调用（其 `force` 参数与路由传入的 `only` 参数都未被使用）；`seed_all` 又经 `platform.db` 直接查询身份中心的 `agents` 表取服务分类；`web/app.py` 顶层导入的 `storage.jdump`、`jload` 未被使用；`web/api_v1.py` 的文件上传在函数内导入 `files.MAX_FILE` 与 `errors.LabError`，在流式读取时预先限长，与 `PrivateFiles.put` 的同一检查重复写出上限与错误文字。`/api/admin/seed` 未写进 web服务 接口页。
