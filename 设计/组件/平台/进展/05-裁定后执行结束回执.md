# 05：裁定后执行结束回执

**目标行为：** 终局裁定后，原服务方提交 caseRef 与原执行关联的结束回执；平台核裁定、实际写入者与原协议 Task 已收敛、冻结卡的原应付款齐全后，在同一事务释放接单容量、关闭交互并把案件执行状态置为已结束；重传恢复原结果，未核实时不释放。

**阻塞于：** 无

**状态：** ready（与当前设计有偏离）

**范围：** 委托中心与消息中心。现状：平台只接受 `arbitration.request` 一种仲裁控制操作；案件的 `execution` 只在裁定提交时按已有市场结局置 finished，其余保持 pending，之后没有任何入口推进，裁定终止的合同其接单名额不会释放，交互不会由此关闭。修复方案：增加结束回执控制操作，由 `ArbitrationCases` 在事务内核 `delegation_protocol_calls` 无 processing、原应付款经支付中心 `require_contract_payments_in` 的冻结卡口径齐全，再调用 `Admissions.finish_in` 与消息中心的关闭通知；客户端侧的发送时机随共用运行时迁移时核对。需读[仲裁](../委托中心/接口/仲裁.md#裁定执行与容量收尾)与[消息中心](../消息中心/接口.md)的裁定通知一节。

**定向测试：** arbitration_processing、arbitration_review、arbitration_cases、resident_termination
