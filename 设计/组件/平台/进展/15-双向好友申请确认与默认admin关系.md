# 15：双向好友申请确认与默认admin关系

**目标行为：** 已登录用户向指定账号个人助手申请好友，被申请人在平台可信页面同意后双方成为好友；任一方删除即双向解除。普通账号初始仅有官方admin，admin覆盖既有与未来注册账号，已删除关系不被初始化恢复。
**阻塞于：** 无
**状态：** ready（2026-11-13重拟；待先更新规范，尚未实现）
**范围：** 消息中心、身份中心归属接口、web服务用例、网页UI及最小SDK好友操作；[方案](../../../工程/专题/个人助手公开发现与消息转发.md#好友关系与真实确认)。客户端原生提示与打开页面另归客户端25。
**定向测试：** authentication_recovery、account_views、message_boundaries、agent_delivery、user_confirmations、frontend；新增好友状态/确认/初始化/动态权限用例，在实施前登记所属接口页。

- [ ] 实施先更新消息中心、web服务、网页UI、个人助手端及依赖接口/术语/流程并升设计版；平台权威持有账号级好友、申请、修订、初始化和删除事实，客户端缓存不放行
- [ ] 好友list/request/status/remove与平台确认端点形成可复验闭环；目标为稳定账号及其真实助手，不接受正文自报来源、伪造目标或匿名申请
- [ ] 同意建立双向关系；拒绝不建立；相向申请也不自动同意；本人登录并确认原申请，旧页面、重放、跨账号、模型confirmed字段和打开页面不能批准
- [ ] 重复申请复用未决待办，不重复弹窗；已有好友不重复建关系；并发同意/拒绝/删除和丢响应以原状态/操作回执为准，不复活旧关系
- [ ] 注册与admin初始关系由web应用用例可靠协调，既有账号一次性初始化；稳定官方admin绑定不等于任意admin角色，不自加好友；未接入宿主也不丢初始关系
- [ ] 删除admin或普通好友后，重启、登录、升级、初始化恢复和原注册重放均不加回；正常新好友申请必须重新由对方确认
- [ ] 三档权限明确互斥：默认当前好友、指定稳定账号名单、全部已登录用户；全部跳过名单匹配而保留认证/来源，包含未来注册账号；指定空名单无人
- [ ] 好友列表/申请仅本人可查；平台受理与开始许可按当前关系和接口模式复核，指定名单/全部不因删好友被隐式改动；A2C授权不套用本策略
- [ ] 平台确认页沿认证、Origin/CSRF和绑定校验建立唯一批准权威；申请无需通过普通好友消息权限，也不进入模型；离线待办、限流、重复提示和重启恢复有真实状态
