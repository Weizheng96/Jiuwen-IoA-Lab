# 13：个人助手根目录公开与能力发现

**目标行为：** 用户自愿公开一份不超过100字的个人助手能力档案；另一认证账号通过自然语言找人取得真实目标并使用固定转发接口联系。
**阻塞于：** 外组前置，见下文
**状态：** ready（待设计细化与实现，功能未实现）
**范围：** 注册中心、web服务、消息中心、身份中心的归属查询，个人助手端SDK公开与发现操作；[方案](../../../工程/专题/个人助手公开发现与消息转发.md)。
**定向测试：** service_publication、search_availability、category_preview、account_views、agent_delivery、agent_flows；新增个人助手公开/搜索/namespace隔离用例并登记。

## 外组前置

[客户端22](../../客户端/进展/22-固定消息转发与按发送方收信.md)提供可核的固定入口、宿主投递就绪契约与认证发信流程；原生Skill完整引导另归客户端后续票据。

- [ ] 注册中心独占公开档案/修订/操作回执/索引投影；身份只引用现有账号与稳定助手，不另建服务身份
- [ ] 描述非空且最多100个Unicode码点；中英文、标点、内部空白与表情边界前后端一致，超长拒绝且不静默截断
- [ ] 个人助手namespace所有档案位于根目录，无领域分类、分类模型、服务兜底叶类或额外长说明
- [ ] 用户经具体预览与可信确认发布，第一次公开与面向全认证账号的固定转发入口一致受理；缺可靠宿主投递能力拒绝公开
- [ ] 两个namespace查询、目录、缓存、树与索引生命周期隔离；原服务发现和分类结果保持原契约
- [ ] SDK支持无委托任务的找人，根目录检索有正例、近似例及无关负例；允许无结果，记录匹配门槛与实际检索模式
- [ ] 搜索仅返回当前公开档案和允许公开的来源/联系状态；不返回私人接口、白名单、原生会话及配置
- [ ] 公开、在线和投递就绪分别表达；离线状态不冒充即时可达
- [ ] 从认证SDK发布、搜索到选择目标并发送至少一条转发消息形成可复验闭环；服务交易不介入
