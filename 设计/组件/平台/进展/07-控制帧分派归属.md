# 07：控制帧分派移出消息中心

**目标行为：** 消息中心只处理投递、交互与收信接口；参与方控制帧按种类交给所属模块这件事由 web服务 的应用层完成，新增一种控制操作不必修改消息中心。现状：`DeliveryBroker.control` 认识全部控制种类，装配后持有支付中心、委托中心、注册中心的对象以及 web服务 的付款与市场用例引用，`operation` 同样按种类转发；领域模块因此反向调用应用层。

**阻塞于：** 无

**状态：** claimed（plat-2）

**范围：** 消息中心与 web服务。方案：web服务 增加控制分派器，登记“种类到事务外准备、事务内提交、原结果查询”三个函数；消息中心保留租约校验、续租、活动记录与自己的五种操作（message.send、message.ack、request.start、interaction.close、contract.bind 的转交），并把租约校验与续租作为接口提供给分派器。按展开、迁移、收口拆：先加分派器并让新旧并存，再逐种类迁移，最后删除 `control` 中的转发与注入属性。需读[消息中心接口](../消息中心/接口.md#控制操作)与[实现](../消息中心/实现.md)。

**定向测试：** agent_delivery、delegation_admission、delegation_scopes、payment_atomicity、resident_fulfillment、arbitration_cases、core_request_lifecycle

- [ ] 消息中心不再持有其他中心与应用用例的引用
- [ ] 每种控制操作的准备、提交、查询仍在同一事务边界内，代次与撤权竞争的拒绝行为不变
- [ ] 消息中心与 web服务 的接口、依赖、实现页同步
