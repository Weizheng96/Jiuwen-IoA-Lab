# web服务

## 目的与范围

平台的装配与对外网络入口：把五个中心、观测与平台基础装成一个进程，提供跨中心的应用用例，向参与方 SDK 与浏览器开放 HTTP 与 WebSocket，并提供命令行、就绪探针和种子装配。路由只处理认证、参数和响应，不直接组合业务 SQL，不在查询时推进状态；跨中心的一致性由应用用例在同一短事务内协调。合同与签名规则直接复用 A2C，本模块不重新定义。调用方是参与方 SDK、浏览器、部署与运维命令。

|---|---|---|

| 配置 | 监听地址与端口、对外地址、运行模式、种子清单、技能包目录、是否自动注入种子 | [平台配置](../平台基础/接口/平台配置.md)的 runtime 组 |

### 应用用例

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `AccountOperations.register(…)`、`login(…,audience)`、`create_account(…)` | 账号创建或登录与赠币在同一事务提交；按 operationId 幂等 | 返回账号、令牌、到期与实际发放；事件在提交后发布 | 同操作异参数 id_conflict 409；密码已变 401；预算满 429 | auth、account_rewards、authentication_recovery |
| `AccountOperations.bind_identity(registry,owner,body)` | 身份绑定并为个人助手登记付款公钥指纹 | 绑定结果 | 见[身份绑定](../身份中心/接口.md#身份绑定) | account_enrollment |
| `LedgerOperations.adjust(…)`、`transfer(…)` | 管理员调账；用途限 ruling、refund、fee 的普通转账 | 新余量 | 余量不足或用途不符 CARD_INVALID | wallet、admin_api |
| `DiscoveryOperations.search(query,top_k,*,by)` | 搜索并附公开可用性快照，记审计事件 | 候选列表与 availability | 不改索引与接单 | search_availability |
| `PaymentOperations.prepare(…)`、`apply_in(conn,…)`、`project(…)`、`operation(…)` | `ap2.pay`：事务外准备 AP2，事务内依次过裁定守卫、关联接单、过账、记入范围预算，原回执经支付中心 `record_operation_in` 同事务保存 | 原 AP2 响应与是否新过账 | 容量与过账事实不一致 unknown_result 409；明确拒绝 payment_rejected 403 | payment_atomicity、payment_rejection、delegation_admission |
| `MarketOperations.prepare(…)`、`apply_in(conn,…)`、`prepare_contract(…)`、`apply_contract_in(conn,…)`、`operation(…)` | `a2c.market`：市场签 3、存证与结清；结清同事务核应付款、释放接单并关闭交互；原回执经委托中心 `MarketService.record_operation_in` 同事务保存 | 原市场结果与是否本次新提交 | 原市场拒绝 invalid_input；准备结果丢失 unknown_result 409 | resident_delegation、resident_fulfillment、provider_market_rejection |
| `ServiceOperations.publish(owner,actor,body)`、`reindex(actor)` | 服务发布：恢复原操作或准备、签认模板、事务内保存原件，再重建索引 | 原发布回执 | 索引失败只记原因，不撤销已发布原件 | service_publication、publication_authorizations |
| `ControlOperations.control(owner,connection,generations,frame)` | 参与方控制帧分派：消息中心核帧与代次；有准备步骤的种类先在锁内核租约再于事务外准备；同一短事务内复核租约、交所属模块提交、记受理活动并续租；提交后唤醒、执行所属模块的提交后动作、广播活动 | `/ws/agents` 的 `operation.result`；种类与所属模块见[控制分派](#控制分派) | 帧或代次不符 stale_generation 409，准备前即拒绝；未登记种类 protocol_error；所属模块的拒绝原样返回 | agent_delivery、delegation_admission、arbitration_cases、resident_delegation、provider_admission |
| `ControlOperations.operation(owner,actor,kind,operationId)` | 按种类转所属模块查询原控制操作结果，其余交消息中心 | `GET /api/v1/operations/{operationId}` 与 `operation.get` | 见所属模块 | agent_delivery、payment_transport_recovery |
| `ControlOperations.register(kind,Control(apply_in,prepare,operation))`、`register_platform(…)` | 登记一种控制操作的事务外准备、事务内提交与原结果查询；kind 为精确种类或以 `.` 结尾的族前缀；新增种类不改消息中心 | 装配时调用 | 与消息中心种类、`operation.get` 或已登记种类重复 ValueError | agent_delivery |

### 进程与命令

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `ioalab check-config`、`init`、`serve`、`reset`、`backup`（`cli.main`） | 校验配置、初始化与注入种子、单进程单 worker 运行、停服后清空或备份数据 | `--config` 或 `IOALAB_CONFIG` 指定私有配置 | 配置有问题退出码 2；数据目录被占用拒绝 | core_ownership、platform_configuration、seed、seed_manifest |
| `Platform(settings,*,configuration)`、`startup()`、`shutdown()`、`close()` | 取得数据目录所有权、迁移、装配、恢复仲裁案件、启动维护循环；关闭时先等实际工作结束再释放 | `configuration` 为命令行载入的配置权威，供管理员配置路由与修订审计；测试可不传 | 关闭中的新请求 closed 503，recovery=retry_original | core_ownership、core_request_lifecycle、admin_websocket_shutdown、arbitration_processing |
| `create_app(platform)` | 路由、统一错误映射、跨站 Origin 检查、原协议入口挂载 | 错误一律为 `{error:{code,message,recovery}}` | 跨站写请求 403 | boundary、frontend、configuration_web、trial_admission、observation_views、workbench_network |
| `/a2a/market`、`/a2a/pay`、`/a2a/agents/{agentId}/…` | A2C 市场、AP2 支付方与公开身份的原协议入口 | 保留原请求、签名与响应 | 已登记服务须经 IoA 执行连接 | boundary、payment_rules、account_enrollment |
| `python -m ioalab.readiness`（`check_ready`、`wait_ready`） | 只读就绪探针：核对响应核心的对外地址 | 不登录、不跟随重定向 | 地址不符或超时即未就绪 | core_readiness |
| `seed_all(platform)`、`load_domains(path)` | 按显式清单幂等建立内部账号与分类树 | 清单最多 64 个领域、2 MiB | 清单无效 ValueError | seed、seed_manifest |
| `source.client_ip(request,settings)` | 来源解析：只信 socket peer，受信代理才读单值来源头 | — | 代理缺少或非法来源 403 | configuration_web、auth_failures |
| `GET /downloads/{bundle}` | 下载产品技能包 `ioalab-assistant-skill.zip`、`ioalab-provider-skill.zip` | — | 未知名称 404；未构建 503 | frontend |

## 不变量

| 规则 | 说明 |
|---|---|
| 依赖方向 | 路由到应用用例与各模块入口，再到模块内部规则与存储；各模块独占所属数据写入，跨中心协调集中在应用用例，模块不反向依赖协调入口 |
| 短事务协调 | 接单预留、范围预算与过账，市场签认与台账，结清、释放与关闭，分别在同一短事务提交；网络、签名与模型等待都在事务外。取舍见[跨模块决策](../../../决策/0001-应用短事务协调接单与付款.md) |
| 单进程 | 核心单进程单 worker，先取得数据目录的操作系统锁再改任何文件或数据库；同目录第二个核心拒绝启动 |
| 关闭 | 先取消维护循环，等实际请求与线程工作结束，再关资源与释放所有权；调用方取消不能丢下正在进行的写入 |
| 公共地址 | 对外地址内嵌于参与方标识、模板与索引，首次初始化后锁定；改址是显式迁移 |
| 事件 | 已受理操作与事件先持久再广播；广播或导出失败不撤销受理，也不让调用方重做业务 |
| 不运行参与方 | 核心不运行个人助手或服务生产，不保存参与方私钥，不替用户签字验收 |
| 种子 | 分类与内部账号只从显式清单读取，平台不按源码路径读取官方目录 |

### 验收条件

单模块的可验证条件；跨模块条件在流程页的“端到端验收”节。

| 场景 | 必须满足 | 测试 |
|---|---|---|
| 数据与跨中心用例 | 每类状态有唯一写入方；模块不直接修改其他模块的表；接单与拟卡费由明确应用入口在同一短事务协调，观察投影不能推进业务 | delegation_admission、observation_transactions |
| 预留到期、付款竞争及进程中断 | 原子协调名额、支付操作和账本，不能出现已释放名额却仍收取本次拟卡费，或付款记录与实际记账分裂 | delegation_admission、payment_atomicity、proposal_expiry |
