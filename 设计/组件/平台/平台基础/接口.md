# 平台基础

## 目的与范围

平台各模块共用的基础设施：数据目录所有权与短事务、数据库迁移的统一入口、公共错误对象、私有文件、机构密钥、事件总线和配置权威。不承载合同、收信或支付等业务规则，不保存业务表结构。调用方是平台内的全部模块。

## 独占数据与配置

| 数据或配置 | 说明 | 存储 |
|---|---|---|
| 数据目录所有权 | 核心对整个数据目录的操作系统锁 | `data/.core.lock` |
| 数据库与键值适配 | 单个 SQLite 文件；A2C 原 Store 接口的键值表，按一方一个前缀隔离 | `data/ioalab.sqlite`、`kv` |
| 私有文件 | 文件引用、上传操作、读取授权；字节按摘要命名保存 | `private_files`、`private_file_operations`、`private_file_readers` 与装配传入的私有目录 |
| 机构密钥 | 市场与支付方的 Ed25519 签名密钥、AP2 的 P-256 密钥；首次生成，文件权限 0600 | `data/keys/<名称>.json` |
| 会话密钥 | 配置给出或首次生成后保留 | `data/secret` |
| 事件历史 | 每条协议报文与平台事件一行；表定义、写入与动作标签同属事件总线，观测只读 | `events` |
| 事件导出 | 每次运行的事件 JSONL | `data/runs/<运行>/events.jsonl` |
| 配置 | 唯一私有 JSON 文件及其修订 | 见[平台配置](接口/平台配置.md) |

### 私有文件

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `PrivateFiles.put(owner,actor,operation,name,expected,data)` | 上传协议文件 | 单文件最多 16 MiB，每账号 512 MiB；先占配额再写盘；同操作恢复原引用；返回 fileId、name、digest、size | 字节与声明摘要不符 invalid_input；同操作异内容 id_conflict 409；超配额 quota_exceeded 429；写盘中断 not_ready 503，recovery=resume_original | private_files |

## 不变量

| 规则 | 说明 |
|---|---|
| 先取所有权 | 任何核心私有文件或数据库修改之前先取得数据目录的操作系统锁；备份与清空同样先取锁 |
| 短事务 | 事务只包写入；`*_in(conn, …)` 形式的接口断言传入的是所属连接且已在事务中；网络、模型与用户等待不持事务 |
| 迁移归属 | 领域表与升级只由所属模块维护，本模块只提供统一顺序调用入口；基础存储不保存业务表结构；已有数据库沿原表升级，不建旧链回退 |
| 私有文件 | 文件引用不等于公开下载地址；读取权只在通过业务校验的投递事务内授予；合同材料与交付证据按业务保留，不按普通消息 TTL 删除 |
| 事件 | 事件不改变协议状态；随原事务记录的事件在提交后发布，发布失败不丢已受理历史 |
| 配置 | 一个私有文件是唯一权威，不以逐字段环境变量、网页数据库或第二个文件覆盖；敏感值不进日志、接口错误或 Git；详细规则见[平台配置](接口/平台配置.md) |

### 验收条件

单模块的可验证条件；跨模块条件在流程页的“端到端验收”节。

| 场景 | 必须满足 | 测试 |
|---|---|---|
| Core 数据所有权 | 同进程/跨进程第二实例在私有文件和 DB 修改前拒绝；正常退出、强制终止、构造/启动失败及 lifespan 异常可安全恢复；实际 writer 退出前锁仍占用，不把端口或 PID 当证明 | core_ownership |
