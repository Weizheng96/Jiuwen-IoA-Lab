# 委托中心

## 目的与范围

提供 A2C 模板签认、合同认证、公共存证、信誉与仲裁，并维护 IoA 接单容量台账。合同字段、签名链、成约方式、期限与验收器直接遵守上游 A2C SDK，本模块不复制合同状态机；admission、交互 UUID、连接与会话信息都不增加 A2C 合同字段。不做服务发现（注册中心），不过账（支付中心），不代参与方签字、验收或执行生产。调用方是消息中心（控制帧与协议消息的事务内校验）、web服务 的应用用例（付款、市场签认、服务发布）与路由（仲裁、验收器包、信誉）以及观测（只读）；参与方经 WS 控制帧与 HTTP 入口到达。

## 独占数据与配置

| 数据或配置 | 说明 | 存储 |
|---|---|---|
| 接单策略 | 每服务的修订、容量上限、接单开关 | `admission_policies` |
| 委托意向与交互关联 | 原未签请求或卡、模板、范围与绑定摘要、到期、开始许可、关闭；意向到交互 UUID 的唯一映射 | `delegation_intents`、`delegation_links` |
| 接单台账 admission | 预留 ID、交互、服务与发起身份、范围与绑定摘要、状态、截止；控制操作幂等记录；付款关联 | `delegation_admissions`、`admission_operations`、`admission_payments` |
| 提案原件 | 实际开始的签名请求、首次签认的提案卡 | `delegation_signed_requests`、`delegation_offers` |
| 成约事实 | 冻结成约卡与摘要、原交付任务、开工消息与许可、接收回执、当前环节请求、已核进展；环节答复；解除报价 | `delegation_contracts`、`delegation_step_answers`、`delegation_termination_quotes` |
| 原协议调用 | 每条 A2C 请求的交互、admission、方法、状态、最后结果与任务 | `delegation_protocol_calls` |
| 市场存储 | 模板与卡快照、存证卡、结清日志、裁定，经平台基础的 A2C Store 适配保存；市场操作幂等记录的写入者见[票据](../进展/01-付款操作记录归属.md) | `SqliteStore("market")`、`rulings`、`delegation_market_operations` |
| 验收器包 | 按摘要寻址的 WASM 验收器包，单包不超过 256 KB | `data/packages/<digest>.zip` |
| 仲裁 | 案件、冻结申请与依据、材料、模型映射、评估尝试、裁定与决定依据、执行状态；申请与管理员操作幂等记录；审计 | `arbitration_cases`、`arbitration_operations`、`arbitration_attempts`、`arbitration_admin_operations`、`arbitration_audit` |
| 配置 | 仲裁观察模型登记 `arbitration_models`、模型入口；机构签名密钥由平台基础提供 | [平台配置](../平台基础/接口/平台配置.md) |

## 接口

| 分组 | 内容 | 子页 |
|---|---|---|
| 接单与容量 | 委托意向、交互关联、接单策略、预留与提交、拟卡费关联、提案签认资格、到期与释放 | [接单与容量](接口/接单与容量.md) |
| 合同与协议 | 成约登记、原协议请求与结果校验、存证与结清、解除、公共市场服务、验收器包、信誉 | [合同与协议](接口/合同与协议.md) |
| 仲裁 | 取证预览、案件受理与查询、评估、人工复核、裁定与执行收尾 | [仲裁](接口/仲裁.md) |

事务内接口以 `_in(conn, …)` 命名并要求所属平台事务；签名、取钥、市场校验与模型观察在事务外的准备阶段完成。字段与报文格式只在[web服务](../web服务/接口.md)定义。

## 不变量

| 规则 | 说明 |
|---|---|
| A2C 原义 | 卡载金额、亲签条款、验收与支付依据按 A2C 原义处理；摘要使用 A2C 原语；协议期限用签名原件判断，投递、上传或存储转发不能刷新时效 |
| 不代行 | 平台不代参与方签字、验收或执行服务生产；不替用户签 7；裁定不直接触发付款 |
| 容量权威 | 平台策略是接单开关与容量的唯一权威，服务方本地只保存镜像；容量单位是尚可能独立成约的承诺或未结束合同加有效短期预留，不是模型线程数 |
| 新候选与既有合同分开 | 新候选资格（当前公示、意向期限、范围尚未选择）与既有合同权限分别核验；旧模板退出公示或授权到期不阻断已有合同的证据与必要控制 |
| 事务边界 | 预留、范围预算与 AP2 过账，市场签认与台账，结清、释放与关闭通知，裁定、市场结局与通知，分别在同一短事务提交；取舍见[跨模块决策](../../../决策/0001-应用短事务协调接单与付款.md) |
| 未知保留 | 付款、签署、开工或生产结果未知时保留 committed 与原检查点，查询原操作，不另签承诺、不按期限自动释放、不清库或手改计数 |
| 原操作恢复 | 相同操作同内容返回原结果且不重新检查已完成动作的当前许可；同键异内容冲突；原件不被替换 |
