# 委托中心 · 实现

| 项 | 值 |
|---|---|
| 代码目录 | `src/platform/ioalab/delegation/` |
| 产物 | `src/platform/VERSION`（`ioalab` 发行包） |

## 入口

| 入口文件 | 公开名 | 说明 |
|---|---|---|
| `__init__.py` | `Admissions` | 接单台账，实现在 `admission.py` |
| `contracts.py` | `ContractAuthority`、`evidence_extends`、`current_card` | 成约事实与合同侧校验 |
| `relay.py` | `ProtocolRelay` | 原协议请求与结果校验 |
| `service.py` | `MarketService` | 公共市场服务、信誉与裁定文书 |
| `packages.py` | `PackageStore` | 验收器包 |
| `models.py` | `ArbitrationModels` | 仲裁观察模型端口 |
| `arbitration_evidence.py` | `ArbitrationEvidence` | 仲裁取证 |
| `arbitration_cases.py` | `ArbitrationCases` | 案件、评估与复核 |
| `migrations.py` | `migrate` | 表定义与升级，由平台基础统一迁移入口调用 |

## 内部分区

| 分区 | 文件 | 职责 |
|---|---|---|
| 接单 | `admission.py` | 意向、关联、策略、预留与提交、拟卡费关联、提案签认资格、到期与释放 |
| 合同 | `contracts.py`、`relay.py` | 冻结成约卡、逐方法校验、进展单调推进、解除与报价；协议封套、文件授权与结果登记 |
| 市场 | `service.py`、`market.py` | 原 Market 的隔离准备与事务内提交、模板签认、信誉、裁定；`AdmissionMarket` 给公网原入口加已登记服务门禁 |
| 仲裁 | `arbitration_evidence.py`、`arbitration_cases.py`、`arbitration_review.py` | 取证与理由成立判断；案件受理、唯一工作者评估、管理员复核与重评；复核结论边界的纯规则。管理员入口在 web服务 `web/arbitrations.py`，SDK 共用历史核验在共用运行时 `adapters/arbitration.py` |
| 资源 | `packages.py`、`models.py` | 验收器包存取；观察模型端口 |
| 存储定义 | `migrations.py` | 本模块全部表；原协议调用表去除旧唯一索引的保数据升级 |

## 存储与迁移

表见[接口](接口.md#独占数据与配置)。迁移由平台基础统一入口持锁后事务内调用。`delegation_protocol_calls` 早期按交互与方法唯一，升级时整表复制并核行数后替换，未知列结构则拒绝启动。`needs` 与 `confirmations` 是托管执行时期的遗留表，当前无写入者，见[已知偏离](#已知偏离)。

## 内部接缝

| 接缝 | 用途 |
|---|---|
| `Admissions(clock=…)`、`ArbitrationEvidence(clock=…)`、`ArbitrationCases(clock=…)` | 固定时间核预留截止、承诺窗口、期限理由 |
| `Admissions.active` | 替换服务执行连接在线判定 |
| `MarketService(models=…, fetch=…, store=…)` | 替换观察模型端口、验收器包来源与 Store |
| `prepare_*` 与 `*_in` 的分界 | 在市场准备后、提交前注入故障，断言快照、台账与通知整体提交或回滚 |
| `ArbitrationCases.process_one` 的评估与终局分两次提交 | 在已保存结果、未提交终局处中断，断言不重调模型 |
