# 委托中心 · 合同与协议

本页是[委托中心](../接口.md#接口)的子页。跨端调用顺序与 SDK 侧契约见[A2C适配](../../../客户端/共用运行时/接口/A2C适配.md)。

## 成约登记与合同权威

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `ContractAuthority.bind_in(conn,owner,actor,payload)` | 个人助手以 `contract.bind` 登记原有效成约卡 | admissionId 与完整原卡；不以定金或开工为前提，不发起生产；返回 admissionId、cardDigest、card | 非原委托方 403；卡带履约进展或签 4—7 被拒 403；admission 非 committed closed 409；与原承诺、已选价款或签名不符 403 | contract_binding |
| `ContractAuthority.card_in(conn,row,card)`、`facts(conn,admission)` | 首次观察时冻结成约卡，之后固定摘要与签 1、2、3 | 核服务方身份、支付方、范围已选合同与卡载用户、提案须等于首次签认卡、签名链生效且不晚于模板有效期 | 未登记 not_ready 409；不符 403 | contract_binding、resident_contracts |
| `ContractAuthority.check_in(conn,value)` | 校验成约后的每条 A2C 请求 | 核原双方与方向、交互、admission 为 committed、原交付任务；按方法核开工窗口、付款用途与方向、解除报价与通知、环节答复、取件期次、验收存证前缀、付款通知的实际凭证 | 方向或参与方变化 403；已解除后的新履约 closed 409；开工窗口已过 expired 409；方法未启用 not_ready 409 | resident_fulfillment、protocol_operations |
| `ContractAuthority.accepted_in(conn,value)`、`started_in(conn,value)`、`result_in(conn,row,reply)`、`answer_in(…)` | 保存开工消息、开始许可、原任务与环节请求、接收回执、环节答复 | 环节答复绑定冻结卡载用户、原请求摘要与 authorizeWithin；任务不得属于另一合同 | 换消息重开工或重答 id_conflict 409；任务或请求不符 403 | resident_fulfillment、resident_multiperiod |
| `ContractAuthority.advance_in(conn,row,card)`、`evidence_extends(previous,current)`、`current_card(facts)` | 已核进展只增不退 | 合法旧前缀只记历史不回退；裁定后只接受不超出冻结卡的证据 | 分叉或替换 403 | resident_fulfillment、observation_views |
| `ContractAuthority.payment_in(conn,owner,actor,admissionId,payment,*,original)` | 合同用途付款与台账的关联 | 核付款双方与方向（退款由原服务方付）、卡摘要、范围、币种；定金核开工窗口，分期核存证前缀，解除款核原解除通知 | 不符 403；解除后新定金 closed 409；同付款异内容 id_conflict 409 | payment_atomicity、resident_payment_recovery |
| `ContractAuthority.termination_card(conn,row,body)`、`quote_result_in(conn,row,reply)` | 解除通知与原解除报价 | 报价按摘要保留；通知须为原委托方对当前期次的签名，协商解除须引用本服务收到的原报价 | 替换原通知或报价来源不符 403 | resident_termination、termination_control |
| `ContractAuthority.market_in(conn,owner,actor,payload)` | 存证与结清前的合同侧校验 | 存证须已获开工许可且未解除，本期签 4 仅比已存证多一期；结清不得省略或替换原解除，未开工须先合法解除 | 非原服务 403；替换已存证期次 id_conflict 409；未开工未解除 not_ready 409 | resident_fulfillment、resident_termination |
| `ContractAuthority.evidence_in(conn,admission)`、`keys(row)`、`original(conn,row)`、`work_window(…)`、`unselected_offer_in(…)`、`anchored_prefix(…)` | 取证用当前原件、验签钥目录、原意向、开工窗口、未中选判定、存证前缀比对 | 只读 | — | arbitration_evidence、proposal_expiry |

## 原协议请求与结果

消息中心在受理 `a2c.request`、`a2c.result`、`request.start` 与 `contract.bind` 时调用协议中继；中继只校验封套与原件，原 A2C 执行留在参与方本地。

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `ProtocolRelay.check_request_in(conn,value)`、`request_in(conn,value)` | 校验并登记一条原协议请求 | body 为 op、body、files、admissionId 与可选 taskId；初始方法走接单台账，其余走合同权威；核接收方与交互；材料文件须为本阶段模板声明的输入、摘要等于签名对象并带用户的信息授权；通过后授予对端文件读取权 | 字段越界 invalid_input；接收方或交互变化 403；未授权材料 403；`request.submit`、`card.countersign` 重复 id_conflict 409；裁定后新履约 closed 409 | protocol_relay、private_files |
| `ProtocolRelay.start_in(conn,value)`、`context_in(conn,value)` | 开始许可与随许可返回的权威上下文 | 成约后的请求随许可携带 contractCard 与实际定金凭证 | 未登记成约 not_ready 409 | protocol_relay、resident_fulfillment |
| `ProtocolRelay.result_in(conn,value,original)` | 校验并登记原协议结果 | reply 保留原方法、原任务 ID 与状态（working、auth-required、completed、failed、rejected、canceled）；未知执行只能配非终态并带 unknown_result；终态同内容重传返回原结果 | 非原请求方或交互 403；无开始许可 403；任务 ID 变化或终态被替换 id_conflict 409 | protocol_relay、protocol_operations、resident_fulfillment |
| `ProtocolRelay.bind_in(conn,owner,actor,payload)` | `contract.bind` 入口，先过裁定守卫再登记并写展示副本 | 同 `ContractAuthority.bind_in` | 同上 | contract_binding |
| `ProtocolRelay.evidence_in(conn,admission,read_messages)`、`proposal_finished_in(…)` | 完整原调用历史供取证；提案是否已完整答复且无后续协议工作 | 核调用绑定与留存消息一致 | 历史已离开保留期 history_gap 409，recovery=restore_state | arbitration_evidence、proposal_expiry |

## 不变量

| 规则 | 说明 |
|---|---|
| 审查先于提交 | 待批准的签 1 卡可在 held 仍有效时投递并取得审查开始许可，该许可只允许审查；SDK 在原 Provider 审查通过后提交 admission，成功才签 2；不能要求提交后才投递签 1 造成相互等待 |
| 签 3 门禁 | 正式提案的市场签 3 须核已提交 admission 与原 requestDigest；市场快照与原签 3 回执一起提交，失败不留下可用的另一份承诺；已成功签认恢复不重签，也不因后续撤权改写 |
| 成约登记 | 首次取得有效合同卡后固定 cardDigest；登记不依赖定金或开工；第一次合法合同 checkout 与 work.start 须核同一登记；冻结原件与原任务是权限依据，不是另一套履约状态机 |
| 开工 | 首次 work.start 核原开工窗口；开始许可或真实回执一经保存，未知结果按可能已开始处理，直到真实结清或合法终态，不按模型“完成”释放 |
| 环节 | 环节请求与答复绑定原卡、原交付任务与卡载用户密钥，不接受任意自签 jwk；上期同意不能授权下期 |
| 存证 | 按合同与期次保存不可替换的原清单、签 4 与签 5；同一原操作恢复原签 5，不能签出同一期另一份清单；已有交付须逐项匹配市场实际存证前缀 |
| 结清与信誉 | 结清复用原 Market 校验并核定金、分期、解除的实际过账凭证；原结清日志、接单释放与关闭通知同一事务提交；信誉只引用该日志，接口不接受自报次数 |
| 解除 | 依据是不可变原成约卡、单调推进的已核签名链、按摘要保留的原报价与通知；只接受已绑定双方在同一交互提交的原件；解除后拒绝新履约开始与追加证据；未开工合同不要求伪造开始许可，没有交付时不要求空存证 |
| 解除结算 | 解除款按实际已付定金确定方向，负余额缺退款不得结清；单方解除不按裁定自动过账；未知开工、生产或工具效果继续占用，待原执行者核实后收尾 |
| 验收 | 验收器包只在 A2C WASM 沙箱执行；正常验收由委托方用自己的模型做 L2 观察、验收器程序判定；仲裁模型只用于复算且须来自部署登记集合 |
| 并行与隔离 | 服务端每个交互单独保存协议 Store、任务与宿主会话；同一服务多交互可并行，本单控制消息不因其他委托等待模型而阻塞 |
| 正式请求过期 | 返回协议错误；发送端先核未知效果与授权，再准备新的合法请求，不改旧签名时间；延迟读取的结果按原协议核验，不一概要求重签 |

### 验收条件

单模块的可验证条件；跨模块条件在流程页的“端到端验收”节。

| 场景 | 必须满足 | 测试 |
|---|---|---|
| 既有合同与窗口 | 原模板退出公示、意向或新委托许可到期后仍可接收合法原合同证据；新的付款另核许可，开工和履约仍遵守原 A2C 窗口 | contract_binding、template_renewal |
| 结清与释放 | 缺实际付款、未知开工/签署不得释放；真实结清、容量与通知原子提交；重复结清不新增信誉次数 | resident_termination、payment_atomicity |
| 首次履约与任务归属 | 定金 checkout 可先于开工登记有效成约；篡改原承诺、其他卡/用户/Task 均拒绝；Task.op 保留创建方法，环节答复须绑定真实用户与原请求 | contract_binding、fulfillment_status |
