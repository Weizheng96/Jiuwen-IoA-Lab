# 观测

## 目的与范围

把各中心的事实汇成按权限裁剪的只读视图：账号、工作台、管理员总览、合同与意向、助手消息、公开服务目录和事件。自己只保存两类数据：随原业务事务写入的已验签合同展示副本，以及事件历史。不执行、不签署、不付款、不调用模型；视图不是任何模块的权限依据。调用方是 web服务 的路由与装配；消息中心经注入取得受理活动的元数据，web服务 的应用用例与委托中心的协议中继经注入保存展示副本。

## 独占数据与配置

| 数据或配置 | 说明 | 存储 |
|---|---|---|
| 合同展示副本 | 每个接单关系一份已核验的原 A2C 卡、摘要、内容校验和、是否已成约、时间 | `observation_contracts` |
| 事件历史 | 每条协议报文与平台事件一行；表在本模块定义，写入者是平台基础的事件总线，见[票据](../进展/10-事件表定义与写入者.md) | `events` |

本模块没有自己的配置项；读取各中心表的取舍见[决策](../决策/0002-观测只读直查各中心表.md)。

## 不变量

| 规则 | 说明 |
|---|---|
| 只读 | 查询不写业务表、不领取消息、不推进游标、不调用模型；观察断开只表示状态未知，不推断合同失败 |
| 两类自有写入 | 展示副本只在原业务事务内保存已核验原件；事件随原事务记录、提交后广播 |
| 不作权限依据 | 视图结果不得回写为任何模块的判断依据；所属鉴权在服务端先于展示 |
| 管理事件裁剪 | 只输出允许的标识、参与方、时间、动作、结果、期次、金额与核验标记；不传递任意 detail 字段、正文、完整合同、业务材料或凭据。管理员概览、实时 WS、历史与回放用同一裁剪规则 |

### 事件与证据

| 来源 | 展示依据 |
|---|---|
| 平台公共服务 | 核验后的签认、存证、过账、结清与裁定事实 |
| 所属参与方合同副本 | 验签后标 verified；旧副本不得覆盖更完整签名链 |
| SDK 过程上报 | 检索、比较、生产、等待确认等标 reported，不能充当付款或裁定依据 |
| 连接与投递记录 | 使用实际连接、入队和送达回执；业务结果另行表达 |

实时协议事件在原事务内固定本次已接受事实，提交成功后发布；不得事后读取更新卡并附到更早的请求事件。入队只表示待投递，不能推断复签、开工或交付完成。事件按稳定 ID 去重，合同摘要与交互 ID 分别关联其业务。重传和历史恢复只补状态，不制造新活动；乱序不能使已结束合同重新开工。

参与方上报的原事件与当前合同投影分别处理：已验签但签名链较旧的快照，不覆盖当前投影；已有开工收据也不得被缺失或不同收据覆盖，不可比较的异链不能替换原件；其首次上报仍按原事件 ID 保留历史，并标记 `stale=true`。该标记只描述上报快照较旧，不宣称发生了新的协议动作。

上报去重记录、获准的投影更新与事件行在同一短事务提交；提交失败全部回滚。提交后才向观察者广播及写 JSONL 导出。广播或导出失败不能丢失已接受历史；同 ID 恢复只确认原件，不再次播放活动。管理员历史与回放统一读取数据库中获准的原事件，JSONL 仅作附加导出。

完整协议报文可按权限展开；内部模型仅展示获准输入与输出，不上传密钥、凭据或隐藏推理。金额区分合同价、已付款及服务收入，币种明确标为虚拟币。

### 授权观察视图

| 展示对象 | 唯一依据与边界 |
|---|---|
| 委托意向 | 原意向消息及接单记录；离线暂存、预留、拟约及未知结果分别显示。尚无卡时不填合同摘要或零报价，已付拟卡费仍按真实凭证显示；已有卡后不重复列作未成约意向 |
| 合同快照 | 本次委托接单关系内已接受的原 A2C 卡，核模板、双方身份、原请求及签名；仅保存原件，不由模型文字或事件标签拼卡。更新必须扩展原签名链，旧副本不能回退、等长异链不能覆盖 |
| 快照写入 | 原协议请求与结果、市场签认、存证、结清及实际付款提交时保存已核验副本。重复原件不产生第二次活动；展示失败不构造新的协议动作 |
| 形成与结束 | 成约以原 A2C 验证结果为准，不把仅签 1 或预留容量当成成约；结清与裁定读取真实市场记录，不能以消息送达、全部已签或金额相等推断整单结束 |
| 未成约记录 | 意向与候选合同独立保留，包括已经结束的记录；不计入已签合同、履约队列或合同完成数。未成约卡的接单已由权威流程释放且没有未知执行结果时，显示“未成约 · 已结束”（`unformed-closed`）；仅时钟过期、断线或缺失副本不能推断已结束。该状态不代表合同结清，不生成付款或信誉 |
| 阶段与金额 | 签名、开工回执、环节请求、协议未知及付款分别显示；拟卡费、委托价款及实际已付分开。收入只计绑定本次接单及正确付款方与收款方的真实 AP2 凭证，不计同摘要的手工转账；累计金额和完成数独立于列表分页及展示副本计算 |
| 助手消息 | 从统一可靠投递记录读取本账号参与的请求及原结果；保留 messageId、interactionId、接口修订、投递和处理状态。送达、处理完成和用户已读分开，后者没有凭据时保持未知 |
| 公开服务 | 使用当前已公示的真实名称、分类和有效模板；登记、公示、索引、连接与接单状态分别展示，不把历史 online 标记当作当前执行租约 |
| 记录保留 | 合同展示副本独立于短期投递正文保存，含原签名及来源关联；启动可从仍保存的原协议事实重建。历史证据缺失明确标明，不按最终状态反推缺失签名；消息正文按原 TTL 及保留规则失效，不从本地参与方文件补读 |

### 验收条件

单模块的可验证条件；跨模块条件在流程页的“端到端验收”节。

| 场景 | 必须满足 | 测试 |
|---|---|---|
| 隔离与只读 | 非参与账号不能看到合同或正文；管理概览/WS/历史不含正文或任意 detail；反复刷新不改变消息/交互/业务记录和收件游标；平台网页不读取本地收信处理正文，配置详情通过九问本地入口查看 | observation_views、workbench_network |
| 原件与恢复 | 重传及旧快照不倒退、不制造新活动；等长异链不能替换原件；重启重建与正文清理后保留的合同副本仍准确，证据缺失不补造签名 | observation_views |
| 付款与收入 | 拟卡费、价款和收入分别来自本次接单实际 AP2 凭证；同摘要手工过账、错误收款方及未支付声明不计入；分期不重复计数 | workbench_network |
| 真实证据与全景 | 阶段、收入与消息状态以真实证据核对，普通账号只获得获准数据；管理员全景同时出现多发起方委托和助手通信，匿名示意不计真实事件 | observation_views |
