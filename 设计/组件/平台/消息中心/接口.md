# 消息中心

## 目的与范围

为个人助手和服务方提供身份绑定的长连接投递、离线暂存和状态查询；为助手通信管理收信接口、格式与发信权限；为 web服务 的控制分派器提供帧与代次校验、租约复核与续租、受理活动记录，并在其事务内提交本模块的五种控制操作。本模块执行确定性校验，不理解业务意图、不调用参与方模型，不决定验收或付款。消息封套、控制操作与错误的线上格式只在 web服务 的[WebSocket与消息封套](../web服务/接口/WebSocket与消息封套.md)定义；委托正文由委托中心的[协议中继](../委托中心/接口/合同与协议.md#原协议请求与结果)校验，不套用助手通信接口的 Schema。调用方是 web服务 的 WS 与 HTTP 路由、控制分派器与结清用例，以及委托中心（裁定通知、在线判定、原消息历史）。

## 独占数据与配置

| 数据或配置 | 说明 | 存储 |
|---|---|---|
| 执行租约 | 每智能体的运行实例、当前连接、代次与到期；连接位置不改变 `agentId` | `delivery_leases` |
| 收件游标 | 每收件身份的最后序号与连续确认序号 | `delivery_mailboxes` |
| 投递记录 | 原封套与指纹、认证双方、接收序列、TTL 与保留期、投递与请求状态、交互与关联、开始许可与代次、结果；已用消息 ID 的摘要 | `delivery_messages`、`delivery_ids` |
| 交互关系 | 起始消息到交互 UUID 的唯一映射、不可变双方、类型、接口与修订、截止、请求上限与计数、状态；建立前关闭事实 | `delivery_interactions`、`delivery_closed_origins` |
| 控制操作记录 | 本模块处理的控制操作的指纹与原结果；清理后保留不可逆键摘要 | `delivery_operations`、`delivery_operation_ids` |
| 收信接口 | 所属账号、当前修订与启停、各不可变修订的公开声明与发信账号 ID；不保存本地处理正文 | `message_interfaces`、`message_versions` |
| 配置 | 心跳 15 秒、执行租约 45 秒、消息 TTL 7 天、正文保留 30 天、元数据保留 90 天、每账号未完成 1000 条、每账号每分钟 60 条 | [平台配置](../平台基础/接口/平台配置.md)的 runtime 组 |

使用平台现有持久数据库与明确的业务校验模块，不增加独立消息中间件或通用工作流引擎。平台不保存双方九问 Session。

### 控制操作

参与方控制帧由 web服务 的[控制分派](../web服务/接口.md#控制分派)按种类交所属模块；本模块只提交下列五种，并向分派器提供帧、租约与活动接口。新增其他控制种类不改本模块。

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `DeliveryBroker.control_frame(generations,frame)` | 核帧内智能体属于本连接且代次为当前代次 | 返回 actor、kind、payload | type 非字符串或 payload 非对象 invalid_input；智能体或代次不符 stale_generation 409，recovery=stop_executor | agent_delivery |
| `DeliveryBroker.renew_in(conn,actor)` | 已受理控制操作在其事务内续租 | — | — | agent_delivery |
| `DeliveryBroker.CONTROLS`、`control_in(conn,actor,kind,operationId,payload,generation)` | 分派器复核租约后在同一事务提交本模块种类，按 actor、种类与 operationId 幂等 | 原结果与活动事实（无活动为 None） | 同操作异参数 id_conflict 409；回执已离开保留期 history_gap 409 | agent_delivery、runtime_delivery |
| `DeliveryBroker.activity_in(conn,frame,result,**facts)`、`publish_activity(recorded)` | 在操作事务内记录受理活动，提交后广播 | 已记录事件 | 广播失败只记日志，不撤销受理 | agent_delivery、observation_transactions |

| 控制种类 | 处理 | 结果 | 测试 |
|---|---|---|---|
| `message.send` | 按下节消息种类校验 | 受理回执 messageId、recipientSeq、acceptedAt | agent_delivery、message_boundaries |
| `message.ack` | 连续确认 | 确认游标 through | agent_delivery、runtime_delivery |
| `request.start` | 助手请求核当前接口权限，委托意向交委托中心，原协议请求交协议中继 | startedAt、resumed、requestState 与协议权威上下文 | agent_delivery、protocol_relay |
| `interaction.close` | 委托类先由委托中心核无已提交义务 | 关闭状态 | agent_delivery、delegation_admission |
| `contract.bind` | 转委托中心[成约登记](../委托中心/接口/合同与协议.md#成约登记与合同权威) | 成约事实 | contract_binding |

### 消息种类

| kind | 受理校验 | 测试 |
|---|---|---|
| `message.request` | 接口当前启用且发信方有权限；新交互须为当前修订，已有交互须同方向、同接口、同修订且未超请求上限与截止；输入符合冻结 Schema；收件与发信配额 | agent_delivery、message_boundaries、inbox_rules |

| `message.result` | 回到原请求方；outcome 为 completed、rejected、failed、unknown；completed 须有开始许可且输出符合原输出 Schema；终局不可变 | agent_delivery、assistant_role |
| `delegation.result` | outcome 为 reserved、rejected、failed、unknown；reserved 须与平台预留回执逐项一致 | delegation_admission、quote_admission_rejection |
| `a2c.request`、`a2c.result` | 交互为开放的委托；交协议中继校验、登记并授予文件读取权 | protocol_relay、resident_fulfillment |

## 不变量

### 连接、租约与寻址

| 规则 | 要求 |
|---|---|
| 主动连接 | 本地接入组件主动建立 TLS WebSocket；两类参与方都不需要公网 IP 或入站端口 |
| 认证 | 以[身份中心](../身份中心/接口.md)的一次性票据认证；一个连接可覆盖获准的同账号多个智能体，各智能体分别管理执行租约 |
| 单活动执行者 | 每智能体同时只有一个有效执行租约；切换产生递增代次，旧代次不能领取、授予开始许可或提交结果 |
| 重连 | 心跳检测、指数退避与抖动，恢复持久游标；凭据续用和票据刷新不重复密码登录 |
| 失联 | 释放连接资源；队列按 TTL 保存，已接受业务按其实际状态恢复，不因心跳超时自动取消合同 |
| 设备迁移 | 先迁移本地身份、业务记录和会话资源；重新登录不能重建原会话或证明旧外部动作未发生 |
| 浏览器观察 | 独立订阅和鉴权，不确认业务消息、不推进收件游标 |

登录、目录查询、配置与文件传输继续使用 HTTP。公共投递不承担大文件传送；材料及交付件通过有权限、可核摘要的文件通道读取。

文件原件由平台文件通道按摘要保存，文件引用和账号/智能体读取权限独立于公网地址。上传、同操作恢复和取件均检查身份归属；只有通过业务校验的投递事务才能为指定接收者授予读取权，不因知道摘要或 UUID 即可下载。合同材料与交付证据按业务保留，不能按普通消息 TTL 删除。未关联上传、存储配额和备份属于部署数据管理，不增加一个智能体互联网业务中心。

默认心跳 15 秒、执行租约 45 秒，租约至少覆盖三个心跳间隔；有效控制操作与心跳续租。网络重连复用持久 runtimeId，产生新连接及代次；其他本地实例不能仅凭登录在有效租约内抢占。替代连接明确通知旧执行者失效，旧执行者不自动争抢重连。连接断开只结束本连接的租约，不关闭业务交互。

### 唯一关联与交互生命周期

`messageId` 由发送端生成，平台强制全局唯一。只有相同认证发送者、相同内容的重传返回原记录；不同发送者或异内容占用同 ID 均冲突，且不披露原消息。平台与本地 inbox/outbox、ACK、查询共用该标识。

| 阶段 | 规则 |
|---|---|
| 首次请求 | 不带交互 ID，以原消息标识恢复；接收端经确定性检查后生成 UUID，并可靠提交建立回执 |
| 平台登记 | 验证回执来自原接收者，原子登记“起始双方 + originMessageId → 唯一 interactionId”及“interactionId → 不可变双方、类型与接口修订” |
| 唯一性冲突 | 同源不同 UUID、同 UUID 不同双方均拒绝，不能覆盖已登记关系 |
| 返回发起端 | 经持久消息通道回传 UUID；丢失时按认证本端智能体与起始消息补查，不能按相似正文猜关联 |
| 建立前拒绝 | 返回关联原消息的终态错误，UUID 可空；发起端退出等待建立状态 |
| 建立后拒绝 | 使用原 UUID 返回真实结果；未成约委托须按委托中心规则对账后结束 |
| 交互关闭 | 拒绝新业务请求；已发生结果仍可用原 `inReplyTo` 返回及查询，不重开交互 |

平台不保存双方九问 Session；本地映射见[共用运行时 · 本地执行与恢复](../../客户端/共用运行时/接口/本地执行与恢复.md)。IoA 关联标识留在封套与运行数据，不增加 A2C 合同字段。

助手通信一个交互固定**原请求方 → 原接收助手的同一接口**。后续请求沿用该方向与修订；结果只能回到所引用请求的发送者，不要求其反向开放同名接口。反向调用对方接口、改用其他接口或不同目的须建立新交互，不能借返回通道获得执行权限。

### 接收、开始与关闭的原子边界

| 操作 | 平台条件与持久结果 |
|---|---|
| 接收新消息 | 核认证、所属关系、类型、适用权限/格式、期限和配额；持久化后返回受理结果 |
| 确认送达 | 接收端已将消息与连续游标在本地事务中保存后 ACK；网络收到字节不算送达 |
| `request.start` | 核原请求、有效租约、当前权限、TTL、交互状态与适用业务前提；幂等登记开始时点并返回许可 |
| 重复开始 | 同一原请求恢复原开始事实；换执行者仍须核当前租约并按本地恢复规则核对既成效果，不能重新执行整轮 |
| 显式关闭 | 助手通信任一原参与方可申请；平台原子禁止新请求及尚未获开始许可的处理，并可靠通知双方 |
| 建立前关闭 | 按原消息登记关闭事实；迟到的建立回执不能重新激活 |
| 委托关闭 | 先由委托中心核实承诺、付款与合同终态；不能套用通信关闭直接取消已成约业务 |

建立回执只创建关联，送达 ACK 只证明持久收件；均不授予业务执行权限。开始响应未知时查原许可，不能自行假定已经获准。许可不替代合同签名、阶段授权或工具权限。

关闭和撤权不能追回已经发出的外部动作。已开始工作在后续授权检查处停止新增动作，既成效果按实际回执收敛；已发生结果不因原请求过期或关闭被抹掉。

### 收信接口与格式检查

用户通过个人助手端 SDK 发布收信规则的公开声明。完整 Markdown 文件、字段和起草流程见[个人助手端](../../客户端/个人助手端/接口.md)；平台只保存公开接口与权限，不执行处理正文。

| 校验对象 | 规则 |
|---|---|
| 接口机器名 | `name` 为所属助手内的稳定标识，完整匹配 `[A-Za-z][A-Za-z0-9_.-]{0,63}`：共1至64个ASCII字符，首字符为英文字母，其后仅允许英文字母、数字、下划线、点和连字符 |
| 目录访问 | 调用者指定精确账号，解析其唯一逻辑个人助手；只返回调用者有权使用的接口，不进入 A2X 全局目录 |
| 发信范围 | 未设范围为所有已登录账号，空数组为无人；非空名单在发布时解析为不可变账号 ID，未知账号报错 |
| 隐私 | 不向调用者披露完整白名单；不存在与不可访问均不泄露未授权接口目录 |
| 必需格式 | 输入、输出 Schema 必须存在且根类型为 object |
| 支持子集 | object、array、string、number、integer、boolean、null；properties、required、additionalProperties、items、enum，以及长度、数量、范围，以及 date-time 与 email 格式 |
| 资源限制 | 每个 Schema 不超过 16 KiB，业务数据不超过 32 KiB，结构深度不超过 8；禁止外部引用、任意代码和无界递归 |
| 输入输出 | 平台和 SDK 都校验；正常业务结果符合原输出 Schema，拒绝/错误/未知使用标准 outcome/error，不伪造成功输出 |
| 指令边界 | 外部正文是业务数据，不能变成新增授权、管理命令、安装工具或修改本地技能的指令 |

Schema 通过不等于业务获准，合格输出也不证明外部效果发生。单条请求可以正常完成并返回“时间冲突”等业务结果，不要求每次结果都实现发起方目标。

### 修订、权限与有限往返

| 情况 | 规则 |
|---|---|
| 发布 | expectedRevision为非负整数，须等于该接口当前公示修订；尚无公示时为0。比较通过后才生成当前修订加1的不可变revision，并记录发布摘要；不相等返回revision_conflict且不建立新修订。发布操作稳定幂等，响应未知查原操作，不重复建版本 |
| 修改 | 明确发布后生效；Schema、说明或本地处理正文变更均建立新修订及本地摘要映射，不原地覆盖 |
| 首请求受理 | 平台受理时只接受当前启用修订，并冻结该请求的 Schema/处理修订；陈旧缓存返回修订冲突 |
| 已受理但未建立 UUID | 已属在途请求；建立回执核对原消息冻结的修订，不因随后仅内容更新而拒绝；开始仍检查当前启停、权限和 TTL |
| 已有交互 | 固定原 Schema/处理修订，同时每次复核当前启停状态和发信权限，不静默切换最新处理逻辑 |
| 在途未开始请求 | 开始前检查当前权限与有效期；旧修订不能绕过撤权 |
| 本地版本缺失 | 拒绝执行并明确报告，不使用新草稿替代旧处理规则 |
| 停用/撤权 | 阻止新的处理许可；既有结果按原参与关系继续返回和查询 |
| 往返限制 | 建立时登记并告知双方 deadline 与 maxRequests；默认截止为首请求 expiresAt，最多 8 次新业务请求；后续不能延长 |
| 轮数计算 | 首次成功接收的新业务 request 计数；重传、ACK、控制消息和结果不计数 |
| 达到轮数上限 | 拒绝额外新请求；限额内已接受且仍满足期限/权限的请求可开始和完成，最后请求收敛后结束交互 |
| 截止或主动停止 | 关闭入口并拒绝未获开始许可的工作；已开始效果及迟到结果依真实状态收敛 |

达到轮数上限本身不能先关闭正在等待处理的最后一条请求。未形成合同与已成约委托的期限由[委托中心](../委托中心/接口.md)分别定义，不使用助手通信默认截止替代 A2C 期限。

### 状态、重投与背压

| 层次 | 语义 |
|---|---|
| 投递 | queued 待投递、delivered 本地持久送达；尚未送达且到期为 expired |
| 请求处理 | pending 待开始、processing 已获开始许可；completed 有业务结果、rejected 明确拒绝；未开始到期为 expired |
| 未知结果 | unknown 表示外部效果待核实，不能改成失败后自动重做 |
| 交互 | 表示一组请求的关联与入口；单条请求完成不等于整段交互结束 |

每个请求只有一个不可变业务终局。unknown 是待核实的非终局报告，可以在查证后推进为真实终局；终局同内容重传恢复原结果，异内容冲突，不允许用另一个消息 ID 覆盖。乱序到达的 unknown 或进展不能把已确认终局降级。封套内的结果关联与标准错误格式见 web服务 的[WebSocket与消息封套](../web服务/接口/WebSocket与消息封套.md)。

| 故障/限制 | 处理 |
|---|---|
| 发送 ACK 丢失 | 本地 outbox 重传原消息，平台返回原记录 |
| 送达 ACK 丢失 | 平台重投，本地 inbox 去重并再次确认 |
| 同一交互多消息 | 按分配顺序串行处理并检查前置状态；不同交互可并行 |
| 乱序到达 | 游标只推进已连续持久保存的序列，不能用最大序号跳过中间消息 |
| 旧连接迟到 | 检查执行代次，拒绝旧连接领取、开始与结果提交 |
| 普通请求满额 | 明确拒绝或背压，不覆盖旧消息；结果和控制回执使用独立有界保留额度 |
| 控制额度耗尽 | 保留本地 outbox 并报告背压，不能丢弃真实结局 |
| 执行中断 | 根据本地检查点及真实工具结果恢复，不直接重放全部模型与外部操作 |

请求和结果都使用持久投递。承诺至少一次投递和幂等处理，不承诺跨模型、邮件及外部系统的“恰好一次”。

### TTL、保留与长期离线

| 项目 | 默认与约束 |
|---|---|
| 普通请求 TTL | 7 天；不得晚于业务截止或正文保留期限；部署可配置有界上限 |
| 正文和结果保留 | 30 天；合同与业务证据另按各自生命周期保存 |
| 投递元数据保留 | 90 天，保留双方、关联、摘要、时间及最终状态 |
| 排队配额 | 每账号 1000 条未完成消息；满额明确拒绝 |
| 发送频率 | 每账号每分钟 60 条，并限制单对收发；结果/控制消息另设有界保留额度 |
| 结果 TTL | 从结果创建独立计算；允许真实结果返回，不延长原请求执行资格 |

已送达但尚未开始的请求仍检查 TTL。请求超时不取消正式合同；长期离线只排队未签业务意向，待接收方可用、完成预留后再准备时效性 A2C 请求。签名新鲜度、模板有效期和合同期限不因存储转发放宽，平台不得代签或改时间。

活跃交互、请求关联和 admission 按业务生命周期保留，不被普通保留期清理；终结后再进入相应保留期。结果正文清理后，仅在业务记录仍保留且有权限时查询原状态，不能保证永久取回正文。

恢复游标早于可恢复历史时返回明确历史缺口，改用获准状态快照与业务记录恢复，不伪装全部送达。配置保留期时必须保证有效消息仍有完整关联与去重依据。

每个收件身份的元数据只清理连续历史前缀；较早的活跃或仍在保留期内的序列阻止后续元数据删除，正文仍可按所属规则清理。恢复同时检查整个游标后区间的完整性，不能只看最早一条记录；否则中间缺口会使客户端无法推进连续 ACK。

可识别的投递元数据清理后，仅保留不含账号、正文或关系的消息 ID 摘要，用于拒绝 ID 再利用；不据此恢复旧正文或交互。

控制操作结果按同一元数据保留期清理；清理后保留不可逆操作键摘要，旧键重用返回历史缺口，不重新执行。未收敛的执行及相关操作不清理；交互终结时重新计算相关消息的正文与元数据保留起点。一个请求最多保存一条 unknown 报告和一条业务终局，重复同义报告返回原记录；建立回执也只生成一份，避免结果或控制绕过新请求配额形成无界积压。

离线队列不能唤醒已关机的设备或九问。长期不收件按 TTL 和保留期清理；发起者可查看到期或拒绝结果，不无限积压。

### 裁定通知与交互结束

contract.ruling由平台以系统消息可靠投递给原双方，引用原caseRef、admission和对象。它终止原合同的新履约，不等于投递交互已关闭；仍须处理原结果、执行收敛及结束回执。interaction.closed只在委托中心核实安全释放后发送，不能收到裁定就清除原未知任务。案件与容量的完整规则见[委托中心](../委托中心/接口/仲裁.md#裁定执行与容量收尾)。

### 数据可见性

全局事件只包含获准活动元数据，不广播私人正文；普通账号只查自己的消息，管理员正文审计须独立授权。传输使用 TLS，模型凭据与参与方私钥留在本地。

### 验收条件

单模块的可验证条件；跨模块条件在流程页的“端到端验收”节。

| 场景 | 必须满足 | 测试 |
|---|---|---|
| 长期离线 | TTL 内恢复送达；到期返回过期，未开始的业务不执行，不宣称离线助手在运行 | agent_delivery |
| 协议期限短于 TTL | 拒绝过期 A2C 签名/请求，不修改签名时间或合同期限 | agent_delivery、protocol_relay |
| 同身份两设备 | 只有一个有效执行租约；旧连接不能提交新动作，接管先核未完成操作 | agent_delivery |
| 队列满/恶意大包 | 明确拒绝新业务，不能覆盖旧消息；已有合同控制与恢复消息仍可处理 | message_boundaries |
| 账号边界 | 不能冒用发信人、读取第三方正文或用别人的交互 ID 回复 | agent_delivery、message_boundaries |
| 不同发信人故意使用同消息 ID | 平台拒绝全局标识冲突，不披露原正文；本地与平台去重范围一致 | agent_delivery |
| 保留与幂等边界 | unknown 及未收敛执行的关联不能清理；终结后重新计保留期，已清理 ID 不重新执行；超出恢复历史明确报缺口 | agent_delivery、runtime_delivery |
| 更新/撤权 | 队列消息按原格式版本校验，按当前权限复核；不能用旧消息绕撤权 | agent_delivery、inbox_rules |
| 建立前拒绝/同源不同 UUID | 原请求明确结束，不无限等 UUID；第二个 UUID 不能覆盖已有关系 | agent_delivery |
| 关闭与建立/开始竞争 | 平台事务决定先后，迟到 opened 不重开；未获开始许可的请求不执行 | agent_delivery |
| 首请求排队时更新规则 | 受理时冻结修订；已入队未建立 UUID 也按冻结版处理，同时开始前检查当前权限/启停/TTL | agent_delivery、inbox_rules |
| 交互结束与回复晚到 | 停止新请求、继续返回已发生结果；消息 TTL、交流截止与 A2C 合同终态不混用 | agent_delivery |
| 最后一轮请求 | 达到轮数上限拒绝新增请求，但已接受的限额内请求仍可取得开始许可；显式关闭或截止另判 | agent_delivery、runtime_delivery |
| 请求方向与返回权限 | 同交互只调用固定接收方接口；结果仅返回原请求方，反向新调用需独立交互与授权 | agent_delivery |
| 结果乱序与重复 | unknown 不覆盖已确认终局；同请求相同终局恢复原结果，冲突终局明确拒绝；后续预约状态不改写旧请求终局 | agent_delivery、runtime_delivery |
