# 官方服务

## 目的与范围

把随部署提供的官方预置服务按普通服务方接入：从包内领域资产生成未签公示与执行配置，经同一 SDK 上传验收器、取得部署发布授权、公示与续期，并按 bootId 排空停止。本模块不运行模型、不另建收件器、履约循环或合同状态机，也不含场景页；美甲、会议与编程等场景见相关文档。调用方是部署安装器与服务单元（经命令行）、在线试用（经入口文件）、种子构建与 Demo 工具（读资产）。

## 独占数据与配置

| 数据或配置 | 说明 | 存储 |
|---|---|---|
| 部署配置 | `platform_url`、`data_dir`、`host`，可选 `accounts`、`max_model_runs`、`native_tools`；字段与初值见[启动器配置与入口](接口/预置服务与启动器.md#启动器配置与入口) | 部署方私有 `official.json`，示例 `deploy/official.example.json` |
| 部署状态 | schema 1、配置绑定摘要、各账号 phase（preparing、prepared）、公开身份、验收器原操作与真实引用、未签服务与执行配置、最终配置摘要 | `<data_dir>/state.json` |
| 授权原请求 | 本次固定清单的 operationId 与 changes，发送前保存 | `<data_dir>/authorization.json` |
| 发布原操作 | 每个 agentId 的续期 operationId、原参数、状态、观察依据与公开结果 | `<data_dir>/publications.json` |
| 部署锁 | prepare、authorize、serve 与 stop 互斥 | `<data_dir>/deployment.lock` |
| 账号运行配置 | 每个 ISP 账号一份 SDK 配置，固定 `require_publication_authorization=true`；resident 目录归共用运行时 | `<data_dir>/accounts/<ISP>/config.json`、`accounts/<ISP>/resident/` |
| 领域资产 | 领域、账号、叶类、服务定义与验收器源码；包资源只读 | `assets/domains/*.json`、`assets/verifiers/*.py` |

### 领域资产

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `catalog.load_domains()`、`definitions()`、`account_of()`、`category_of()` | 读取全部领域及服务定义 | 每个领域含 slug、label、account、category、services；服务补 category、domain、origin，缺省 `runnable=true`，countersign 与 proposal 容量 1、其他 3 | slug、账号、叶类或服务 id 重复，或领域缺字段时断言失败 | official_resources、seed |
| `catalog.materialize(service,origin)`、`common_source()` | 把 `checks` 规则或 `script` 名称统一为 `verifier{id,reads,source}` | `checks` 嵌入 `common.py` 并推出 reads；`__CRITERIA__` 替换为判据；proposal 与判据补交付说明 | 脚本名越出包资源、判据为空或缺 checks 与 script ValueError | official_resources |
| `catalog.seed_manifest()` | 公开摘要与来源校验值，供 `tools/build_seed.py` 生成部署种子 | `{source:{路径:LF 规范化后的 sha256}, domains:[账号、label、category、服务摘要]}`；不含样件、生成提示与验收源码 | 无领域 ValueError | seed_manifest |
| `prepare_service(service_id,*,profile,verifier_ref,payment_provider,now)`（包入口名，即 `profiles.prepare`） | 由一项定义生成未签公示与执行配置，不登录、不发布、不调用模型 | `service` 含 profile、name、description、tags、categoryId 与一个未签模板；`execution` 含 instructions、resources、`max_active_delegations`、accepting | 未知服务、profile 不合 `[A-Za-z0-9][A-Za-z0-9_-]{0,63}`、引用不是该验收器的 `{id,uri,digest}`、付款声明不是 `{id,jwksUri}`、formation 非 countersign 或 proposal ValueError | official_resources、publication_authorizations、official_service_runtime |
| `programming.definition(service_id)`、`production_document(value)`、`variant(service_id,*,scope)` | 读取 `code-*` 编程服务定义与生产说明；`variant` 给出 display（无自助取消）与 architecture（签约前审架构图）两种范围，场景只填名称与价格 | 已 materialize 的独立副本 | 非 `code-*` 或未知范围 ValueError | programming_services、nail_scene、booking_demo |

### 部署协调命令

`python -m ioalab_services <命令> --config <文件>`，或 `ioalab-official` 脚本；结果以一行 JSON 输出，completed 退出码 0、waiting 2、rejected 与 failed 1。

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `prepare`（包入口 `prepare_deployment`，即 `preparation.prepare`） | 每个账号以未配宿主的 `ResidentRuntime(ProviderRole())` 上传验收器、预览服务，停止后写完整配置 | completed，含 accounts、services、`publishedDuringPrepare=false`、`modelStarted=false` | 已 prepared 的账号只重新加载不覆写；未完成配置被改 configuration_changed；SDK 操作未完成按原错误与原 operationId 报告，重跑继续同一操作 | official_deployment |
| `authorize --admin-username <名> --admin-password-env <变量名>`（`authorization.administrator_session`、`authorize`） | 以部署管理员 Web 会话一次授权全部服务的固定条款 | completed 及原 `authorizationReceipt`、`currentAuthorizations`；已全部符合时 `existing=true` 且不发新请求 | 缺用户名或口令 forbidden；登录无会话 protocol_error；已有记录部分存在、撤销或失配 configuration_changed；原回执未重新启用 forbidden（configure_publication）；未 prepare not_ready（prepare） | official_deployment、official_lifecycle |
| `serve`（`lifecycle.serve`、`coordinator.tick`） | 持部署锁，每 60 秒对各账号启动或接管运行时、核身份、公示与续期；SIGINT 或 SIGTERM 后排空 | 每轮一行 JSON，含各服务状态与 `allServicesReady`；全部释放后退出码 0 | 每项错误写入该行不中断其他账号；释放未完成 not_ready（inspect_original_runtime），不强杀 | official_deployment、official_lifecycle |
| `status`（`coordinator.status`） | 只查询各账号运行时与 `provider.status` | 每账号 runtime 与 services；未连接的服务报 restore_connection | 不启动、不修改；未 prepare not_ready（prepare） | official_deployment |
| `stop [--wait-seconds 0—30]`（`lifecycle.stop`） | 协调器已停后的独立恢复：对冻结的 bootId 请求 `runtime.stop` 并以 `client.lock` 证明释放 | completed、waiting 或 rejected，各账号 phase 为 released、draining、waiting 或 blocked | 等待越界 invalid_input；部署锁被占 not_ready（stop_coordinator）；身份或实例变化 blocked，不向新实例发停止 | official_lifecycle |
| 参数校验 | `--wait-seconds` 仅限 stop，管理员两参数仅限且必须随 authorize | — | argparse 报错退出码 2、无 JSON，与 waiting 同码；其他异常 failed not_ready（inspect_official_configuration） | — |

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `Deployment(path,*,services=None)`：`lock()`、`state(*,prepared)`、`save`、`environment()`、`config_path(account)`、`base(domain)`、`binding` | 校验部署配置并持有部署目录；在线试用在进程内以 `services` 取受限目录 | `services` 为服务 id 列表时只保留含这些服务的领域，账号校验与 binding 摘要按筛后目录计算；构造即用 `RuntimeConfig.from_mapping` 校验各账号配置，不建任何文件；`environment` 只留系统、证书、代理、`A2C_CACHE_DIR` 与账号 password_env，并置 `PYTHONUTF8=1` | 字段越界 invalid_input；`services` 为空、非列表、含非字符串或未知 id 为 invalid_input；目录混有他物 invalid_input；配置或资产变化 configuration_changed；已完成记录不完整 not_ready；锁被占 RuntimeError | official_deployment、trial_bootstrap |

## 不变量

| 规则 | 说明 |
|---|---|
| 同类唯一账号 | 每个领域必须对应唯一 ISP 账号与唯一叶类，账号下每项服务必须有独立 agentId；不得以服务品牌名区分登录账号 |
| 准备无效果 | prepare 不得公示、启动宿主或运行模型；已 prepared 的账号重跑不得覆写配置、身份或人工编辑 |
| 原操作先存 | 验收器上传、授权请求与续期发布必须在发送前保存 operationId 与参数；回执丢失必须以原操作恢复，不得新建操作 |
| 授权不重启用 | authorize 不得重新启用已撤销或失配的授权，也不得覆盖已有记录；只在全部目标都未授权时新建一批 |
| 凭据不驻留 | 管理员口令与 Web 会话只得存在于 authorize 进程内；serve 与各账号运行时不得继承管理员凭据 |
| 公示不覆盖 | 已公示条款与准备清单不符时必须停止该服务并报告，不得覆盖人工公示 |
| 续期只换期限 | 续期必须使用准备时的完整服务，只替换 `validUntil` 为 30 天后；剩余 7 天以上不得续期 |
| 状态只读 | status 不得启动运行时、修改配置或补写状态 |
| 停止有据 | 只有 resident 目录的 `client.lock` 可取得才得报告 released；不得按进程名终止，不得向冻结后出现的另一 bootId 发停止 |
| 锁互斥 | 同一 data_dir 同时只得有一个 prepare、authorize、serve 或 stop 持有部署锁；serve 必须持锁直到全部运行时释放 |

### 验收条件

单模块的可验证条件；跨模块条件在流程页的“端到端验收”节。

| 场景 | 必须满足 | 测试 |
|---|---|---|
| 产品配置 | 官方/普通服务走相同 SDK；个人助手在核心外；新接口不需要改平台分发器源码 | official_deployment、boundary |
| 默认配置 | 安装包生成 8 个 ISP 运行时及 50 个服务 profile；通过实际 SDK 绑定、上传验收包、授权、公示和 A2X 索引；不新增核心执行器或 50 项启动模型任务 | official_deployment、official_resources |
| 轮换与续期 | 启动及周期按 30 天/7 天/60 秒策略检查；实际原模板仍有效可复用，到期不用于新委托；续期生成新摘要，新模板可试用，原合同及原 Session 仍使用原件完成；重启不延长旧合同 | template_renewal、official_deployment |
| 重启和未知 | 保留原身份/引用/签名请求/操作；重复启动不重新赠币、不覆盖暂停或撤销，不重签未知发布；索引失败恢复当前投影而不覆盖新修订 | official_deployment |
| 真实执行 | 至少一项由原版九问经同一部署入口完成实际生产、WASM 验收、AP2 付款及信誉；记录模型/Session/原卡，不拿批量桩代替真实业务 | official_service_runtime |
| 发行与部署 | 模块、资源、路径及精确依赖摘要随包；离开源码目录可安装运行，无部署期 GitHub 访问；Windows 与 Linux 分别证明，旧入口仅在整体切换后归档 | official_resources、package_installation |
| 启动器恢复 | 准备无公示/模型，真实引用与操作先保存；中断恢复同一身份；已完整配置及人工编辑不覆盖；严格授权缺失不生成确认；启动/状态不读取私钥或业务库，状态无副作用；到期观察含已过期原件，原合同不改 | official_deployment |
| 安全停止 | 活动作业期间等待且原已授权工具可收尾；跨异步线程保留原作业许可，排队/已结束/等待用户/异实例不得借用，离线仍拒绝；排空答复与 OS 锁释放分开；丢回复、IPC 暂失、启动中及原安装/配置变化均保留原对象；换 bootId 或身份不符拒绝；占部署锁不并发停止；超时返回 waiting，原合同/密钥/未知结果与会话保留 | official_lifecycle |
