## 入口

| 入口文件 | 公开名 | 说明 |

| `__main__.py` | `main` | `python -m ioalab_services` 与 `ioalab-official` 脚本；部署安装器、服务单元、Windows 本机编排与默认部署验证以命令调用 |
| `__init__.py` | `prepare` | 包级再导出 `profiles.prepare` |

| `preparation.py` | `prepare` | 在线试用在进程内准备 |
| `authorization.py` | `administrator_session`、`authorize` | 在线试用在进程内授权 |
| `coordinator.py` | `tick`、`status` | 在线试用探针读取状态 |
| `lifecycle.py` | `serve`、`stop`、`Shutdown`、`released` | 在线试用在进程内运行协调器 |
| `programming.py` | `definition`、`production_document`、`variant` | Demo 工具 `tools/media/delegation-provider` 读取编程服务资产 |

## 内部分区

| 分区 | 文件 | 职责 |
|---|---|---|
| 领域资产 | `catalog.py`、`programming.py`、`assets/domains/*.json`、`assets/verifiers/*.py` | 以包资源读取领域与验收器源码，统一验收器写法并补默认值；导出公开种子清单；编程服务的定义与范围变体 |
| 配置映射 | `profiles.py`、`__init__.py` | 一项定义到未签公示与服务方执行配置的纯映射 |
| 部署协调 | `deployment.py`、`preparation.py`、`authorization.py`、`coordinator.py`、`lifecycle.py`、`__main__.py` | 部署配置与状态、锁与子进程环境；准备；管理员授权；周期公示与续期、状态；排空停止与释放证明；命令分派 |

## 存储与迁移

数据位置见[接口](接口.md#独占数据与配置)。`state.json` 固定 `schema=1`，并保存由部署配置、解析后的 data_dir 与 host、全部领域资产摘要计算的 `binding`；任何一项变化都使所有命令以 configuration_changed 拒绝，现有状态原样保留，没有自动迁移，改配置或升级资产须另行显式处理原身份与在途业务。`authorization.json` 同样绑定 `binding`。所有状态文件经 `private_json` 原子写入；data_dir 只允许 `deployment.lock`、`accounts/`、三份状态文件及其原子写临时文件，混入他物即拒绝。账号的 resident 目录与运行库归共用运行时，本模块只读其 `client.lock` 判定释放。

## 内部接缝

| 接缝 | 用途 |
|---|---|
| `deployment.load_domains` | 测试替换为单一领域，缩小准备与公示范围 |
| `catalog.domain_files`、`catalog.DOMAINS_DIR` | 测试注入重复账号的领域或另一份资产目录 |
| `coordinator.start`、`coordinator.connected`、`coordinator.tick` | 截获子进程环境、禁止停止后再启动、控制 serve 的单轮 |
| `tick(…,clock,stop_event)`、`serve(…,stop_event,interval)` | 测试注入时钟与停止事件，不发信号 |
| `httpx.Client` | 管理员登录以 `MockTransport` 替身 |
| `LocalClient.call` | 模拟 IPC 回执丢失与停止中的预览 |

`Deployment.__init__` 的 host 字段与 `ioalab_jiuwen` 的 `ProcessHost.from_config` 各自列出同一组四个 host 字段，修改时须同步。
