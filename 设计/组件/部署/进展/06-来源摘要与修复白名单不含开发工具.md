# 06：来源摘要与修复白名单不含开发工具

**目标行为：** 构建链迁入 `deploy/` 后，开发工具 `tools/` 的修改不再改变安装来源摘要，也不再作为允许变化的控制器文件；受管升级与修复只把实际参与构建与运行的目录算入来源。现状：部署01 已让 `deploy.build` 不再导入 `tools/`，但 `deploy/jobs.py` 的 `SOURCE_DIRECTORIES` 仍含 `tools`，`deploy/repair.py` 的 `CONTROLLER_FILES` 仍列 `tools/check_scope.py`。这改变来源摘要的定义，属于不变量变化，须先改部署接口页并升版。

**阻塞于：** 无

**状态：** ready

**范围：** 部署模块 `deploy/jobs.py`、`deploy/repair.py`；部署接口页“发行与依赖”子页的来源摘要定义。

**定向测试：** deployment_jobs、deployment_repair、production_release

- [ ] 来源摘要只含构建与运行实际读取的目录，`tools/` 改动不改变摘要
- [ ] 修复白名单不含开发工具文件
- [ ] 已有部署的来源摘要比较规则写明（新旧摘要不同即视为新来源，不静默放行）
