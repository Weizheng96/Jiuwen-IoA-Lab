# 01：部署链导入开发工具

**目标行为：** 部署代码不导入、不执行 `tools/` 下的开发工具；`tools/check_modules.py` 不再报告 部署 → 开发工具，依赖页删去开发工具行；Linux 受管安装从同一源码构建出的候选发行与摘要不变。现状经核对有四处：`deploy/install_swarm.py` 先 `sys.path.insert(0,str(ROOT))` 再 `from tools.check_vendor import validate`，违反[发行与依赖](../接口/发行与依赖.md#交付与安装单元)“运行入口不手工修改 sys.path”，且该文件只被 `tests/test_vendor_deployment.py` 调用，不在任何受管或本机安装链上；`deploy/installation.py` 的 `Installation.candidate` 在 build 环境以 `-c` 执行 `from tools.build_deployment import build`（cwd 为源码根），`build` 再导入 `tools.build_packages`、`tools.check_vendor`、`tools.deployment_dependencies` 并运行 `tools/build_access_skills.py`，检查脚本看不到这条子进程链；`deploy/repair.py` 的 `CONTROLLER_FILES` 把 `tools/check_scope.py` 列为允许变化的控制器文件；`deploy/jobs.py` 的 `SOURCE_DIRECTORIES` 含 `tools`，开发工具的任何修改都改变安装来源摘要。

**阻塞于：** 无

**状态：** claimed（deploy-trial）

**范围：** 部署；开发工具（`tools/build_deployment.py`、`build_packages.py`、`check_vendor.py`、`deployment_dependencies.py`、`build_access_skills.py`、`check_scope.py`）。需读[运行环境与发行清单](../接口/发行与依赖.md#运行环境与发行清单)、[初次启动的控制器修复](../接口/升级与修复.md#初次启动的控制器修复)与[实现入口](../实现.md#入口)。可选做法：发行构建与 vendor 校验移入 `deploy/`，工具保留为调用它的薄命令；`install_swarm.py` 移入 `tools/` 或删除；同时决定来源摘要与修复白名单是否继续覆盖 `tools/`，白名单变化是不变量变化，先改升级与修复页。
