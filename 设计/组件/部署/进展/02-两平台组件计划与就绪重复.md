# 02：两平台组件计划与就绪重复

**目标行为：** Linux 受管部署与 Windows 本机从同一份组件计划取得每个组件的运行单元、模块、参数、工作目录与环境文件，并用同一函数判定官方服务与管理员助手就绪；Linux 只把计划渲染成 systemd 单位，Windows 只把它交给 Job 所属进程。现状：`deploy/units.py` 的 `plans` 与 `deploy/windows_local.py` 的 `Local.plans` 各自写出 core、official、三个原版九问服务与 assistant 的同一组命令；`Installation.readiness` 与 `Local.readiness` 各自解析 `ioalab_services status` 的账号、服务、indexReady、templateReady、executionReady 与 accepting，并各自核 ISC_001 的 `runtime.status`；`Installation.bootstrap` 与 `Local.prepare` 各自编排官方 prepare、authorize、管理员 prepare 与登录顺序。两处已出现差异（Windows 记录逐项进度并在首次就绪后放宽 accepting，Linux 按动作与 recheck 判定），继续各改一处会分叉。

**阻塞于：** 无

**状态：** ready

**范围：** 部署。需读[Linux受管安装](../接口/Linux受管安装.md#初始化与启动)、[Windows可信本机体验](../接口/重部署与本机体验.md#windows可信本机体验)，以及[官方服务部署协调命令](../../官方服务/接口.md#部署协调命令)与[管理员助手部署准备](../../管理员助手/接口.md#部署准备)的回执字段。两平台差异（试用单位、首次与升级后的 accepting 要求）作为计划或判定函数的显式参数保留。

**定向测试：** linux_service_management、deployment_lifecycle、deployment_entry、deployment_repair、windows_local

- [ ] 官方与助手就绪判定只在一处，两平台差异是显式参数
