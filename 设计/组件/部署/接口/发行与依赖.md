# 部署 · 发行与依赖

本页是[部署](../接口.md#接口)的子页。

## 交付与安装单元

| 单元 | 源位置 | 安装与资源边界 |
|---|---|---|
| 平台 `ioalab` | `src/platform/` | 包含五个中心、观察和 Web；不安装参与方执行器、九问 Process SDK 或九问本体 |
| 统一 SDK `ioalab-sdk` | `src/access/sdk/` | 包含两个角色模块与共用常驻组件；不导入平台源码、九问实现或官方场景 |
| 九问适配 `ioalab-jiuwen` | `src/hosts/jiuwen/` | 启动装配、公开接口适配和扩展资源；依赖统一 SDK 及固定的九问 Process SDK，通过 AgentHost 边界注入 |
| 产品接入技能 | `src/access/skills/assistant/`、`src/access/skills/provider/` | 包含技能、流程、配置引导、确定性调用脚本和依赖安装清单；复用兼容的 SDK/适配环境 |
| 可选官方资源/工具 `ioalab-official` | `src/official/` | 服务定义、模板、验收器、管理员预设与业务工具；安装包在本目录构建，由通用运行时加载，不建立专属执行引擎；核心 SDK 不反向依赖 |
| 原版九问及第三方依赖 | `vendor/` | 官方实例和复现实验使用固定源码与发行物；普通用户复用既有九问，接入包不包含或替换其本体 |

网页引用的静态样式和脚本带内容摘要；源码修改后由固定工具同步摘要并检查，避免部署新页面仍使用浏览器缓存的旧资源。

各 Python 发行包使用各自实际产物 VERSION，不从设计 VERSION 推断实现完成。接入发布清单记录 SDK、适配、技能、Process SDK 的兼容组合及摘要；官方资源包另列资源和工具依赖。产物依据的归属见架构，迁移目录不自动升级依据。

仓库根 `requirements.txt` 只作为开发环境入口；生产环境按安装单元使用明确依赖清单。可安装包通过包资源或显式配置定位文件，不读取相邻源码目录；运行入口不手工修改 `sys.path`，资源定位不隐含依赖调用者工作目录或相邻 A2C 仓库。

发行目标只有Linux x86_64/CPython3.11。平台、官方实例与在线试用不提供Windows部署方式，也没有Windows发行目标或依赖锁；客户端（SDK、产品技能、九问宿主适配）仍支持Windows，经产品技能安装，不经本模块。原因见[决策0002](../../../决策/0002-只保留Linux部署.md)。core、participant、swarm使用同一Python建立三个依赖锁隔离的venv；原版wheel自带网页静态资源，默认使用SQLite及内置记忆；Redis、Milvus、Elasticsearch或其他可选外接能力不成为启动前提。

一个原版九问指一个网页实例与原版安装，个人助手及服务方仍可通过其公开Process接口建立各自会话；不承诺只有一个OS进程。官方资源及参与方仍在核心外经同一SDK运行，不把生产移入平台核心。模型凭据只由所属组件按原配置契约使用，保存于受限私有配置，不进源码、发行包或日志。A2UI答复仍是结构化输入，SDK保护动作继续要求原可信确认，不以启动成功或模型文字代替用户批准。进程管理及数据保留按[重部署与保留](重部署与保留.md)执行。

Python 发行包从隔离源码快照构建，排除 build、dist、egg-info、字节码和开发环境；构建后按源码清单核对模块，已有构建缓存不得使已删除的旧模块重新进入安装包。 A2C依赖同步仅从干净的已提交Git源码提取原blob构建，核对包内字节和版本；未提交源码、构建期间换提交或混入模块均拒绝入库。Windows工作区的自动换行不能改变来源提交所代表的包内容。

### 运行环境与发行清单

| 环境 | 包与权限边界 |
|---|---|
| core | 平台、A2C、A2X及其普通依赖；不安装参与方SDK、Process SDK、官方业务或九问本体 |
| participant | 统一SDK、九问适配、官方包、A2C和Process SDK；不安装平台或九问本体 |
| swarm | 固定原版九问及随仓Git依赖；不安装本平台或参与方SDK；部署方新建工作区与用户既有九问分开 |
| build | 仅固定构建工具，生成上述wheel及接入包；不作为任何服务的运行环境 |

发布构建从本仓固定输入生成ioalab.deployment-release/1清单，包含目标OS/CPU、CPython主次版本、各单元本地wheel名称/版本/原始SHA256、普通依赖锁及摘要、初始化数据与两接入ZIP摘要。路径为发行目录内的相对路径，拒绝越界、链接或未登记的Git依赖。整体清单内容摘要确定发行目录，完成后不原地改写。生产安装不使用根开发requirements、editable安装、VCS或Node/npm构建。

普通包分别按目标平台解析为精确版本锁；core、participant和swarm的直接依赖由实际wheel元数据取得。Git直接引用只映射到清单中已固定的本地wheel；其余直接URL拒绝。锁不包含安装源、远端引用或其他requirements文件，安装源由部署者选择的HTTPS国内镜像提供。纳入摘要的依赖锁固定UTF-8/LF字节，先写定再计算摘要，并核对Git暂存或克隆后的同一字节；不得让平台默认换行转换改变已记录摘要。锁的直接输入摘要必须与当前wheel依赖一致；解析成功不代表Linux实机通过。只提供Linux x86_64/CPython3.11清单。

安装环境按单元清单、实际平台及Python版本确定独立目录。安装前核全部摘要，安装后核精确版本、依赖及禁止混入的组件；参与方沿用[共用安装身份](../../客户端/共用运行时/接口/安装与实例.md#安装与实例核对)。只有验证完成才发布ready。完整环境不原地修补；失败保留现场，已确认失败可显式重试，只有旧状态而无真实完成/所有者证据时保持未知。运行数据不放在环境目录内。 环境使用短目录及短尝试名，目录摘要前缀只用于定位，所有权必须核对完整身份摘要；前缀冲突拒绝接管。安装后核真实依赖导入。

Linux运行路径经受控的current符号链接指向已核验完整集合；更新前须停止相关单元并确认SDK执行权释放。集合、环境链接及发行资源的路径边界由[激活与升级](升级与修复.md#激活与升级)定义。官方配置引用稳定的swarm入口和固定工作区，包升级不因此改写准备绑定、身份或业务定义；核心与参与方实际安装身份仍按真实环境路径核对。

## 依赖与发布

所有 Git 源码依赖随本仓固定，按 `vendor/SOURCES.json` 保存来源、提交、许可证、摘要及构建信息。服务器不访问 GitHub，不使用子模块、VCS 安装或现场 Node/npm 网页构建。可从部署方配置的 GitCode 远端同步或导入完整源码目录；来源 URL 仅用于追溯。

| 依赖 | 发布形式 |
|---|---|
| A2X | 普通源码快照；本平台分类数据由本仓配置生成 |
| A2C、九问 Process SDK | 锁定 wheel，并保留相应源码来源与摘要 |
| 九问及其 Git 依赖 | 原始固定源码归档、许可证、预构建 wheel；网页资产随包 |
| 普通 PyPI 依赖 | 锁定依赖及部署者可访问的国内镜像；不宣称全离线 |
| 产品接入技能 | 从源构建安装包，包含 SDK、九问适配、官方可选工具、A2C 和固定 Process SDK 的 wheels、引导与校验清单；两个技能使用同一兼容清单，生成物不回拷为第二份源码 |

`ioalab-official` 同时交付服务资源和业务工具。服务目录、验收源码及初始化摘要脱离源码仓库后仍可读取；构建按声明的源码根检查完整模块及资源，排除旧build输出。相同源码和构建环境采用固定归档时点，重复构建的wheel及接入发布摘要一致，修改技能说明本身不产生新的依赖环境。

官方工具随产品接入环境安装，但只有本机显式配置的工厂才被加载；安装本身不创建安排、开放接口、读取私人日历或发送通知。通用SDK独立安装不因此依赖官方工具。

技能安装脚本先验证清单与摘要，在用户目录准备隔离接入环境；相同账号、相同实例的另一角色复用已有运行时，仅增加角色配置。依赖或状态版本不兼容时停止接管并明确报告，不同时启动两个身份库写入者。完成检查后发布安装标记；已完成环境不可原地修补，标记损坏明确失败。启动及业务调用按[共用运行时](../../客户端/共用运行时/接口.md)核对实际安装身份，发布更新不能被相同账号或配置掩盖。SDK 的调用脚本经本机认证的 IPC 操作常驻组件，不另开同一身份数据库。

普通用户接入以其已经安装且可用的九问 Swarm 为前提。接入安装器只管理独立的 SDK/适配环境及 IoA 本地配置和数据，不写九问安装目录或全局配置，不安装、覆盖、升级或降级九问，也不更改其模型、工具权限、全局指令、自动更新及技能市场设置。用户通过九问原生入口导入接入技能，指定已有宿主命令或公开接口；额外工具和扩展仅在现有版本原生支持且用户显式配置时启用。能力缺失明确报告未就绪，不以更换宿主或自动放宽权限补齐。

随仓固定的九问版本用于官方实例和复现实验，不要求普通用户替换已有安装。部署方安装器仅可配置自己新建的独立实例，保留已有用户实例。适配先检查公开能力，不使用网页内部资源 ID 代替进程模型选择键；真实用户答复关联不可用时保持待确认。

九问网页通知使用适配包随附的 IoA 通知扩展，遵循九问原版应用扩展机制；使用[通知契约](../../客户端/宿主适配/接口/九问网页通知.md)的准备命令配置本扩展原生命名空间，凭据不写全局环境。协议能力核对不通过时保留队列并报告具体缺项；不修改上游源码或历史数据库来补齐。

容器基础镜像等第三方原件统一归vendor，固定来源、平台与完整字节摘要；本仓部署不得依赖维护者本机独占镜像缓存。容器构建先由仓内校验/导入工具核已加载标签及镜像内容，紧接构建前复核身份并使用--pull=false，不隐式pull或采用未经核实的漂移标签。第三方普通锁依赖仍按已声明的可达包镜像取得，不能把该范围表述为任意环境完全离线。
