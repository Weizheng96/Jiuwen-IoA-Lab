# 部署 · 实现

| 项 | 值 |
|---|---|
| 代码目录 | `deploy/`（`deploy/trial/` 归在线试用） |
| 产物 | `deploy/VERSION`；依赖锁 `deploy/locks/`：`build.lock` 固定 packaging 与 setuptools，`linux-x86_64/`、`windows-x86_64/` 下三单元的 `.lock` 与 `.json` 由 `tools/lock_deployment.py` 生成 |

## 入口

| 入口文件 | 公开名 | 说明 |
|---|---|---|
| `install.sh`、`upgrade.sh` | — | Linux 受管入口脚本，`umask 077` 后转交 `python -m deploy install` 或 `upgrade` |
| `__main__.py` | `main`：install、upgrade、status、start、stop、repair-bootstrap、`_worker`；`existing`、`status` | 部署者命令；`_worker` 只由 `Job.submit` 经 `systemd-run` 调用 |
| `windows_local.py` | `main`：install、start、serve、stop、status；`Local`、`WindowsProcesses`、`private_directory` | Windows 本机命令；start 以 `-m deploy.windows_local serve` 起监督进程 |
| `configure.py` | `initialize`、`main` | `python -m deploy.configure`；`tools/llm.py` 调用 `initialize` |
| `migrate_configuration.py` | `main`、`migrate`、`imported` | `python -m deploy.migrate_configuration` |
| `environment.py` | `main`、`Environment`、`validation_code`、`writer` | `python -m deploy.environment` |
| `workspace.py` | `main`、`Workspace`、`path_without_links`、`save` | `python -m deploy.workspace` |
| `release.py` | `load`、`FORMAT`、`UNITS`、`TARGETS`、`HEX`、`digest`、`sha`、`pins`、`canonical`、`file_record`、`wheel_metadata`、`read_json` | 发行清单格式；`tools/build_deployment.py`、`lock_deployment.py`、`check_deployment.py`、`deployment_dependencies.py` 导入 |
| `configuration.py` | `load`、`validate`、`platform`、`model` | 安装输入与模型输入校验；`tools/llm.py`、`import_model_source.py` 导入 `model` |
| `layout.py` | `Layout` | `tools/llm.py` 与验证工具导入 |
| `install_swarm.py` | `main` | 开发机安装固定原版九问，按文件路径运行；见[票据](进展/01-部署链导入开发工具.md) |

没有其他模块导入本目录；`tools/verification/`、`tools/smoke.py` 与测试另行导入内部文件做白盒验证，检查脚本只核模块之间的导入。

## 内部分区

| 分区 | 文件 | 职责 |
|---|---|---|
| 命令入口 | `__main__.py`、`install.sh`、`upgrade.sh`、`configure.py`、`migrate_configuration.py` | 命令解析、提交或观察原任务、平台 JSON 创建与一次性导入 |
| 布局与输入 | `layout.py`、`configuration.py`、`configs.py` | 三根认领与部署标识；安装输入与平台投影校验；角色配置一次生成 |
| 发行与环境 | `release.py`、`builder.py`、`environment.py`、`activation.py`、`processes.py` | 发行清单核验；build 环境；单元环境安装与导入核验；环境集合与 `current` 切换；子进程最小环境 |
| Linux 任务与系统 | `jobs.py`、`installation.py`、`repair.py`、`lifecycle.py`、`units.py`、`linux.py`、`backup.py` | 临时 service 任务与父子请求；安装与升级阶段；控制器修复准入；启动停止；单位生成；账号、权限与 systemd 窄操作；切换前备份 |
| 九问工作区与技能 | `workspace.py`、`assistant_skill.py`、`install_swarm.py` | 部署方九问工作区准备与模型配置；本机个人助手技能导入；开发机原版九问安装 |
| Windows 本机 | `windows_local.py` | 本机安装、监督进程、Job 所属进程与正常停止 |
| 模板与种子 | `platform.json.example`、`deployment.json.example`、`default-seed.json`、`nginx.conf`；`official.example.json`、`access-runtime.json.example`、`access-jiuwen.json.example` | 平台 JSON 与安装输入模板、种子清单（`tools/build_seed.py` 生成，构建时进入发行）、反代示例；后三个分别是官方服务与 SDK 的配置示例，由其文档引用 |

## 存储与迁移

数据位置见[接口](接口.md#独占数据与配置)。记录文件都带 `format` 字段（`ioalab.deployment-layout/1`、`initial-configuration/1`、`installation-job/1`、`deployment-environment/1`、`environment-set/1`、`deployment-release/1`、`owned-swarm/1`、`windows-local/1`、`deployed-skill/1`），格式或身份不符一律拒绝而不重建。可变记录经 `workspace.save` 或 `environment.atomic` 临时文件改名写入；初始与生成文件经 `layout.write_initial` 排他创建，已存在时只核同内容。唯一的格式迁移是 `migrate_configuration`：把已完成部署的 `core.env` 导入平台 JSON，原输入归档为 `initial.before-platform-config.json`，意图记于 `configuration-migration.json`。

## 内部接缝

| 接缝 | 用途 |
|---|---|
| `Installation.command`、`installed`、`sdk` | 测试替换子进程，断言命令、角色身份与回执处理 |
| `Systemd(…, directory=, cgroups=)`、`linux.execute` | 指向临时单位目录与 cgroup 树，不调用真实 systemd |
| `installation.activation`、`installation.backup` 模块属性 | 升级流程测试替换激活与备份并计数 |
| `environment.execute`、`venv.EnvBuilder.create` | 环境安装测试替换 pip 与 venv |
| `Local.api`（`WindowsProcesses`）、`Local.run`、`windows_local.http_open` | Windows 本机测试替换 Job、公开命令与 HTTP |
| `assistant_skill.upload`、`sdk_status` | 替换原版网页上传与产品技能状态查询 |
| `install_swarm.installation_plan`、`run`、`ensure_pip`、`initialize_workspace` | 开发机安装测试不联网、不装包 |

`units.plans` 与 `Local.plans` 各自列出同一组组件命令，`Installation.readiness` 与 `Local.readiness` 各自判定官方与助手就绪，修改时须同步，见[票据](进展/02-两平台组件计划与就绪重复.md)。
