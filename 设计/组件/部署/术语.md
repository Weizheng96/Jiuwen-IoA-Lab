# 部署 · 术语

只收部署独有的术语；被两个以上模块使用的术语在[术语地图](../../术语.md)，如安装信息。

**三根**：一个部署独占且互不嵌套的运行根、状态根与配置根，Linux 默认 `/opt/ioalab-runtime`、`/var/lib/ioalab`、`/etc/ioalab`，均不得与源码目录相交。
_Avoid_：安装目录、工作目录。代码：`Layout(root,state,config)`

**部署标识**：首次认领三根时排他写入的同一 UUID 与归属记录，之后一切接管都先核它。
_Avoid_：实例 ID、PID 文件。代码：`Layout.claim`、`inspect`、`MARKER`

**安装输入**：部署者私有 JSON，只含部署意图与对唯一平台 JSON 的引用；首次认领后连同摘要固定。
_Avoid_：部署配置、core.env。代码：`configuration.validate`、`initial.json`

**内容发行**：目录名等于清单内容摘要的自包含发行，含三单元 wheel、依赖锁、种子与两个接入技能包。
_Avoid_：安装包、构建产物。代码：`release.load`、`ioalab.deployment-release/1`

**运行单元**：按包隔离的三类运行环境 core、participant、swarm；build 只用于构建，不是运行单元。
_Avoid_：角色、服务（systemd 单位另称受管单位）。代码：`UNITS`、`Environment`

**环境集合**：引用三个已核验运行环境与原发行的不可变目录；`current` 链接指向的那个即在用集合，尚未激活的叫候选。
_Avoid_：版本、slot。代码：`activation.prepare_set`、`activate`、`envs/sets/<setId>`

**安装任务**：一个 operationId 绑定的 install、upgrade 或 repair-bootstrap 请求，由独立 systemd 临时 service 执行，前台命令只提交或观察。
_Avoid_：安装进程、原操作（SDK 用语）。代码：`jobs.Job`、`Installation`

**受管单位**：由本部署按已安装包入口生成、带部署标识注释的 systemd service。
_Avoid_：服务、守护进程。代码：`units.plans`、`render`、`linux.Systemd`

**执行权证明**：所属控制组已空，且核心、官方协调器与各 SDK 的实际 OS 锁可取得；是报告已停止、备份与切换的唯一依据。
_Avoid_：进程已退出、PID 不存在。代码：`Systemd.released`、`execution_leases`、`Lifecycle.leases`

**部署方九问工作区**：部署者为官方服务或管理员助手新建并登记归属的原版九问工作区，与普通用户已有的九问分开。
_Avoid_：用户九问、Swarm 实例。代码：`workspace.Workspace`、`ioalab.owned-swarm/1`

**控制器修复**：对首次 bootstrap 失败且已停止的安装，只允许部署控制器文件变化、复用原候选续接的子任务。
_Avoid_：重装、强制修复。代码：`repair.submit`、`CONTROLLER_FILES`
