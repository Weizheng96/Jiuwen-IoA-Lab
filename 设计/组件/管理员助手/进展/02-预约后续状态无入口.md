# 02：预约的接受、释放与结果未知核对有实际入口

**目标行为：** 主人能核对结果不明的邀请、把已接受的预约标记为 accepted，并在明确拒绝、取消或规则失效时释放预留，释放后该时段重新可约；所有转换都不重发邀请。现状：`appointments.py` 只产生 reserved、sending、submitted、unknown 与 conflict，`ACTIVE` 虽含 accepted 但无代码写入；没有任何代码把预约改为已释放；`calendar.book` 返回的恢复建议 `reconcile_invitation` 没有对应的工具或命令，`ioalab-schedule` 也只读预约库。于是已提交或未知的预约永久计入忙碌，同一交互出现 unknown 后再无法预约。

**阻塞于：** 无

**状态：** ready

**范围：** 管理员助手。需读[日历业务工具](../接口.md#日历业务工具)与[会议预约](../../../示例/会议预约.md)的“冲突与改约”“本地可编辑安排”“邀请发送与幂等”。入口是本机主人命令还是受信工具需先定方案；不得让来信或模型触发转换。

**定向测试：** appointment_source、local_schedule、calendar_outputs

- [ ] 主人可将 unknown 核对为已提交或已确定失败，核对不重发邀请
- [ ] 接受须有可靠回执或真实用户确认才写入 accepted，原 `message.result` 不被改写
- [ ] 释放后的时段可被新请求预约，已提交但未释放的时段仍计忙碌
