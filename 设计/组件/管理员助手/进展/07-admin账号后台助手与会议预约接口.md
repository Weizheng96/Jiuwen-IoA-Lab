## 已定需求与初始方案

本票为需求登记，尚未变更现行接口或实现。当前规范仍绑定 ISC_001，预约收件人只取本机配置；实施前按 design 更新账号归属、预约输入、双方收件人、后台生命周期与并发限额的唯一归属接口页并升版，再开发。

- 消息转发继续使用 message.forward 和现有 owner.notify 链路，转发到管理员九问会话，保留排队、会话收到与已读的区分。
- 会议预约沿用 meeting.request，输入增加必填的预约者本人邮箱；管理员邮箱取配置，预约者邮箱取该次预约输入，使用此前注册的 AgentMail 邮箱向双方发送 Outlook 会议邀请邮件。已有日程冲突、改约及邀请未知结果对账规则继续成立；提交邮件与对方接受分别记录，不把发出邀请当作已接受。
- 管理员本人邮箱与平台和服务方的预置 LLM API key 一样，纳入启动配置管理，默认值为 zhengw.cc@outlook.com；管理员可以在网页管理员界面查看并修改，保存到唯一配置来源，重启后保留人工修改，不被默认值覆盖。实施时同步配置模板、校验、管理员配置接口和页面，按现有修订机制防止并发覆盖，并明确显示已保存值与运行时生效状态；配置字段名及应用边界在实施前的接口设计中定稿。管理员邮箱用于接收会议邀请，AgentMail 发件邮箱继续沿用此前注册的邮箱。
- 不再增加泛化的“邮箱”对外接口，本票默认接口为消息转发、预约会议；邮箱具体凭据与私有数据不写入票据或模型上下文。
- 原共享 Swarm 资源治理诉求本期以分类独立并发限额落实：在线试用3、官方预置服务4；管理员助手长期后台运行。暂不实现管理员助手、预置服务方和在线试用之间的优先级、抢占调度。
- 实施前按 grilling 明确并发计量对象、配置归属、生效方式及满额时的排队/拒绝和资源释放规则，不擅自把并发限额变成服务总数限制。
- 迁移保留原身份映射、收信规则、会话、安排及未决邀请/通知，沿原回执恢复；与管理员助手04真实邀请验收衔接。

## 验收项

- [ ] 默认助手归 admin，ISC_001 不再配置该助手；现有部署有明确迁移和恢复路径，原数据及未决副作用不丢失、不重发
- [ ] 消息转发、预约会议两个默认接口面向所有接入方发布并可调用；消息按当前实现转发到管理员九问会话，回执如实区分排队、收到与已读
- [ ] 预约会议接口要求填写预约者本人邮箱，缺失或格式不合法时不提交邀请；管理员邮箱与该次预约者邮箱按定稿契约绑定，不串用其他预约的收件人
- [ ] 管理员邮箱作为启动配置项提供默认值 zhengw.cc@outlook.com；网页管理员界面可查看、校验、修改并持久保存，普通用户不可修改；配置修订冲突有明确反馈，重启、升级不覆盖人工设置，页面如实显示保存和生效状态
- [ ] 后续新预约使用当前已生效的管理员邮箱；配置变更不改写历史邀请收件人、不重发已提交或结果未知的邮件，预约者本人邮箱仍由该次预约输入提供
- [ ] 使用此前注册的 AgentMail 邮箱向管理员和预约者双方发送 Outlook 会议邀请邮件，核对双方收件、同一会议信息及真实提交回执；接受状态单独取证，未知结果沿原回执核对、不盲目重发

- [ ] 在线试用和官方预置服务有独立可配置的并发上限，本次分别配置为3和4；并发申请时原子执行各自上限，单类满额不会绕过限额或占用另一类名额
- [ ] 验证满额、重复启动、在途收尾、故障恢复和资源回收，记录混合负载下的实例数与资源占用；保留账号、凭据、会话与试用数据隔离；本期不实现优先级调度
