# 09：admin好友通信与九问零模型转发

**目标行为：** admin与所有注册账号建立可删除的初始双向好友；message.forward接收获准的纯文本，通过九问Swarm定制处理器直接进入管理员按发送方分组的可见会话，全流程不调用模型，其他独立业务保持其规则。
**阻塞于：** 外组前置，见下文
**状态：** ready（2026-11-13新增；现有模型调用owner.notify不满足本票，尚未实现或验收）
**范围：** 管理员助手预设/装配、个人助手端确定性入站扩展、九问公开会话/通知接口与Linux实机；[方案](../../../工程/专题/个人助手公开发现与消息转发.md#admin定制零模型转发)。不重写07的既有模型路径实测证据。
**定向测试：** admin_assistant_preparation、inbound_context、runtime_delivery、runtime_scheduling、web_notifications、native_web_delivery、official_lifecycle；新增确定性零模型转发及Linux专项并登记。

## 外组前置

[平台15](../../平台/进展/15-双向好友申请确认与默认admin关系.md)提供好友及三档权限；[客户端22](../../客户端/进展/22-固定消息转发与按发送方收信.md)定稿固定文本/权限契约。本票不依赖普通收信模型执行器，不等待其模型回执替代零模型路径。

- [ ] 实施前更新管理员助手、个人助手端/共用运行时及九问接口页并升设计版；确定性处理器由admin装配注册，平台核心不运行Swarm，不允许发送者点名工具或处理器
- [ ] 官方admin初始好友覆盖既有/未来账号；删除关系不会被prepare、登录、重启、升级、注册重放加回；恢复关系走普通申请确认
- [ ] 三档权限按当前配置复核，不用admin特权绕过关系删除；纯文本Schema与普通固定入口统一，任何文件/附件载荷都在处理前拒绝
- [ ] 直接调用九问公开追加/通知能力，来源与正文分开展示，按接收助手与发送稳定账号分组；不经过模型规则、意图判断或模型调用owner.notify
- [ ] 首次收信、重复投递、查询、丢回执及重启恢复均无模型轮次/请求，未知先查原通知，不能以模型固定回执冒充零模型
- [ ] 在Linux真实九问前台看见原文和认证来源；queued、session_received、已读区分，不以日志/数据库记录代替界面收到
- [ ] 本人未登录时后台收信仍运行，离线排队与恢复、原消息去重和结果保留正常；被撤权但未开始的旧消息不能新增转发
- [ ] 会议预约等独立明确授权业务不被改为零模型或默认停用；原07/04及其他实机待验范围保持，分别记录已提交、已发布和实机通过
