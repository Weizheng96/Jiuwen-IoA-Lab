# 管理员助手

## 目的与范围

为每个部署预置绑定 ISC_001 的固定业务助手（两条内置收信接口及其本机配置），并提供本地安排、会议预约与邀请发送这组可选业务工具。本模块不运行模型或收信循环（正常运行由[宿主适配](../客户端/宿主适配/接口.md#命令行)的 `ioalab-jiuwen serve` 承担），不批准委托授权、合同或付款，不替其他账号配置。调用方是部署安装器（经命令行）、主人（经 `ioalab-schedule`、`ioalab-agentmail`、`ioalab-outlook`），以及任何在本机 `host.business_tools` 中选用 `calendar` 工厂的实例（经入口点组 `ioalab.business_tools` 按名动态加载，不限于管理员助手，会议预约场景即如此使用）。

## 独占数据与配置

| 数据或配置 | 说明 | 存储 |
|---|---|---|
| 准备配方 | 安装器生成：deployment_id、platform_url、password、host、web_url、recipient，可选 notification、max_model_runs | `<状态根>/.deployment/admin-assistant/config.json`，部署私有 |
| 准备记录 | schema=1、binding 摘要、phase（preparing、finishing、prepared）、每条预设的原草稿与发布操作、确认摘要、原发布结果、身份、webSecret | 同目录 `state.json`；另有 `host-preview.json`、`web-arguments.json`、`prepare.lock` |
| 包内预设 | message.forward、meeting.request 的声明与处理正文；资源摘要绑定准备记录 | 包资源 `ioalab_admin_assistant/presets.json`，只读 |
| 运行配置与身份 | 完整 SDK 配置，`host.business_tools` 含 `jiuwen-web` 与可选 `calendar`；SDK 数据在 `resident/` | `<状态根>/agents/admin-assistant/config.json`、`resident/`；原版九问工作区 `<状态根>/agents/swarm-admin/` |
| 网页通知凭据 | `IOALAB_ADMIN_WEB_SECRET` | `<状态根>/agents/admin-assistant/web-notification.env`，私有 |
| 本地安排 | 主人可编辑：timeZone、rules、events；至多 256 KiB、1000 条 | 配置的 `schedule_file`，旁有 `.lock`、`.bak`；管理员默认 `<状态根>/agents/admin-assistant/schedule.json` |
| 预约库 | `appointments` 表：operation 主键、输入指纹、状态（reserved、sending、submitted、unknown、accepted、conflict、failed、released）与上下文、回执、结果、主人核对记录 settlements；来源标识防错绑 | `<源文件>.ioa/appointments.sqlite`、`source.json`、`<源文件>.appointments.lock`；源文件为 schedule_file 或 Graph 的 token_file |
| 工厂选项 | calendar、notification、recipient，可选 rules、requires_steps；凭据只用变量名或 `credentials_file` 引用，微软 SMTP 只引用 client_id 与 token_file | 本机配置 `host.business_tools` 的 `calendar` 项 |
| AgentMail 注册状态 | human_email、username、inbox_id、organization_id、api_key、verified、status | `<home>/account.json`，默认 `~/.ioalab/agentmail/`，私有 |
| 微软授权令牌 | Graph 与 SMTP 分开缓存，绑定 clientId、账号、scopes、tenant；由 `ioalab-outlook` 校验账号后写入 | 显式 `token_file`，私有；两种授权不得共用同一文件 |

固定预设的规则、准备授权与中断恢复在子页；其余分组见下文。

### 部署准备

`ioalab-admin-assistant <命令> --config <配方>`，亦可 `python -m ioalab_admin_assistant`；结果以一行 JSON 输出。无批准或运行命令，不注册为模型工具。

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `prepare`（`preparation.prepare`） | 在新建、未运行模型的受管实例上发布两个固定接口并写完整配置 | status=completed 退出码 0；返回 phase、account、originalPublications、meetingInitiallyEnabled，runtime 恒为 `{state:not_queried}` | 非 Linux root 进程 forbidden；路径或字段不符 invalid_input；归属或身份不符、未登记实例 identity_conflict；配方、资源或草稿被改 configuration_changed；确认过期或未批准 not_ready；RuntimeFault 退出码 1 status=rejected，其他异常 status=failed；中断后重跑沿原操作恢复 | admin_assistant_preparation、deployment_entry |
| `status`（`preparation.status`） | 只读查询准备阶段、原发布回执与常驻实例的实际状态 | completed 退出码 0，未完成 waiting 退出码 2；`runtime.state` 为 not_running（无应答且 `resident/client.lock` 可取得）、not_queried（查询失败、无应答但锁被持有、实例配置/安装/身份与原准备不符、或准备未完成时已有实例应答，附 error）、ready 或 not_ready（经本机 IPC `runtime.status` 应答，附 bootId、executionReady、platformConnected、hostAvailable、stopping）；currentInterfacesChecked、modelStarted 恒为 false | 同 prepare 的配方校验；prepared 阶段身份映射不符 identity_conflict，缺原密钥或运行库 not_ready；不创建目录、不登录、不启动实例 | admin_assistant_preparation |
| `presets.load(*, meetings)` | 读取包内预设；部署环境检查也调用 | 返回（资源摘要, 预设列表）；meetings=false 时 meeting.request 为 enabled=false、tools 为空 | 名单不是两项固定接口 not_ready；声明无法编解码时拒绝 | admin_assistant_preparation |

### 固定预设

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| 收信接口 `message.forward` | 面向全部已登录账号，把留言转到管理员九问网页 | 输入 title（≤120 字）、text（≤4000 字）；输出 status、可选 notificationRef；工具 `owner.notify`、`owner.notification_status` | queued、session_received 均不代表已读；结果未知查询原 notificationRef，不重复发 | admin_assistant_preparation |
| 收信接口 `meeting.request` | 面向全部已登录账号，依本地安排预约会议 | 输入 title、start、end、timeZone；输出 status、reason、建议时段、reservationId、inviteSubmitted、calendar；工具 `calendar.book`、`calendar.status` | 配方无 notification 时发布为停用；冲突时等发送方同交互新消息改约；结果未知查 calendar.status，不重发邀请 | admin_assistant_preparation、business_tools |

### 日历业务工具

工厂随 `ioalab-official` 在入口点组 `ioalab.business_tools` 登记为 `calendar`；只由宿主适配的 [`ConfiguredTools`](../客户端/宿主适配/接口.md#本地业务工具装配) 按本机配置构造，装配与工具契约见[本地业务工具](../客户端/共用运行时/接口/本地业务工具.md#本地业务工具)。

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| 入口点 `calendar` → `appointments.configure(options,*,home,profile,base_dir)` | 按配置构造两个工具，不写库、不连网 | options 必含 calendar、notification、recipient；相对路径按配置目录解析；返回 `BusinessTools`，修订 `calendar-2:<options 摘要>` | 字段不符或明文凭据 invalid_input；来源旁有旧 `mailbox.sqlite` identity_conflict；Graph 无令牌 not_ready；安排缺失或结构错抛异常，由装配转 not_ready，不建空日程 | business_tools、calendar_outputs |
| `calendar.book`（副作用类别 notification，`Appointments.book`） | 每条来信只按原输入决定一次预约 | 输入同 meeting.request；返回 conflict（reason=busy 或 outside_rules，可选建议时段）或 invite_submitted（reservationId、inviteSubmitted=true、calendar=awaiting_acceptance） | 格式不符或标题含换行 invalid_input；同消息改输入 id_conflict；原状态 sending 或 unknown、同交互有未决邀请 unknown_result（reconcile_invitation，由主人经 `ioalab-schedule reconcile` 核对）；主人核对为 failed 的原消息 closed（send_new_message），不重新预约；发送异常记 unknown 并保留预留，不自动重发；判定中安排被改则不提交 | appointment_source、local_schedule、business_tools、calendar_outputs |
| `calendar.status`（副作用类别 none，`Appointments.status`） | 查询本交互既有预约，不推进状态 | 输入 reservationId；有终局返回原回执，否则 status 为已存状态、inviteSubmitted=null、calendar=unknown | 非本 agent 与交互 forbidden；格式不符 invalid_input；主人核对为 failed 的预约 closed（send_new_message） | calendar_outputs、appointment_source |
| `calendar.backend=local`（`LocalSchedule`） | 显式选用可编辑安排 | 字段仅 backend、schedule_file；一次决定内持安排锁，按修订号核对未变 | 文件缺失或结构错阻止预约，不假定空闲 | local_schedule |
| `calendar.backend=graph`（`GraphCalendar`） | 显式选用个人 Outlook 只读日历 | 字段仅 backend、client_id、token_file；读 calendarView，核对账号，分页上限 50 | 令牌由 `ioalab-outlook graph-login` 生成；账号或范围不符、授权失效抛错并指向该命令 | assistant、outlook_auth |
| `notification.transport=agentmail`（`AgentMailNotification`） | 经 AgentMail Calendar API 提交邀请 | sender、api_key_env，可选 credentials_file；client_id 为 UID 的 SHA-256，时间转 UTC；返回 invite_submitted 回执 | 非 2xx 或响应不符抛错，由 book 记 unknown；不回退 SMTP | agentmail_invitation |
| `notification.transport=smtp`、`smtp-capture`（`SMTPNotification`） | 标准 iMIP 邀请；capture 仅用于回环测试 | host、port（默认 587）、sender，密码模式用 username_env、password_env，可选 credentials_file；微软端点（smtp-mail.outlook.com、smtp.office365.com，端口 587）改用 client_id、token_file 经 STARTTLS 与 XOAUTH2 发送（`OutlookSMTPAuth`）；返回 invite_submitted 回执 | capture 非回环 ValueError；微软端点缺 OAuth 字段 ValueError，指向 client_id、token_file 与 `ioalab-outlook smtp-login`；OAuth 与密码字段并用、仅给其一、非 smtp 传输带 OAuth 字段或 token_file 与日历来源相同 invalid_input；令牌文件缺失 not_ready；收件人被拒抛错 | business_tools、outlook_auth |

### 本地安排命令

`ioalab-schedule <命令> --file <schedule_file 或 Graph token_file> [--args <JSON>|--args-file <文件>]`，离线运行，不创建 SDK 身份、不发信；结果带 `appointments` 列表（reservationId、start、end、state、requestId、settlements）。核对与释放只由主人在本机运行，来信与模型无入口；每次转换在预约锁内追加一条 settlements 记录，不改写原消息结果。

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `init`（`LocalSchedule.init`） | 显式创建工作日 9—18 点规则与空安排 | 返回 source、path、revision、document、scope | 已存在拒绝，退出码 1 与 `{error}` | local_schedule、business_cli |
| `show`（`LocalSchedule.show`） | 读取安排与修订号，并列本地预约状态 | 同上；不写文件 | 文件缺失或结构错、预约来源不符退出码 1 | local_schedule、appointment_source |
| `replace`（`LocalSchedule.replace`） | 按读取时修订号替换全文件 | 参数 document、revision；校验、加锁、写 `.bak`、原子替换 | revision 不符或结构错退出码 1，不写入 | local_schedule |
| `reconcile`（`appointments.settle`） | 核对结果不明的邀请 | 参数 reservationId、outcome（submitted 或 failed）；只接受 unknown；submitted 写入与正常提交相同的 invite_submitted 回执并继续计入忙碌，failed 释放时段；返回 appointment | 状态或字段不符 invalid_input；无此预约 not_ready；不重发、不建库 | appointment_source、business_cli |
| `accept`（`appointments.settle`） | 主人确认已接受邀请 | 参数 reservationId；只接受 submitted；写 accepted，原回执不变，仍计入忙碌 | 同 reconcile | appointment_source |
| `release`（`appointments.settle`） | 释放明确拒绝、取消或规则失效的预约 | 参数 reservationId、reason（declined、cancelled、rule_invalid）；只接受 submitted、accepted；写 released 后时段可再约，原回执不变 | 同 reconcile | appointment_source、business_cli |

### AgentMail 注册

`ioalab-agentmail [--home <目录>] <命令>`，由部署者在本机运行，不进入模型；错误以 `{error}` 退出码 1，不含服务方响应正文或凭据。

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `signup --human-email <邮箱> [--username <名>]` | 注册通知邮箱 | 先存 signup_pending 再请求；返回 inbox、owner、verified、status、stateFile | 参数变化拒绝并保留原状态；上次结果不明不自动重注册 | agentmail_setup |
| `verify [--code-file <文件>]` | 提交六位所有权验证码 | 无文件时隐藏输入；返回同上 | 服务未确认 verified 抛错，保持不可发送 | agentmail_setup |
| `configure --credentials-file <文件>` | 写入 `AGENTMAIL_API_KEY`，保留文件内其他键 | 返回可填入工厂的 notification 对象 | 未验证、inbox 非邮箱形式或目标为注册状态文件拒绝 | agentmail_setup |
| `status` | 查看注册状态 | 不访问网络 | 无本地注册拒绝 | agentmail_setup |

### 微软授权

`ioalab-outlook <命令>`，由主人在本机完成个人 Microsoft 账号设备码登录（tenant consumers，公共客户端，无客户端密钥），不进入模型；设备码提示写标准错误，结果一行 JSON（status=authorized、resource、account、tokenFile、messageSent=false），错误以 `{error}` 退出码 1，不含令牌。新令牌先核对账号再原子写入私有 token_file，失败时保留原授权。

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `graph-login --client-id <id> --account <收件人> --token-file <文件>` | 为 `calendar.backend=graph` 授权只读日历 | scopes `offline_access Calendars.Read User.Read`；以 Graph `/me` 核对 mail 或 userPrincipalName 等于 account | 账号不符或授权失败不覆盖原令牌 | outlook_auth |
| `smtp-login --client-id <id> --sender <发件人> --token-file <文件> [--host <微软端点>]` | 为微软 SMTP 通知授权 SMTP.Send | scopes `offline_access https://outlook.office.com/SMTP.Send`；以新令牌经 XOAUTH2 认证、不发信后保存；host 默认 smtp-mail.outlook.com | 非微软端点或端口拒绝；认证失败不覆盖原令牌 | outlook_auth |

## 不变量

| 规则 | 说明 |
|---|---|
| 唯一特权 | 初始确认只用于包内两个固定接口；不得接受模型提供的账号、规则或确认引用，不得批准委托授权、合同、实名环节、验收或付款 |
| 准备可恢复 | 中断必须沿原 operationId 恢复；不得新建操作规避未知结果，已准备实例重装不重发确认或发布 |
| 不接管 | 准备不得采用未登记的旧实例、旧安排或符号链接路径；缺少原文件时不得重建空状态 |
| 准备不运行业务 | prepare 与 status 不得启动宿主、收信循环、模型或业务工具 |
| 工具可选 | 本模块工具不得被 SDK 核心静态导入；只有配置选用 `calendar` 工厂时加载，未选用时不得影响运行 |
| 构造无副作用 | 工厂不得写库、连网或创建空日程；首次调用工具时才建预约库 |
| 一消息一决定 | 同一 agentId、interactionId、messageId 只决定一次预约，结果（含 conflict）不可改写；改约必须是新消息 |
| 不重发 | 发送前必须保存 sending；sending 或 unknown 不得自动重发，换 operationId 也不得产生新邀请 |
| 预留串行 | 同一安排的检查与预留必须在同一锁内完成；未解决的预留必须计入忙碌 |
| 状态诚实 | invite_submitted 只表示邀请已提交，不得表述为已接受、已入历或已读 |
| 后续状态归主人 | unknown 的核对、accepted 的写入与预留释放只得由主人的本机命令执行，来信与模型不得触发；转换不得重发邀请，不得改写已有原回执 |
| 收件人固定 | 通知收件人只取本机配置，不得由来信指定；来信不得修改安排或规则 |
| 凭据隔离 | API key、SMTP 密码、微软令牌不得进入工具 Schema、模型、平台、输出或 Git |

### 验收条件

单模块的可验证条件；跨模块条件在流程页的“端到端验收”节。

| 场景 | 必须满足 | 测试 |
|---|---|---|
| 管理员预设 | root 固定预设准备仅限本部署 ISC_001 的两个接口；原确认及发布可恢复，模型/普通用户不得取得此权；缺邮件明确停用会议；重装保留人工修改/停用及原通知回执 | admin_assistant_preparation |
| 业务副作用未知 | 标 unknown 并对账，不自动重发邀请；本地记录不冒充 Outlook 已接受 | calendar_outputs、agentmail_invitation |
