# 在线试用

## 目的与范围

核心外的可选应用：Linux 服务器上按固定容量提供隔离试用席位，负责准入、排队、租期、撤权与整轮重置，每轮在独立容器内运行试用核心、SDK、原版九问与官方服务。不运行正式业务、不读写正式核心或 SDK 业务库。调用方是浏览器、正式平台签发的准入票据、部署单元与生命周期命令，以及席位内的预装技能。

## 独占数据与配置

| 数据或配置 | 说明 | 存储 |
|---|---|---|
| 试用配置 | profile、两个试用 origin 与正式 origin、端口、`control_directory`、`admission_key`、租期与宽限；`sandbox` 组：部署名、镜像摘要、外网桥、供应商地址与密钥文件、`control_key`、`port_base`、资源限额、模型名 | 部署方私有 JSON，模板 `deploy/trial/config.example.json` |
| 控制库 | `tickets`、`queue`、`seats`、`sessions`（只存令牌摘要）、`deployment`（profile、capacity、resource_layout）；无业务正文 | `<control_directory>/control.sqlite` |
| 单写者锁与停机回执 | `coordinator.lock`；`shutdown.json`（`configSha256`、`allEpochResourcesStopped`） | `<control_directory>/` |
| 供应商密钥 | `{"api_key"}`，root:root、600，只读挂进本轮模型代理 | `proxy_secret_file` |
| 轮次资源与数据 | 三个容器、一个业务卷、一个内部网络，带 owner、role、layout 标签；卷内四个 UID 主目录与 `control/` | 本机 Docker；卷挂于 `/epoch` |
| 受审镜像输入 | `plan.json`、`service-ids.json`、技能副本、`acceptance/` | 镜像 `/opt/trial/` |

### 浏览器网关

两个 HTTPS origin 由同一网关按精确 Host 分路；拒绝一律 403 `{error}`、`Cache-Control: no-store`。

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `create_app(coordinator,sandbox,*,secure,confirm_origin,formal_origin)` | 装配网关、启动唯一的 `reconcile` 工作线程；启动时撤销全部未结束轮次 | FastAPI 应用；关闭时先 `begin_shutdown` 再 `shutdown(sandbox)` | 原生、确认与正式 origin 不独立 ValueError；同 hostname 只允许显式 IP 不同端口 | trial_gateway |
| `GET /health` | 反代与部署的就绪探针 | `{ready,capacity}` | 停机中或任一席位非 ready/leased/reconnect_grace 或无 epoch 时 503 | — |
| `GET /entry`、`/trial`；`POST /trial/api/entry {ticket}` | 消费准入票据并建立本 origin 会话 | `{csrf}`；`__Host-ioa_trial_native` 或 `__Host-ioa_trial_confirm` cookie | 非同源、票据无效、过期、重放或停机 403；确认票据要求已持有席位 | trial_gateway、trial_leases |
| `GET /trial/api/status`、`POST /trial/api/join`、`POST /trial/api/end` | 查询、排队与主动结束 | 状态含 state、capacity、position 或 id、epoch、expires | 写入须同源 Origin 与 `X-Trial-Csrf` | trial_gateway、trial_leases |
| `GET /trial/confirm`、`GET /trial/user/api`、`POST /trial/user/decision` | 可信确认 origin 上复用 SDK 确认页，经本轮控制端口读取与提交决定 | 原确认列表或原决定结果 | 原生 origin 403；轮次变化 403；SDK 400/403/409 为 confirmation_rejected，其余 unknown_result 503 | trial_gateway、trusted_user_port |
| 原生 origin 其余 HTTP 与 WS 路径 | 透传到本轮入站转发器的固定 8080 | 剥离 Cookie、Set-Cookie、Authorization；响应先缓冲 | 路径越界、跨源写、外部重定向 403；撤权即丢弃缓冲并以 4403 关 WS | trial_gateway |

### 租用协调

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `Store(path,*,deployment_profile)`：`transaction`、`seats`、`close` | 控制库与容量、布局绑定 | 首次建表并登记绑定；席位编号 1..capacity | 缺绑定、绑定不符或编号不符 ValueError，原库不改 | trial_profiles |
| `Coordinator(store,*,audience,admission_key,lease_seconds,grace_seconds,clock,confirm_audience)`；`consume(ticket,*,audience)`、`session(token,*,audience)` | 校验准入票据并签发会话 | `(token,csrf)`；会话随租期与宽限到期 | `Denied`：签名、期限、audience、重放、停机 | trial_leases、trial_profiles |
| `enqueue(owner)`、`status(owner)`、`access(owner,epoch,*,touch)`、`end(owner)` | 原子排队分配、续用原轮次、心跳 | 席位或队列位置 | 轮次不符、过期或宽限耗尽 `Denied` | trial_leases |
| `revoke(seat,reason)`、`tick()`、`listeners` | 撤权并删除会话，通知网关关闭连接；到期与断线判定 | 席位进入 revoking | — | trial_leases、trial_gateway |
| `reconcile(sandbox)` | 唯一工作线程推进 stopping、wiping、preparing 并周期复核运行状况 | 新 epoch 先持久再建资源，健康后 ready 并分配 | 任一步异常进入 quarantined，不再分配 | trial_leases、trial_sandbox |
| `begin_shutdown()`、`shutdown(sandbox)` | 部署停机：清会话与队列、撤权后停止全部轮次，保留轮次与卷 | `shutdown_verified` | 任一停止失败 quarantined 并抛出 | trial_leases |

## 不变量

| 规则 | 说明 |
|---|---|
| 单协调器 | 每个 control_directory 只有一个持 OS 锁的协调器；资源的创建、停止与删除只由唯一工作线程串行执行，用户请求只做只读核验与控制端口调用 |
| 绑定先于开放 | profile、容量与资源布局与控制库、镜像标签一致后才开放网关；不符时保留原库与资源，不自动迁移或接管 |
| 准入一次 | 票据 60 秒内有效、按 jti 只消费一次并绑定 audience；正式平台凭据不进入网关或席位 |
| 撤权先于停止 | 结束、过期、宽限耗尽或停机先持久撤权并删除会话、关闭连接，再进入任何停止 |
| 轮次隔离 | 会话与确认绑定 owner、seat、epoch；旧轮次的 cookie、WS、链接与决定不能作用于新轮次 |
| 完整核验后动作 | 首个 TERM、发送控制 bearer 与首个删除前，均完整核验三个容器、卷与内部网络的归属和形状 |
| 失败即隔离 | 停止、销毁或健康状况未知时进入 quarantined，不推测为成功，不再分配 |
| 停机不等于重置 | 部署停机只停止并保留原轮次；回执只在全部资源核实退出时为真 |
| 密钥归属 | 供应商密钥只在模型代理；席位只得到本轮代理令牌；转发器无凭据、无挂载 |
| 固定目标 | 网关、转发器与模型代理都不接受调用方指定的地址、端口、URL 或 CONNECT 目标 |
