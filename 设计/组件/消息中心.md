# 消息中心

## 目的与范围

为个人助手和服务方提供身份绑定的长连接投递、离线暂存和状态查询；为助手通信管理收信接口、格式与发信权限。消息中心执行确定性校验，不理解业务意图、不调用参与方模型，不决定验收或付款。

消息封套、控制操作与错误格式唯一见[平台接口](../接入/平台接口.md)；本页定义其必须遵守的状态与校验规则。委托正文由 A2C 适配处理，不套用助手通信接口的 Schema。

## 职责与数据

| 权威数据 | 内容与边界 |
|---|---|
| 连接与执行租约 | 每智能体的当前连接代次、有效执行者、授权范围；连接位置不改变 `agentId` |
| 投递记录 | 原消息摘要、认证双方、接收序列、正文、TTL、投递与终态回执 |
| 交互关系 | 起始消息与交互 ID 的唯一映射、不可变双方/类型/接口修订、入口状态及请求计数 |
| 请求开始记录 | 原请求是否获准开始、许可时点及执行代次；不是模型完成证明 |
| 收信接口 | 所属助手、公开声明、不可变修订、当前启停状态与发信权限；不保存本地处理正文 |
| 业务投影 | 接收端报告的进展及真实结果引用；不代替协议原件、实际工具回执或用户已读证据 |

使用平台现有持久数据库和明确的业务校验模块，不增加独立消息中间件或通用工作流引擎。

## 连接、租约与寻址

| 规则 | 要求 |
|---|---|
| 主动连接 | 本地接入组件主动建立 TLS WebSocket；两类参与方都不需要公网 IP 或入站端口 |
| 认证 | 以[身份中心](身份中心.md)的一次性票据认证；一个连接可覆盖获准的同账号多个智能体，各智能体分别管理执行租约 |
| 单活动执行者 | 每智能体同时只有一个有效执行租约；切换产生递增代次，旧代次不能领取、授予开始许可或提交结果 |
| 重连 | 心跳检测、指数退避与抖动，恢复持久游标；凭据续用和票据刷新不重复密码登录 |
| 失联 | 释放连接资源；队列按 TTL 保存，已接受业务按其实际状态恢复，不因心跳超时自动取消合同 |
| 设备迁移 | 先迁移本地身份、业务记录和会话资源；重新登录不能重建原会话或证明旧外部动作未发生 |
| 浏览器观察 | 独立订阅和鉴权，不确认业务消息、不推进收件游标 |

登录、目录查询、配置与文件传输继续使用 HTTP。公共投递不承担大文件传送；材料及交付件通过有权限、可核摘要的文件通道读取。

文件原件由平台文件通道按摘要保存，文件引用和账号/智能体读取权限独立于公网地址。上传、同操作恢复和取件均检查身份归属；只有通过业务校验的投递事务才能为指定接收者授予读取权，不因知道摘要或 UUID 即可下载。合同材料与交付证据按业务保留，不能按普通消息 TTL 删除。未关联上传、存储配额和备份属于部署数据管理，不增加一个智能体互联网业务中心。

默认心跳 15 秒、执行租约 45 秒，租约至少覆盖三个心跳间隔；有效控制操作与心跳续租。网络重连复用持久 runtimeId，产生新连接及代次；其他本地实例不能仅凭登录在有效租约内抢占。替代连接明确通知旧执行者失效，旧执行者不自动争抢重连。连接断开只结束本连接的租约，不关闭业务交互。

## 唯一关联与交互生命周期

`messageId` 由发送端生成，平台强制全局唯一。只有相同认证发送者、相同内容的重传返回原记录；不同发送者或异内容占用同 ID 均冲突，且不披露原消息。平台与本地 inbox/outbox、ACK、查询共用该标识。

| 阶段 | 规则 |
|---|---|
| 首次请求 | 不带交互 ID，以原消息标识恢复；接收端经确定性检查后生成 UUID，并可靠提交建立回执 |
| 平台登记 | 验证回执来自原接收者，原子登记“起始双方 + originMessageId → 唯一 interactionId”及“interactionId → 不可变双方、类型与接口修订” |
| 唯一性冲突 | 同源不同 UUID、同 UUID 不同双方均拒绝，不能覆盖已登记关系 |
| 返回发起端 | 经持久消息通道回传 UUID；丢失时按认证本端智能体与起始消息补查，不能按相似正文猜关联 |
| 建立前拒绝 | 返回关联原消息的终态错误，UUID 可空；发起端退出等待建立状态 |
| 建立后拒绝 | 使用原 UUID 返回真实结果；未成约委托须按委托中心规则对账后结束 |
| 交互关闭 | 拒绝新业务请求；已发生结果仍可用原 `inReplyTo` 返回及查询，不重开交互 |

平台不保存双方九问 Session；本地映射见[本地接入组件](本地接入组件.md)。IoA 关联标识留在封套与运行数据，不增加 A2C 合同字段。

助手通信一个交互固定**原请求方 → 原接收助手的同一接口**。后续请求沿用该方向与修订；结果只能回到所引用请求的发送者，不要求其反向开放同名接口。反向调用对方接口、改用其他接口或不同目的须建立新交互，不能借返回通道获得执行权限。

## 接收、开始与关闭的原子边界

| 操作 | 平台条件与持久结果 |
|---|---|
| 接收新消息 | 核认证、所属关系、类型、适用权限/格式、期限和配额；持久化后返回受理结果 |
| 确认送达 | 接收端已将消息与连续游标在本地事务中保存后 ACK；网络收到字节不算送达 |
| `request.start` | 核原请求、有效租约、当前权限、TTL、交互状态与适用业务前提；幂等登记开始时点并返回许可 |
| 重复开始 | 同一原请求恢复原开始事实；换执行者仍须核当前租约并按本地恢复规则核对既成效果，不能重新执行整轮 |
| 显式关闭 | 助手通信任一原参与方可申请；平台原子禁止新请求及尚未获开始许可的处理，并可靠通知双方 |
| 建立前关闭 | 按原消息登记关闭事实；迟到的建立回执不能重新激活 |
| 委托关闭 | 先由委托中心核实承诺、付款与合同终态；不能套用通信关闭直接取消已成约业务 |

建立回执只创建关联，送达 ACK 只证明持久收件；均不授予业务执行权限。开始响应未知时查原许可，不能自行假定已经获准。许可不替代合同签名、阶段授权或工具权限。

关闭和撤权不能追回已经发出的外部动作。已开始工作在后续授权检查处停止新增动作，既成效果按实际回执收敛；已发生结果不因原请求过期或关闭被抹掉。

## 收信接口与格式检查

用户通过个人助手端 SDK 发布收信规则的公开声明。完整 Markdown 文件、字段和起草流程见[个人助手端 SDK](../接入/个人助手端SDK.md)；平台只保存公开接口与权限，不执行处理正文。

| 校验对象 | 规则 |
|---|---|
| 目录访问 | 调用者指定精确账号，解析其唯一逻辑个人助手；只返回调用者有权使用的接口，不进入 A2X 全局目录 |
| 发信范围 | 未设范围为所有已登录账号，空数组为无人；非空名单在发布时解析为不可变账号 ID，未知账号报错 |
| 隐私 | 不向调用者披露完整白名单；不存在与不可访问均不泄露未授权接口目录 |
| 必需格式 | 输入、输出 Schema 必须存在且根类型为 object |
| 支持子集 | object、array、string、number、integer、boolean、null；properties、required、additionalProperties、items、enum，以及长度、数量、范围和 date-time |
| 资源限制 | 每个 Schema 不超过 16 KiB，业务数据不超过 32 KiB，结构深度不超过 8；禁止外部引用、任意代码和无界递归 |
| 输入输出 | 平台和 SDK 都校验；正常业务结果符合原输出 Schema，拒绝/错误/未知使用标准 outcome/error，不伪造成功输出 |
| 指令边界 | 外部正文是业务数据，不能变成新增授权、管理命令、安装工具或修改本地技能的指令 |

Schema 通过不等于业务获准，合格输出也不证明外部效果发生。单条请求可以正常完成并返回“时间冲突”等业务结果，不要求每次结果都实现发起方目标。

## 修订、权限与有限往返

| 情况 | 规则 |
|---|---|
| 发布 | 平台按稳定发布操作幂等生成不可变 revision，并记录发布摘要；响应未知查原操作，不重复建版本 |
| 修改 | 明确发布后生效；Schema、说明或本地处理正文变更均建立新修订及本地摘要映射，不原地覆盖 |
| 首请求受理 | 平台受理时只接受当前启用修订，并冻结该请求的 Schema/处理修订；陈旧缓存返回修订冲突 |
| 已受理但未建立 UUID | 已属在途请求；建立回执核对原消息冻结的修订，不因随后仅内容更新而拒绝；开始仍检查当前启停、权限和 TTL |
| 已有交互 | 固定原 Schema/处理修订，同时每次复核当前启停状态和发信权限，不静默切换最新处理逻辑 |
| 在途未开始请求 | 开始前检查当前权限与有效期；旧修订不能绕过撤权 |
| 本地版本缺失 | 拒绝执行并明确报告，不使用新草稿替代旧处理规则 |
| 停用/撤权 | 阻止新的处理许可；既有结果按原参与关系继续返回和查询 |
| 往返限制 | 建立时登记并告知双方 deadline 与 maxRequests；默认截止为首请求 expiresAt，最多 8 次新业务请求；后续不能延长 |
| 轮数计算 | 首次成功接收的新业务 request 计数；重传、ACK、控制消息和结果不计数 |
| 达到轮数上限 | 拒绝额外新请求；限额内已接受且仍满足期限/权限的请求可开始和完成，最后请求收敛后结束交互 |
| 截止或主动停止 | 关闭入口并拒绝未获开始许可的工作；已开始效果及迟到结果依真实状态收敛 |

达到轮数上限本身不能先关闭正在等待处理的最后一条请求。未形成合同与已成约委托的期限由[委托中心](委托中心.md)分别定义，不使用助手通信默认截止替代 A2C 期限。

## 状态、重投与背压

| 层次 | 语义 |
|---|---|
| 投递 | queued 待投递、delivered 本地持久送达；尚未送达且到期为 expired |
| 请求处理 | pending 待开始、processing 已获开始许可；completed 有业务结果、rejected 明确拒绝；未开始到期为 expired |
| 未知结果 | unknown 表示外部效果待核实，不能改成失败后自动重做 |
| 交互 | 表示一组请求的关联与入口；单条请求完成不等于整段交互结束 |

每个请求只有一个不可变业务终局。unknown 是待核实的非终局报告，可以在查证后推进为真实终局；终局同内容重传恢复原结果，异内容冲突，不允许用另一个消息 ID 覆盖。乱序到达的 unknown 或进展不能把已确认终局降级。封套内的结果关联与标准错误格式见平台接口。

| 故障/限制 | 处理 |
|---|---|
| 发送 ACK 丢失 | 本地 outbox 重传原消息，平台返回原记录 |
| 送达 ACK 丢失 | 平台重投，本地 inbox 去重并再次确认 |
| 同一交互多消息 | 按分配顺序串行处理并检查前置状态；不同交互可并行 |
| 乱序到达 | 游标只推进已连续持久保存的序列，不能用最大序号跳过中间消息 |
| 旧连接迟到 | 检查执行代次，拒绝旧连接领取、开始与结果提交 |
| 普通请求满额 | 明确拒绝或背压，不覆盖旧消息；结果和控制回执使用独立有界保留额度 |
| 控制额度耗尽 | 保留本地 outbox 并报告背压，不能丢弃真实结局 |
| 执行中断 | 根据本地检查点及真实工具结果恢复，不直接重放全部模型与外部操作 |

请求和结果都使用持久投递。承诺至少一次投递和幂等处理，不承诺跨模型、邮件及外部系统的“恰好一次”。

## TTL、保留与长期离线

| 项目 | 默认与约束 |
|---|---|
| 普通请求 TTL | 7 天；不得晚于业务截止或正文保留期限；部署可配置有界上限 |
| 正文和结果保留 | 30 天；合同与业务证据另按各自生命周期保存 |
| 投递元数据保留 | 90 天，保留双方、关联、摘要、时间及最终状态 |
| 排队配额 | 每账号 1000 条未完成消息；满额明确拒绝 |
| 发送频率 | 每账号每分钟 60 条，并限制单对收发；结果/控制消息另设有界保留额度 |
| 结果 TTL | 从结果创建独立计算；允许真实结果返回，不延长原请求执行资格 |

已送达但尚未开始的请求仍检查 TTL。请求超时不取消正式合同；长期离线只排队未签业务意向，待接收方可用、完成预留后再准备时效性 A2C 请求。签名新鲜度、模板有效期和合同期限不因存储转发放宽，平台不得代签或改时间。

活跃交互、请求关联和 admission 按业务生命周期保留，不被普通保留期清理；终结后再进入相应保留期。结果正文清理后，仅在业务记录仍保留且有权限时查询原状态，不能保证永久取回正文。

恢复游标早于可恢复历史时返回明确历史缺口，改用获准状态快照与业务记录恢复，不伪装全部送达。配置保留期时必须保证有效消息仍有完整关联与去重依据。

每个收件身份的元数据只清理连续历史前缀；较早的活跃或仍在保留期内的序列阻止后续元数据删除，正文仍可按所属规则清理。恢复同时检查整个游标后区间的完整性，不能只看最早一条记录；否则中间缺口会使客户端无法推进连续 ACK。

可识别的投递元数据清理后，仅保留不含账号、正文或关系的消息 ID 摘要，用于拒绝 ID 再利用；不据此恢复旧正文或交互。

控制操作结果按同一元数据保留期清理；清理后保留不可逆操作键摘要，旧键重用返回历史缺口，不重新执行。未收敛的执行及相关操作不清理；交互终结时重新计算相关消息的正文与元数据保留起点。一个请求最多保存一条 unknown 报告和一条业务终局，重复同义报告返回原记录；建立回执也只生成一份，避免结果或控制绕过新请求配额形成无界积压。

离线队列不能唤醒已关机的设备或九问。长期不收件按 TTL 和保留期清理；发起者可查看到期或拒绝结果，不无限积压。

全局事件只包含获准活动元数据，不广播私人正文；普通账号只查自己的消息，管理员正文审计须独立授权。传输使用 TLS，模型凭据与参与方私钥留在本地。
