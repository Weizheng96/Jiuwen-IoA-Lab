# 注册中心

## 目的与范围

通过 A2X 分类树发现与需求相关的专业服务，保存可验证的公开服务资料和合同模板索引。不拟卡、不承诺接单，不负责助手通信接口目录。助手通信接口由[消息中心](消息中心.md)管理。

## 职责与数据

| 对象 | 规则 |
|---|---|
| 分类树 | 管理领域、类别与服务关联；本期实际发现使用 A2X 分类搜索 |
| 服务索引 | 关联所属账号、稳定服务 `agentId`、说明、类别及平台协议地址 |
| 签名元数据 | 缓存完整签名 Agent Card/JWKS 与合同模板；保持原签名、摘要、身份及有效期 |
| 模板索引 | 指向经委托中心签认的模板摘要及公开字段，不复制另一套合同规则 |
| 可用性投影 | 分别记录已登记、已公示、在线、接单容量和宿主就绪信息；不将种子存在等同可接单 |

索引可重建，签名原件不可因索引刷新而被改写。调用者仍须使用 A2C SDK 验签，不能仅相信搜索列表中的说明或价格摘要。

## 服务登记与发现

| 操作 | 规则 |
|---|---|
| 登记 | 认证账号提交其所属服务身份、收款公钥、签名元数据及说明；身份绑定以[身份中心](身份中心.md)为准 |
| 寻址 | 使用平台提供的稳定服务地址；不要求服务方有公网 IP、入站端口或长期运行的公网 HTTP 端点 |
| 分类 | 指定分类时校验树中节点；未指定时依据公开说明和能力在 A2X 树中匹配，返回实际路径及依据；无法确定则请求用户选择，不静默分配无关分类 |
| 公示 | 本地签署模板，经委托中心签认后提交索引；公开资料须与签名对象一致 |
| 搜索 | 按类别与需求返回候选；正式判断须读取完整模板、材料要求、规格、验收器、期限和真实信誉 |
| 刷新 | 同一服务更新索引，旧模板摘要及原件仍可查询，已成立合同继续引用原件 |
| 下线 | 停止新的推荐/接单入口，不删除既有合同所需资料；停止接单和断开连接分别呈现 |
| 地址安全 | 平台从认证上传获得签名公开资料，不根据用户输入任意抓取公网地址 |

是否接纳委托由服务方端 SDK 与[委托中心](委托中心.md)的容量规则决定，在线状态或搜索结果都不是接单承诺。普通服务接入模式及签署限制也由委托中心定义。

## 分类预览

分类预览只接收公开名称、说明、标签和可选分类，不上传业务技能、私有工具配置或合同材料，也不登记服务、签署模板或写入A2X。分类路径和目录摘要由实际A2X叶类生成；自动匹配使用平台配置的发现模型，只能从这些叶类选择一项，并返回依据。没有模型、说明不足、匹配含糊或结果无效时返回待选择及实际分类列表，不自动选择“其他”。显式分类也须先核实际叶类。

SDK先保存实际预览，包括解析后的完整service、分类路径/依据、内容摘要和预期修订。同一预览操作恢复原结果；输入变化另建操作。用户确认解析后的具体内容，发布只签署并提交该service，不重新匹配。分类已删除或修订变化时拒绝新发布并要求重新预览，不能改换用户确认的分类。

## 签名发布与原件

服务方上传签名声明和已由自己签署的模板，不提供供平台抓取的 URL。声明使用 `ioalab.service/1`，绑定稳定身份、协议地址、修订、名称、说明、标签、分类和模板摘要；签名覆盖整份声明，属于 IoA 发布凭据，不冒充 A2A Agent Card 的标准签名。平台从声明生成原版 A2C Agent Card，公开声明、证明和模板原件均可独立取得。

| 边界 | 规则 |
|---|---|
| 身份 | 仅所属 service 身份可发布；声明地址和签名公钥必须等于当前绑定，不能更换收款身份或提供任意地址 |
| 修订 | 首次为 1，后续严格递增；同一发布操作的参数不可改变；发布回执是原修订的历史事实，当前状态另查 |
| 模板 | 委托中心复用 A2C 核验、快照和签认；普通服务仅待批准/提案，付款提供者必须是本平台；不改写上传的 provider 签名，恢复先查相同摘要的已签认原件 |
| 分类 | 本次发布须有有效叶类；自动匹配不能可靠确定时返回可选分类，请用户选择，不回落到无关分类 |
| 持久化 | 声明、模板原件和发布回执在同一短事务保存；提交时复核身份、公钥、修订、分类及模板期限 |
| 索引 | A2X 是可重建投影；原件提交后刷新最新修订。索引失败不撤销已发布原件，恢复旧操作也只重建当前最新投影，不覆盖后续修订 |
| 可用性 | 已发布、索引就绪、连接在线、可执行和容量分别报告；完成公示不能直接将服务标成可接单 |

旧修订及模板按摘要保留，公开 `template.get` 可返回当前有效模板或明确指定的历史原件；业务请求仍须通过投递与接单门禁。索引重建不得重签模板、改延有效期或创建第二份身份。

## 预置内容

| 内容 | 默认配置 |
|---|---|
| 领域与服务 | 8 个领域、50 项服务；软件领域 8 项，其余领域各 6 项，配置允许每领域 5—10 项扩展 |
| 所属账号 | 每领域一个 ISP 账号；账号种子幂等创建，见身份中心 |
| 默认成约 | 官方默认服务使用待批准或提案；预批准保留为协议实验，不绕过统一接单约束 |
| 所在目录 | `src/official/services/` 保存服务配置、模板、验收器和业务技能 |
| 部署与执行 | 随平台提供，由独立服务进程经公开 SDK 接入；模型只在业务需要时调用 |
| 外部服务 | 采用同样的登记、签认、容量及执行接口；官方内容没有特殊协议权限 |

部署清单显式提供分类与内部账号种子，平台经受控初始化入口接收；服务身份及签名资料仍由参与方经 SDK 登记和发布。平台不按仓库相对路径读取官方参与方源码。默认目录须可重建，重复部署不创建同名重复身份。配置缺失、验收模型不可用或模板签认失败时显示具体未就绪原因，不以演示样件补出成功状态。

## 模板有效期与轮换

| 时点 | 官方预置服务规则 |
|---|---|
| 新模板发布 | 从签认起有效 30 天 |
| 启动与运行 | 启动时检查；运行中每 60 秒检查 |
| 即将到期 | 剩余不足 7 天时由服务方端 SDK 重新签署、请求签认并刷新 A2X |
| 轮换完成 | 新模板具有新摘要，新委托使用有效版本；原合同继续使用原模板 |
| 轮换失败 | 保留原件并报告，不能伪称续期成功；到期模板不得用于新签约 |

以上是官方服务的配置策略，不修改 A2C 模板字段及有效期语义。续期不能延长已签合同的履约期限，也不能恢复过期的用户授权。配置、连接、容量满足且模板有效后，服务启动即可试用。

## 异常与恢复

| 情况 | 处理 |
|---|---|
| 上传成功、索引刷新未知 | 以稳定发布操作及模板摘要查询结果，不重复生成不同模板 |
| 搜索命中但已离线/满额 | 展示当前状态；允许按消息规则保存意向，不能先收费或假定已接单 |
| 缓存与原件不一致 | 拒绝使用并重取可验证原件，不修补原签名字段 |
| 删除或替换种子 | 不覆盖已有身份、合同与历史原件；显式迁移目录配置 |
