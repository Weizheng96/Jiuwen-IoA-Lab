# 宿主适配

## 目的与范围

在固定原版九问 Swarm 的公开 Process SDK 上实现 SDK 的 `AgentHost` 契约（capabilities、run、cancel），并提供用户确认表单、可选网页通知扩展与本机装配入口；九问实现与[Codex适配](../Codex适配/接口.md)、[ClaudeCode适配](../ClaudeCode适配/接口.md)同级，各自实现同一三方法契约。本模块不解析合同、报价、接单、授权或付款，不修改九问源码、全局指令、全局配置或私有历史数据库。调用方是两角色模块（经 `AgentHost`）、产品技能入口脚本与部署单元（经命令行）、管理员助手与在线试用（经入口文件）。

## 独占数据与配置

| 数据或配置 | 说明 | 存储 |
|---|---|---|
| 宿主配置 | `command`（原版进程 argv）、`data_dir`（既有九问数据目录）、可选 `model`（selection_key）、可选 `skill_directories`（技能名到本机绝对目录）；不含模型密钥 | 本机配置的 `host` 区域，编辑入口见共用运行时[配置](../共用运行时/接口/配置.md#不读取凭据的配置辅助) |
| 业务工具选择 | 每项 `{factory, profile, options}`，至多 32 项；只由用户或工具配置入口管理 | 本机配置的 `host.business_tools` |
| 轮次记录 | operationId、requestId、sessionId、state（prepared、running、实际终态或 unknown）、定义摘要、原生工具是否启用、用量与错误 | `<轮次工作目录>/runs/<requestId>.json`，私有文件 |
| 业务技能读取状态 | 每轮所选主文档已实际读取的集合；冻结文档归共用运行时 | 轮次内存；快照位置见共用运行时 |
| 网页通知队列 | 固定目标、按来源消息唯一的通知、状态与回执、receiptStoreId | `<home>/roles/<profile>/business/web-notifications/`：`notifications.sqlite`、`queue.json`、`queue.lock` |
| 通知扩展文件与回执库 | 随包扩展、只含 user_id 与通知密钥的私有设置；扩展的回执、会话分组与 receiptStoreId | 九问数据目录的 `application_plugins/ioa-notifications/`、`plugins/ioa-notifications.sqlite` |
| 通知密钥 | 环境变量名 `secret_env`，或 IoA 配置目录内的专用 `credentials_file`；不交给模型、平台或 Git | 环境变量或本机凭据文件 |

### AgentHost 实现

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `ProcessHost.from_config(value,*,base_dir)` | 由 `host` 区域构造宿主，不启动进程 | 字段仅 command、data_dir、model、skill_directories；技能名 `[A-Za-z0-9][A-Za-z0-9_.-]{0,63}`、大小写折叠唯一、至多 64 个、目录须绝对 | 缺字段或格式不符 invalid_input | jiuwen_host、configuration_edit |
| `ProcessHost.probe()` | 查询 `protocol.capabilities`、`model.list`、`permission.get` 并缓存能力快照 | 需 custom_agent、host_tools、session_resume、interaction_callback、run_permissions 五项特性及有效模型；返回 `capabilities()` | 查询失败或缺项时 available=false 并给出原因，不抛出；技能源不可读记入 skillSourceErrors | jiuwen_host |
| `ProcessHost.capabilities()` | 供常驻状态报告宿主能力 | available、model、protocol、features、nativeToolPolicy（命名策略，非完整目录）、skillSources、skillSourceErrors、reason；`runtime.status` 的宿主状态即此结果加 `businessTools`，不再含 `notify` 字段，通知是否可用看 `businessTools` 中 `jiuwen-web` 资源的状态 | — | jiuwen_host |
| `ProcessHost.run(turn: HostTurn)` | 以固定 Agent 定义执行或续接一轮受限工具轮次 | 返回 `HostResult(status, session_id, usage, error, request_id)`；本地工具名不合原版规则或为 ask_user 时改用稳定 `ioa_` 别名并在说明中给出映射；补充展示用 `call_goal` 且在回调前剥离；输出契约附在工具说明 | 未通过 probe not_ready（configure_host）；工具名重复或原生工具名、权限非法 invalid_input；原生工具被宿主策略拒绝 not_ready；进程中途换 Session identity_conflict；任何异常返回 status=unknown、error.code=host_unknown，保留已见 Session，不重试 | jiuwen_host、host_tool_names、tool_output_contract、business_skills |
| `HostTurn.on_session`、`on_tool`、`on_event`、`on_interaction` | 把原版回调转给角色模块 | 首个事件带来 Session 时先写轮次记录再调用 `on_session`，只绑定一次；工具回调收到原名、剥离后的参数与 call_id；`on_interaction` 收到原生问题记录与 `_cancelled` 检查 | 未绑定 Session 或名称不在本轮清单的工具调用由回调以 forbidden 拒绝；无 `on_interaction` 时不暴露 ask_user，宿主仍提问时回调以 not_ready（wait_for_user）拒绝 | jiuwen_host、assistant_role |
| `ProcessHost.cancel(operation_id)` | 取消该操作正在执行的全部轮次 | 返回是否找到运行中的轮次 | 无运行轮次返回 false | jiuwen_host |

### 业务技能冻结

复用共用运行时的[冻结技能契约](../共用运行时/接口/本地执行与恢复.md#模块与依赖)，九问适配只负责本轮读取回调与先读后调用检查。

### 本地业务工具装配

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `ConfiguredTools(specs,profiles,*,home,base_dir)` | 按工厂名从入口点组 `ioalab.business_tools` 构造各 profile 的 `BusinessTools` | 工厂以 `(options, home=, profile=, base_dir=)` 调用，须返回 `BusinessTools`；按 profile 汇集 `ToolBinding` | 工厂名不合规则或像导入路径、profile 不属本机、选项超过 64 KiB invalid_input；未装或重复安装 not_ready（install_business_tools）；工厂异常 not_ready（configure_business_tools）；保留名 ask_user、ioa_reply、`provider.task.*`、助手工具带 requires_steps、非对象输入 invalid_input；任一失败先关闭已构造的资源 | business_tools、tool_output_contract |
| `for_profile(profile)`、`by_profile` | 给个人助手端与服务方端注入各自工具 | 名称到 `ToolBinding` 的副本 | 无配置返回空 | business_tools |
| `start()`、`status()`、`close()` | 资源生命周期与状态 | `start` 幂等；`status` 返回每项 factory、profile、resource；`close` 逆序关闭 | 单项状态异常记为 resource_status_unavailable；关闭失败保留失败项并 not_ready（inspect_business_resources） | business_tools、web_notifications |
| 入口点 `jiuwen-web` → `web_notifications.factory` | 网页通知工厂 | 返回含 `owner.notify`、`owner.notification_status` 的 `BusinessTools` | 见子页 | web_notifications、native_web_delivery |

### 确认表单

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `requirement_form()` | 原版网页 A2UI 0.8 需求表单 | 三条消息 beginRendering、surfaceUpdate、dataModelUpdate（surface `ioa-requirements`）；提交按钮 `ioa_requirements_submit` 只回传七个需求字段的数据路径，提交由宿主模型读取，不构成 SDK 批准 | — | jiuwen_a2ui_forms |
| `candidate_form(task_ref,candidates)` | 投影已完成比较的候选行供用户选择 | 1–32 行 offered 或 unsigned 原行，显示服务、合同总额与交付验收；按钮回传 taskRef、quoteRef、validUntil | 行中含批准或秘密字段、状态不合格、缺原引用或金额 ValueError | jiuwen_a2ui_forms |
| `python -m ioalab_jiuwen.a2ui [--candidates-file <文件>]` | 产品技能取完整表单 | 输出 `<a2ui-json>…</a2ui-json>`；候选文件只含 taskRef 与 candidates | 文件含其他字段时参数错误退出 | jiuwen_a2ui_forms |

表单不是授权：提交后仍由 SDK 展示可信确认，模型不能代填或以表单结果代替用户批准。

### 命令行

`python -m ioalab_jiuwen <命令> --config <本机配置>`，亦可用 `ioalab-jiuwen` 脚本；结果以一行 JSON 输出。

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `start` | 取得实例所有权并在后台启动常驻进程 | 调用 SDK `start`，子进程命令为本包的 `serve`，装配名 ioalab-jiuwen；completed 或 waiting 退出码 0 | 安装身份不符或旧进程缺核对信息时按 SDK 规则拒绝复用 | configuration_edit、package_installation |
| `serve` | 前台常驻进程：装配工具、宿主、两角色模块与常驻运行时 | probe 通过后启动业务工具再运行；退出时先关运行时再关工具 | probe 不通过 rejected not_ready（configure_host）；其他异常 failed not_ready（inspect_local_configuration） | configuration_edit |
| `assembled(path)` 上下文管理器、`Assembly.run()` | `serve` 与在线试用 `sdk_entry` 共用的唯一常驻装配；调用方只可在其外增加服务（如试用的受信确认） | 产出 `Assembly(config,runtime,host,tools)`；`run` 先 probe，通过后启动业务工具再运行常驻运行时；退出时先关运行时再关工具 | probe 不通过 RuntimeFault not_ready（configure_host），不启动业务工具 | business_tools、trial_processes |
| `configuration`、`validate`、`configure --args-file <文件>` | 离线查看、校验与局部修改配置 | 复用 SDK 配置命令，另校验 host 区域；`configure` 只接受 command、data_dir、model、skill_directories 的修改，技能目录按名称合并 | 其他字段或空修改 invalid_input；不读取工具选项或启动宿主 | configuration_edit、configuration_boundary |
| `web-extension --args-file <仅含profile的文件> --role <assistant或service>` | 为已有九问准备 IoA 通知扩展 | 返回 status=prepared、path、userId、loaded=false 与下一步提示 | 规则见子页[原生配置准备](接口/九问网页通知.md#原生配置准备) | web_setup |

## 不变量

| 规则 | 说明 |
|---|---|
| 只用公开接口 | 必须只经原版 Process SDK 与 ApplicationPluginExtension 调用九问；不得修改其源码、全局指令、全局配置或私有历史数据库，不得为补能力换版 |
| 先探测后执行 | `run` 不得在 probe 通过前启动原版进程；缺能力、缺模型时明确 not_ready |
| Session 先绑定 | 必须在首个业务工具回调前保存真实 Session 并调用 `on_session`；续接不得更换 Session |
| 不明不重做 | 轮次结果不明必须返回 unknown 并保留轮次记录与 Session，不得自动重发同一轮次 |
| 工具清单固定 | 宿主可见工具只能是本轮定义的工具、冻结技能读取器、所配原生工具及（有 `on_interaction` 时）ask_user；原生技能读取与安装工具不得出现；原生工具仅在 `allow_native_tools` 时按冻结权限启用，否则为 deny |
| 快照不重建 | 续接必须使用首轮技能快照；快照缺失或被改时停止恢复，不得用当前源文件替换 |
| 构造无副作用 | 业务工具工厂与通知工厂构造不得写库、连接或发送；资源在运行时取得所有权后启动，全部作业停止后关闭 |
| 不承担授权 | 本模块不得解析合同、发布规则或调用支付；表单与模型布尔参数不构成用户批准 |
| 秘密不外泄 | 模型密钥不得写入 IoA 配置；通知密钥不得进入模型、平台、状态输出或 Git |

### 验收条件

单模块的可验证条件；跨模块条件在流程页的“端到端验收”节。

| 场景 | 必须满足 | 测试 |
|---|---|---|
| 原版宿主轮次 | 固定 Agent/技能/工具与原 Session 续接；真实 Session 在工具前保存，原生问题在同进程获得真实答复，不伪造批准或把后台结果当网页已显示 | jiuwen_host |
| 原版九问 | 适配器检查公开能力、按原定义恢复 session；真实用户答复绑定对象与阶段，关联不可用时保持待确认；未获用户答复不回答原生 ASK，网页呈现单独核验 | jiuwen_host、jiuwen_a2ui_forms |
| 原生生产工具 | 加载技能不自动授予工具；本机精确清单及权限冻结，报价/复签 deny、生产按原许可启用；明确宿主拒绝阻止新生产，未核实不伪称已验证，实际错误保留；工具配置变化不扩大原会话权限；SDK 回调允许不代替真实用户确认 | jiuwen_host、host_tool_names |
| 本单业务文档 | 原生选中不是授权；只读回调仅访问所选技能的冻结主文档/Markdown 引用，拒绝其他技能、私有文件、链接与越界；源变化不替换旧交互，快照损坏不得重建掩盖；实际读主文档后才可提交本单动作 | business_skills |
| 九问网页通知 | 原生命名空间准备可重复执行，异内容/目标拒绝覆盖，不改安装和全局配置、不自动重启；prepared 不等于 loaded 或 ready；显式配置 IoA 通知扩展和固定用户，缺密钥/错用户不发送；离线保留、同源同内容去重、异内容冲突；发送未知先查询原回执，不换 ID 重写；TTL 不抹除未知，回执库标识改变不得将 absent 当作未执行；工具资源按实例生命周期启动/关闭；真实网页可见与会话持久化分别验收 | web_notifications、web_setup、web_extension |
