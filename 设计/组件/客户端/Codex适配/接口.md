# Codex适配

## 目的与范围

实现共用运行时定义的[内部宿主契约](../共用运行时/接口/宿主提交.md)，仅由公共层调用，不直接向模型或平台暴露。业务轮次经用户当前桌面随包的官方App Tools MCP调度：新业务用create_thread创建桌面聊天，取得真实SID并经P28确认后再发送业务；续轮保原聊天。原生审批、工具与权限由桌面UI及用户原设置处理。合同、账号、批准、消息、定义选择与幂等仍归公共层。

## 独占数据与配置

| 数据或配置 | 说明 | 存储 |
|---|---|---|
| 原生设置 | 内部定位并复用已有桌面、CLI、模型、认证、目录；统一产品只选适配器 | 宿主原设置及适配私有定位，不复制密钥 |
| 请求与原生引用 | 原operation/attempt、真实SID、提交前持久的唯一关联标记、原发送正文摘要、实际turn及事件 | 原轮次私有记录，保留旧在途原件 |
| 随包资源 | 静态登记、固定入口包装与窄hook、必要扩展及启用/重载说明 | 适配器发行包 |
| 桌面连接上下文 | 真实hook会话与正常继承的executor身份一致时，取得桌面管道、官方插件与Node定位、caller线程；不读聊天历史或模型凭据 | 适配私有受限文件；不替换原launch claim或账号配置 |

## 不变量

| 规则 | 说明 |
|---|---|
| 原会话 | 实际ID自动取得，绑定后才执行依赖该绑定的SDK工具；续轮不改原归属 |
| 桌面执行（路线A） | 业务、报价、复签审查与观察轮次只由用户当前桌面调度执行；适配经官方随包MCP调用create_thread及send_message_to_thread，不另起App Server writer。创建时只给无业务效果的初始化说明，真实SID经P28持久确认后才发送业务定义及工具；续轮保原SID。继承宿主正常审批，不使用私有前端函数或伪造caller上下文 |
| 原生工具限制 | 本期原生与显式SDK入口均不限制宿主工具；公共各阶段nativeToolsEnabled=true、nativeToolsRestricted=false，保留参数供后续逐阶段政策；继承用户原工具/Skill/权限/沙箱与原审批，不强制空工具、只读或自动批准。SDK保护和准确未支持边界见[宿主工具调用](../共用运行时/接口/宿主提交.md#只读观察) |
| 定义与工具 | 冻结定义、工具声明和受控引用由适配渲染进本次排队或受限轮次正文并附原摘要；桌面轮次的SDK工具只经固定入口+窄hook或用户已配置的MCP/Skill到达公共caller，不注入动态工具、不改用户永久设置 |
| 原生能力 | 桌面轮次复用已有工具/Skill/MCP/模型/权限；原生审批只在桌面UI出现，适配不自动allow/deny、不以浏览器代替，等待期间保持running/unknown |
| 原生入口窄授权 | 用户明确授权的固定IoA入口可由原生hook附带真实会话身份并允许本次执行；精确边界见下节，其他命令保留宿主原审批 |
| 原事实 | 文件失败保原执行事实，未知保原请求与真实资源；不重复生产或提交 |

### 路线A公开能力条件

- 桌面投送：只调用官方App Tools的create_thread/send_message_to_thread；创建和发送前均持久登记原操作及阶段。已有SID不新建；异常后效果不明保持unknown、不重投。桌面忙时不得借steer打断原轮次，不能兑现排队则明确未提交或unknown。
- 关联与终态：send只返回SID时，不把它当turn ID；通过read_thread的机器类型functionCallOutput（固定codex_app/send_message_to_thread）中未截断的官方delegation记录，精确核真实source_thread_id和完整原prompt及唯一提交标记，只接受唯一实际turn，并先P28确认才执行SDK工具。不得匹配模型回复、标题、最近轮次或正文子串；截断、冲突和缺记录保持unknown。仅该实际turn为completed且completedAt非空才是机器终态。
- S04/S05本期不声明：当前主路径有界跟踪原请求；跨重启恢复、取消与桌面重启上下文刷新自动化单列高可用专题，不冒充已支持能力。
- 通知类作业：因S04暂不声明，[原会话业务事件](../共用运行时/接口/本地执行与恢复.md#原会话业务事件)的通知作业以“官方桌面工具已受理、原操作与SID及关联标记已持久化”记为投递完成；业务、报价、复签审查与观察轮次不适用，仍按上条机器终态。受理不等于桌面已处理或用户已读。
- 连接捕获：仅明确原生setup及真实source入口在hook一次性交接/P10后刷新适配私有连接；普通runtime.status不采来源。不从其他进程抓管道或复制会话令牌，不伪造thread/turn/call身份；缺失时返回run_native_setup，不退回独立App Server执行。

### S02健康

- 常驻形态（总则见[S02运行期健康](../共用运行时/接口/宿主提交.md#s02运行期健康)）：属于本CODEX_HOME的桌面server进程存在即available（依据“desktop server present”），不按单个聊天判断，也不报busy：桌面开着而目标聊天未加载或未打开仍为available，不算unavailable；单聊天忙或待加载由S01排队体现。
- 检查间隔内持续确认不到该进程报unavailable（“desktop app not running; queued work cannot be consumed”），按共同生命周期的持续不可调用时长排空退出；无法完成枚举（权限、超时）报unknown，不累计。
- 只读进程映像与安装位置，不读命令行；认证撤销等由实际S01失败记录，check不推断。

### 原生入口窄授权

用户已明确允许安装固定IoA入口的原生hook。适配器只对本次安装绑定的绝对解释器、角色入口脚本及约定参数结构进行精确匹配，使用宿主真实工具调用元数据附带实际宿主与会话身份；官方接口要求改写入参同时返回允许执行时，仅此匹配入口可依用户授权返回允许。

相似路径、未绑定脚本、额外参数或命令、shell拼接、替换与重定向均不能扩大匹配范围。无法证明为原固定入口时，不改写输入、不返回允许，继续宿主原审批。模型提供的身份、环境猜测与最近会话不能代替原生来源。规则、解析与随包启用资源由本适配内部维护，公共层只消费已验证来源，不新增宿主方法或专有公共参数。

此授权只允许调用公共客户端入口，不批准SDK合同、环节授权、验收、付款或其他受保护业务动作；原业务仍按原对象、原期限和真实用户决定执行。hook安装、重载、实际命中及拒绝边界须分别留证；安装文件存在不表示当前桌面已启用。

## 产品配置与常驻装配

统一产品配置只保存所选适配器；必要入口与扩展不依赖可选自动安装的副作用。显式SDK应用装配仍复用统一角色/运行时，若受新契约影响由27列消费者迁移，不顺带重构官方部署。路线A实施差距登记在[31票](../进展/31-Codex桌面会话与上下文投递.md)。
