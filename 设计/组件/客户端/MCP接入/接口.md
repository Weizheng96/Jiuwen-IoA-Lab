# MCP接入

## 目的与范围

随统一 `ioalab-client`（内含 SDK）安装的本地 MCP Server，通过公共客户端操作访问所属常驻实例。提供标准 MCP 工具、MCP Apps 资源和无 Apps 时的浏览器入口；不保管账号秘密、不创建业务运行库、不维护第二套业务状态机。

## 独占数据与配置

无持久业务数据。进程只接收外置配置路径，持有本次 MCP 会话和客户端能力；实例、表单和操作记录归共用运行时。

## 接口

### 本地服务

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `create_server(config_path)` | 构造标准 MCP Server | 配置路径；工具和资源通过公共客户端入口访问 | 未启动实例明确 not_ready，不自行启动无宿主实例 | mcp_access |
| `main(argv)`；`python -m ioalab_sdk.mcp --config <path>` | stdio 入口 | stdin/stdout 仅承载 MCP；诊断走 stderr；EOF 关闭适配进程 | 不停止所属常驻实例，不重做未收敛业务 | mcp_access |
| `ioa_status`、`ioa_configuration` | 连接及非秘密配置摘要 | 无工具参数；真实 SDK 回执 | 凭据、私钥和 IPC 令牌不输出 | mcp_access |
| `ioa_setup`、`ioa_setup_status` | 安装后尚无配置时打开账号页、读取接入进度 | 无参数；受控浏览器入口与公开阶段 | 不接收秘密，不要求常驻实例；不在 App 或工具回执内返回密码 | mcp_access、onboarding |
| `ioa_forms`、`ioa_open_form`、`ioa_get_form` | 发现、打开和恢复通用表单 | kind、可选初值；原 reference | 不认识的 kind 拒绝；打开不产生批准 | mcp_access、interaction_forms |
| `ioa_update_form`、`ioa_preview_form`、`ioa_submit_form` | 编辑、预览、申请效果及原操作续接 | reference、revision、普通 values | 乐观版本冲突拒绝；提交不等于批准，原回执保留 | mcp_access、interaction_forms |
| `ioa_open_browser` | 在本机打开原表单；waiting 且有确认引用时直接打开可信确认页 | reference；只返回 opened 和原引用 | 入口秘密仅交给浏览器，不返回普通工具 | mcp_access、interaction_forms |
| `ui://ioalab/forms/v1.html` | MCP Apps 通用表单资源 | `text/html;profile=mcp-app`；工具 `_meta.ui.resourceUri` 关联；无外部网络依赖 | 未支持 Apps 的宿主仍获得完整文本/结构化结果和浏览器打开操作 | mcp_access |

### 协议与能力

使用官方 Python MCP SDK 的 stdio 生命周期和工具/资源接口；Apps 按 [SEP-1865 稳定规范](https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx)进行能力协商、`ui/initialize`、工具调用和结果通知。仅在宿主声明支持对应 MIME 类型时附 App 元数据；标准 MCP 可用不代表宿主支持 Apps 或后台 AgentHost。

## 不变量

| 规则 | 说明 |
|---|---|
| 单一业务执行 | 所有业务调用必须经共用运行时的公共客户端入口与受认证 IPC，固定实际 bootId；本模块不得打开账号库、私钥或运行库 |
| 批准隔离 | 不提供 approve、任意操作或命令执行工具；App 表单提交不得生成可信批准，仍由所属 SDK 确认机制核验 |
| 双通道 | MCP 会话只提供交互；平台 HTTPS/WSS 与业务调度由常驻实例持有，关闭 MCP 不结束业务 |
| 原操作 | 业务表单 reference、revision 与原操作身份独立于 MCP request id；超时及重连沿原表单恢复 |
| 脱敏 | 配置只返回明确公开字段；异常不回显原始凭据、启动 URL 或配置内容 |
