# 14：A2C与IoA网络传输统一

**目标行为：** 保留原 A2C Client、Provider、AP2 等协议实现，将其网络传输统一交由 IoA 客户端管理。两角色复用同一常驻实例的网络资源与 CA 信任策略：业务消息走既有 WSS，账号、模板、公钥、文件等走共用 HTTPS，避免角色各自创建 A2C HTTP 客户端和异步事件循环。

**阻塞于：** 无

**状态：** ready

**验收环境：** 本机先执行定向及链路验证；服务器验证以[部署05](../../部署/进展/05-新Linux服务器部署与验收基线打通.md)的新部署为前置。与客户端12、13无硬阻塞，按项目约定串行开发后组合验收。

**范围：** 共用运行时[A2C适配](../共用运行时/接口/A2C适配.md)、[账号与登录](../共用运行时/接口/账号与登录.md)、[调用与启动](../共用运行时/接口/调用与启动.md)、[实现](../共用运行时/实现.md)，个人助手端、服务方端及 SDK装配；依赖 web服务[接口](../../平台/web服务/接口.md)及[WebSocket与消息封套](../../平台/web服务/接口/WebSocket与消息封套.md)。相关需求见[专题](../../../工程/专题/接入易用性与Agent调用效率.md)。

**定向测试：** sdk_tls、sdk_contract、runtime_delivery、protocol_operations、access_products、account_enrollment、authentication_recovery、service_publication、task_recovery_receipts；设计定稿后补资源复用、并发、关闭及凭据隔离验证。

## 现状与初始方案

本票为需求登记，尚未变更现行接口或实现。当前 SessionTransport 已将主要合同、履约及付款调用映射至 IoA 长连接与文件通道，但个人助手 Trading 和服务方 ProviderExecution 仍分别创建 A2ATransport/httpx.AsyncClient，读取模板及公钥；SessionTransport 还存在默认创建独立 A2ATransport 的路径。账号和连接恢复也各有 HTTP 客户端。此前 CA 问题暴露出多处独立构造带来的配置遗漏风险，当前其他会话的 TLS 修复仍须独立交付和验证，本票不替代该修复。

1. 盘点所有客户端网络构造、调用方、鉴权、超时、代理、CA 和关闭归属；按同一实例内可共享资源与独立短期控制场景明确生命周期。实施前按 design 定义统一网络 owner、注入接口及拒绝/恢复契约，更新所属接口页、依赖及实现页并升版。
2. 由 IoA 共用运行时唯一管理网络策略及常驻实例的共享 HTTPS 连接池、WSS 生命周期；账号会话继续拥有凭据，角色模块和协议适配只使用注入能力。显式登录及安装前控制等独立进程复用同一构造与策略定义，各自正确关闭资源，不要求跨进程共用一个连接池。
3. 通过 A2C 原有 Transport 等公开契约接入 IoA 传输，保留合同字段、签名、期限、验收、AP2 和协议状态机；移除角色自建 A2ATransport/AsyncClient 及其专用事件循环，SessionTransport 不再隐式创建第二套网络资源。协议适配负责转换，连接与 TLS 由共用运行时负责，不修改上游协议库来依赖 IoA。
4. 已有业务消息及控制继续走同一 WSS；登录、配置、目录、Agent Card、模板、公钥、文件和恢复查询使用共用 HTTPS 能力，保留公开协议入口及其原件校验。不把全部流量迁到 WSS，不增加断线时改走另一业务执行链的回退。
5. CA 信任来源、证书链及主机/IP 校验、代理策略、错误分类与超时从统一位置定义；按操作保留合适的超时和并发边界。大文件传输及慢查询不得阻塞心跳、控制和任务进展；统一策略不等于无限重试或所有请求使用同一超时。
6. 公共读取与带账号凭据的请求按目标和用途隔离；共享连接池不自动附带 Bearer、密码或 Cookie 到公钥、模板及外部 URL。校验目标、重定向及允许访问范围，保持交互、公钥归属和文件授权检查；TLS 信任不替代 A2C 签名验证。
7. 保持原 operationId、messageId、taskId、签名、文件摘要、游标及恢复语义；断线重连只恢复原操作，未知效果不换号重做。统一 owner 关闭资源，角色退出不提前关闭其他角色仍在使用的连接，失败初始化和安全停止均释放本次资源。

## 验收项

- [ ] 提供改造前后网络调用与资源归属图；两角色无独立 A2C HTTP 客户端、专用事件循环及隐式网络构造路径，共享连接池和 WSS 按实例管理
- [ ] 登录、模板、公钥、目录、文件、恢复查询及 A2C 业务链路经统一网络策略运行，正确处理各自鉴权、超时和错误，保留原协议验证
- [ ] 对实际 HTTPS/WSS 路径验证受信任内部 CA 成功、未知 CA 与错误主机/IP 拒绝；同步/异步调用方均覆盖，不以一条路径成功替代其余路径验收
- [ ] 公共/外部请求及重定向不泄露账号凭据；双角色并发、慢请求和文件传输期间，心跳、控制及其他角色操作可继续处理
- [ ] 验证角色关闭、初始化失败、安全停止与重启，无提前关闭共享资源、遗留连接或线程；显式登录短期入口不依赖已运行实例
- [ ] 委托、履约、验收、付款及多期合同正常与故障恢复不变，无重复签名、收费、生产或通知；已有身份、业务数据与原操作保留
- [ ] 比较连接池、事件循环/线程及握手数量与代表场景耗时，报告实际收益，不把网络收敛等同于模型思考次数减少
- [ ] 定向与链路检查通过，并以新服务器、实际安装包及原生九问完成两角色验证，记录版本、CA信任环境、回执和未验证范围
