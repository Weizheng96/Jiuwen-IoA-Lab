# 18：多宿主与无 Apps 接入验收

**目标行为：** 共用 IoA 安装及本地 MCP 接口在目标宿主按各自能力工作；无 Apps 仍可经浏览器或 Skill/CLI 完成三类业务，同一助手身份只有一个活跃执行者。

**阻塞于：** 12、13、15、16、17

**状态：** ready

**验收环境：** 九问、Codex、Claude Code 的实际受测版本，所属系统用户的客户端安装，以及[新服务器验收基线](../../../工程/实施资料/部署发行.md#新服务器验收基线2026-11-11)。

**范围：** [宿主适配](../宿主适配/接口.md)、[安装与实例](../共用运行时/接口/安装与实例.md)、[调用与启动](../共用运行时/接口/调用与启动.md)、[用户确认](../共用运行时/接口/用户确认.md)、MCP/UI及两角色技能；决策以[专题](../../../工程/专题/接入易用性与Agent调用效率.md)为准，结合既有客户端09、10、11复用未变输入的验收证据。

**定向测试：** access_products、package_installation、installation_identity、lease、resident_runtime、jiuwen_host、trusted_user_port、task_recovery_receipts；后续补宿主配置与显式交接用例。单元测试不代替下列实机矩阵。

## 待实施方案

本轮只登记验收范围，不启动安装、宿主修改或业务开发；所需适配先按所属接口设计和升版。

1. 对每个实际版本分别记录标准 MCP 连接、标准 Apps 呈现、可信用户确认、后台入站执行四项能力与证据；不从其中一项推出其余项已兼容。
2. 九问首期使用浏览器表单。验证真实浏览器入口、状态回传及原会话续接；有标准 Apps 的宿主另验资源加载与桥接，没有则如实记录替代呈现路径。
3. 用相同业务输入分别走 App（能力允许时）、浏览器和 Skill/CLI，核对三类业务的效果、授权、状态与恢复一致；配置读取和其他公共工具不依赖 UI。
4. 同机同系统用户切换宿主复用兼容安装与凭据引用，但分别配置入口及适配；同一身份显式暂停新任务、处理在途记录、释放原绑定再交接。不能可靠交接的任务保持待处理，不静默丢弃或让两宿主并发执行。
5. 覆盖重复启动、租约冲突、原宿主失联、目标宿主能力不足、重启与交接中断；保留原数据及恢复引用，不共享可被两个进程同时写入的运行目录。
6. 分别记录模型轮次、工具调用、阅读量和分阶段耗时；对不可用能力提供具体下一步，不承诺所有宿主能自动执行相同后台工作。

## 验收项

- [ ] 三宿主能力矩阵有版本、入口、实际结果和未验证项；不修改第三方宿主源码，不把 A2UI 当作标准 Apps
- [ ] 接入、私人交互、委托交易在无 Apps 路径均有完整真实证据；有能力的宿主完成 App 路径
- [ ] 换宿主复用安装，不重复注册或复制身份；同一身份同时只有一个活跃执行者，权限和在途业务正确交接
- [ ] 普通工具、模型、日志与各宿主配置不含账号密码或参与方私钥；真实批准不能由工具参数伪造
- [ ] 失败、取消、重复调用及中断恢复保持原业务语义，实际效率对比和未完成适配按事实记录
