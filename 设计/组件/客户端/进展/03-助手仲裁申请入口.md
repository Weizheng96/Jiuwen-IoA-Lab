# 03：个人助手仲裁申请与案件查询

**目标行为：** 本机个人助手对本机原合同（contractRef）或已付拟卡费的原请求（quoteRef）调用 `assistant.delegation.dispute`（二选一引用、ground、必要 period 与材料引用，可选原 confirmationRef），SDK 取原依据与取证预览、准备本助手所属的材料上传引用，独立请求用户确认后提交原 `arbitration.request`，分别返回申请与受理回执及 caseRef；`assistant.delegation.dispute_status`（caseRef）返回已验签的原案件与裁定、执行收敛与实际付款；同操作重传恢复原案件，错过通知时按原 admission 补查，不新建案件。

**阻塞于：** 无

**状态：** ready（开发中，与当前设计有偏离）

**范围：** 个人助手端。现状：[委托交易入口](../个人助手端/接口/委托交易入口.md#委托交易入口)与[仲裁申请与材料](../个人助手端/接口/候选比较与合同状态.md#仲裁申请与材料)定义了两项操作，但 `AssistantRole.bind` 的操作清单未登记，`src/access/sdk/ioalab_sdk/assistant/` 无仲裁代码，产品技能的 `references/delegation.md` 也无此流程；平台的 `arbitration.request` 与 `/arbitrations/preview` 已存在（`tests/test_arbitration_cases.py` 直接经 `connection.call` 调用），共用运行时 `adapters/arbitration.py` 的 `read_case`、`require_open` 尚无调用方。修复方案：在 `role.py` 的操作表增加两项，复用共用运行时的案件读取与验签、[用户确认](../共用运行时/接口/用户确认.md#用户确认)与[案件恢复](../共用运行时/接口/操作与恢复.md#案件恢复与新轮次)；与服务方同类入口（[05](05-服务方仲裁申请与案件查询.md)）的共用部分落在共用运行时。需读[web服务 仲裁接口](../../平台/web服务/接口/仲裁接口.md)与[委托中心 仲裁](../../平台/委托中心/接口/仲裁.md#争议案件与原证据)。

**定向测试：** arbitration_cases、arbitration_evidence

- [ ] 两项操作登记并按子页输入校验，未确认返回 waiting
- [ ] 同操作恢复原 caseRef，不创建第二份案件
- [ ] dispute_status 只读，不触发复算或按裁定付款
- [ ] 产品技能的委托交易流程页增加仲裁一步；个人助手端接口页删除“尚未实现”注记
