## 实现方案

### 2026-11-16检查点与可交接切片

- Codex 0.167.0-alpha.3.2：新测probe通过；同版后台工具轮次／原ID续接／取消复用既有真实证据。本轮独立公开CLI queue向实际桌面原活动会话投一次，退出0，queue/list查到原queueId；用户确认排队可见，当前turn结束后同一原聊天自动消费为下一轮user消息，主智能体确认。busy采用串行排队，不是中途steer。31可依此推进，空闲单测和独立新会话原生列表仍待验。本轮隔离真实推理45秒unknown，不重试。
- Claude CLI 2.1.325／SDK 0.2.181：本轮无模型握手5.9秒退出0；当前firstParty API key认证适用Channels。30可推进原生交互会话＋公开MCP Channel，须启动时启用且受组织政策约束，SDK开发Channel开关无效；SDK/-p创建默认resume列表隐藏，不能冒充列表验收。活动、空闲、关闭恢复与列表尚未实测。
- 九问Windows workSwarm 0.2.8已有完整运行安装；公开Process能力／权限成功，model.list在12秒期限超时；原生Web models.list成功。现有默认workspace无IoA通知扩展，32需准备并经原生加载，验证用户／渠道归属和原聊天回投。本轮不动已有进程／配置。
- 27先实施能力事实、绑定及分级回执，不等待所有宿主都通过；各项unknown不重发，accepted不当handled。当前不变量未改、产品源码未改、未提交／发布；36整体门禁保持未通过。精确调用、认证、限制与证据见[现状与证据](../../../工程/专题/一句话接入与三宿主全流程/现状与证据.md#26先行验证检查点2026-11-16)。

1. 以仓内适配器与当前安装SDK为起点，按官方公开接口逐项建立能力矩阵；九问使用Process查询与原生Web扩展，Claude使用Agent SDK及适用的Channels，Codex核桌面实际连接与App Server公开入口。
2. 先执行不调用模型的预检，再在隔离本机目录执行一次无外部副作用的真实轮次及同Session续接；保存真实ID、版本、终态与可见性证据。日常健康检查不重复模型探针。
3. 从独立客户端进程而非本聊天工具调用原会话；Codex须实际桌面可见，Claude须在claude --resume列表可见，九问须在原生用户历史可见。
4. 记录认证方式、组织政策、启动参数、工作目录、扩展重载条件；预检只代表通道及配置证据，真实推理／活动回投／历史可见分别报告。
5. 按宿主分别交付精确调用、适用条件和失败回执；必需能力无公开可行通道时阻塞该宿主及依赖切片，带可选方案向用户提问。其他已验证切片可继续，36不整体通过；不自行降级成新会话、后台日志或等待下次Skill调用。
