## 已有基础与剩余差距

已有三宿主适配和probe/run/cancel入口；客户端16、17及实施资料保存了部分真实轮次、同Session续接、取消、产品启动和Codex业务闭环记录。这里复用输入、版本及适用条件仍有效的证据，不重写适配器，也不把这些记录升级为原活动会话投递成功。

| 宿主 | 已有基础 | 本票剩余核实 |
|---|---|---|
| Claude Code CLI | Agent SDK后台执行、真实Session续接和取消；产品双角色启动记录 | 独立客户端活动原会话投递、关闭后恢复、claude --resume可发现及继续；Channels认证、组织和重载条件 |
| Codex桌面 | 独立stdio App Server适配、真实工具轮次／续接及产品业务记录 | 连接实际桌面会话的公开通道、活动／空闲投递、原生历史可见；当前run拒绝active线程 |
| Windows九问 | Process适配、网页原生会话／历史通知扩展 | Windows原聊天投递、外部独立会话的用户／渠道归属、真实模型处理及原生继续 |

三宿主五项能力按宿主分别登记证据、版本、认证和限制。某宿主必需能力无可行公开通道时，阻塞其适配及依赖该能力的工作；其他已验证宿主的独立切片可继续，36整体门禁保持未通过。共用契约只采用已核实能力。

## 实现方案

1. 以仓内适配器与当前安装SDK为起点，按官方公开接口逐项建立能力矩阵；九问使用Process查询与原生Web扩展，Claude使用Agent SDK及适用的Channels，Codex核桌面实际连接与App Server公开入口。
2. 先执行不调用模型的预检，再在隔离本机目录执行一次无外部副作用的真实轮次及同Session续接；保存真实ID、版本、终态与可见性证据。日常健康检查不重复模型探针。
3. 从独立客户端进程而非本聊天工具调用原会话；Codex须实际桌面可见，Claude须在claude --resume列表可见，九问须在原生用户历史可见。
4. 记录认证方式、组织政策、启动参数、工作目录、扩展重载条件；预检只代表通道及配置证据，真实推理／活动回投／历史可见分别报告。
5. 按宿主分别交付精确调用、适用条件和失败回执；必需能力无公开可行通道时阻塞该宿主及依赖切片，带可选方案向用户提问。其他已验证切片可继续，36不整体通过；不自行降级成新会话、后台日志或等待下次Skill调用。
