# 01：常驻入口不反向导入角色

**目标行为：** 共用运行时的代码不再导入个人助手端或服务方端：`ioalab-access serve` 由归属角色一侧的装配入口把 `AssistantRole`、`ProviderRole` 注入 `ResidentRuntime`，`validate`、`configuration`、`configure` 所需的服务方配置校验与可改字段同样由装配方作为参数传入；命令行为、退出码、`python -m ioalab_sdk.runtime` 与 `ioalab-access` 的既有调用保持不变，`tools/check_modules.py` 不再报 共用运行时 → 个人助手端、服务方端 的依赖。现状：`runtime/__main__.py` 的 `serve` 直接 `from ..assistant.role import AssistantRole`、`from ..provider import ProviderRole`；`validate_roles` 与 `setup_command` 导入 `provider.configuration` 的 `validate_provider`、`EDITABLE_SERVICE_FIELDS`，宿主适配又从 `__main__` 反向取用 `validate_roles`，依赖图出现 共用运行时 → 两角色 的环。

**阻塞于：** 无

**状态：** ready

**范围：** 共用运行时（`runtime/__main__.py`），个人助手端与服务方端的入口，宿主适配 `ioalab_jiuwen/__main__.py`。方案：`setup_command` 的 `service_fields` 改为必传参数、`validate_roles` 移到服务方端入口（或拆为两角色各自的校验函数由装配方组合）；`serve` 的角色装配移到不属于共用运行时的 SDK 装配入口，`pyproject.toml` 的 `ioalab-access` 与 `-m ioalab_sdk.runtime` 的消费者（`_shared/ioalab.py`、`deploy/`、`tools/smoke.py`、`tools/verification/`、测试）按展开、迁移、收口三步切换，收口时删除旧路径，不留别名。新入口的归属先在 `tools/check_modules.py` 的 MODULES 与[架构](../../../架构.md#模块表)登记。需读[共用运行时 接口](../共用运行时/接口.md#本机生命周期与调用)、[依赖](../共用运行时/依赖.md)与[实现](../共用运行时/实现.md#入口)。

**定向测试：** access_products、configuration_boundary、configuration_edit、installation_identity、resident_runtime、package_installation、cli_encoding

- [ ] `src/access/sdk/ioalab_sdk/runtime/` 中没有对 `assistant`、`provider` 的导入
- [ ] `serve`、`start`、`validate`、`configure` 的输出与退出码不变；受管部署与产品技能的调用路径同步
- [ ] 共用运行时 依赖页删除两角色行，实现页入口与已知偏离同步
