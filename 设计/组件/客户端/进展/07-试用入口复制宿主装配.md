# 07：试用入口复用宿主常驻装配

**目标行为：** 在线试用的参与方进程与 `python -m ioalab_jiuwen serve` 经同一装配函数取得工具、宿主、两角色模块与常驻运行时，两处探测、启动与关闭顺序一致，网页通知的 notifier 注入也只在一处；试用只在其外增加可信用户确认服务。现状：`src/trial/ioalab_trial/sdk_entry.py` 逐行复制了 `ioalab_jiuwen/__main__.py` 的 `serve` 装配（`ConfiguredTools`、`ProcessHost.from_config`、`AssistantRole`、`ProviderRole`、`ResidentRuntime`、`probe`、`tools.start`、逆序关闭），且缺少 `host.notifier` 注入，两条装配链会继续分叉。

**阻塞于：** 无

**状态：** ready

**范围：** 宿主适配与在线试用。宿主适配在入口文件中提供一个装配函数（返回运行时、宿主与工具，或以上下文管理器负责关闭），`serve` 与 `sdk_entry` 都改调它，删除复制的装配代码；装配函数须进[实现](../宿主适配/实现.md#入口)的入口表。需读[宿主适配接口](../宿主适配/接口.md#命令行)与[本地业务工具装配](../宿主适配/接口.md#本地业务工具装配)。

**定向测试：** configuration_edit、business_tools、trial_bridge、trial_processes

- [ ] `sdk_entry.py` 不再直接构造 `ConfiguredTools`、`ProcessHost`、角色模块与 `ResidentRuntime`
- [ ] `serve` 与试用入口的探测失败、启动与关闭顺序由同一函数保证
- [ ] 入口表与在线试用依赖页同步更新，`tools/check_modules.py` 通过
