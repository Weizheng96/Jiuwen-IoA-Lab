# 22：固定消息转发与按发送方收信

**目标行为：** 已知对方账号时，任何认证账号均能向固定“消息转发”接口发自然语言文本；SDK直接转入接收者所属宿主按发送方分组的会话，完全不运行模型，回执可恢复。
**阻塞于：** 21
**状态：** ready（待设计细化与实现，功能未实现）
**范围：** 个人助手端、共用运行时、三宿主适配，消息中心与web服务的固定收信接口契约；[方案](../../../工程/专题/个人助手公开发现与消息转发.md)。实施先更新唯一归属接口页、不变量与设计版本，不复制另一套投递引擎。
**定向测试：** agent_delivery、assistant_role、runtime_delivery、runtime_scheduling、web_notifications、native_web_delivery、codex_host；新增固定转发/Claude回归并登记到所属接口页。

- [ ] 用户确认固定收信目标和面向所有现有/未来认证账号开放；认证来源不可自报，匿名及冒名拒绝
- [ ] 固定接口只接受1—2000码点纯文本，不接受任意目的会话/URL/脚本/工具；危险格式按文本呈现
- [ ] 确定性处理器沿现有消息租约、当前启停校验、调度和幂等入口执行；普通host.run与模型选工具调用次数为零
- [ ] 同一发送账号跨新交互、断连重启和显示名修改仍进入同一收信会话；不同发送方隔离
- [ ] 三宿主分别通过固定目标、实际会话可见、来源展示、被动接收不启动模型的验收
- [ ] 收到、查看、恢复与重投均不触发模型；来信不注入其他业务会话或正在运行的轮次
- [ ] 队列满、超长、过期、资源未就绪均有确定性拒绝/状态，不能以模型兜底
- [ ] 重复消息与丢回执不重复写入，创建/写入未知查原结果；queued与session_received分开，发送方看不到原生Session ID
- [ ] 普通已授权收信规则仍保持原行为，固定接口不可被替换为模型处理正文
