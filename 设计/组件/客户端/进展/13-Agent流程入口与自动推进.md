# 13：Agent流程入口与自动推进

**目标行为：** 委托交易、助手通信、服务发布与接单管理各提供一个 Agent 流程入口，九问 Swarm 只提交业务输入及原流程引用；客户端连续推进确定性步骤，在需要业务判断、补充输入、真实确认或外部等待时返回明确下一步，避免九问自行推导底层接口顺序。服务方完成本期交付后主动推送进展，个人助手自动续接原委托流程、取件并展示成果，无需用户再次询问进度。

**阻塞于：** 无

**状态：** claimed（开发中；流程入口、后台取件与本机测试已落地；原用户会话关联及完整实机验收未完成，待用户指令集中部署）

**验收环境：** 与[客户端12](12-一句话接入与账号引导.md)独立设计和开发，最终组合验收使用[当前验收入口](../../../工程/实施资料/部署发行.md#当前验收入口)。

**范围：** 个人助手端、服务方端、共用运行时[操作目录](../共用运行时/接口.md#装配与常驻实例)、[调用与启动](../共用运行时/接口/调用与启动.md)、[本地执行与恢复](../共用运行时/接口/本地执行与恢复.md)、[用户确认](../共用运行时/接口/用户确认.md)及两角色产品技能；平台依赖以[委托交易](../../../流程/委托交易.md)、[助手通信](../../../流程/助手通信.md)、[服务方接入](../../../流程/服务方接入.md)所链接口为准。跨模块顺序见[专题](../../../工程/专题/接入易用性与Agent调用效率.md)。

**定向测试：** assistant_flow_guidance、operation_catalog、access_products、user_confirmations、protocol_operations、inbox_rules、service_publication、task_recovery_receipts、resident_fulfillment、resident_multiperiod、runtime_delivery；定稿后补流程推进、交付推送触发取件、断点续接与效率对比用例。

## 现状与初始方案

本轮已实现三个Agent流程入口，原确定性操作、异步作业和确认沿原标识续接；产品技能按业务动作与flowRef调用。现行契约见[Agent流程](../个人助手端/接口/Agent流程.md)及[服务管理](../服务方端/接口/配置与管理.md#agent管理流程)，调用图和本机证据见[验证记录](../../../工程/实施资料/Agent流程本机验证.md)。尚无同场景原生模型分阶段耗时基线，不宣称原生耗时或token改善。

交付续接的代码核查现状：服务方 `provider.task.deliver` 在取得签4/5后，通过原委托交互推送 `a2c.result` 任务快照；个人助手 SDK 后台收件，`assistant.delegation.status` 可从已验签快照读取 `availablePeriods`，再经 `fetch` 取件。本轮新增交付观察：经flow成约并开工的合同，在原委托进展验签后登记稳定期次待办，后台取件、保存文件、WASM预览并调用既有owner.notify；原用户会话关联尚未接通，目前通知按交互分组，不能计为原会话续接完成。未完成真实两端的通知续接验收；本机替身不计为实机闭环。

1. 固定需求、模型/宿主、服务及版本，测量原生 Skill 读取次数、工具/SDK调用次数、模型轮次、输入输出量及总耗时；区分模型判断、网络、生产、用户等待，保存调用顺序、重试原因及各阶段耗时。
2. 逐步分析三类交互的输入、效果、自动推进条件和等待点；每类只向 Agent 提供一个稳定流程入口，以业务动作和原流程引用启动、补充、观察及恢复。助手通信包含发信、多轮交流及收信设置；服务方包含发布与接单管理，入站本单执行仍由可信运行时调度。
3. 确定性编排归所属角色模块，共用运行时持久化进度并调度恢复；复用原平台接口和 A2C 实现，不建立第二套协议或执行链。底层原子操作按职责保留在内部或诊断面，不以兼容别名增加 Agent 学习负担。
4. 客户端自动处理已确定对象的查询与引用传递、校验、已授权动作的连续调用、结果接收和状态收敛；批量步骤有界。模型无需逐个搬运签名、协议字段和操作标识，也无需为了确定下一接口而新增推理轮次。
5. 业务匹配、规格拟定、候选比较和选择、成果判断等语义工作保留模型或用户决定；返回必要业务证据和明确待办，不用硬编码选择替代判断，不用摘要替代合同及验收器的必要审阅。
6. 回执统一表达稳定流程引用、真实状态、完成摘要、等待原因、所需字段及格式、继续方式；客户端推进到下一个实际等待点再返回。异步任务由后台或推送续接，给出查询时机，避免模型高频轮询和重复读同一说明。
7. 需要批准时准备真实待确认事项并打开现有可信入口，真实决定后恢复原流程；保持任务授权、具体合同、合同环节、验收及付款边界。拒绝、过期及未知结果按原语义处理，不换操作标识绕过。
8. Skill 只保留流程入口、业务输入、等待与恢复说明。与[客户端12](12-一句话接入与账号引导.md)联调接入后的业务使用；不纳入尚未实现的委托分解和悬赏。

### 交付通知与自动取件续接

本项细化第6项，纳入同一委托流程入口；涉及[宿主适配](../宿主适配/接口.md)的九问会话续接，平台投递与协议依据继续复用[消息中心](../../平台/消息中心/接口.md)和[履约调用](../共用运行时/接口/A2C适配.md#履约调用)。

1. 服务方完成本期真实交付并取得签4/5后，沿原委托交互主动推送进展。个人助手核验原参与方、合同、期次及签名后，持久化可恢复的本期取件待办；外来消息正文不作为执行指令，不另建助手通信交互或要求用户发布收信接口。
2. 客户端按原流程引用自动续接已授权的确定性步骤，完成取件、保存本机副本及本地验收预览；需要解释成果或请求用户判断时，由宿主唤起或续接对应九问会话，展示真实文件路径、报告及下一步。无需用户再次发言或模型高频查询来发现交付；后台取件与语义处理的职责在实施前明确到所属接口页。
3. 交付已通知、SDK已收件、文件已领取、验收报告及用户确认接受分别记录。取件涉及签6，沿原协议保存签收及缓存；本地验收预览不替代用户独立确认，不自动签7或付款。多期合同逐期续接，保持原期次顺序、付款前提及独立确认。
4. 重复或乱序推送、断线、ACK丢失及两端重启恢复原待办、作业、签名和文件，避免重复取件签收或重复展示同一待办；结果未知先核原回执。离线时在有效期内补投和恢复，不能唤醒已关机设备；宿主不可用时保留待办并给出明确等待状态。已解除、裁定或不再允许履约的合同按原状态收敛，不因迟到交付重新开工或取件。
