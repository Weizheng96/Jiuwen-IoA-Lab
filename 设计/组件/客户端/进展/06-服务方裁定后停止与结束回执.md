# 06：服务方裁定后停止新履约与结束回执

**目标行为：** 服务方收到平台系统消息 `contract.ruling` 或启动恢复时查到已裁定案件后，核市场签名与原 case/admission/subject，停止本卡新的生产轮次与 anchor、card.close，等待原写入者收敛后提交 `arbitration.finish` 结束回执；回执未知时恢复原操作，未收敛时保留占用。

**阻塞于：** 无（结束回执的平台侧入口见平台进展的“裁定后执行结束回执”票）

**状态：** ready（开发中，与当前设计有偏离）

**范围：** 服务方端。现状：`execution.py` 的扫描只处理 `delegation.intent` 与 `a2c.request`，不处理 `contract.ruling`；新宿主轮次前不读取当前案件（共用运行时 `adapters/arbitration.py` 的 `require_open` 无调用方）；`termination.py` 只覆盖解除与结清。修复方案：在扫描与生产排程前读取当前案件，已裁定则停止新轮次；排空沿用 `Termination.writers` 的方式，结束回执作为新的 `provider.*` 控制作业提交。平台侧 `arbitration.finish` 尚未实现，先完成停止部分。需读[接单与任务恢复](../服务方端/接口/接单与任务恢复.md#仲裁操作)、[A2C适配](../共用运行时/接口/A2C适配.md#仲裁与原执行结束)与[委托中心 仲裁](../../平台/委托中心/接口/仲裁.md#裁定执行与容量收尾)。

**定向测试：** arbitration_processing、resident_termination

- [ ] 收到裁定后不再排新生产轮次，已开始轮次按实际写入者收敛
- [ ] 进程重启后经案件查询恢复停止状态，不依赖通知仍在 TTL 内
- [ ] 平台入口就绪后提交结束回执并恢复原操作
