# 25：好友模块与申请确认页面联动

**目标行为：** 三种宿主的客户端均能查看好友、发起/查看申请及删除好友；收到申请时提示并打开平台确认页，用户明确同意/拒绝后显示真实结果，离线恢复不丢待办或自动同意。
**阻塞于：** 外组前置，见下文
**状态：** ready（2026-11-13新增；待设计与实现）
**范围：** 个人助手端、共用运行时、三宿主通知/打开入口、产品Skill与平台确认页联动；[方案](../../../工程/专题/个人助手公开发现与消息转发.md#好友关系与真实确认)。
**定向测试：** user_browser、user_confirmations、trusted_user_port、agent_flows、assistant_flow_guidance、frontend、web_notifications、codex_host；新增好友模块和三宿主页面联动专项。

## 外组前置

[平台15](../../平台/进展/15-双向好友申请确认与默认admin关系.md)提供好友申请、平台可信确认页及状态查询。

- [ ] 好友模块显示当前好友、认证账号、待处理申请和真实状态；初次接入普通账号仅见默认admin关系，不能靠本地改缓存扩大权限
- [ ] SDK/Skill支持向精确账号申请、查询原申请、删除好友；操作稳定幂等、来源来自登录账号，不以可变显示名猜目标
- [ ] 被申请者收到独立控制待办，三宿主分别真实提示并打开平台确认页；不借普通来信模型决定同意，不把后台日志或通知排队当页面已出现
- [ ] 同意/拒绝仅在本人平台认证页面执行；客户端只读取已确认状态，模型、RPC、A2UI文字与发送方输入不能持有批准凭据或代点同意
- [ ] 页面被关、客户端离线、未登录、打开失败均保留待处理；恢复/重投复用原申请且不重复建关系或反复弹同一待办
- [ ] 删除好友明确说明双向解除；admin可删除且不会重启自动加回；后续好友模式消息被拒绝，历史记录保留
- [ ] 好友模块与能力公开独立：不公开也可精确申请和通信；搜索只是取得目标，不能自动添加好友
- [ ] 九问、Codex、Claude原生提示/页面打开/人工真实确认逐项取证；任何宿主缺项不以脚本确认代验
