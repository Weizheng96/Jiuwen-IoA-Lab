# 05：服务方仲裁申请与案件查询

**目标行为：** 本机服务方所有者对所属服务的原任务调用 `provider.dispute`（profile、原 taskRef、ground、必要 period 与材料引用），SDK 从本单记录确定 admissionId，取得取证预览并独立请求用户确认后提交原 `arbitration.request`，返回平台 caseRef 与受理回执；`provider.dispute_status`（profile、caseRef）返回已验签的原案件与裁定；同操作重传恢复原案件，不创建第二份。

**阻塞于：** 无

**状态：** ready（开发中，与当前设计有偏离）

**范围：** 服务方端。现状：[接单与任务恢复](../服务方端/接口/接单与任务恢复.md#仲裁操作)定义了两项操作，但 `ProviderRole.bind` 未登记，`src/access/sdk/ioalab_sdk/provider/` 无任何仲裁代码；共用运行时 `adapters/arbitration.py` 的 `read_case`、`verify_case` 尚无调用方。修复方案：在 `publication.py` 的操作表增加两项，复用共用运行时的案件读取与验签和[用户确认](../共用运行时/接口/用户确认.md#用户确认)，不另建服务方仲裁引擎。需读[web服务 仲裁接口](../../平台/web服务/接口/仲裁接口.md#仲裁接口)与[委托中心 仲裁](../../平台/委托中心/接口/仲裁.md#争议案件与原证据)；若个人助手端同类入口一起实现，共用部分落在共用运行时。

**定向测试：** arbitration_cases、arbitration_evidence

- [ ] `provider.dispute` 经真实确认提交并返回 caseRef；拒绝或过期不提交
- [ ] 同 operationId 重传恢复原案件；异参数 id_conflict
- [ ] `provider.dispute_status` 只返回所属服务案件并验签裁定
- [ ] 接口页仲裁行补测试列并删除票据链接
