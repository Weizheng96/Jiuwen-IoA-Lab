# 23：公开能力接入与找人通信引导

**目标行为：** 三种宿主的用户通过个人助手Skill完成自愿公开、描述修改、撤回，以及“寻找有某能力的人→选择账号→发送自然语言消息”；接收者无需操作即可在收信会话看见原文，人工查看不自动调用模型。
**阻塞于：** 22
**状态：** ready（待设计细化与实现，功能未实现）
**范围：** 个人助手产品Skill、SDK流程目录、接入配置和本人公开状态展示；[方案](../../../工程/专题/个人助手公开发现与消息转发.md)。不增加专用“让模型处理来信”按钮或复杂人员门户。
**定向测试：** agent_flows、assistant_flow_guidance、access_products、configuration_edit、frontend、workbench_rendering；新增公开/找人引导覆盖并登记。

## 外组前置

[平台公开与发现](../../平台/进展/13-个人助手根目录公开与能力发现.md)及[更新撤回恢复](../../平台/进展/14-公开档案更新撤回与故障恢复.md)已经提供完整公开契约。

- [ ] 首次接入可跳过公开；已有用户可主动公开，未批准不上传描述，不扫描本地Skill自动生成公开档案
- [ ] 展示100字计数、真实公开摘要、认证来源与所有账号可发消息的边界，用户无需手写Schema
- [ ] 三宿主固定目标和投递能力逐项核验，缺项明确停止，不能以安装成功或后台模型可用冒充可收信
- [ ] 找人进入个人助手namespace，服务采购仍走现有委托流程；不要求为找人签合同或授权付款
- [ ] 候选包含真实账号与摘要，用户选择后重读固定接口及当前修订；无匹配不猜账号，不随意发送给第一名
- [ ] 修改和撤回沿稳定operationId恢复，100字超限、修订冲突及未知结果给出准确下一步
- [ ] 发送、排队、会话接收和已读分开展示，不向发送者返回私有会话/配置；接收者可人工查看来源与原文
- [ ] 主动让模型处理仍由用户自行提出需求，转发组件不自动总结、回复、处理正文或升级权限
