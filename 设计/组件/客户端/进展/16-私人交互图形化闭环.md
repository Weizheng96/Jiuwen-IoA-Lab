# 16：私人交互图形化闭环

**目标行为：** 用户表达发布收信接口或联系对方的意图，界面引导补充信息，经校验、预览和所需确认后发布或发送，并完成多轮交流与结束；字段由通用 Schema 驱动。

**阻塞于：** 12、13、15

**状态：** ready

**验收环境：** 真实宿主、本地客户端和[新服务器验收基线](../../../工程/实施资料/部署发行.md#新服务器验收基线2026-11-11)，同时覆盖浏览器与无 Apps 路径。

**范围：** [个人助手端](../个人助手端/接口.md)、[助手通信与收信规则](../个人助手端/接口/助手通信与收信规则.md)、[共用运行时](../共用运行时/接口.md)、[消息中心](../../平台/消息中心/接口.md)、[注册中心](../../平台/注册中心/接口.md)及本地 MCP/UI；流程见[助手通信](../../../流程/助手通信.md)，总体见[专题](../../../工程/专题/接入易用性与Agent调用效率.md)。

**定向测试：** inbox_rules、rule_boundaries、model_messaging、user_confirmations、operation_catalog、assistant_flow_guidance；后续补通用表单、接口维护、多轮及页面恢复用例。

## 待实施方案

本轮只登记方案；后续先细化唯一归属接口和流程并按 design 升版，再实现。

1. 定义消息服务表单：名称/标识、用途、可使用者、首次输入 Schema、附件限制、本地处理方式与回复要求；明确公开字段和仅保存在本地的指令、工具权限。
2. 支持自然语言拟稿、用户编辑、有效/无效示例校验、具体版本预览确认和发布；支持更新、启用/停用与未知提交恢复。
3. 从对方的已发布接口发现允许使用的能力，按实际 Schema 采集、校验和预览接收方及消息；发信、多轮补充和结束关联原交互。
4. 页面放在 `messaging/`，目录发现复用 `registry/`，跨页导航放在 `flows/interaction/`；这些是拟定逻辑目录，业务仍由个人助手 SDK 编排。
5. 消息投递、权限、格式校验及本地执行复用原 HTTPS/WSS 和收信链路；外部消息不可借表单触发配置修改、服务发布或任意工具执行。
6. MCP App、浏览器及 Skill/CLI 使用同一操作、状态和恢复引用；会议只是一个示例，不将日程或邀请工具写入通用 SDK。

## 验收项

- [ ] 用户从“帮我定义一个接口”完成拟稿、补充、预览确认、发布、更新和停用；权限及公开/本地字段边界正确
- [ ] 会议与另一种非会议输入使用同一表单机制，无需新增场景专用业务逻辑
- [ ] 从接口发现到首次发送、多轮、结束形成真实闭环，未授权或格式错误请求被正确拒绝
- [ ] 无 Apps 时完成同一闭环；关页、断线、重复点击和重启恢复原操作，无重复发信或执行
- [ ] 真实确认、入站执行与管理权限分离；平台/宿主版本、调用回执、恢复证据及未验证范围齐全
