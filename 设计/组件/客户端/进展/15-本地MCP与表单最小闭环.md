# 15：本地 MCP 与表单最小闭环

**目标行为：** 宿主已有 MCP Client 连接随 IoA 客户端安装的本地 MCP Server，通过公共客户端操作打开表单、校验草稿并读取真实结果；已有账号可先完成最小闭环，后续接入和业务页面复用同一机制。

**阻塞于：** 无

**状态：** ready

**验收环境：** 本地宿主与客户端、新服务器；实际基线见[部署发行](../../../工程/实施资料/部署发行.md#新服务器验收基线2026-11-11)。

**范围：** [共用运行时](../共用运行时/接口.md)、[用户确认](../共用运行时/接口/用户确认.md)、[宿主适配](../宿主适配/接口.md)、[SDK装配](../SDK装配/接口.md)、接入包及[平台web服务](../../平台/web服务/接口.md)。整体决策见[专题](../../../工程/专题/接入易用性与Agent调用效率.md)。

**定向测试：** operation_catalog、resident_runtime、trusted_user_port、user_confirmations、user_browser、jiuwen_host、access_products；后续新增 MCP 协商、工具/资源、浏览器提交、实例绑定与恢复测试，名称在接口定稿时登记。

## 待实施方案

本轮只登记文档。实施前明确新适配模块的代码/设计目录、接口、依赖和测试，更新架构模块表与相关流程并按 design 升版；不把下列目标称为现有能力。

1. 本地 MCP Server 仅提供工具与界面资源适配；配置、账号、业务操作、状态与恢复归客户端公共能力。优先 stdio 薄入口连接所属实例的受控 IPC，单一业务写入者；不新增云端 MCP Server。
2. 定稿工具与资源清单：流程打开、普通字段提交、校验/预览、查询和恢复如何映射现有操作；声明输入输出 Schema、资源 URI、版本、错误、取消和可见性。协议请求编号与业务操作引用分开，不暴露任意本地命令或通用批准工具。
3. 实现能力探测和配套浏览器表单；标准 App 容器通过宿主桥接调用工具，浏览器通过本地受控入口使用同一公共能力。九问首期采用浏览器；A2UI 支持不作为标准 Apps 支持的证据。
4. 用已有账号选择一条可独立核验的草稿、预览和真实确认链路，绑定对象、版本、会话和有效期；复用可信用户确认能力。秘密录入另走受控路径，工具、模型及日志只见脱敏结果。
5. UI 逻辑目录按身份、注册、消息、委托、支付和服务方划分，流程层仅导航；定义页面资源来源、浏览器会话与请求来源校验、重放保护及关闭后的恢复方式。
6. 核验宿主重连、重复启动、关页及重启对原常驻业务的影响；MCP 接口不可用时公共操作仍可由 Skill/CLI 使用。

## 验收项

- [ ] 模块、字段、工具、资源、依赖和失败回执完成设计登记；平台只通过现有公开 web 服务被调用
- [ ] 已有账号在真实宿主完成 MCP 调用、打开浏览器表单、保存/校验、可信确认和读取原操作结果
- [ ] 标准 MCP Apps 使用符合协议的资源与桥接；实际嵌入兼容性按被测宿主记录，不用模拟表单替代声明
- [ ] 无 Apps/关闭页面/换入口可继续原操作；重复启动不会产生第二个业务写入者或重复执行
- [ ] 模型伪造确认、跨会话提交、过期或修改后的对象、重放均不能推进原授权；秘密不进入普通 MCP 回执
- [ ] 保留现有 SDK、两角色、HTTPS/WSS、宿主执行与确认回归；记录真实宿主版本、结果及未验证范围
