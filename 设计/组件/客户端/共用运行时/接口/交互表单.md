# 共用运行时 · 交互表单

本页是[共用运行时](../接口.md#接口)的子页。公共表单与客户端操作独立于 MCP；CLI、MCP 和受控浏览器通过同一入口访问。

## 公共客户端与表单

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `ClientOperations(config_path).configuration()`、`call(operation,args,operation_id=…)` | 复用 CLI 的配置定位、实例检查及 IPC 调用 | 仅公开配置；业务调用固定已核对的 bootId，保留原 SDK 回执 | 缺实例 not_ready；配置或安装不符拒绝；未知结果保留原标识 | mcp_access、interaction_forms |
| `ClientOperations.confirmation_entry(reference=None)` | 可信呈现适配入口，不是普通业务操作 | 实际origin；等待委托可附限原确认能力，仅送App _meta | 配置/安装/bootId不符拒绝；不创建批准，详见[用户确认](用户确认.md#业务内嵌确认) | mcp_access、user_confirmations、interaction_forms_browser |
| `FormDefinition(kind,title,schema,preview,submit)`；角色 `bind` 返回 `forms` | 由角色注册通用表单 Schema、预览和提交处理器 | 回调使用同一稳定业务 operationId；提交接收已冻结预览 | kind 唯一；Schema 无外部引用；角色负责原效果幂等与恢复 | interaction_forms |
| `runtime.forms.list` | 列出可用表单定义及本机原表单摘要 | 无参数；kind、标题、Schema、reference、状态 | 未装配的角色不出现 | interaction_forms |
| `runtime.forms.open` | 创建或恢复普通字段草稿 | kind、可选 values；reference、revision、values、Schema、phase、preview、result | 同 operationId 异初值 id_conflict；无对应 kind not_ready | interaction_forms |
| `runtime.forms.get` | 读取原表单 | reference | 非本机/不存在的 reference 拒绝；不推进业务 | interaction_forms |
| `runtime.forms.update` | 替换普通字段草稿 | reference、revision、values；revision 递增并清除旧预览 | 修订不符 id_conflict；已提交记录不可改；Schema 校验拒绝不覆盖原稿 | interaction_forms |
| `runtime.forms.preview` | 冻结本修订的真实预览 | reference、revision；由角色生成预览，无批准效果 | 缺字段拒绝；重复请求恢复同一预览；编辑后需重新预览 | interaction_forms |
| `runtime.forms.submit` | 申请效果或续接原业务 | reference、revision；原角色回执及确认引用 | 先持久化提交状态；等待、拒绝、未知和完成均保存，重复调用保持原 operationId；不得创建批准 | interaction_forms |
| `runtime.forms.open_ui` | 打开已有表单的本机页面 | reference；opened 与原引用 | 原表单先核对；不返回浏览器会话或一次性入口秘密 | interaction_forms、user_browser |
| `form_page(mode)` | 提供 SDK 包内的通用表单页面 | `browser` 或 `app`；HTML 与自包含脚本 | 不读取配置或账号；未知模式拒绝 | mcp_access、interaction_forms、interaction_forms_browser |

## 存储与顺序

表单记录在所属实例的运行库检查点命名空间 `forms`，由常驻进程单写。reference 由 runtimeId 与打开操作标识稳定派生；每个修订有独立、稳定的业务操作标识。定义摘要绑定 kind 和 Schema，定义发生不兼容变化时停止提交并要求重新检查，不将旧草稿自动用于新行为。

草稿可不完整，预览前校验全部必填项。预览只准备角色原对象；提交前将修订与预览冻结并落库，再进入角色处理器。已提交的修订不可编辑，结果未知先恢复原引用；不重新生成业务标识。提交进程中断后保留未知状态，继续调用由角色按其恢复契约核对原效果。完成后的重复提交返回原结果。

MCP表单工具与普通RPC可编辑、预览、申请或续接，但不能批准。委托App的独立用户卡片按[用户确认](用户确认.md#业务内嵌确认)经受限直连通道取得决定。原受控浏览器的入口交换、Cookie、Origin、CSRF 和确认绑定机制继续有效；表单页与确认页共享同一实例用户会话，入口令牌只通过系统浏览器启动交付。页面关闭不删除草稿、确认或业务记录。

浏览器 API 只暴露以上固定表单操作，不接受任意 SDK 操作名；表单提交与确认决定分开。App 通过宿主桥接调用同一固定工具，不直接向本地 HTTP 发送跨域请求，不把普通 App 可见性当作可信用户证据。

共享页面逻辑按 `runtime/web/shared/`、`messaging/` 等业务归属组织；角色定义字段和业务回调，页面只展示、提交和导航。业务调度不依赖页面常驻。

## 多阶段业务与首次接入

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `WorkflowDefinition` | 角色提供带阶段的表单定义，复用上述 forms 操作 | 初始 Schema、预览和提交；每步接收已存 context，返回原业务回执及可选 next（Schema、values、context、title） | 每阶段使用独立修订；等待/未知续接原修订；进入下一阶段时保存上一阶段回执，不能自动批准 | interaction_workflows |
| `Onboarding(config_path).submit(values)`、`status()` | 无账号配置时的公共受控接入能力 | submit 仅受控用户页面调用；选择登录/注册、平台与本地身份；status 仅公开阶段与账号摘要 | 先私存原注册参数及 operationId 再发请求；未知不换账号；已有配置不覆盖；同配置接入锁互斥 | onboarding |
| `account_page()` | 提供共享账号页面的 App 版本 | 自包含 HTML，页面直连账号服务，模型不处理秘密 | MCP 协商、限时受控能力与浏览器降级见账号接口 | mcp_access、interaction_forms_browser |
| `account.setup`、`account.setup.status` | Skill/CLI、MCP 打开或查询首次接入 | 无秘密参数；独立短控制服务显示本机受控页面 | 不要求账号/常驻实例；原服务复用，不返回入口令牌 | onboarding |

首次接入的浏览器页面复用 UserUi 的一次性入口、同源会话和 CSRF；内嵌账号页使用[账号与登录](账号与登录.md#内嵌账号接入)的受限直连通道，不将凭据送入 MCP 工具或模型参数。临时控制服务只拥有配置旁的私有接入目录，不打开业务库，不冒充业务常驻实例。账号配置写入后使用原显式登录及启动入口；安装与宿主配置结果、账号已认证、业务已连接分别报告。未核实原注册前不能变更其平台、账号、密码或邀请码。平台拒绝注册时保留拒绝与可纠正原因；自动生成的注册输入在发出之前加密持久化；账号配置只保存设备凭据引用，存储和迁移以[账号与登录](账号与登录.md)为准。

所有表单在 waiting 且绑定确认已离开 pending 后，常驻线程自动续接同一修订与业务操作；pending 不推进，unknown 不自动重试，拒绝/过期按原角色处理，完成不重复执行。普通表单不因 accepted/running 自动重试；多阶段表单仍按下述阶段规则推进。受控浏览器页面轮询只读取，不触发提交；数据未变不重建控件，不打断焦点、滚动或编辑。MCP App 不后台轮询工具，避免反复触发宿主授权；业务仍由常驻实例续接，用户返回后显式刷新原表单。App 的显式浏览器按钮使用[MCP接入](../../MCP接入/接口.md#不变量)定义的导航信息；该信息只在页面内存中处理，不写业务字段、不展示给模型或用户，缺失时提示刷新原表单，不退回自动打开浏览器。App 同时只允许一个工具请求，等待宿主授权或回执时明确显示等待，不以固定等待时长宣称业务结果未知或删除原请求；延迟回执仍更新原操作，实际拒绝/错误按原回执显示，关闭后沿原引用恢复。

多阶段表单保存 context、当前 Schema、各已完成修订的回执。常驻线程只续接 accepted/running，或确认记录已经离开 pending 的 waiting；到新输入阶段停止，unknown 不自动重试。排空/关闭时先停止流程推进，线程未结束不释放实例所有权。旧已完成修订的 preview/submit 返回最新阶段而不重复效果；update 仍严格比较当前修订。

接入页的配置入口只调用原 SDK 非秘密 configure 操作；必须带原 configurationDigest，原实例持锁时拒绝修改。显式停止必须带所见 bootId，保存后仍需核实际宿主与启动。`runtime.connect` 是产品脚本串联安装、账号引导和原启动的入口；`runtime.mcp.configuration`在安装完成后、账号配置前可用，返回本机stdio配置、stage=mcp、nextAction=enable_in_current_chat、accountRequired=false及角色对应setupArguments；不读写账号配置、不启动常驻实例、不冒称宿主已加载。普通聊天接入顺序归[首次账号引导](账号与登录.md#首次账号引导)，runtime.connect不代替宿主连接器挂载。

用户可在同一受控账号页显式查看已保存凭据；该入口接受浏览器同源会话与 CSRF 或账号 App 受限能力认证的 POST，不出现在 MCP 工具、IPC 或普通状态中，页面默认隐藏且可清除。注册政策错误只映射客户端已知的原因，不回显任意远端文字。临时 not_ready 保留原提交为 waiting，可手动续接；不将等待当成终局拒绝。

共享表单保存反馈：内嵌和浏览器页面均在操作按钮区域以可访问状态提示显示正在保存、已保存和无新修改；仅更新回执成功才宣称保存完成。新编辑清除旧成功提示，保存失败保留编辑并显示真实错误；自动保存成功而后续预览失败时分别报告。无改动点击不重复写入、不递增修订；保存反馈不代表预览、提交或用户批准。

处理中回执说明当前正在等待业务结果，刷新仅查询；unknown 明确停止自动推进并要求核对原任务，不能仅显示处理中或建议新建业务。

工作流可提供只读 recover 回调。runtime.forms.recover(reference,revision) 仅将已拒绝/失败的原修订转为角色核定的恢复选择，不执行新业务；保留原失败历史并递增修订，重复原修订返回当前表单。get 暴露 canRecover 提示但不推进。共用页面对错误回执直接展示原因，过期提示不藏在原始JSON内。测试：interaction_forms、proposal_expiry。

带confirmationRef且data.reason=expired的工作流终局回执可进入角色核定的显式恢复；页面明确显示“确认已过期”与“重新申请验收确认”，不误标报价过期。不将用户拒绝、取消或未知结果当作过期恢复。

工作流可提供纯展示回调 `presentation(context)`：仅从已存 context 的副本生成 choices（字段名→原枚举值→显示标签）及展示摘要。读取时附加 presentation，并仅替换对应枚举的 enumNames；枚举值、校验约束、修订、冻结预览、批准绑定和业务状态均不变，不访问网络、不写业务。已有表单无需重建即可获得新标签。测试：interaction_forms、interaction_workflows。

修订冲突时保留未保存输入，禁止继续向旧修订保存或提交；刷新入口明确改为“加载最新版本”，只读获取同一reference，不再要求先保存。加载后将本页未保存内容留作核对副本，不自动合并、保存、预览或提交；用户依据新阶段重新填写。副本只在当前页面内存，关闭或重载网页会清除。

工作流展示投影可声明 `directActions`（action枚举值→按钮文字），仅用于不需要独立用户批准的角色动作；页面只在当前可编辑阶段、声明与实际枚举相符时提供一次点击入口。共用页面依序复用原 update/preview/submit，将中间草稿和预览步骤自动完成；不绕过修订校验、Schema、原操作幂等或批准机制，不新增业务执行链。每步核对原引用、修订和动作，阶段已变化即停止，不将新阶段自动提交。没有声明的动作仍显式预览/提交。下载与验收预览可能取件、签收和运行验收器，不称为纯只读，不能代替接受交付或付款批准。

显式刷新在声明了refresh一键动作且当前可编辑、无未保存内容时更新业务状态；等待/未知、修订冲突或需要核实原结果时只get原表单。按钮分别标明“刷新合同状态”和“刷新表单状态”，反馈正在处理、已更新/无变化或真实错误；请求未返回时禁止重复点击。原 get 接口仍不推进业务。浏览器和App共用上述交互。


## 与原生会话来源的衔接

本地MCP/浏览器表单没有通用的可信宿主SID，不接受模型自报会话或伪造原生来源。公共表单owner仅在已保存原表单的预览、提交、恢复回调内建立内部表单来源；新委托保存原form引用并冻结当时默认登记宿主，私人交互沿同一宿主登记器的应用来源绑定。后续恢复使用原任务/交互，不更换已绑定宿主或聊天，也不声称通知已回到发起聊天。原生Skill新业务仍须通过原生包装校验来源；此内部来源不作为公开参数，不降低合同、验收、付款的独立批准要求。两种UI共用相同业务owner和S01执行链。测试：interaction_workflows、native_context_transport。

## 分层呈现与信息补齐

共享App/浏览器以当前阶段为中心：填写只展开缺项、权限与当前选择，已提供的长说明与结构化定义以摘要加编辑折叠展示；预览后收起重复编辑区，可返回修改。检查并继续仅顺序保存当前字段及生成预览，不提交业务或生成批准；提交为另一步。点击检查时即使没有输入事件，也比较页面实际值与原草稿，必要时先保存页面保守缺省和明确的单一身份选择；不自动选服务、报价、支付或扩大权限。规则机器标识可按原表单引用生成稳定候选，明确显示为待核对内容；已有值不覆盖。模型拟稿与用户批准分开，不新增模型填充通道。

摘要由实际字段、Schema标题和已有展示投影生成，不改变原JSON、精度、签名和批准绑定。金额、对象、权限、关键期限及错误保持直接可读，长规则与完整条款可展开；机器编号、哈希与原始回执放高级详情。未知业务字段保持可读，不因未识别而静默丢弃。对方回复、交付与验收结果使用可读内容呈现，并保留完整原始数据。已知嵌套Schema用结构化控件，无法无损结构化的JSON保留高级编辑；必填缺项展开定位，校验仍由原owner执行。

已就绪接入只突出账号、平台与真实连接状态，设备管理和专业配置按需展开；秘密不进入工具或模型。宿主工具批准与业务用户决定分别说明；不因界面简化自动发布、签约、验收、付款或恢复未知效果。页面升级后须验证宿主实际展示，不能仅用read_resource返回新源码作为用户页面已更新的证明。

收信接口的tools不作为用户必填文本框；内嵌与浏览器共用默认收起的“高级设置：自动处理能力”，空选择序列化为[]，含义为仅接收并回复。FormDefinition与WorkflowDefinition均可提供只读presentation；角色从真实已配置工具生成名称/用途，页面用用途说明勾选，不自由输入内部名称。原选中但当前不可用的能力明确标记、原样保留，用户可以取消；模型填充不额外扩大授权，预览与发布仍用原校验和独立确认。呈现数据不参与业务schema摘要，不改写原草稿。测试：interaction_forms、interaction_forms_browser。

只读查询定义QueryDefinition(kind,title,schema,query)复用表单引用及版本校验；open/get/update只查询或保存查询条件，queryOnly标识视图，preview/submit明确拒绝，不进入业务推进器或批准通道。角色经本机store.received_requests(actor,before,limit)有界按收件序号倒序读取；精确对象沿原message(actor,id)复核归属，不建第二收件库。测试：interaction_workflows、interaction_forms_browser。
