# 共用运行时 · 交互表单

本页是[共用运行时](../接口.md#接口)的子页。公共表单与客户端操作独立于 MCP；CLI、MCP 和受控浏览器通过同一入口访问。

## 公共客户端与表单

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `ClientOperations(config_path).configuration()`、`call(operation,args,operation_id=…)` | 复用 CLI 的配置定位、实例检查及 IPC 调用 | 仅公开配置；业务调用固定已核对的 bootId，保留原 SDK 回执 | 缺实例 not_ready；配置或安装不符拒绝；未知结果保留原标识 | mcp_access、interaction_forms |
| `FormDefinition(kind,title,schema,preview,submit)`；角色 `bind` 返回 `forms` | 由角色注册通用表单 Schema、预览和提交处理器 | 回调使用同一稳定业务 operationId；提交接收已冻结预览 | kind 唯一；Schema 无外部引用；角色负责原效果幂等与恢复 | interaction_forms |
| `runtime.forms.list` | 列出可用表单定义及本机原表单摘要 | 无参数；kind、标题、Schema、reference、状态 | 未装配的角色不出现 | interaction_forms |
| `runtime.forms.open` | 创建或恢复普通字段草稿 | kind、可选 values；reference、revision、values、Schema、phase、preview、result | 同 operationId 异初值 id_conflict；无对应 kind not_ready | interaction_forms |
| `runtime.forms.get` | 读取原表单 | reference | 非本机/不存在的 reference 拒绝；不推进业务 | interaction_forms |
| `runtime.forms.update` | 替换普通字段草稿 | reference、revision、values；revision 递增并清除旧预览 | 修订不符 id_conflict；已提交记录不可改；Schema 校验拒绝不覆盖原稿 | interaction_forms |
| `runtime.forms.preview` | 冻结本修订的真实预览 | reference、revision；由角色生成预览，无批准效果 | 缺字段拒绝；重复请求恢复同一预览；编辑后需重新预览 | interaction_forms |
| `runtime.forms.submit` | 申请效果或续接原业务 | reference、revision；原角色回执及确认引用 | 先持久化提交状态；等待、拒绝、未知和完成均保存，重复调用保持原 operationId；不得创建批准 | interaction_forms |
| `runtime.forms.open_ui` | 打开已有表单的本机页面 | reference；opened 与原引用 | 原表单先核对；不返回浏览器会话或一次性入口秘密 | interaction_forms、user_browser |
| `form_page(mode)` | 提供 SDK 包内的通用表单页面 | `browser` 或 `app`；HTML 与自包含脚本 | 不读取配置或账号；未知模式拒绝 | mcp_access、interaction_forms、interaction_forms_browser |

## 存储与顺序

表单记录在所属实例的运行库检查点命名空间 `forms`，由常驻进程单写。reference 由 runtimeId 与打开操作标识稳定派生；每个修订有独立、稳定的业务操作标识。定义摘要绑定 kind 和 Schema，定义发生不兼容变化时停止提交并要求重新检查，不将旧草稿自动用于新行为。

草稿可不完整，预览前校验全部必填项。预览只准备角色原对象；提交前将修订与预览冻结并落库，再进入角色处理器。已提交的修订不可编辑，结果未知先恢复原引用；不重新生成业务标识。提交进程中断后保留未知状态，继续调用由角色按其恢复契约核对原效果。完成后的重复提交返回原结果。

MCP App 与普通 RPC 可编辑、预览、申请或续接，但不能批准。原受控浏览器的入口交换、Cookie、Origin、CSRF 和确认绑定机制继续有效；表单页与确认页共享同一实例用户会话，入口令牌只通过系统浏览器启动交付。页面关闭不删除草稿、确认或业务记录。

浏览器 API 只暴露以上固定表单操作，不接受任意 SDK 操作名；表单提交与确认决定分开。App 通过宿主桥接调用同一固定工具，不直接向本地 HTTP 发送跨域请求，不把普通 App 可见性当作可信用户证据。

共享页面逻辑按 `runtime/web/shared/`、`messaging/` 等业务归属组织；角色定义字段和业务回调，页面只展示、提交和导航。业务调度不依赖页面常驻。

## 多阶段业务与首次接入

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `WorkflowDefinition` | 角色提供带阶段的表单定义，复用上述 forms 操作 | 初始 Schema、预览和提交；每步接收已存 context，返回原业务回执及可选 next（Schema、values、context、title） | 每阶段使用独立修订；等待/未知续接原修订；进入下一阶段时保存上一阶段回执，不能自动批准 | interaction_workflows |
| `Onboarding(config_path).submit(values)`、`status()` | 无账号配置时的公共受控接入能力 | submit 仅受控用户页面调用；选择登录/注册、平台与本地身份；status 仅公开阶段与账号摘要 | 先私存原注册参数及 operationId 再发请求；未知不换账号；已有配置不覆盖；同配置接入锁互斥 | onboarding |
| `account.setup`、`account.setup.status` | Skill/CLI、MCP 打开或查询首次接入 | 无秘密参数；独立短控制服务显示本机受控页面 | 不要求账号/常驻实例；原服务复用，不返回入口令牌 | onboarding |

首次接入的受控页面复用 UserUi 的一次性入口、同源会话和 CSRF；不将凭据送入 MCP App 或模型参数。临时控制服务只拥有配置旁的私有接入目录，不打开业务库，不冒充业务常驻实例。账号配置写入后使用原显式登录及启动入口；安装与宿主配置结果、账号已认证、业务已连接分别报告。未核实原注册前不能变更其平台、账号、密码或邀请码。平台拒绝注册时保留拒绝与可纠正原因；自动生成的注册输入在发出之前加密持久化；账号配置只保存设备凭据引用，存储和迁移以[账号与登录](账号与登录.md)为准。

所有表单在 waiting 且绑定确认已离开 pending 后，常驻线程自动续接同一修订与业务操作；pending 不推进，unknown 不自动重试，拒绝/过期按原角色处理，完成不重复执行。普通表单不因 accepted/running 自动重试；多阶段表单仍按下述阶段规则推进。页面轮询只读取，不触发提交；数据未变不重建控件，不打断焦点、滚动或编辑。

多阶段表单保存 context、当前 Schema、各已完成修订的回执。常驻线程只续接 accepted/running，或确认记录已经离开 pending 的 waiting；到新输入阶段停止，unknown 不自动重试。排空/关闭时先停止流程推进，线程未结束不释放实例所有权。旧已完成修订的 preview/submit 返回最新阶段而不重复效果；update 仍严格比较当前修订。

接入页的配置入口只调用原 SDK 非秘密 configure 操作；必须带原 configurationDigest，原实例持锁时拒绝修改。显式停止必须带所见 bootId，保存后仍需核实际宿主与启动。`runtime.connect` 是产品脚本串联安装、账号引导和原启动的入口；`runtime.mcp.configuration` 只返回本机 stdio 启动配置，不冒称宿主已加载。

用户可在同一受控账号页显式查看已保存凭据；该入口只接受同源会话与 CSRF 的 POST，不出现在 MCP、IPC 或普通状态中，页面默认隐藏且可清除。注册政策错误只映射客户端已知的原因，不回显任意远端文字。临时 not_ready 保留原提交为 waiting，可手动续接；不将等待当成终局拒绝。
