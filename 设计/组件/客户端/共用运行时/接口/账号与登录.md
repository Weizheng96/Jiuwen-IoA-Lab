# 共用运行时 · 账号与登录

## 公共操作

### 首次账号引导

| 操作 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|
| 产品脚本 `account.setup` / SDK `account-setup` | 外置配置路径、可选非秘密参数文件（platform_url、role）；角色由所选Skill绑定为assistant或service，参数不允许覆盖绑定角色；后台打开本机账号页，快速返回waiting | 缺省平台为https://120.46.80.150，原配置或明确参数优先；先5秒公开API探测，失败返回stage=platform/ask_platform_url后才询问地址；已有配置保留平台、账号、data_dir、身份与宿主；同一账号页重复调用复用，不另起常驻实例 | account_setup、access_products |
| `account.setup.status` / SDK `account-setup-status` | 原配置路径；只返回账号阶段和脱敏认证结果 | 不输出密码、令牌、邀请码、浏览器入口或CSRF；completed不代表宿主或业务就绪 | account_setup |

本机账号页复用用户确认页的回环Host、同源Origin、一次性入口、HttpOnly会话与CSRF保护；无需已登录账号、角色或常驻实例。提供已有账号、帮我注册、取消均由本机用户选择。提交持client.lock，与登录、配置及常驻实例互斥；不自动停止持锁实例。页面独立短期存活，超时关闭；关闭不清除原操作。账号设置与安装、宿主配置、连接、角色能力分别核验。

首次配置草稿随原账号操作私有保存，中断后复用原平台与角色；账号认证通过后才原子保存外置配置。有效登录态复用时保留原密码或环境变量引用，不把未经密码登录验证的新输入覆盖到原凭据；已知拒绝可重新输入，未知登录必须恢复原凭据。取消账号页不要求停止已有常驻实例。

代注册在本机生成随机账号密码，并在请求前原子私有保存账号、凭据、邀请码、平台与operationId；调用平台SDK注册入口取得受限SDK登录态，不再额外发起一次赠币登录。未核实结果保留原输入和操作，重试原注册；明确拒绝后用户可重填邀请码或生成新名，限流和网络错误不换号。已有账号复用显式登录恢复，不向模型传密码。生成凭据只可在受控本机页查看；配置、注册记录与会话均使用所属用户权限保存，模型只获账号与结果。账号变化、配置被外部改写或未知操作不匹配时拒绝覆盖。

全部操作的名称、输入形状、效果、确认与开放范围以[操作目录](../接口.md#装配与常驻实例)为准；下表补充公共操作的输入与输出含义。

账号会话由 SDK 共用模块维护：两角色复用同一账号目录中的凭据缓存和待恢复登录操作；首次调用前先持久化 operationId，响应未知时沿用。有效凭据复用及续用不调用密码登录；明确重新登录才建立新操作，已有未核实登录须先恢复，不能覆盖。失效凭据不妨碍通过受控 account.login 入口显式重新认证。凭据与本地私钥不进入模型参数、状态摘要或日志。服务身份绑定不创建个人助手，身份就绪、连接就绪和可以接单分别报告。

| 操作 | 输入 | 输出 |
|---|---|---|
| `account.login` | 本地账号配置引用、显式登录意图 | 原登录结果或待恢复操作；不向模型返回原密码/令牌 |
| `account.refresh` | 当前有效的本地凭据 | 受限 SDK 凭据更新；不赠币，失效时要求重新登录 |
| `runtime.start` | 本地配置引用、要启用的角色 | 实例、各身份及连接/宿主能力状态；失败原因明确 |
| `runtime.status` | 本地实例引用 | 各角色就绪、连接、队列、等待确认与未核实操作摘要；不暴露凭据 |
| `runtime.stop` | 停止方式及等待条件 | 进程停止或等待已有动作收敛；不删除状态、不声明业务取消 |
| `identity.status` | 本端身份引用 | 当前账号、agentId、角色、公钥绑定及权限摘要 |
| `operations.get` | 原data.reference完整对象：job为kind/id；delivery为kind/agentId/operation/operationId；不以job.reference字符串替代 | 外层status表示查询结果；data内的原作业status才表示业务进展，completed后从data.data读取原产物 |
| `operations.resume` | 同一原reference | 核同一投递/作业；不提供通用模型重跑，未知效果由所属角色恢复 |
| `runtime.open_ui` | 空参数 | 打开本机受控用户页，不返回批准凭据、不表示已批准 |
| `confirmations.get` | 原确认引用 | 等待、同意、拒绝或过期，以及可信答复关联 |

`provider.pause` 只停止接新单；`runtime.stop` 停止进程。两者不得混用。停止或重启不自动取消合同、释放有效承诺或延长协议期限。

## 显式登录恢复

account.login由SDK的短期账号控制入口执行，不是另一个常驻运行时。产品技能将命令交给已安装的SDK；SDK统一读取配置，持同一data_dir的client.lock，只打开账号会话，不加载角色、私钥、业务库、九问或模型。常驻实例仍持锁时明确要求先runtime.stop并核实际释放；不停止别人的实例或并发读写账号库。普通启动不因认证失效自动重新密码登录。

| 当前账号会话 | 显式account.login行为 |
|---|---|
| 有效缓存、无未核实登录 | 在线核账号后复用；不生成新登录操作、不赠币 |
| 缓存失效、无未核实登录 | 明确认证失败后新建一次登录，成功后保存同一账号的新凭据；网络错误或5xx不能触发新登录 |
| 无缓存 | 沿同一会话模块创建一次初始登录 |
| 未核实登录 | 先校验原输入并恢复同一operationId；不换标识，不因重试增加赠币 |
| 已明确拒绝的登录 | 普通启动保持拒绝；再次显式account.login保存原拒绝记录后复用有效缓存或建立一次新登录，允许用户修正账号配置 |
| 输入已改变或原记录无法验证 | 保留原记录并要求检查；不能拿新密码/新账号改写未核实请求 |

登录发送前保存operationId、待恢复阶段及本机HMAC输入摘要；HMAC密钥仅在同一受限账号库中，输入摘要、密钥、密码及令牌均不回传模型。请求仍只含原有username、password、operationId，不新增网络字段。仅401/authenticate明确凭据拒绝保存为rejected；400/invalid_input不推断凭据错误，429/rate_limited保留原操作并返回wait_rate_limit，不自动新建登录或循环重试；超时、断开、5xx、限流、冲突和不可识别响应保留pending，不能据此推定未提交。已提交结果恢复但凭据已经失效时先保留该原结果，再由下一次显式登录开始新操作。

账号绑定是平台、账号名及已知不可变账号ID的共同约束。不可变ID独立保存于账号绑定元数据，不能因单条令牌缓存缺失而丢失原归属。核当前账号、恢复登录或续用时不得把同名但不同ID当作原所有者；拒绝发生在替换缓存或本地身份之前。成功回执仅报告认证、账号、原登录标识和是否新登录，不暴露凭据；重试相同回执不等于又赠币。

SDK CLI采用`ioalab-access login --config <文件>`；两种产品技能均以`account.login --config <文件>`调用，不要求用户填写令牌或账号库路径。account.refresh继续由当前常驻实例经认证IPC处理，使用既有会话续用；失败不回退密码登录，也不赠币。受管实例启动前可由明确部署配置调用同一login入口，不给长期进程添加管理员凭据或额外登录引擎。
