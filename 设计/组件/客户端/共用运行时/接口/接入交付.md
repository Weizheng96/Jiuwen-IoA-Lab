# 共用运行时 · 接入交付

本页是[共用运行时](../接口.md#接口)的子页。

## 持久安装与绑定

新安装默认使用`~/.ioalab/client`作为持久根目录：`env/`只放程序和依赖，`settings.local.json`保存账号及运行配置，`settings.local.data/`保存身份和业务状态，`role-skills/`保存导出包。升级只替换安全停止后的程序，不覆盖配置与数据。已有客户端用其真实解释器和原配置重新导出绑定，不自动搬迁、重注册或启动第二个写入者。

两份产品Skill同时准备。导出脚本绑定同一个客户端解释器与配置绝对路径，只包含非秘密定位信息；调用参数不能改写绑定的角色或配置。配置只由SDK解析；宿主和模型无需知道安装路径或再次输入凭据。绑定目标缺失时明确修复原绑定，不另找账号或自动注册。客户端程序目录和配置/数据目录必须分离。

| 入口 | 行为与结果 | 边界 | 测试 |
|---|---|---|---|
| `ioalab-client skills --output <目录> --config <原配置>` | 同时导出两个绑定相同客户端及配置的ZIP | 不读配置正文、不启动或认证 | access_products、client_onboarding |
| `ioalab-client skills-install --host <宿主> [--config <原配置>]` | Codex默认用户级`~/.agents/skills`，Claude Code默认`~/.claude/skills`，同时安装两角色并核文件；九问导出两包及原生导入步骤 | 未知、修改过或其他客户端的同名目录不覆盖；权限不足返回实际目标和手动指导；导入文件不等于原生加载 | client_onboarding |
| `ioalab-client onboarding --host <调用宿主> [--config <原配置>]` | SDK脱敏查询账号、执行宿主、两角色身份、连接及技能安装状态，输出固定交付摘要和未完成项 | 不返回密码、令牌或私有工具选项，不启动业务 | client_onboarding |

宿主原生安装与实际发现分开核验。新会话实际加载两份Skill并调用原绑定的只读状态入口，验收记录须保留宿主、角色、客户端/配置绑定、安装摘要与该会话引用；更换安装内容后须重新验收。记录归实施资料，程序默认保持待验，不接收自报会话ID作为原生发现证明。脚本被命令行执行只能证明脚本可用，不能自行证明宿主发现成功。无法自动操作的新会话须给用户原生加载和查询步骤，保持待验。

## 角色与多宿主

首次账号创建同时准备assistant与service身份；服务方默认暂停接单且无公示模板，使用入口就绪与专业服务可接单分别报告。已有账号或运行实例保持原身份与政策，缺角色经受控配置入口补充，不能为安装Skill隐式停止或改写活跃配置。

各宿主的两份Skill是调用入口，共用一个客户端、账号、数据及常驻实例；`host.default`选择外部新业务默认登记宿主，新增入口不切换它。反向来信交给已配置执行宿主及原业务会话，通知目标由明确配置的通知工具决定，不绑定首次安装者。九问通知仍按[网页通知](../../宿主适配/接口/九问网页通知.md)配置；其他宿主尚不支持的推送如实报告，不以后台线程冒充当前聊天已收到。统一通知扩展仍归客户端17的待验范围。

## 固定交付摘要

每次接入结束，无论完整或待人工操作，输出`format=ioalab.onboarding/1`的脱敏数据及对应固定顺序中文摘要：

1. 接入状态与待完成事项。
2. 客户端根目录、程序环境、数据目录和实际账号配置路径。
3. 账号名、密码所在配置文件/环境引用及通过绑定Skill的`account.setup`打开本机凭据页的方法；密码仅在受保护本机页面查看，既有登录与生成账号均覆盖。
4. 两角色Skill名称、实际安装/导入路径、安装状态、使用入口与新会话验收状态。
5. 调用入口宿主、后台执行宿主、用户通知通道及限制。
6. 实际平台官网、登录页与“我的智能体”入口；用户使用客户端同一账号密码登录官网，浏览器登录状态与SDK会话分开，不复制令牌。

默认官网为`https://ioalab.openjiuwen.com`，已有平台地址优先。官网下载、注册、配置、文件安装、连接、身份绑定和新会话验收分别报告，不把任一局部状态称为全部接入完成。

同角色导出Markdown及引用保持同份；宿主特定安装位置、入口文字及失败指导由对应hosts包装返回，来源绑定元数据与正文分离。原生实际目录缺失不以环境变量或目录猜测兜底。
