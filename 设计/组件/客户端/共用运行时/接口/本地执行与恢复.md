# 共用运行时 · 本地执行与恢复

本页是[共用运行时](../接口.md#接口)的子页。

## 常驻进程

共用运行时以常驻进程运行在用户设备或服务方环境中，负责连接、可靠收发、业务调度及宿主会话恢复。它不属于平台核心，也不依赖模型循环轮询维持在线。

个人助手端和服务方端是同一软件包的两个角色模块，共用这一进程；同账号的一个实例可以承载个人助手及多个服务，各自保留身份、配置与业务状态。内部分区见[实现](../实现.md#内部分区)，调用的其他模块见[依赖](../依赖.md)，产品调用契约见[共用运行时](../接口.md)。

## 模块与依赖

原协议入口先用独立控制作业完成校验、真实任务创建与进展返回，再将延期业务交给模型作业。控制作业显式登记且不能调用模型；非模型的长时间协议等待仍是业务作业。调度为控制保留工作线程，业务等待不能占满全部控制资源。max_pending_requests 限制新增本地业务，已通过接单校验的协议推进仍可入队，由角色核原 admission 后标记；不因此提高模型并发或绕过同交互/会话互斥。

SDK核心只接收显式注入的ToolBinding/BusinessTools；已安装业务包的选择和构造归本机装配入口，不建立另一套收件或角色执行器。SDK 核心不导入平台核心、A2X 内部实现、宿主适配或官方场景目录；平台核心不导入参与方执行器。各宿主适配包的启动入口将角色处理器和实现 AgentHost 的宿主对象注入运行时；运行时仅通过该窄接口调用宿主，不自行发现插件或复制角色流程。

AgentHost 负责上述宿主能力及其真实结果，合同、报价、接单和会议规则不属于宿主接口。可信用户答复由适配器关联，授权对象和阶段仍由 SDK 核验；无法建立关联时按下文保留等待并使用本地受控确认入口。业务技能负责生产和业务判断，传输、签名、付款与重试由 SDK 执行，不建立通用工作流引擎。

公共层以[宿主提交](宿主提交.md)的S01—S05为唯一宿主调用契约；静态登记、必要扩展与来源包装随适配器交付，资源生命周期留内部。专业能力归用户宿主已有配置；SDK只固定业务定义、回调和业务材料边界，业务定义与SDK回调由角色传入中性execution，不新增公共run/deliver双链。原生工具批准不能替代SDK真实批准。

## 冻结业务文档

本期不向宿主分发、安装、冻结或锁定专业Skill文件版本；专业工具与Skill完全复用用户宿主已有配置、原权限和沙箱。IoA只提供两角色Skill、必要入口与本轮SDK业务工具。服务、私人规则和既有合同中的instructions、skills名称及业务定义摘要继续保留；skills是能力引用/承诺描述，不是IoA新增工具许可，也不要求解析为专业文件后才能执行。各角色把原skills名称放入本轮prompt独立capabilityReferences，不修改HostDefinition结构、原instructions或definition_digest，不宣称这些能力已安装或版本已冻结。

SDK继续固定原业务定义、SDK工具声明、作用域、授权和合同期限；不能为迁移清空旧合同或规则，未知效果仍沿原引用核对。旧显式SDK冻结文件及原在途数据保留，不强制删除，不作为产品新业务的专业能力分发路径。官方已安装专业资产与工具由原官方装配管理，不随此次边界调整删除。

输入材料与成果的权限、摘要、范围、大小及期次校验仍由原业务负责；文件交接见[材料与产出](宿主提交.md#文件排队与等待)。本期所有阶段的宿主工具调用政策见[工具调用](宿主提交.md#只读观察)，SDK受保护操作不因宿主工具允许而获得批准。

## 本地数据所有权

Agent流程日志由共用运行时以 `flow:<角色流程>:<agentId>` 命名空间存入原 `runtime_checkpoints`；记录原调用参数摘要、稳定流程与子操作键、当前步骤、真实结果及明确等待点。原调用绑定与流程初始状态同事务写入，效果前保存子操作参数；角色独占决定业务顺序，不建立第二套协议或模型编排器。进程重启读取原日志与作业，未知结果仅由原角色恢复证据，不能通用重排。角色入口与测试见[Agent流程](../../个人助手端/接口/Agent流程.md)。

共用运行时是身份目录、私钥和 SDK 业务数据库的唯一写入所有者。技能脚本和 CLI 经本机认证的 IPC/回环 API 调用，不另开同一身份库，不持有竞争的全局长期锁。

同一 data_dir 在打开账号、私钥或协议数据前取得操作系统进程锁；第二实例明确失败，不凭遗留 PID 文件认定进程仍存活或删除数据。端点描述只在监听就绪后原子写入，含回环地址、随机访问凭据、进程与实例标识，文件仅所属用户可读。描述文件不是运行证明，客户端必须验证当前接口和实例；重启更换访问凭据，清理只删除本实例自己的描述。

启动按配置激活本地身份，不自动接管账号下其他设备的全部智能体。角色的本地 profile key 对应持久 agentId；重新启动不换钥，加角色不另起实例。已有身份与原业务数据缺失时要求迁移，不能用新目录重建同名助手。旧执行入口与新运行时切换前须确认原写入者已经停止。

平台暂时不可达时，仅有已绑定身份、未过期缓存凭据和已固定公共配置的实例可离线启动；持续恢复连接并报告离线。首次认证或绑定必须在线完成，认证明确拒绝时不使用缓存绕过；离线启动不授予业务开始许可，也不重新密码登录或赠币。

| 数据 | 保存规则 |
|---|---|
| 身份与凭据 | 本地私钥、付款身份、平台凭据；不上传平台或交给模型 |
| 用户授权 | scope、阶段确认对象与真实用户答复来源、许可动作、有效期和预算使用记录 |
| 协议原件 | 模板、请求、合同、材料、交付件、签名链、验收及付款回执，由 A2C SDK 管理 |
| 收发记录 | inbox/outbox、去重依据、连续 ACK 游标和控制操作结果 |
| 执行映射 | 起始消息、交互 ID、参与方、宿主会话、固定技能/工具定义摘要与业务检查点 |
| 收信版本 | 已确认的完整本地规则、内容摘要与平台修订映射；修改草稿不覆盖在途处理版本 |

数据库事务和写锁只覆盖短操作，不在锁中等待网络、模型或用户。观察上报失败只进入 outbox，不回滚已成功的协议动作；平台观察副本不替代本地原件。

日程、预约、邀请等业务状态及原始工具回执由所属本地业务工具保存；运行时保存调用标识、输入摘要、回执引用及检查点。工具沿用运行时传入的稳定操作键，恢复时先查询原回执；未知外部效果不能由新一次模型调用自动重做。工具状态不复制成 SDK 内的会议或邮件状态机。

## 交互建立与会话映射

统一 `HostRegistry` 协调S01提交与原数据；`for_interaction(actor,interaction)` 在原runtime_checkpoints持久记录hostRef、真实sessionId、workspace和来源(kind=external/native)，然后返回该宿主；恢复核原账号、身份和登记，不按默认改绑。外部首次业务绑定当时默认；原用户会话须由适配层提供可信来源，不接受模型猜测的PID、目录或用户名。一个原用户会话可绑定多个业务。能力及工具均按持久绑定读取，不因更换默认漂移；不同登记的资源在唯一实例锁后启动、作业排空后关闭，冲突明确失败并释放已构造资源。

HostRegistry承接公共P20唯一提交及P22事实接收，契约见[宿主提交](宿主提交.md)。原operation、绑定、单调回执及未知资源归属保留；不保留旧prepare/来源运行期方法或run/deliver公共分叉。

既有调度继续独占交互、同(hostRef,真实Session)串行与模型额度；未知作业阻止同会话新效果。执行映射与投递引用均用既有检查点，不新建业务状态机。

可信来源由适配随包原生入口自动获得，公共验证后进入内部绑定；不接受模型JSON自报。发送前record_origin持久保存原消息归属，真实interaction.opened再原子关联；已出站后不补造来源。原绑定和恢复不随默认变化。

投递首次在原store事务claim unknown后才外调；同operationId重复同参返回原回执，异参id_conflict；查询同时核原actor/interaction/host/session与投递引用，不能跨业务查错。最终写入事务重读原回执，accepted/delivered/handled已确证事实只前进；并发晚到unknown、超时或较弱回执不能抹掉更强已知事实，原引用不改。取消仅针对原绑定宿主及已知请求，S05受理不当真实结束；S02只在运行期由35检查默认宿主，不作接入、配置或启动门禁。

| 时点 | 本地行为 |
|---|---|
| 可靠收件 | 在同一事务保存 inbox、去重记录与可连续推进的游标，再确认送达 |
| 首次有效请求 | 以“接收智能体、发送智能体、起始消息 ID”查唯一记录；不存在才创建交互 UUID |
| 建立回执 | 同一事务保存交互映射和待发 `interaction.opened`；重传只返回原记录 |
| 开始业务 | 先取得平台登记及请求开始许可，再执行业务工具；不得把创建本地会话视为获准接单 |
| 发起端关联 | 按 originMessageId 原子补齐 UUID；等待期间记 awaiting_open，不凭正文或用户名猜测关系 |
| 补查 | 原建立回执丢失时查询平台登记或重传原请求；查到建立前终态则结束等待，不创建第二交互 |
| 后续发送 | 接受本地交互句柄，由 SDK 自动附加 UUID 和修订；未建立或已关闭时返回明确状态 |

平台关联约束和关闭竞争以[消息中心](../../../平台/消息中心/接口.md)为准。本地保留 A2A 请求 ID、任务 ID、合同摘要；这些协议标识与宿主 Session ID 都不能替代业务幂等键。

每个**入站交互**拥有独立执行会话；发起端的用户会话可以协调多个对外子交互。收到结果先更新原任务，不把回复当成新入站请求。不同候选服务分别有交互；同一目的的改约可以沿用原交互。

调度同时按交互和实际宿主 Session 串行，避免多个子交互同时修改同一用户会话。续接固定原 Agent、技能版本和工具集合；双方保存各自 Session ID，不要求相同，也不向平台上传。

## 调度、容量与等待

| 资源 | 限制与释放 |
|---|---|
| 接单容量 | 服务的有效预留及未结束承诺；权威台账在[委托中心](../../../平台/委托中心/接口.md)，本地仅镜像；等待授权/验收仍占用 |
| 模型执行并发 | 同时运行的宿主模型轮次，由 max_model_runs 限制；本轮结束或中断后释放 |
| 本地待处理队列 | 有界；消息开始、过期或明确拒绝后收敛；排队不延长协议期限 |
| 控制通道 | 授权答复、解除、状态查询、回执与恢复独立调度，不能被新委托或满额模型队列阻塞 |

业务检查点采用 queued/running/waiting/completed/rejected/failed/unknown；这是本地执行状态，不能替代 A2C 合同状态或签名证据。

调度器只接受本地装配时登记的角色处理器。提交时按稳定操作及输入摘要落库，重传不新建作业；是否需要模型、是否为确定性控制由本地登记决定，外来正文不能改变。调度前原子保存 running，调用期间不持有数据库事务。同交互及同 Session 的业务轮次串行；waiting 释放可释放的模型轮次，unknown 禁止自动新增业务效果。角色显式恢复只可在核实所属原轮及效果、满足其恢复契约后原子入队；[服务方生产恢复](../../服务方端/接口/接单与任务恢复.md#原生产任务的恢复)不提供任意未知作业重跑。已登记原任务的授权答复、验收/付款通知、取件和原结果核实可独立处理，仍核原任务、签名与动作许可，不能借控制通道启动模型。重启将未收敛 running 标为 unknown，角色先查原结果；尚未开始的 queued 可继续执行。

取得有效执行连接前不调度新入站作业；业务工具发起效果前仍须复核连接及该动作的许可。连接有效性以最近平台认证/心跳确认的保守租期判断，不以 TCP 尚未关闭判断；本地使用单调时钟及对应请求发送时点计算期限，迟到的心跳不能乐观延长旧许可。失效即暂停新调度并恢复连接，不改变已经发生效果的状态。

可结束本轮的业务等待先持久化 waiting，再释放模型名额；对应原答复通过短控制处理后，角色验证等待事项已收敛，再续接原业务。一个交互的多个控制处理相互串行；它们不等待该交互的模型作业，但原 Provider/Store 的短修改仍受同一锁保护。宿主原生提问如需同一进程回调，保留原进程及会话独占、释放模型名额，答复后重新取得名额及执行资格；不能伪造同意或把杀进程当作可恢复暂停。

控制处理器和已有合同记录的收件不依赖模型当前可用或模板仍在公示；缺宿主时不接新业务、不启动生产。on_start 只持久登记生产，不在原 Provider 锁中等待整个模型轮次。原 Task 的开始、授权、交付及结清事实驱动业务续接，不能按模型“完成”推进合同。具体映射见 [A2C 适配](A2C适配.md)，宿主能力验证见[宿主适配验收条件](../../宿主适配/接口.md#验收条件)。

模型观察复用当前执行作业的名额，校验实际作业、所属身份与交互；服务方自测的嵌套只读轮次在父模型等待回调时串行运行，不能重复申请名额造成死锁。助手验收及预览登记为模型作业，等待用户批准后结束本轮并释放名额；同一批准续接原作业。观察的实际Session单独保存为辅助记录，不调用业务会话绑定。协议控制处理器不得调用模型观察。

关闭时先停止接新工作并静默收件/扫描线程，再等待或取消本次执行中的宿主轮次及作业，最后关闭角色传输、平台连接、数据库及实例锁。角色提供quiesce停止调度入口，close释放资源；作业仍可能读取原公钥、验收器或付款回执时不得提前关闭其传输事件循环。失败清理也遵守同一顺序，不以删除状态结束等待。

## 用户确认与预算保护

| 边界 | 规则 |
|---|---|
| 确认来源 | 保存真实原生答复或本地受控确认入口的记录；模型传 confirmed=true 不能自证同意 |
| 确认绑定 | 绑定账号/智能体、具体对象摘要、阶段及获准动作；对象或动作变化不能复用旧确认 |
| 使用确认 | 受保护操作前检查当前阶段、对象、授权期限及原操作记录，避免重复签署或跨阶段套用 |
| 宿主不支持 | 无可信答复关联时保留待确认，通过本地受控入口完成，不绕过用户 |
| scope 预算 | 总预算覆盖拟卡费与履约价款，并另核拟卡费子限额；同 scope 的并发候选使用同一预算记录 |
| 并发费用 | 按稳定操作标识原子预留在途费用，成功计入已支出，确认未生效才释放；结果未知保留占用 |
| 合同选择 | 核已付/在途费用与拟承诺合同总价，不因分期付款而忽略整份承诺；后续阶段费用继续使用原关联 |

本地预算预留保证多个模型或候选不会并发越过用户限额；[支付中心](../../../平台/支付中心/接口.md)还须对同一授权凭证核额度，不能仅相信客户端声明。网络或模型等待期间不持有预算数据库锁。

## 按需执行与工具边界

| 触发 | 执行方式 |
|---|---|
| 身份、模板、历史结果查询、ACK | 确定性处理，不调用模型 |
| 协议验证、价格、签名、确定性验收 | 调用 A2C SDK；验收器只在核摘要后的 WASM 沙箱运行 |
| 拟卡业务判断与服务生产 | 容量、格式、阶段和权限检查后启动或续接宿主 |
| 助手通信处理 | 装载原修订的本地规则，按需调用宿主及已授权业务工具 |
| 配置技能 | 只处理本机用户的配置意图；外部业务消息不能切换为发布、安装或修改权限流程 |

工具权限限定当前账号、交互和阶段；外部输入只能填充业务参数，不能选择任意文件、密钥、工具或修改接入技能。收信处理文本不是 Python/Shell 程序，不能作为可执行代码导入；业务工具由用户预先配置。官方日程、邀请邮件等工具归 `src/official/tools/`，通过已配置的宿主工具入口调用；SDK 核心不导入该目录，普通接入也不自动获得这些业务能力。

各宿主适配器仅使用所锁定宿主的公开接口，不改宿主源码、全局指令和私有历史数据库；宿主运行请求 ID 不等于业务幂等键，具体续接方式归各适配接口页。网页显示、通知和审批须分别取得真实证据，后台成功不能记作网页已显示或用户已读。

## 故障与外部效果恢复

运行期P34由原常驻生命周期驱动`RuntimeHealth`，仅检查默认宿主S02并合并可信正常业务机器反馈；`snapshot()`及P12只读已记录投影。S02判据见[S02运行期健康](宿主提交.md#s02运行期健康)，公共层只消费四态。采样间隔为内部常量30秒，不是配置项；到退出阈值前仍以一次新S02复核，不只看缓存。S02不在常驻主循环中同步阻塞执行：采样移出主循环并有界运行，主循环只读取已完成的结果，停止信号、调度与控制处理不等待S02；超时或未完成只记unknown，不记unavailable。busy/unknown不累计确证unavailable；适配给出带依据的unavailable即经P35暂停本实例新接单，默认持续600秒后请求原排空，退出前恢复则经P35原修订guard自动恢复本系统暂停（[系统暂停与恢复](../../服务方端/接口.md#系统暂停与恢复)）。每次采样不调用平台admission.status，只在需暂停、核原未决操作或恢复原自动周期时访问原策略。已核机器认证撤销/账号或策略禁用保存在原host-health记录，目录available不能清除，真实正常业务成功才能解除对应业务故障依据。公共层不为官方实例、某一适配或执行形态写分支；将来若需不同健康策略，只能新增公共配置项，由部署方写入实例配置。不创建模型心跳、第二调度器或唤醒守护；采样的有界执行单元归原常驻生命周期所有，随P13排空停止。测试：runtime_health、provider_admission。

| 情况 | 处理 |
|---|---|
| 启动恢复 | 恢复本地记录和连接代次，核对原协议步骤、工具回执与接单台账，再开放新业务 |
| 租约失效 | 停止发起新外部动作；工具调用前检查执行资格；新代次不能消除旧外部效果 |
| 外部调用 | 发起前保存稳定操作键，返回后保存真实结果；未知则查询或交由用户核实，不盲目重复发信、付款或生产 |
| 接单状态未知 | 查询平台权威台账；不得根据本地缺记录释放名额 |
| 收信版本缺失 | 停止执行并报告；不以新草稿代替原处理流程 |
| 模型退出但缺 SDK 动作 | 只在有界轮次内提示补齐；遇未知副作用、原生交互或协议错误停止自动重放 |
| 授权或期限失效 | 停止对应新动作，保存已经发生的效果并返回明确状态 |

平台控制请求可幂等恢复，不等于外部工具具有同样保证。结果未知保留检查点及证据，不能以“模型说完成”推进实际合同或付款状态。

## 原会话业务事件

用户主动发起的委托/私人交互，其已核异步待决、结果、拒绝、关闭及成果待验收事件，由原角色判定并经NativeEvents送回该业务已持久化的native来源。事件不是授权，不替用户签约、验收或付款；handled仅证明原宿主处理通知，不证明业务完成。external来源沿原S01逻辑执行，不双投；无可信原来源明确待恢复，不猜default、PID、目录或用户名。

NativeEventTarget固定actor、businessRef及原mid/task/flow source定位。首次发送前冻结原host/SID/workspace与事件快照；interaction建立后只核同源，不能把通知目标从origin改成iid。通知子操作由原语义事件键确定，原业务operationId保留；与interaction投递共用同一host-deliveries事务claim/回执与单调结果，不另建业务状态机。同步RPC已返回的同一事实不额外唤醒；真实新业务进展才产生通知，心跳/ACK/无变化扫描零模型调用。

eventKind是本地结构化notice分类，不新增协议wire种类：business.decision/result/candidate/contract/delivery_ready分别表达待决、结果、候选、成约与成果待验收；原message.result/interaction.closed表达实际已核消息事实。分类标签不替代原稳定事件键或业务操作引用。

通知也只经P20/S01，必要连接初始化封装在适配内部，不新增prepare_delivery或公共deliver方法。原claim/attempt/store与原绑定的可信验证保留在公共协调和适配内部传输记录；明确未提交才沿同operation等待。已受理/未知不重投，普通not_ready/timeout不能当未执行。新空库/身份变化不能凭absence证明可重发。

DeliveryReceipt.execution可附NativeExecutionEvidence(operation_id,host_ref,session_id,request_ref,attempt_nonce,receipt_store_id,terminal,evidence_ref)。全部引用非空且绑定原operation/host/SID/attempt/store；terminal只接受原机器请求/轮次确证的completed/failed/cancelled。宿主必须从原queue/item关联真实native request及终态证据，不能从模型ACK、文字、cancel true或qid消失猜补。validate_native_execution校验公共归属；同原request_ref不可变，已证execution随回执单调保留。宿主原生证据由30—32实现及验收。

Native事件用现有Scheduler、uses_model=True、control=False。accepted/delivered及只有handled ACK均不释放模型名额；有界机器查询须同时核handled与匹配execution。超时/排空/重启unknown仍按JobHandler.retain_model_on_unknown保留原permit。该标志只给可能仍活着的native轮次，不把所有SDK未知效果当模型存活。_next与user_wait重新取名额共享唯一_model_permits；同(hostRef,SID)未收敛阻断后事件。只凭匹配机器终态证据resolve释放通知作业，不将其当业务完成；唯一例外是未声明S04、只承诺通知投送受理的适配：通知类作业以该适配给出的真实宿主受理及原操作关联引用持久化证据记为投递完成并释放，该证据只适用于通知，不适用于业务、报价、复签审查或观察轮次，不证明宿主已处理、用户已读或业务完成，具体机器关联条件写在该适配接口页；不另设quota/费用系统，用户自己启动的模型不属SDK管辖。

恢复、角色watch及inbox/检查点检索均分页有界；活动flow使用原检查点的活动索引，异步receipt与待消费指针同事务落盘，inactive结果在消费前后中断均按原事件键恢复。机器预检/恢复查询持久1—30秒指数退避，首次有界等待也按1—30秒退避；单事件故障不终止其他事实扫描。runtime.status.nativeEvents只给本地pending计数及有界诊断样本，不probe或触发模型，不输出私有nonce/store身份、原参数或错误文本。原角色核语义事件与去重owner：私信终态/关闭、候选与成约阶段、后续环节/验收付款终态及已核成果。通用flow只记录所有child的parent因果索引，具体角色叶选择消费去重owner；不因包含contractRef就过滤后续阶段。waiting的真实待决confirmation与携同ref的终态使用不同稳定事件键。原生transport与会话实际处理分别由30—32及36验收。
