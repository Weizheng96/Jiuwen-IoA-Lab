# 共用运行时 · 安装与实例

本页是[共用运行时](../接口.md#接口)的子页。

## 安装与实例核对

运行状态的installation在启动时冻结，包含format、environment（实际Python安装前缀）、releaseId、versions和assembly。产品安装器在依赖/版本/完整性检查后写入环境根的ioalab-release.json及.ready；前者保存格式ioalab.access-installation/1、清单摘要releaseId和发行包versions，后者保存相同摘要。运行时只读取本机安装元数据，不导入清单中的业务模块。两文件不一致、已安装版本不符或缺必需项时拒绝就绪，不修补正在使用的环境。

runtime.start同时核账号、非凭据配置摘要及installation；旧进程缺该信息、宿主装配不同、安装前缀或发布摘要改变，均返回installation_changed，要求显式安全停止后用原配置/数据目录启动。不能启动第二个写入者或删除状态来消除不兼容。

产品技能/CLI的普通角色或业务调用先核当前受认证运行状态的installation，再将请求固定到同一bootId；核对后实例发生切换时返回instance_changed，不向新实例发送业务。runtime.status、identity.status、confirmations.get、operations.get、runtime.open_ui和runtime.stop保留为旧实例诊断及安全停止入口，不由此开放新的业务效果。停止仍绑定实际bootId。独立serve主线程接收SIGINT/SIGTERM时只设置停止意图，随后通过同一调度器排空；拒绝新业务和新调度，原已运行作业可完成原授权工具。信号处理保持到连接、数据库及执行锁实际关闭，重复信号不强杀；嵌入其他线程的运行时由宿主管理信号。runtime.stop的completed只表示调度器当前无活动作业，不证明IPC、连接和目录写入者已全部释放；升级方仍需核对对应目录的OS锁，不得以答复或描述符消失替代。排空期间，仅由调度器认证为当前运行中、未等待用户的原作业上下文可继续执行工具；上下文须属于本实例且仍在活动集合中，异步工具回调保留该上下文。队列、已结束、等待用户或其他实例的上下文不能取得许可；平台连接、原授权、工具范围和期限照常核验，不通过普通RPC提供排空豁免。

未经过产品安装器的自管环境报告实际安装前缀、SDK及装配包版本，releaseId为空；不得冒充已核验发布。自管环境执行显式停止后升级，不支持对活跃进程原地热替换源码或依赖。安装信息只用于兼容核对，不代替身份认证、用户授权或工具权限。

## 安装与发布

客户端源码、宿主适配、角色Skill与示例统一归src/client。一个持久客户端由bootstrap.py持有唯一安装链。Windows bootstrap.ps1只准备环境并调用它：已有依赖支持的Python≥3.11及Git优先复用；缺Git用官方固定MinGit ZIP，缺合适Python用官方固定uv ZIP取得已验证的依赖支持解释器。便携ZIP执行前核源码固定SHA256，工具装入用户私有目录，不改全局PATH/TLS或注册表策略；PowerShell只可选择进程级RemoteSigned，组织强制策略优先，拒绝时明确policy_blocked和当前宿主手动步骤。

一句话接入的唯一用户指令写在给人看的根README.md，逐字为「先 git clone --depth 1 --filter=blob:none --sparse https://gitcode.com/WeiZheng96/jiuwen-IoA-lab.git 下载 IoA Lab，然后参考其中的 README_AGENT.md 接入 IoA Lab。没有 git 请先安装 git。」README_AGENT.md留在仓库根目录（--sparse只检出根目录文件），智能体逐字读取本地副本，不经raw/blob网页取原文（GitCode网页地址对curl/WebFetch返回HTML外壳或403，部分克隆加稀疏检出可达）；README_AGENT先以sparse-checkout取得src/client安装器，再运行安装器完成下载、安装与配置。缺git的宿主先按该句安装git。

正式来源为GitCode main的实际固定commit或GitCode发布tag：用户这次部分克隆的HEAD即固定来源，bootstrap在该官方clone内运行，不再另行clone；开发验证用官方GitHub develop clone的实际固定commit，二者明确区分。未给commit/tag时，bootstrap.ps1按`-Channel main|develop`（默认main；develop只用于测试，对应GitHub clone）取所在官方clone的HEAD为完整commit并回报resolvedCommit，此后与显式commit同样核验：clone的官方origin与通道不符即拒绝，main须在GitCode origin/main谱系，develop须在GitHub develop谱系，marker记录channel，有对应design标签时一并记录。核官方origin、固定commit及脚本Git对象一致；src/client以外安装所需路径（如受审vendor）由安装器从同commit按最小集合补取，路径清单只在安装器一处维护，不懒取整仓；从同commit生成客户端与受审vendor快照，不混工作区或构建缓存。来源、vendor摘要、精确依赖、pip check和RECORD校验均保留；无缓存构建wheel并核实际安装来源和wheel SHA256，即使产物版本相同也不复用旧构建冒充新源码。

带固定SHA256的下载项（便携Git、uv、解释器等）在官方源失败时可改用随源码登记的国内镜像备用源，或用户显式配置的镜像/代理；无论来源都核同一固定SHA256与TLS，不符即拒，不以镜像换版本或非官方包。网络失败不触发解释器重试或其他换源。

bootstrap创建独立venv，核实际基础解释器而不把宿主venv当base；不修改宿主或全局Python。持久布局见[接入交付](接入交付.md)；安装到`~/.ioalab/client`后客户端不依赖接入所用的clone，完成摘要告知可删除。已有未知或链接目录保留并拒覆盖；同固定来源的完整安装可重复核验。中断留下的未完成安装仅当marker为同一安装标记、同一固定来源，且配置文件与数据目录都不存在时，原env改名保留后原位重装；其他未完成情况保留现场并拒覆盖，不动原配置、账号与数据。

显式`-Upgrade`（bootstrap.py `--upgrade`）是已有安装的唯一升级入口，用户重新说同一句接入指令并要求升级，智能体在新clone内带-Upgrade运行：核marker归属与新固定来源，经原客户端runtime.stop安全停止并以实际取得原data_dir的OS锁证明无写入者，原env改名保留后同路径安装新wheel并核status/RECORD/pip check，再更新marker并按[接入交付](接入交付.md#持久安装与绑定)重装自有Skill；任一步失败恢复原env并保留日志。账号、配置、数据和默认登记不变；入口绑定按安装指纹变化报待迁移。原客户端缺安全停止入口时返回explicit_upgrade_required。未给-Upgrade时已有安装只核验、不升级。追加宿主在原环境补其extra，配置存在时持原data_dir的OS锁排除活跃写入者；补装不重装客户端代码、不改账号/数据/default。补装和依赖核验失败不登记installedHosts成功，保留现场并允许原来源重试。只有明确解释器依赖不兼容才指导选择私有已验证Python，不能将网络失败归为版本不支持或覆盖失败环境。

两个Skill绑定同一客户端、原配置及实际hostRef；安装、发现、账号、认证、连接、身份与业务就绪分别交付。安装本身不隐式注册账号、改默认或启动业务；完整一句话接入由clone根目录的README_AGENT.md编排SDK本机账号页、统一runtime.configure、宿主安装回执与唯一runtime start，不新增启动链。失败亦交付固定六项摘要，含bootstrap.ps1环境准备阶段的失败。测试：background_installation、package_installation、client_onboarding。

统一wheel保存平台条件的单一依赖锁，按所选宿主extras安装；Codex不拉取Claude SDK，pywin32仅Windows的Claude依赖需要。构建不读取开发机已安装的第三方元数据，不把Windows条件展开为Linux必需包。

统一wheel包含[平台TLS信任](平台TLS信任.md)的公共CA/Origin清单、SDK、宿主适配及两角色Skill资源，并纳入本仓src/a2c同源模块/NOTICE及vendor中摘要锁定的Process SDK模块及许可证；不包含宿主本体、平台核心、官方业务实例或私人配置。构建检查自有A2C包字节/资源与vendor摘要；单一安装元数据列出组件版本。Linux受管部署仍按部署模块的隔离单元构建组件wheel；它们是同一客户端源码的部署组件。

客户端导出ioalab-assistant-skill.zip与ioalab-provider-skill.zip，两者仅含角色说明、共用流程和绑定同一客户端解释器及配置路径的调用脚本，无wheel、安装器或独立运行环境。用户在原生界面导入并选择角色Skill后，以skill_tool实际读取，再继续账号页和宿主配置；不能把文件导出或Skill读取称为已连接。

两个Skill由程序绑定同一客户端与配置（新安装默认~/.ioalab/client/settings.local.json），使用同一data_dir及常驻实例。选择Skill决定本次可调用的角色命名空间；实际身份、归属与授权由SDK核验，不因切换Skill删除、重建身份或停用另一角色。同账号至多一个assistant、可有多个service，保留原角色配置及业务。

公共调用通过所选Skill的scripts/ioalab.py转交统一安装的ioalab_client。runtime.install.status只核已安装客户端，不创建环境；角色Skill不得触发安装。启动、状态、身份和安全停止沿同一客户端与原配置执行；安装元数据或运行bootId改变时，仍按本页的安装与实例核对规则拒绝新业务并允许诊断和安全停止。

| 接口 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|
| bootstrap.ps1 [-Commit/-Tag 或 -Channel main/develop] [-Upgrade] → bootstrap.py (--tag <tag> 或 --commit <commit> --channel <通道>) [--upgrade] --host <host> --host-ref <ref> --install-dir <dir> --output <dir> | 在官方clone内运行，以其HEAD（或显式commit/tag）为固定来源安装或安全升级并导出两角色Skill；返回来源、resolvedCommit、解释器、文件路径及clone可删除提示 | 非官方clone、origin与通道不符、来源/谱系/摘要/依赖不符、目录冲突拒绝，升级失败恢复原env；不启动业务 | background_installation、access_products |
| ioalab-client status / skills --output <dir> | 核RECORD；导出绑定同一解释器的两个Skill | 文件变化不覆盖；未安装不尝试pip | access_products、package_installation |

`--reuse-installed`将引导验真来源与原client安装来源分开：原公开导出须支持host_ref与sourceBinding/2，随后从原marker官方完整commit取得对象，只补原extra；错归属、旧能力或活跃OS锁拒绝，不升级代码、不换账号。明确Requires-Python失败返回unsupported_python与日志位置，Windows提供显式ManagedPython及未占用隔离目录步骤；不自动切换有效安装根或将网络失败重试为解释器问题。

## 适配资源与启动边界

适配选择和静态资源来自随包清单，不为安装计划/保存配置/启动调用宿主探针。原安装/账号/配置身份、固定源码、依赖摘要、OS锁、单实例及停止活跃写入后升级仍必须核验；适配实际定位/连接失败在真实调用返回准确阶段及人工动作，不能以删除门禁省掉定位。必要资源由完整自动/手动交付取得，规则见[宿主提交](宿主提交.md)。
