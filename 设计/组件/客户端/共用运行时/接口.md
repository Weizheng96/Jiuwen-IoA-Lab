# 共用运行时

## 目的与范围

参与方本机常驻进程的共用部分：同一 data_dir 的唯一写入者，持有账号会话、本地身份、平台连接、可靠收发、作业调度、用户确认、本机 IPC 与 A2C 协议适配，并提供两款产品技能共用的引导与安装脚本。不含角色业务规则，不导入平台核心、九问或官方业务包，网络格式归 [web服务](../../平台/web服务/接口.md)。调用方是两角色模块、宿主适配与官方实例的装配入口，以及经本机 IPC 调用的产品技能脚本与 CLI。

## 独占数据与配置

| 数据或配置 | 说明 | 存储 |
|---|---|---|
| 冻结业务技能文档 | 用户所选业务文档、固定定义绑定与摘要；续接只读原快照 | SDK分配的轮次工作目录下`skill-documents/` |
| 公共配置 | platform_url（可省略，默认https://120.46.80.150）、username、password 或 password_env、data_dir、identities（1—64 个，至多一个 assistant）、max_model_runs（2）、max_pending_requests（128）、user_browser；assistant、provider、host 区域由角色与宿主校验 | 用户外置 JSON，产品默认 `~/.ioalab/settings.local.json` |
| 实例所有权 | data_dir 的操作系统锁 | `client.lock` |
| 本机端点 | 回环地址、随机令牌、pid、runtimeId、bootId | `runtime.json` |
| 账号会话 | 账号绑定、凭据缓存、待恢复登录与 HMAC 输入摘要 | `account.sqlite` |
| 本地身份 | 每 profile 的私钥、付款密钥与 agentId；身份索引 | `identities/<key>/keys.json`、`identity-index.json` |
| 投递与交互 | runtimeId、收件游标、inbox、outbox 与回执、交互映射与 Session、检查点（含 A2C 协议存储） | `runtime.sqlite`：`runtime_meta`、`runtime_cursors`、`runtime_inbox`、`runtime_operations`、`runtime_interactions`、`runtime_checkpoints` |
| 作业与确认 | 角色作业与续接回执；确认绑定、决定与来源 | `runtime_jobs`、`runtime_job_resumptions`、`runtime_confirmations` |
| 安装标识 | 安装器写入的发布摘要与包版本 | 环境根 `ioalab-release.json`、`.ready` |

data_dir 是 SDK 专用目录，其中 `roles/`、`materials/`、`deliveries/` 归两角色模块；混放无关文件时拒绝启动。

| 单写者 | 同一 data_dir 必须先取得 `client.lock` 再打开账号、私钥或运行库；遇持锁者拒绝，不得凭 PID 或描述文件判断存活 |
| 脚本不开库 | 脚本与 CLI 只经回环 IPC 调用，不得打开运行库或私钥；业务调用必须固定已核对的 bootId |
| 原操作先落库 | 变更请求的 operationId 必须在发送前持久保存；响应未知沿原标识恢复，不得换标识重做 |
| 统一结果 | status 只表示本次 SDK 操作；合同、投递、付款状态只在 data 中 |
| 批准来源 | 批准必须来自 SDK 确认记录；模型参数、模型文本、宿主工具 allow 不得产生批准，普通 RPC 不提供批准入口 |
| 执行资格 | 无有效执行连接时不得调度新入站作业或发起新外部效果；离线启动不得授予开始许可 |
| 未知不重跑 | 重启把未收敛的 running 标为 unknown；unknown 只能由所属角色核实原效果后显式续接 |
| 串行与名额 | 同交互、同 Session 的业务轮次串行；控制处理器不得调用模型；模型轮次不超过 max_model_runs |
| 短事务 | 事务与写锁内不得等待网络、模型或用户 |
| 停止不取消 | 停止必须先排空作业再释放连接、库与锁；不得删除状态、取消合同或释放承诺 |
| 安装与配置一致 | 运行实例的 installation 或 configurationDigest 与当前不同时，业务调用必须拒绝；诊断与安全停止仍可用 |
| 依赖方向 | SDK 核心不得导入平台、九问、官方业务包、两角色或 SDK装配，只接受注入的角色、宿主与 BusinessTools；产品脚本与 `start` 只以模块命令启动 SDK装配 与宿主适配，不导入其代码 |
| 操作目录 | 新增、改名或删除操作必须先改操作目录；产品技能中出现的操作名必须在目录中，目录中开放给智能体的操作必须在所属产品技能中出现 |
| 凭据不外泄 | 凭据、私钥与本机令牌不得进入模型可见结果、状态摘要或日志 |
| 协议原件 | A2C 存储与传输只用于本地 delegation 交互；重试必须恢复原报文、签名与消息 ID |

### 验收条件

单模块的可验证条件；跨模块条件在流程页的“端到端验收”节。

| 场景 | 必须满足 | 测试 |
|---|---|---|
| 本地写入所有权 | 技能/CLI 只经本机认证的 IPC 调运行时；同一实例的两个角色复用身份和连接，不另开数据库或持有竞争的长期锁 | resident_runtime、configuration_boundary |
| 业务工具隔离 | 日程与邀请规则归官方业务工具，SDK 只保存操作关联及执行检查点；同一稳定操作键恢复原回执，未知外部效果不自动重做 | business_tools、appointment_source |
| 配置与参数所有权 | 引导不解析账号配置；两技能、SDK 及宿主一致读取 Windows UTF-8 配置/参数。账号配置或其文件别名、SDK 数据不得被参数元信息覆盖；配置/安装改变时业务拒绝且无效果，缺凭据或业务配置错误时仍可定位原实例诊断与安全停止；不提供旧 CLI 别名 | configuration_boundary、external_product_config |
| 确认流程可执行 | 预览不创建批准；按下一步角色调用生成真实 waiting 后才打开页面。打开页面不改变 pending；重复申请同一操作复用原确认，聊天 confirmed 与 A2UI 选择均不能批准 SDK 保护动作；可读确认与原签署对象一致；真实批准后原操作只签名/发布一次，合并调用跨重传和重启不重复收费或签名 | user_confirmations、jiuwen_a2ui_forms、confirmation_view |
| 凭据续用与重建 SDK | 两角色复用同一缓存；续用不新增登录或赠币，失效不循环密码认证 | authentication_recovery、account_enrollment |
| 显式登录恢复 | 同一 OS 锁且不碰身份/业务；有效缓存不赠币，失效时仅显式新登录，丢响应恢复原操作；输入改变或账号 ID 变更拒绝；明确拒绝、限流、5xx 及未知结果分开；双 Skill 和真实安装包入口均验证 | authentication_recovery |
| 本机实例与 IPC | 同目录只能一个进程持有运行数据；描述文件遗留不证明存活，旧实例不能删除新端点；Origin/Host/访问凭据/大小检查有效，CLI 不打开身份库 | resident_runtime、lease |
| 离线与停止 | 仅已绑定且凭据有效的实例能离线启动，状态明确离线；重连不再登录赠币；停止保留合同及操作，已有轮次未收敛时不提前释放所有权 | resident_runtime、runtime_signals |
| 调度与恢复 | 同交互及同实际 Session 串行，跨交互受模型上限约束；等待释放轮次、控制不阻塞；重启不重跑未知外部效果，原作业重传及异参数校验正确 | runtime_scheduling、concurrent_tasks |
| 等待用户 | 占接单名额、释放可释放的模型名额；原生确认不会由模型自动答复 | runtime_scheduling |
| 等待与控制 | 生产等待环节/验收时，同交互的原控制可处理并续接原 Session；模型忙或缺失不阻断已有控制，不重复执行 unknown | runtime_scheduling、resident_fulfillment |
| 用户确认入口 | 脚本不能取得浏览器批准凭据或写入同意；确认绑定真实对象、预览和原操作，跨对象/阶段/过期/重复伪造拒绝，原发布未知可查询恢复 | user_confirmations、trusted_user_port |
| 确认页浏览器 | 默认浏览器或本机配置的绝对可执行路径；含空格路径按独立参数启动，不使用 shell，远端/模型不能临时传路径或 URL；无效配置/打开失败明确报错且不回退或泄露入口。配置摘要变化须安全重启；打开前后原确认仍待决定，仅真实浏览器通道可批准 | user_browser |
| 模型观察与验收预览 | 原 L2 包提出观察、WASM 判定，错误观察/缺宿主不得通过；观察无业务工具和批准入口，不覆盖业务 Session；受当前模型作业预算约束，并发上限 1 时嵌套自测不死锁；异步预览不签7，真实批准后原 SDK 复验；用户拒绝或确认过期后，无需再次模型调用即可结束本地等待，不签7、不付款 | verifier_observations |
| 本地业务工具 | 仅本机选择已安装工厂，按 profile 隔离；SDK 不导入具体包，外来消息不能加载工具；工具目录无凭据，规则/会话绑定策略修订；服务方只在生产及本期真实环节同意后执行，未知不重调；作业结束后才关闭工具资源 | business_tools |
| 工具输出契约 | 目录/预览/入站上下文提供已声明输出格式；非法 Schema 在业务前拒绝，None 不推断成功；工具契约变化要求新确认；输出不合约时保留原回执与未知效果，助手/服务方/直接通知均不自动重做 | tool_output_contract |
| 安装与运行版本 | 两包共享含可选工具的清单和环境，未配置不启用；检查完成才发布安装标记，损坏不原地覆盖；旧实例缺身份或发布/环境不同拒绝启动和业务，仍可诊断/安全停止；预检后 bootId 切换不得发送业务；重启保留稳定身份、原交互/会话、合同、授权及回执，不重新登录赠币 | installation_identity、access_products |
| 安装任务 | 前台快速返回，父调用结束后后台继续；双技能并发只产生一个实际安装任务。纯查询/业务不隐式安装、不读凭据、不回写原业务参数。实际锁与完成包决定状态；明确失败才显式重试，进行中失去所有者保持 unknown 且不重建；损坏就绪标记不覆盖 | background_installation |
| 原生入口与安装状态 | 宿主模型正文不含绝对技能目录时，按公开环境/默认布局确定唯一入口，缺文件明确停止，不扫描旧示例或读取凭据；相同版本号但不同发行摘要的旧实例返回安装不匹配及原观测数据，不能报告新包已启动，安全停止仍可用 | skill_location、installation_identity |
| 原生结构化调用 | 参数语法错误与编码/文件错误分开且无业务效果；同一真实 JSON 经过 UTF-8/GBK 宿主解码得到相同中文；完整作业引用能取得原比较及验收源码，查询失败不得宣称已核对 | native_json_boundary、cli_encoding |
| 配置辅助 | 两产品技能经相同 SDK 离线命令查询/修改；输出无账号/密码/令牌/资源/宿主参数或工具选项。局部合并保留凭据、业务资源、稳定身份及其他角色；同值重复无业务效果，异摘要/改角色/大小写冲突/越权字段/参数别名拒绝。活跃实例持锁时不修改，启动取得锁后复核原快照，变更时认证与建库均未发生；校验和查询不联网或创建运行目录，不将结构有效报告为业务就绪 | configuration_edit |
| 本地写入与断点 | inbox 与连续游标同事务；建立 UUID 与 opened outbox 同事务；落库失败整体回滚，不能先 ACK | runtime_delivery |
| 多身份结果关联 | 控制响应携带 agentId、操作类型与操作 ID；不得把另一身份的同名操作结果应用到本地任务 | runtime_delivery、agent_delivery |
| 原协议任务进展 | 保留上游 taskId、任务状态及无任务响应；不能替换原任务或回退终态；投递台账的调用完成不替代合同完成 | protocol_operations、task_recovery_receipts |
| 同方法多次调用 | 多期 checkout、取件及验收通知各有原操作；当前格式下重启保留原消息、签名、任务与结果，不覆盖早期调用；不要求旧表自动迁移 | protocol_operations |
| 决定证据核验 | SDK 重算公开决定证据摘要并验签，与本案及原合同绑定；改卡、删付款、换案件、替换摘要、签名时间不符均拒绝。历史有效文书可恢复，不泄露原 AP2 请求凭据 | arbitration_review |
