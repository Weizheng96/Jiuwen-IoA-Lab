# 服务方端 · 接单与任务恢复

本页是[服务方端](../接口.md#接口)的子页。

## 入站接单与任务工具

入站消息由运行时确定性分派。服务方 SDK 先检查身份、结构、协议时效和接单策略，通过 `admission.reserve` 取得平台预留并可靠返回原请求；平台提交容量后才允许形成有效承诺。满额拒绝新委托，既有合同继续处理。接单结果、交互关联和合同成立分别记录。

| 任务能力 | 输入 | 输出及限制 |
|---|---|---|
| 本单固定上下文 | 运行时注入当前阶段、原模板/卡、材料与受限工具Schema | 九问先读取实际上下文；这不是另一个管理RPC或inspect工具，不能指定其他任务 |
| `provider.task.verifier.publish` | 本单verifierId、UTF-8源码source，可选reads与kind（script/skill）；源码至多64 KiB | 仅提案quote阶段可用；与管理上传共用打包、包摘要核验及原操作恢复，返回真实id/uri/digest；不执行源码、不签约、不修改公示或配置 |
| `provider.task.quote` | 符合本单模板的确定报价、验收条目与验收时长，或单独拒绝原因 | 返回业务决定已记录；SDK 后续复用原 A2C 拟卡/签认，实际结果从原任务读取；不能绕过期限或容量提交 |
| `provider.task.decision` | 本单待批准 taskRef、批准或拒绝及原因 | 仅处理真实 card.countersign 请求；批准前复核委托方签1、卡摘要、期限及接单资格，原子提交预留后复用 A2C 复签形成签2；拒绝返回原协议原因，不签约 |
| `provider.task.request_step` | 已开工合同、模板声明的环节名 | 复用 A2C Provider.request_step，产生签名 stepRequest 并经原任务推送；保存等待状态，收到对应有效授权前不执行受保护动作 |
| `provider.task.selftest` | 本单候选成果 | 用合同验收器进行自测，返回真实报告；不修改判据、不替委托方验收 |
| `provider.task.deliver` | 本单通过检查的成果引用 | A2C 原协议交付与存证结果；只有真实回执才报告已交付 |

上述操作是 A2C Provider 原语的本单适配，不定义第二套合同状态机。业务技能负责实际生产；SDK 负责协议与权限。九问任务由运行时固定当前交互、Session、技能及工具能力，来信不得选择平台管理模式或另一任务。

宿主任务工具的本单上下文由 SDK 固定；模型不传入或更换 taskRef、UUID、签名身份及 Session。quote 的 acceptance、acceptWithin、lineItems 均以实际模板交付件名为键，拒绝报价时只提交 reason，不把说明文本混入成功报价的拒绝分支。

SDK 每轮明确给出当前协议阶段、所需动作和输入 Schema；业务技能说明不改变当前阶段。调用其他阶段工具时返回准确的本单拒绝原因和允许动作，由同一轮次纠正；不能把审查已确认合同变成重新报价，也不把错误提示的改进当作新增授权。

本单验收器回调由SDK绑定当前身份、作业和交互，模型不传profile、UUID或会话；同一本单同内容复用原上传记录，不因宿主调用ID改变而重复准备；每个quote作业至多准备32份包。SDK上传前复用原A2C清单校验，明确返回reads等格式错误；reads声明合同规格/材料字段路径，不是交付文件名。平台对最终包完成原A2C核验后才保存并返回引用，不生成已知无效的公示资源。原输入、待核上传和已取得引用由SDK保存，显式恢复先核原上传，再把已准备引用带回原Session。收到真实引用后才能填入quote；上传未知时保留原输入并结束本轮，核对后恢复，不能编造引用继续。报价决定已记录、待批准审查或生产阶段均不得再创建本单验收器；已签验收标准不能被此入口改变。

### 原拟约任务的恢复

| 检查 | 规则 |
|---|---|
| 查询 | 本机服务管理入口按所属profile查询原taskRef；SDK保存并返回关联，用户不手抄UUID。任务状态与恢复入队回执分别展示 |
| 可续接证明 | 仅quote阶段、验收器上传结果未知、原宿主轮次明确返回completed或failed终局且Session已保存、尚无报价决定；SDK保存已结束轮次的事实。进程重启或上传pending本身不构成证明，普通模型异常和其他未知效果保持unknown |
| 显式恢复 | 本机用户明确要求后调用provider.task.resume；核原任务、服务身份、交互、Session、定义摘要、原期限及可执行能力。暂停新接单不阻止已承接任务的恢复 |
| 持久入队 | 调度器同事务保存恢复操作回执与原作业续接；相同operationId重传返回原resumeReceipt，并另列currentTask，不因后续再次unknown而重新入队；同操作指向另一任务报冲突 |
| 再执行 | 原作业先核同内容上传，再把preparedVerifiers带回原Session。调用A2C Provider.resume_request及原finish，复用原A2C任务、请求、材料核验、拟卡费凭证与respondWithin，不重新request.submit |
| 新轮次 | 真正调用宿主前清除上次可续接证明；若新轮次结果不明，不能沿用旧证明。SDK仍使用原会话串行、模型并发及容量约束，不提供任意任务重跑入口 |

### 原生产任务的恢复

本机所有者明确要求继续已开工合同的生产时，复用上述查询及恢复操作。此入口仅续接首个尚未交付期次的原生产作业，不重新开工，不回放旧工具调用，不改变原卡、已签验收判据、业务技能、工具权限或Session。旧失败轮次、自测报告及候选成果保留，续接由模型在原权限内修正成果。

| 核验对象 | 推进条件 |
|---|---|
| 原业务 | SDK核原服务身份、作业、交互、合同与期次的绑定及原签名；合同仍在履行，当前期次尚无交付或验收，未解除、结清或被禁止继续；原环节许可仍有效，不存在未答复或已拒绝的受保护环节 |
| 期限 | 复用原A2C时序、实际开工及环节停表规则判断仍允许的履约；不改签名时点、不重置期限。上游允许迟延履约时保留原迟延及其协议后果，不称准时；原协议已禁止继续时拒绝，不由SDK另建期限状态机 |
| 业务效果 | 程序逐项核对该合同当前期次的原调用台账及协议原件。每项已开始调用均有合法、可解释的终局结果；缺result、unknown、仅有observedResult而输出尚未核验、交付/签署/付款/外部通知结果未决，均保持待核对，所有者确认也不能越过 |
| 宿主与排他 | 原Session和冻结定义可用，连接及宿主可执行；本机无该作业、交互或Session的活动执行者，按原串行锁和模型名额入队。进程消失、运行时重启、空闲元数据或本地日志单独不能证明原轮完成及全部效果已知 |
| 运行时证明 | SDK亲自接收原Host轮次completed或failed终局后，持久保存真实来源，绑定原轮、请求、作业、身份、交互、Session、定义摘要、合同、期次及已核对效果摘要。未知、取消或未结束不生成此证明；模型可写的工作目录及runs日志不能充当权威来源 |
| 原生工具效果 | Host终局只证明该轮结束，不证明原生工具的所有本地或外部效果均已收敛。SDK须有可核验的原效果记录，或进入下文所有者审阅；实际仍有未决效果则停止。不得仅因SDK业务回调均有result便认定任意Shell等原生效果安全 |
| 查询展示 | 返回canResume、resumeReason及recoveryMode（runtime_verified或owner_review）；不具备任一恢复依据时recoveryMode为空。需审阅的候选标记requiresConfirmation=true且canResume=false，允许申请本次审阅，不表示可以入队；真实批准及程序复核均满足后才可执行。已核验的运行时证明与仅有待审阅诊断材料分开展示 |

当原版宿主没有权威原请求回查、SDK未保存可信终局或原生效果需要本机所有者核对时，只能申请一次真实本机审阅确认。预览列出原轮证据来源及其局限、原服务/作业/合同/期次/Session/定义、诊断原件摘要、程序核对的本单调用与结果摘要、未交付事实，以及待核对的原生效果范围。所有者须实际确认原轮已结束且所列原生效果已核对、允许在原权限内继续；材料不足、无法确定非活动或任一效果仍未知时不批准。SDK记录为所有者审阅声明，不生成或冒称程序回查的Host终局。外来消息、模型生成的confirmed/证明JSON和笼统的继续文字均不能替代该页面决定；获准自动操作的代理须如实记录代理身份和实际审阅范围。

SDK决定使用运行时核验还是所有者审阅，不接受调用方任意选择恢复方式或上传自制证明。申请确认和入队前均重新核上表中程序负责的原件、效果、状态和排他条件；预览所绑定的原轮、证据、工具结果、合同进展或权限变化时旧确认失效。确认拒绝、过期或缺失不入队，历史unknown不因申请或批准被改写为completed。

恢复操作原子保存绑定本次原轮及依据的resumeReceipt，并续接原作业；同operationId重传只恢复该回执，不能因后续新轮再次unknown而再入队。实际调用Host前使上一轮恢复证明及批准失去执行资格，保存新轮关联；崩溃后不得借旧证明再启动。每一新轮若要再次恢复，须重新核对该轮及其效果；旧失败、自测与原审批记录保持可追溯。暂停新接单不阻止已承接合同按此条件恢复；原协议期限不因恢复而延长。

quote 工具明确区分三类验收器引用，不要求每项交付同时包含三类。保存业务决定前复用 A2C 校验卡结构、包摘要与清单种类；错误返回本单准确校验原因，由原模型轮次修正，不自动删改业务条款，不因此重收费或另起委托。

待批准模式的签2即成约，不能用 decision 给多个未获用户具体确认的候选预先复签。批准或签署结果未知时恢复原操作，不生成另一份承诺；拒绝和过期均返回实际原因。

待批准的 held 只允许接收原签1卡及审查，不允许直接签2。原 Provider 审查回调完成业务检查后提交容量，提交成功才返回批准；失败返回真实拒绝，不由模型自行绕过。这样服务方能先取得提交所需签名原件，也保留签2前的原子容量保障。

环节授权经原交互和任务回到委托方，个人助手端 `assistant.delegation.answer_step` 消费当前请求绑定的真实用户答复，并调用 A2C 原语返回同意或拒绝。服务方 SDK 核对 stepRequest 摘要、签名、当前阶段和期限后恢复；拒绝不能当作同意继续执行该动作。授权等待及期限计算仍遵守 A2C，服务方不能替委托方回答。业务工具可按服务配置扩展，不强制所有服务只使用官方样例工具；任何新增外部效果都须受本地授权约束。

生产工具的上下文继续绑定原交互、原 Session 和固定 Agent 定义；完整调用与等待规则见 [A2C 适配](../../共用运行时/接口/A2C适配.md)。request_step 输入 step，SDK 派生原卡和期次，返回原请求及等待状态；selftest/deliver 的 files 以交付文件名为键，每项含 mediaType，以及 text、bytesBase64、artifactPath 三选一。artifactPath 仅指本次工作区 artifacts 下的相对文件，不接受任意本机路径。自测只返回实际报告；deliver 只有取得原签5才返回已交付。

发出环节请求或交付后，本轮停止产生新的业务效果，等待真实答复或本期验收及应付款凭证；后续阶段由同一 Session 续接。业务工具读取原授权状态，不以模型称“已同意”为凭据。原任务的控制收件保持可用；宿主缺失、离线或原定义不兼容时，明确停止新生产，不另开一个无历史的 Session。

## 仲裁操作

provider.dispute以profile、原taskRef、ground及必要period/材料引用定位本单；SDK由原任务的交互取得admission，取平台preview并核其对象为本单已处理的卡或原提案请求，不成立直接返回rejected与reason，成立后由本机用户独立确认再提交arbitration.request；材料只收本服务已上传的完整FileRef。provider.dispute_status以所属profile及caseRef查询，只返回本服务近期任务所涉对象的已验签案件。两项与助手端共用共用运行时的DisputeFlow与case_status。SDK从原本单记录确定admissionId，不接受模型替换合同、身份或Session。原案件恢复与助手端共用取证/验签，不另建服务方仲裁引擎。

收到平台原contract.ruling（发送者为平台系统身份）后，SDK不信通知正文，按本单admission读取当前案件，核案件对象为本单已处理的卡或原提案请求，并验市场签名与公开决定证据；进程启动后每单首次排产前也读取一次，错过通知同样恢复。已裁定则在本单保存caseRef与裁定摘要，停止新生产轮次、普通结清与解除结清，排空未开始工作并拒绝在途轮次的新工具动作；原写入者全部收敛后以provider.arbitration作业提交arbitration.finish（caseRef、admissionId），结束回执保存于本单。平台拒绝（如原应付款尚未齐全）时保留占用并在30秒后以新操作标识再提交；结果未知只消费原操作的已存响应，不另起结束：未答复的原操作留在本地发件箱，每次重连由连接以同一operationId与原载荷重发，平台迟到的受理或拒绝落库后据此收敛为completed或rejected；中断时原操作从未写入发件箱的作业确定未发出，记为rejected（not_sent）后立即以新操作标识再提交。案件读取失败时不排新轮次。已裁定卡不得走普通Provider.close或伪装解除；债务和容量的规则见[委托中心](../../../平台/委托中心/接口/仲裁.md#裁定执行与容量收尾)。

## 解除处理

原 termination.quote/notify 由本单协议接收器处理，不依赖模型轮询。先核本单原有效签1；报价策略属于本机服务配置，默认沿原 A2C 策略，不能为演示将费用静默改为0。收到合法通知后停止新生产，原执行和工具收敛后再结清；实际终止、退款待办和外部效果未知通过既有任务查询返回。

协商负余额只按原签名解除记录与实际已付定金，复用同一 AP2 Port 及 Provider.refund_termination；付款身份为本单原服务方，收款单由原个人助手签发。退款成功保存原付款及凭证；余量不足、离线或结果未知保持原任务待处理，不伪造完成或重复付款。无需新增个人助手收费接口、退款合同字段或另一套付款引擎。完整规则见[A2C适配](../../共用运行时/接口/A2C适配.md#解除与结清)。
