# 服务方端

## 目的与范围

为用户自己的九问提供服务配置、模板起草、确认后公示、接单策略、入站委托的本单报价/批准/生产/交付、解除结清与显式恢复；普通服务和官方服务使用同一入口，主动连接平台，不要求公网 IP。不实现共用的连接、存储、调度、确认、A2C 适配与宿主契约（见[共用运行时](../共用运行时/接口.md)），不决定容量与承诺状态（以[委托中心](../../平台/委托中心/接口.md)为准），不导入官方服务目录或具体宿主。调用方是共用运行时与宿主适配的装配入口、官方服务的资源构造与启动器、本机用户经产品技能脚本发起的 `provider.*` 操作，以及运行时为入站委托调度的宿主本单轮次。

## 独占数据与配置

| 数据或配置 | 说明 | 存储 |
|---|---|---|
| 服务配置 | `provider.services.<profile>`：instructions、skills、resources、native_tools、max_active_delegations（1—1000，默认 1）、accepting；`provider.require_publication_authorization` | 实例外置配置文件的 `provider` 组，契约见[配置](../共用运行时/接口/配置.md) |
| 管理操作记录 | 模板起草、预览、发布已签请求与回执、发布授权来源、验收器上传及本单验收器上传 | 运行时检查点 `provider:<agentId>` |
| 接单策略镜像 | 待处理策略写入、上次已处理配置快照、原操作回执；实际策略在平台 | 检查点 `provider-policy:<agentId>` |
| 入站意向 | 每条 delegation.intent 的预留回执与模板，或拒绝原因；先存后发的回复封套 | 检查点 `provider-inbox:<agentId>` |
| 本单协议记录 | 冻结的服务配置与业务工具策略、业务决定、工具尝试、生产调用台账与交付文件、A2C 卡与任务 | 共用运行时 `ProtocolStore`（按身份与交互分区） |
| 恢复证明 | 拟约轮次的可续接证明；生产轮次记录与运行时终局证明 | 检查点 `provider-recovery:<agentId>`、`provider-production-recovery:<agentId>` |
| 本单工作区 | 生产成果 `artifacts/` 与诊断 `runs/`，模型可写，不作权威证据 | `<home>/roles/<profile>/sessions/<interactionId>/` |

## 接口

规则正文在子页；本节只列调用标识，先按下表找到子页，只读所需的一页。

| 子页 | 内容 |
|---|---|
| [配置与管理](接口/配置与管理.md) | 服务配置、管理操作、接单策略的归属与恢复、模板起草与公示确认、部署发布授权与续期、暂停与失败处理 |
| [接单与任务恢复](接口/接单与任务恢复.md) | 入站接单与本单任务工具、原拟约任务与原生产任务的恢复、仲裁操作、解除处理 |
| [产品技能](接口/产品技能.md) | `ioalab-provider` 技能包的目录、管理与本单两种入口、流程页契约、运行与验证 |

管理操作经本机 IPC 以 `provider.<名称>` 调用，统一返回 `{status,data,error}`；平台 HTTP 错误按原错误对象透传，A2C 校验失败为 invalid_input，平台 5xx 或网络中断为 unknown_result，recovery=resume_original。同 operationId 同参数恢复原结果，异参数 id_conflict。

### 装配

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `ProviderRole(host,tools_by_profile)`、`bind(runtime)` | 装配服务方角色并向运行时登记管理操作与作业处理器 | host 为 `AgentHost`；tools_by_profile 为各 profile 的本地业务工具；返回 operations（[操作目录](../共用运行时/接口.md#装配与常驻实例)中 handler 为 provider 的全部操作，参数按目录的输入形状检查）与 jobs；无 service 身份时为空 | 配置无效 invalid_input，不启动 | external_provider、provider_profile_recovery |
| `start`、`wake`、`quiesce`、`close`、`ready(profile)` | 控制线程起停；ready 表示公示有效、宿主与技能工具可用 | — | 控制线程 15 秒未停抛错，保留本地所有权 | provider_admission、provider_profile_recovery |
| `validate_provider(value,profiles)`、`EDITABLE_SERVICE_FIELDS` | 服务配置的纯校验与可编辑字段 | 返回按 profile 的服务配置 | 未知字段、空 instructions、越界容量或非法工具权限 invalid_input | configuration_edit、access_products |

|---|---|---|---|---|

| `provider.verifier.publish` | 上传验收器源码，取得真实包引用 | profile、verifierId、source，可选 reads、kind → {id,uri,digest} | 语法或清单错误 invalid_input；回执不符 protocol_error | provider_authoring、task_verifiers |
| `provider.categories` | 读取平台 A2X 叶类与路径 | {} → 分类目录 | 平台错误原样返回 | — |
| `provider.preview` | 解析分类并给出可发布摘要 | service → contentDigest、expectedRevision、nextAction；省略 categoryId 时先返回 accepted 与 job | 待选择时无 nextAction | service_publication、provider_authoring |
| `provider.publish` | 用户确认或部署授权后签名公示 | service、contentDigest、expectedRevision，可选 confirmationRef → waiting+confirmationRef，或 publicationReceipt 与 currentPublication | 摘要或修订不符 id_conflict；分类失效 category_required；要求授权而不匹配 forbidden | service_publication、publication_authorizations |
| `publication_terms(protocolId,service)` | 公示条款摘要，供部署发布授权比对 | 纯函数 → 摘要 | 缺身份或服务 ValueError | publication_authorizations |

| `provider.reputation`、`provider.tools.list` | 读取已验签信誉；列出本身份已装配的业务工具策略 | profile | — | resident_fulfillment、provider_business |

### 接单策略

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `provider.pause`、`provider.resume` | 关闭或开启新预留 | profile → policyReceipt 与实时 currentPolicy | resume 时未就绪 not_ready，recovery=restore_service；平台修订冲突原样返回；写入未知 unknown_result，先恢复原操作 | provider_admission |
| 入站 `delegation.intent` 处理 | 就绪时自动 `request.start` 与 `admission.reserve`，回复 reserved 或 rejected | 平台消息，无调用方输入 | 满额、暂停、过期等回复原因；网络未知保留待重试 | provider_admission、delegation_admission、quote_admission_rejection |

### 本单任务工具

宿主轮次内由 SDK 绑定当前身份、交互、Session 与阶段；模型不传 profile、taskRef 或 UUID。错误阶段返回 forbidden 与当前允许动作。

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `provider.task.quote` | 提交报价或拒绝原因 | 以交付件名为键的 acceptance、acceptWithin、lineItems，或 reason → recorded | Schema、卡或包校验失败返回原因，同轮修正 | resident_delegation、task_verifiers、rule_boundaries |
| `provider.task.decision` | 批准或拒绝待批准复签 | approved、可选 reason → recorded；批准后先提交容量再复签 | 容量提交失败为拒绝 | resident_delegation、official_service_runtime |
| `provider.task.verifier.publish` | quote 阶段打包本单验收器 | verifierId、source（≤64 KiB），可选 reads、kind → 引用 | 决定已记录 forbidden；上传未知结束本轮 | task_verifiers、provider_task_recovery |
| `provider.task.request_step`、`provider.task.selftest`、`provider.task.deliver` | 请求环节授权、合同验收器自测、原协议交付 | step；或以交付文件名为键的 files → waiting、自测报告或 delivered | 环节未获同意 forbidden；工作区外路径 forbidden；效果未知不重做 | resident_fulfillment、resident_multiperiod |
| 本地业务工具（`tools_by_profile`） | 生产阶段的已配置业务动作 | 原输入 Schema → 原结果 | 缺所需环节同意 requires_authorization；输出不可序列化 invalid_tool_output | provider_business |

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| `provider.tasks.get` | 查询本服务最近 100 个任务或指定任务 | profile，可选 taskRef → phase、status、canResume、resumeReason、recoveryMode | 不存在的 taskRef not_ready | task_recovery_receipts、provider_task_recovery |
| `provider.task.resume` | 显式续接原拟约或原生产作业 | profile、taskRef，可选 confirmationRef → accepted、resumeReceipt、currentTask；需审阅时 waiting | 不满足条件 unknown_result，recovery=reconcile_original；原状态已变 id_conflict | provider_task_recovery、provider_production_recovery |

| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |
|---|---|---|---|---|
| 解除报价与通知接收、`provider.settlement` 作业 | 原写入者收敛后按余额退款并 `Provider.close` | 平台消息，无调用方输入 | 执行未收敛保留占用；结果未知恢复原关闭 | resident_termination、termination_control |
| 正常结清 | 全部期次验收且应付款齐全后自动关闭原卡 | — | 缺凭证不关闭 | resident_fulfillment |
| `contract.ruling` 处理、`provider.arbitration` 作业 | 裁定后停止新履约，排空原写入者后提交 `arbitration.finish` 结束回执 | 平台系统消息或每进程首次核对本单时的案件查询，无调用方输入；见[仲裁操作](接口/接单与任务恢复.md#仲裁操作) | 案件读取失败或验签失败不排新轮次；原写入者未收敛保留占用；平台拒绝 30 秒后换新尝试；结果未知只消费原操作的已存响应 | arbitration_processing |
| `provider.dispute`、`provider.dispute_status` | 申请仲裁、查询案件 | dispute：profile、原 taskRef、ground，可选 period、materials、confirmationRef；dispute_status：profile、caseRef；见[仲裁操作](接口/接单与任务恢复.md#仲裁操作) | 理由不成立 rejected 并给 reason；未确认 waiting；非本服务任务或对象 forbidden；同操作异参数 id_conflict | arbitration_cases |

## 不变量

| 规则 | 说明 |
|---|---|
| 公示授权 | 必须取得本机用户真实确认或匹配的部署发布授权后才签名公示；模型的 confirmed 不得替代；同一 operationId 的授权来源首次选定后不变 |
| 容量在签前 | 有效承诺形成前必须先取得平台预留；待批准模式必须先提交容量再签 2，零拟卡费提案在提案前提交 |
| 策略权威 | 平台接单策略是实际状态；未取得真实回执不得宣称已暂停或恢复；重启、重连、发布或同配置重启不得重新开启已暂停的接单 |
| 暂停范围 | 暂停只关闭新预留；已有预留、合同、控制消息与显式恢复继续 |
| 本单固定 | 本单工具的身份、交互、Session 与冻结定义由 SDK 固定；来信不得进入管理操作，配置变更不得扩大既有合同能力 |
| 真实回执 | 没有签名、交付、付款或平台回执时不得报告相应完成；结果未知不得自动重做，只能查原操作或经 `provider.task.resume` |
| 原操作 | 同 operationId 同参数必须返回原结果，异参数必须 id_conflict；回执与当前状态分开返回 |
| 恢复限定 | 恢复必须续接原作业与原 Session，不得重新开工、回放旧工具调用或延长协议期限 |

### 验收条件

单模块的可验证条件；跨模块条件在流程页的“端到端验收”节。

| 场景 | 必须满足 | 测试 |
|---|---|---|
| 暂停与恢复 | 公示前可暂停；真实策略回执/当前状态分列，同配置重启及重公示不恢复。新预留拒绝，原有效 held 可提交、既有合同继续；容量单字段改变不改暂停，未知写入恢复原请求，旧 resume 回执不重新开启 | provider_admission |
| 本单验收器准备 | 无预置验收引用时可在原 quote 作业内打包并取得真实引用后拟卡；身份及 UUID 由 SDK 绑定，变换宿主调用 ID 复用原内容；错误源码/包摘要/种类及越界字段拒绝，上传未知先保留原记录；待批准、生产或决定后拒绝；不改公示、配置或已签判据，完整履约仍经原 WASM 验收和 AP2 付款 | task_verifiers |
| 原拟约恢复 | 无原模型结束证明、已返回决定、其他阶段/身份、过期或原 Session 变更时不可重跑；已核验验收器准备中断可经公开任务查询及显式恢复，同事务保持恢复回执与原作业，丢回复/重传/并发/重启不重复入队；原 UUID/Session/A2C 任务/费用及期限保持，最终真实验收付款结清 | provider_task_recovery |
| 显式生产续接 | 按[原生产任务的恢复](接口/接单与任务恢复.md#原生产任务的恢复)分别验证真实 Host 终局来源与所有者审阅来源；工作区伪造日志、空闲/重启、无真实确认均不得伪造证明。未决业务或原生效果、已交付/验收/解除、错误身份/合同/期次/Session/定义、未批准环节及活动执行者拒绝；正确原件和已核效果仅续接原作业。预览变化、拒绝/过期、重复操作、并发恢复、入队/开始前崩溃和新轮未知均不复用旧批准或重复执行；原失败、自测、签名、费用及历史结果保留 | provider_production_recovery |
| 服务方起草与错误输入 | 原 A2C 业务字段、多交付件与真实平台支付声明；有效起草同操作重传/重启保留原有效期，异内容冲突；不签署或公示，不改业务定价；错误输入、鉴权、限流及跨站拒绝使用统一对象，已知拒绝不成为未知结果 | provider_authoring、provider_market_rejection |
