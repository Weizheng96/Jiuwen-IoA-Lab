## 内部分区

| 分区 | 文件 | 职责 |
|---|---|---|
| 管理与公示 | `publication.py`、`terms.py`、`verifiers.py` | 管理操作分派、模板起草、分类预览作业、确认或授权后签名发布与索引恢复；条款摘要与授权覆盖判断；验收器校验、语法沙箱、上传与本单包记录、平台错误映射 |
| 发布与履约链路 | `publication.py` 的 `ProviderRole` → 同目录执行模块 | 真实确认后公示，统一运行时处理接单、生产和恢复 |
| 配置与策略 | `configuration.py`、`admission.py` | 服务配置校验；接单策略的初始化、暂停恢复与未知写入的原操作恢复 |
| 入站执行 | `execution.py`、`policy.py` | 控制线程扫描、意向预留与回复、协议消息排程、按交互建 A2C Provider；公共读取借用共用Network同步池和系统CA，无独立事件循环；报价与批准轮次的宿主定义、本单工具与决定保存 |
| 生产 | `production.py` | 生产工具、交付文件解析、按期次排产、生产台账与本地业务工具调用、正常结清 |
| 恢复 | `tasks.py`、`production_recovery.py` | 任务查询、拟约可续接证明、生产轮次记录、恢复候选与所有者审阅、续接校验 |
| 解除 | `termination.py` | 原写入者排空、余额退款、解除后关闭与恢复 |
| 裁定收尾 | `arbitration.py` | 收到 `contract.ruling` 或每进程首次核对本单时读取并验签当前案件；已裁定则停止新生产、普通结清与解除结清，排空原写入者后以 `provider.arbitration` 作业提交 `arbitration.finish`，拒绝后按间隔换新尝试，未知只消费原操作的已存响应，从未写入发件箱的中断作业记 not_sent 后立即换新尝试 |

## 存储与迁移

本模块无独立数据库与迁移，全部写入共用运行时的 `runtime.sqlite` 检查点与 `ProtocolStore`；命名空间见[接口](接口.md#独占数据与配置)。作业处理器以 `provider-a2c-v1`、`provider-control-v1`、`provider-production-v1`、`provider-settlement-v1`、`provider-arbitration-v1`、`provider-preview-v1` 版本登记，改变作业载荷须换版本并由共用运行时处理旧作业。

## 内部接缝

| 接缝 | 用途 |
|---|---|
| `ProviderRole(host=…)` | 用显式 `AgentHost` 替身驱动报价、批准与生产轮次，或模拟宿主终局、取消与不可用 |
| `ProviderRole(tools_by_profile=…)` | 注入本地业务工具替身，核环节同意与未知效果 |
| `runtime.connection.call`、`account.api` | 在策略写入、发布或上传处模拟丢响应，断言恢复原操作而非重做 |
| `runtime.confirmations` 的时钟与页面驱动 | 公示与生产恢复的批准、拒绝、过期 |
| `verifiers._check_source` | 验收器源码在目标语法沙箱中编译而不执行 |
