# A2C协议

## 目的与范围

本仓维护A2C合同协议SDK，唯一源码在src/a2c，安装名与公开import仍为a2c。平台、角色SDK及官方工具复用本模块的字段、签名、期限、验收及AP2规则；不依赖外部A2C仓库的构建、下载或发布。业务决定及执行资格由调用方持有，本模块不替代用户批准。

## 独占数据与配置

| 数据或配置 | 说明 | 存储 |
|---|---|---|
| 协议原件与任务 | 原签名卡、请求、材料、任务及延迟恢复检查点 | 调用方注入的Store；SDK适配可提供持久命名空间 |
| pending_countersigns | 同原taskId的原body、摘要、材料、reviewed、decisionReturned及明确协议失败terminal；不是第二合同状态机 | 原Store |
| 材料恢复封存 | 新准备任务封存原template及其payload/原件摘要、body/bodyDigest、需review文件字节/摘要、reviewPlan、原信息授权引用及原绝对截止；复用原pending表，不持久化host/SDK执行账本 | 原Store |
| 密钥与模型 | 明确注入Signer/Directory/model，模块不读取业务配置或另仓 | 所属调用方 |

### 材料恢复字段与守卫

MaterialReviewScope是核心生成的只读原件投影：taskId/op/provider/client、requestId/version/requestDigest或cardDigest、templateDigest/原件摘要、bodyDigest、需review材料(name,digest)、原informationAuthorization原件摘要/delegationScopeDigest、原签名时点/response绝对截止、按material/verifier id/digest的reviewPlan。不含SDK私有结构、私钥或可由模型传入的proof；摘要不能替代真实授权。SDK权限、原scope及执行证明归[本地执行与恢复](../客户端/共用运行时/接口/本地执行与恢复.md)，宿主观察及原请求事实归[宿主提交](../客户端/共用运行时/接口/宿主提交.md)，本页不重复其规则。

`guard(scope)->None`由受信调用方注入，prepare及实际finish前各核一次。只消费本地原scope/权限/代次和完整观察子项的已核事实；回查网络必须先在调用方接缝完成。guard在原Endpoint锁内调用，但不在Store事务或SDK全局scope锁中回调；调用方不得持有需等待A2C的SDK锁进入A2C，guard不得等待可能反向调用A2C的线程/锁。可使用不可变资格快照加原执行租约代次的非阻塞重核；竞争/过期则保留等待或拒绝，由调用方原控制异常表达，不把暂不可续接伪成已审/批准或明确协议失败。ModelPort/context hook不再反向调用同task的恢复入口。实际锁顺序由SDK owner落实并定向验证。

MaterialObservation的稳定身份为(taskId,op,subjectDigest,materialName,verifierId,verifierDigest,ordinal)；ordinal由原runner当前`len(responses)`生成，从0开始，不能来自need/model正文。needDigest和准确files digests仅作同元组冲突核验，不用于合并不同次数。`material_observation_context(context)`只建立本次纯上下文，包裹原ModelPort(request,files)一次调用；不引入第二模型来源/链。含skill观察的可恢复scope必须接线此元数据；原两参ModelPort调用接口不变，不扩展P40/selftest。调用方只复用其原操作结果与真实执行事实，本模块不存宿主operation/nonce或另建模型账本。

新pending在最初准备时封存原template/body/需review文件及授权引用，按payload摘要与真实签名验证其对应原对象，不以Store的键名代替value核验。材料验收成功才持久reviewed=True；原决定及明确协议终态持久防重，工作中active仅为当前进程内存/原锁的排他与重入护栏，不持久化为崩溃后永恒active。重启时内存护栏消失不代表旧原生已停，跨重启资格仍须guard原证明。

旧pending缺seal时，本次新prepare明确拒绝且不补写；保留原记录及旧reviewed-only接口。旧任务并非永久不可恢复：显式迁移须先完整备份，并取得可验证的原SDK message/body fingerprint、原材料字节/声明、信息授权与委托scope引用、原模板及对应签名/公开key、原任务/版本/截止和执行结果证明。模板来源可为历史存档，或经实际重算templateDigest、验原provider/market签名且与原消息证据对应的Store候选；仅以digest为Store key或拿另一份最新模板不够。A2C owner核原件一致/仍未决定未终态及实际原权限/截止后，才可显式追加seal与来源记录，不改原task/fee/body/card/签名/期限/reviewed；证据不足保持拒绝。首实现不自动迁移旧记录，也不授权SDK写核心私有表；取得证据后须按上述契约经独立明确迁移入口恢复。

## 不变量

| 规则 | 说明 |
|---|---|
| 发行校验 | 包字节、资源、版本及NOTICE核验由[部署发行](../部署/接口.md#发行构建)唯一持有，本模块只声明同源交付要求 |
| 唯一源码 | a2c由本仓受Git管理的src/a2c构建；发行及统一客户端使用同一固定源码的字节，保留来源NOTICE，不从PyPI或旧vendor wheel补A2C |
| 恢复原件 | resume_countersign不运行policy、model、网络、材料验收或签名；必须原签1、无签2及后续签名，用原卡内JWK和无fetch Directory执行原verify_card，不截掉签名后验 |
| 决定边界 | 材料核验成功先持久reviewed；policy返回后先持久decisionReturned才允许签2。签署/保存/回执未知只能调和，禁止再生成签2 |
| 材料前恢复 | 旧resume_request/resume_countersign的reviewed守卫保持；新resume_material_review只接原未核材料任务，prepare不做模型/材料验收/联网/签名，finish沿原材料→reviewed→原policy/签名顺序，不能重handle或伪reviewed |
| 外部效果 | 调用方必须证明旧callback/observer停止且原role没有未知效果；进程重启、模型文字及取消回执不构成资格。本模块不承诺跨系统原子性 |
| 原期限 | 原respondWithin/validUntil与原签1时间不变；恢复不重handle、不重收费、不改授权/付款/容量边界 |
