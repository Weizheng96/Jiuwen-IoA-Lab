# 部署

个人助手可配置`IOALAB_CALENDAR_BACKEND=local|graph`与`IOALAB_SCHEDULE_FILE`。local使用该账号客户端目录内的可编辑schedule.json；首次显式执行schedule init，不自动补建丢失文件。graph保留原Microsoft读取授权流程。两者均以本地待接受预约补充冲突检查，通知邮箱配置独立。未设置backend的旧配置保留graph语义，避免升级后悄然更换预约依据。日程、备份、SQLite与凭据都保存在忽略的data/下；部署和技能配置必须让收件器与九问使用同一IOALAB_HOME及日程路径。

## 进程与数据

Linux + Python 3.11，venv + systemd + 可选 Nginx，不要求 Docker。核心与官方服务是两个独立进程与数据目录；用户九问与实验客户端不在核心进程中启动。

| 单元 | 命令 | 数据 |
|---|---|---|
| 核心 `ioalab.service` | `ioalab serve` | `IOALAB_DATA`：账号、市场、模拟支付、观察 |
| 官方服务 `ioalab-providers.service` | `python official-services/serve.py` | `IOALAB_PROVIDER_DATA`：服务密钥、合同、队列、交付与九问会话 |
| 实验客户端 | `python experiments/traffic.py`，按需启动 | 本地 SDK 身份、实验记录 |

首次安装先启动核心，幂等创建内部账号与分类内容；官方进程经公开接口登录、登记并公示模板，成功后服务才可接单。升级前分别备份两个数据目录，不以平台重启终止双方合同。原核心助手停止执行，旧数据只作历史查询。

管理员个人助手为第三个独立服务单元`ioalab-assistant`，独立配置/数据/九问venv；核心和官方服务不混装九问。安装支持锁定九问候选版本、自动配置ISC_001技能与默认免费接口。首次Microsoft设备授权与通知邮箱发件配置由部署者完成；测试模式与真实模式分离。

## 配置归属

| 变量 | 默认/含义 |
|---|---|
| `IOALAB_BIND` · `IOALAB_PORT` · `IOALAB_PUBLIC_URL` | 核心 127.0.0.1:8750，对外地址首次初始化锁定 |
| `IOALAB_DATA` · `IOALAB_SECRET` · `IOALAB_ADMIN_PASSWORD` | 核心目录、会话密钥、管理员口令；trial 口令至少12位 |
| `IOALAB_MODE` · `IOALAB_REGISTRATION` | dev/trial；open/invite/closed |
| `IOALAB_LOGIN_CREDIT` · `IOALAB_ISC_COUNT` · `IOALAB_AUTOSEED` | 每次成功登录赠100；ISC默认10；启动创建内部账号 |
| `IOALAB_LLM_API_KEY/BASE_URL` · `IOALAB_A2X_MODEL` · `IOALAB_EMBED_MODEL` | 核心仅用于发现，未配 key 走确定性检索；不作为用户模型配置 |
| `IOALAB_LLM_MODEL` · `IOALAB_LLM_CONCURRENCY` · `IOALAB_LLM_BASE_URL_FALLBACK` | 保留发现配置适配；官方生产模型读取独立九问配置 |
| `IOALAB_PROVIDER_BIND/PORT/PUBLIC_URL` | 官方服务默认127.0.0.1:8751；对外URL须供用户访问，与服务身份一致 |
| `IOALAB_PROVIDER_DATA` · `IOALAB_PROVIDER_CONCURRENCY` | 官方独立数据目录；有界生产并发默认2 |
| `IOALAB_SERVICE_MODEL` | 官方服务使用九问Process SDK的model.list返回的selection_key，例如qwen-plus#1；不使用网页资源ID。未指定使用独立九问默认选择；启动时只读校验可解析，否则不登记接单 |
| `IOALAB_SWARM_COMMAND` | JSON argv，默认 `jiuwenswarm-process`；通过进程模式发送服务定义与任务，不拼接 shell 字符串 |
| `IOALAB_STUB` | 显式测试桩，不调用真实模型，禁止生产模式缺依赖时自动降级 |
| `A2C_CACHE_DIR` | 每个执行方自己的 WASM 运行时缓存 |

消息保留与配额：IOALAB_MESSAGE_RETENTION_DAYS=30、IOALAB_MESSAGE_METADATA_DAYS=90、IOALAB_MESSAGE_PENDING_LIMIT=1000、IOALAB_MESSAGE_RATE=60、IOALAB_MESSAGE_TTL_DAYS=7。

管理员客户端配置以`deploy/personal-assistant.env.example`为配置字段入口：`IOALAB_BASE_URL/USERNAME/PASSWORD/HOME`、`IOALAB_RECIPIENT_EMAIL`（默认zhengw.cc@outlook.com）、`IOALAB_SWARM_WS`、`IOALAB_SWARM_BRIDGE_SECRET`、`IOALAB_NOTIFICATION_TRANSPORT`（smtp/agentmail）、`IOALAB_GRAPH_CLIENT_ID`、`IOALAB_SMTP_HOST/PORT/USERNAME/PASSWORD/FROM`、`IOALAB_SMTP_AUTH`（password/oauth2）、`IOALAB_SMTP_CLIENT_ID`（可复用Graph应用ID）、`IOALAB_ALLOWED_SENDERS`、`IOALAB_APPOINTMENT_RULES`。SMTP默认STARTTLS，465端口SSL；不提供生产明文开关。Outlook专用通知邮箱选oauth2，固定Microsoft SMTP端点与587端口；通过smtp-login登录通知邮箱、smtp-check只验证连接和身份，不发送邮件。calendar-login只登录被预约邮箱、只读日历；令牌分别保存在客户端的smtp-token.json与calendar-token.json。SMTP.Send与Graph权限不放在同一次OAuth请求。公开邮箱地址不表示公开密码或令牌；创建邮箱、应用注册与首次授权由部署者本人完成。九问独立环境另设`JIUWENSWARM_DATA_DIR`、`EXTENSION_DIRS`与`IOALAB_SWARM_USER_ID`；双方共享本地桥接口令，核心不持有。核心`IOALAB_ASSISTANT_PASSWORD`只控制首次预置管理员账号；trial未设置时生成到data/assistant.secret，迁移旧弱口令，不在日志输出。测试日历/SMTP仅由独立demo脚本显式选择，不进入生产收件器。真实规则、授权和副作用不由核心执行。

AgentMail部署工具使用固定官方API端点，登记邮箱与本地状态；默认复用已有登记，不反复注册或轮换密钥。验证成功后将通知邮箱、smtp.agentmail.to:465及API key写入客户端环境文件，保留平台账号、日历配置和已有本地身份。注册响应与密钥不入库，验证码不进入命令行参数或日志。首次注册网络结果不明时保留状态并停止，避免重复创建；AgentMail默认设置IOALAB_NOTIFICATION_TRANSPORT=agentmail，通过固定官方Calendar API发邀请，复用SMTP_FROM与SMTP_PASSWORD中的邮箱和API key；smtp模式保留原实现。发信器接口仍为check/send，不新增平台邮件组件。notification-check验证所选传输，smtp-check仅诊断实际SMTP；AgentMail的组织者日历不代替用户Outlook的真实可用性检查。

用户只配置 `IOALAB_BASE_URL`、`IOALAB_USERNAME`、`IOALAB_PASSWORD`；SDK本地目录可通过 `IOALAB_HOME` 指定。首次技能运行自动安装锁定 SDK，不向平台提交私钥。用户模型由自己九问配置，官方服务由部署者九问配置，核心发现单独配置。

安装脚本生成核心、服务方与独立管理员助手的systemd单元与配置模板，先核心后服务及助手；反代分别指向8750、8751，支持 `/ws/`。默认内部账号使用演示口令，试用限定内部网络。验证依次是版本检查、桩测试、独立进程协议闭环、真实九问接入、Linux安装；没有实测的步骤明确记未验收。

仲裁模型注册表IOALAB_ARBITRATION_MODELS使用JSON对象（模型标识到实际模型名称），默认为空，未配置时拒签skill验收器。模型端点沿用IOALAB_LLM_BASE_URL/IOALAB_LLM_API_KEY，缺配置则不注册；不伪造可执行模型。客户端普通L2验收可配置IOALAB_VERIFIER_MODEL及客户端IOALAB_LLM_BASE_URL/IOALAB_LLM_API_KEY，不从平台下载执行模型代码。

客户端可选IOALAB_MIN_QUOTES（1—8，默认1）配置在skill的settings.local.json或助手进程环境，仅SDK读取，核心不读取。me显示实际生效策略；最低数固化到新scope，旧scope不追溯变化。演示的三份偏好见独立示例，不能部署成所有账号固定三家。
