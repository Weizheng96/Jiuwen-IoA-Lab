# 三段领导演示

设计职责与数据边界见[管理员控制台](../设计/管理员控制台.md)。本文件仅规定镜头，不重复协议规则。

| 片段 | 镜头与操作 | 短字幕 | 证据 |
|---|---|---|---|
| 全局① | 管理者实时全景，多客户端并发 | 一个活跃的智能体互联网 | experiment来源、实际订单与消息 |
| 全局② | A2X与分类领域 | 找服务，先经过A2X | 发现事件、公开分类 |
| 全局③ | 消息中心与委托并行 | 委托与消息，两条交互路径 | 消息id与合同摘要分别关联 |
| 全局④ | 点击一名助手，再恢复全景 | 聚焦一人，看清关联活动 | 同账号聚焦，不修改业务 |
| 委托① | 左九问真实输入，右本人网络 | 说出需求，助手连接服务 | 九问会话与技能工具 |
| 委托② | A2X→候选服务，说明剔除理由 | 先筛条件，再比较报价 | 完整验签模板与实际候选 |
| 委托③ | 比较合同金额与验收标准；用户确认 | 把验收标准写进合同 | 已签合同与预算 |
| 委托④ | 服务生产与交付；点选对应组件 | 有据交付，本地验收 | 存证、本地WASM报告与签7 |
| 委托⑤ | 模拟支付；切服务方 | 同一笔委托，双方都可追踪 | 过账凭证、完成记录与收入 |
| 交互① | A设置精确允许账号与接口格式 | 开放接口，限定范围 | 白名单、inputSchema修订 |
| 交互② | B查询A账号，留言与预约 | 按账号交流，离线也可送达 | 实际消息及九问通知会话 |
| 交互③ | A读取本地时间安排与待接受预约，按规则处理 | 根据本地安排，确认可预约 | 本机有效日程；明确未读取私人Outlook日历 |
| 交互④ | 展示邀请，再由用户接受 | 接受邀请，会议进入日历 | Outlook真实界面；不伪造接受回执 |

全景允许样例服务，但必须持续标识仿真实验、真实协议与虚拟币。另两段正式用例要求真实九问与真实生产/通知依赖。每条字幕优先不超过20字；旁白可更完整，按音频时长留镜头，不用大幅加速压入等待间隙。
