# 配置边界

适用于定位既有安装、导入技能和配置原生扩展。

| 对象 | 处理 |
|---|---|
| 用户已有九问 | 保留安装、模型、权限和现有技能；先询查明确提供的命令/工作区，通过公开能力检查兼容性，缺能力明确未就绪 |
| 项目新建实例 | 独立环境、工作区和端口，可固定复现实验版本；不把实验安装流程当成普通用户接入要求 |
| SDK/适配包 | 安装在接入组件自己的环境，避免向九问环境追加或强制重装依赖 |
| 产品接入 Skill | 通过原生导入/选择入口使用；账号与密钥留本机受限文件，配置检查调用SDK脱敏入口。禁止读原文须写成全程约束，避免“不先读取”被理解为稍后可读；核验实际工具记录，不能只看提示词 |

已核对的 workSwarm 0.2.5b1 应用扩展机制：ExtensionManager 扫描工作区 `application_plugins/`；每个应用使用独立子目录，入口为 `extension.py` 与 `extension.yaml`。这与网页“我的扩展”、技能库和模型工具列表不是同一概念。其他版本先核对自己的公开支持。

扩展只带必要源码及清单，尽量不声明向宿主环境安装依赖。私有设置放本扩展命名空间；同件复用，异内容/身份先核对，不能覆盖旧回执。文件准备、扩展加载、能力就绪与真实消息可见分别判断；需要重启时由用户使用原生入口，不顺手重启其已有进程。

已核对的原生网页导入路径是“技能→我的技能→创建→上传技能”，支持含SKILL.md的ZIP；既有对话可在输入框键入“/”并选择技能，不必为选择而新建会话。导入后“去试试”将技能放入当前输入。上传控件隐藏时点击实际可见的上传区域并使用文件选择器；该版本覆盖导入会替换技能目录，运行配置应外置，更新前保留本机文件。验证完整资源是否保留，并检查skill_tool、实际流程页及SDK回执；不能假定首轮选中或读取后，每轮都会正确继续使用。即使原生选中也可能被同机业务技能分流；产品主指令应明确当前角色和执行方式，用自然业务请求实测，不能靠禁用用户技能或修改全局指令纠正。

路径来自实际原生加载结果、明确配置或安装元数据；不假设当前仓库、个人目录和安装目录相邻。只检查本次需要的配置，不遍历其他凭据文件或输出密钥。

导入业务Skill后，还须核对它是否真正装配进原服务。使用SDK公开配置摘要、runtime.status中的实际skillSources/skillSourceErrors及原身份比较；模板起草、公示预览或聊天中的新旧配置表都不能代替执行配置。配置摘要未变、也没有实际配置调用时，保留未切换状态。更新既有服务沿用实际名称，改名须来自用户明确要求；批准前核真实预览。

分别记录模型调度中的active与平台已接纳的active委托；前者为零不证明没有待签、待开工或其他在途业务。必要配置升级遵守原操作恢复和安全停止规则，保留原候选及合同。

同一声明版本下也可能存在不同内容的包或安装缓存。发布包、原生导入资源、SDK实际运行发行分别记录内容摘要及来源提交；只构建了新包、页面显示同一版本或安装目标已更新，都不能补算运行实例已切换。不同角色若使用不同批次包，验证记录分别列出，不用一方的新包摘要代表双方。

旧会话及其分支可能继续采用历史工具回执中的旧流程正文。新包专项验证须核本轮实际读取的流程页；必要时用正常新聊天携带原对象引用接续，不把旧正文的执行算作新包通过。分支还须核实际复制截止点，不能假定最后看到的助手结果全部被复制；原业务状态仍以公开查询为准。

项目环境、锁定源码和用户原版安装分别核版本与加载来源。发现同名依赖的代码或版本不一致时，不能拿项目环境的实验冒充原版；独立进程可用完整锁定资源做确定性实验，但仍须单独验证实际原生入口，不向用户已有环境强装依赖。
