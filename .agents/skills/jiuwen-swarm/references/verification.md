# 排错与证据

适用于接入失败、运行异常及完成核验。

1. 用明确的宿主命令、工作区与端口定位当前实例，先查同一个进程/会话。首次依赖安装给足终端运行期限；观察超时不等于进程结束，先查原进程与日志，不因暂时无输出重启另一套执行者。
2. 分层诊断：目录/依赖 → 公开能力与模型 → 技能正文 → 工具及权限 → 实际业务回执 → 网页显示。缺哪层就修哪层，不用宽松验收或额外救援提示掩盖错误。模型生成验收器时先核业务约定是否明确、ABI是否正确，再用原沙箱核实际成果和反例；不修改已签判据迁就错误输出。
3. 原生接口以当前安装包和锁定来源为证；必要时阅读对应原版源码，不凭网页资源名字推断SDK语义。上传覆盖后须核对延后弹出的确认及最终技能详情；文件选择或上传按钮返回不证明导入完成。runtime.install.status中的目标包发行与runtime.status中的运行实例发行分别核对，两者一致后才认定升级，不把旧实例重启当作新包生效。升级前后用公开只读快照比较原身份、配置摘要、公示绑定、接单策略及修订、原任务与占用；调度器无活动不等于合同占用为零，不能为升级自动取消或启动原业务。保留版本/提交与摘要，勿复制大段手册进本技能。
4. 在受控实验中验证真实会话续接、用户答复、实际工具效果和网页；模拟适配器、直接调用SDK与录屏分别标明证明范围，不能相互替代。旧会话先等历史加载完成；页面队列或发送点击不证明请求已提交，须核实际chat.send的原requestId及后端回执。已核对版本的session.get_metadata可能暂显idle，而原Web流仍在推进；终态须核同一requestId的final/error及流完成记录，不能仅凭idle取消运行或另开业务轮次。浏览器控制受阻不等于Skill失败，网站权限与九问/SDK业务确认分别核验。
5. 邮件、付款、签约或消息写入结果不明时先查原件；不为排错或重拍重复执行。只结束本任务确认拥有的进程，不按通用进程名批量关闭。

浏览器权限排查同时核对全局配置与当前会话配置；全局允许、扩展已连接仍可能受会话拒绝记录阻塞。只通过正常权限设置恢复目标站点授权，不直接改写权限文件或扩大权限；在原会话对同一地址实际读取成功后才认定恢复。仍被拒绝则停止该页面控制，不换浏览器、地址或API绕过，也不反复要求用户开启同一全局开关。

原生窗口控制无法可靠确认网址、目标站点权限拒绝、桌面抓屏黑帧分别定位；一个失败不能推定其他入口也失败或已恢复。工具明确安全终止本轮时按要求结束，不反复以同一窗口重试或改用系统输入绕过；后续只有外部状态改变才重新核该入口。原本已获准的网页标签读取是否仍可用，按其自身回执单独记录，不据此宣称原生窗口控制或整屏录制已恢复。

AX连接提示与实际画面矛盾时，用当前DOM和截图核对是否仍可见，再检查原生只读列表及连接证据；残留提示不能独自证明后端断连。页面可读、后端列表可用、模型执行及业务完成分别报告。

多角色网页演示须分别核对平台账号、九问数据目录、WebChannel用户及通知固定目标；不同浏览器或平台Cookie不自动隔离九问。已核对原版本地session.list按整个实例目录返回历史，user_id只作路由与观测关联；不同URL用户也不能证明列表隔离，须用独立数据目录实例或原版支持的部署路由实测。通知疑似发回自己时，先按原通知ID核所属IoA队列、实际收发身份、固定user_id及原生sessionId；正文“来源”通常是发送者，不能当作收件人。预约等后台任务没有新增网页会话时，核原消息的业务回执与已确认规则实际允许、调用的通知工具；Process执行、SDK收件和网页通知是不同证据。已有队列或扩展锁定旧目标时，沿显式迁移处理，不直接改user_id复用旧回执或覆盖另一个主人的扩展。

已核对的Process入口从标准输入查询时使用完整参数`--query-json -`，不能附加`--debug`；启动失败读取其返回的`process_cli_logs`诊断文件。Windows清理子进程环境时保留架构变量并显式设置`PYTHONUTF8`。依赖版本与pip检查通过后仍须验证真实入口及原生库加载；路径过长时缩短本项目环境目录，不改宿主或系统设置。

`inspect_workspace.py`适合重复的无副作用初查；它不读取配置正文、账号、模型密钥、会话或消息。发现必要的新诊断步骤时扩展对应脚本，验证成功和失败路径；不要把业务判断或用户授权做成脚本猜测。

配置完整性按明确的原配置文件比对摘要；原版公开运行会在`config/runtime_state/`生成本会话运行数据，不能把整个目录未增文件作为判据，也不能只比对旧文件就声称整个目录未变化。分别记录配置摘要和运行产物的增量。
