# 接口与会话

适用于公开接口适配和用户交互；具体字段以当前安装版本的能力响应、SDK和源文件为准。

| 机制 | 关键区别 |
|---|---|
| 原生 Skill | 核对实际流程页及调用；已核实skill_tool用relative_file_path读子文件，已核实skill_directory只在程序数据中，模型正文仅含内容和目录树；用公开JIUWENSWARM_DATA_DIR/默认布局计算唯一路径，不能从账号data_dir猜或扫描旧示例。SDK输入提供完整operation、类型、回执字段来源和最小命令示例，机械协议字段由SDK补齐；先对照工具原调用排除操作名被缩写，不能据模型对错误的解释改身份或接入配置。参数文件按原动作保留，新动作独立创建UTF-8文件，避免终端重定向编码及覆盖保护引发反复猜错 |
| Process SDK | 后台执行通道，可提供固定Agent定义、受限工具及Session续接；completed/failed终局与unknown分开，终局失败不证明业务副作用失败，续接仍由所属SDK核对效果范围；完成不代表网页历史已出现 |
| 宿主工具名 | 原生格式受限时使用稳定可读别名，碰撞才加短摘要；核声明、白名单与回调为同一映射。模型拼错名称不意味着应放宽白名单，别名也是固定Session定义的一部分 |
| WebChannel | 网页通道；已核对版本使用`/ws`并以`user_id`关联用户，不能把根路径403当作需关闭鉴权 |
| 确认页与浏览器 | 原生Windows窗口标题不足以核验网址时改用受支持的浏览器通道；确认SDK实际打开的浏览器已连接，连接另一浏览器不会改变系统默认目标。权限由用户配置，不提取入口令牌或伪造批准 |
| 用户确认 | 区分预览、申请确认、页面打开和真实批准；先取得waiting及原引用再打开页面，决定后恢复原操作。关联原生问题ID、真实答复、对象和阶段；模型文字或confirmed布尔值不是授权。用户明确要求自行批准的隔离仿真沿其持续授权自动点击真实页，核对具体对象及虚拟金额，不反复索要同类确认；记录为自动化确认，不能声称真人点击或扩大真实账号/资金权限。自动审批仍拒绝时保留原卡，说明具体拒绝原因，不另写批准记录 |

宿主处理入站业务时，将接收者已确认的处理说明、经过校验的请求和实际允许调用的工具声明一同传入；不能只传消息正文或靠工具名字暗示能力。外来数据不覆盖本地规则，程序仍执行权限与参数检查。

业务交互ID、模型运行request_id、原生Session ID分别保存。取得Session后先持久关联，再允许业务副作用；双方各用自己的Session，不要求共享ID。同一实际Session串行，不靠新建会话绕过未知结果。

运行所用模型键来自公开Process model.list的selection_key；已核对版本WebChannel对应models.list，二者操作名与返回结构不能混用。网页显示名称、模型配置资源ID与该键可能不同。网页会话选用模型与后台SDK宿主选择分别核对，页面已切换不证明后台也切换；修改资源型号后重新查询实际selection_key，SDK经安全停止、公开configure和启动应用新选择，保留原身份和未知作业。用无业务副作用的真实工具调用核兼容性；保存或连接测试不能代替任务正确性。命名权限策略只表明配置，不证明工具真实可用；技能加载不自动赋予生产工具或外部操作权限。

权限机制按入口分别核对：锁定版本的Process run_permissions不能证明普通Web Skill会话受限；原生单Agent专家的tools加载也是追加能力，不能直接当最终白名单。公开Tool/Rail专家扩展是另一条候选路线，需证明实际工具效果前拒绝、并行调用无共享状态绕过及守卫失效时停止；静态挂载、工具声明过滤或后台通过均不足以证明网页边界。未完成这些验证时保持明确未通过。

渐进工具声明可能经原生tool_call包装器调用目标工具。守卫须分别检查外层封闭参数和实际内层工具，只允许精确匹配的目标，不放行任意或递归包装；外层success可能包住内层拒绝后的空结果，正控还须核真实目标回执与效果。普通回调异常可能被框架吞掉，拒绝机制须用实际锁定版本验证，并覆盖并行调用；不改全局守卫状态或用户原版源码。

Web调用要区分确认帧与最终结果：已核对版本的history.get通过history.message事件流给出记录，accepted仅表示收到，须等done；该版本分页从1开始。

页面导航或刷新后，先等历史加载完成、输入框恢复，再选择技能并发送下一条请求。暂存队列不等于已发送；核对用户消息实际进入会话及原执行元数据。队列在恢复时消失，只有确认原请求未开始后才重新提交，不能因界面暂时空白重做业务。

原生问答残留时，用公开`session.get_metadata`仅传目标`session_id`核实际执行与待控制项；`runtime_resume`会订阅并重放保留帧，重放的旧问题不能独自证明仍在等待。若processing=false、全部执行及dispatch均已终态且waiting_control_id均为空，旧问答仍锁住输入，不把它当作真实待答。已核对版本的问答“取消”“跳过”会向后端提交答案，不是本地关窗；不靠重复作答清理重放。可通过正常“新建任务/会话”进入新的原生聊天，选择原产品技能，继续使用同一SDK配置、原taskRef及contractRef；先只读核对实际状态，再从原合同未完成的步骤续接。保留旧聊天及业务证据，不重新委托、注册或重签，不改原版源码、全局指令或私有历史。

实际仍有活动执行时，已核对版本的正常停止方法为`chat.interrupt`及`intent=cancel`，沿用真实会话的mode/work_mode/project_id，等待`chat.interrupt_result`再查询执行终态；收件accepted不代表已取消。该公开入口按会话停止，不提供按execution_id精准取消；先核其中全部非终态执行都属于本任务，不为清理问答重启宿主或SDK。

原生终端回显不能替代SDK原数据。先区分JSON语法、UTF-8文件、宿主代码页和业务值损坏；跨终端的结构化输出可用ASCII转义JSON保留中文，不能因回显乱码重写合同。大段既有非秘密素材及真实SDK回执，按产品共用calling.md的方法用本机UTF-8脚本提取组合，不要求模型逐字重抄。异步调用保存完整引用对象，并分别核查询和原作业终态，未取得源码不宣称已核验收覆盖。

本机公开历史审计用`python .agents/skills/jiuwen-swarm/scripts/read_web_history.py --ws-url <已观察的本机WebChannel地址及user_id> --session-id <实际会话ID> --out <本机私有新文件> --configuration-path <本轮实际配置路径>`；多个配置重复该选项，只比较元数据，不打开配置。脚本按页等done、按tool_call_id去重，只向stdout汇报调用元数据；不扫会话库或上传正文。变量转交等静态分析无法确定的调用须另核代码，未匹配不能当作访问隔离证明。已核对版本会向原网页广播历史事件，在模型终态后审计，恢复最新页面再继续，录制期间不回放历史。

网页通知可采用原生ApplicationPluginExtension及受控公开历史接口。历史持久化不自动建立列表所需的用户/渠道归属；先用原生会话创建接口取得真实ID并保存映射，不自己拼接web会话ID。固定目标用户、独立鉴权、稳定通知ID、输入摘要和持久回执；传入正文只作数据，不暴露任意RPC。响应丢失先查原回执，库重建不能被当作从未发送。后台会话、网页持久化、页面实际可见、用户已读是不同证据，不直接写九问私有历史数据库补齐。
