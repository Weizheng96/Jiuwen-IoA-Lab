# Linux部署诊断

常规操作仍只按[部署教程](../../../../设计/工程/部署.md)。本页用于出现异常后的判断和取证，不是第二套安装步骤。规则归[部署模块](../../../../设计/组件/部署/接口.md)，当前结果归[部署发行](../../../../设计/工程/实施资料/部署发行.md)；不要从历史失败推断服务器此刻仍处于相同状态。

## 固定来源与连接

- GitCode只含用户要求合入main后同步的提交；正式部署核GitHub与GitCode的main为同一完整SHA，服务器直连GitCode取这个SHA。合入前的受审候选按教程从已推送develop复制固定提交到独立目录，仍走同一安装入口并明确待发布身份。保存源码SHA、内容发行摘要、环境集合和实际运行身份，控制器更新不能冒充业务产物更新。未提交工作树、设计标签、同名wheel版本都不足以证明输入一致。
- Git请求用`git -c http.proxy= -c https.proxy= ...`，HTTP诊断用`curl --noproxy '*' ...`，SSH用`-o ProxyCommand=none -o ProxyJump=none`并核主机指纹。若系统TUN改变路由，这些参数并不保证物理路径直连；分别记录TCP连通、SSH主机身份和GitCode/TLS结果，不修改全局代理或放宽主机校验。
- 自动连接的唯一私有源为本机`.agents/server-connection.json`，现已替换为新服务器配置；旧配置与临时凭据源已移除，不再使用。JSON含format、host、port、username、password、host_key_type、host_key_base64、host_key_sha256和connect_timeout_seconds；不读取正文来写报告，不同步Git。使用`tools/server_connection.py`（开发环境paramiko 4），直接读取该JSON并固定校验已核主机公钥及SHA-256指纹，未知或变更密钥拒绝，不依赖旧服务器或另一份known_hosts配置。`--script`经stdin传输Bash，`--upload`经SFTP传输文件；不硬编码口令，敏感配置经已固定会话stdin或受限文件传输。人类使用自己的SSH凭据或已核alias，不绑定该文件。
- Git来源依赖采用随仓固定原件；普通包走已配置国内HTTPS镜像。先检查本地固定输入、目标锁及真实环境身份，不现场从GitHub/VCS补包或向运行venv手工pip修补。

## Linux消费者格式与权限

下表用于同类问题的定向前置检查，不要求每次部署重跑全部检查。用实际消费者解析证明，不以字符串搜索命中认定缺陷。

| 边界 | 已有经验及诊断方法 |
|---|---|
| 系统账号 | `useradd`的GECOS不能含冒号、换行；曾因此返回exit 3。现有合法标记实现仍须严格核同名账号归属，不能去掉归属验证来让创建通过。保留原部署id与角色，不接管未知账号 |
| systemd单位 | `WorkingDirectory`、`EnvironmentFile`等字段与`ExecStart`命令行使用不同编码；路径含空格、引号、反斜杠、中文或`%`时尤其要按字段渲染。在独立临时目录生成候选并用`systemd-analyze verify <单位文件>`检查，不能先安装到真实单位试错 |
| 嵌套Python与失败安装 | 解释器自身显示3.11不证明其base解释器相同；创建前核实际base的major/minor，新venv再核prefix、版本与pip。Linux产品入口明确用python3.11。失败env按产品公开归属/归档准入处理，缺归属保持unknown，不补pip、不删缓存或借探针切新目录绕过 |
| 环境与JSON | 必需`EnvironmentFile`不能加`-`静默忽略。物理LF分行与Python`splitlines()`对Unicode分隔符的处理不同，不能静默截断值；单行协议中的CR/LF/TAB按所属校验拒绝，不临时替换secret。JSON回执与环境文件分开处理 |
| 运行权限 | 三个环境的root导入成功不能代替服务账号可遍历父目录、读取安装资源。分别用所属core/agents身份检查；只调整本部署所属必要目录，不递归放宽状态树、模型、私钥或其他用户目录 |
| 配置投影 | 唯一平台参数归实例`platform.json`；已有模型、管理员人工配置及组件工作区保留。SDK/Swarm读取所属运行配置，不跨读开发者`.agents/llm_apikey`，不把模型密钥放argv、全局env、镜像或普通日志 |

格式修复必须进入项目、定向验证并双仓发布，再由服务器取固定SHA；不在冻结发行、已装venv、真实unit或元数据里打现场补丁。涉及公共组件先报告唯一owner，Windows/Linux不能各复制一套修法。

## 停止与失败初装

先保留原deployment id、三根、source/input摘要、操作id与阶段、current集合、单位InvocationID、cgroup及锁证据。查询输出可脱敏，原配置/原始回执留受限本地资料；任务request与日志不可改写。

正常停止使用教程公开入口。`waiting`只表示观察时间到；`deactivating`、主PID消失、IPC断开、父安装任务退出也不证明全部写入者退出。只有原所属进程组确证为空、core与SDK实际执行锁释放后，才能备份及启动新候选。不能按python/docker等通用名称强杀，也不能删锁文件释放所有权。正常排空失败时，维护处置须明确批准且限定确证所属对象，记录为异常清退，不能算正常停启通过。备份范围内的独立验收实例也须经自身公开入口正常停止并核空组、实际锁；正式单元全停不覆盖嵌套实验写入者。快照因特殊状态文件拒绝时，先定位活跃IPC或套接字，正常停其owner后续接原升级，保留原目录与失败记录。

旧版本曾出现core停止挂起，并对`ws_admin`断连后任务未收敛作过独立临时实例复现；这是历史证据，不代表最新发行已复现，也不证明Windows supervisor句柄问题同因。不要以增加停止等待或强杀宣称修好。

未完成初装不能直接套正常升级或另建根绕归属。当前公开CLI无`bootstrap-upgrade`，不照旧规范表或旧草稿调用；`repair-bootstrap`仅适用于该发布实际支持的窄控制器修复，不能用它更新业务候选。未发布跨版恢复草稿不能作为操作入口，实际切换必须重新核执行锁与原单位归属。若原source/input无法合法续跑，报告具体阶段及公开入口缺口，等待受审方案；不伪造completed、改父请求、重置账号或删除合同/付款。明确授权的归档后新装不能推广成默认清空旧数据。

旧版本的同IP登录5次/小时曾阻断官方准备；源码新策略与服务器实际生效分别验证。不能清计数、伪头换IP、删除SDK nonce、循环重试或用新控制器配旧候选冒称升级成功。SDK结果unknown先核原回执，用户批准不能由模型补签。

## TLS与反代专项

- 先确认可达来源：仅指定局域网可直连的服务器不具备公网 HTTP-01 前提。已确认此策略后停止公网签发重试，按教程由用户选择内部CA；不关闭源限制或用VPN凑可达。SSH不经代理不代表浏览器也直连，需另核Windows路由、系统ProxyOverride及目标IP例外；保持其他地址的代理配置。
- 内部CA的服务端系统信任、每个客户端系统信任与各HTTP库信任是三件事。CA私钥留服务器；只经固定SSH传公共CA、核指纹后按明确授权加入客户端当前用户库。Windows导入可能等待“安全警告”，需用户处理实际弹窗，再查目标指纹确已入库；命令发起不等于导入完成。浏览器仍有警告时不自动越过。
- 系统curl/readiness成功而SDK、官方授权或A2C执行握手出现ConnectError，先查具体请求URL、异常链与实际Python客户端的CA来源；先核 SDK 共用 Network owner、两角色注入与短期授权入口是否都采用同一信任策略；账号登录成功不证明模板、公钥或服务执行 HTTPS 已通。按[模型诊断](../../llm/references/instance-configuration.md#目标主机诊断)做真实TLS对照并回所属源码修复；不能在发行venv里改certifi或禁用验证。发布/索引就绪而执行未就绪时先查该段握手，不据此更换LLM。Nginx reload后核实际握手证书与指纹，不凭一次旧worker响应反复重签。

- IP证书核SAN的实际IP、默认信任链、到期时间及服务器续期任务。已有证书复用，不每次应用发布都签发。诊断先查`nginx -t`、指定续期timer状态及日志，再按教程执行一次dry-run；禁止`curl -k`或关闭验证。
- 历史环境中ACME协商失败，曾仅为独立Certbot进程指定受限`OPENSSL_CONF`约束TLS1.2后签发及续期dry-run通过。这个网络专项不能写成所有服务器的默认SSL设置；若确需复用，先以该主机实际握手证据确认，并确保续期service引用同一配置，不能只在临时SSH shell设置。主站TLS不降级，系统OpenSSL配置不改。
- 核心代理socket来源应为独立`127.0.0.2`，Nginx覆盖`X-IOALAB-Client-IP=$remote_addr`，实例只信确切代理地址；不把Nginx来源当本机豁免，不用用户XFF首值判本机。公网正常请求、伪造来源头与本机SDK分别验，配置正确不替代实测。
- 正式443、管理员回环隧道和三席的两个独立HTTPS入口分别验证。仅保存端口、不报配置错或本机监听成功都不等于公网可达。三席还需验证Cookie/票据受众、各席身份及模型sidecar归属、停止与整轮reset；不满足时保持未开放，不用同源路径绕隔离。

## 验收边界

按顺序区分：真实安装身份 → 核心/HTTPS/API → 目录与官方/助手连接 → HTTP/WS与权限 → 三类组件最小模型通路 → 正常停启及数据保留 → 可选三席。无邮件就明确禁用邮件业务；不为部署检查签约、付款或发送外部通知。裸模型API、llm=true、core200、浏览器打开登录页均只证明各自范围。原始证据留忽略目录，公开摘要只回收到部署发行事实索引。
