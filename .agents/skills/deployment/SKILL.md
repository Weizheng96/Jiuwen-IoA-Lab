# 部署

常规部署只按[部署教程](../../../设计/工程/部署.md)执行，模型配置也在同一教程完成。教程缺少实际公开入口时先核当前CLI并报告缺口，不编造参数、另建安装链或让普通读者串读多篇。

异常、旧实例恢复、所属进程未知或专项验收时，再按[异常与专项](references/operations.md)选入口。真实规则由[部署模块](../../../设计/组件/部署/接口.md)和[平台配置](../../../设计/组件/平台/平台基础/接口/平台配置.md)持有，技能不重复定义。

Linux出现发布源、SSH/代理、证书、systemd格式或旧初装恢复问题时读[Linux部署诊断](references/linux.md)。人类教程使用普通SSH，不依赖Codex私有配置。远端部署目标是用户提供的全新服务器，用户拥有其全部权限；首次部署按新装执行，不沿用原服务器的部署记录、证书或状态。自动连接使用`tools/server_connection.py`读取Git忽略的`.agents/server-connection.json`，按JSON中已核主机密钥及SHA-256指纹严格校验；依赖及参数见[工具索引](../../../tools/README.md)。旧服务器配置已从该文件移除；凭据不进入脚本或聊天。

验收分别记录核心、官方、助手、模型、正常停启及可选三席的真实结果；页面可用与配置存在不等于全部就绪。三席入口按[在线试用](../../../设计/组件/在线试用/接口/试用规则.md)核独立HTTPS端口及Cookie隔离，不能用单IP的正式443可达证明额外端口可用。

部署前先核目标允许的来源、直连/代理与证书方案。指定局域网可达而外部被拒绝时，CA验证超时是策略结果，不反复签发或放通；内部CA按教程经用户选择配置；服务器与客户端共用CA时按教程复用原CA、签域名叶证书、核包内指纹并安装本机续期；应用更新保留CA，维护timer跟随当前固定来源。客户端自动信任限已打包Origin，浏览器信任单独核验。系统HTTPS通过后继续核SDK、官方授权及WSS的信任链；目标主机的实际模型调用通过后再进入业务就绪验收。
