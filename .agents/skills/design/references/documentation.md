# 文档编辑

修改文档结构、术语或表达时阅读。

- 按读者问题分层：整体架构讲目标和边界，流程讲参与方顺序，组件讲数据与规则，接入讲 SDK/技能契约，界面讲可见内容。拆开混合职责，不只移动文件。
- 整体架构留在设计根目录，其余按职责分目录；一个稳定主题一篇，不为每次需求新增补充页。
- 一条规则只在一个职责页写全，其他页面引用；根索引说明归属和阅读路径，移动页面同步当前引用。
- 术语说明用途与边界，并映射代码标识。具体产品用具体名称；区分接入技能、业务技能、开发技能，避免泛称“Skill”“服务端”。
- 每篇先写目的与范围，再用职责表、步骤表和必要时序图展开。沿用设计索引规定的格式，省略空章节和重复说明。
- 正文只写现行规范；历史与取舍进 `设计/变更/`，实现差距进开发计划，实测结果进验证记录。规范成立不等于功能已经实现。
- 场景参数放示例或配置，不反向限定通用流程；尚需宿主实证的能力明确列为实施门槛。

交付时确认读者能从索引找到唯一规则来源；不要以附录、补丁页或旧方案解释当前矛盾。
