# 文档编辑

修改文档结构、术语或表达时阅读。版本与变更登记规则只在[交付](../../develop/references/delivery.md#提交标题与版本)；不变量变化与事实性修正的判据只在 [design](../SKILL.md#先判断改动类型)，本页不复述。

- 按读者问题分层：整体架构讲目标和边界，流程讲参与方顺序，组件讲数据与规则，接入讲 SDK/技能契约，界面讲可见内容。拆开混合职责，不只移动文件。
- 整体架构留在设计根目录，其余按职责分目录；一个稳定主题一篇，不为每次需求新增补充页。
- 一条规则只在一个职责页写全，其他页面引用；根索引说明归属和阅读路径，移动页面同步当前引用。
- 单页超过约 1.5 万字时按子主题拆到 `<页名>/<子页>.md`：父页只留目的与范围、“子页”表和相关文档，子页首行链回父页并保留原小节标题；根索引只列父页，子页覆盖与锚点由 `tools/check_docs.py` 核对。拆页只搬运原文和重算链接，不顺带改规则。新写内容段落不超过三句，规则进表格一行一条。
- 术语说明用途与边界，并映射代码标识。具体产品用具体名称；区分接入技能、业务技能、开发技能，避免泛称“Skill”“服务端”。
- 每篇先写目的与范围，再用职责表、步骤表和必要时序图展开。沿用设计索引规定的格式，省略空章节和重复说明。
- 设计职责页只写现行规范；历史与取舍进 `设计/变更/`，常规部署操作统一进 `设计/工程/部署.md`（仅Windows本地与Linux服务器两部分），其余实际入口和操作事实进 `设计/工程/实施资料/`，实现差距只归其中的开发计划，原始实测记录归忽略的 `.agents/data/`，必要公开结论只在既有实施资料摘要维护。集中保存时单独索引非规范资料，不把计划或旧验收结果升级为规则。
- 合并差距报告时保留代码依据和未验证范围，删除第二份现行维护入口；图片随对应资料迁移并核原字节摘要。历史变更及证据保留当年路径和事实，通过现行路径映射定位，不伪改旧结论。
- 场景参数放示例或配置，不反向限定通用流程；尚需宿主实证的能力明确列为实施门槛。

交付时确认读者能从索引找到唯一规则来源；不要以附录、补丁页或旧方案解释当前矛盾。

设计 VERSION 是三段当前规范入口，历史仅解释取舍。README、docstring 与设计正文不散写平台版本号；A2C 依据只在设计入口标记并匹配 `vendor/wheels/SOURCE.json`。产物 VERSION 的归属从架构交付表读取。场景专属值进入示例，不进入通用 Skill/SDK；产品文案的付款与授权边界从术语、支付中心及相应界面职责页读取，不另造全仓规则。
