# 模块文件夹格式

定义 `设计/组件/` 下每个模块的文件集、模板、词汇与阅读预算。改模块设计、建新模块或领票开发时读本页；深模块原理与判定法读 [codebase-design](codebase-design.md) 与 [deepening](deepening.md)，比较备选接口读 [design-it-twice](design-it-twice.md)，票据切法读 [to-tickets](to-tickets.md)，术语与 ADR 的原始格式读 [glossary-format](glossary-format.md) 与 [adr-format](adr-format.md)。

## 目录骨架

```text
设计/
  README.md  核心理念.md  术语.md(术语地图)  架构.md(模块表与依赖图)  VERSION
  决策/                     跨模块 ADR
  组件/
    平台/                   README.md 术语.md 决策/ 进展/
      身份中心/ 注册中心/ 委托中心/ 支付中心/ 消息中心/ 观测/ web服务/ 网页UI/ 平台基础/
    客户端/                 README.md 术语.md 决策/ 进展/
      共用运行时/ 个人助手端/ 服务方端/ 宿主适配/
    官方服务/  管理员助手/  在线试用/  部署/
  流程/                     跨模块交互到接口级；场景/ 放业务场景页
  工程/                     部署.md 测试.md 进展.md 专题/ 实施资料/
  变更/                     只保留变更表
```

模块文件夹要么直接放六件（接口、依赖、实现、术语、决策/、进展/），要么放 README.md 索引加子模块文件夹；子模块各有接口、依赖、实现三页，术语、决策、进展放在模块层。最多两层。架构.md 的模块表是唯一入口，每个模块与子模块一行：名称、src 目录、一句职责、文件夹链接。

三方参考页中的路径按下表映射：`GLOSSARY.md` 是模块 术语.md，`GLOSSARY-MAP.md` 是 设计/术语.md，`docs/adr/` 是 决策/，issue tracker 与 `.scratch/` 票据是 进展/ 加 工程/进展.md，spec 是 工程/专题/，`CODING_STANDARDS.md` 是[架构审查](architecture.md)与[实现边界](../../develop/references/implementation.md)。

## 词汇

正文统一使用下列词，目录名 `组件/` 沿用不改。

| 词 | 英文 | 含义 | 代替 |
|---|---|---|---|
| 模块 | module | 有接口与实现的任何单位，与规模无关 | 组件、服务、单元 |
| 接口 | interface | 调用方正确使用模块须知的一切：签名、不变量、顺序、错误模式、所需配置、性能 | API、签名 |
| 实现 | implementation | 模块内部的代码体 | — |
| 接缝 | seam | 接口所在的位置，可在此替换行为而不改此处代码 | 边界 |
| 适配器 | adapter | 在接缝处满足接口的具体实现，描述角色而非内容 | — |
| 深度 | depth | 每学会一单位接口能驱动的行为量；小接口大实现为深 | — |
| 杠杆、局部性 | leverage、locality | 深度给调用方的收益；深度给维护方的收益 | — |

判定法：删除测试，删掉模块后复杂度消失则它是透传，复杂度散到多个调用方则它在挣饭吃；接口即测试面，要测到接口之后说明模块形状不对；一个适配器是假接缝，两个才是真接缝。

## 六件

### 接口.md

```markdown
# <模块名>

## 目的与范围
三句以内：解决什么、不做什么、谁调用。

## 独占数据与配置
| 数据或配置 | 说明 | 存储 |

## 接口
### <按调用方或主题分组>
| 接口 | 用途 | 输入与结果 | 拒绝与恢复 | 测试 |

## 不变量
| 规则 | 说明 |

## 相关文档
```

接口列写代码标识；分组标题是依赖页链接的锚点；测试列写 `tests/test_<名>.py` 的文件名或 nodeid，检查脚本核其存在。不变量一行一条“必须/不得”，只写调用方可观察的顺序、幂等、期限与权限。超过约 1.5 万字时按分组拆 `接口/<分组>.md`，父页留目的、分组表与相关文档。

### 依赖.md

```markdown
# <模块名> · 依赖

| 依赖模块 | 接口 | 用途 | 类别 | 测试替身 |

## 外部依赖
| 包 | 用途 | 版本来源 |
```

接口列链到对方 接口.md 的分组锚点。类别取 [deepening](deepening.md) 四类：进程内、本地可替身、自有远端、外部服务；替身列写用哪种替身测本模块。未声明的跨模块导入由检查脚本判失败；反向依赖或绕过入口的导入先登记为票据。被谁依赖由架构.md 的依赖图持有，本页不写。

### 实现.md

```markdown
# <模块名> · 实现

| 项 | 值 |
| 代码目录 | `src/...` |
| 产物 | `<VERSION 文件>` |

## 入口
| 入口文件 | 公开名 | 说明 |

## 其他入口
| 文件 | 调用方式 | 说明 |

## 内部分区
| 分区 | 文件 | 职责 |

## 存储与迁移
## 内部接缝
## 已知偏离
```

入口是其他模块导入本模块的文件，模块外只导入入口文件。包形态模块（各中心、SDK 子包、宿主适配等）只以 `__init__.py` 为入口，在其中导出全部公开名，入口只含导入与 `__all__`，不放业务逻辑；散文件模块（平台基础，web服务 的 `app.py`、`operations.py` 等）按文件入口，每模块不超过 8 个，全部列在入口表。不经导入的入口（`python -m`、控制台脚本、入口点、产品技能文件、网页）列在其他入口表，不计入入口规则。检查脚本对全部模块核外部导入只落在入口文件；对 `tools/check_modules.py` 的 `CONVERGED` 名单中的模块再核入口存在、包形态只有 `__init__.py` 且无逻辑、散文件不超过 8 个，模块收敛后在名单中加一行。内部分区按职责分组列文件，每组一句，逐文件说明留给模块 docstring。内部接缝写测试替换的位置。已知偏离只链票据。

### 术语.md

```markdown
# <模块名> · 术语

**<术语>**：一两句定义，写它是什么。
_Avoid_：同义词。代码：`标识`
```

只收本模块独有的术语；被两个以上模块使用的进 设计/术语.md 并在那里标归属。多个同义词时选一个，其余列入 Avoid。

### 决策/NNNN-主题.md

```markdown
# <决定标题>

背景、决定、原因，一到三句。可选：状态、备选、后果。
```

难逆转、无背景会费解、真实取舍三条件同时成立才写；四位编号递增。写 ADR 是事实性修正，不升版。升版的不变量变化若同时够格，变更表该行直接链向 ADR，不再写变更详情文件。涉及两个以上模块的放 设计/决策/。

### 进展/NN-主题.md

```markdown
# NN：<标题>

**目标行为：** 端到端可验证的行为，不是分层实现清单
**阻塞于：** NN、NN，或 无
**状态：** ready 或 claimed（执行者）
**范围：** 模块或子模块；需读页面；要用的其他模块接口锚点
**定向测试：** 文件名或 nodeid

- [ ] 验收项
```

一票一个垂直切片，一次新会话能完成；编号从 01 按阻塞顺序排。宽重构按展开、迁移、收口三段拆票，收口票阻塞于全部迁移票并删除旧形态。领票先改状态再动手；完成即删除文件并更新 工程/进展.md。票据是实施资料，增删不升版。

## 阅读预算

| 任务 | 读 |
|---|---|
| 改一个模块 | 架构.md 模块表与依赖图；本模块六件；依赖页所指的其他模块接口分组；手里的票 |
| 新增模块 | 架构.md；要调用的模块的 接口.md；设计/术语.md；一个现有模块文件夹做样板 |
| 改一个流程 | 该流程页；步骤表所链的接口分组 |

架构.md 不超过约 1 万字。超出预算说明文档分层出了问题，先修文档归属再继续。
