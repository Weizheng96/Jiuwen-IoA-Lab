# 设计文档

[设计索引](../../../设计/README.md)是唯一现行规范。按[架构](../../../设计/架构.md)模块表找到模块文件夹，只读本模块的六件与所依赖模块的 接口.md；文件、模板、词汇与阅读预算见[模块文件夹格式](references/module-format.md)。差距只写模块票据与工程进展索引。

## 先判断改动类型

问一句：这句话变了之后，代码应有的行为要跟着变吗？

| 类型 | 判据 | 做法 |
|---|---|---|
| 不变量变化 | 要变。数据的唯一所有者、授权/付款/合同边界、接口契约、流程顺序、“必须/不得”条款 | 先写票据给出初始方案；改唯一归属的接口页与术语；同一提交递增设计 VERSION 第三位、变更表登记一行、打 design 标签；再交 develop 实现 |
| 事实性修正 | 不变。数量、路径、命令名、目录、链接、错别字，以及只是追平代码现状的描述 | 随代码一起改，或攒到一次收口；不升版。收口时一次升版并在变更表登记一行“同步事实” |

实现偏离正确设计时不为 bug 改规范；只在票据写修复方案并标“与当前设计有偏离”。

## 编写

1. 一条规则只在一个模块的接口页或不变量表写全，其他处链接；新模块或子模块加入架构模块表与依赖图。
2. 接口表一行一个接口并带测试名；依赖页链到对方接口分组锚点并标类别；实现页只列入口与分区。
3. 决定满足难逆转、无背景会费解、真实取舍三条件时写 ADR；超过一次会话的工作先拆票据，跨模块的工作写工程专题。
4. 边界、接口或流程变化按[架构审查](references/architecture.md)核 owner、契约与调用闭环；方案有多个开放问题时按 [grilling](../grilling/SKILL.md) 分轮问清再写。
5. 完工把最新完整方案收回接口页与实现页，删除已完成票据。

## 扫描与重构

找深化候选按 [improve-codebase-architecture](references/improve-codebase-architecture.md) 从 git 热点出发，报告写入 `temp/`；比较备选接口按 [design-it-twice](references/design-it-twice.md)。派子智能体须用户授权。

## 验证与交付

运行 `python .agents/skills/develop/scripts/check.py` 核版本、链接、索引、锚点，以及模块文件夹对代码的依赖声明、入口导入、接口测试列与进展索引（`tools/check_modules.py`，模块到代码目录的映射在该脚本维护），再按[交付](../develop/references/delivery.md#提交标题与版本)提交推送。结构、术语与分层细则读[文档编辑](references/documentation.md)；尚未迁入模块文件夹的职责页沿用同一规则，迁移由工程专题的票据推进。
