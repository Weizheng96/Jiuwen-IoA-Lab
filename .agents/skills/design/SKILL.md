# 设计文档

先读根 [AGENTS.md](../../../AGENTS.md) 和[设计文档索引](../../../设计/README.md)。职责页定义唯一现行规范；实施事实与实际入口归工程实施资料，差距只归[开发计划](../../../设计/工程/实施资料/开发计划.md)。

规则或架构改变时先给初始方案，在开发计划标开发中，更新唯一职责页、术语、设计 VERSION 与变更索引，再交 develop 实现。完成后将最新完整方案收回职责页，删除已完成进展项，不叠加补丁说明。实现偏离正确设计时只在开发计划写修复方案并精确标“开发中，与当前设计有偏离”，不为 bug 改正确规范。

方案交接前按[架构审查](references/architecture.md)列清受影响职责、规则/数据/状态所有者、公共契约和调用闭环；发现跨层私有依赖、循环或重复权威时先修边界，不把局部方案直接拼成实施方案。小改只核其影响范围。

| 工作 | 按需参考 |
|---|---|
| 文档结构、术语、版本及历史 | [文档编辑](references/documentation.md) |
| 模块边界、接口职责、跨端闭环 | [架构审查](references/architecture.md) |

验证依 [testing](../testing/SKILL.md)，沿用 `scripts/check.py` 与 develop 入口，不另建检查流程。维护后确认索引可达、规则唯一，工作方法更新所属技能。
