# 共享工作流程

分配任务、处理共享文件故障、暂停或汇总交付时阅读。

## 分工与变更交接

分工消息给出目标、依赖、拥有文件、禁止触碰的邻接边界、验收证据和下一接棒。共享装配、配置、数据库迁移、公共夹具和版本资料单独指定 owner；其他任务提出精确补丁或接口需求，不自行覆盖。主智能体审查的是最终模块关系和调用闭环，不能把多个局部成功直接拼成整体成功。

新故障的交接至少回答：实际观察与原退出码是什么，根因证据是什么，建议怎样修，涉及哪些文件与接口/配置/数据，哪些任务会受影响，怎样分别验证成功、拒绝和恢复。批准后由所属 owner 实施；修改扩出原批准范围时重新协调。设计正确但实现偏离时先列修复计划，不为了 bug 改正确规范。

等待依赖期间可在 temp 准备候选、清单与确定性演练，保留原输入。交接要明确最早可写时点、当前消费者与源码指纹。隔离快照只说明其精确候选；不得夹入未审 WIP，也不能借旧布局、旧提交或源码检查报告证明新输入已验收。文件窗口开放后及时完成实际落盘，避免方案一直停在草稿。

## 独占资源与暂停

测试串行及具体记录要求复用 testing。一次检查只冻结其真实输入；新增源码后旧结果仍仅适用于旧指纹。Git 暂存、提交、推送与版本递增由约定协调者串行完成，提交前核精确文件清单，不能把另一 owner 的未验改动捎带发布。

每次调度先查询真实 agent 状态及当前工具上限。主智能体也占槽；pending_init、残留或已中断实例可能仍占名额。暂停使用 interrupt，保存原阶段、输入、真实运行候选和接棒条件；interrupted 不等于删除。界面条目消失的原因未验证时保持未知，不猜归档或槽位释放。followup 恢复须符合用户指令与既定条件，不因空闲自行恢复已暂停任务。

interrupt 中断 agent 不表示它已启动的检查或部署子进程自动停止。交接须报告所属 session/PID 及是否仍运行，按用户暂停范围处理且不触碰其他任务；在原子进程仍读写输入时，不能仅凭 agent 显示 interrupted 就解除该输入冻结。

## 生命周期与证据

状态回报区分已准备、正在检查、已发布、已部署和已验收，并列真实退出码、候选/提交 hash、当前运行阶段与未验证范围。进程存在、首页200或单核心就绪不能推出全栈 ready；旧实例恢复也不等于新版本升级完成。主智能体在阶段性 FINAL 后继续安排必要接棒，不把无人执行的后续步骤当作完成。

部署 owner 使用已发布、已核准且双远端同 SHA 的产物；新修复先审模块边界与共享冲突，再由原 owner 实施。最终交付核集成版本及其实际运行候选，不让各组件永远停在不同旧基线。

最终完整回归需用户授权的交付范围及统一冻结输入；真实环境、模型与外部业务证据单列。保留私人数据和真实业务授权边界，不为测试或影片伪造用户签名、确认或已完成效果；局部替身通过只证明其确定性规则。
