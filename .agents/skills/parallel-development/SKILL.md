# 多智能体协作开发

先确认用户授权的范围与当前工具并发上限；上限包含主智能体。用真实状态清单核可用槽位，不把界面显示数量当作运行事实。

1. 主智能体按依赖划分任务，确定架构、模块契约、逐文件 owner、检查协调者与交付条件；子智能体负责自己的实际实施，不能只交方案就永久停工。共享文件只有一个当前写入者。
2. 能独立开发的任务并行；接口或规范改变先协调并落实唯一职责页。通用层保持原职责，不为场景或操作系统增加旁路、重复状态机或配置权威。
3. 新故障由子智能体报告事实、根因、推荐方案、精确文件及接口/配置/数据影响、成功和失败验证；主智能体核架构与并发冲突，批准后由 owner 修复。普通已授权操作继续执行，扩大范围时再上报。
4. 检查、固定端口、Git 索引与发布、版本号等独占资源各有一个协调者。冻结只覆盖当前检查实际读取的输入；其他任务可准备隔离候选并约定最早交接，不能无限等待另一任务的全量检查。
5. 明确准备、实现、检查、发布、部署、验收的接棒。阶段性 FINAL 只是该次回报；长流程由主智能体明确后续执行者和恢复条件，直到用户目标完成或明确暂停。
6. 发布产物须绑定主智能体核准源码及两个远端同一 SHA；部署固定基线，区分原实例恢复与新版升级，最终还须核集成版本。最终阶段统一冻结新输入并显式完整回归，环境和模型专项证据分别报告。

资源争用、故障交接、暂停与证据判断按需读[共享工作流程](references/shared-workflow.md)。设计、实现、检查、部署、同步分别复用 [design](../design/SKILL.md)、[develop](../develop/SKILL.md)、[testing](../testing/SKILL.md)、[deployment](../deployment/SKILL.md)、[gitcode-sync](../gitcode-sync/SKILL.md)，不复制其执行步骤。
