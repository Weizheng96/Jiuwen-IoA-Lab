# 实现边界

模块重构、状态调整或跨端开发时阅读。

| 边界 | 实现要求 |
|---|---|
| 责任归属 | 同一业务的数据与不变量由所属模块维护；跨中心用例调用公开接口，不跨模块改表 |
| 依赖 | 平台不执行参与方；SDK 不导入平台、宿主实现或官方场景；宿主对象由组合入口注入 |
| 共用运行时 | 身份、连接、收发箱、会话、授权与恢复只有一个写入所有者；技能和 CLI 经本机认证 IPC 调用 |
| 协议 | 复用上游签名、金额、期限与 WASM 验收；交互 UUID、连接及 session 关系只放运行数据 |
| 并发 | 事务只包短写入；接单容量、模型并发、用户预算分别检查；控制与结果不能被新任务堵住 |
| 外部效果 | 区分模型工具调用与业务请求；副作用按消息/合同等稳定业务来源去重，换工具调用ID不能变成新业务。先保存原记录，恢复先查结果；未知保留占用和证据，不重发付款、邮件或签约 |
| 安装 | 使用包资源、显式配置和固定命令；不依赖 cwd、相邻源码或手工 sys.path；第三方 Git 依赖随仓标来源 |
| 替换与归档 | 内部开发统一现行实现，不堆旧版兼容层；新链路验收并替换调用/构建/部署引用后，整组归档旧源码并登记入口；当前身份、合同和未知结果不能随源码清理，不提前升产物版本 |

业务技能和收信规则提供业务能力；通用接入流程留在产品技能。不得为固定剧情修改宿主、写死推荐结果，或通过特殊录制入口绕过正常权限和协议。
