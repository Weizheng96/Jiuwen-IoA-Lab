# 验证与诊断

修复故障、选择测试或交付时阅读。

1. 先定位真实失败边界：用户/服务配置不足，设计矛盾，还是代码违反设计。超时先查持久作业及工具检查点，失败用例名不等于实际失败阶段。异步任务为unknown时，沿原ID核已保存的底层工具或协议操作回执，再核宿主执行元数据；外层异常类型、网页持续计时或idle不能独自证明模型超时。先区分明确原拒绝与缺失回执，再决定是否需要新增恢复机制。保存输入、稳定标识及真实回执；不在日志暴露密钥。
2. 配置问题修配置并明确引导；设计问题先改唯一职责页；代码问题在所属模块修复。不要用延长等待、救援提示或宽松验收掩盖原因。
3. 新测试覆盖有价值的不变量或已复现故障：重传、重启、未知效果、并发、权限/期限变化。在准备、提交、返回边界注入故障，同时核对权威数据和原始回执；状态探测也可能短暂持锁，须检查探测与实际工作者同时争锁的路径。沿用原覆盖，不以改断言迁就错误行为。
4. 桩测试证明确定性规则；真实九问、原生确认、网页可见性、邮件及视频分别需要实际证据。读脚本和模型的成功报告不证明已执行，须核原调用、真实实例及业务状态；后台completed或安装清单不证明用户已看到或已接受。 生命周期验证须并发取消观察方与停止服务，区分停止回执与原执行写入者释放：用认证实例和实际OS锁核对；IPC消失、旧PID或等待超时不能单独证明退出，不能因观察超时重启仍存活的任务。 排空还须验证活动任务能够完成原授权工具，且新任务、已结束及失去许可的上下文仍被拒绝。
5. 交付核对设计验收、包安装独立性、公开端到端和本轮改动范围；检查实际安装包清单，防止旧缓存把已删除模块带回。涉及产物交付或导出时，从用户正常公开入口验证能取得原件并按约使用，摘要、内部缓存或后台取件成功不等于用户已拿到文件。发现真实出口缺失时优先补所属实现，不用读取私有存储的救援结果冒称正常教程完成。报告实际通过及缺口，不能把旧视频或旧验收当作新实现的证明。

本仓生成并由Git跟踪的摘要文本，须在计算摘要前固定编码与换行，并核对暂存或克隆blob的实际字节；工作区校验不能代替发布快照校验。外部固定内容按来源清单保持原始字节。

新增文件输出能力时，同时核首次取得、缓存复用及unknown恢复路径的实际产物。原外部业务已完成但本地保存失败须分别报告，恢复不能重复原外部动作；仅首次输出成功不能代替恢复路径验证。

故障注入须核钩子实际触达预期对象，尤其同一夹具先改实例方法、后改类方法时：monkeypatch恢复实例上的绑定方法可能留下实例属性，遮蔽后续类级钩子。核对描述符和实例属性的原归属，恢复后不能残留遮蔽；新增注入后运行受影响的成约方式、丢失回执等参数组合，不能只验容易通过的正常分支。

异步测试的同步条件须覆盖断言所依赖的全部事实：市场结清可能早于原work.start终态回执，不能只等ledger就假定复核摘要已稳定。先等原调用真实终态，再读取并提交所见快照；保留旧快照409与越权403断言，不用固定sleep或反复重试POST掩盖竞态。

检查层级遵守根 AGENTS.md；先按变更涉及的模块与不变量选择测试路径或 nodeid，不把每轮修改自动升级为整仓验收。耗时异常时核对原报告的当前用例、阶段日志与真实进程，区分慢测试、失败和未退出；有持续用例推进才能证明仍在执行，CPU增长本身不能排除忙循环。依据慢测试统计优化重复准备或无效等待，不能凭猜测削减覆盖。

长阶段检查指定唯一执行者，保存提交及在途执行输入的指纹，运行期间不修改受影响源码、测试、依赖和模板。独立且不被执行读取的说明可另做A，分别记录适用输入；不能据此宣称原检查覆盖新改动。出现FAILED后等原任务给出真实退出、trace及XML，再按原因修复并定向验证；未执行的selfcheck单列，不把局部通过覆盖失败，也不为获取失败详情另启全量。

默认 CI 的路径规划先用具体文件职责，再用最具体的目录规则，不叠加所有父目录范围。跨模块关键边界和昂贵集成矩阵使用明确 nodeid，覆盖必要成功、失败和恢复；新增函数和测试类仍须完整选中，包括异步方法及类、方法参数化，完整原矩阵留在显式 C 检查。共享依赖和 fixture 清单先按职责识别，不能因文件扩展名或普通测试文件分支而漏掉关键边界。测试依赖按真实 Python 导入和发生变化的共享函数、常量、fixture 传播，不能以文件名全文子串把示例或普通测试断言变更扩散成大批集成检查。`--changed-from` 只读取基线与 HEAD 的已提交 blob；删除和重命名同时核旧消费者，工作区草稿不混入范围。修改规划器时验证成功、失败、重命名、未映射提示及自身变更范围，并保留选中 nodeid 与实际耗时；完整入口使用流程替身验证调度，不为检查入口再启动慢全量。

配置生成验收由真实模型读取实际能力后自行起草，不在测试驱动中预填最终Schema掩盖能力声明缺口；先核对预览与工具原回执，再验证业务结果。格式校验须用反例确认对应校验器实际启用，不能因第三方库接受format声明就认定已检查。获准使用子智能体时，按独立文件和状态所有者分工，源码冻结后再跑共享真实链路；复用未变输入的报告，避免多个执行者重复构建、安装或验收同一业务。

CI提效先分别测checkout/fetch、范围规划和pytest，浅克隆仍须取得并固定真实比较基线，取不到则明确失败；HEAD与比较范围不能因优化改变。不同提交范围的用例数和总耗时不作同输入加速对比，保留原完整覆盖入口。

精简测试以独立规则、失败条件、原输入和协议路径建立旧用例到新归属的映射；确认完全承接后直接删除重复用例，不按名称或行覆盖率推断冗余。共享不可变包/构建基线，保留场景实际参数及全部反例；不共享可写数据库、端口、权限或故障钩子。纯Mock测试可记录退避而不真实等待，真实时序与进程验证仍使用真实边界。第一层失败只输出对应模块诊断入口，不自动重跑；同输入前后比较使用独立报告及真实退出码，子集提速不推为整仓比例。

真实业务仅在已授权的隔离场景运行，重拍前核对既成效果，不能为录制重复收费或发邀请。静态网页修改后运行`tools/stamp_static.py`更新内容摘要；页面验收同时核实际加载资源，避免旧缓存造成误判。
