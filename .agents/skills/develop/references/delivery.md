# 提交与交付

本仓日常在 develop 开发、验证、提交并推送 GitHub，不直接向 main 提交；main 只接收用户要求的合入，见[合入 main](#合入-main)。跨仓修改先读该仓 AGENTS，各仓独立管理版本。大改先保存已提交回退检查点。每个文件只有一个当前写入者，共享装配、数据库迁移、配置清单和公共夹具先协调。

提交前核 diff 与精确暂存清单，只纳本任务文件，保留他人的 WIP、未跟踪草稿与运行数据。不自动另建开发分支或工作区，不替并行任务 stash/提交。

AI 自行完成的提交与推送只到 develop；main 只按下节由用户要求的合入更新。develop 的提交标题用 `v0.0.x.y：主题`：前三段取当前设计 VERSION，x 即其第三位，y 为该设计版本下的开发推送序号，先查已有提交中相同设计的四段标题顺延；第四段仅提交序号，不写入设计 VERSION。每次提交递增第四位。每次修改更新设计文档（`设计/` 下的现行规范：职责页、术语、流程、组件、接入、界面与工程规范页；开发计划、部署发行等实施资料和部署教程属非规范事实，不计）在同一提交里递增设计 VERSION 第三位，维护变更索引与 `YYYY-MM-DD-vX.Y.Z-主题.md` 详情，创建 design-vX.Y.Z 标签并与提交一并推送，此后第四位从 1 重新计起；前两位由用户决定。产物依据不得随设计虚升。

## 合入 main

只有用户明确要求时才把 develop 合入 main，不因阶段完成、定期或自行判断合入。

1. 核 develop 已推送且没有未提交的跟踪改动，按 [testing](../../testing/SKILL.md) 完成发布所需检查；涉及产物版本或发行输入时先完成下节核对。
2. 切到 main，执行 `git merge --no-ff --no-commit develop`。在这次合入里把设计 VERSION 第三位加一，并在变更索引登记该版本及所含范围；合入只额外包含这项版本登记，重跑轻量检查后以 `v<新三段>：主题` 提交，标题不带开发序号。
3. 推送 main 和 design-v<新三段> 标签并核远端引用，再依 [gitcode-sync](../../gitcode-sync/SKILL.md) 同步 GitCode。
4. 切回 develop 并快进到 main，推送 develop；后续提交从 `v<新三段>.1` 顺延。

合入版本只表示 main 接收了这一批 develop 提交，不代表产物依据或阶段验收随之升级。

## 发行输入与锁一致性

产物VERSION、pyproject安装要求或构建输入变化时，沿实际消费者检查到最终发行：本仓wheel版本、接入技能固定版本、各目标运行锁及配套JSON必须对应同一份受审输入。重点核`src/access/skills/_shared/requirements.lock`和`deploy/locks/<target>/{core,participant,swarm}.{lock,json}`；不能只改VERSION，或凭单元/轻量检查通过就认定发行可构建。

先从最终源码构建实际wheel，再用现有`tools/build_requirements.py`消费者和`tools/lock_deployment.py`唯一目标锁入口更新相应输入。目标锁JSON中的inputSha256包含本仓版本等构建依据；即使第三方包未变，本仓版本变化也可能要求更新元数据。所有受影响目标均须核对，输入未变的结果复用，不机械重生成无关文件。

只调整本仓版本时，将原普通锁作为constraints约束重新解析，并比较新旧.lock字节；若普通依赖发生变化，先查明实际要求差异，不能顺便升级第三方包或仅手改摘要使门禁放行。区分“本仓固定版本变更”“锁输入指纹变更”和“第三方依赖变更”，在交付中说明实际范围。

发布给部署者前，运行受影响的真实接入技能打包及目标发行构建入口（`tools/build_access_skills.py`、`tools/build_deployment.py`），保存最终输入、真实退出码与产物清单；组合测试可辅助验证，但不替代实际构建。本机与目标环境专项分别报告；已构建产物及缓存只在相关输入未变且摘要匹配时复用。出现版本/锁不一致应在源码及发布阶段修复，普通部署用户不承担改锁、重算摘要或现场补包的维护工作。

## 发布与核对

推送前 fetch 核远端历史，保留历史；推送后核实际远端引用。GitHub 可按需使用命令级代理，不改系统全局代理，不因直连失败自动换代理。GitCode 只在用户要求合入 main 后依 gitcode-sync 同步并保存实际退出及引用；连接边界归该技能。共享历史回退优先 git revert，不改写历史。

报告真实提交哈希、GitHub/GitCode同步结果、失败检查和未验证范围。已发设计规范不等于实现或阶段验收完成。
