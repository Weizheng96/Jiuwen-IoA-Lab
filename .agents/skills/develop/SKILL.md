# 按设计开发

先读根 AGENTS.md、设计索引和开发计划，按本次需求读取架构、流程、组件、接入及验收职责页。设计是规范；旧代码与已有测试只能证明当前行为。

## 工作顺序

1. 核对工作区、已提交基线及远端；保留在途业务和用户已有改动。遵守仓库及用户指定的分支约定，大改先保存回退检查点，以可验证的功能闭环提交。
2. 将需求映射到设计规则、代码所有者和验证证据。规则缺失、矛盾或无法执行时，先用 design 技能修正职责页、版本及历史，再写实现；实际差距记开发计划。
3. 按明确依赖和状态归属实现，复用 A2C/AP2；迁移资源、安装入口和检查工具时同步更新引用。完成替换后移除重复主流程，保留既有业务可恢复性。
4. 用公开接口验证输入、结果和异常恢复，核对数据及真实回执；通过检查后才更新产物 VERSION、开发计划并提交推送。

## 固定检查

项目 Python 执行 `python .agents/skills/develop/scripts/check.py --tests <测试路径...>` 做本轮定向验证；交付前不带参数执行完整检查。脚本复用仓库检查，不修改版本或 Git。

用户反馈中的通用经验合并进对应参考页；产品规则归设计，场景专属配置归示例或 Demo，不将问题逐条堆入本技能。
