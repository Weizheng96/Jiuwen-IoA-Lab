# 双屏试用

左屏为用户自己的九问 Swarm，右屏打开平台 `/admin?view=panorama`。验收位置、服务激活与两进程职责见设计，不在本手册另写规则。

## 准备

1. 按 `设计/部署.md` 启动核心和独立官方服务；官方服务 `/health` 应为 ready，平台注册表应有48个online服务。
2. 构建连接器 `python tools/build_connector.py`；在另一台用户机器从首页下载并导入九问，填写核心地址、账号与密码。首次运行自动准备SDK，需能获取依赖。
3. 让九问查看自己的IoA账号。管理员全景应出现其本地身份；未接入的ISC账号保持空闲。
4. 真实服务进程必须使用已安装配置好的九问，关闭 `IOALAB_STUB`；核对实际任务有Swarm会话与用量记录。桩模式只用于协议排练。
5. 若需要背景流量，在独立终端启动 `experiments/traffic.py`，不在核心里点击创建助手或投放。

## 展示

| 场景 | 用户请求示例 | 核对 |
|---|---|---|
| 预批准 | 为茶小满写三条春日上新朋友圈文案 | 本地签1，官方服务收到开工才生产，本地验收并付款 |
| 待批准 | 成人Python入门课程大纲 | 服务复签后生效；繁忙时可拒绝，用户助手换家 |
| 提案 | 杭州两日行程，每日至少三个景点 | 提案拟卡先激活服务，用户确认定数报价后开工 |

点选任一参与方按账号聚焦；事件标明“证据已核验/当事方上报”和实验来源。查看SDK命令返回与本地交付文件，不能仅凭聊天文字宣布已完成。

## 异常演练

| 异常 | 预期 |
|---|---|
| 用户退出九问 | 平台不替其验收；重新启动后从同一本地目录继续poll |
| 服务进程重启 | 已保存任务继续；已有签4的期不重复交付 |
| 验收失败 | 本地生成失败报告，经用户同意申请市场复算，不签7、不付期款 |
| 观察上报断线 | 合同动作不回滚，outbox稍后重发；界面观察缺失不能当成合同失败 |
| 付款明确失败 | 本地保留签7；用户确认后补付；结果不明则先核对账本，禁止重复支付 |

Linux实机部署、干净用户环境和真实九问闭环的验收结果在变更记录登记。没有实际执行时保持未验收。
