# 开发与验收入口

本页记录实现与[现行设计](../设计/README.md)之间的差距，不定义另一套产品规范。各产物实际依据见各自 VERSION；历史见[设计变更](../设计/变更/README.md)，现有实测证据见[验证记录](../demo/verification/README.md)和[部署依赖验证](../deploy/verification/dependencies.json)。

[原版九问只读探测](../deploy/verification/jiuwen-capabilities.json)已确认宿主工具、技能、会话续接能力及原工作区的三个模型选择项。[助手通信实测](../deploy/verification/assistant-messaging.json)另外使用真实原版九问和 HTTP/WS，验证冲突后再请求、同交互与同 Session；工具和浏览器确认属于显式隔离测试，不代替会议邮件、原生网页可见性或正式视频证据。

## 当前状态

[架构](../设计/架构.md)已定义目标项目目录、三个发行包、官方参与方资源以及 Demo 分场景组织。重构在独立工作区进行，原主分支保持已提交基线；回退标签为 checkpoint-20261030-before-runtime。develop 技能及固定检查已建立并验证。平台、SDK 与可选九问适配已迁入 src，可分别安装，各包版本读取实际产物依据；显式初始化清单已实现。身份认证和支付已按组件归位；其余中心拆分、官方资源及 Demo 尚待迁移，产物 VERSION 保留实际依据。后文目标路径是实施落点，不能当作当前可执行命令。

安装基础已通过包构建和离开源码的版本/资源检查。长连接新增公开票据、WS、操作恢复、投递与交互台账，以及 SDK 的事务收件、连续游标、操作 outbox 和 UUID 原子关联。账号登录与赠币统一事务，浏览器和 SDK 保存原操作恢复；SDK 两角色复用账号会话，刷新凭据不重新赠币。服务可独立绑定密钥并连接，不创建个人助手、不要求公网地址；其稳定地址已提供公钥、签名声明、Agent Card 及 A2C 模板读取。接单和业务执行仍需后续验收，不能以完成公示代替。

最新完整检查点为 300 项通过；两项依赖本机模型配置的测试默认跳过，先前检查点保留真实九问实测证据。版本、56份文档与仓库自检通过。覆盖服务公示、用户授权、委托意向及 UUID、容量与费用并发、当前代次付款、完整价款预留、原 AP2/预算/容量事务，以及私有材料授权和原协议初始投递；原消息和宿主覆盖继续保留。隔离源码构建验证安装入口、模块清单及本机页面；这些检查仍不代表完整依赖干净安装、官方会议业务或四段视频完成。

常驻 SDK 入口已提供单实例所有权、本机认证 IPC、稳定角色身份、连接/收发箱、持久调度及独立控制查询；CLI 经本机调用，不打开协议库。真实子进程已验证两角色共享登录、缺宿主不执行、崩溃保留 unknown，以及模型忙时控制仍响应。默认入口装配助手设置与通信操作；`ioalab-jiuwen` 装配原版宿主及入站处理。状态结合角色健康、宿主、连接和调度判断，缺任何执行条件保持未就绪。

服务方角色新增 categories/preview/publish/status，经同一常驻组件和真实本机用户确认上传签名声明、模板。平台保存修订原件与不可变回执，A2X 作为可恢复投影；旧操作恢复不覆盖新修订，签认响应丢失复用原模板，源写入失败整体回滚。8 项新增测试及原外部服务/授权共20项联合测试通过，并已通过上述完整检查。原协议入口改为每服务持久 A2A 应用，修复临时处理器任务回收导致的队列死锁。服务公开资料不依赖公网 IP；现有发布技能尚待切换，服务方入站模型执行和履约尚未装配。

助手模块已支持本地 Markdown 草案/预检/预览/确认发布、固定修订、结构化发送/回复、多轮与关闭。发布响应丢失及本地映射失败从原操作恢复；真实用户入口的权限与脚本 RPC 分离。[原版九问提问实测](../deploy/verification/assistant-native-question.json)确认同一进程等待本机浏览器答复，回答前不执行工具、释放模型名额；此处用户答复由隔离测试驱动。未知工具效果不重跑。当前宿主装配不自动提供日程或邮箱业务工具。

新委托角色现已提供 prepare/authorize/renew/status/close 及意向投递/查询，统一采用设计中的 prepare 名称和默认7天配置，已签许可仍保持原截止。固定 context 与可续期 grant，经本机可信用户批准后签发；原 proof 及预算不因恢复而重置。平台提供意向业务绑定、接收端 UUID 登记、容量策略、原子预留、零拟卡费及待批准提交。当前连接中的 ap2.pay 已将真实拟卡费、范围预算、admission 和操作回执放入同一事务；原付款恢复不受后续撤权影响，也不重新扣款。

`/ws/agents` 已支持助手消息与委托意向/预留结果；SDK 两端保存同一 UUID，常驻助手已暴露 intent/intent_status。新增14项测试与原消息、授权、公示共53项联合检查通过，覆盖并发名额/费用争抢、晚到接管、付款回滚、活动承诺保留、分类投影未就绪及双端恢复。

原 A2C 投递初始阶段已提供 request.submit、card.countersign 和拟卡费 ap2.checkout 封套，受原交互、当前连接、admission 及签名校验约束。待批准在有效 held 下接收签1审查，原 Provider 回调提交容量后才签2；拒绝未提交或改动原卡的签2结果，审查期间到期不得签约。私有文件有账号配额、原操作恢复、摘要核验和读取权限；合法材料授权、文件读取授权与消息入库同事务。11项新增测试与原 admission 共25项联合通过，包括实际原版 Provider 复签、原任务进展、缺材料授权拒绝及失败不泄露读取权。新接入服务不能从公共市场签3绕过 admission。

平台容量控制尚未装配到服务方模型执行；常驻 SDK 的原 A2C 收发适配、提案市场签3授权入口、完整履约/分期付款及结清释放仍待打通。当前市场门禁明确拒绝未装配阶段，不代表提案签认已完成。产品技能和原业务路径尚未统一切换，不以当前局部链路代替四段新视频或完整产品接入。

原十个测试文件保留。仅设计与维护工具变更不得删除原测试、启动真实委托或发送邀请；回归继续用显式测试桩。
