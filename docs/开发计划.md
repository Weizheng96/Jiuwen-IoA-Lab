## 迁移门槛与版本

| 项目 | 当前需处理的差距 |
|---|---|
| 付款与接单原子性 | 拟卡费及合同付款使用同一应用事务协调 admission、真实 AP2、预算和原凭证；正常结清核真实付款并原子释放名额；多期、拒绝/解除与更多中断恢复验证完成后再切换旧主路径 |
| 本地写入 | 新常驻入口先取进程锁再开库，短事务存储/调度、两角色共享连接，CLI 走认证 IPC；旧产品入口仍需切换，不能并行持有同一身份或自动从旧目录重建密钥 |
| 平台发行版本 | 已改为 src/platform/pyproject 读取本包 VERSION；平台和 SDK 构建包的安装版本及网页资源已脱离源码目录验证 |
| 产物依据 | 按架构维护各安装/资源单元和四个 Demo 的 VERSION；迁移继承原依据，实现并验收后才升级；合并单元须如实记录未覆盖差距 |
| 安装与资源路径 | 构建脚本、systemd、工具配置、验收器读取和静态资源含旧路径；统一到包入口、包资源或显式配置后再移除旧路径 |
| Demo 复现 | 当前部分录制/配音工具依赖相邻 A2C 主仓；收录必要工具及来源，迁移播放器、素材与证据引用；移动路径不等于重新录制或验收 |
| 检查入口 | 平台和 SDK 的版本、文档、构建及静态检查已跟随新目录；后续随其余源码迁移继续调整，集成冒烟入口已移到 tools/smoke.py |

在途合同迁移前备份，核实身份、承诺、付款、模板、授权与投递回执；不删历史订单或私钥。尚不能接管的业务先在原环境完成或按协议结束，新旧执行器不得同时持有同一智能体的活动执行权。

## 检查与交付

1. 先更新职责页、设计 VERSION 与变更索引，再实现；产物完成相应迁移后才更新其 VERSION。
2. 执行 `python 设计/check.py`、`python tools/check_docs.py`、`python -m pytest -q tests`、`python tools/selfcheck.py`。
3. SDK/技能发布补做干净安装、独立性和双入口验证；按[验收](../设计/工程/验收.md)补架构边界、故障竞争及端到端场景。
4. 视频按先剧本后录制的流程制作；旧视频不作为新架构验证。证据迁移前仍从本页现有入口查阅，迁移时保留原实测事实并同步链接。
5. 对应仓提交、推送，核对远端提交和设计标签；temp、运行数据、凭据、原始私人消息不提交。

原十个测试文件保留。仅设计与维护工具变更不得删除原测试、启动真实委托或发送邀请；回归继续用显式测试桩。
