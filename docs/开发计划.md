# 开发计划

设计入口：[设计/README.md](../设计/README.md)。实现状态与差异只记 [变更记录](../设计/变更记录.md)，本文件只记施工顺序和验收入口。

| 阶段 | 交付 | 完成证据 |
|---|---|---|
| 1 | 核心移除助手；本地SDK与身份绑定；官方独立Provider；显式桩闭环 | 两进程＋本地Client走三种成约；本地验收；平台无Client实例；错主体与重放被拒 |
| 2 | 服务方技能、按需九问适配、可恢复队列；客户端观察与重试 | 无任务无Swarm；重复任务不重复交付；重启恢复；失败不伪造样件成功 |
| 3 | 锁定安装包、首次技能引导、独立背景流量、管理员与两进程部署 | 干净环境引导；明确实验来源；无服务依赖的核心启动；安装脚本检查 |
| 4 | 真实九问与Linux验收 | 用户导入技能走一单、官方Swarm按需生产、双屏展示、服务重启；没有环境时记录未验收 |

全程使用现有 A2C wheel，不修改九问源仓；发现接口缺口先更新对应设计。先跑聚焦测试，最后运行 `tools/selfcheck.py`、`pytest tests`、`设计/check.py`；完成阶段分别提交并推送。真实模型、服务器与全局安装操作按会话授权执行，不能用测试桩替代验收结论。

助手间消息系统仍未纳入本轮范围。原始需求在A2C主仓本地开发者草稿中；本文取代个人助手目录里的旧施工计划。
