# 代码导览

本文件只说明当前代码的阅读路径和模块职责；源码分层、常驻接入和业务迁移的实际差距及实施顺序见[开发计划](开发计划.md)。目标结构与依赖约束见[架构](../设计/架构.md)，运行结果与未验收项见[验证记录](../demo/verification/README.md)，不在此重复目标目录或状态表。

## 常驻接入与业务

以下是新产品接入链路；默认部署及尚未切换的调用另列，不能把两套入口串成同一流程。

| 活动 | 阅读路径 |
|---|---|
| 技能启动与调用 | `src/access/skills/assistant/`或`provider/`的流程页 → 共用`_shared/ioalab.py` → 已安装SDK/九问适配CLI；依赖安装归`_shared/installer.py`，两角色共用本机实例 |
| SDK运行 | `runtime/resident.py`装配账号、身份、调度与角色；`runtime/ipc.py`提供本机受限调用，`runtime/connection.py`维持平台WebSocket及可靠收发 |
| 用户发起委托 | `assistant/references/delegation.md` → SDK的`assistant/delegation.py`、`trading.py`、`contracts.py`、`fulfillment.py` → 锁定A2C/AP2；授权、合同、环节和验收分别确认 |
| 服务配置与接单 | `provider/references/` → SDK的`provider/publication.py`中ProviderRole及同目录职责模块；用户确认后签名公示，接单和生产沿统一运行时处理 |
| 收信设置与通信 | `assistant/references/inbox-rules.md`或`messaging.md` → SDK的`assistant/rules.py`、`role.py` → 共用连接 → 核心`messaging/`；入站上下文含原已确认规则、实际请求与获准工具 |
| 案件与独立复核 | 核心`delegation/arbitration_evidence.py`收集原事实，`arbitration_cases.py`拥有案件与原操作，`arbitration_review.py`判独立复核政策；`web/arbitrations.py`提供管理员入口。SDK的`adapters/arbitration.py`重算公开证据并验历史签名，相关非Demo功能按开发计划继续验证 |
| 九问执行 | `src/hosts/jiuwen/ioalab_jiuwen/process.py`的ProcessHost调用原版公开接口；`skills.py`处理业务技能，`tools.py`装配本机明确允许的工厂；不改用户九问 |
| 日程、邀请与通知 | `src/official/tools/ioalab_tools/`提供可选日程/预约/邮件工厂；九问原生网页通知归宿主的`web_setup.py`和`web_notifications.py`；通用SDK不反向导入这些业务实现 |
| 账号与安全停止 | `runtime/authentication.py`与`session.py`恢复账号；`ResidentRuntime.run`将独立进程信号送入同一排空流程，官方协调器再核原bootId和实际OS锁 |
| 不可变验收包 | `runtime/session.py`的fetch_package供两角色共用；仅相同摘要GET断开有界重试，不重放业务 |
| 核心与观察 | `src/platform/ioalab/__main__.py` → `platform.py`装配各中心；`participants.py`接收报告，`observation/`维护已核验投影，`events.py`保存观察历史 |
| 工作台与全景 | `web/workbench.py`裁剪本人数据；`static/index.js`与`network.js`展示本人网络；`panorama.js`展示管理员事实，`network-map.js/css`共用布局；`tools/check_panorama.py`离线验证状态与连接边界 |
| 讲解与实验 | `demo/global_web/scene.js`执行有限讲解计划；`experiments/`通过参与方SDK发起活动，核心不创建背景个人助手 |

## 部署与官方实例

| 活动 | 阅读路径及当前边界 |
|---|---|
| 发行与运行环境 | `tools/build_deployment.py` → `deploy/release.py` → `deploy/environment.py`；固定构建环境归`builder.py`，目标锁归`tools/deployment_dependencies.py`及`tools/check_deployment.py`；见[部署发行](部署发行.md) |
| 部署基础 | `deploy/configuration.py`校验初始输入，`layout.py`保存三根归属，`activation.py`核完整环境集合并原子切换；尚未接入默认安装/升级脚本 |
| 原版工作区 | `deploy/workspace.py`核归属、公开初始化和原模型资源；只管理部署方新建实例，不接管普通用户既有九问 |
| 官方服务 | `src/official/services/ioalab_services/catalog.py`是唯一领域/验收资源入口；`profiles.py`构造业务配置；`preparation.py`、`authorization.py`、`coordinator.py`分别负责准备、受限初始授权、运行及续期 |
| 管理员业务助手 | `src/official/admin-assistant/ioalab_admin_assistant/`核固定root配方、读取包内预设并复用SDK确认/发布；prepare/status已存在，正常收信仍由同一SDK/九问适配承担，默认脚本尚待切换 |
| 第三方输入 | [vendor](../vendor/README.md)保存来源、许可与摘要；现有锁文件和调用位置的迁移次序见[开发计划](开发计划.md) |

## 尚未整组替换的入口

| 现存调用 | 切换与归档条件 |
|---|---|
| `deploy/install.sh`、`upgrade.sh`及旧单位 | 仍使用源码目录、editable安装和旧服务/管理员入口；须接入新发行、独立账号、SDK排空、备份和整体切换后，再退役旧部署组 |
| `official-services/serve.py`、`swarm.py`及旧ProviderAgent | 部分实验、smoke和会话级测试夹具仍调用；将原覆盖迁到常驻接单链路后整组归档，不再复制官方领域资源 |
| `personal-assistant/assistant.py`及旧通知扩展 | 仍由旧默认单位加载；新管理员业务助手已入官方包，须验证默认运行、通知及全部调用切换后再归档 |
| `connector/`、旧LabClient/消息CLI及旧实验 | 部分实验与协议回归仍依赖；新产品技能不走该编排。逐项迁移原验证，保留身份、合同及未知操作数据后再整组归档 |

`src/access/sdk/`不依赖核心Python包，核心不导入用户Client、Provider或九问运行时。服务验收器只在A2C WASM沙箱执行。协议实现来自[wheel来源](../vendor/wheels/SOURCE.json)，不在本仓复制规则。

## 检查入口

```powershell
python 设计/check.py
python -m pytest -q tests
python tools/selfcheck.py
python demo/script_documents.py --check
```

自检不调用模型、不发送邮件。真实端到端录制须显式运行demo入口并使用本地配置，不能因文档整理启动真实委托或重发邀请。可选录制依赖在`demo/requirements.txt`，与平台运行依赖分开。

旧delegate编排只用于恢复已有受管理任务与外部声明计划；美甲计划和台词在examples/nail-booking，不随主skill分发。主skill不依赖九问全局指令或工具开关覆写。
