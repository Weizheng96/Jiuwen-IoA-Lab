# 生产发行与独立环境

本页说明已实现的发行构建、依赖锁和环境安装工具。默认Linux安装、配置和升级入口尚待切换，实际差距见[开发计划](开发计划.md)；本页命令不能作为完整平台部署教程。普通个人助手或服务方用户使用产品接入技能，不需要构建发行包。

## 维护端构建

使用CPython 3.11，在独立构建venv中从国内镜像安装[构建工具锁](../deploy/locks/build.lock)，不安装根开发requirements。以下命令在本仓根运行，`python`指该构建venv的解释器。

```text
python -m tools.build_deployment --wheels-only --target linux-x86_64 --out temp/deployment-wheels
python -m tools.check_deployment --wheels temp/deployment-wheels
python -m tools.build_deployment --target linux-x86_64 --out dist/deployment
```

构建核对随仓来源、许可及摘要，从隔离源码生成wheel，再生成两份产品接入ZIP。发行目录以内容摘要命名，包含`release.json`、三组wheel与普通包锁、初始化数据、产品ZIP及来源许可，不复制data、凭据、浏览器状态或开发环境。已有同摘要目录只核对，不覆盖。

wheel依赖变化时，先在维护端使用uv重新生成两个目标平台的锁；部署端不需要uv：

```text
python -m tools.lock_deployment --wheels temp/deployment-wheels --target linux-x86_64 --out deploy/locks/linux-x86_64
python -m tools.lock_deployment --wheels temp/deployment-wheels --target windows-x86_64 --out deploy/locks/windows-x86_64
```

可用`--constraints`传入显式约束目录，分别提供core.txt、participant.txt、swarm.txt。生成后提交锁文件和元数据，再重新构建。普通包只允许精确版本；Git直接引用只能映射到已核对的本地wheel。锁记录目标平台和实际依赖输入摘要；构建拒绝旧锁和未随仓URL。

## 安装与核验

在目标机使用CPython 3.11，从已同步的本仓运行安装器。`RELEASE`替换为发行目录的绝对路径，`ENVS`替换为专用环境根目录；两者不得放业务状态或用户已有九问中。

```text
python -m deploy.environment --release RELEASE --unit core --root ENVS
python -m deploy.environment --release RELEASE --unit participant --root ENVS
python -m deploy.environment --release RELEASE --unit swarm --root ENVS
```

| 单元 | 安装内容 | 边界 |
|---|---|---|
| core | 平台、A2C、A2X及其普通依赖 | 不安装参与方SDK或九问 |
| participant | SDK、九问适配、官方包、A2C、Process SDK | 不安装平台或九问本体 |
| swarm | 随仓固定原版九问及其普通依赖 | 不安装平台或参与方SDK；不改用户已有九问 |

Windows环境目录使用短摘要和短尝试名，并核对完整身份。环境路径前缀限制为145个UTF-16字符，安装后的原生库路径须不超过240个字符；超限时按错误提示选择更短的`ENVS`，不修改系统设置。

普通包默认从清华HTTPS镜像安装；`--index`可指定不含账号密码的HTTPS镜像。本地wheel禁用索引并由pip强制核SHA256。版本、依赖、导入来源和禁止混入的组件全部核验后才发布ready，返回JSON中的python为实际环境入口。参与方生成SDK认可的同一安装身份。

重复执行只核验完成环境；安装失败保留原目录和日志。确认失败后可加`--retry-failed`，新建尝试目录，不修补原环境。若只有中断状态且无真实完成证据，保持结果未知，显式重试也不会覆盖。已完成身份损坏时拒绝执行，不自动重装。

加`--verify`只接受已有完成环境，不进行包安装。安装器不切换服务、不创建业务账号、不授权公示、不调用模型或发送邮件；这些属于后续默认部署编排。Windows安装通过不代表Linux/systemd验收通过。

规范见[部署设计](../设计/工程/部署.md)，实际证据见[生产发行核验](../deploy/verification/production-release.json)。

## 部署方九问准备

这是默认安装器使用的准备工具，普通用户不运行。它仅配置本部署新建的独立工作区，不能用来接管用户已有九问。默认安装/升级及systemd编排仍待切换；本节不代表完整部署教程。

复制[部署配置模板](../deploy/deployment.json.example)到本机受限目录。public_url为平台公共根地址；model缺省为null，准备结果明确not_ready。需要模型时填写完整对象：

```json
{
  "name": "API中的模型名",
  "base_url": "https://模型服务商的兼容端点/v1",
  "api_key": "仅在本机填写密钥",
  "provider": "OpenAI"
}
```

已安装并核验swarm环境后，可从本仓运行下列底层准备入口。CONFIG为本机配置；WORKSPACE为专用新空目录；DEPLOYMENT_ID为安装器创建并保存的同一部署UUID（32位小写十六进制），重装不能新建标识。

```text
python -m deploy.workspace --release RELEASE --environments ENVS --config CONFIG --workspace WORKSPACE --deployment-id DEPLOYMENT_ID
```

准备调用原版公开初始化/配置接口，关闭这个新官方实例的自动更新；不调整工具权限或全局指令。模型密钥通过标准输入传递，不出现在命令行和返回JSON。结果中command、data_dir和model供后续官方配置使用；model从公开目录解析，不猜测选择键。

中断后继续原目录和部署标识，先查询原模型资源，避免重复创建。已完成工作区重复执行仅查询当前模型，保留人工修改的权限、技能和模型。不同初始模型输入、原资源缺失、同名目录歧义和未知目录明确报错，不覆盖现场。补齐awaiting_model的模型输入可继续同一次准备。此工具不运行生产模型、不公示服务、不建立另一套收件器。
