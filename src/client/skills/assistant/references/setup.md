# 接入设置

触发：首次接入、修改配置或诊断。用户要求接入时先读[MCP启用](mcp-setup.md)，在当前聊天启用后再读[账号引导](account-setup.md)，不要求用户预先注册或手写凭据配置。已有配置沿用下列受控入口。

1. 账号页创建或复用~/.ioalab/client/settings.local.json或指定外置文件；通过受控配置入口按host-setup.md补齐对应宿主公开字段。账号、身份和宿主检查只使用SDK脱敏结果；不得读取该文件正文，即使只是检查文件存在或角色配置。
2. data_dir使用专用持久目录；同账号至多一个assistant，可另有多个service。assistant身份承接本技能的委托发起和助手通信；委托方是其业务职责，配置中没有client角色。需要辅助修改时读取公共流程，用runtime.configuration/configure按字段更新，不读取账号配置正文。已有实例时使用原配置、身份及路径，不另建身份库。max_model_runs限制同时执行模型轮次，不是累计调用数。
3. 首次账号按account-setup.md，账号认证完成后按[宿主接入](host-setup.md)，最终状态按[状态核对](status.md)逐项报告。已有配置只查状态时直接读status.md；安装、启停和错误恢复按[公共SDK恢复](shared-runtime.md)。不以导入或进程存在报告业务成功。

个人助手后台收件由常驻SDK维护，不由模型轮询连接。收信规则和外部工具按本机明确配置装配；安装官方可选包不会自动启用邮箱、日程或其他权限。配置变更不扩大旧交互的冻结定义。

结构化业务界面统一按[本地交互表单](forms.md)：优先 MCP Apps 内嵌，同一客户端无 MCP 时使用本机表单。接入不要求开启 A2UI 或修改九问全局配置；表单和签名授权分别核验，不以输出界面描述宣称展示成功。

当前宿主的可选交互、插件与通知能力由其安装回执提供，分别验证实际加载和事件。结构化澄清不承担签名授权；准备完成不等于通知已送达。

接入结束读取[接入交付](onboarding.md)，生成固定摘要并逐项核验两份Skill与新会话；不省略客户端、账号配置和官网入口。
