# 收到的请求

用户查看收到的预约、咨询或其他请求时，先读forms.md，默认以messaging.inbox内嵌打开通用收件列表；已有原查询页用ioa_get_form恢复。已知messageRef可作为values直接展示详情，不能猜引用。无需预览、提交或批准，页面提供查看详情、返回、刷新和分页。查询不发送新消息、不重新处理、不改变已读或批准状态。

用户要“最新请求的详情”时，先核原查询页的筛选：values含messageRef或before就用ioa_update_form清为{}取得最新列表；从真实items选择目标，再用同一reference及最新revision更新values为{"messageRef":"实际目标引用"}。最后一次页面回执必须含evidence.detail；只有items是列表，不能宣称已打开详情。不要拿旧的详情数据配上新列表当作完成。原查询页的phase=draft不是待提交业务，不向用户称草稿或要求保存、预览、批准。

详情展示后只回复一句“已展示预约详情，可在卡片中查看内容和实际回复。”；不在聊天复制整份字段、JSON、表格或技术引用。用户另问业务状态时再按真实记录解释。

没有MCP时使用同一SDK本机查询页；用户明确只要文字时，用assistant.messaging.received，参数可含messageRef或limit/before（最多50条）。此操作不自动启动实例。flow的inbox动作只列收信规则，不能用来读消息；messaging.status用于本身份发送的原消息，不是收件查询。

发送者未提供可验证账号时展示真实智能体标识，不凭显示名猜账号；内容和回复按真实记录说明。pending_confirmation只是对方回复中的业务值，不证明存在可点击的批准任务，也不代表已安排日历。打开详情不算已读或已批准；本轮只查询，不替用户承诺后续动作。

每轮以当前用户意图和最新指引为准：查看预约不表示同意先前提出的迁移计划。MCP与原实例正常而脚本报告migrate_host时，报告调用路径差异；不得因查询失败就迁移、重启或重配。明确已停止时报告需要恢复原实例，停止本轮查询，不自行调用configure/stop/start。无需重新注册、发布或发送同一请求。
