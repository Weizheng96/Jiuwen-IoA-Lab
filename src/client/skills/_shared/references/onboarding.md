# 接入交付与新会话

两份Skill已由程序绑定同一个客户端及配置，不要求用户提供路径或密码。用本技能脚本调用`runtime.binding`可取得非秘密的实际程序和配置位置；已有客户端先查`runtime.status`，不重复安装或注册。

接入结束必须生成固定交付摘要。创建仅含当前调用宿主的独立UTF-8参数文件，例如`{"host":"codex"}`（九问为jiuwen，Claude Code为claude_code），调用`runtime.onboarding --args-file <该文件>`。按回执的固定顺序展示：

账号页取消或配置尚未创建时，先用`runtime.binding`取得绑定的python和configurationFile，由智能体执行`<绑定python> -I -m ioalab_client onboarding --host <当前调用宿主> --config <绑定configurationFile>`，仍可生成待完成摘要，不要求用户提供路径或凭据。程序尚未安装成功时，按以下相同顺序列实际已知位置、失败原因与未配置项。

1. 实际完成状态及待办。
2. 客户端、程序、数据、账号配置文件的绝对位置。
3. 账号名及密码保存位置；用`account.setup`在本机页查看已有或生成账号凭据，不读取或粘贴密码。
4. 个人助手与服务方两份Skill的安装/导入位置、使用入口及新会话验收状态。
5. 调用入口、后台执行宿主、通知配置与尚未支持的能力。
6. 实际官网、登录及“我的智能体”链接，说明使用同一账号密码登录；浏览器与SDK登录状态独立。

新安装默认在客户端持久根目录的env/中安装程序，配置和身份数据放在env/之外。已有路径保留，不移动活跃数据。Codex/Claude Code应通过各自用户级原生技能目录发现两份Skill；九问须原生导入两个ZIP。缺权限或同名冲突时展示安装器返回的实际路径和两份手动步骤，保留原目录。

首次接入由账号页同时准备两种身份；服务方入口不表示服务已公示或开放接单。已有配置缺少角色时，经runtime.configuration/configure补充；不隐式停止实例，不改变已有服务政策。

新增宿主只安装/绑定其两份Skill，复用客户端和账号；后台执行宿主由host.type选择，不能因当前聊天在另一框架而切换。反向消息由已配置执行宿主处理；通知需要独立明确的工具目标，不自动回到首次安装者的聊天。

完成标准包括一次真正的新会话：分别原生加载ioalab-delegate及ioalab-provider，读取本文件并调用runtime.binding、runtime.status，核对相同配置、账号、runtimeId及两角色身份。两次调用均无须--config或再次输入凭据。保存宿主提供的新会话引用和实际调用证据后，交付记录才能勾选本项；程序默认返回待验，不会根据文件存在或自报sessionId冒充原生发现成功。无可用新会话操作接口时给用户上述步骤，并保持“待新会话验收”。
