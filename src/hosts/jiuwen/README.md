# 九问宿主适配

本包使用固定原版九问的公开 Process SDK，提供能力探测、受限工具轮次、原 Session 续接及同进程用户问题回调。SDK 基础包不导入本包；本包负责装配角色模块和宿主，不修改九问源码、全局指令或私有历史数据库。

安装仓库锁定的依赖后，使用 `python -m ioalab_jiuwen start --config <本机配置>`。共用配置及数据目录见 [SDK](../../access/sdk/README.md)，增加 host 区域：

```json
{
  "host": {
    "command": ["jiuwenswarm-process"],
    "data_dir": "<自己的九问数据目录>",
    "model": "<model.list 返回的 selection_key>",
    "skill_directories": {}
  }
}
```

data_dir 决定九问实际配置及模型目录；不是项目代码或单次工作目录。配置中不放模型密钥，宿主读取用户已有九问配置。启动前先取得 SDK 实例所有权，再探测能力与模型；探测不通过时不启动业务。常驻状态分别报告处理器、连接与宿主能力。安装身份还固定本包的装配版本；不同安装或旧进程缺核对信息时，start拒绝复用，要求保留数据并显式安全重启。

业务技能与工具白名单分别配置。角色配置的 `skills` 填业务技能名称，`host.skill_directories` 将名称映射到用户明确选择的本机绝对目录；可使用九问原生加载结果返回的 `skill_directory`，不读取其私有数据库。目录应包含 SKILL.md，流程说明放 references 下的 Markdown；设置文件和脚本不会作为技能文档送入模型。

适配器冻结本单选中的文档，通过受限只读回调加载；每轮实际读到主文档后才接受 SDK 业务动作。后续会话使用原快照，源文件变更只影响新交互；原快照丢失或损坏时停止恢复，不能用新内容替换。原生全库技能读取器不在本单工具清单中，技能文档不产生业务授权。

服务方的 `provider.services.<profile>.native_tools` 只填用户确认过的原版精确工具名及权限，例如 `{"write_file":"allow"}`；默认不授予原生工具。`permission.get` 是命名权限策略，不是完整工具目录；状态中的 `nativeToolPolicy` 保留该策略，已知拒绝阻止新接单，未列出的工具显示为未核实，实际调用失败仍需处理。拟卡/复签轮次拒绝原生工具，生产轮次才按冻结权限启用；宿主已有拒绝规则保持有效。工作目录不构成新的沙箱，不能将此配置用于绕过合同授权或外部效果幂等检查。

SDK 回调在本次宿主轮次标记允许，但合同、环节和验收仍分别取得 SDK 绑定的真实用户确认；原生问题仍经真实答复回调处理。修改工具或权限不会静默更换既有合同的冻结定义。

可选本地业务工具按[官方工具说明](../../official/README.md)配置host.business_tools，按profile隔离；SDK仅消费已注入的绑定，不加载具体业务包。构造工厂不初始化日程或发送通知，工具资源在运行时任务全部停止后关闭。

当前助手收信模块使用本机受控用户确认入口；普通模型布尔参数不能批准规则。网页通知能力需显式配置公开桥接，未配置不声称通知已显示。实际能力与待完成项见[开发计划](../../../docs/开发计划.md)，本包依据见 VERSION。
