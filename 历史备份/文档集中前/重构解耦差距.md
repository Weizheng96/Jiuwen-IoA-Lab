# 重构解耦差距

## 范围

本页说明保留实现与[架构](../设计/架构.md)之间的职责差距，不另定义规范。整体实施顺序见[开发计划](开发计划.md)，实际阅读入口见[代码导览](代码导览.md)，真实业务与成片证据见[验证记录](../demo/verification/README.md)。三段 Demo 已完成；整理源码不重开第二阶段，也不把 Demo 完成视为所有功能或服务器部署通过。

目录名称不同、功能待完善和职责耦合分别判断。已退出的旧实现及当时的回归保存在[历史备份](../历史备份/README.md)，不作为当前运行、构建或测试依赖。历史原卡、付款、身份与未知结果留在原数据所有者处，不随源码归档删除或重建。

## 保留实现仍需继续收敛的职责

### 持久化建表仍集中在基础存储

[storage.py](../src/platform/ioalab/storage.py) 的基础 `SCHEMA` 仍集中定义 `users`、`agents`、`wallets`、`transfers`、`rulings` 等不同中心的表；新组件另有各自的建表脚本。实际写入已有所属组件，但存储基础设施仍知道多中心业务字段，领域结构变化还会牵动基础存储文件。

后续把领域DDL及升级步骤按中心/迁移职责归位，基础存储只提供连接、所有权锁、短事务和共用存储适配。保留原数据库、约束和证据，不通过DROP旧业务表完成“解耦”，也不能只复制建表SQL产生两个来源。

### 网页路由仍知道部分跨中心表结构

[web/workbench.py](../src/platform/ioalab/web/workbench.py) 的 `summary` 仍直接筛选事件和身份，再组合合同、服务、收入等多组件结果；[web/app.py](../src/platform/ioalab/web/app.py) 的管理员账号查询仍直接联表读取账号与钱包。这些是授权只读入口，没有据此执行参与方或推进协议，但路由对数据库字段和投影组合方式还有依赖。

后续把相应组合查询下沉到观察/所属组件的窄查询接口，路由仅传入已验证身份和筛选条件。保留本人/管理员权限差异、匿名化、迟报和终态验证；不能因移动SQL而扩大可见性，或另存一套业务状态。

## 另外三类差距

| 类型 | 含义与后续阶段 |
|---|---|
| 目录与文件命名 | 测试尚未全部按职责分组、部分媒体工具仍平铺。这些单独不证明越界。迁移时一起处理构建、资源、安装和检查入口，不预建空目录 |
| 功能完善 | 完整角色端仲裁体验、广泛异常恢复、管理员业务助手及其他非 Demo 能力属第五阶段；网页体验属第四阶段；全部官方领域交付质量属第六阶段。已有底层接口或一项真实业务不能替代各自完成条件 |
| 独立环境验收 | 默认 Linux/systemd 安装、权限、启停、升级、恢复和 GitCode 同步属第七阶段；源码和 Windows 检查不能替代服务器实机证据 |

每次后续开发先确定数据与接口所有者，再修改实现及相邻边界验证。已经完成替换的旧实现整组归档，不为历史影片、旧算法测试或旧运行数据恢复第二条产品执行链。
